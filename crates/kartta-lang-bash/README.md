# kartta-lang-bash

Bash for the kartta code graph: the functions, aliases, globals and commands of a shell script, and the files it
sources.

`Bash` implements the `kartta_lang::Language` contract over the `tree-sitter-bash` grammar. It claims every file whose
extension is `sh` or `bash`, in any case.

## What a file extracts to

Every function definition is a function symbol, and so is every name that `alias name=value` defines. Every variable
assigned outside every function, bare or behind `export`, `declare`, `readonly` or `typeset`, in an `if` or a loop too,
is a variable symbol; an assignment that prefixes a command, `LANG=C sort`, or one inside a function is none. Bash has
no namespaces, so the qualified name of a symbol is its name.

Every command is a call of its name from the function around it. A subshell, a loop or a command substitution opens no
scope. A command outside every function is a call from file scope, before the script's first definition too. A command
binds a function or an alias of its name and never a variable. The handler of `trap cleanup EXIT` and the completer of
`complete -F _tool tool`, named as one word, are uses of them.

## Resolution

A `source` or `.` with a literal argument, or with a literal tail after the expansions it starts with as in
`"$DIR/lib/x.sh"`, names a file; an expansion after a literal part names nothing. A path that starts with `./` or
`../` is relative to the sourcing script; any other path is relative to the root of the repository, or else matches the
only file whose path ends in it at a segment. Each candidate is probed as written, then with `.sh` and `.bash`, and a
suffix that two files match under any of those spellings names none.

A `*_test.sh`, `*_test.bash` or `test_*` file, or a file below a `test` or `tests` directory in any case, is test code.
A `@generated`, `DO NOT EDIT` or `generated by` marker in the comments that open the file marks it generated. A `main`
function at the top of the script is its entry point.

## Fingerprint

The fingerprint covers the crate's version and source and the grammar's version, node types and table sizes, so a cache
keeps the extractions of each build of this crate apart.
