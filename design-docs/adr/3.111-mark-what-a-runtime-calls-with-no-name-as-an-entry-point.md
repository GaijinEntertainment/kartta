A runtime or a language calls some definitions with no call that spells their name, so no extraction records one and
ADR 3.23's dead-code query would report each dead. Each language marks those it knows as entry points, and the query
counts them under `entry` instead of judging them.

## Decision

Each language marks its own entry points (`SymbolFlags::is_entry`):

- **C++:** a free `main`, `wmain`, `WinMain`, `wWinMain` or `DagorWinMain` in the global namespace; and every
  constructor, destructor and operator, which the language calls for an object it makes or ends and for an expression.
- **Python:** a free `def main` at module level, the one a script runs under `if __name__ == "__main__":`; and a
  class's special method (`__init__`, `__enter__`) or property (`@property`, `@cached_property`, or a
  `@name.getter`, `.setter` or `.deleter` over `def name`), which the interpreter calls for an object, a statement, an
  operator or an attribute read.
- **Rust:** a top-level `fn main` in a crate root other than the library's `src/lib.rs`: `src/main.rs`, `build.rs`, and
  the binaries, examples, tests and benches under `src/bin/`, `examples/`, `tests/` and `benches/`.
- **Go:** `main` in package `main`, and every `func init()` with no parameters and no result, which the runtime calls
  for each package and no code can name.
- **Bash:** a `main` function directly under the program, which a script runs through a top-level `main "$@"`.
- **daslang:** a `def` that an annotation other than a compile hint registers with what calls it.

The mark only ranks answers elsewhere (ADR 3.22); here it decides what a dead-code answer leaves out, and the answer
counts it.

## Why

- The constructors no `new` names, the destructors and the operators read dead: 10,544 destructors and 6,157 operators
  on the C++ game-engine tree (2026-10-17).
- Every Go `init` read dead: 248 of the 1,716 dead Go definitions of the Go monorepo (2026-10-18, #78).

## Consequences

- A method the language does not call implicitly but a framework calls by convention, as a test runner or a plugin
  host does, is still judged and may read dead. Accepted.
- A C++ operator or constructor that nothing uses is never reported. Accepted.

## Rejected

- **Count special methods and operators `unobservable`** — the same exclusion under a reason that says the graph cannot
  see them, where the runtime or the language calls them with no name; `entry` already says that for `main` and for
  registered functions, and ranks them last among hotspots (ADR 3.22).

## Revisit if

A language's runtime calls definitions by a convention its extraction does not mark, often enough to fill the dead
list. Medium confidence: the marks cover each shipped language's own runtime, not its frameworks.
