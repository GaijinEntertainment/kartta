# Bind a name a TypeScript or JavaScript package import binds outside the repository

- **Date:** 2026-10-23
- **Governs:** `crates/kartta-lang-jsts/src/resolve.rs` (`bind_outside`), `crates/kartta-lang-jsts/src/walk/exports.rs`
  (`imported_names`, `binds_a_require`)
- **Pinned by:** `crates/kartta-languages/tests/engine.rs`
  (`a_javascript_bare_call_of_a_name_imported_from_a_package_binds_no_namesake_of_the_project`,
  `a_javascript_require_of_a_package_binds_its_names_outside_the_repository`)

A name a TypeScript or JavaScript file imports from a package holds that package's code, which the graph does not
hold. Where [ADR 3.100](/design-docs/adr/3.100-jsts-import-resolution.md)'s resolver finds no file for a bare
specifier, each name the import binds is bound outside the repository, so no call through it or of it binds a project
namesake, at the price of the calls of a package the resolver mistakes a project file for.

## Decision

- **Outside bindings.** Each name that an `import` of a bare specifier binds, or a declarator that takes a `require` of
  one, where the specifier resolves to no file, is an import binding outside the repository, which the cascade answers
  as a call into an external import, whether through the name
  ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md), tier 2) or of it
  ([ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md), tier 6), unless the caller's file defines the name:
  `<Dialog.Footer>` with `Dialog` from `@chakra-ui/react`, `useState()` with `useState` from `react`, and
  `fs.readFileSync()` or `readFileSync()` with `const fs = require("fs")` or `const { readFileSync } = require("fs")`,
  bind nothing in the repository.
- **What a declarator binds.** The declarator binds each name of its pattern, a property key and a default value none,
  and `require("chalk").default` binds no name.
- **Specifiers that name the repository.** A specifier that starts with `.`, `/` or `#` names a file of the repository
  even where none resolves, so its names get no such binding.

## Why

- A name imported from a package holds that package's code, so a member call through it bound a repository definition
  that only shares the member's name: 146 such caller and callee pairs on three trees, none right (2026-10-23, #301). A
  bare call of the name bound the same way: 660 such pairs on dagor and the Go monorepo snapshot, none right
  (2026-10-24, #422). A `require` of a package holds that package's code as an import does; on dagor, daScript, sso and
  the snapshot the one pair it lets bind no more is wrong, `utf8.encode()` with `utf8` from `require('utf8')` bound to
  a vendored bundle's `encode` (2026-10-24, #423).
- The caller's file defines an imported name only where a definition nested in the caller shadows the import, or
  where a test hook such as `beforeEach` is named for itself, so its definition is the one meant.

## Consequences

- A bare specifier that names a file of the repository only through configuration the resolver does not read, a
  bundler's own alias, is taken for a package, so no call of a name it imports binds: no right pair lost on dagor or
  the Go monorepo snapshot (2026-10-24, #422). Accepted.

## Rejected

- **An external binding for every specifier that resolves to no file** — dropped 5 more pairs on SillyTavern, 3 of them
  right, `MacrosParser.registerMacro` through `'/scripts/macros.js'`, a path a web server roots at `public/`
  (2026-10-23, #301).
- **Ending a bare call at the import before the caller's file** — drops the 22 pairs from a `describe` to its
  `beforeEach` or `afterEach` hook where `vitest` exports the hook's name, pairs a global hook keeps (2026-10-24, #422).

## Revisit if

A bare specifier reaches files of the repository through a bundler's alias the resolver does not read, so the names it
binds are the repository's own; none seen yet.
