# Stop a Node call by a binding id its handle gives it

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-21
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `bindings/node/src/kartta.ts` (`Kartta.build`, `Kartta.refresh`, `Kartta.grep`, `Kartta.call`,
  `Kartta.close`)
- **Pinned by:** `bindings/node/test/kartta.test.ts`

A Node caller stops a build, a grep or a refresh with an `AbortSignal` or by closing the handle
([ADR 4.3](./4.3-reach-the-engine-from-node-through-an-addon-over-the-same-dispatch.md)), and the library's
`cancel {}` reaches only the calls that have entered it. The handle names each such call by an id of its own, which the
library remembers for a call yet to enter, so a stop reaches it waiting or running; the trade is a map entry per call
in flight.

## Decision

- The handle names each build, grep and refresh it starts by a `binding_id` of its own, in place of any the params give,
  `call`'s included, and passes the `id` a caller gives on as it is, in `call`'s params and a typed call's options
  alike: the rule both bindings follow
  ([ADR 4.30](./4.30-cancel-a-build-a-grep-or-a-refresh-by-the-id-it-names-even-before-it-enters.md)). The library
  keeps the builds', the greps' and the refreshes' ids apart, and the binding ids apart from the ids callers give.
- `build`, `refresh` and `grep` take `{signal}`. An abort cancels the call's binding id, so it stops the call waiting or
  running, and a rejection it causes carries the signal's reason as its cause. A build rejects with `build_cancelled`.
  A refresh stops only before its walk ends, rejecting with `refresh_cancelled`; one past it answers what it changed.
  A grep answers what it covered, `cancelled` set and the files it did not open counted `unsearched`, as the wire
  answers a cancelled grep
  ([ADR 4.30](./4.30-cancel-a-build-a-grep-or-a-refresh-by-the-id-it-names-even-before-it-enters.md)); one that
  opened its last file answers whole.
- A signal aborted before the call rejects with its reason and leaves the handle as it was, as a done context does in
  the Go binding.
- `close` cancels each build, grep and refresh in flight by its binding id, then every call that has entered the
  library with `cancel {}`, then drops the handle. A build it cancels rejects with `build_cancelled` and a refresh with
  `refresh_cancelled`, each with a `closed` error as its cause; a refresh past its walk answers, and a grep answers
  what it covered.

## Why

- A grep still queued for a pool thread, or waiting in the library for a refresh under way, holds its own reference to
  the engine and has not entered, so `cancel {}` missed it and it ran in full after `close`: up to 16 s on a tree of
  182,714 entries (2026-10-21). Under a binding id it answers as soon as a pool thread takes it, every candidate
  unsearched.
- A caller's `id` and the handle's id each stop only the calls they name when they travel apart: the caller cancels by
  the id it gave, and `close` and a signal by the handle's.

## Consequences

- A map entry per build, grep and refresh in flight, and no measurable time per grep. Accepted.
- The library remembers the latest 1,024 ids of each kind
  ([ADR 4.30](./4.30-cancel-a-build-a-grep-or-a-refresh-by-the-id-it-names-even-before-it-enters.md)), so a `close`
  that lands while more than 1,024 builds, greps or refreshes have yet to enter it leaves all but the latest 1,024 of
  that kind running. A caller's
  stale cancels never push out those a `close` sent ahead. Accepted.

## Rejected

- **The signal handled in the addon** — napi's `AsyncTask::with_signal` drops only a task that has not started; a
  cancel by id from JavaScript stops one running or waiting alike.
- **A grep stopped by `cancel {}` alone** — `close` would leave a grep queued for a pool thread, or waiting for a
  refresh under way, to run in full.
- **The id the params give, as the handle's own** — a grep the caller gave no id could not be named by `close`.
- **The handle's id in place of the caller's** — a caller's cancel by the id it gave stopped nothing, and stayed
  remembered against the call the handle later gave that id.

## Revisit if

A consumer keeps more than 1,024 builds, greps or refreshes of one kind waiting to enter the library at once, so that
a `close` leaves some running. Medium confidence: no known consumer queues that many.
