# Record Python data sites in the scope that binds them

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-lang-python/src/walk/uses.rs`, `crates/kartta-lang-python/src/walk.rs`, the Python
  `Conventions` (`ValueUses::Imported`, `UntypedMembers::FileField`)
- **Pinned by:** `crates/kartta-lang-python/tests/extract.rs`
  (`a_use_names_its_receiver_s_class_and_reads_a_module_value_the_file_binds`,
  `a_class_body_reads_the_module_values_it_names`, `module_level_code_reads_the_module_values_it_names`,
  `a_class_body_reads_the_attributes_it_binds_and_none_of_its_targets`,
  `a_class_body_s_names_reach_its_first_iterable_and_nothing_nested_in_it`)

Python binds a name for the whole scope that binds it, and a module's names are its classes, functions, imports and
assignments. The walk records each attribute taken without a call and each name the module or a class body binds,
decided when the scope closes, so `find_references` answers a Python field and `dead_code` sees a function taken as a
value, at the cost of a deferred decision per use and a file-field guess for untyped values.

## Decision

- **Where.** Inside a definition, in a class body, which the class makes
  ([ADR 3.12](/design-docs/adr/3.12-python-qualified-names.md)), and in code outside every definition, a decorator of a
  module-level definition included, which makes its uses at file scope
  ([ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)): each attribute taken without a call, and each bare name the
  module binds by an assignment, an import, a `def` or a `class`. An imported name read only to take an attribute of it
  is no use of the name. A class body also records each bare name it binds itself. The fields the uses bind are those
  [ADR 3.103](/design-docs/adr/3.103-python-class-fields.md) declares.
- **Binding is no use.** A name the module or a class body binds is not used where it binds it, as a function's own
  binding is not: an assignment's, a `for`'s, a `with`'s or an assignment expression's target there records nothing, but
  an augmented assignment updates the value it binds again.
- **Scope.** A use waits in the scope that holds it until that scope closes, as a call does, so a name the scope binds
  later hides the module's; a `global` declaration gives the name to the module. A parameter default is looked up in its
  function's scope, as [ADR 3.12](/design-docs/adr/3.12-python-qualified-names.md) accepts for calls. A class body's
  names reach its own statements and a comprehension's first iterable, as Python's class scope does, and no method,
  nested class, lambda or comprehension's inner part, which read the scope around the class.
- **Receivers.** An attribute on a method's first parameter, `self` or `cls`, is an own-receiver use; a static
  method's first parameter is no receiver. An attribute on a name the module binds to a class, a function or an import,
  or on a name nothing in the file binds, names that name as its owner path. A bare name a class body binds names that
  class as its owner path, so it binds the class's member. On anything else, a module value or a
  local included, the path is empty and the use takes the file's one field of the name: Python keeps
  `UntypedMembers::FileField`, and sets `ValueUses::Imported` ([ADR 3.173](/design-docs/adr/3.173-data-use-binding.md)).

## Why

- The file's one field of the name bound right in 46 of 50 sampled sites on the game-engine tree, so it stays on
  (2026-10-18, #83).
- A function a module defines and passes as a value, or a method taken through `self`, is used where no call names it;
  without these uses `dead_code` judged it dead.
- A script reads its module values from its top level: 21,405 file-scope uses in 820 of the game-engine tree's 1,215
  Python files, every one of 139 sampled a read, an update, a write or a type its source spells (2026-10-24, #448).
- A class body reads its own constants and takes its own methods as values, `do_HEAD = do_GET`: 156 such uses on the
  Python trees, 29 of 30 sampled right (2026-10-31, #778).

## Consequences

- A class body's name binds whatever its place in the body, so the right side of `reader = reader.Reader()`, which
  reads the module's `reader`, binds the field the line declares: 1 of the 156 uses of #778. Accepted.
- A method's parameter default, which Python evaluates in the class body, reads the module as the Scope rule looks it
  up in its function. Accepted.
- A module imported under an alias, `import a.b as m`, binds no `m.X`; a dotted `a.b.X` records the empty path and can
  bind the file's own field `X`. Accepted.
- An attribute on a builtin or a star-imported name binds nothing, since its owner is not in the graph. Accepted.
- A Python class taken as a value is a use, but `dead_code` judges no Python class. Accepted.
- A file-scope use keeps its name alone ([ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)), so `find_references`
  lists no module-level read of a value; `find_callers` lists the file. Accepted.

## Rejected

- **`UntypedMembers::Unbound` as TypeScript sets it** — drops the 46 of 50 the file's one field binds right.

## Revisit if

The file's one field stops binding right for most Python values, as a fresh sample on a tree of another shape would
show. Held on one tree's sample.
