# Plug languages in through a trait

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang/src/language.rs` (`Language`, `Resolver`, `Repository`, `Conventions`),
  `crates/kartta-lang/src/lib.rs`, `kartta_graph::Graph::conventions`
- **Pinned by:** `crates/kartta/tests/engine.rs` (`a_claimed_file_is_in_its_family_graph_and_an_unclaimed_one_in_none`,
  `languages_of_one_family_share_a_graph_and_the_first_to_claim_a_file_takes_it`,
  `the_first_language_to_decline_a_file_names_itself_and_its_reason`),
  `crates/kartta-graph/tests/graph/contract.rs` (`a_graph_answers_the_conventions_it_was_made_with`)

The code graph is one structure fed by many languages, each with its own grammar and its own heuristics for what a name
refers to. A language is a value implementing `kartta_lang::Language`, and the engine is handed the languages to build
with, so the graph knows no language and a language kartta does not ship plugs in without a change to kartta; each
language crate pays for a contract of its own instead of a shared enum.

## Decision

- **The trait.** A language names itself and its family, the languages whose files resolve against each other in one
  graph, as TypeScript and JavaScript do; claims the files that are its, and says why it leaves out a file of its kind
  it does not claim, as Go leaves out a name no Go build reads (`matchFile` in go1.27.3
  `src/go/build/build.go:1451-1453`, [ADR 3.7](/design-docs/adr/3.7-call-resolution.md)); states the fingerprint of
  what it extracts, the conventions its calls resolve under, and its doc-comment forms
  ([ADR 3.134](/design-docs/adr/3.134-doc-comment-forms.md)); extracts one file; and builds the resolver its family's
  files resolve through. `kartta::Engine::build` takes the languages as values. Each of kartta's own is a crate of its
  own, and anyone else's is one more crate against the same contract.
- **What `kartta-lang` holds.** The contract, the records it speaks in, and the helpers languages would otherwise each
  copy: path helpers, the scan of a generated-code banner, a `MemoryRepository` for a resolver's tests, the identity of
  a crate's source that its build script hands it, and, behind the `tree-sitter` feature, the tree-sitter walk helpers
  and the fingerprint of a language that parses with a grammar. The contract names no parser.
- **Extraction is split where a cache can share it.** `Language::extract` reads only the file's bytes and returns a
  `RawExtraction`, so every file with the same content, in any tree, has the same one, and the per-file cache of
  [ADR 2.2](/design-docs/adr/2.2-build-cache-lookup.md) computes it once. Whatever depends on the path or the
  repository, which file an import names and whether the file is a test, is recorded as a directive and applied by the
  `Resolver` against a read-only `Repository`. A language that reads configuration, a `go.mod` or a `tsconfig.json`,
  reads it through the repository in `Language::resolver`; `Resolver::resolve` reads no file's content, under the
  contract [ADR 3.33](/design-docs/adr/3.33-refresh-dependency-tracking.md) states. A family no file of which the build
  read builds no resolver and reads no configuration.
- **What the graph cannot infer is data the language states.** How a bare call reaches the members of the caller's own
  type, whether a variable can be called, how an owner's chain of names is joined: these are `Conventions`, read by
  the graph and never decided by a language's name. A concept only some languages have, a package whose files see each
  other's names, a re-export, a declaration folded into its definition, is a channel of the extraction that a language
  fills or leaves empty, so the graph implements it once for every language that uses it.
- **A graph hands out its conventions.** `Graph::conventions` answers the conventions the graph was made with, those of
  its family's first language. A consumer that says what an answer leaves out reads it from them, never from a list of
  language names of its own; `find_references` names a language whose `type_uses` is `TypeUses::Nowhere`
  ([ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md)) or whose `unrecorded_data` lists the symbol's kind
  ([ADR 4.22](/design-docs/adr/4.22-unrecorded-data-uses.md)), and `find_importers` quotes the `includers` a language
  states ([ADR 4.68](/design-docs/adr/4.68-importer-counts.md)).
- **The rules split off.**
  - A language derives its fingerprint from its code and its dependencies' versions:
    [ADR 3.120](/design-docs/adr/3.120-language-fingerprints.md).
  - A language states its conventions as a `const` over the default, as the doc of
    [`Conventions`](/crates/kartta-lang/src/language.rs) states with its reason.
  - A family resolves through the one resolver its first language builds:
    [ADR 3.122](/design-docs/adr/3.122-language-family-resolvers.md).
  - A resolver owns what it read and is handed the repository with each file:
    [ADR 3.123](/design-docs/adr/3.123-resolver-repository-handoff.md).
  - `Resolver::resolves_as` lets a resolver built again say it resolves as the kept one:
    [ADR 3.82](/design-docs/adr/3.82-followed-resolver-rebuilds.md).

## Why

- A graph built around the languages it started with grows their special cases, what a Go package is or which
  extensions a TypeScript import may omit, and every new language then changes the graph's crate.
- The split at the bytes lets one cache entry serve every copy of a file, across trees and builds, and a capability
  stated as data reaches every language that states it, where one keyed to a name reaches that language alone.

## Consequences

- A rule the graph needs from every language is one more `Conventions` field or trait method, and every language
  crate states it or takes the default; accepted.

## Rejected

- **Every language in one crate behind an enum** — one place to change for a new language, and the graph's special
  cases grow from the languages it was built around.
- **Languages loaded at run time from shared libraries** — Rust has no stable binary interface, so the boundary would be
  a C one, unsafe on both sides and versioned by hand.
- **Languages loaded at run time as WebAssembly modules** — every file's bytes are copied in and every extraction copied
  out, and a runtime comes with them.
- **Languages described by tree-sitter tag queries** — a grammar and a query file give definitions and calls with no
  code, but not the resolution of imports or the heuristics a receiver needs; such a language fits as one more crate
  under this contract, not in place of it.

## Revisit if

A host needs languages it was not compiled with, which only run-time loading serves. Low likelihood: every consumer
kartta ships builds its languages in.
