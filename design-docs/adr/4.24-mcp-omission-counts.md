# Count in each MCP answer what it left out

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-mcp/src/render.rs`, `crates/kartta-mcp/src/render/`, `crates/kartta-mcp/src/llmxml.rs`,
  `crates/kartta-mcp/src/languages.rs` (`echo`)
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`, `crates/kartta-mcp/tests/graph.rs`

An agent reads a cut answer as complete unless the answer says what it cut. Each answer of
[ADR 4.1](/design-docs/adr/4.1-mcp-server-tools.md)'s server counts, as attributes of its envelope, what the engine
turned away where it made the cut, and lists what a match passed over, so a count costs no work the query does not
already do.

## Decision

- **Counts.** Where the engine counts what an answer left out, the answer says so, each count only when it is not zero:

  | `list_dir` | `unlisted` beneath a directory not entered, `shown` and `excluded` |

  Each count's word is [ADR 4.71](/design-docs/adr/4.71-mcp-count-vocabulary.md)'s. `grep`'s counts are
  [ADR 1.11](/design-docs/adr/1.11-content-search-limits.md)'s, and `list_dir`'s
  [ADR 1.8](/design-docs/adr/1.8-listing-counts.md)'s. A list a call's `limit` cut in `find_symbols`, `find_callers`,
  `file_outline`, `find_importers`, `read_definitions` (each name's), `impact_of_edit`, `impact_of_change` (its seeds
  and its hotspots, each alone) or `find_unused` ends, after its records, with a line naming `limit` as the way to the
  rest, beside the `shown` and `truncated` that count it. A cut by anything else claims no `limit`, as `find_symbols`'
  dropped words, or `impact_of_change`'s 300-entry cap under a higher `limit`; a higher `limit` lists its seeds and
  hotspots only up to that cap, so past it the line promises more than any `limit` lists (#1243). `find_importers`'
  `hops` follows the importers `unexpanded` counts. A path filter's cut is counted as `excluded`, as `grep` and
  `list_dir` count theirs; `find_references`' `sites_under` counts the sites, files and file-scope users outside it
  ([ADR 4.11](/design-docs/adr/4.11-mcp-reference-listing.md)). A `grep` answer whose size cut its context
  ([ADR 4.23](/design-docs/adr/4.23-mcp-default-limits.md)) counts the lines a side it shows in `context_shown`, beside
  the `context_lines` asked, and ends with a line naming a narrower `includes` or a lower `max_results` as the way to
  more. An `impact_of_edit` list its answer's size cut counts what it shows in `shown` of `total` and ends with a line
  saying so, naming the same call as a list its fixed cap cut.
- **Fixed caps.** A list a cap no parameter raises cut ends the same way, with a line naming the call that lists the
  rest, or saying that no parameter or call does:
  - `impact_of_edit`'s 50 direct callers, users and callees of a symbol, and `impact_of_change`'s 10 callers, users or
    their directories of a seed: `find_callers` with `hops` 1 and a `limit` of their count, `find_references` or
    `find_callees` of the symbol, picked by `path_prefix` and `line`;
  - the five `<candidate/>` records of a match, and the five definitions a miss lists: `find_symbols` of the name with
    a `limit` of every definition it selects, and with `languages` naming where that count holds, since one limit spans
    every graph `find_symbols` searches: the match's family, or the miss's own filter where it had one;
  - a `read_definitions` body past 500 lines: the lines of its file that hold the rest, unless the file changed size;
  - `grep`'s five unreadable files: `grep` with narrower includes;
  - none for `find_implementations`' 500 implementors and the build's errors past five;
  - the file-scope users past 50: in `find_references` a narrower `sites_under`, and in `find_callers` no parameter,
    where `grep` of the name's last segment, the key a file-scope user is listed under
    ([ADR 3.38](/design-docs/adr/3.38-callee-listing-key.md)), finds them among its other uses;
  - the one-edit suggestions past five: `find_symbols` of a suggested name for its namesakes, with the call's own
    `languages` where it had them, and no call for the other names.
- **Candidates.** A match that passed symbols over lists up to five as `<candidate/>` records with the `callers=`,
  `sites=` or `implementors=` each has; `find_implementations` names the type it took in a `<root/>`, and
  `find_call_path` marks each `end="from"` or `end="to"`. Where its `limit` cut a `read_definitions` name's definitions,
  the name lists the next five nearest as candidates, each with its `lang=`, after the definitions it shows.
- **Selection.** An answer names what its filters selected. A symbol tool's `languages=` names the families it
  searched, since a language of a family selects the family's one graph
  ([ADR 3.4](/design-docs/adr/3.4-jsts-extraction.md)). `<index>`'s `languages=` names the languages a filtered
  `index_root` built, and the answer for a name that matches nothing repeats them as `index_languages=`. A
  `find_call_path` match locates the ends it picked in `from_loc=` and `to_loc=`, and a match without a chain whose
  names passed symbols over says that only the picked pair was searched, as
  [ADR 3.35](/design-docs/adr/3.35-shared-name-selection.md) picks it. A `find_implementations` answer for a parent
  with no indexed type, asked with no `path_prefix` and no `line`, carries `outside_graph=`, counts the unreached
  `namesakes=` and says it listed one hop ([ADR 3.208](/design-docs/adr/3.208-parents-outside-the-graph.md)).
- **Unnamed implementors.** The graph finds only the types that name a parent
  ([ADR 3.20](/design-docs/adr/3.20-implementor-resolution.md), #1169). A `find_implementations` answer whose root a
  type of its language can implement by its members alone, without naming it, says that such a type is not listed, in
  its text when no type names the root and in a `<note>` before the list otherwise, naming the language: a Go
  interface, a TypeScript interface, and a Python class whose bases list typing's `Protocol` itself, written bare, as
  `typing.Protocol` or as `typing_extensions.Protocol`.
- **File-scope callers.** A file whose top level calls a `find_callers` root is a `<file_scope path=/>` record after
  the refs, with a call's confidence mark and no line, since the graph keeps only the names a top level spells; the
  walk goes no further, `role` lists none of them, and `below_confidence=` counts those the floor dropped. The first 50
  are listed ([ADR 4.23](/design-docs/adr/4.23-mcp-default-limits.md)), and `file_scope_shown=` says the cap cut them.
  `find_callers` of a field points at `find_references`.
- **A data symbol's impact.** The impact answers of a field, a variable or a constant count `users=` and list
  `<users>`, or past 30 `<user_dirs>`, in place of callers, which its users hold.
- **What other ADRs decide.** Own ADRs decide what a floor dropped
  ([ADR 4.13](/design-docs/adr/4.13-confidence-floor-notes.md)), the calls of a name that bound nothing
  ([ADR 4.12](/design-docs/adr/4.12-ambiguous-call-counts.md)), a call of itself
  ([ADR 4.14](/design-docs/adr/4.14-self-call-listing.md)), an outline's holders
  ([ADR 4.15](/design-docs/adr/4.15-outline-holders.md)), a name that selects nothing
  ([ADR 3.48](/design-docs/adr/3.48-other-separator-reading.md),
  [ADR 3.49](/design-docs/adr/3.49-names-holding-separators.md), [ADR 4.18](/design-docs/adr/4.18-mcp-name-misses.md))
  and a type's unrecorded uses ([ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md)).

## Why

- An agent reads a cut answer as complete unless the answer says what it cut, and picks its next call from what the
  answer holds (CLAUDE.md, `<answers>`); the engine counts each cut where it makes it (#74).
- A count absent at zero keeps the bytes of an answer that cut nothing.
- A count past a cap no parameter raises leaves an agent to guess which call reaches the rest, since no argument
  repeats the call wider (#1038).
- An empty answer reads as absence unless it shows what the query and the build left out: after a TypeScript-only
  build, `find_callers` of a Rust function answered "no symbol matches" with no trace of the filter (#1041).
- A Go type implements an interface when it is in the interface's type set (the Go specification, "Implementing an
  interface"), TypeScript checks an `implements` clause only as an assignability check (`src/compiler/checker.ts`,
  `createImplementsDiagnostics`), and a Python protocol is satisfied by structural subtyping (`Lib/typing.py`, the
  `Protocol` docstring), a class being one only where its bases list `Protocol` itself (`_is_protocol` in
  `Protocol.__init_subclass__`). The types that name such a root are a part of its implementors, and an answer of that
  part alone read as all of them (#1313).

## Consequences

- A count says how much was cut, not which: an agent that needs those makes the call the last line names, a wider
  one where a parameter raises the cap. Accepted.
- `find_implementations` past 500 has no such call: dagor holds 5 C++ parents with more than 500 direct implementors
  (#1234). A walk its 500-symbol cap stopped names no way past it (#1235). `impact_of_change`'s 300 seeds and 300
  hotspots name no way past them, and a lower `limit`'s line there promises more than a higher one lists: 28 lists on
  dagor (#1243).
- The closing line costs 79 to 130 bytes in each list a fixed cap cut, and nothing in an answer that cut none
  (2026-11-07), and the `limit` line 56 bytes in each list a `limit` cut. Accepted.
- A hit after a filtered build does not repeat the build's languages; only `<index>` and a miss carry them. Accepted.
- The unnamed-implementors note costs 97 to 121 bytes in an answer that lists types, by the languages it names,
  and 82 to 106 bytes more than the line it replaces in one that lists none (2026-11-27). Accepted.
- No note marks a TypeScript class, an object-type alias, a Go alias of an interface, an `outside_graph` library
  interface or a protocol reached through an aliased import (#1328), nor a protocol written `Protocol[T]`, whose
  subscripted base the extraction does not record (#1324).

## Rejected

- **A data symbol's callers beside its users in the impact answers** — its users hold its callers, so a
  function-valued variable that is called would list each caller twice.
- **A languages filter narrowed by file extension inside a family** — a check per record, and the family's one graph
  binds calls across its languages, so the narrowed answer would hide edges it holds.
- **A count of the files a filtered build left out, per language** — a pass over the paths per answer, where the
  agent's next call needs only to know the filter is on.
- **`find_call_path` over every pair the two names select** — it reopens
  [ADR 3.35](/design-docs/adr/3.35-shared-name-selection.md)'s one-symbol selection.

## Revisit if

A count stops riding on the work its answer already does, so it costs each call. Held: every count is taken where the
engine makes the cut.
