# Bind a C++ call on a declared class through the class nearest the caller's file

The C++ walk records a member call's receiver as the class its operand is declared as, spelled with the scopes the
declaration writes, and the class a type alias names ([ADR 3.75](/design-docs/adr/3.75-cpp-call-receivers.md)). A
class's bare name does not say which class, so the graph follows the spelling through the aliases it names, binds the
member of the class of that name nearest the caller's file, chooses among namesakes by the spelling as C++ lookup does,
and searches the class's bases where it declares no member of the name
([ADR 3.188](/design-docs/adr/3.188-cpp-inherited-member-calls.md)), at the price of a class the file reaches only
through a header that includes it.

## Decision

- **Aliases.** A receiver's spelling, a field's class ([ADR 3.47](/design-docs/adr/3.47-cpp-field-calls.md)) among
  them, is first followed through the type aliases it names: the first of its names that names an alias is replaced by
  the class the alias records, and the next is read from that alias's scope, so `StateList::iterator`, with
  `StateList` a typedef of `List` and `List` declaring `typedef IteratorImpl<T, List> iterator`, names `IteratorImpl`.
  The aliases are read without the template arguments the spelling writes, `dag::Array` of `dag::Array<int>` and
  `Inner` of `Outer<int>::Inner`, since an alias template's arguments name no class of their own. A name is looked up
  as C++ looks it up: the first in the class around the use, of namesake classes the one the scope around the use is,
  then the namespaces around it; a name after a class among that class's aliases; a name after namespaces among their
  aliases, where no class of that spelling is nearer. An alias that records no class hides the names around it all the
  same. Where the chain comes back to an alias it passed, ends at a name no class of the graph has, or meets no alias,
  the spelling stands as written.
- **The nearest class.** Where scopes nest, as C++'s do, a receiver that names a class binds the member of a class of
  that bare name nearest the caller's file through its includes: its own file, then the files it includes, then the
  rest of their closure. Where the file reaches none, the call resolves as one on a value.
- **Namesakes.** Of the classes in the nearest tier that hold the member:
  - a tier of one class binds it whatever the spelling says;
  - else the ones whose qualified name the spelling names, looked up from the caller's scope outward, a member's class
    first, then its namespaces, the global scope last, so a bare `Widget` inside `namespace b` names `b::Widget`;
    where the spelling names none, all of them go on;
  - of the classes left, those whose member the caller's own file holds, where any does;
  - of those, the one that the order [ADR 3.65](/design-docs/adr/3.65-cpp-namesake-classes.md) states for a use picks
    binds, the class the caller is read in standing for the use's: the receiver's template arguments, the class in the
    caller's file that the caller's function defines or whose body holds the caller, the caller's own class, the
    template arguments of the caller's scope;
  - else classes of one qualified name, a template and specializations nothing picks, a class under each branch of a
    conditional or copies of one class, bind the first;
  - namesakes of other qualified names leave the call ambiguous.
- **Bases.** A class the file reaches that declares no member of the name binds the member of its bases, as
  [ADR 3.188](/design-docs/adr/3.188-cpp-inherited-member-calls.md) states.

## Why

- A class's name alone does not say which class: `vector` names EASTL's and a vendored PhysX one, `Unit` the game's and
  `xray::Unit`. Through the nearest class, 73,589 calls of the C++ game-engine tree of 43,356 files that bound nothing
  bound a member, 39 of 40 sampled right (2026-10-19, #114).
- Two classes of one bare name a file includes at one depth, `a::Widget` and `b::Widget`, were left to path order;
  with the spelled scopes, 1,153 calls moved to another member, 30 of 30 sampled right (2026-10-22, #176, #180).
- A typedef owns no member, so a receiver spelled through one, FMOD's `InstrumentList::iterator`, matched every
  namesake `iterator` class. Through the aliases, 20,514 pairs of the game-engine tree are added, 29 of 30 sampled
  right, and none of 30 sampled of the 3,446 they replaced was right (2026-10-24, #378, #477).

## Consequences

- A class the file meets only through the header that includes it is not reached.
- An alias of a class that many namesakes share spells that class, which can leave its call ambiguous: 271 calls on
  `dag::vector`, an alias of `dag::Vector`, one of ten `Vector` classes, bind nothing (#613).

## Rejected

- **Bind through the nearest class alone, with no fallback to a call on a value** — lost 14,693 calls.
- **Bind the caller's own class where the file reaches no class of the name** — added 1,142 calls at about half right.
- **Make namesakes of one qualified name ambiguous** — took 1,160 more calls, 24 of 30 sampled of those sharing a file
  had bound right.
- **Check a tier's one class against the spelling** — took 5,667 calls, 18 of 20 sampled had bound right; a
  using-directive or a macro read as the class's name leaves the spelling short.
- **Spell a specialization's arguments into its class's qualified name** — told `Box<bool>` from `Box` but moved the
  resolution of bases and lost 3,702 to 4,026 calls (#374).

## Revisit if

The class nearest the caller's file is the wrong class in more than one sampled call in ten, as a namesake the
caller's includes reach before the class the build compiles would be. High confidence: 39 of 40 sampled were right.
