# Count what a listing leaves out

- **Date:** 2026-10-13
- **Updated:** 2026-10-13
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fs/src/list.rs` (`ListOptions`, `Listing`, `Listed::unlisted`, `Index::list`)
- **Pinned by:** `crates/kartta-fs/tests/index.rs`
  (`a_listing_reports_how_many_entries_the_index_holds_under_the_directory`,
  `a_collapsed_directory_is_listed_with_its_contents_counted_at_any_level`, `the_listed_directory_is_never_collapsed`,
  `a_collapsed_directory_counts_once_toward_the_limit`,
  `an_excluded_entry_leaves_the_listing_with_its_subtree_and_is_counted`,
  `exclusion_wins_over_collapse_and_spares_the_listed_directory`, `an_excluded_entry_never_counts_toward_the_limit`)

An agent cannot see what it was not given, so a listing of the file index says how much each of its bounds left out.
It counts only what the index's depth-first layout makes free, so every count is in indexed entries, the index's own
numbers rather than what the listing would have shown.

## Decision

- A listing takes two `Filter`s beside its depth and limit, compiled in the query glob dialect (ADR 1.4) and matched
  against root-relative paths:
  - `ListOptions::exclude` leaves out a file it matches, and a directory it matches together with its subtree.
  - `ListOptions::collapse` lists a directory it matches without entering it.
  - Exclusion wins where both match. The listed directory itself is never excluded or collapsed, so naming a
    directory by path always shows what is inside it.
- Hiding dot entries is the pattern `**/.*`, not an option of its own.
- `Listed::unlisted` is the number of indexed entries beneath a directory the listing did not enter, at the depth bound
  or collapsed, zero included, so an unentered directory never reads as an empty one. It is `None` for a directory the
  listing entered and for anything that is not a directory.
- `Listing::excluded` counts the indexed entries the exclusion removed, each removed directory and everything beneath
  it, up to where the listing ended (ADR 1.5).
- `Listing::total` is how many entries the index holds under the listed directory at every depth, the excluded ones
  included, which bounds what the depth and the limit turned away.
- The counts are the index's own: a collapsed directory's count includes entries an exclusion would have removed.
- Excluded entries and a collapsed directory's contents never count toward the limit, and `truncated` keeps the meaning
  ADR 1.5 gives it.

## Why

1. Every count is free. Index order is depth-first, so a subtree is one contiguous run, and the binary search that
   skips it, which a depth-bounded listing does anyway, lands on its size.
2. The total is the listed directory's own run, whose end the listing finds once to know where to stop, so it costs
   one search per call whether or not the limit ends the listing early.
3. Subtracting what an exclusion would remove from a collapsed directory's count means visiting the subtree the skip
   exists to avoid.

## Consequences

A count states entries, directories included, where a reader asking how big a directory is usually means files.
Accepted.

## Rejected

- **Bare directory names for collapse** — the unit the consumers passed and a cheaper comparison, and it gives the two
  pattern sets two matching units; a bare name is the glob `**/name`.
- **A file count instead of an entry count** — it costs a scan of the skipped subtree or four bytes per entry for a
  running count. Reopened when a consumer needs files rather than entries.
- **A flag that a directory was not descended** — the same cost as the count, with less information.
- **Leaving the counts out** — the caller lists the directory again to learn what the first call could have said.

## Revisit if

Counting stops being free, as in an index layout without contiguous subtrees; each count is then measured before it
is kept. High confidence while the index stores entries depth-first.
