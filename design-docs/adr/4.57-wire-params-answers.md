# State what each wire method takes and what its answer left out

- **Date:** 2026-11-02
- **Governs:** `crates/kartta-ffi/src/wire/params.rs`, `crates/kartta-ffi/src/wire/files.rs`,
  `crates/kartta-ffi/src/wire/graph.rs`, `crates/kartta-ffi/src/wire/build.rs`, `bindings/go/wire/`,
  `bindings/node/src/wire.ts`
- **Pinned by:** `crates/kartta-ffi/tests/dispatch.rs`, `crates/kartta-ffi/tests/golden.rs`, `bindings/go/zero_test.go`

A consumer of the wire reads a bounded answer with no way to ask what the bound cost it. Params refuse what a method
does not take, a bound is required or optional as its Rust signature makes it, a value sent means what it means in the
public layer, and each answer carries the counts the engine holds; the trade is an object with counts where a bare array
would be smaller, and a caller that states every bound a Rust caller must.

## Decision

- **Params and answers.** Params are one type per method and refuse unknown fields; JSON that is neither an object nor
  `null` answers `invalid_params`. Answers may gain fields: a new key is additive, absent where it would say nothing.
- **Bounds follow the Rust signature.** The wire holds no default of its own. A bound the Rust function takes as an
  argument is required, and a request without it answers `invalid_params` naming it: the `depth` of `callers`,
  `callees`, `call_path`, `analyze_segment`, `analyze_change`, `implementations` and `dependents`, the `limit` of
  `references`, `implementations`, `definitions`, `sources`, `search`, `dead_code` and `resolution`, and `max_files`. A
  bound the Rust layer sets through a builder or an option takes the public layer's own default when left out, which
  cuts nothing: `max_symbols`, `candidate_limit`, `call_limit`, `consumer_limit`, `seed_limit`, `hotspot_limit`, and
  every cap of a file query.
- **Zero.** A value sent means what the public layer makes of it, 0 included. `max_symbols`, `max_files` and every cap
  of a file query set no cap at 0; a graph query's `limit` answers the counts alone; a graph `depth` follows nothing,
  and a listing's `depth` walks the whole subtree; a `line` of 0 selects nothing and says `off_line`; a `threads` of 0
  answers `invalid_params`; and 0 is an id like any other. A range is the one exception: a `start_line` or an `end_line`
  of 0 reads as left out, since an empty range serves no caller. A Go params field whose 0 differs from leaving it out
  is a pointer, a required bound among them so that nil answers `invalid_params`; `binding_id` is not, as the binding
  picks it and starts at 1.
- **Absent counts.** A count absent from an answer reads as 0, except those a field says are counted only when asked or
  when the work ran: `dropped`, `fuzzy_total`, `matched`, `total_files` and `total_lines`. There, absent means not
  counted, and the Go field is a pointer.
- **What a count of 0 shows.** A count holds what the graph records, so 0 never shows that nothing uses a symbol; the
  `*_uses_unrecorded` flags name a kind its language records nowhere. `ruled_out: 0` states that no candidate was
  skipped, and not that an index answered.
- **Answers carry what they left out.** Every capped or bounded answer is an object with the engine's counts: `total`,
  `truncated`, `turned_away`, `unexpanded`, `below_confidence`, `passed_over`, `unresolved`, grep's account of every
  candidate and its `unsearched` ([ADR 1.11](/design-docs/adr/1.11-content-search-limits.md)), a listing's `excluded`
  and `unlisted`. An answer mirrors the engine's answer type, so it carries every count the engine's docs state, those
  [ADR 3.112](/design-docs/adr/3.112-file-scope-names.md), [ADR 3.37](/design-docs/adr/3.37-call-walk-cut-counts.md),
  [ADR 3.132](/design-docs/adr/3.132-data-symbol-reach.md), [ADR 3.110](/design-docs/adr/3.110-data-dead-code.md),
  [ADR 3.187](/design-docs/adr/3.187-reflected-definitions.md),
  [ADR 1.55](/design-docs/adr/1.55-path-query-exclusion.md) and
  [ADR 1.56](/design-docs/adr/1.56-ranking-match-count.md) add included; the view types of
  [`wire/graph.rs`](/crates/kartta-ffi/src/wire/graph.rs) and [`wire/files.rs`](/crates/kartta-ffi/src/wire/files.rs)
  name each field. A `references` part carries `ambiguous` at zero too. A `callers` part adds the `band` that a segment
  or a change gives a symbol, from its `reached`; a `callees` part has none, as it reaches no callers of the symbol. A
  file query that reads a stopped build's index carries `stopped_build`
  ([ADR 4.45](/design-docs/adr/4.45-wire-build-lifecycle.md)).
- **Counters.** The wire reports each cache and grep counter the built engine holds at no extra work, and nothing the
  engine would have to compute or keep for it. `build` and `stats` answer the index's `threads`, each language's
  `cached`, and a content index's `files`, `unindexed`, `trigrams` and `bytes`; `grep` answers every count of
  [`Matches`](/crates/kartta-fs/src/matches.rs). `kartta_cache::Stats` and `kartta_cache::Merged` stay off the wire: a
  build merges the store and drops the store and the merge's counts, so no built engine holds them. What a merge could
  not remove answers as an `errors` entry of kind `cache`.

## Why

- An object gives every count a place a bare array does not.
- A silently ignored option is worse than an error; an added answer field breaks no consumer that reads what it knows.
- The wire takes no default and mirrors the Rust layer (#1141). A default on the wire is a consumer's policy
  inside the public surface, and it would freeze with the wire; a consumer that wants defaults keeps its own, as the MCP
  does ([ADR 4.23](/design-docs/adr/4.23-mcp-default-limits.md)).
- The ABI maps the public layer thinly (#154). Reading 0 as left out added a rule of the wire's own, which took away the
  lifted caps and the counts-only answers the engine gives at no extra work, and Go's `omitempty` then parted from Node:
  `line: 0` selected every line from one and none from the other (#1045).
- Keys appear in answers as the rule of **Params and answers** adds them, so a new count is absent at 0 whatever the old
  ones do, and one sentence for the reader costs no bytes (#1045).
- These counters serve logs and metrics, and no behaviour depends on them (#1061). A key added later is additive and a
  key answered at the freeze stays (#125), so a counter the engine would have to keep waits for a consumer that acts on
  it.

## Consequences

- A consumer cannot watch the shared cache's size or its merges, and a search an unreadable index left to read every
  candidate answers as one with no index: accepted, as its answer is whole and only slower (#1045).
- A file query that leaves its bounds out, or sends 0, answers everything its path, globs and exclusions select, and a
  builder bound left out lists everything its walk reached: accepted, as the caller sets each bound (#1141).
- A Go caller takes the address of a variable to set such a field, since the module's `go 1.25` has no `new(expr)`:
  accepted.
- A passed-over symbol of a kind its graph does not record ranks last at `count: 0`, as a Rust field below a namesake
  function, and its candidate does not say so (#1113).
- A field's `total: 0` in a language that records some accesses says neither "unused" nor "unrecorded": dagor holds
  sites on 349 of 400 sampled C++ fields and 307 of 400 Python ones. Accepted: it needs a convention the language crates
  do not hold.

## Rejected

- **0 reads as left out** — no caller could lift a cap or ask for counts alone, and the bindings parted on `line`.
- **Refusing an id of 0** — Go's `omitempty` would still turn `CancelParams{Build: 0}` into a cancel of every call.
- **Keep a default for each bound left out** — every consumer inherits kartta's numbers, and a later change to one moves
  answers under a frozen wire (#1141).
- **Move the defaults into the engine** — grows the public layer for one consumer, and the MCP keeps its own
  ([ADR 4.23](/design-docs/adr/4.23-mcp-default-limits.md)).
- **Cut nothing when a graph bound is left out** — the Rust function takes it as an argument, and a walk with no depth
  can reach most of the graph (#1141).
- **Every count always present** — bytes on every answer, and a key added later stays absent at 0 all the same.
- **A `cache` object of the merge's counts** — every outcome and engine would keep them for keys nothing acts on.
- **Lookup counts: misses by cause, publishes, bytes** — `Store::get` counts nothing, so each adds work per file.
- **A `narrowing` reason on `grep`** — not a counter: the search holds an `Option` and not why it is empty, so the
  wire would freeze a new label set for logs alone.
- **`unexpanded` for a call path's `at_depth_bound`** — `unexpanded` also counts what the cap left and the root at a
  depth of 0, and a path's count neither, so one word would hold two meanings (#1047).
- **A rename of `truncated_seeds`** — it reads as `changed_symbols` beside it does, and any other word for a count of
  stopped walks stays a count (#1047).

## Revisit if

A consumer acts on a count the engine does not keep, or a Rust signature moves a bound between an argument and a
builder. High confidence: a new key is additive, so neither reopens the rule, only its list.
