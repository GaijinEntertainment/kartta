# Refresh the parts of a tree a caller names

- **Date:** 2026-10-15
- **Governs:** `crates/kartta-fs/src/index/scoped.rs` (`Index::refresh_paths`, `Index::parts_of`),
  `crates/kartta-fs/src/index/splice.rs`, `BuildError::Misspelled`, `kartta_fs::PathFault`
- **Pinned by:** `crates/kartta-fs/tests/refresh.rs` (the `refresh_paths` and `parts_of` tests),
  `crates/kartta-fs/src/index/splice.rs`

A consumer that follows the filesystem learns which paths changed, a few at a time, and a whole walk of
[ADR 1.15](/design-docs/adr/1.15-whole-tree-refresh.md) for each batch costs it the tree. `Index::refresh_paths` walks
again only the parts the paths name and splices them into the index in place, so a call costs the walk of those parts
plus one pass over the index's per-entry arrays, at a copy of those arrays held while it runs.

## Decision

- **What a call walks.** `Index::refresh_paths` walks again only the paths it is given, root-relative and
  forward-slash, and splices what they hold into the index in place. Each path names something that changed, and a
  directory is walked again with everything below it. A change no path names is not seen.
- **What it makes.** The result is what `Index::refresh` would make of those parts: the same ignore sources, pruned
  names, binary extensions, content index storage, stamps and threads, and the same ids, stamps and carrying of
  unchanged files ([ADR 1.40](/design-docs/adr/1.40-unchanged-file-detection.md)).
- **Refusals and failures.** A path that starts with `/` or `\`, starts with a drive such as `C:`, or holds a `\` or a
  `..` name returns `BuildError::Misspelled` with that `PathFault` before anything is walked; a `.` name and an empty
  name are no fault, so `./a` and `a//b` refresh `a` and `a/b`. This is the one rule of every refresh path: the wire's
  and the MCP server's refreshes answer with this error, the wire's before it reads the handle's state
  ([ADR 4.32](/design-docs/adr/4.32-wire-refresh.md)), and the MCP path arguments name a miss's fault by `PathFault`
  ([ADR 4.61](/design-docs/adr/4.61-mcp-path-arguments.md)). A returned error, a cancelled call included, leaves the
  index answering as it did.
- **Widening.** The splice replaces an indexed subtree, or inserts one where the tree order puts it, so a path's parent
  has to be an indexed directory that is still a directory on disk. Until it is, the path widens to the parent, so a
  file in a new directory walks the new directory. Each parent is checked once by each run of paths that asks about it
  ([ADR 1.46](/design-docs/adr/1.46-scoped-refresh-slow-mounts.md)). While ignore rules apply, a
  `.gitignore` widens to the directory that holds it, and so does a `.git` below the root, since both decide the rules
  of everything below that directory. With `IgnoreSources::None` a `.gitignore` is an ordinary file.
- **Skipped paths.** A path that names nothing the index holds, inside a `.git` or through a name in
  `BuildOptions::pruned_names`, is skipped; [`Index::refresh_paths`](/crates/kartta-fs/src/index/scoped.rs) lists the
  cases.
- **Order.** The parts are sorted into the index's tree order, and a part below another is dropped. A path that widens
  to the root makes the call a whole `Index::refresh`. `RefreshOutcome::walked` lists the parts walked, the empty path
  for the whole tree, so a consumer sees when a few changed paths cost a large directory or the whole tree.
- **Parts without a walk.** `Index::parts_of` answers the parts a call walks for the paths without walking them: each
  path widened and skipped as above, from what the index holds. It reads no ignore rule, so a file
  the rules hide in a directory the index holds still counts as a part. Nothing stale decides a part either: a part the
  index last saw ignored is walked under the rules read for this call. The engine's limit on named refreshes counts
  these parts ([ADR 3.80](/design-docs/adr/3.80-named-refresh-widening.md)).
- **Rules, spelling and threads.** The rules above a part are read again on every call, as
  [ADR 1.43](/design-docs/adr/1.43-scoped-refresh-rules.md) states, and a path's spelling follows the disk's, as
  [ADR 1.42](/design-docs/adr/1.42-refresh-path-spelling.md) states. Which thread takes a part and reads a file
  follows [ADR 1.45](/design-docs/adr/1.45-scoped-refresh-reads.md), and which asks the filesystem about the parts
  follows [ADR 1.46](/design-docs/adr/1.46-scoped-refresh-slow-mounts.md). What the outcome answers of the parts and of
  the positions they moved follows [ADR 1.44](/design-docs/adr/1.44-refresh-outcome-positions.md).
- **The splice.** The splice builds the new per-entry arrays beside the old ones and installs them at the end, after the
  content index is merged, the one step after the walk that can still fail, so a failure leaves the old index whole.
  Every entry outside the walked parts is copied once, a run between two parts at a time, so a call costs one pass over
  the per-entry arrays whatever the number of paths, plus the copy, held until the call returns. A refresh that kept
  every position copies the arrays too. The table for carrying files is built only for the positions inside the walked
  parts.
- **Calls that change nothing.** A call whose parts are neither indexed nor on disk, such as ignored paths and files
  already gone again, changes nothing and makes no pass, unless ids that a stopped refresh handed out wait to be
  retired.
- **Ids and content.** What a call reads goes into a content index segment of its own, merged by
  [ADR 1.41](/design-docs/adr/1.41-refresh-content-indexing.md)'s rule. The ids a stopped refresh handed out are retired
  by the next call that completes, whichever kind it is ([ADR 1.15](/design-docs/adr/1.15-whole-tree-refresh.md)).

## Why

- A whole walk costs a follower the tree for every batch: 46.6–51.2 s on the data volume's 5.5M entries, where a call
  naming one file took 6.5 ms (2026-10-15).
- Only the index knows which directories it holds, so it widens a path itself instead of refusing it.
- The index splits a path on `/` alone, so `/a.go` walked and extracted `a.go`, and `src\a.rs` named one entry at the
  root, matched nothing, and answered that nothing changed (#683, #1043).
- Counting parts rather than paths keeps a build that names its outputs by the thousand inside one ignored directory
  from turning into a whole refresh: 45,525–46,401 files inside a checkout's ignored `target/` took 18.0–36.6 ms as one
  part, against a whole refresh of 9.3–19.2 s on 6.2M entries (2026-10-20).
- The copy keeps the old index whole through the one step that can fail, and it stays below the build's peak: over 200
  one-file refreshes of a followed engine on 2.92M entries, the heap's highest point stayed 574 MiB under the build's
  peak (2026-10-21).

## Consequences

- A call holds a copy of the per-entry arrays until it returns, 176–180 MiB on the data volume, and makes it on every
  change a follower takes in (accepted).
- `parts_of` works the parts out once more for a call that names more paths than the engine's limit (accepted).
- A file the rules hide in a directory the index holds counts against the limit (accepted).
- A name that holds a `\` or starts with a drive, legal outside Windows, cannot be named; a refresh of the directory
  that holds it takes it in, as a watcher names it ([ADR 1.17](/design-docs/adr/1.17-change-notifications.md))
  (accepted).

## Rejected

- **Apply the change in place, moving each array's tail** — a content index merge that fails afterwards would leave a
  half-applied index, and the copy stays below the build's peak.
- **Write a refresh that kept every position into the arrays in place** — saves 5.7 ms of a 17 ms one-file call on
  2.92M entries, at a second way to apply a splice, about 100 lines, that an index keeping a content index cannot take;
  the heap it saves is given back on return and does not set the peak.
- **Keep a refresh's entries in a delta beside the arrays, merged later** — writing in place bounds what it saves at
  4.3 ms of the index's 8.0 ms on 2.92M entries, and a delta adds a lookup to every read of an entry.
- **Check a path's spelling in each surface that takes one** — the copies drifted: the wire refused a leading `/`
  alone while the MCP server refused all four faults, and the engine refused only `..` (#683).
- **Refuse a path that cannot be walked alone** — leaves every consumer to work out the widening, which needs the
  index's own view of what is indexed.
- **Apply the ignore rules before the engine counts the parts** — drops a hidden file in a held directory, at a read of
  the rules above every part made again by the walk; such files are few, 35 outside an ignored directory in the Go
  monorepo's checkout and none in the game-engine checkout's.

## Revisit if

The copy of the per-entry arrays sets a follower's peak, or becomes most of a call a consumer waits on. High
confidence: it stayed hundreds of MiB below the build's peak over 200 calls on 2.92M entries.

## History

- 2026-11-03 — Refusals and failures: an absolute, drive or `\` path walked the wrong part or nothing, and each
  surface kept its own copy of the check (#683, #1043)
- 2026-10-24 — Rules, spelling and threads: on a network mount the stats of a call's parts, one round trip after another
  on the calling thread, took most of the call (#339)
- 2026-10-20 — Parts without a walk: the engine counted every named path against its limit, so a build's outputs in
  an ignored directory turned a call into a whole refresh (#148)
