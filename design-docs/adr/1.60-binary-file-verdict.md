# Settle a file as binary by its extension, else by a NUL in its first 64 KiB

- **Date:** 2026-08-24
- **Governs:** `crates/kartta-fs/src/inspection.rs` (`PROBE`), `crates/kartta-fs/src/binary.rs` (`BUILTIN`),
  `crates/kartta-fs/src/scan.rs`, `Index::is_binary`
- **Pinned by:** `crates/kartta-fs/tests/index.rs` (`an_extension_settles_a_binary_file_without_the_file_being_read`,
  `a_nul_settles_a_file_whose_extension_does_not`, `a_nul_past_the_probe_leaves_the_file_reported_as_text`,
  `a_nul_at_the_last_probed_byte_still_settles_the_file`)

A binary verdict decides whether content search reads a file, and
[ADR 1.6](/design-docs/adr/1.6-file-facts-timing.md) reads it when asked. A file is settled by its extension where the
format is binary by construction, and otherwise by whether its first 64 KiB hold a NUL; the verdict describes that
prefix, not the whole file.

## Decision

- **Two layers, in order.** An extension in `BuildOptions::binary_extensions` answers binary with nothing opened. Every
  other file is binary when a NUL appears in its first 64 KiB, and text otherwise. An extension's answer is about the
  name, so it stands for a file since deleted or replaced.
  [ADR 1.7](/design-docs/adr/1.7-binary-extension-set.md) states how a caller composes the set.
- **The set is one-sided.** It says "binary, do not open" and never says text. A format joins the built-in set only by
  being binary by construction, so the set stays short rather than complete, with two exceptions. `svg` is XML, built
  in because it holds machine-emitted path data no reader uses, so an SVG reports binary unread. `dag` is Dagor's
  binary format and also names the text workflow files of the Condor job scheduler; a tree that holds those states a
  set of its own.
- **The verdict describes a prefix.** A file that is text for 64 KiB and binary after reports text.
- **One probe for every reader.** Wherever a reading build
  ([ADR 1.12](/design-docs/adr/1.12-build-content-reads.md)) or a content search probes a file, it probes the same
  64 KiB, `PROBE`, and publishes into the slot `is_binary` answers from, so one file has one verdict. A file a bounded
  search skips as larger than its `max_file_bytes` is not probed, and settles nothing.

## Why

- The two mistakes a set can make differ. A text format held in it is reported binary and passed over by every content
  search, a file nobody can find; a binary format left out costs one read, which finds the NUL and answers anyway.
- The built-in names settled 8.2% of the files on a home directory of 1,418,788 entries (2026-08-24, #13): the archives,
  media, disk images and model weights that hold the bulk of its bytes, so the costliest files settle for free.
- The probe's depth is chosen for what it catches, since its cost is flat: the open dominates, 57 µs per file at 1 MiB
  against 56 µs at 1 KiB. 64 KiB missed 1 of the 2,076 files holding a NUL among 10,026 sampled (2026-08-24, #13).
- 64 KiB is what `grep-searcher` reads at a time, so its own reading of a file agrees with this verdict.

## Consequences

- A file whose first NUL lies past 64 KiB reports text and is searched; one in 2,076 binary files of the sample.
  Accepted.
- Under the built-in set an SVG and a Condor `.dag` file are never searched. Accepted;
  [ADR 1.7](/design-docs/adr/1.7-binary-extension-set.md) lets a caller state a set without them.

## Rejected

- **A companion set of text extensions** — would have covered 43.1% of the same tree's files, and must claim a format
  never holds binary content, where `json`, `txt` and `xml` routinely carry an embedded blob; its mistake is the
  expensive one.
- **A shorter probe, 1 KiB or git's 8000 bytes** — costs the same and misses more of the sample's binary files.
- **A 256 KiB probe** — missed none in the sample, and disagrees with the searcher's 64 KiB read.

## Revisit if

A tree shows that the set's shape is wrong, not only its contents. Medium confidence; no such tree has turned up.
