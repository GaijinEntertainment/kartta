# Keep the tables a followed engine's resolvers find files in across refreshes

- **Status:** accepted
- **Date:** 2026-10-21
- **Updated:** 2026-10-21
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta/src/repository.rs` (`FileTables`, `IndexRepository::recording`,
  `IndexRepository::into_tables`), `crates/kartta/src/following.rs` (`Following::refresh`)
- **Pinned by:** `crates/kartta/src/repository.rs`
  (`tables_brought_through_each_refresh_are_those_of_the_index_it_left`)

The repository a resolver asks finds files by name, and by a path in another case
([ADR 3.30](/design-docs/adr/3.30-case-insensitive-path-lookup.md)), through tables it
builds from every entry of the index the first time a resolver asks. A followed engine keeps the tables a refresh's
repository built and moves them through the next refresh, so a one-file refresh pays no pass over every entry,
at eight bytes a regular file for each table a resolver asked for.

## Decision

- An engine built with stamps keeps the tables of files by name and by folded path that a refresh's repository built,
  and hands them to the next refresh's repository.
- A refresh that kept every position of the index
  ([ADR 1.44](/design-docs/adr/1.44-refresh-outcome-positions.md)) leaves them as they are. One
  that moved entries hashes the regular files its walked parts hold now, moves every kept entry outside those parts to
  its position through `RefreshOutcome::position_after`, and merges the two in hash order: a pass over each table.
- A table is built from every entry only the first time a refresh's resolver asks for it.
- The build's own tables are dropped with its repository; the first refresh that asks builds its own.

## Why

- Building the table by name from every entry took 222.7 ms of a one-file refresh of 305.9 ms at the median on 16 copies
  of the C++ game-engine tree, 2,923,440 entries (2026-10-21), paid by a refresh of any language whose resolver asks by
  name.
- The table of folded paths answers only a Quirrel or Blk path that names no file, which few refreshes ask, and a table
  kept from the build would be moved by every refresh that moves entries.

## Consequences

- Each kept table holds eight bytes for each regular file: 20.3 to 21.0 MiB past the first refresh that asked by name on
  the 16 copies' 2,746,048 files; accepted.
- A removed file, which built no table before since no resolver asked, now pays the move: 7.1 ms on the 16 copies,
  against the 239 ms an added file saves; accepted.

## Rejected

- **Keep the tables the build made** — saves the first refresh that asks its pass over every entry, at 42.1 MiB held
  from the build on the 16 copies, and every refresh that moves entries then moves the folded table too.
- **Keep the tables only across a refresh that kept every position**, building them again after one that moved entries
  — no move, but an added file pays the whole table again: 273.0 ms against 62.9 ms on the 16 copies.
- **Build the table by name again on each refresh, faster** — 16 to 19 ms on the index's 18 threads on the 16 copies,
  still a pass over every entry on every refresh that asks, where a kept table costs a refresh that kept every position
  nothing.

## Revisit if

Most refreshes stop asking by name, so the tables are held for refreshes that never read them; high confidence while
C++, DSHL, Go, the jsts family, PHP and Quirrel resolve by name.
