# Record TypeScript and JavaScript data sites through what a value declares

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-lang-jsts/src/walk.rs` (the hoist), `crates/kartta-lang-jsts/src/walk/uses.rs`,

  `a_destructuring_assignment_at_file_scope_writes_what_it_names_and_reads_its_defaults`)

A script spells no type for most values, so a TypeScript or JavaScript member use names an owner only where `this`, a
declaration or a name says which. The walk records a member use with the owner it can name and leaves the rest
unbound, and records each module value the module's code reads, its top level included, so `find_references` and
`dead_code` see what the code takes as a value, at the cost of the members of untyped values. A body's own values are
its locals, which no use outside it can take.

## Decision

- **Where.** Inside a definition and in a class's body, which the class makes, or for a class expression the name that
  binds it ([ADR 3.4](/design-docs/adr/3.4-jsts-extraction.md)): each member taken without a call, and each use of a
  variable or a constant the module imports or declares, before its declaration too, as a body runs once the module has
  run.
- **File scope.** Outside every definition, a callback no definition holds included, each use of such a name is a use at
  file scope, which keeps its name alone ([ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)): an object literal's,
  an argument's, `router` in `router.post()` and in `export default router`. A member there records no use. A name a
  top-level declaration binds is no use of it, each name of a binding pattern and a `var` of `for … in` included, nor is
  the name of an overload signature, of a namespace or of an index signature's parameter.
- **Writes.** The left of `=`, of a `for … in` or `of` that declares nothing, a name a destructuring pattern there
  holds, its default aside, and a key, plain, quoted or shorthand, of an object literal whose type is written beside it
  as an annotation, `as` or `satisfies`. `op=` and `++` update.
- **Owners.** A member names its owner through `this`, the own receiver inside a member and the class as a path in the
  class body; the one type its value's declaration spells, `p: Props`, `const cfg: Config` or `new Pool()`, or that the
  context of a parameter no annotation types spells ([ADR 3.101](/design-docs/adr/3.101-jsts-value-receivers.md)); or a
  class, an import or another module-level name by its name. TS/JS sets `UntypedMembers::Unbound`, so a member of a
  value whose declaration spells no type binds nothing and counts as ambiguous, and `ValueUses::Imported`
  ([ADR 3.173](/design-docs/adr/3.173-data-use-binding.md)).
- **A function or a class taken as a value.** A name the module binds at its top level by a `function`, `function*` or
  `class` declaration and spells without a call or `new`, `setTimeout(tick)`, `{ queryFn }` or `Component={Panel}`, is
  a bare use of it; a body that binds the name again hides it, and the declaration's own name is no use.
- **Blocks outside every body.** The hoist reads the statements of every block outside every body and namespace, `if`,
  `else`, `try`, `finally`, loops, `switch`, `with`, labels and bare blocks, though no expression. Each `var` there, a
  `for (var … in …)` or `of` included, is a module value inside its block and after it; a block's function is one where
  the file has no `import`, no `export` and no `"use strict"` prologue, and its name taken as a value is then a bare
  use of it, as a top-level function's is. A `let`, a `const` and a class stay the block's.
  As a call's receiver a block's `var` keeps its name after its block
  ([ADR 3.101](/design-docs/adr/3.101-jsts-value-receivers.md)), and a
  member read on it names the type its declaration spells, or none.
- **Locals.** A variable or a constant a function body declares by one name, unless a function or a class is its
  value, is a local of that body: no use binds it, and a bare call of its name is a local call of it where the
  innermost scope around the call declares it, before the call too, a `var`'s scope being its whole function. A
  member of it names the type its declaration spells, as above.

## Why

- The file's one field of the name was the member a value held in 32 of 50 sampled sites of the Go monorepo's
  TypeScript, too few for a tier (2026-10-18, #83).
- ECMAScript scopes a `var` to the function or the module around its block, and in a script that is not strict code
  Annex B.3.3 scopes a block's function the same way.
- A handler registered, a callback passed or a component passed as a property is the only use many functions have:
  `dead_code` judged them dead while each was taken as a value in its file.
- A body's value held as a symbol of the file took the reads and calls of its namesakes: each of the 75 hand-written
  pairs that keeping it local removes on the Go monorepo snapshot and SillyTavern bound a namesake (2026-10-24,
  #449).
- A module runs its top level, where `export default` evaluates its expression and a reference resolves its binding
  (ECMA-262 Exports, Runtime Semantics: Evaluation; Identifiers, Runtime Semantics: Evaluation), and those reads were
  the only use of 29 of 30 constants that #450 sampled on the same trees. Recording them adds 6,453 uses, 32 of 32
  sampled right, and takes 182 functions off `find_unused`'s list, 28 of 30 sampled through the site that means them,
  with none joining it (2026-11-02, #776).
- A top-level declaration binds a module name, so it would read as its own use. TypeScript merges a namespace with a
  function of its name (`types.ts` `FunctionExcludes`), and a `for … in` with no declaration assigns its left
  (ECMA-262 ForIn/OfBodyEvaluation).

## Consequences

- Left out: a member of a value whose declaration spells no type; a computed member `obj["k"]`; a member at file scope,
  2,073 on the Go monorepo snapshot and 22,056 on SillyTavern (2026-11-02). Accepted.
- `find_references` lists no use at file scope, which keeps its name alone; `find_callers` names its file (#544).
- A use at file scope reaches each namesake its file sees: 29 of the 182 functions leave the list through an imported
  name that an object literal's method shares, a method a library calls rather than the name's reader. Accepted.
- A read before a later `let` of the name in its block binds the module's value of the name. Accepted.
- A local's reads bind nothing, so `find_references` on it answers no site, saying that no read of a function's local
  is recorded ([ADR 4.22](/design-docs/adr/4.22-unrecorded-data-uses.md)), and `dead_code` leaves it unjudged.
  Accepted.
- A function or a class value a body declares stays a symbol of the file, which a namesake's call can still bind
  (#543).
- The hoist walks those statements once more, a cost the build's time and peak footprint do not show. Accepted.

## Rejected

- **The file's one field for an untyped member** — right in 32 of 50 sampled sites.
- **Binding a strict file's block functions as they are declared** — recorded not one more use on either tree measured;
  covering them whole means hoisting each block's declarations.

## Revisit if

The extraction records the type a value holds where no declaration spells it, so an untyped member could bind. Not
planned.
