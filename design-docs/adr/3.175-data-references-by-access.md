# Answer the references of a field or a value by access

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-graph/src/calls.rs`, `Graph::references`, `SiteQuery`
- **Pinned by:** `crates/kartta-graph/tests/graph/typed.rs`, `crates/kartta-graph/tests/graph/members.rs`

"Who reads or writes `Config.Timeout`?" asks for the sites of a field by what each does to it. The uses of
[ADR 3.34](/design-docs/adr/3.34-field-and-value-uses.md) answer it through `Graph::references`, which an
access narrows, and the answer counts every site it turned away; the counts ride on the resolution the query already
runs.

## Decision

- **Referents and access.** Fields, variables and constants are referents of `Graph::references`, which takes a
  `SiteQuery`: a confidence floor, a limit, and an optional access that keeps the readers (reads, updates and uses as a
  type), the writers (writes and updates), the updates or the uses as a type, and drops calls.
- **Sites.** A site carries its access, so a read and a write on one line are two sites.
- **Counts.** The answer counts every site by kind past the floor whatever the access keeps, the uses as a type apart
  from the reads ([ADR 3.174](/design-docs/adr/3.174-type-use-access.md)).
- **Ambiguous.** Its `ambiguous` counts, for a member, the uses of its name that the tiers left ambiguous, and, for any
  root, the calls of the name that `Walk::ambiguous` counts, so `find_references` and `find_callers` give one number for
  them.
- **Rendering.** [ADR 4.11](/design-docs/adr/4.11-mcp-reference-listing.md) states how `find_references` renders the
  sites.

## Why

- "Who sets it" and "where is it used" are both asked of a field, and an access on each site answers either from one
  query.
- An answer that leaves sites out says how many (CLAUDE.md, `<answers>`), and the resolution the query runs already
  holds each site's kind and every ambiguous one.

## Consequences

- An access narrows what is listed, not what is resolved: a query for the writers of a busy field binds its every use.
  Accepted.

## Rejected

- **Writes only** — answers "who sets" but not "where is it used".
- **A new tool for field uses** — `find_references` already promises the question, and a tool description costs every
  session.
- **One record per site in `find_references`** — up to 11 times the tokens where one function touches the field many
  times.

## Revisit if

Agents ask for a field's sites by a distinction the four accesses do not draw. Medium confidence.

## History

- 2026-10-23 — Counts: a value read through a type, `EventType.COMMENT_CREATED`, was labelled a use as a type and
  counted in `types=` (#278)
- 2026-10-20 — Ambiguous: `find_callers` answered "no callers" for a method whose calls the graph could not bind, while
  `find_references` said some calls may be missing, two tools disagreeing on one fact (#214)
- 2026-10-19 — Rendering: a hot field's answer at the 500-site cap took about 63 KB, roughly 16k tokens, for
  `Point3::x` on the C++ game-engine tree ([ADR 4.11](/design-docs/adr/4.11-mcp-reference-listing.md), #113)
