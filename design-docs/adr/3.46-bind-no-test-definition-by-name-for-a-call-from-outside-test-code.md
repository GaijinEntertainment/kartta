# Bind no test definition by name for a call from outside test code

The tiers that bind by name alone, the one callable of the name and the three proximity steps of ADR 3.7, find a test's
stub among the definitions of a product call's name. Test code is built apart from the code it tests: a call from
outside test code binds no test definition there, and the definition still counts, so no other definition is guessed
in its place, except the one type that a test's type stands in for.

## Decision

- A call from outside test code binds no test definition at the one callable of the name or at the three proximity
  steps.
- The test definition still counts among the definitions of its name. Where it is the one callable, the call binds
  nothing and counts as not admitted; where nearness picks it, as the nearest of its name, the call binds nothing and
  counts as ambiguous, and a definition farther away is not taken in its place.
- Where the definitions of the name outside test code are one type, or a constructor that stands for its type, such a
  call binds it at 60. A member does not take part in this exception.
- The scope tiers keep test code apart already: a package names its directory only through code outside test code
  (ADR 3.7), and a module's file shows a test definition only to its crate's tests (ADR 3.45).

## Why

- Every sampled product call that bound a test definition was wrong, in every language, as Python's `time.time()`
  binding a test's `FakeClock.time` (C++ game-engine tree, Go monorepo snapshot, this repository and tree-sitter,
  2026-10-23).
- A test function most often stubs a builtin or a library outside the graph, so the one function outside test code is
  no surer to be the one called. Code outside test code constructs no test type, so a test's type of the name stands in
  for the type outside it, or holds a fixture: the exception binds C++ pairs of which about 96% are right.

## Consequences

- Test support that a language's test rule reads as product code loses right pairs, about 5% of the C++ pairs the rule
  drops, breakpad's `synth_elf.cc` calling the `Section` members of `test_assembler.h` (#432); test directories written
  in another case, as `Tests/`, stay product code (#430).
- The type exception binds 106 wrong C++ pairs: c50's `Verbosity()` macro calls to Catch2's enum, breakpad's
  `std::wstring` calls to EASTL's typedef, and the 3ds Max plugin's SDK `Point3` calls.
- A scope tier can still bind a test definition for a product call at 80: a C++ header's call into a test file that
  includes it (#431), and Rust's same-file tier into an inline `mod tests` (#235).

## Rejected

- **Test definitions out of the tail, or out of nearness alone** — the call binds the namesakes the stub had shadowed:
  5,885 Quirrel `loc()` calls take a game's own `loc` for the native localizer (2026-10-23).
- **The one type or member** — 97% of the Python member pairs it adds are `TestContext.sleep` namesakes
  (2026-10-23).

## Revisit if

Every language's test rule reads its test-support files and test directories in any case (#430, #432), so that the one
function outside test code is more often the one called. Medium confidence.
