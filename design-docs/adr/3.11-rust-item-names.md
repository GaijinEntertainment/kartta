# Name Rust items by their module chain

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-rust/src/walk.rs`, `crates/kartta-lang-rust/src/walk/settle.rs`,
  `crates/kartta-lang-rust/src/walk/attributes.rs`, `crates/kartta-lang-rust/src/walk/imports.rs`
  (`assert_undeclared_impls`), `crates/kartta-lang-rust/src/resolve.rs` (test and generated files, `read_assertion`),
  `crates/kartta-lang-rust/src/lib.rs` (`CONVENTIONS`)
- **Pinned by:** `crates/kartta-lang-rust/tests/modules.rs`, `crates/kartta-lang-rust/tests/resolve.rs`,
  `crates/kartta-lang-rust/tests/extract.rs`, `crates/kartta-mcp/tests/graph.rs`
  (`find_implementations_lists_a_rust_impl_in_a_file_that_does_not_declare_its_type`,
  `find_implementations_lists_no_type_a_rust_impl_does_not_reach`)

A Rust file names what it declares through inline modules, `impl` blocks and paths. `kartta-lang-rust` qualifies an item
by the chain of its inline modules, never by the file's own module, which the file's bytes do not show, and owns a
member by the type its `impl` or trait names in the file;
[ADR 3.181](/design-docs/adr/3.181-rust-module-layout.md) finds the files its `mod` declarations reach.

## Decision

- **Names.** An item is qualified by the chain of its inline modules: an item of `mod a { mod b { .. } }` is
  `a::b::Worker`. A member of a `trait`, or of an `impl` whose target names a type, is owned by that type and qualified
  under it, `a::b::Worker::run`, and a field or a variant under its struct or enum. Outside a function body an `impl`
  for a tuple, `dyn` or function type opens no type, so its functions are free; inside a body the type as written owns
  them, `(u8, u8)::show`. A function of an `extern` block is free, except a wasm-bindgen method, constructor or static
  method, which the type it names owns. A `macro_rules!` keeps its bare name and no owner, and only `#[macro_export]`,
  with or without arguments, exports one, at its crate's root path whatever module defines it. A file's own module is
  no part of any qualified name. An item a function body declares inside an `impl` is qualified under the type but is
  no member of it. `pub` exports an item, `pub(self)` and `pub(in self)` do not.
  [The crate docs](/crates/kartta-lang-rust/src/lib.rs) state each wasm-bindgen form and the visibility of a trait's
  members and an enum's variants.
- **Impl owners and trait parents.** An impl's owner is the type its path names in the file, `impl super::W` inside
  `mod inner` of `mod a` naming `a::W` where the file declares `a::W`, and otherwise the path as written; a path through
  `crate::`, a leading `::` or a `super::` past the file's root keeps its spelling too. The owner settles after the
  walk, and what the walk recorded under the impl follows it, as the crate docs list; settling one impl renames nothing
  of another. `impl Trait for Type` adds `Trait` to the parents of the struct, enum or trait the file declares under
  that path, else under that name, the first the file declares; a path that names no declaration of the file,
  `impl Trait for other::Foo`, adds no parent. A primitive and the impl's own type parameter name no item.
- **Impl assertions.** An impl of a type the file does not declare is a statement of that type, which
  [ADR 3.20](/design-docs/adr/3.20-implementor-resolution.md) reads as an assertion. The walk spells each side as the
  path the file's `use` of its first segment gives, or keeps a bare name the file declares or a glob may bring. A bare
  name neither reaches is the prelude's or a macro's, and a path into the standard library or a crate outside the tree
  says nothing of the tree, so the impl records nothing. The resolver leaves the name a path ends at and the file that
  holds it; a type's path that runs past the module files, through an inline or a re-exported module, keeps its last
  name, and a trait's records nothing. A path whose last name the file also declares records nothing, as that name
  alone would read as the file's own type.
- **Calls and paths.** [ADR 3.56](/design-docs/adr/3.56-rust-call-receivers.md) decides what a call records as its
  receiver, and [ADR 3.50](/design-docs/adr/3.50-rust-cross-crate-paths.md),
  [ADR 3.51](/design-docs/adr/3.51-rust-crate-relative-paths.md) and
  [ADR 3.52](/design-docs/adr/3.52-rust-block-use-scope.md) which paths a `use`, a path call and a macro invocation
  keep for the resolver. Neither a `use` nor `extern crate` adds an include, and `extern crate` adds nothing.
- **Modules.** [ADR 3.181](/design-docs/adr/3.181-rust-module-layout.md) decides the file a `mod` declaration
  includes, the crate roots and the entry points.
- **Test and generated code.** An item is test code, with everything in it, when an attribute whose path ends in
  `test` or `bench` marks it, `#[tokio::test]` included, or a `cfg` gates it that holds only under `test`; a file-top
  `#![cfg(test)]` marks the file, and an inline module's inner gate the module. A `cfg` predicate is decided over every
  assignment of the atoms it repeats, an atom written once left unknown, as the crate docs show; past 12 repeated atoms
  the rest stay unknown. A file below a `tests` directory outside `src`, counted from the repository root or from any
  package around the file, is integration-test code. A test-gated `mod`, or any `mod` of a test file, makes the file it
  pulls in a test include, since that file is extracted on its own and cannot see the gate;
  [ADR 3.5](/design-docs/adr/3.5-graph-file-storage.md) decides when the graph marks such a file. A `*.gen.rs` or
  `*_generated.rs` file, or one with a `@generated` or `DO NOT EDIT` marker in its leading comments outside a backtick
  span, is generated code.
- **Conventions and fingerprint.** Rust's `Conventions` set `MemberCalls::ModulePaths`
  ([ADR 3.184](/design-docs/adr/3.184-rust-module-path-calls.md)), `NamespaceCalls::Unbound`
  ([ADR 3.44](/design-docs/adr/3.44-namespace-call-targets.md)), the standard library's most-called methods as
  `runtime_methods` and every public method of `core`, `alloc` and `std` with a `self` receiver as `library_methods`
  ([ADR 3.40](/design-docs/adr/3.40-runtime-method-calls.md)), `other` alone as an own-type receiver
  ([ADR 3.41](/design-docs/adr/3.41-own-owner-receivers.md)), `Receivers::ReturnPaths`
  ([ADR 3.55](/design-docs/adr/3.55-rust-parameter-receivers.md)), `CallsApart::Marked`
  ([ADR 3.177](/design-docs/adr/3.177-macro-invocation-binding.md)), `Twins::Every`, so a call its file or its
  receiver's type binds reaches every `cfg` branch's definition of its callee
  ([ADR 3.7](/design-docs/adr/3.7-call-resolution.md)), `IncludedRuntimeMembers::SpelledOwnOrExported`
  ([ADR 3.185](/design-docs/adr/3.185-included-runtime-members.md)), `OwnMembers::Unreached` and
  `TypeUses::Nowhere`.
  The fingerprint covers the walk and the grammar, as
  [ADR 3.120](/design-docs/adr/3.120-language-fingerprints.md) decides.

## Why

- A file's module path depends on its location and on its crate's `mod` tree, which the extraction from the bytes does
  not see; the inline-module chain is in the bytes and keeps two modules' same-named items apart.
- A scoped impl path leads where the file cannot tell, so matching it by its last segment hands the trait to an
  unrelated local type of that name.
- Rust places an impl anywhere in a crate: the orphan rule names the crate, never a module (the Reference,
  `items.impl.trait.orphan-rule`; `compiler/rustc_hir_analysis/src/coherence/orphan.rs:168`). Dropping such an impl
  answered that nothing implements a trait that had implementors, and asserting it took the one-deep pairs of wasmtime,
  rust-analyzer, tokio and this repository from 2,433 to 2,822, 30 of 30 sampled right (2026-11-02, #822).
- web-sys and js-sys declare their methods as `#[wasm_bindgen(method)]` functions whose `this` names the type, and
  their constructors and static methods as functions Rust calls through the type, `Number::is_nan(x)`: owning them
  binds 63 calls of js-sys 0.3.106 (2026-10-24, #357).
- A `macro_rules!` is in scope by text order rather than by path, and `#[macro_export]` places it at the crate root.
- The `cfg` check decides a predicate exactly however many atoms it writes once, and the bound of 12 repeated atoms
  keeps it under 2^12 assignments.

## Consequences

- A wasm-bindgen static method joins its type's namesakes, so a call on a value of a generic type whose trait declares
  that name, `promises.all()` under `T: PromiseTuple` beside `Promise::all`, binds nothing: 2 calls of js-sys (#357).
  Accepted.
- Past 12 repeated atoms a `cfg` check can miss a gate that holds through a thirteenth, or mark as test code an item no
  build compiles. Accepted.
- An impl stays unlisted where a macro or a generator declares a side, which no symbol holds, or where a re-export or a
  `cfg` leaves two types of the name in reach, as `OwnedRooted`: 393 impl heads on wasmtime, rust-analyzer and tokio
  whose two last names the tree declares somewhere, by text (2026-11-02). Accepted.
- A trait path into a module file that declares no type of the name, as a file that only `include!`s generated code,
  reads the one type of the name its crate reaches: a false pair where that type is a namesake (#1090).
- An impl in an inline module reads its names from the imports of the whole file, so two inline modules that import one
  name from two places leave the impl unlisted (#1092).

## Rejected

- **Matching a scoped impl target by its last segment** — gives `From` to the file's own `Error` for
  `impl From<Error> for io::Error`, and a trait implemented for `std::fs::DirEntry` to a local `DirEntry` (registry,
  2026-10-16, #36).
- **Reading a trait's path past the module files by its last name** — credits a generated module's `Host` to every
  namesake: 18 of 30 sampled pairs wrong on the five Rust trees (2026-11-02, #822).
- **Qualifying by the file's module path** — every name would change with the file's location, and the extraction
  could not carry it.
- **A `tests` directory in any case** — Cargo finds integration tests under `tests` alone, so a `Tests/` directory
  holds no target Cargo builds as a test.

## Revisit if

The extraction sees a crate's `mod` tree, so an item could carry the module path rustc gives it. High confidence it
does not: a file is extracted from its own bytes.
