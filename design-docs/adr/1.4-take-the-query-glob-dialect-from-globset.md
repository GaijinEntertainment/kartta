# Take the query glob dialect from globset

- **Status:** accepted
- **Date:** 2026-08-24
- **Revised:** 2026-10-13
- **Initiative:** `01-kartta-fs-port`

A glob in this crate appears in two unrelated places, and they are compatibility surfaces with different systems. The
one inside a `.gitignore` has to agree with git, because git wrote the file; that one stays with `gix-ignore`. The one a
caller types into a query has to agree with the tools that caller already uses — ripgrep, `fd`, an editor's file
picker — because that is where the pattern in their fingers comes from. Reading both off git's dialect would be the
category error of treating "a glob" as one concept.

The two dialects differ exactly where a typed query is fragile. Git's wildmatch has no `{a,b}` alternation, so
`*.{rs,toml}` is a literal filename nobody has. And it has no invalid pattern at all: every byte string parses, so
`src/[` compiles to a glob that matches nothing, and the caller's mistake comes back as an empty result rather than as
an error. A pattern written by a human at a prompt is exactly the input that must fail loudly, so the type that holds
one is fallibly constructed and holding it is proof its patterns parsed.

`globset` costs three crates the normal graph did not carry — itself at 3,292 lines, `aho-corasick` at 20,937 and
`regex-syntax` at 58,465. `regex-automata` was already there under `bstr` and gains features rather than entering, and
`log` is dropped with `default-features = false`. Against that, it compiles a whole pattern set into one matcher behind
literal, extension and prefix prefilters, so a query costs one pass per path rather than one pass per pattern, where
`gix-glob` matches sequentially. This is not a case where dependency weight is the deciding argument: the same survey
that put the walk in this workspace found the real weight elsewhere.

Three dialect rules are pinned rather than left to the library's defaults, because each one would otherwise vary:

- **A pattern is anchored at the index root**, which is what an indexed path is relative to.
- **A pattern containing `/` stops `*` at a segment boundary; one without `/` does not.** So `*.rs` names a file
  wherever it sits and `src/*.rs` names a place.
- **`\` escapes the next character on every platform.** The library's default makes it a separator on Windows and an
  escape on unix, which would give one pattern two meanings. An indexed path is forward-slash form everywhere, so `\`
  is never a separator here and is free to be the escape.

Matching is case-sensitive, where the fuzzy query folds case. A glob is a specification the caller wrote out and a
fuzzy query is a guess at one, so the two want opposite answers about a spelling that does not quite match.

The second half of the decision is what a filter may say. **A `Filter` selects.** It is a disjunction of patterns,
which makes a filter with no patterns match nothing rather than everything; selecting everything is a different
question and is spelled `None`. Removing is the opposite question and gets its own argument. **`exclude` names one
operation at two steps:** a build that excludes an entry never stores it, and a query that excludes an entry never
returns it. A query that excludes takes its exclusions as a second pattern set compiled in this same dialect, never as
`excludes` inside the filter. What git's rules hide stays `ignore`. The cap goes the same way: `max_results` is an
argument of the query, not a field of the filter, because a limit is not a predicate and two callers sharing one
compiled filter want their own.

## Considered Options

- **`gix-glob`, which is already in the graph** — zero new crates, and it is git's wildmatch run byte-faithfully,
  which is precisely why it is right for `.gitignore` and wrong here: no `{a,b}`, no invalid pattern, and sequential
  matching pattern by pattern.
- **Hand-roll the glob-to-regex translation** — around 55 lines for the common rules, and the value being bought is
  the dialect a caller already knows down to its corners. Hand-matching a dialect is where the silent divergences live,
  and a divergence here returns a wrong file list rather than an error.
- **Re-add the `ignore` crate for its matcher** — still git's dialect, and it drags `walkdir` and `same-file` back
  into a graph written to drop them.
- **A `Filter { includes, excludes, max_results }`** — three jobs in one value. A caller
  sharing a compiled filter would share its exclusions and its cap with it, and the cap would read as a predicate.
- **Leave exclusion to the caller** — a query that only selects is the smaller surface, and it moves the work rather
  than removing it. A caller that drops results after a capped query gets a short answer with a wrong `truncated`, so
  to stay correct it asks for everything, filters, and caps again. A listing cannot skip an excluded subtree from
  outside the index at all, so the caller walks it to throw it away.
- **Fold case in globs, to match the fuzzy query** — consistent on the surface and wrong underneath: it would make
  `*.rs` a pattern that cannot be written to mean what it says, on a case-sensitive filesystem where `.RS` is a
  different extension.
- **Regex queries instead of globs** — a strictly larger surface, unfamiliar to the caller for the common cases, and
  the two are not exclusive. If regex arrives it arrives beside this, under its own name.

Revisit if `gix-glob` grows alternation and pattern validation, or if compile time becomes the driver, in which case
the target named by the dependency survey is measured first.
