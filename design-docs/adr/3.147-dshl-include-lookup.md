# Resolve a DSHL include to the nearest file of its spelling

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-16
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-dshl/src/resolve.rs`, `crates/kartta-lang-dshl/src/walk.rs` (`include`,
  `hlsl_includes`)
- **Pinned by:** `crates/kartta-lang-dshl/tests/resolve.rs`

The shader compiler looks a DSHL include up under the include paths of the build configuration that compiles the file,
and which configuration that is belongs to the build, not to the repository. The resolver takes the file of the
include's spelling nearest the including file, which is the copy a game's own configuration finds first, and leaves an
include that two copies serve equally as an import rather than bind a game to another game's file.

## Decision

1. An `include` and an HLSL `#include "x"` or `#include <x>` that a line scan of an `hlsl { }` block reads are
   directives of one form, resolved alike.
2. A spelling that climbs, `../common.dshl`, is joined to the including file's directory and names that file where it
   exists.
3. Any other spelling, a leading `./` dropped, takes the files whose path ends in it at a directory boundary, and of
   several the one that shares the most leading directories with the including file. Two candidates equally near
   resolve to neither, and the include stays an import.
4. An include that resolves to the including file records nothing.

## Why

- The compiler looks an include up under each include path of the configuration, in order, then relative to its
  working directory, and never relative to the including file. A library shader is compiled by each game that lists
  it, each with its own include paths.
- A game's configuration puts its own shader directory first, as `samples/testGI` puts `./source`, and the copy there
  is the one nearest the game's files.
- A guess between two equally near copies binds a game's shader to another game's globals.

## Consequences

- An include of a file that each game keeps its own copy of, such as `shader_global.dshl`, held 7 times, stays an
  import where no copy is nearest: a library file that includes one is compiled against each copy in turn, so no single
  edge is right. 561 of the 3,145 includes of the public Dagor Engine shader tree stay imports (2026-10-16). Accepted.
- The tree's checkout holds no HLSL files, so the resolution of its 1,322 HLSL `#include` lines is not measured.
  Accepted.

## Rejected

- **Resolve an include only where one file has its spelling** — no edge is a guess, but the 286 includes that nearness
  resolves to the including game's own copy stay imports.
- **Read the build configurations** — the `.blk` files name the include paths, but a configuration includes others and
  is chosen per platform, and it still does not say which game's configuration compiles a library file; the resolver
  would become a model of the build system.
- **Record an edge to every candidate** — an include of `shader_global.dshl` would claim seven files, and the contract
  has no way to mark edges as alternatives.

## Revisit if

The build configuration becomes an input of the graph, or the contract can mark edges as alternatives. Not planned.
