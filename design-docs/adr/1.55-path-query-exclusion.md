# Exclude from a path query before its limit

- **Date:** 2026-08-24
- **Governs:** `crates/kartta-fs/src/filter.rs` (`Filter`), `crates/kartta-fs/src/glob.rs` (`GlobOptions`, `Capped`),
  `crates/kartta-fs/src/fuzzy.rs` (`FuzzyOptions`), `crates/kartta-fs/src/index.rs` (`Index::candidates`)
- **Pinned by:** `crates/kartta-fs/tests/index.rs`
  (`a_glob_exclusion_removes_a_file_and_a_directory_with_everything_beneath_it`,
  `a_glob_limit_stays_exact_under_an_exclusion`, `a_cut_glob_counts_every_match_and_exclusion_past_its_limit`,
  `a_fuzzy_exclusion_removes_a_file_and_a_directory_with_everything_beneath_it`),
  `crates/kartta-fs/src/fuzzy.rs::chunks_ranked_apart_answer_and_count_as_one_chunk_does`,
  `crates/kartta-fs/src/glob.rs::chunks_counted_apart_count_as_one_chunk_does`

A path query selects with one pattern set and leaves out with another, and its limit is an option of the query. The
index removes what an exclusion matches, a directory with its whole subtree, before the limit is spent, so a glob's
`truncated` stays exact and a ranking's order and `matched` count cover only what the exclusion leaves. A glob pays
one filter match per non-directory path beneath an excluded directory to count what the exclusion removed in the unit
of its answer.

## Decision

- **A filter selects.** A `Filter` is a disjunction of its patterns, so a filter with no patterns matches nothing;
  selecting everything is a different question, spelled `None` where an option takes a filter.
- **Leaving out.** Leaving out is its own argument: a second `Filter`, compiled in the same dialect
  ([ADR 1.4](/design-docs/adr/1.4-query-glob-dialect.md)), never `excludes` inside the selecting filter. What git's
  rules hide is `ignore` ([ADR 1.3](/design-docs/adr/1.3-ignore-sources.md)), and a name the build never indexes is
  pruned ([ADR 1.19](/design-docs/adr/1.19-pruned-names.md)).
- **The limit.** The limit is an option of the query (`limit` on `GlobOptions`, `FuzzyOptions` and `ListOptions`),
  never a field of the filter.
- **Excluding before the limit.** `GlobOptions::exclude` and `FuzzyOptions::exclude` remove a file the exclusion
  matches, and a directory it matches together with everything beneath it, before the limit is spent. A listing's
  exclusion is [ADR 1.8](/design-docs/adr/1.8-listing-counts.md)'s, a content search's
  [ADR 1.11](/design-docs/adr/1.11-content-search-limits.md)'s.
- **A ranking skips the subtree.** A ranking neither matches nor scores a path beneath an excluded directory. The index
  is depth-first, so the subtree is one run, which the query skips by binary search. A run of the parallel ranking that
  starts inside an excluded directory reads its first path to find that directory among its ancestors.
- **Counting what a glob excluded.** A glob matches its filter against each non-directory path beneath an excluded
  directory once, and `Capped::excluded` counts the non-directory paths the filter selects that the exclusion removed.
  An excluded directory is no match of its own. The count covers the whole index, past the cut included, as the glob's
  count of matches does ([ADR 1.5](/design-docs/adr/1.5-query-caps.md)): the runs that count the matches past the cut
  count what the exclusion removed there.

## Why

- A limit is not a predicate, and two callers sharing one compiled filter each want their own limit and their own
  exclusions.
- A caller that drops paths after a capped query gets a short answer whose `truncated` describes the paths before the
  drop. To stay correct it lifts the cap and holds every match: 64 MiB for a glob of `**` excluding `**/node_modules`
  on the macOS data volume, 6.2M entries, which the index answers under a cap of 100 in 22 KiB (2026-10-20, #152).
- A caller's filter over the returned file paths never removes what lies beneath a matched directory: `**/Library`
  removed none of the 846K files there (2026-10-20, #152).
- A count of what a cut answer left out is only worth reading in the unit of the answer, and a glob answers matches.
- A count of exclusions that ended at the cut, beside a count of matches that does not, read as covering one tree:
  a cut list of the Go monorepo snapshot counted 28 excluded paths where its uncut list counted 75 (2026-11-27,
  #1347).

## Consequences

A query that excludes matches the exclusion against each directory it visits and each file its filter selects. Beneath
an excluded directory a glob still pays its one filter match per non-directory path, so the exclusion saves it only the
rest of that work; a ranking, which counts no exclusions, skips the subtree unmatched. Accepted.

## Rejected

- **A `Filter { includes, excludes, max_results }`** — three jobs in one value: a caller sharing a compiled filter
  would share its exclusions and its cap, and the cap would read as a predicate.
- **Leaving exclusion to the caller** — the smaller surface, and it moves the work rather than removing it: the caller
  asks for everything, filters and caps again, and walks a subtree only to throw it away.
- **Counting an excluded directory's run, as a listing does** — free, since the skip lands on the run's end, and it
  states entries as matches: 1,083,753 for about 1,870 matching paths on the data volume (2026-10-20).

## Revisit if

The one match per path beneath an excluded directory shows in a glob's profile on a large tree. Moderate confidence:
measured only for `**/*.rs` capped at 100 excluding each home's `Library` and `.cache`.

## History

- 2026-11-27 — Counting what a glob excluded: the count ended at the cut while the glob's count of matches covered the
  whole index, so one answer's two counts covered different trees (#1347)
- 2026-10-20 — Excluding before the limit and Counting what a glob excluded: a glob and a ranking took no exclusion,
  so every caller dropped excluded paths after the cap, which Leaving out rejects, and lifted the cap to stay
  correct (#152)
- 2026-10-13 — Leaving out: a ban on exclusion at query time rested on naming alone, and pushed callers into listing
  everything and dropping entries themselves, with a wrong `truncated` whenever a cap was involved (#15)
