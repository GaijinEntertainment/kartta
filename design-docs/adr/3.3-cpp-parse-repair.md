# Repair what the C++ grammar cannot parse instead of vendoring it

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-cpp/src/repair.rs`, `crates/kartta-lang-cpp/src/lib.rs` (`extract`, `EXTENSIONS`),
  `crates/kartta-lang-cpp/Cargo.toml` (`tree-sitter-cpp`)
- **Pinned by:** the tests of `crates/kartta-lang-cpp/src/repair.rs` beside those
  [ADR 3.71](/design-docs/adr/3.71-cpp-brace-splitting-conditionals.md),
  [ADR 3.169](/design-docs/adr/3.169-cpp-second-parse-repairs.md) and
  [ADR 3.178](/design-docs/adr/3.178-cpp-namespace-macros.md) name, and those of `crates/kartta-lang-cpp/src/walk.rs`
  named for a macro, a class head or a lone macro line

`tree-sitter-cpp`'s error recovery does not stay local: one construct the grammar cannot reduce can take every
declaration after it to the end of the file. The parser reads a repaired copy of the file instead of a patched grammar,
at the price of a byte scan per file and a second parse of the few files whose first tree shows a misreading.

## Decision

- **The parser reads a repaired copy; the walk reads the original.** `tree-sitter-cpp` is pinned at 0.23.4. A repair
  blanks bytes to spaces and keeps every newline, so the copy has the original's length and every node position
  addresses the original bytes, from which every name, signature and text is taken. The copy is made at the first
  blank, so a file with nothing to repair allocates nothing. A repair also fires inside comments and string literals,
  where it is inert. [ADR 3.70](/design-docs/adr/3.70-cpp-macro-declarators.md) reads a declarator a macro misjoins
  without a repair, and [ADR 3.31](/design-docs/adr/3.31-cpp-numeric-tables.md) blanks a table's data.
- **Before the first parse.** One pass over the bytes blanks:
  - **An empty trailing argument.** The comma of an empty trailing call argument, `CHECK(ptr, )`, which turns it into
    the equivalent `CHECK(ptr )`.
  - **A reserved calling convention.** `__cdecl`, `__clrcall`, `__stdcall`, `__fastcall`, `__thiscall` and
    `__vectorcall`, which the grammar reads only before a free definition's declarator, outside a directive's lines.
    A calling convention written as a macro is read in the walk
    ([ADR 3.70](/design-docs/adr/3.70-cpp-macro-declarators.md)).
  - **A class head's macros.** In a class head that goes on to a base list or a body, the upper-case macros before the
    name, `class TORRENT_EXPORT torrent : base`, macro calls among them, `struct DECLSPEC_ALIGN(16) N {`, and the
    macros after the name where the name shares the key's line, `class Builder FLATBUFFERS_FINAL_CLASS {`, on any
    line; where the name stands on a later line than the key, the macros after it are left, since a key that ends a
    comment line, `// a list class`, would take the next line's key for the name. The scan reads past a
    specialization's arguments, `struct RTM_DEPRECATED("...") float_traits<float> {`, holding a parenthesized
    expression's `<` and `>` apart, and leaves the attributes the grammar reads, `alignas`, `__declspec`,
    `__attribute__` and `[[...]]`, and `struct STAT st;`.
  - **A macro call around the key.** `ATTRIBUTE_ALIGNED16(class) btCollisionObject {`: its name and parenthesis before
    the key and the parenthesis after it, where one name and a body or a base list follow.
  - **A lone macro line above a head.** A macro name alone on its line where the code below it, past comments and such
    lines, opens a `template`, a class key or a `namespace`, `RTM_IMPL_FILE_PRAGMA_PUSH` above `namespace rtm {`, and
    one at a namespace's edges, as in [ADR 3.178](/design-docs/adr/3.178-cpp-namespace-macros.md). Above a function
    it is read as the return type and stays, as do a macro call alone on its line, `TABLE_END(name)`, and a
    `#define`'s continuation.
  - **A macro before a constructor's initializer list.** The macro that opens a line, past its specifiers, where a
    scoped name, its parameters and a `:` follow on from that line, `PX_INLINE Sc::Shape::Shape(bool b)` `: mFlags(0)`.
    The definition's signature starts past the macro. A macro before a constructor with a plain body is left to the
    walk ([ADR 3.70](/design-docs/adr/3.70-cpp-macro-declarators.md)), and one before an unscoped name to the second
    parse ([ADR 3.169](/design-docs/adr/3.169-cpp-second-parse-repairs.md)).
  - **A head each branch writes.** A conditional with a later branch that a `{` follows, whose branches each hold one
    head of the same names, the scoped names before its first and its last outermost `(` or the `:` of an initializer
    list, and no `;`, brace or conditional, `#ifdef A` `void f(int a)` `#else` `void f(int a, int b)` `#endif` `{`: its
    opening directive, and everything from its first later branch through its `#endif`. Heads of two names stay, and
    so does a branch whose first `(` closes a macro's name, `ATTRIBUTE_ALIGNED16(class)`. A brace, a return type or a
    statement a branch splits is [ADR 3.71](/design-docs/adr/3.71-cpp-brace-splitting-conditionals.md)'s.
- **After the first parse.** The repairs read from the first tree's errors are those of
  [ADR 3.169](/design-docs/adr/3.169-cpp-second-parse-repairs.md) and
  [ADR 3.71](/design-docs/adr/3.71-cpp-brace-splitting-conditionals.md).
- **A restrict qualifier on a reference parameter stays unparsed.** `const Event &__restrict evt` is a GCC and MSVC
  extension the grammar takes only after `*`.
- **The claimed extensions are measured.** `cpp`, `cc`, `cxx`, `h`, `hpp`, `hxx`, `hh`, `c`, `inl` and `inc`, in any
  letter case. Objective-C `m`, Objective-C++ `mm` and CUDA `cu` and `cuh` are not claimed, each until it is measured
  again.
- **What the walk names and records.** It is decided apart: names in
  [ADR 3.72](/design-docs/adr/3.72-cpp-name-qualification.md), includes in
  [ADR 3.73](/design-docs/adr/3.73-cpp-include-resolution.md), declarations in
  [ADR 3.74](/design-docs/adr/3.74-cpp-declaration-links.md), receivers and calls in
  [ADR 3.75](/design-docs/adr/3.75-cpp-call-receivers.md), and the shared generated-code banner in
  [ADR 3.76](/design-docs/adr/3.76-generated-code-markers.md).

## Why

- A gap is worth closing only where it costs symbols: 30.31% of 17,408 first-party C++ files carried a parse error
  (2026-10-16, #30), and one `CHECK(ptr, )` line cost a file the 50 symbols after it.
- A blank invents no token and keeps every position, so no repaired byte can reach a symbol, a call or a snippet, and
  a repair firing inside a comment or a string changes nothing.
- What the grammar misreads as a heading, a class head or a namespace, fails with errors of a row or two, under the
  spill gate of [ADR 3.169](/design-docs/adr/3.169-cpp-second-parse-repairs.md), and the bytes alone show it;
  repaired before the first parse, it costs a check at each line's start in the pass the empty argument already makes,
  and saves second parses.
- A reserved calling convention in a prototype or a class body, `void __cdecl f(int a);`, is a syntax error whose
  recovery can take the declaration after it; blanking it kept 135 of the 410 such functions of the game-engine tree
  that the walk's reading left lost, at a check per word that starts with `_` (2026-10-24, #402). In a `#define`'s
  value a blank leaves trailing spaces, and the directive takes the `#elif` below it.
- An initializer list takes no type, so a macro read as the constructor's type turns the first initializer into the
  function; that lost 115 of the game-engine tree's 319 such constructors, and blanking the macro leaves 1, which a
  template parameter loses with no macro at all (2026-10-31, #409).
- The grammar reads the `#endif` of a head each branch writes as an error inside the last branch's definition, so the
  conditional stays open past it, and the class around it is lost or the tree fails at its top level, which flattens
  a class that shows a misread member, where the bytes alone show the head. The first branch alone is a whole definition
  of the same name: 128 game-engine files change, with 913 symbols added, 747 of them methods, and 706 regaining their
  class or namespace, 30 of 30 sampled right on each side (2026-10-31, #410).

## Consequences

- A macro alone on its line above a member that writes its own return type stays, so the 9 `TORRENT_DEPRECATED`
  members of libtorrent's `torrent_info` are read as fields (#438).
- An `#include` inside a class body is not recorded (#440).
- The constructor's macro is looked for at every line's start, 0.48% of the extraction's samples on the game-engine
  tree (2026-10-31, #409). Accepted: 114 constructors kept, and a gate on the line's first byte saved nothing.
- A head each branch writes loses what only a later branch writes: `if (macosx_get_desktop_res(w, h))` stands for
  `if (d3d::get_render_target_size(w, h, 0, 0))`, and the signature of a definition runs on through the `#endif`.
  Accepted, as for [ADR 3.71](/design-docs/adr/3.71-cpp-brace-splitting-conditionals.md): the definitions around such
  a conditional outweigh it, and the second parses saved leave C++ extraction 0.37% fewer instructions on the
  game-engine tree, with a directive check at each line's start and a scan of a conditional's branches up to their
  first `;` or brace (2026-10-31, #410).
- Heads of two names keep the misreading, so `main` of `#if _TARGET_SCARLETT` and the code around it read as before.
  Accepted.

## Rejected

- **Vendor and patch the grammar** — regenerating it needs the C grammar vendored as well, both then move with
  tree-sitter in lockstep and every patch is re-applied on each update; for `&__restrict`, patching took the error
  share from 30.31% to 28.48% and recovered one symbol, because the reference parameter's error stays local (#30).
- **Delete the offending construct** — filling the empty slot gains as much, and blanking only the macro keeps the
  declaration it annotates, which deleting the line loses.
- **Blank a class head's macros, or a lone macro line, after the first parse** — recovers 8 of 48 heads with a macro
  after the name and 53 of 130 around the key, and parses 3,135 files twice against 1,596 (2026-10-23, #376, #403).
- **Blank a lone macro line above a member with its own return type** — brings back 8 of the 9 `torrent_info` members,
  loses 9 members of 4 other files and moves about 1,400 definitions' start to the line below their macro (#376, #403).
- **Join a macro's constructor to its body in the walk alone** — kept 8 of the 120 sites it had lost (#394, #409).
- **Take the first branch of a head whatever each branch names** — changes 183 game-engine files and loses 232 symbols
  where one name in each branch loses 94, `main` of `#if _TARGET_SCARLETT` and every `pcre16_*` among them (#410).
- **Blank a macro before a destructor** — names `AdjEdge`'s destructor, and leaves `PxTriangle`'s class lost, since the
  conditional and not the macro fails the tree around it (#410).
- **Claim `mm`, `m`, `cu` and `cuh`** — 72%, 90%, 96% and 100% of such files carried an error, at 990, 95 and under
  300 symbols per MB, where `hh` holds 1,968 and `inc` 3,112 (2026-10-16, #30).

## Revisit if

`tree-sitter-cpp` publishes a release, or the share of files with a parse error grows on a new code base. High
confidence that 0.23.4 stays the latest for the near term.

## History

- 2026-10-31 — A head each branch writes: read with the first branch taken before the first parse, since such a
  conditional lost the class around it or failed the tree, and an in-class destructor kept its class's name (#410)
- 2026-10-31 — A macro before a constructor's initializer list: blanked before the first parse, since the definition
  was lost or named after its first initializer (#409)
- 2026-10-24 — A reserved calling convention: blanked before the first parse, since a prototype or a class member that
  wrote one was lost (#402)
- 2026-10-23 — A class head's macros, A macro call around the key, A lone macro line above a head: blanked before the
  first parse, since a class whose head held an export macro, or that a lone macro line preceded, lost its name or its
  symbol, 638 of 1,537 such heads on the game-engine tree, and its members read as free functions (#376, #403)
- 2026-10-19 — A class head's macros: a macro call there is blanked too, since a head it hid, `struct
  DECLSPEC_ALIGN(16) N`, read the class's methods as free functions (#114)
- 2026-10-17 — A class head's macros: an export or visibility macro between the key and the name is blanked, since the
  class's members read as free functions (#67)
