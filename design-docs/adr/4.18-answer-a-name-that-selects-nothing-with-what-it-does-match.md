# Answer a name that selects nothing with what it does match

- **Status:** accepted
- **Date:** 2026-10-19
- **Updated:** 2026-10-23
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta/src/reading.rs` (`unmatched`, `selects_as_callers`), `crates/kartta-mcp/src/render.rs`
  (`unresolved`, `named_instead`, `did_you_mean`), `crates/kartta-mcp/src/server.rs` (`unmatched`, `suggestions`)
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`a_name_that_picks_no_one_of_several_lists_them_and_implementations_name_the_type_they_took`,
  `a_line_picks_one_of_several_symbols_of_a_name_in_one_file`,
  `a_name_several_symbols_of_one_file_end_with_names_the_line_that_picks_one`,
  `a_call_path_lists_each_ends_passed_over_symbols_and_what_an_unselected_end_matches`,
  `read_definitions_answers_an_unknown_name_with_close_alternatives`),
  `crates/kartta-mcp/tests/names.rs::a_name_one_character_from_a_definition_suggests_that_definition_first`

"No symbol matches" leaves an agent to guess why: the name may be shared by several definitions, sit outside the path
prefix, or be a typo. A symbol tool whose name selects nothing answers the definitions that say why, from one engine
lookup the C ABI shares, and falls back to the search's best hits only where that lookup finds nothing.

## Decision

- **Which tools.** `find_callers`, `find_callees`, `find_references`, `find_implementations`, `find_call_path` and
  `read_definitions`, after the readings of
  [ADR 3.48](./3.48-read-a-qualified-name-with-the-other-owner-separator-when-it-selects-nothing.md) and
  [ADR 3.49](./3.49-select-a-name-whose-last-part-holds-a-separator-by-its-longer-parts.md). `find_call_path` answers
  so, under `<from>` or `<to>`, for each end that selects nothing in any graph searched, tested as `find_callers`
  selects, ranking none.
- **In order,** among the definitions of the kinds the tool selects, at most 5 listed:
  - several under the path prefix and on the line end with the name and the tool picks none of them: "N definitions
    end with this name and it picks none of them - a longer name, or path_prefix with one's file and line with its
    line, picks one", with `<candidate/>` records;
  - the name names some outside the prefix or off the line and at most one under and on them: "no definition of this
    name is under path_prefix - N are elsewhere", with `<candidate/>` records, or, for a selector with a line, "no
    definition of this name under path_prefix starts on line L - N are elsewhere", without "under path_prefix" where
    none was given;
  - the name names no definition of any kind, and names one edit from it do: "no symbol matches - did you mean", with
    `<suggestion/>` records, `one_edit=` counting them all;
  - otherwise the search's best hits as `<suggestion/>` records, none named the name itself, run only then.
- **`find_symbols`.** When `unmatched=` names a word of its query and the whole query names nothing, the definitions
  named one edit from the whole query come as `<suggestion/>` records ahead of its hits, counted by `one_edit=`. A query
  of several words is a word search, so a word of it gets none; that word asked alone does.
- **One lookup.** The cases are `kartta::unmatched` and the ends `kartta::selects_as_callers`, which the C ABI's symbol
  methods call too and name in `unmatched`
  ([ADR 4.34](./4.34-say-how-a-symbol-method-read-a-name-and-why-it-matched-nothing.md)); the search's best hits are
  these tools' alone, which the wire leaves to its `search`. The one-edit lookup is
  [ADR 3.131](./3.131-answer-a-missed-name-with-the-definitions-one-edit-from-it.md)'s.
- The `find_symbols` description says what an edit is and which characters replace or are added; every tool's says what
  `one_edit=` counts.

## Why

- Each case names the call that answers: a longer name, a path prefix and a line, or the spelling meant. The hint names
  the line whatever the listed share, since a file that holds two of them can be past the five listed.
- On this repository `find_references` of `#handel` answered "no symbol matches" where `#handle` is a field, because
  the search's fill-up forgives characters left out alone (ADR 3.21). Asked of 500 typos on the C++ game-engine tree,
  the meant definition is among the alternatives for 493 (2026-10-21).
- A name that selects runs none of it; a miss the lookup answers costs a lookup per graph and runs no search.

## Consequences

- A typo one edit from several names lists them all, `max` and `qmax` for `mqax`; an agent picks by kind and place.
  Accepted.
- A name one edit from nothing still pays both the lookup and the search. Accepted.
- Of several that start on one line of one file, as in minified code, the hint's path prefix and line pick none; only a
  longer name does (ADR 3.35). Accepted.

## Rejected

- **"No symbol matches" with a hint to `find_symbols`** — the agent spends a search to learn what the engine already
  held.
- **The search's best hits as the only alternatives** — they forgive left-out characters only, so a swapped or
  replaced character answered unrelated definitions.

## Revisit if

Agents' misses are mostly something other than a shared name, a prefix or a single edit, so the lookup rarely answers
and the search runs after it.
