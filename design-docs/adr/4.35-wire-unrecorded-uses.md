# Flag a references part where its language records none of its symbol's uses

- **Date:** 2026-10-20
- **Governs:** `crates/kartta-ffi/src/wire/graph.rs` (`ReferencesView`), `bindings/go/wire/graph.go`
  (`References.TypeUsesUnrecorded`, `References.DataUsesUnrecorded`)
- **Pinned by:** `crates/kartta-ffi/tests/golden/references.json`,
  `crates/kartta-ffi/tests/golden/references-unrecorded_data.json`, `crates/kartta-ffi/tests/dispatch.rs`
  (`every_data_kind_a_language_states_unrecorded_flags_its_references`,
  `a_rust_field_with_no_recorded_site_is_told_from_an_unused_constant`,
  `a_function_s_local_value_flags_its_references_and_a_module_value_does_not`)

Several languages record no use of a type where code names it as one, or no read or write of a data kind, so a
`references` answer of [ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md) for such a symbol held no site and a `total` of 0,
which a consumer reads as an unused symbol. The part says so with one flag per gap, read from what the graph already
holds, so only the parts it is true of grow.

## Decision

- **The type flag.** A `references` part whose `symbol` is a type, by `SymbolKind::is_type`, in a graph whose
  conventions state `TypeUses::Nowhere` ([ADR 3.1](/design-docs/adr/3.1-language-plugin-contract.md)), carries
  `type_uses_unrecorded`, true: its `sites` hold only the calls that name the type and, where the language records them,
  its reads as a value. Rust, C and C++, TypeScript and JavaScript, PHP, Ruby, daslang and Puppet state it.
- **The data flag.** A `references` part whose `symbol` has a kind the graph's `Conventions::unrecorded_data` lists
  ([ADR 4.22](/design-docs/adr/4.22-unrecorded-data-uses.md)) carries `data_uses_unrecorded`, true: its `sites` hold
  only uses that spell the name as something else, as a call does. The kind is the `symbol`'s own, so the flag names
  none. A variable or a constant local to a function body, by `References::local_value`, carries it too: no graph
  records its reads and writes, and its `sites` hold only its calls from inside that body.
- **Absent otherwise.** Each key is absent where it would say nothing: `type_uses_unrecorded` for the part of a type
  whose language records some or every use of one, as Go, Python, DSHL and Quirrel do, and for every symbol that is no
  type; `data_uses_unrecorded` for every kind its language does not list, but a body's local value. A language that
  records some uses, as Python records an annotation inside a body and C++ a member access, carries no key: its sites
  hold the uses it records.
- **The type test.** `SymbolKind::is_type` is the test the graph tells a type by, which the MCP tools read too
  ([ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md)), so both surfaces tell a type the same way.
- **The bindings.** Go's `wire.References.TypeUsesUnrecorded` and `wire.References.DataUsesUnrecorded` and the
  TypeScript type carry them.

## Why

- What a consumer acts on is whether one part's `sites` can stand for every use of the symbol. A flag on the part reads
  the answer the consumer holds and needs no list of kartta's languages, which would fall behind them.
- Every type the key marked in the samples was true, 27 of 27 distinct types (C++ game-engine tree and Go monorepo
  snapshot, 2026-10-20, #282).
- Of 30 sampled parts the data flag marked, all with no site, 25 name their symbol again in its own file (this
  repository, Symfony, Rails and the C++ game-engine tree, 2026-11-02, #529).
- A new key is additive under [ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md), so the data flag breaks no consumer.
- The test costs a read of the graph's conventions and a look through a list of at most three kinds per part, with no
  allocation.

## Consequences

- A symbol under a flag still answers no site for those uses; the flag says the sites are partial, not where the uses
  are: accepted.
- A field of a language that records some field accesses carries no flag, so its `total` of 0 still says nothing of the
  accesses that language leaves out, because such a language states no gap of its own for the wire to read (#1045).
- A definition in `candidates` carries no flag, so a passed-over field's `count` of 0 is the same gap on a smaller
  surface, with its `kind` on the record (#1045).

## Rejected

- **The conventions' label on every type's part, `type_uses` as `nowhere`, `partial` or `every`** — every Go and Python
  type's part gains a key, and a consumer learns what each label leaves out to act on the one value that matters.
- **The conventions per graph in `stats`** — a consumer joins them to each part by its graph and has to know they bear
  on a type's sites alone.
- **A note in words, as the MCP answer carries** — the wire answers facts a program reads;
  [ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md) and
  [ADR 4.22](/design-docs/adr/4.22-unrecorded-data-uses.md) word them for an agent.
- **One key for both gaps** — it would rename a key consumers read, and a type's part and a data symbol's differ in what
  their `sites` hold.
- **A key of its own for a body's local value** — its `sites` hold what a listed kind's hold, uses that spell the name
  as something else, so a consumer acts on both the same way and would read two keys for one fact.

## Revisit if

Every shipped language records the uses of a type as a type and the reads and writes of every data kind it extracts, so
no graph states `TypeUses::Nowhere` or lists a kind. High confidence: several language families state each.
