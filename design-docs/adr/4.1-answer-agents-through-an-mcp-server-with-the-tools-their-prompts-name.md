# Answer agents through an MCP server with the tools their prompts already name

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-23
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-mcp` (`src/server.rs`, `src/params.rs`, `src/render.rs`, `src/render/`, `src/llmxml.rs`,
  `src/config.rs`)
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`, `crates/kartta-mcp/tests/graph.rs`

Agents reach a code graph through MCP, and the prompts in use name the tools, pass their arguments and read their
envelopes. kartta answers under those names and envelopes, so those prompts work unchanged, and adds as attributes the
counts of what each answer left out. Every tool is description text each session pays for, so a tool exists only for a
question no other tool answers in one call.

## Decision

**The server.** `kartta-mcp` is a binary crate with a library part, built on the engine directly, with no C ABI between
them. It speaks MCP over stdio through `rmcp` 3.5.1 with tools alone: no resources, no prompts, no HTTP transport. The
tests drive the binary over its stdio as a client does. It holds one repository's engine
([ADR 4.21](./4.21-hold-one-repository-s-engine-per-process.md)).

**The tools.** The names, inputs and defaults are those the prompts use: `index_repo`, `index_stats`, `find_files`,
`glob_files`, `grep`, `list_dir`, `find_symbols`, `read_definitions`, `file_outline`, `find_callers`, `find_call_path`,
`find_references`, `find_implementations`, `find_importers` and `impact_of_edit`. Four more answer what the engine holds
and no other tool answers in one call: `find_callees`, `impact_of_change`, `find_unused`, and `refresh`
([ADR 4.44](./4.44-refresh-on-request-and-list-what-the-tree-fails-now.md)). A tool's description says when to prefer
it over its neighbors and what it cannot see.

**Parameters.** Every tool refuses an unknown argument. A limit is `NonZero`, so a zero is a wrong call, except the
`max_results` of `find_files` and `glob_files`, where zero lists every match. `languages` takes kartta's sixteen
language names and the family key `jsts`; an unknown name fails the call with every name it takes. The floors
`likely` and `certain` are the tiers `SAME_DIR` and `SAME_FILE` of ADR 3.172, and an answer marks a call bound below 80
`likely` and below 50 `guess`. `find_callers`, `find_callees`, `find_references` and `find_implementations` take `path_prefix`
and `line`, and `find_call_path` `from_path_prefix`, `from_line`, `to_path_prefix` and `to_line`, to pick one of the
symbols a name selects (ADR 3.35).

**Defaults and limits.**

- `grep`: 100 matching lines, a line cut to 1 KiB around its match with the bytes it lost, files over 4 MiB skipped; an
  unscoped search excludes `**/vendor`, `**/node_modules`, `**/dist` and `**/__pycache__`.
- `list_dir`: one level, 1000 entries; it does not enter `vendor`, `node_modules`, `dist`, `build` or `__pycache__`.
- `find_symbols`: 20 hits; keyword matches that underfill the limit are topped up by fuzzy hits marked `fuzzy=true`.
- `read_definitions`: 3 definitions of each of at most 10 names, a body at most 500 lines, each cut at 1,024 bytes;
  a definition ranks `same-directory`, `vendored` or `other` by directory, not by the imports of the asking file.
- `find_callers`: 3 hops; `find_callees`: 1 hop, `at=` only on a direct callee, since the walk records the line of each
  call but not which callee further out made it; both stop at 500 symbols.
- `find_call_path`: 8 calls, 20,000 symbols. `find_implementations`: 500. `find_importers`: 3 includes away.
- `find_references`: every site counted, 100 listed and 50 more files named
  ([ADR 4.11](./4.11-group-a-symbol-s-references-by-file-the-busiest-first.md)).
- `impact_of_edit` and `impact_of_change`: ADR 3.22's walk at 3 hops and 500 symbols. `impact_of_edit` lists 50 direct
  callers and callees; `impact_of_change` lists 20 changed symbols and 20 hotspots, and 10 direct callers of each, or
  their directories past 30 callers. A change arrives as regions or a diff
  ([ADR 4.20](./4.20-read-a-change-from-the-new-side-of-a-unified-diff.md)).
- `find_unused`: ADR 3.23 over every kind, under an optional `path_prefix`, 50 listed in path order across the graphs;
  an answer that judged every definition and found each reached says so.
- `index_repo` and `index_stats` count each graph's `calls`, `uses` and `includes`, not resolved edges, which ADR 3.7
  does not build. With `coverage`, `index_stats` resolves every call (ADR 3.24) each time it is asked, and adds a
  `<coverage/>` record for each language that holds a file.

**The answers.** An answer is one root element named for the question, counts as attributes, one record a line, and an
attribute marking the unusual only where it applies. A wrong call is a tool error naming the fix; a valid call over
nothing is an envelope with a count of zero and a hint. The path searches answer plain paths, one a line
([ADR 4.10](./4.10-close-a-cut-path-list-with-a-line-no-path-can-read-as.md)). Where the engine counts what an answer
left out, the answer says so, each count only when it is not zero:

| Tool | Counts |
| --- | --- |
| `index_repo`, `index_stats` | `unheld`, `files_without_symbols`; `<errors>`, the walk's failures |
| `grep` | `truncated`, `unsearched`, `excluded`, `binary`, `oversized`, `ruled_out`, `symlinks` (ADR 1.11) |
| `list_dir` | `unlisted` beneath a directory not entered, `total` and `excluded` (ADR 1.8) |
| `find_symbols` | `total` past the limit, `unmatched` query words, `dropped_words` |
| `find_callers` | `passed_over`, `unexpanded`, `ambiguous`, `below_confidence`, `turned_away`, `file_scope` |
| `find_callees` | `unresolved`, `passed_over`, `unexpanded`, `below_confidence`, `turned_away` |
| `find_call_path` | `at_depth_bound`, `below_confidence`, `turned_away`, `passed_over_from`, `passed_over_to` |
| `find_references` | per-kind counts, `shown`, `files`, `files_shown`, `ambiguous`, `below_confidence`, `passed_over` |
| `find_implementations` | `total` past 500, `passed_over`, `depth=` on an implementor through another |
| `find_importers` | `unexpanded` at the hop limit, `depth=` on an importer through another |
| `read_definitions` | `shown`, `resized` for a file changed since the build, `error=` for one that would not read |
| `impact_of_edit` | `ambiguous`, `unresolved`, `unexpanded`, `truncated`, `users`; `shown`/`of` on each list |
| `impact_of_change` | `truncated_walks`, `unheld_regions`, `regions_outside_symbols` |
| an `impact_of_change` seed | `truncated`, `turned_away`, `unexpanded`, `ambiguous`, `users`; `shown`/`of` on lists |
| `find_unused` | `total` past the limit, `live`, `<excluded/>` by reason, `reflected` among them |

A match that passed symbols over lists up to five as `<candidate/>` records with the `callers=`, `sites=` or
`implementors=` each has; `find_implementations` names the type it took in a `<root/>`, and `find_call_path` marks each
`end="from"` or `end="to"`. A file whose top level calls a `find_callers` root is a `<file_scope path=/>` record after
the refs, with a call's confidence mark and no line, since the graph keeps only the names a top level spells; the walk
goes no further, `role` lists none of them, and `below_confidence=` counts those the floor dropped. `find_callers` of a
field points at `find_references`. The impact answers of a field, a variable or a constant count `users=` and list
`<users>`, or past 30 `<user_dirs>`, in place of callers, which its users hold. Own ADRs decide what a floor dropped
([4.13](./4.13-count-what-the-confidence-floor-dropped-in-place-of-an-empty-answer-s-verdict.md)), the calls of a name
that bound nothing ([4.12](./4.12-count-the-calls-of-a-symbol-s-name-that-several-definitions-leave-unbound.md)), a call
of itself ([4.14](./4.14-list-a-symbol-s-call-of-itself-apart-from-its-callers-and-callees.md)), an outline's holders
([4.15](./4.15-name-the-definition-that-holds-an-unowned-symbol-in-an-outline.md)), a name that selects nothing
([3.48](./3.48-read-a-qualified-name-with-the-other-owner-separator-when-it-selects-nothing.md),
[3.49](./3.49-select-a-name-whose-last-part-holds-a-separator-by-its-longer-parts.md),
[4.18](./4.18-answer-a-name-that-selects-nothing-with-what-it-does-match.md)) and a type's unrecorded uses
([4.19](./4.19-name-a-language-that-records-no-use-of-a-type-in-a-type-s-references.md)).

**Configuration** comes from the environment: `KARTTA_CACHE_DIR` the shared cache (ADR 2.1),
`KARTTA_CACHE_ENTRY_TTL_SECS` an entry's time to live, a week when empty or `0` (ADR 2.3), `KARTTA_GREP_INDEX`
`memory`, `file` or `mmap` and `KARTTA_GREP_INDEX_DIR` the trigram index (ADR 1.14), `KARTTA_THREADS` the thread bound
(ADR 1.13), and `KARTTA_WATCH` the watch (ADR 4.4). A value that does not read warns on stderr and keeps the default.
`KARTTA_CACHE_SWEEP` is not read: every build's merge expires entries. The walk prunes the engine's default
`PrunedNames` (ADR 1.19).

## Why

- A server under the names, inputs and envelopes the prompts in use already read serves them without a rewrite, and
  every fact kartta adds fits an attribute of those envelopes.
- An agent reads a cut answer as complete unless the answer says what it cut, and picks its next call from what the
  answer holds (CLAUDE.md, `<answers>`); the engine counts each cut where it makes it.
- Every session loads every tool's description, so a tool that answers what another answers costs each session and
  answers nothing new.

## Consequences

- A `find_unused` listing is a candidate: function values, outside callers and dynamic dispatch are unseen. Accepted.

## Rejected

- **A server over the C ABI** — adds a serialization round trip to every answer the engine's own types already serve.
- **Answers in kartta's own vocabulary** — the prompts in use break on every tool, while every fact kartta adds fits an
  attribute.
- **An HTTP transport** — its server stack brings dependencies `deny.toml` has not reviewed, for no consumer that needs
  one.
- **A separate tool for reads and writes** — `find_references` already promises "where is this used", and a tool costs
  every session.
- **`find_callees` 3 hops deep by default, as `find_callers`** — a callee past the first hop carries no line of its
  call, and the question asked is what a body calls.
- **A kinds filter on `find_unused`** — each record names its kind, and the parameter is description text every session
  pays for.
- **Coverage on every `index_stats`, or cached per build** — every first call would pay 0.1 to 0.4 s on the measured
  trees and a resolution's memory for counts most calls do not read, and a cache saves only a repeat.

## Revisit if

A consumer needs a transport other than stdio; held while the agents served launch MCP servers as child processes.
