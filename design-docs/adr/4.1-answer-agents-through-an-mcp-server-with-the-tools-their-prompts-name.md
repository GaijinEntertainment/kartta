# Answer agents through an MCP server with the tools their prompts already name

- **Status:** accepted
- **Date:** 2026-10-18
- **Revised:** 2026-10-18
- **Initiative:** `04-consumer-surfaces`

Agents reach a code graph through MCP, and the prompts in use today name fifteen tools, pass their arguments and read
their envelopes. A server answering under those names serves those prompts unchanged. kartta holds more than those
envelopes carry, a count of what each cap or bound left out above all, and an agent learns that only if the answer says
it.

**`kartta-mcp` is a binary crate with a library part**, built on the engine directly, with no C ABI between them. It
speaks MCP over stdio through `rmcp` 3.5.1, with tools alone: no resources, no prompts, and no HTTP transport, whose
server stack would bring dependencies `deny.toml` has not reviewed. The tests drive the binary over its stdio as a
client does.

**The tool set, names, inputs and defaults are the ones those prompts use.** `index_repo`, `index_stats`,
`find_files`, `glob_files`, `grep`, `list_dir`, `find_symbols`, `read_definitions`, `file_outline`, `find_callers`,
`find_call_path`, `find_references`, `find_implementations`, `find_importers` and `impact_of_edit`, each refusing an
unknown argument, with its limits as `NonZero` so a zero is a wrong call, but for the `max_results` of `find_files` and
`glob_files`, where zero lists every match as the prompts expect. The pinned limits stay: 100 grep matches, a line cut
at 1 KiB and files over 4 MiB skipped, 1000 listed entries a level deep, 20 symbols, 3 definitions of each of at most
10 names, a 500-symbol walk 3 hops deep for callers and impact, a 20 000-symbol call path search 8 calls long, 500
references and implementors, importers 3 includes away. The `languages` filter takes kartta's sixteen names and the
family key `jsts`, and an unknown name fails the call with the names it takes. The confidence floors `likely` and
`certain` are the tiers `SAME_DIR` and `SAME_FILE`, and an answer marks a call bound below 80 `likely` and below 50
`guess`.

**The answers keep the envelopes those prompts read, with kartta's counts added as attributes.** One root element named
for the question, counts as attributes, one record a line, an attribute marking the unusual only where it applies; a
wrong call is a tool error naming the fix, and a valid call over nothing is an envelope with a count of zero and a hint.
The path searches answer plain paths, one a line; a path holding a control character or opening with a quote is quoted
and escaped as an attribute value is, so a line break cannot split it. Where kartta counts what an answer left out, the
answer says so, each count only when it is not zero:

| Tool | Added |
| --- | --- |
| `index_repo`, `index_stats` | `unheld` claimed files no graph holds; `<errors>` the walk's failures |
| `glob_files` | closing `(truncated: ...)` and `(excludes removed: N)` lines (ADR 1.5) |
| `grep` | `unsearched`, `excluded`, `binary`, `oversized`, `ruled_out`, `symlinks` (ADR 1.11); bytes cut from a line |
| `list_dir` | `unlisted` beneath each directory not entered, `total` and `excluded` on the listing (ADR 1.8) |
| `find_symbols` | `total` past the limit, `unmatched` query words, `dropped_words` |
| `find_callers` | `passed_over`, `unexpanded`, `below_confidence`, `turned_away`; `at=` the line of each call |
| `find_call_path` | `at_depth_bound`, `below_confidence`, `passed_over_from`, `passed_over_to` |
| `find_references` | `below_confidence`, `passed_over` |
| `find_implementations` | `total` past 500, `passed_over`, `depth=` on an implementor through another |
| `find_importers` | `unexpanded` at the hop limit, `depth=` on an importer through another |
| `read_definitions` | `resized` for a file changed since the build, `error=` for one that would not read |
| `impact_of_edit` | `unresolved` calls, `unexpanded`, `truncated`; `at=` the line of each call |

**Where kartta answers differently by design, the answer is kartta's.** Search ranks by the words of names and paths
(ADR 3.21), calls resolve when a query asks (ADR 3.7), implementors are found transitively from the parents written
(ADR 3.20), and a listing counts what it left out (ADR 1.8). `read_definitions` ranks a definition `same-directory`,
`vendored` or `other`: the graph ranks by directory, not by the imports of the asking file. `find_files` answers the
best matches without a count past the cap, as ADR 1.5 decides for a ranked answer. The index answer counts `calls`,
`uses` and `includes` in place of resolved `edges`, which ADR 3.7 does not build.

**One repository per process, built by `index_repo` or at launch.** A root given as the argument or as `KARTTA_ROOT`
starts the build before any call; until it ends, `index_stats` answers `status="building"` with the seconds so far, and
every other query answers a tool error saying so. An `index_repo` of the request being built waits for it; any other
cancels it. A rebuild starts once the cancelled build has ended and every query holding the replaced engine has
answered, so the process never holds two engines.

**The configuration is the environment's**, the variables deployments of those prompts already set, mapped onto
kartta's options: `KARTTA_CACHE_DIR` the shared cache (ADR 2.1), `KARTTA_GREP_INDEX` `memory`, `file` or `mmap` and
`KARTTA_GREP_INDEX_DIR` the trigram index (ADR 1.14), and `KARTTA_THREADS` the thread bound (ADR 1.13). A value that
does not read warns on stderr and keeps the default. The walk prunes `PrunedNames::builtin` (ADR 1.19), the clutter
those deployments expect pruned. `KARTTA_CACHE_ENTRY_TTL_SECS` is the time to live of a cache entry, a week when empty
or `0`. `KARTTA_CACHE_SWEEP` has no counterpart: every build's merge expires entries, so a value only warns that it does
not apply.

**Parity, measured 2026-10-18** by driving kartta's server and the server those prompts were written for over stdio with
the same fifteen calls, the symbol taken from kartta's own search:

- **dagor** (C++ tree, 182k entries): kartta indexed in 12.7s against 20.8s. `find_files`, `list_dir` and
  `find_importers` answer identically; `glob_files` differs only by its truncation line. `find_symbols` adds
  `total="82477"` past the limit of 10. The graph tools differ where a Python package's `__init__.py` is named: kartta
  qualifies it by the module its path names (ADR 3.12), `pyDataBlock.DataBlock`, where the other server keeps
  `pyDataBlock.__init__.DataBlock`, so a name copied from one server's answer is unknown to the other.
- **A Go monorepo**: kartta indexed in 4.5s against 8.3s. `find_files`, `glob_files`, `read_definitions`,
  `find_importers` and `file_outline` answer identically. Where the tree holds two copies of a package, kartta picks the
  first in path order and says `passed_over="1"`; the other server picks the other copy and says nothing.

No difference found is a defect of the server: each is the envelope's added counts, or an engine behavior an ADR
records.

**Revised 2026-10-18: three tools and a flag answer what the engine already holds.** An agent asks what a symbol
calls, what a whole diff reaches and what nothing uses, and the engine answers each; it can also say how well a
language's calls bind. Each tool is a description every session pays for, so each answers a question no other tool
answers in one call, and its description says when to prefer it over its neighbors and what it cannot see.

- **`find_callees`** takes the name, `languages`, `hops` and `min_confidence` of `find_callers` and answers its
  envelope without the reach band and the role filter, which grade and sort callers. `hops` defaults to 1: the question
  is what a body calls, and only a direct callee carries `at=`, because the walk records the line of each call but not
  which callee made a call further out. `unresolved=` counts the calls in the bodies walked that bound nothing.
- **`impact_of_change`** answers the engine's change analysis (ADR 3.22) at the bounds of `impact_of_edit`, 3 hops and
  500 symbols. A change arrives as `regions`, each a file and an optional line range, as the text of a unified diff, or
  both, so an agent holding `git diff` output passes it as is. The diff is read for its file and hunk headers, each
  hunk's body by the counts its header gives, so a changed line that reads like a header is not taken for one, and a
  line that is no body line fails the call naming it. A hunk covers its lines on the `+` side, those of the tree the
  change is applied to; a hunk that only deletes covers the line either side; a deleted file is a whole-file region of
  its old path, answered while the index still holds it. A path git quotes is not unquoted and counts in
  `unheld_regions`. The answer lists at most `limit`, 20 by default, changed symbols and as many hotspots, and at most
  10 direct callers or caller directories for each changed symbol, every list as `shown` of `of`; `truncated_walks`
  counts the changed symbols whose walk the cap stopped.
- **`find_unused`** answers the engine's dead-code query (ADR 3.23) over every kind, under an optional `path_prefix`,
  listing at most `limit`, 50 by default, in path order across the graphs, with each graph's counts summed: `total`,
  `live`, and an `<excluded/>` record by reason. `name_used_elsewhere` marks a definition whose name calls or uses
  spell while binding other definitions: the weaker candidate, and the rarer, 23,143 of the first 100,000 listed on the
  C++ tree and 1,618 of 6,401 on the Go monorepo. The description says a definition listed is a candidate, not a
  proof, and what to check before deleting it.
- **`index_stats` takes `coverage`**, which resolves every call (ADR 3.24) and adds a `<coverage/>` record for each
  language that holds a file: its sites, those bound in the `certain`, `likely` and `guess` bands the call tools mark,
  the caller and callee pairs, and the misses by reason. It resolves on every call: a repeated call cost what the first
  did on both trees, so a cache per build would save only a repeat.

extraction marks them entry points (ADR 3.23).

## Considered Options

- **A server over the C ABI** — waits on another crate, and adds a serialization round trip to every answer for no
  consumer the engine's own types do not serve.
- **Answers in kartta's own vocabulary** — the prompts in use would break on every tool, while every fact kartta adds
  fits an attribute.
- **Keep the replaced engine serving while a rebuild runs** — doubles the peak memory of a rebuild to serve answers
  about a tree the caller asked to replace.
- **Count every fuzzy match past the cap** — makes every capped `find_files` keep and sort every match instead of the
  best few, a cost per call on a tree of millions of paths, for a count ADR 1.5 decides a ranked answer does without.
- **Refresh and watch** — waited for an engine-level refresh; ADR 4.4 decides them, and an index follows its tree.
- **`find_callees` 3 hops deep by default, as `find_callers`** — a callee past the first hop carries no line of its
  call, and the question asked is what a body calls.
- **Regions alone for `impact_of_change`** — an agent holding a diff turns each hunk header into a line range by hand,
  and a deletion's range is the one it gets wrong.
- **A diff's lines on its `-` side** — they name the tree before the change, which an index of the changed tree does
  not hold.
- **A kinds filter on `find_unused`** — the engine judges four kinds, each record names its kind, and the parameter is
  description text every session pays for.
- **Coverage on every `index_stats`, or cached per build** — every first call would pay 0.1 to 0.4 s and a
  resolution's memory (ADR 3.24) for counts most calls do not read, and a cache saves only a repeat.

Revisit when a consumer needs a transport other than stdio.
