# Answer agents through an MCP server with the tools their prompts already name

- **Status:** accepted
- **Date:** 2026-10-18
- **Revised:** 2026-10-20
- **Initiative:** `04-consumer-surfaces`

Agents reach a code graph through MCP, and the prompts in use today name fifteen tools, pass their arguments and read
their envelopes. A server answering under those names serves those prompts unchanged. kartta holds more than those
envelopes carry, a count of what each cap or bound left out above all, and an agent learns that only if the answer says
it.

**`kartta-mcp` is a binary crate with a library part**, built on the engine directly, with no C ABI between them. It
speaks MCP over stdio through `rmcp` 3.5.1, with tools alone: no resources, no prompts, and no HTTP transport, whose
server stack would bring dependencies `deny.toml` has not reviewed. The tests drive the binary over its stdio as a
client does.

**The tool set, names, inputs and defaults are the ones those prompts use.** `index_repo`, `index_stats`,
`find_files`, `glob_files`, `grep`, `list_dir`, `find_symbols`, `read_definitions`, `file_outline`, `find_callers`,
`find_call_path`, `find_references`, `find_implementations`, `find_importers` and `impact_of_edit`, each refusing an
unknown argument, with its limits as `NonZero` so a zero is a wrong call, but for the `max_results` of `find_files` and
`glob_files`, where zero lists every match as the prompts expect. The pinned limits stay: 100 grep matches, a line cut
at 1 KiB and files over 4 MiB skipped, 1000 listed entries a level deep, 20 symbols, 3 definitions of each of at most
10 names, a 500-symbol walk 3 hops deep for callers and impact, a 20 000-symbol call path search 8 calls long, every
reference counted with 100 sites listed and 50 more files named, 500 implementors, importers 3 includes away. The
`languages` filter takes kartta's sixteen names and the family key `jsts`, and an unknown name fails the call with the
names it takes. The confidence floors `likely` and
`certain` are the tiers `SAME_DIR` and `SAME_FILE`, and an answer marks a call bound below 80 `likely` and below 50
`guess`.

**The answers keep the envelopes those prompts read, with kartta's counts added as attributes.** One root element named
for the question, counts as attributes, one record a line, an attribute marking the unusual only where it applies; a
wrong call is a tool error naming the fix, and a valid call over nothing is an envelope with a count of zero and a hint.
The path searches answer plain paths, one a line; a path holding a control character or opening with a quote is quoted
and escaped as an attribute value is, so a line break cannot split it. Revised 2026-10-20 below: so is a path opening
with a parenthesis. Where kartta counts what an answer left out, the answer says so, each count only when it is not
zero:

| Tool | Added |
| --- | --- |

| `find_files` | closing `(N of M matching paths, best first)` line when `max_results` cut the list; the empty query ADR 1.5 leaves uncounted is a tool error |
| `glob_files` | closing `(truncated: ...)` and `(excludes removed: N)` lines (ADR 1.5) |
| `grep` | `unsearched`, `excluded`, `binary`, `oversized`, `ruled_out`, `symlinks` (ADR 1.11); bytes cut from a line |
| `list_dir` | `unlisted` beneath each directory not entered, `total` and `excluded` on the listing (ADR 1.8) |
| `find_symbols` | `total` past the limit, `unmatched` query words, `dropped_words` |
| `find_callers` | `passed_over`, `unexpanded`, `ambiguous`, `below_confidence`, `turned_away`, `file_scope`; `at=` |
| `find_call_path` | `at_depth_bound`, `below_confidence`, `passed_over_from`, `passed_over_to` |

**Where kartta answers differently by design, the answer is kartta's.** Search ranks by the words of names and paths
(ADR 3.21), calls resolve when a query asks (ADR 3.7), implementors are found transitively from the parents written
(ADR 3.20), and a listing counts what it left out (ADR 1.8). `read_definitions` ranks a definition `same-directory`,
`vendored` or `other`: the graph ranks by directory, not by the imports of the asking file. `find_files` answers the
best matches without a count past the cap, as ADR 1.5 decides for a ranked answer; revised 2026-10-20 below, a list the
cap cut counts every match. The index answer counts `calls`, `uses` and `includes` in place of resolved `edges`, which
ADR 3.7 does not build.

**One repository per process, built by `index_repo` or at launch.** A root given as the argument or as `KARTTA_ROOT`
starts the build before any call; until it ends, `index_stats` answers `status="building"` with the seconds so far, and
every other query answers a tool error saying so. An `index_repo` of the request being built waits for it; any other
cancels it. A rebuild starts once the cancelled build has ended and every query holding the replaced engine has
answered, so the process never holds two engines.

**A request the client cancels stops its grep.** `notifications/cancelled` trips the request's context, and the server
passes that on as the search's cancel (ADR 1.10), which each file checks before it is opened: a cancelled search of a
large tree ends with the files already being read, rather than reading on for the ~12 s a data-volume search takes
while nobody waits for the answer. The answer of a cancelled request is never sent. Revised 2026-10-19: the search's
cancel was never set, so a cancelled grep ran to the end.

**The configuration is the environment's**, the variables deployments of those prompts already set, mapped onto
kartta's options: `KARTTA_CACHE_DIR` the shared cache (ADR 2.1), `KARTTA_GREP_INDEX` `memory`, `file` or `mmap` and
`KARTTA_GREP_INDEX_DIR` the trigram index (ADR 1.14), and `KARTTA_THREADS` the thread bound (ADR 1.13). A value that
does not read warns on stderr and keeps the default. The walk prunes `PrunedNames::builtin` (ADR 1.19), the clutter
those deployments expect pruned. `KARTTA_CACHE_ENTRY_TTL_SECS` is the time to live of a cache entry, a week when empty
or `0` (ADR 2.3). `KARTTA_CACHE_SWEEP` has no counterpart and is not read: every build's merge expires entries.
Revised 2026-10-19: a value no longer warns that it does not apply, since the sweep it asks for runs anyway (ADR 2.3).

**Parity, measured 2026-10-18** by driving kartta's server and the server those prompts were written for over stdio with
the same fifteen calls, the symbol taken from kartta's own search:

- **dagor** (C++ tree, 182k entries): kartta indexed in 12.7s against 20.8s. `find_files`, `list_dir` and
  `find_importers` answer identically; `glob_files` differs only by its truncation line. `find_symbols` adds
  `total="82477"` past the limit of 10. The graph tools differ where a Python package's `__init__.py` is named: kartta
  qualifies it by the module its path names (ADR 3.12), `pyDataBlock.DataBlock`, where the other server keeps
  `pyDataBlock.__init__.DataBlock`, so a name copied from one server's answer is unknown to the other.
- **A Go monorepo**: kartta indexed in 4.5s against 8.3s. `find_files`, `glob_files`, `read_definitions`,
  `find_importers` and `file_outline` answer identically. Where the tree holds two copies of a package, kartta picks the
  first in path order and says `passed_over="1"`; the other server picks the other copy and says nothing.

No difference found is a defect of the server: each is the envelope's added counts, or an engine behavior an ADR
records.

**Revised 2026-10-18: three tools and a flag answer what the engine already holds.** An agent asks what a symbol
calls, what a whole diff reaches and what nothing uses, and the engine answers each; it can also say how well a
language's calls bind. Each tool is a description every session pays for, so each answers a question no other tool
answers in one call, and its description says when to prefer it over its neighbors and what it cannot see.

- **`find_callees`** takes the name, `languages`, `hops` and `min_confidence` of `find_callers` and answers its
  envelope without the reach band and the role filter, which grade and sort callers. `hops` defaults to 1: the question
  is what a body calls, and only a direct callee carries `at=`, because the walk records the line of each call but not
  which callee made a call further out. `unresolved=` counts the calls in the bodies walked that bound nothing.
- **`impact_of_change`** answers the engine's change analysis (ADR 3.22) at the bounds of `impact_of_edit`, 3 hops and
  500 symbols. A change arrives as `regions`, each a file and an optional line range, as the text of a unified diff, or
  both, so an agent holding `git diff` output passes it as is. The diff is read for its file and hunk headers, each
  hunk's body by the counts its header gives, so a changed line that reads like a header is not taken for one, and a
  line that is no body line fails the call naming it. A hunk covers its lines on the `+` side, those of the tree the
  change is applied to; a hunk that only deletes covers the line either side; a deleted file is a whole-file region of
  its old path, answered while the index still holds it. A path git quotes is not unquoted and counts in
  `unheld_regions`. The answer lists at most `limit`, 20 by default, changed symbols and as many hotspots, and at most
  10 direct callers or caller directories for each changed symbol, every list as `shown` of `of`; `truncated_walks`
  counts the changed symbols whose walk the cap stopped.
- **`find_unused`** answers the engine's dead-code query (ADR 3.23) over every kind, under an optional `path_prefix`,
  listing at most `limit`, 50 by default, in path order across the graphs, with each graph's counts summed: `total`,
  `live`, and an `<excluded/>` record by reason. `name_used_elsewhere` marks a definition whose name calls or uses
  spell while binding other definitions: the weaker candidate, and the rarer, 23,143 of the first 100,000 listed on the
  C++ tree and 1,618 of 6,401 on the Go monorepo. The description says a definition listed is a candidate, not a
  proof, and what to check before deleting it.
- **`index_stats` takes `coverage`**, which resolves every call (ADR 3.24) and adds a `<coverage/>` record for each
  language that holds a file: its sites, those bound in the `certain`, `likely` and `guess` bands the call tools mark,
  the caller and callee pairs, and the misses by reason. It resolves on every call: a repeated call cost what the first
  did on both trees, so a cache per build would save only a repeat.

**Revised 2026-10-18: `find_references` answers who reads and who sets a field, a constant or a variable.** The graph
records data accesses (ADR 3.34), so the tool takes an optional `access` of `read` or `write`, marks each site `call`,
`type`, `read`, `write` or `update`, counts every site by kind on the match whatever `access` keeps, and counts in
`ambiguous=` the uses of a member's name it could not tell apart. One record holds the lines one enclosing symbol
touches the symbol on in one way; since the 2026-10-19 revision below, that record sits in its file's
`<file path=...>` record as `at="31,40,52"`. `find_callers` on a field points at `find_references`. No
tool is added: the description already promised "where is this used", and each new tool costs every session.

**Revised 2026-10-19: a shared name's tools take a path prefix and list what they passed over.** `find_callers`,
`find_callees`, `find_references` and `find_implementations` take `path_prefix`, and `find_call_path`
`from_path_prefix` and `to_path_prefix` (ADR 3.35). A match that passed symbols over lists up to five as
`<candidate/>` records with the `callers=`, `sites=` or `implementors=` each has, and `find_implementations` names the
type it took in a `<root/>`; a `find_call_path` match lists up to five per end, each marked `end="from"` or
`end="to"`. A name that picks none of several symbols, or none under the prefix, answers how many definitions of the
kinds the tool selects it does match, and lists up to five of them, instead of answering "no symbol matches".
`find_call_path` lists them per end, under `<from>` or `<to>`, for each end that selects nothing in any graph searched.

**Revised 2026-10-19: `find_callers` lists the files whose top level calls the root.** A function a script called only
from its top level answered "no callers", while `find_unused` judged it reached through the same name (ADR 3.23).
- **The shape:** a match counts these files in `file_scope=N`, then lists each after the refs as a `<file_scope path=/>`
  record, with the confidence mark a call carries.
- **What a file-scope caller lacks:** a line. The graph keeps only the names a top level spells. The walk goes no
  further, because the file holds no symbol.
- **What it leaves out:** `role` lists none of them, and `below_confidence=` also counts the files the floor dropped.
- **No-caller text:** a match without callers or file-scope records states why, as before.

**Revised 2026-10-20: `file_outline` names the definition that holds a symbol without an owner.**
- **The defect:** a local of a body, a member of an inline type or an object literal, and an item of a module block
  carry no owner, so the outline listed them as it lists a top-level definition, while the description left the owner
  out on a top-level symbol alone. The outline of `bindings/node/src/kartta.ts` listed 17 of them beside its classes:
  the `const` locals of its methods and the members of its `as { ... }` types and of a destructured parameter's type.
  The graph keeps them, and every language but daslang, DSHL and BLK declares some: a local of a TypeScript or
  JavaScript body, a nested function or class in Python, Rust, Lua, Quirrel, PHP, Ruby, Bash and Puppet, a `var`,
  `const` or `type` of a Go body, a local type in C++, an item of a Rust `mod` block.
- **The shape:** such a `<symbol/>` carries `in=`, the qualified name of the innermost listed definition holding it.
  A definition holds another that starts strictly inside its lines; a callable also holds a field or a method that
  starts on its first or last line, a member of an inline type in its signature. Definitions declared together, as
  `int a, b;`, a Go `var (...)` group, a `typedef struct` or a DSHL `shader a, b`, share their lines, so none of them
  holds another.
- **Cost:** the outline answers it from the lines it already holds, so the graph stores nothing more and a build runs
  the same code. On the C++ game-engine tree, base against branch, 6 rounds each at load 24–31: cold medians 22.1 s and

  953 and 932 MiB warm. A call walks its definitions once beside a stack of the open ones: the median outline answers
  in 0.1 ms either way, and the largest, 5,926 symbols, in 3.9 ms against 3.4 ms.

**Revised 2026-10-20: `find_files` and `glob_files` hand their excludes to the index.** Each kept its cap only without
excludes: with them, `find_files` ranked every match and `glob_files` globbed the whole tree, and each dropped what its
excludes matched and capped again (ADR 1.4).
- **What an exclude removes:** a matched directory with everything beneath it, as `grep`'s and `list_dir`'s excludes
  do. Matched against the returned file paths alone, `**/vendor` removed nothing beneath `vendor/`.
- **A capped `glob_files`:** its last lines say the first N paths and that more match, as one without excludes says,
  and `(excludes removed: N)` counts the matches removed before the list ended. Counting every match past the cap is
  the whole-tree walk the cap exists to avoid.
- **`find_files`:** says nothing of what its excludes removed, as before; its order explains the cap (ADR 1.5).

**Revised 2026-10-20: `find_files` counts its matches when its cap cut the list.** A capped answer ends with
`(N of M matching paths, best first)`, M the ranking's own tally of what it scored (ADR 1.5), so an agent reads that its
20 paths are 20 of 43,729 and narrows the pattern rather than raising the cap. An answer the cap did not cut ends as
before, and M holds only what the includes and excludes leave. This reverses "answers the best matches without a count
past the cap" above, and the considered option below that rejected the count: it took counting to mean keeping and
sorting every match, where the ranking scores every match anyway and a counter beside its heap counts them.
- **Parity against `main`:** on dagor 285 of 560 `find_files` calls gain that line, and 402 of 719 on the Go monorepo
  snapshot; nothing else in them changes, and no other tool's answer does.
- **The count checked:** each of the 687 lists exactly M paths when asked again without a cap, and 60 of them, counted
  apart from the ranking by a subsequence match of each term over what `glob_files` lists under the same includes and
  excludes, agree.

**Revised 2026-10-20: `find_callers` counts the calls of the symbol's name it could not bind.**
- **The defect:** a function or a method that no call bound answered "no callers - entry point, dead code, or dynamic
  dispatch", even where the graph had resolved calls of its name and bound none of them, because several definitions
  of the name could be meant. On this repository:
  - `CancelToken::cancel` answered so against 17 calls of `cancel` the graph left unbound, `token.cancel()` and
    `build.cancel.cancel()` among them, on values whose type the Rust graph does not follow; it now answers
    `ambiguous="17"`;
  - `Index::refresh_paths` answered so while the 10 calls of the name it shares with `Engine::refresh_paths` went to
    neither; each of the two now answers `ambiguous="10"`.

  `find_references` said only that some calls could be missing. `impact_of_edit` and `impact_of_change` answered
  `callers="0"` and no reach without a word. `find_unused` was already right: it leaves such a definition unjudged as
  `uncertain` (ADR 3.23).
- **The shape:** a match counts those calls in `ambiguous=`. They are the calls of the root's own name that the cascade
  left ambiguous (ADR 3.24), made as a call of the root can be made:
  - for a member, through a receiver;
  - for a free definition, bare, or through a receiver where no member of the name is a call target;
  - for a definition local to a body, none, since only a call in that body can mean it, and it binds as a local call.

  The count is the root's alone, so `hops` 1 and 3 give the same count, whatever `role` keeps. A match with no caller
  states first that no call binds it, that those calls may, and that grep finds them. It then names what else may hold:
  for a callable an entry point, dead code, or dynamic dispatch, and for another kind the uses `find_references` lists.
  Revised 2026-10-20 below: where the floor dropped callers, the note counts them instead.
- **The same count on the other tools:** `find_references` adds it to its `ambiguous=`, so both tools give one number.
  `impact_of_edit` carries it on a `<symbol>` and `impact_of_change` on a `<seed>`, beside a `callers=` and a reach that
  count none of those calls.
- **Cost:** each of these queries already resolves every call of the root's name and records each one that binds
  nothing. The count is two counters on that record, kept for each name a query resolves. The parity plan's 3,292
  `find_callers` calls on the Go monorepo snapshot, each asked of `main` and of the branch in turn, 3 to 5 rounds in 3
  runs at load 18–24: medians equal at 0.06–0.13 ms, totals from 0.6% faster to 3.7% slower. The build runs none of
  it. On the C++ tree, `main` against the branch in alternating rounds:
  - 6 cold rounds: medians 14.94 s and 14.76 s, peak footprint 1,118 and 1,185 MiB;
  - 8 more cold rounds at load 17–32: 22.1 s and 20.9 s, 1,162 and 1,181 MiB;
  - 6 warm rounds: 3.53 s and 3.54 s, 950 and 943 MiB.

  A counting allocator puts the heap's peak at 765.7–766.2 MiB on both sides, so the footprint spread is not the
  heap.

  - **The count:** 45 of 45 sampled counts on the C++ tree and 40 of 40 on the Go monorepo equal the call sites the

  - **The sites:** 14,696 of 14,797 counted sites on the C++ tree, and 604 of 696 on the Go monorepo, call the name on

    and Python's polymorphic `e.checkRecursion()`. The other 31 are generic names, `String`, `Len`, `__str__`, `init`,
    whose calls mostly reach other types or arrive by dynamic dispatch; the text keeps naming that.
- **What it leaves out:** a bare call left ambiguous where the language looks a member up first counts for no member;
  a call bound by proximity to another definition of the name counts as that definition's caller, as before.
- **Against upstream:** the answers these prompts were written for carry no such count and keep the verdict. The
  callers, callees and reach are unchanged from `main`, so the comparison of ADR 3.22 stands.
- **The C ABI:** the callers, segment and change answers keep their fields and carry no such count, so a wire consumer
  reads their empty caller lists as before; a field for it is a change to ADR 4.2's contract, outside this one. The
  references answer's `ambiguous` counts those calls too, as the Go and Node types state. Revised 2026-10-20: the
  callers, segment and change answers carry the count as `ambiguous`, absent when 0 (ADR 4.2).

Considered:
- **Every unbound call of the name, whatever the miss:** a call into an external import, an undefined name or a
  receiver whose type has no such method cannot reach a definition the graph holds.
- **Checking each ambiguous call against the root's own shape:** exact, but it recomputes the cascade's shape for each
  such call in every query, a second resolution of them; the forms above follow the shape the cascade gives each form.
- **A count summed over every symbol the walk expands,** as `find_callees` sums `unresolved=`: an answer at 3 hops is
  then dominated by the names of the callers in between, and differs from the 1-hop answer.
- **The no-callers text naming only the ambiguous calls:** it drops the dynamic-dispatch reading, which holds for most
  of the 31 generic names above.

## Considered Options

- **A server over the C ABI** — waits on another crate, and adds a serialization round trip to every answer for no
  consumer the engine's own types do not serve.
- **Answers in kartta's own vocabulary** — the prompts in use would break on every tool, while every fact kartta adds
  fits an attribute.
- **Keep the replaced engine serving while a rebuild runs** — doubles the peak memory of a rebuild to serve answers
  about a tree the caller asked to replace.
- **Count every fuzzy match past the cap** — makes every capped `find_files` keep and sort every match instead of the
  best few, a cost per call on a tree of millions of paths, for a count ADR 1.5 decides a ranked answer does without.
  Taken on 2026-10-20 as a tally of the scoring, which keeps nothing more: see the revision above.
- **Refresh and watch** — waited for an engine-level refresh; ADR 4.4 decides them, and an index follows its tree.
- **`find_callees` 3 hops deep by default, as `find_callers`** — a callee past the first hop carries no line of its
  call, and the question asked is what a body calls.
- **Regions alone for `impact_of_change`** — an agent holding a diff turns each hunk header into a line range by hand,
  and a deletion's range is the one it gets wrong.
- **A diff's lines on its `-` side** — they name the tree before the change, which an index of the changed tree does
  not hold.
- **A kinds filter on `find_unused`** — the engine judges four kinds, each record names its kind, and the parameter is
  description text every session pays for.
- **Coverage on every `index_stats`, or cached per build** — every first call would pay 0.1 to 0.4 s and a
  resolution's memory (ADR 3.24) for counts most calls do not read, and a cache saves only a repeat.

Revisit when a consumer needs a transport other than stdio.
