# Answer agents through an MCP server with the tools their prompts already name

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-23
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-mcp` (`src/server.rs`, `src/params.rs`, `src/render.rs`, `src/render/`, `src/llmxml.rs`,
  `src/config.rs`)
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`, `crates/kartta-mcp/tests/graph.rs`

Agents reach a code graph through MCP, and the prompts in use name the tools, pass their arguments and read their
envelopes. kartta answers under those names and envelopes, so those prompts work unchanged, and adds as attributes the
counts of what each answer left out. Every tool is description text each session pays for, so a tool exists only for a
question no other tool answers in one call.

## Decision

**The server.** `kartta-mcp` is a binary crate with a library part, built on the engine directly, with no C ABI between
them. It speaks MCP over stdio through `rmcp` 3.5.1 with tools alone: no resources, no prompts, no HTTP transport. The
tests drive the binary over its stdio as a client does. It holds one repository's engine
([ADR 4.21](./4.21-hold-one-repository-s-engine-per-process.md)).

**The tools.** The names, inputs and defaults are those the prompts use: `index_repo`, `index_stats`, `find_files`,
`glob_files`, `grep`, `list_dir`, `find_symbols`, `read_definitions`, `file_outline`, `find_callers`, `find_call_path`,
`find_references`, `find_implementations`, `find_importers` and `impact_of_edit`. Four more answer what the engine holds
and no other tool answers in one call: `find_callees`, `impact_of_change`, `find_unused`, and `refresh`
([ADR 4.44](./4.44-refresh-on-request-and-list-what-the-tree-fails-now.md)). A tool's description says when to prefer
it over its neighbors and what it cannot see. Each tool's default limits are
[ADR 4.23](./4.23-bound-each-mcp-tool-s-answer-by-a-default-limit.md)'s.

**Parameters.** Every tool refuses an unknown argument. A limit is `NonZero`, so a zero is a wrong call, except the
`max_results` of `find_files` and `glob_files`, where zero lists every match. `languages` takes kartta's sixteen
language names and the family key `jsts`; an unknown name fails the call with every name it takes. The floors
`likely` and `certain` are the tiers `SAME_DIR` and `SAME_FILE` of ADR 3.172, and an answer marks a call bound below 80
`likely` and below 50 `guess`. `find_callers`, `find_callees`, `find_references` and `find_implementations` take
`path_prefix` and `line`, and `find_call_path` `from_path_prefix`, `from_line`, `to_path_prefix` and `to_line`, to pick
one of the symbols a name selects (ADR 3.35).

**The answers.** An answer is one root element named for the question, counts as attributes, one record a line, and an
attribute marking the unusual only where it applies. A wrong call is a tool error naming the fix; a valid call over
nothing is an envelope with a count of zero and a hint. The path searches answer plain paths, one a line
([ADR 4.10](./4.10-close-a-cut-path-list-with-a-line-no-path-can-read-as.md)). What each answer counts of what it left
out, and the records it lists of what a match passed over, are
[ADR 4.24](./4.24-count-in-each-mcp-answer-what-it-left-out.md)'s.

**Configuration** comes from the environment: `KARTTA_CACHE_DIR` the shared cache (ADR 2.1),
`KARTTA_CACHE_ENTRY_TTL_SECS` an entry's time to live, a week when empty or `0` (ADR 2.3), `KARTTA_GREP_INDEX`
`memory`, `file` or `mmap` and `KARTTA_GREP_INDEX_DIR` the trigram index (ADR 1.14), `KARTTA_THREADS` the thread bound
(ADR 1.13), and `KARTTA_WATCH` the watch (ADR 4.4). A value that does not read warns on stderr and keeps the default.
`KARTTA_CACHE_SWEEP` is not read: every build's merge expires entries. The walk prunes the engine's default
`PrunedNames` (ADR 1.19).

## Why

- A server under the names, inputs and envelopes the prompts in use already read serves them without a rewrite, and
  every fact kartta adds fits an attribute of those envelopes.
- Every session loads every tool's description, so a tool that answers what another answers costs each session and
  answers nothing new.

## Consequences

- A `find_unused` listing is a candidate: function values, outside callers and dynamic dispatch are unseen. Accepted.

## Rejected

- **A server over the C ABI** — adds a serialization round trip to every answer the engine's own types already serve.
- **Answers in kartta's own vocabulary** — the prompts in use break on every tool, while every fact kartta adds fits an
  attribute.
- **An HTTP transport** — its server stack brings dependencies `deny.toml` has not reviewed, for no consumer that needs
  one.
- **A separate tool for reads and writes** — `find_references` already promises "where is this used", and a tool costs
  every session.
- **A kinds filter on `find_unused`** — each record names its kind, and the parameter is description text every session
  pays for.

## Revisit if

A consumer needs a transport other than stdio; held while the agents served launch MCP servers as child processes.
