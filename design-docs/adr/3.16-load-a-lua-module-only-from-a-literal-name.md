# Load a Lua module only from a literal name

- **Status:** accepted
- **Date:** 2026-10-16
- **Initiative:** `03-code-graph`

Lua has no import statement. A file loads another at run time through a function call: `require "a.b"` loads a module
through the search path of `package.path`, and `dofile` and `loadfile` load a file by its path. The extraction reads one
file and does not know the search path that the host program sets.

**Only a bare loader with a string literal loads a module.** `require`, `dofile` and `loadfile` are loaders when the
call names them directly. `M.require("x")` is a method of `M`, and a computed argument, `require(name)` or
`require("a" .. "b")`, names a module that only the run time knows. Those calls are ordinary calls. All three string
forms, `require("a")`, `require "a"` and `require[[a]]`, are literals. An empty literal loads nothing.

**A load is an include, and no call.** A bare loader call with a literal is classified as a load before calls are
recorded, so it records no call. The loader is the run time's own function, so a call of it would bind only where a
file redefines it, and the include already states the dependency. A loader is a load wherever the file calls it,
inside a function too. The extraction records a load before it drops the calls that come before the first function,
because a module loads most of its dependencies at its top, before any function, and those loads would be lost.

**A module name is found by the two common search paths.** `require "a.b"` includes `a/b.lua` or the package
`a/b/init.lua` at the root first, and then the same names in the requiring file's directory. The `./?.lua;./?/init.lua`
entries of the default `package.path` give the root form when the program runs from the root, and the relative form
when a script runs from its own directory.
`dofile` and `loadfile` take a path, whose dots are not separators, from the file's directory first and then from the
root. A module that the repository does not hold, such as one of the standard library or of a rock, includes nothing.

**A function bound to a name is a symbol, and its scope opens at the function.** `M.f = function() end`,
`local f = function() end` and a field of a table bound to a name, `local T = { f = function() end }`, are the common
ways to define a method in Lua, so each is a symbol. In `f, g = mk(), function() end`, the call of `mk` comes before the
function of `g`. The scope of `g` opens when the walk reaches the function, so `mk` is no call of `g`. A table
constructor bound by an assignment owns its fields under the variable in its own place, `U` for the second table of
`local T, U = {...}, {...}`. A nested table's fields have no owner. `local` makes a function bound to a name
unexported, but not a method of a local table, because a module hands its local table out with `return M`. The
extraction does not check that the file returns the table, so exported is a guess for a method: one of a table the
file keeps to itself is exported too.

On Kong, 1,311 Lua files give 3,660 loads and 2,469 includes. On Neovim, 856 files give 1,721 loads and 1,336 includes.

## Considered Options

- **A call of `require` as well as the include** — the call binds to no symbol, and it costs one row per load.
- **The requiring file's directory before the root** — finds a sibling module before a module of the same name at the
  root, but under the default `package.path` the run time searches from the working directory, not from the requiring
  file.
- **The configured `package.path`** — exact, but the host program sets it, often in code that is not Lua.

Revisit when the extraction reads a `.rockspec` or a `.luarc.json`, which name the module directories of a project.
