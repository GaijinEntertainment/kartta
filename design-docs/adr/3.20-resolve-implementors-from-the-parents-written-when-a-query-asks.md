# Resolve implementors from the parents written when a query asks

- **Status:** accepted
- **Date:** 2026-10-17
- **Initiative:** `03-code-graph`

A type keeps the parents its language records, as written: `Base`, `io.Reader`, `cm::Task`, a C++ `::Root` marked as
written from the root. Which type a parent names depends on the file that writes it: its package, its imports, the
namespaces around the type, its includes. ADR 3.7 resolves calls when a query asks, because an edge stored at insert
goes stale when any file it was resolved from changes; a parent is resolved from the same kind of facts.

**Implementors are resolved when a query asks, and no edge is stored.** The graph lists each file under the last segment
of every parent that its types write and of every interface that its assertions name, a file at a time.
`implementations` reads the files listed under the bare name of the type it starts from, and keeps each type of those
files whose written parent names that type. A parent written by a function or a variable names nothing.

**A parent names the type that its language's scopes reach.** Where a package is a directory, as in Go, a bare parent
names a type of its own directory and a qualified one a type of the directory its import binds. Where a language joins
an owner chain, as Ruby, Python, Rust and TypeScript do, the parent is looked up from the scope around the type that
names it, inside out, as the call queries look up a type's bases, and a bare parent that the lookup does not reach names
nothing. Where a language nests scopes, as C++ does, the lookup runs from the scope around the type out to the root, and
the innermost scope that holds a type of the parent's spelling decides; a parent written from the root names the type of
that qualified name. Elsewhere, and for a parent that those lookups do not reach, the parent names the type of its name
nearest the file that writes it: in that file, in the files it includes, in its directory, then anywhere, among the
types whose qualified name ends with what a qualified parent spells. Types tied at the nearest of those each count the
parent. On the game-engine tree the namespace lookup took the implementors one level deep of its 59,619 qualified C++
type names from 23,537 to 21,610, by parents that a tie had credited to every type of their name, as a `Visitor`
written in namespace `SQCompilation` was credited to each of 100 types named `Visitor`.

**An assertion is a parent its file states for a type it does not declare.** Go code writes
`var _ io.Reader = (*File)(nil)`, often in a file other than the one that declares `File`, and for an interface that the
type never embeds the assertion is the only place the relation is written. A slot keeps the type name and the interface
of each assertion as written. A query reads the interface from the asserting file as it reads a parent that the file
writes, and the type name in the same way among the types of that name; a type name that reaches several types, as an
external test package that declares a namesake of its own package's type, or none, adds nothing. No slot keeps an edge
to another slot.

**A name selects one type, and the answer says what it passed over.** A name selects as `definitions` does: the types
whose qualified name it is, else the types of that bare name, else those whose qualified name ends with it. Among
several, the one the most distinct types name as a parent is the root, the first in path order on a tie, as the call
queries select the most-called callable; `passed_over` counts the other types that `definitions` lists for the name, so
an agent can list them and ask again by a longer name. Copies of one type that share its qualified name, as a vendored
package and the same package in a second checkout, are reached by no longer name, and the query answers for the copy
the most types name.

**The walk is transitive to a depth, and the limit bounds the answer, not the work.** Implementors come a depth at a
time, each type once, at the depth where it is nearest, in path order within a depth. Every implementor within the depth
is found before the limit applies, so `total` counts them all, and `unexpanded` counts the types at the depth bound
whose own implementors the query did not look for. A type that implements an interface without naming it, as Go's
structural typing allows, is not found.

## Measured

On the Go monorepo and the C++ game-engine tree of ADR 3.19, with a warm extraction cache, three interleaved rounds on
an 18-core machine at a load of 3 to 7. The queries ask for the 100 types of each family that the most types name as a
parent, by qualified name.

The index of written parents and the assertions take 1.4 MB on each tree; the rest of the heap's growth, 8.3 MB on the
Go monorepo and 2.3 MB on the game-engine tree, is the includers of ADR 3.19. The queries listed 2,108 Go implementors
one level deep and 2,538 within three, and 8,556 and 10,478 C++ ones. The build times overlap at that load.

The same types were asked of an index keyed by the parent as written, which answers the name asked and, where that
finds nothing, its last segment. On the Go monorepo it listed 4,680 implementors of the 104 types where this decision
lists 2,116. Of the 2,648 it alone lists, 2,235 implement another type of the name, a copy in the second checkout or a
vendored namesake, which `passed_over` counts here, and 413 name a nearer type of their bare name in their own package,
as an interface that embeds its own package's `Client` listed under `asset.Client`. It missed 84 that this decision
finds: 70 that write the bare name inside the type's own package, where the qualified key already held the embedders of
other packages, and 14 written through an aliased import, which neither key reaches. On the game-engine tree it listed
8,757 against 8,720 for 144 types: of the 729 it alone lists, 373 implement another type of the name and 356 a nearer
namesake. It missed 692: 504 that write the bare name, and 188 written partly qualified, as `Cm::Task` and
`shdfnd::UserAllocated`, which neither key reaches. Neither tree has an implementor that the index lists and this
decision misses for its own type.

Ties stay where a lookup cannot see what the compiler sees. Of the types sharing a bare name with those 144 types on the
game-engine tree, 1,789 of 8,462 implementors are credited to more than one: the specializations of one template in one
file, each naming another, and the nested C++ types, which the extraction qualifies by their enclosing class alone, so
that the namespace lookup does not see the namespaces around them. On the Go monorepo 58 of 4,909 are.

## Considered Options

- **An index of implementors keyed by the parent as written** — a lookup in microseconds that answers a string: the
  types of every namesake under a bare name, and under a qualified one only the files that spell it so. The numbers
  above are its answers on the same types.
- **Resolved edges stored at insert** — queries without resolution, and edges that go stale whenever a file that a
  parent's resolution read changes: a package, an import, an include, a namespace anywhere in the family, the
  invalidation ADR 3.7 declined for calls.
- **Credit a tied parent to no type** — no type gains a child it does not have, and the type the parent names loses it
  with the others: on the game-engine tree, a fifth of the implementors that share a bare name.
- **Answer the union of every type the name selects** — one list for a name, which mixes copies and unrelated
  namesakes into it; `passed_over` tells an agent that they exist, and a longer name reaches each that does not share
  the qualified name of the root.
- **Direct implementors only** — one level, as an index of written parents answers; three levels listed 22% more
  implementors on the game-engine tree, 10,478 against 8,556, for 26 to 41 µs more at p50.

Revisit when the C++ extraction qualifies a nested type by the whole chain of namespaces around it, which removes most
of the ties left, when using-directives are extracted, which add a lookup tier, when a query can name a type by its
file, which reaches the copies that share a qualified name, or when a family's parents make a query exceed tens of
milliseconds.
