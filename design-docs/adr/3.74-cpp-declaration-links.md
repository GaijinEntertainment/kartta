# Fold a C++ declaration into the one definition its file reaches

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-cpp/src/walk.rs` (`queue_prototype`, `flush_prototypes`),
  `crates/kartta-lang-cpp/src/resolve.rs` (`export_c_constants`), `crates/kartta-graph/src/resolve.rs`
  (`linked_definition`)
- **Pinned by:** `crates/kartta-lang-cpp/src/walk.rs` (`prototypes_emit_only_without_a_same_file_definition`,
  `namespace_prototypes_qualify_at_queue_time`), `crates/kartta-lang-cpp/src/resolve.rs`
  (`a_file_scope_constant_of_a_c_file_is_exported_unless_static`), `crates/kartta-graph/tests/graph/calls.rs`
  (`a_declaration_links_to_the_definition_in_a_header_its_own_file_includes`,
  `a_declaration_links_to_the_definition_in_a_header_its_own_file_reaches_through_another`,
  `a_definition_in_a_header_no_file_of_the_class_includes_links_to_nothing`,
  `a_declaration_whose_file_includes_two_definitions_links_to_neither`,
  `a_declaration_outside_test_code_links_no_test_definition`)

A C++ callable is declared in one place and defined in another, often in another file, and a call binds whichever the
caller sees. The walk keeps a declaration only where its own file holds no definition of it, and the graph links a
declaration to the one definition the translation units that declare it hold, so a call of either reaches the same
body; a declaration with several candidate definitions links to none of them.

## Decision

- **A declaration its file defines.** A declaration without a body is queued during the walk and flushed after it. It
  is emitted only where the file has recorded no callable of its identity, its callable key, by then: no definition,
  and no earlier declaration of the key. A declaration without a key is always emitted. An in-class declaration whose
  out-of-line definition the same file holds is recorded as a folded declaration of that definition.
- **A queued declaration.** It takes its namespace when it is queued, since the namespace scopes have closed by the
  flush. Its id comes after every definition's, and it opens no scope that a call is attributed to, so the ids of the
  callers stay in source order.
- **A `.c` file's constants.** A file-scope constant of a `.c` file that its signature does not mark `static` is
  exported, with a definition keyed by its qualified name, as C links it outside its file.
- **The one definition linked.** The graph links a declaration to a definition of its key whose file reaches the
  declaration's file through its includes, or, where a language's includes are transitive as C++'s are, one the
  declaration's own file reaches, as an inline implementation header that a class header includes at its end. Only the
  one definition that qualifies links: where two qualify, a platform's conditional alternatives, the declaration links
  to none, and a copy in another checkout, which no file of the class reaches, stays apart.
- **No test definition for a declaration outside test code.** A declaration outside test code links no definition in
  test code, and such a definition does not count against the one that qualifies, as
  [ADR 3.46](/design-docs/adr/3.46-test-definition-binding.md) keeps test code apart.

## Why

- A header keeps its declarations, which a call sees through an include, while a source that declares and defines a
  function keeps one symbol for it.
- An `#include` pastes text in place, so a definition the declaration's own file reaches is in every translation unit
  that declares it. Linked only from the definition's side, the members an inline header defines linked nothing: a
  call bound the empty declaration, the definition had no callers, and a bare call in its body met no class. Linked
  both ways, 554 caller and callee pairs arrived on the C++ game-engine tree, 28 of 30 sampled right (2026-10-23,
  #177).
- A test that includes a header to stub what the header declares is built apart from the code that header serves, so
  its stub is in no translation unit of that code: linked, a header's call bound the stub, `msRtlAlignedHelper.h`'s
  `is_address_natively_allocated` binding `memAllocTest.cpp`'s; kept out, 27 of 30 sampled pairs it moved were right,
  each now binding the product definition or the declaration (C++ game-engine tree, 2026-10-25, #431).
- C gives a file-scope `const` external linkage where C++ gives it internal linkage, and the walk reads every file as
  C++.

## Consequences

- A query builds the closure of the declaration's file where a definition of the key misses the first test; nothing
  is stored.
- A declaration whose header reaches several platforms' bodies links none, so a call of it binds the declaration.
  Accepted.
- A call inside such a member on a field still binds nothing (#482).
- A product header's implementation that the test rule reads as test code links no more, so its callers bind the
  declaration: 8 C++ pairs on the game-engine tree, `tests/sampleCollector.cpp` and `checkNanTest.cpp` (#432).

## Rejected

- **Link a definition that only the declaration's file includes directly** — binds 207 pairs this rule does not, each
  an arbitrary one of a declaration's platform alternatives its header happens to include directly,
  `dag_vecMath_neon.h` for `dag_vecMath.h` (#177).
- **Link a definition whose includer reaches the declaration, through the includers index of
  [ADR 3.19](/design-docs/adr/3.19-file-dependents.md)** — binds 360 pairs more, 7 of 20 sampled a platform's
  alternative again (#177).

## Revisit if

A language whose includes are transitive gains a construct that pastes one definition per build, so that several
definitions a header reaches are not alternatives. Medium confidence that C++'s are alternatives most often.
