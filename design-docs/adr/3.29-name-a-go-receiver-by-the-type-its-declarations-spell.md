# Name a Go receiver by the type its declarations spell

- **Status:** accepted
- **Date:** 2026-10-17
- **Revised:** 2026-10-23
- **Initiative:** `03-code-graph`

ADR 3.2 records the empty receiver for a call through a value the caller declares, because the value's name matches an
owner only by naming convention. The call then binds by its method's name alone, and among the thousands of methods of
a common name the cascade finds none to prefer: on the Go monorepo 421,957 of the 1.95M Go call sites ended ambiguous.
The reference engine binds 41,302 of them by name, and on sampled sites its guesses reach the method called less often
the surer it says it is.

**A receiver is the path to its value's type, as the file's declarations spell it.** `Conventions::receivers` is
`Receivers::TypePaths` for Go. The extraction records the operand of a member call as a path that starts at a name the
file's package declares or an import binds and goes on through fields, results and elements: `s.client.Do()` in
`func f(s *Server)` records `Server.client`, and a variable records the path of what its declaration gives it, a type
it names, a composite literal, `new(T)`, a call's result, a range or index element, a type switch's one type. Every
function, method, field, variable and alias records the types of the values it yields, `Symbol::value_types`. The graph
follows the path across files and packages and binds the method of the type it reaches, or of a type that type embeds,
at 85; a path into code the graph does not hold binds nothing, as an import of such code does, and one the graph cannot
follow leaves the call to the tiers that read no type. A name that two files of a package declare is read from the
caller's own file, since only build constraints let two files declare it. A path is cut at 160 bytes, a path that
follows value types through other paths at 16 of them nested, and the embedded types of one type at 32.

**Revised 2026-10-23: a path through an anonymous struct reaches its members.** A field, a variable or a literal that
`:=` or `var` assigns to a name, whose type is an anonymous struct with a field, records the name the walk gives that
struct as its value type (ADR 3.34), so a call on a member of it binds through the path. On the monorepo snapshot 148
caller and callee pairs join at 85, 98 rise to 85 from guesses at 50 to 80, and 34 guesses at 15 to 80 leave, each a
call of a function-typed field or of a library type's method that had bound a namesake.

## Measured

On the Go monorepo (39,771 Go files) against `main` and the reference engine, distinct caller and callee pairs by
qualified name; precision from sampled sites, each read against its source, a binding right when it reaches the method
the call does and an absent one right when the target lies outside the repository:

| | `main` | this decision | reference |
| --- | --- | --- | --- |
| sites bound | 948,434 | 1,167,094 | — |
| ambiguous | 421,957 | 10,745 | — |
| external | 245,679 | 477,973 | — |
| pairs | 683,989 | 853,004 | 726,920 |

Of the reference's pairs that `main` left ambiguous, sampled 25 each: at confidence 15 the reference is right on 23,
at 70 on 5 and at 80 to 95 on none, `bytes.Buffer.Write` bound to a namesake of the repository, an interface's method
bound to one implementation; this decision is right on all 75, 39 of them by binding nothing because the value's type
is the standard library's. Of the 207,335 pairs it gains, 25 sampled among those the reference holds and 25 among
those it does not are all right; of the 38,320 it loses, 49 of 50 sampled were wrong in `main`. The one right there,
`mapper.Mremap()` in `x/sys/unix`, where two files declare `mapper` for different systems, binds again through the
caller's own file; one of the wrong ones is a call this decision misses too, below. On the C++ game-engine tree's 68 Go
files, 981 pairs against 942 in `main` and 954 in the reference; 33 sampled sites across the same buckets are all
right, against 21 wrong in the reference and 15 in `main`.

`dead_code` of the monorepo's Go reports 1,716 definitions against 1,714 in `main`: 41 leave the answer and 43 join
it, among them functions passed as values, `RunE: run`, which the Go extraction records no use of and which a call of
the name that bound nothing used to keep out as uncertain. `analyze_change` on the reference's 44 Go change sets keeps
36 footprints and grows 8, 147 to 631 symbols in all: one grows from 5 to 466, because a change to smithy-go's
`TracerProvider` reaches every operation of the AWS service clients through their `operationTracer`, whose
`p.Tracer()` `main` left ambiguous.

Interleaved with `main` over three rounds after a warm-up, on an 18-core machine:

| | `main` | this decision |
| --- | --- | --- |
| Go monorepo build | 1.83–2.03 s | 2.05–2.39 s |
| heap after build | 284 MB | 293 MB |
| peak footprint, build and queries | 958–988 MB | 872–891 MB |
| Go extraction, one thread | 27.2–29.4 s | 28.1–29.5 s |
| `callers` and `callees` of 400 Go names, depth 3 | 0.80–1.3 s, p50 528–683 µs | 1.1–1.2 s, p50 185–194 µs |

| C++ tree build, peak | 3.8–4.7 s, 716–727 MB | 4.0–4.3 s, 704–716 MB |

The value types and the longer receivers cost 9 MB of heap and about 3% of the extraction; a walk over callers holds
more edges, so its slowest queries take longer, p99 40–51 ms against 29–48 ms, and resolution reaches fewer by-name
tiers. The build differs by 0.03 and 0.11 s in two rounds and 0.56 s in a third under load, which the build's own
variance covers.

## Considered Options

- **The empty receiver for a declared value** (ADR 3.2) — no wrong edge from a name, and 421,957 ambiguous sites.
- **The reference's guesses by name** — the precision above, which falls as the confidence rises.
- **Type paths, then the one method of the name in the caller's package and the directories it imports, at 15** — adds
  no site: the include tier already binds the one method of a name across the imported packages, and the sites left
  ambiguous have no method of the name in reach (1,272) or several (9,473), protobuf getters shared by message types
  and an interface beside its implementation.
- **Conversions of a generic type, `T[int](x)`, as uses** — a conversion written as a call is a call of the type, as
  `B(x)` is, because the syntax cannot tell it from a call; 162 sites on the monorepo are generic and 35,044 plain.
- **Package variables of a sibling file in `vars[K]()`** — no site on the monorepo calls a package variable through an
  index, so the generic reading of such a call is kept.

Open: a type defined over a named interface, grpc's `type DepthLoggerV2 internal.DepthLoggerV2`, has that interface's
methods, but the extraction records no underlying type for a defined type outside a function type's results, so a
call through it binds nothing: 176 calls of grpc's package `logger` end `NotAdmitted` on the monorepo, where `main`
bound `componentData`'s method by name, a guess at one implementation.

Revisit when the graph keeps the types of local values across function literals, a defined type records its
underlying type, or a language other than Go spells its receivers as paths.
