# Write a location as its span, and a call's line bare

- **Date:** 2026-11-24
- **Governs:** `crates/kartta-mcp/src/render.rs` (`span`, `lines`), `crates/kartta-mcp/src/render/calls.rs`
  (`edge`, `path_match`, `site_record`, `direct_lists`, `seed`, `caller_match`, `callee_match`, `self_call`),
  `crates/kartta-mcp/src/render/symbols.rs` (`outline`, `implementations`), the MCP tool descriptions
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs` (`find_callees_walks_forward_with_the_line_of_each_direct_call`,
  `find_call_path_and_find_references_follow_the_calls`, `impact_of_edit_answers_the_symbols_a_range_overlaps`,
  `impact_of_change_lists_the_changed_symbols_and_where_their_reaches_meet`,
  `find_implementations_locates_each_type_by_its_span`), `crates/kartta-mcp/tests/stdio.rs`
  (`find_callers_walks_callers_with_the_line_of_each_call`), `crates/kartta-mcp/tests/outline.rs`

An MCP answer places a symbol and a call in two ways. A record names where its symbol sits by the symbol's whole span,
since an agent's next step is reading it, and names where a call sits by the line alone, since the record it is listed
under already names the file. The span costs a few bytes a record; the bare line saves a path a record.

## Decision

- **A symbol's place is its span.** Every `loc`, `from_loc` and `to_loc` is `file:start-end`, or `file:line` for a
  symbol on one line: on `<hit>`, `<definition>`, `<match>`, `<ref>` in a walk, a path or an impact list, `<seed>`,
  `<hotspot>`, `<root>`, `<type>`, `<candidate>`, `<suggestion>` and `find_unused`'s `<symbol>`. A record inside a
  `<file>` or an answer of one file writes the same span without the file as `lines=`: `file_outline`'s and
  `impact_of_edit`'s `<symbol>`, and `find_references`' `<ref>`.
- **A call's place is a bare line.** Every call site is `at=` a line, or a list of lines, in the one file the record
  it sits in already names: the caller's own file for a `find_callers` ref, a hop of `find_call_path`, an impact
  caller and user; the match's file for a direct `find_callees` ref and a `<self_call>`; the edited file for an
  `impact_of_edit` callee; the `<file>`'s path for a `find_references` ref. The `initialize` instructions say it once:
  `at=` is a line of the file of the symbol that calls or uses.

## Why

- A record that named only a start line made an agent read a guessed window or call again for the end, though every
  definition the graph holds carries it.
- A call's file is in the record by construction, so a path on `at=` repeats it: on the C++ game-engine tree, the paths
  took 22,956 of the 107,293 bytes of one hot function's `find_callers` answer at `limit` 500 (2026-11-24, #1037).
- One spelling per fact lets one reader take every tool's answer: the answers wrote `file:15` beside `lines="15-15"`,
  and `call=` beside `at=` for the same line.

## Consequences

- A span adds the end line, about 4 bytes, to each record of a symbol on more than one line: 1.6% more bytes over
  2,204 sampled `find_callers` answers on the C++ game-engine tree (2026-11-24). Accepted.
- An agent reading a bare `at=` takes its file from the record, a rule the instructions state. Accepted.

## Rejected

- **A start line on the records that list many symbols** — the agent pays a call per symbol it reads to learn the
  span the engine holds.
- **`at=file:line` on every call** — the path repeats the record's own file, 16% of the bytes over those 2,204
  `find_callers` answers.

## Revisit if

The graph records a call's line in a file other than its caller's, as a call a macro brings in from a header could:
`Reached::line` is a line of the caller's file. High confidence.
