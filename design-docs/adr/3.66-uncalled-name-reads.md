daslang, Quirrel, Lua and Rust record calls and no data use, so a handler subscribed, a comparator passed or a
function placed in a dispatch table reached nothing, and `dead_code` judged it dead. Each walk records a name its code
reads where no call takes it as a bare use, which binds by the language's rule below, hidden by the language's own
bindings, so such a function is reached, at the cost of the uses stored and of a namesake bound where a binding the walk
does not follow hides the name.

## Decision

- **daslang.** `@@f` and `@@mod::f`, typed or not, and `_::f`, record a bare use of `f`, or one qualified by `mod`; a
  splice `@@$c(...)` names nothing. A call, a constructor `T(...)`, a `new T` or an `@@` inside `quote`, `qmacro` or a
  `qmatch` pattern, which the code-as-data rule of [ADR 3.141](/design-docs/adr/3.141-daslang-call-attribution.md)
  records no call for, is a use of its name, sited at the `def` around it; a member call inside them records nothing.
  daslang sets `ValueUses::Expanded` ([ADR 3.173](/design-docs/adr/3.173-data-use-binding.md)): the file's own
  function, else the one a file it requires exports, else a re-export of it, else the one such a file declares
  `private`, else nothing where the runtime answers the name first, else the one in `daslib/builtin.das`, else the one
  definition those rules find from the files that expand the macro.
- **Quirrel.** An argument, a slot's value, a shorthand `{ handler }`, a `return` and `::name` read a name; a name being
  declared, a slot's key, a member's field, an assignment's target, a member access's receiver, a `foreach` variable and
  an increment's operand do not. A parameter or a local of an enclosing function hides its name in the whole body;
  `::name` reads the root whatever hides it. A bare use binds the constant or the function its file declares outside
  every owner and body, a field of the enclosing class first (`OwnMembers::First`); a `from` import or a destructured
  `require` names a module the graph does not keep, so a name another module exports binds nothing.
- **Lua.** An argument, a value an assignment, a `return` or a loop takes, a field's value, `{ on_click = handler }`,
  an operand, a condition and an index's key read a name; an assignment's target, a callee and a table indexed through
  `.`, `:` or `[]` do not. A parameter hides its name in its function, as `self` does in a method declared with `:`
  and a local function its own name in its body; a local hides its name from the end of its declaration to the end of
  its block, the chunk included, so `local f = f` reads the `f` outside, and a loop variable inside its loop. Outside
  every function a local function, a local bound to a function and a local declared without a value hide nothing: each
  is a definition the file binds, the last through a later `function f()` or `f = function() end`. A use binds the
  function its file declares outside every function.
- **Rust.** An argument, an element, an operand, a range's bound, a condition, an indexed value or an index, a returned,
  a broken-out, a block's or a closure's last value, the value a `let`, a `let` condition, an assignment, a `const`, a
  `static`, a field, a shorthand field, a reference, a cast, a `match`, an arm or a `for` takes, either side of `+=` and
  its kin, the base of a field access or a method call, and an awaited or a `?` operand read a name; `Self::make` read
  so names the member of the type around it, and `Service::make` the member of `Service`. A pattern's name hides it from
  the end of what the binding reads on: a parameter in its function or closure, an arm's pattern in the arm, a `for`'s
  pattern in its body and not its iterator, an `if let` or a `while let` in the operands after it and the branch it runs
  on a match, a `let` to the end of its block; a function's own region ends the lookup. The walk keeps a bare read where
  its own inline module declares the item outside every owner and body, a `use` the file keeps binds the name where the
  read is in the `use`'s scope, or the file keeps a glob, and the read binds as a bare call of the name does: the file's
  own item, else what the `use` or the glob brings. A read through a path that may end at a module, `walk::raw_walk` or
  `crate::m::f`, holds the path's place as a path call's receiver does and binds what that module's file shows a call
  through it; a type the file declares under the path with a member of the name answers first, and an absolute `::`
  path, or one whose last segment a path call or a `use` binds to another path, keeps nothing. A read through `Self` or
  a type is kept only where the file declares a member of the name under that type. Only the base of a field access is a
  use; the field is not. [ADR 3.54](/design-docs/adr/3.54-rust-macro-arguments.md) decides the reads a macro's arguments
  write.

## Why

- A function taken as a value is the only use many functions have: `dead_code` reported 7,426 fewer Quirrel
  definitions dead on the game-engine tree once Quirrel reads were uses, and every sampled one left was read as a value
  (2026-10-19, #115).
- Each language's own bindings decide what a name means, so the walk hides a name exactly where its local does.
- A Rust read keeps a use only where the item exists in its module, a `use` brings it or the file keeps the path of
  the module it is read through, so `None`, `String::from`
  and a local the patterns missed cost nothing outside a file with a glob.
- A path in an expression denotes an item, a function item yields a value of its type, and a `use` binds a local name
  to the path it names (Rust Reference, `src/expressions/path-expr.md:12`, `src/types/function-item.md:5`,
  `src/items/use-declarations.md:15`), so a function another module defines and a file passes by name through a
  `use` or a module path is used: 25 Rust functions left the `find_unused` lists of this repository and the four
  public Rust trees, each one used so, and none came onto them (2026-11-27, #1314).
- Compiled daslang names no `private` function of another module, so the last tier binds only a name no visible
  definition holds.

## Consequences

- A Rust read through a type another file declares, `Spill::into_map`, records nothing, since a read through a type
  is kept only where its own file declares the member: 2 functions of this repository's `find_unused` list are read
  only so (2026-11-27, #1342).
- A function a Rust macro's arguments pass by name, `assert!(items.iter().all(helper))`, records no use, since
  [ADR 3.54](/design-docs/adr/3.54-rust-macro-arguments.md) reads only capitalised words there; uncounted (#1343).
- A function a serde attribute names in a string, `serialize_with = "label::kinds"`, records no use, since a string
  is no path: 17 of the 27 Rust functions of this repository's `find_unused` list are named so (2026-11-27, #1344).
- A Rust read in an inline module binds through the file's top-level `use`s, as a bare call there does, since a
  file's bindings hold one path per name. Accepted.
- In a Rust file that keeps a glob, every bare read the patterns leave is a stored use, bound or not, at 16 bytes each:
  the glob rule keeps 5,425 more uses on wasmtime's 2,128 files for 48 more bound sites (2026-11-27, #1314).
  Accepted.
- A static a Rust macro declares reads as the function of its name the file declares, as rustix's `weak!` does.
  Accepted.
- A Lua local declared without a value outside every function hides nothing, so a namesake function binds its reads
  when the local never holds it. Accepted.
- Quirrel extracts no variable, so a module variable's reads bind nothing. Accepted.
- A use records no count of arguments, so a daslang quoted call takes the first overload of its name in the file that
  declares it, whatever it passes: 9 of the 1,355 quoted calls on the game-engine tree pass a count that first overload
  does not take (2026-10-31, #801), as `LLVMFunctionType` at `llvm_dsl.das:47`. Each stays in the right file, and no
  overload they mean reads as unused. Accepted.

## Rejected

- **Give a daslang quoted call a count of arguments** — a field on every language's `UseRef` and 8 bits of every stored
  use, for 9 uses of the 1,355 quoted calls on the game-engine tree (2026-10-31, #801); the 66 calls whose overloads
  take the same counts stay beyond it, as `get_component`.
- **Lua `ValueUses::Imported`** — reaches nothing more on the three trees measured.
- **Lua: every chunk-level local hides its name, one declared without a value too** — 7 of 9 reads it dropped on Kong
  read a forward-declared local that a later `f = function() end` binds (2026-10-25, #493).
- **Lua `M.f` and `self.f` as uses of the table's method** — records 8 to 10 times the uses, nearly all of a table no
  method is declared on, for 10 more definitions reached.

## Revisit if

daslang, Quirrel or Lua gains imports the walk follows, as Rust's `use`, so a read could bind another module's item.
Not planned.
