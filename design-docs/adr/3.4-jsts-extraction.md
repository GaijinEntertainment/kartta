# Extract TypeScript and JavaScript as one family

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-jsts/src/walk.rs`, `crates/kartta-lang-jsts/src/walk/calls.rs`,
  `crates/kartta-lang-jsts/src/walk/exports.rs`, `crates/kartta-lang-jsts/src/syntax.rs`,
  `crates/kartta-lang-jsts/src/generated.rs`, `crates/kartta-lang-jsts/src/flavor.rs`,
  `crates/kartta-lang-jsts/src/lib.rs` (`CONVENTIONS`), `kartta_lang::SymbolFlags::is_label`
- **Pinned by:** `crates/kartta-lang-jsts/src/tests/extraction.rs`, `crates/kartta-lang-jsts/src/tests/identity.rs`,
  `crates/kartta-languages/tests/jsts_test_registrations.rs`

TypeScript, TSX and JavaScript are three tree-sitter grammars over one module system, and much of what a review asks
about in a frontend, a component, a handler or a hook, is a function with no declaration of its own. `kartta-lang-jsts`
extracts the three as one family and gives such a function a scope of its own, and it leaves CommonJS exports
unmodelled.

## Decision

The [crate documentation](/crates/kartta-lang-jsts/src/lib.rs) lists every form each rule below takes: the wrappers,
the registrars and their modifiers, the owner chains and the file-role patterns.

- **One family.** `TypeScript`, `Tsx` and `JavaScript` each parse with their own grammar and share one walk and the
  family `jsts`, so their files resolve against each other in one graph. Imports and re-exports resolve as
  [ADR 3.100](/design-docs/adr/3.100-jsts-import-resolution.md) decides.
- **Scopes.** A function bound to a name, by a declarator, a wrapper such as `memo` or `useCallback`, an object
  property, a class field or method, or an anonymous `export default`, is a function symbol that owns the calls of its
  body. An anonymous callback, such as an inline JSX prop arrow, opens no scope, and its calls belong to the function
  around it. A class declaration, and an anonymous `export default class`, owns the calls of its body outside those
  functions: a field's initializer, a decorator and a static block. A class expression a declarator binds,
  `const Box = class {}`, has them made by that name, `Box`, as a function bound to a name does.
- **Test registrations.** A registrar's call, `describe`, `it` or `test` and their forms, opens a scope over the
  function it is passed: a function symbol named by its description, flat as object keys are, never qualified by the
  `describe` around it. A lifecycle hook, `beforeEach` and its kin, is one named for itself. Either name is a label
  (`SymbolFlags::is_label`): the registration owns its body's calls, and no call or use of the name binds it on any
  tier, so a call of `placeOf` inside `describe("placeOf", ...)` binds the import. A description that is not
  a plain string names nothing, and a shape outside the list, `it.each(rows)(...)`, is no registration; either way the
  body stays with the scope around it. A registration in a production file opens its scope too; the file's name alone
  decides whether it is test code.
- **Owners.** A member is owned by the chain of names that encloses it: `A.Worker.run` in
  `namespace A { class Worker { run() {} } }`. A `const`, `let` or `var` that a `namespace` or a `declare module` block
  declares is its member, `A.limit`. A class with no name goes by the name that binds it, and that name owns its
  methods. A body owns no member: a function's body and a class's static block start no chain, so a class declared
  inside a function starts a new one.
- **Calls.** A capitalised JSX tag is a call of its component, and `new Foo()` a call of `Foo`. A call on a value the
  file declares records the empty receiver, a call on a value whose declaration leads to a type that type or the path
  of calls to it, and a call on `this` the class, as
  [ADR 3.101](/design-docs/adr/3.101-jsts-value-receivers.md) decides. Data sites follow
  [ADR 3.62](/design-docs/adr/3.62-jsts-data-sites.md).
- **What is not modelled.** Export assignments, `module.exports = …` and `exports.f = …`, are ordinary assignments, so
  a CommonJS module has no export surface and a function that exists only on the right side of one has no symbol. No
  symbol is an entry point.
- **File roles.** A file is test code by its name, or by a test directory on its path, whose name matches in any case; a
  directory named `test` is not enough. A file is generated code by a `@generated` or `DO NOT EDIT` banner outside a
  backtick span in the comments before its first line of code, by a first line of code past 500 bytes, or by its name. A
  `.d.ts` file is not generated. A file under a `node_modules` or `vendor` directory is vendored code.
- **Conventions.** The family's [`CONVENTIONS`](/crates/kartta-lang-jsts/src/lib.rs) set `OwnMembers::Unreached`, `.`
  as the owner chain separator, a bare call that reaches the owners enclosing the caller's own (a `namespace` is a
  lexical scope of what it holds), ECMAScript's and the DOM's methods as `runtime_methods`
  ([ADR 3.40](/design-docs/adr/3.40-runtime-method-calls.md)), `ValueUses::Imported` and `UntypedMembers::Unbound`
  ([ADR 3.173](/design-docs/adr/3.173-data-use-binding.md)), and `TypeUses::Nowhere`
  ([ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md)).
- **Fingerprint.** Each of the three languages takes its fingerprint as
  [ADR 3.120](/design-docs/adr/3.120-language-fingerprints.md) decides, with no name of its own in it.

## Why

- React frontends keep shared code in `.ts` and the components that use it in `.tsx`, so most imports and calls cross
  grammars: three separate graphs severed 34% of the resolved import edges on the frontends this was built against
  (2026-10-16, #30).
- Without a scope, every call in an arrow body belongs to the file, and a caller query dead-ends on exactly the
  components and handlers a review is about. An inline callback has no name to address, and the component around it
  is the consumer a reviewer asks about.
- A test file is built from registrations whose bodies bind no name: without a scope their calls are file-scope calls
  that the graph keeps only as names ([ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)), and no test is their
  caller. A class body's calls were file-scope calls in the same way, so the class had no callees and
  [ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)'s file-scope rule let the name reach every namesake in the
  file; of the pairs a class body's calls added, 46 of 47 were right on three trees (2026-10-23, #187). A class
  expression's body was left to the scope around it in the same way; crediting it to its name added 3 call pairs and
  removed 9, every one right, all in one bundled script on SillyTavern (2026-10-25, #466).
- A test runner calls a registration through its registrar, and no code spells its description, yet the same-file tier
  bound a call of that name to it ahead of the import the call means: 832 call pairs on the Go monorepo snapshot bound
  a registration or a hook by its name, wrong in 30 of 30 sampled, and the 803 pairs that replaced them were right in
  30 of 30 sampled (2026-10-29, #474).
- A variable a namespace declares was a symbol with no owner while a function beside it was a member, so `Ns.limit`
  selected nothing.
- A program's entry is a bundler's or a `package.json`'s notion, and it names a file, not a symbol.
- A minifier writes a whole module on a few lines, and four committed vendor bundles carried about 10% of the symbols
  on the frontends this was built against (2026-10-16, #30). Documentation of the banner convention quotes it in
  backticks. `test` is a common name for a feature or a command directory.
- The three languages differ in their grammars, so the language's name adds nothing to the fingerprint.

## Consequences

- A CommonJS module's exports have no symbol. Accepted until a consumer asks (Revisit if).
- A label counts among the namesakes of no call, so where a call's import does not resolve, a lower tier can bind a
  namesake elsewhere: 9 of the 363 pairs the rule added on SillyTavern bind the server's `delay` from browser code,
  whose import of its own `delay` binds nothing (accepted; the import miss is its own defect).
- Extracting the 172,660 scripts of a monorepo checkout of 374,827 files takes 74.5 s on one macOS thread
  (2026-10-16, #30).

## Rejected

- **A family per grammar** — severs the imports between `.ts` and `.tsx` files, a third of a frontend's edges.
- **Modelling CommonJS exports** — gains a symbol for a function assigned to `exports`, at the cost of an arm for every
  assignment shape; nothing that consumes the graph has asked for it.
- **Matching `-min.js` names as generated** — no such file was found, and hand-written names end in `-min`.
- **Marking `.d.ts` files generated** — such files are commonly written by hand.

## Revisit if

A consumer needs the export surface of CommonJS modules. None asks yet.
