A C++ value's class is spelled where a local or a parameter is declared, a bare name in a member reads the class
before the namespaces, and an include pastes the included text in place. The walk records each data site of a
function with the class its operand's declaration names, and the graph binds it through tiers that follow C++ name
lookup, then through the includes, so a field's uses answer across a header and its users and a function named
without a call is reached, at the cost of a scope stack in the walk and guesses through includes where the operand's
class is unknown.

## Decision

**What the walk records.** Only a function's initializer list and body yield uses, and outside them only the
initializers below. `x.f` and `x->f` that are not a call's callee are member uses whose path is the class a local or a
parameter `x` is declared as, a value of it or a reference to it for `.`, a pointer to it for `->`, spelled with its
scopes (ADR 3.65), else empty. `this->f`, a constructor's initializer list and its writes, a base's initializer
included, are on the own receiver. A designated initializer writes the field of the type its named declaration or
compound literal spells; a nested list records the empty path. A bare name that no local, parameter, capture or
enclosing template parameter declares before it stays a bare use. The walk keeps a scope stack in its one pre-order
pass, following every declarator the crate's data symbols follow and a reference declarator's unnamed child, range-for,
structured bindings and init-captures. Enumerators and macros are kept.

**How the graph binds it.** In order, each tier taking the first that binds:

- **The own receiver, or a bare name in a member** (`OwnMembers::First`): the own class's field at 85, else the field
  of the one base the lookup of a bare call certainly finds (`Shape::Inherited`) at 85. A base it only admits beside
  free definitions, or several bases, count the use as ambiguous. The own receiver stops there; a bare name goes on to
  the value tiers.
- **A path naming a class:** that class's field or method at 85, else the field of the one base of it that declares the
  name at 85. A name the graph holds no type of binds nothing. A type the graph holds that neither declares, an alias
  most often, leaves the use to the untyped tier.
- **The untyped tier** (`UntypedMembers::IncludedField`): the one field of the name in the file at 80, in its direct
  includes at 70, then, for a name at most 32 fields share, in the files those reach at 70.
- **A bare name past the class** (`ValueUses::Included`): the one namespace-scope variable, constant or free function
  of the name in the file at 80, in the direct includes at 70, then in the files those reach at 70 for a name at most 32
  values share; a declaration and its definition count once, several in one tier bind none, and a type or a macro binds
  no use.
- **Which class:** the own class or a declared one is taken among the classes the use's file declares or includes, then
  those it reaches. Where the member's declaration lies in a file the member's own file does not reach, an inline
  implementation header that a class header includes at its end, the tiers look from the declaration's file as well
  ([ADR 3.74](/design-docs/adr/3.74-cpp-declaration-links.md) links the two). A
  class of the name the file reaches no way binds nothing, and the use counts as ambiguous where it names a field.

**Names read without a call.** C++ takes a function as a value by its name and names a class's constant through its
scope, so these are uses too, beside the free function the value tiers above bind:

- A qualified name read without a call, `Config::kLimit`, `&Widget::draw` or `ns::Box<int>::empty`, is a use of its
  last name on the path of its scopes (ADR 3.65); `::limit` is bare. A callee stays a call and a type no use. The class
  tier binds a method of the owner beside its field, as a method taken as a value.
- A scope can name a namespace, which emits no symbol
  ([ADR 3.72](/design-docs/adr/3.72-cpp-name-qualification.md)): the value or free function
  outside every owner whose qualified name is the scope and the name binds where the use's file reaches it. The lookup
  runs as C++ looks a qualified name up, from the namespaces around the use outward, a member's those around its class
  (ADR 3.72 leaves them out of a member's own qualified name), so `detail::scale` inside `cfg` binds
  `cfg::detail::scale` at 88, and from the root at 90; a scope written from the root, `::cfg`, reads the root alone.
  Such a value wins over the member the class tier finds by the scope's last name, a namesake class
  `other::detail`'s `scale` for `cfg::detail::scale`, unless that member takes the same qualified name. A scope that
  names neither a class nor a namespace holding the name, `std::npos`, binds nothing.
- A namespace-scope value takes its qualified name as the key a function takes its signature as
  ([ADR 3.74](/design-docs/adr/3.74-cpp-declaration-links.md)): `extern` without
  an initializer declares it, anything else defines it, and a file-local value takes none. A declaration links
  to the one definition where either's file reaches the other, so a use bound to the header's declaration counts at the
  definition, as a call does.
- An initializer outside every body, `{by_file_ctrl, ...}` or `Handler h = on_event;` at namespace scope, or a member's
  default, records each name it reads as a use at file scope, which binds no edge and keeps only the name: `dead_code`
  counts every definition of that name the file sees as reached
  ([ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)). A lambda outside a body yields nothing.

`find_references` on a C++ field notes that a member on a value whose type the graph cannot name binds only where one
field of the name is in the file or its includes, and that `ambiguous=` counts the rest.

## Why

- A definition's head holds annotation macros the grammar reads as names: `PX_FORCE_INLINE void f()` gave `void` 10,656
  uses on the game-engine tree (2026-10-18).
- C++ looks a bare name in a member up in the class, then its bases, then the namespaces, and the operand's declaration
  names its class: those tiers bound 48 to 50 of 50 sampled sites right each (game-engine tree, 2026-10-18).
- A translation unit holds the class header's text before the inline implementation header's, so the class is there
  for a member defined in the latter.
- A class the file neither includes nor reaches bound right 26 of 50 times, its twin in another vendored copy most
  often; those uses count as ambiguous instead.
- A callback, a method table or a dispatch array names a function where no call does, and `dead_code` judged such a
  function dead: of the function uses, the file tier binds 85%, 49 of 50 sampled right (game-engine tree, 2026-10-19).
- A value declared in a header and defined in a source is one value, whose uses split across the two otherwise.
- A namespace's constants, globals and callbacks are read through the namespace, and its qualified name is the one
  thing that names it: of the use pairs the namespace tier binds on the game-engine tree, 90 of 90 sampled were right,
  30 of them from an enclosing namespace (2026-10-24).

## Consequences

- The include tiers guess: 44 to 50 of 50 right, the misses most often the right field in another copy of a library the
  tree vendors twice. Accepted.
- Enumerators and macros are bare uses that bind nothing and count nowhere, most of the 832,391 such names on the tree.
  Accepted.
- A using-directive is no scope the lookup searches. Accepted.
- The namespace tier reads every namespace value of the name once per qualified use. Accepted.
- The field note omits the tier through the files the includes reach. Accepted.
- An initializer outside a body binds no edge, so `find_references` lists no site for it. Accepted.
- Qualified names read without a call add about 250,000 uses on the game-engine tree, 4 MB at 16 bytes. Accepted.

## Rejected

- **A base the lookup only admits beside free definitions** — 6 of 30 sampled right: generated parameter structs share
  a name across namespaces and two vendored copies.
- **Names filtered at extraction by spelling, enumerator-like or all-caps** — the walk sees one file, and 3,967 of
  10,428 same-file constants it binds are all-caps `static const`s.

## Revisit if

The extraction parses every class head and the operand's type where no declaration spells it, so that the include
tiers could give way to the class tiers. Not planned.
