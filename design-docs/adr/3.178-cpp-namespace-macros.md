# Blank a namespace's own macros at its edges

- **Date:** 2026-10-24
- **Governs:** `crates/kartta-lang-cpp/src/repair.rs` (`lone_macro_line`, `namespace_closes`, `opens_a_namespace_body`,
  `is_set_apart`)
- **Pinned by:** `crates/kartta-lang-cpp/src/repair.rs`
  (`a_lone_macro_line_is_blanked_at_a_namespace_s_edges_and_nowhere_else`), `crates/kartta-lang-cpp/src/walk.rs`
  (`a_namespace_a_macro_opens_inside_another_keeps_its_definitions`)

A library that versions its namespace opens it with a macro inside the outer one, `namespace absl {` then
`ABSL_NAMESPACE_BEGIN`, and closes it with another before the outer `}`. The grammar reads both as code, so before the
first parse ([ADR 3.3](/design-docs/adr/3.3-cpp-parse-repair.md)) both lines are blanked, at the price of one scan of a
file's braces where a lone macro line stands before a `}`.

## Decision

- **The opening macro.** A macro name alone on its line whose code above, past comments and other such lines, is the
  `{` of a namespace head, `namespace`, `namespace a` or `namespace a::b`, is blanked where a blank or a comment line
  sets it apart from the code below.
- **The closing macro.** A macro name alone on its line whose code below, past comments and other such lines, is a `}`
  that closes a namespace body is blanked. The braces are matched once per file, past comments and literals and with
  each conditional's first branch taken, at the first such line.
- **Elsewhere at a brace the line stays.** Before the `}` of a table or a function it is a value or a statement, and
  after any `{` with code right below it, `DAGOR_NOINLINE` above a function, it annotates that code.

## Why

- The opening macro reads as the type of the declaration below it: an enum or a constant there is lost, and a function
  starts at the macro, its signature holding the macro and the comments after it. Blanked, abseil's
  `absl::ConstInitType` and acl's `acl::compression_level8` are found, and 42 game-engine files start a definition at
  its own line (2026-10-24, #370).
- The closing macro reads as a declaration that takes the namespace's `}`, and beside a member misread elsewhere the
  second parse of [ADR 3.169](/design-docs/adr/3.169-cpp-second-parse-repairs.md) lost `namespace rtm` from 52
  definitions of rtm's `quatf.h` (2026-10-24, #370).
- Both misread lines leave errors in the first tree; blanked before it, 143 of the 1,607 game-engine files that parsed
  twice parse once, leaving the 1,464 that [ADR 3.169](/design-docs/adr/3.169-cpp-second-parse-repairs.md) counts
  (2026-10-24, #370).

## Consequences

- A file with a lone macro line before a `}` scans its braces once: 2,555 of 43,356 game-engine files, 61 of their
  572 MB, a pass the 143 second parses it saves outweigh; build time and peak memory stay within noise (2026-10-24,
  #370).
- A constant behind an annotation macro of its own, `ABSL_DLL extern const char RFC3339_full[]`, parses only with the
  opening macro above it, so 1 constant of 43,356 game-engine files is lost (#370). Accepted.

## Rejected

- **Blank a lone macro line at any brace** — changes 316 game-engine files against 73: a table's last entry, a
  statement and a body's annotation lose their macro (#370).
- **Blank the opening macro with code right below it** — takes `BENCHMARK_EXPORT` and `DAGOR_NOINLINE` off the
  signatures of 14 files to bring back 3 variables (#370).
- **Blank the closing macro only after a blanked opening one** — spares the brace scan, but misses rtm's
  `scalar_common.h`, whose opening macro stands above a namespace head, and parses 88 more files twice (#370).

## Revisit if

A `tree-sitter-cpp` release reads a lone identifier before a `}` as an error the parser recovers from locally. High
confidence that 0.23.4 stays the latest for the near term.
