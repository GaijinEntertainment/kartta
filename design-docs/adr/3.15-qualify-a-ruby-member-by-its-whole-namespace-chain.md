Ruby reopens a type in any file, two libraries often hold types of one name in different namespaces, and much of a
type's structure comes from method calls in its body. The extraction reads one file and runs no code: it qualifies a
member by the whole namespace chain of its type and reads the class-body macros with no receiver as structure, at the
cost of what only running the code would show.

## Decision

**A member is qualified by the whole chain of its type.** The owner of a member is the `::`-joined chain from the
outermost enclosing type, `Geo::Shape`, and the member's name extends it: `Geo::Shape#area` for an instance method,
`Geo::Shape.build` for a class method, `Geo::Shape::MAX` for a constant or a nested type. A `class << self` block is
transparent, and its `def` is a class method. A method ends the chain, so a type that a method holds belongs to no
outer type. `def self.x` belongs to the enclosing type, `def Foo.x` to the nearest enclosing type named `Foo`, else to
`Foo` as written, and `def obj.x` to no type. A constant bound to `Struct.new` or `Data.define` is a class, and a
qualified constant assignment, `Foo::BAR = 5`, defines nothing.

**A call records its receiver as the source spells it.** A plain name is the receiver as written, `self` is the chain
of the caller's own type, and any other expression, a constant included, is the empty receiver. How a call outside
every method names its type is [ADR 3.158](./3.158-credit-a-ruby-call-in-a-type-s-body-to-the-type.md).

**A class-body macro is structure only with no receiver.** `include`, `extend` and `prepend` add their constant
arguments to the parents of the enclosing type; in a method body they add nothing. `attr_reader :x` defines
`Owner#x`, `attr_writer :x` defines `Owner#x=`, and `attr_accessor` both, as class methods inside `class << self`.
A bare `private`, `protected` or `public` sets whether the methods after it in the body are exported, accessors and
aliases included; `private :x` changes a method the body has already declared, and `private def x` changes one method.
A `class << self` body keeps a visibility of its own, which covers its class methods, and `private_class_method :x` and
`public_class_method :x` change a class method from the class body. A bare `private` in a class body leaves a
`def self.x` exported, as Ruby does. `module_function` is not tracked. A macro stays a recorded call beside the
structure it adds. The same words with a receiver, `Other.include Comparable`, are calls of methods of their own, and
add no structure.

**An alias is one callable with the body its original names at the alias.** `alias` and `alias_method` define the new
name, a class method inside `class << self`. When the file declares the original before the alias, in the same type,
kind and enclosing method, the two symbols are one callable: the original's body defines it, and the alias declares
it. A later redefinition of the original leaves the alias on the earlier body, as Ruby does. A later declaration of the
alias's own name replaces the alias, so that alias joins nothing.

**A bare name records no call.** A call with no receiver, no arguments and no parentheses, `setup`, parses as a name,
the same as a read of a local variable. `setup()` parses as a call and records one.

How a require resolves is [ADR 3.157](./3.157-resolve-a-ruby-require-under-the-load-roots-projects-set.md).

## Why

- Two types of one name keep their members apart, and a call on `self` names the chain of the caller's own type, so
  it binds the member of that type and no namesake's.
- The macros are the class body's structure, and read without a receiver they mean what Ruby's own `Module` methods
  do: on Homebrew, the visibility of a `class << self` body and `private_class_method` hide 161 class methods
  (2026-10-16).
- Telling a bare name from a local variable needs the bindings of each scope, and a binding form the extraction missed
  would turn a variable read into a wrong edge.

## Consequences

- A type or a method that code defines at run time, `Class.new`, `define_method` or `class_eval`, is not seen.
  Accepted.
- `private_class_method def self.x` leaves `x` exported, since the modifier reads only symbol arguments and a
  `def self.x` is exported. Open (#501).
- A call written `setup`, with no arguments, binds nothing. Accepted.

## Rejected

- **An owner by its last name, `Worker`** — one string less per member, but `A::Worker#run` and `B::Worker#run` become
  one name, and a call binds to either.
- **A call for a bare name that the file does not bind** — finds `setup`, but needs every binding form of each scope,
  block parameters and patterns included, and a form it misses turns a variable read into a wrong edge.

## Revisit if

The extraction runs code, or reads what a type gains at run time through `define_method` or `class_eval`. Not planned.
