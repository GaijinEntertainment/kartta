# Bind a call through a module's file as the module's paths see it

- **Date:** 2026-10-22
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`through_binding`, `imported_module_export`, `module_export`,
  `module_item`, `used_by_module`, `globbed_by_module`, `macro_exported_below`, `glob_imported`, `include_roots`),

A Rust module is one file, so an import that names only a directory, as a Go package is, cannot say which module a path
reaches. An import binding and a dot import may name a module's file; a call through one binds what that file shows the
caller under Rust's visibility, or what the file's own `use`s and globs reach, and a name none of them answers goes on
to the tiers below.

## Decision

- **Module files as targets.** An import binding's target, and a dot import's, may be a file the graph holds. Only the
  Rust resolver emits one ([ADR 3.50](/design-docs/adr/3.50-rust-cross-crate-paths.md)). The tier reads a bare call's
  bindings only where the file stores one and one of them names a file the graph holds.
- **Calls through the file.** A call whose receiver names such a binding, `tree::text()`, or a bare call of a name such
  a binding imports, `text()` after `use kartta_lang::tree::text;`, binds the definition the file declares at its top
  level under the name, outside every owner and inline module, at 95.
- **What the file shows.** It shows an exported definition to any call, a definition it does not export only to a call
  from the module and below, and a test definition only to test code whose file shares an include root with the
  module's file, a file that nothing includes and that reaches both, as Rust's visibility and its test build admit
  them; `module_item` in [`resolve.rs`](/crates/kartta-graph/src/resolve.rs) states each case.
- **Types.** A type binds only where the file defines nothing else of the name at its top level, since a language that
  keeps types apart from values lets a type share its name with the function that the call names.
- **Macros.** A macro the file does not export answers no call through the file, and a function of its name binds past
  it. A macro invocation reaches only the file's macros and any other call none
  ([ADR 3.177](/design-docs/adr/3.177-macro-invocation-binding.md)), so a name the file exports both as a macro and as
  a function binds each by the call's form.
- **A name the file does not define.** Where the file defines nothing of the name at its top level, the file's own
  binding of the name answers, `pub use` or not: the call binds what the binding's file shows it under the name the
  binding reaches there, by these rules, so `kartta::unmatched()` binds `kartta::reading::unmatched` through
  `pub use crate::reading::unmatched;`. A binding into code the graph does not hold leaves the call to the tiers below.
  Without a binding of the name, the file's globs answer the same way, where one answer comes of them. Each module's
  file is read once under each name, so a chain or a cycle of re-exports ends.
- **Exported macros below.** Where neither answers a macro invocation, the one exported macro of the name that the
  files it includes define, directly or through others, binds it at 95, outside test code; two such macros leave it to
  the tiers below. A binding that reaches a function or code outside the graph answers no macro invocation, since a
  `use` of a function brings no macro of its name. Otherwise the call goes on to the tiers below. `used_by_module` and
  `macro_exported_below` in [`resolve.rs`](/crates/kartta-graph/src/resolve.rs) state each case.
- **Globs.** A dot import of a module's file, a Rust glob, binds a bare call that the caller's own file does not
  answer, by the rules above, at 95, where one such import answers; two leave the call to the tiers below. It comes
  after the caller's own file, which shadows a glob, and after Go's dot imports, which name no file.

## Why

- Rust's `use` and paths reach an item by its module, and the module is a file: without the file, `find_callers` of
  `kartta_lang::tree::text` answered none with 198 calls ambiguous, and with it answers 151 (this repository,
  2026-10-22, #203).
- A module's file can hold what its module exports through `pub use`, `#[macro_export]` macros and inline modules that
  its definitions do not show, so a miss there does not mean the name is absent.
- Rust admits a private item from its module and the modules below it, and a crate's test build compiles its test
  items for that crate's tests alone: tree-sitter's 223 calls of the test helper `get_language` from
  `crates/cli/src/tests/` bind only when test items bind crate-wide (2026-10-23, #384).
- `#[macro_export]` places a macro at its crate's root whatever module defines it.
- A `use` is an item of its module, and a crate root re-exports its API through `pub use`: 179 pairs of this repository
  and the Go monorepo snapshot that run through one bound by name or not at all, `kartta::unmatched(...)` in kartta-mcp
  among them (2026-10-23, #217).
- Code that compiles reaches no private `use` from outside the module and the modules below it, so a binding needs no
  visibility for the graph to follow it, and the file's bindings already hold the path of each `use` that
  [ADR 3.50](/design-docs/adr/3.50-rust-cross-crate-paths.md) keeps.

## Consequences

- A re-export that renames, `pub use m::f as g`, binds `g()` to `f`, but `find_callers` of `f` reads the sites listed
  under `f` alone and misses it. Accepted: neither measured tree renames a function so (2026-10-23).
- An item a re-export reaches binds by its own visibility: a `pub(crate)` one only from its module and below, though
  Rust admits it crate-wide. Accepted.
- The private and test checks read the file's include closure and walk to its include roots, only for a definition the
  file does not export or a test definition.

## Rejected

- **End the cascade at a module file's miss, as a directory's does** — drops 1,219 edges in a cargo registry of 488
  crates (2026-10-22), the right ones among them re-exports the file holds but does not show, postcard's `to_stdvec`
  and anyhow's `anyhow!`.
- **Exported items only** — binds 359 fewer pairs in this repository, each sampled one right (2026-10-23).
- **Test items within their module only** — tree-sitter's 223 `get_language` calls bind nothing (2026-10-23).
- **A re-export record per `pub use`, followed by the re-export tier** — stores again the path a binding holds, and that
  tier reads the re-exports of every file a caller includes, where a Rust parent sees a child module's item only
  through a `use`.
- **A binding's visibility kept, so a private `use` answers only its module and below** — binds the same 179 pairs, as
  each of the 21 that run through a private `use` comes from that module's own subtree, at the cost of a field in every
  binding the graph stores (2026-10-23).

## Revisit if

A miss in a module's file, its bindings, its globs and the macros exported below it leaves only what an inline module, a
`#[path]` module or a crate outside the tree holds, so ending the cascade there may pay. Medium confidence.
