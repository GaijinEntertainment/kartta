# Read a PHP property's class from its declared type, else from the writes its class's body makes

- **Date:** 2026-11-01
- **Governs:** `crates/kartta-lang-php/src/walk.rs` (`own_field`, `is_own_class`, `field_call`, `name_field_receivers`,
  `declare_fields`, `declare_field`, `property_class`, `write_field`, `field_written`, `assigned_class`)
- **Pinned by:** `crates/kartta-lang-php/tests/field_classes.rs`,
  `crates/kartta-languages/tests/php_property_receivers.rs`

A call on `$this->c` or `self::$c` names no class, so it took the name tiers, which bound the caller's own member, a
namesake or nothing. The extraction holds what settles it, the property's declared type or else the writes in the
class's own body, so the walk records that class as the call's receiver, at the price of the writes one class's body
does not show.

## Decision

- **The receiver.** A member call on `$this->name` or `$this?->name` has as its receiver the class the property of that
  name holds in the type around the call, spelled as a variable's is
  ([ADR 3.199](/design-docs/adr/3.199-php-variable-classes.md), The class). A property no rule below settles keeps the
  empty receiver of a chained call. `$this->$name` and `$this->{X}` name no property. The type around the call is the
  innermost class, trait or anonymous class, and a closure in it stays in it.
- **A static property.** `self::$name`, `static::$name` and `Own::$name`, where `Own` is the type around the call by any
  spelling PHP compiles to it, read and write the property as `$this->name` does, under the same key. The walk leaves
  `parent::$name`, another class's name, `$class::$name` and `self::$$name` outside the table: a call on one keeps the
  empty receiver, and a write through one says nothing.
- **A scoped call.** `$this->name::m()`, `$this?->name::m()`, `self::$name::m()` and the other spellings of A static
  property take the class the same table holds, as a member call does. An instance method through `::` binds as
  `Own::m()` does, and `$this->name::NAME` is no call. A property the table gives no class, a `string` one or one
  written a class name, keeps the empty receiver.
- **A declared type.** A property with a type, a promoted constructor parameter's included, holds the class the type
  names, whatever any write says. `X`, `?X` and a union of `X` with built-in types that hold no class, `X|null`,
  `X|false`, `X|int`, name `X`, and `self` and `parent` give the receiver of that word. A built-in type alone, `object`,
  `mixed`, `iterable`, a union of two classes, an intersection and a type in disjunctive normal form name none, and no
  write then names one.
- **The writes read.** A property with no type holds the one class the writes in the class's own body give it, in any
  member and in any order. `$this->name = new X` and `??= new X` name `X`, as a variable's `new` does, and
  `$this->name = $v` names the class `$v` holds there. An anonymous class gives its name.
- **What says nothing.** `= null`, `unset($this->name)` and a declaration with no default or a default of `null`.
- **A miss.** Two classes, or a class beside any other value, name none: a call, a compound assignment but `??=`,
  `new $class`, a conditional, either side of `=&`, a list or `foreach` target, a default other than `null`, or an
  untyped promoted parameter.

## Why

- A typed property holds its type at every read. PHP checks each write (`zend_assign_to_typed_prop`,
  `Zend/zend_execute.c`), a read before the first write throws (`zend_typed_property_uninitialized_access`,
  `Zend/zend_object_handlers.c`) and a read through `__get` is checked against the type
  (`zend_verify_prop_assignable_by_ref_ex` in `zend_std_read_property`), a `get` hook takes the type as its return type
  (`Zend/zend_compile.c`, `zend_compile_property_hooks`), and a child redeclares a parent's typed property only with the
  same type (`emit_incompatible_property_error`, `Zend/zend_inheritance.c`). All read at php-src 8.5.12.
- One key serves both kinds, because a class holds one property of a name: a second declaration, static or not, is a
  compile error (`zend_compile_prop_decl`, `Zend/zend_compile.c`), and `self::$c` on an instance property throws
  (`zend_std_get_static_property_with_info`, `Zend/zend_object_handlers.c`). The static lookups below were also run on
  the `php:8.5.12-cli` image.
- `$object::m()` compiles its scope to `ZEND_FETCH_CLASS` (`zend_compile_class_ref`, `Zend/zend_compile.c`), which takes
  an object's class at run time, the class a string names, and throws on any other value (`Zend/zend_vm_def.h`), so an
  object's class answers `::` as it answers `->`. `ZEND_INIT_STATIC_METHOD_CALL` looks the method up there, and a method
  that is not static runs only where the caller's `$this` is an instance of that class, on that `$this`, and throws
  elsewhere (`zend_non_static_method_call`). A string's class is a run-time value the table does not hold. The shapes
  were run on `php:8.5.12-cli`.
- A typed static property holds its type at every read as well. `ZEND_ASSIGN_STATIC_PROP` checks each write
  (`Zend/zend_vm_def.h`), a read before the first write throws (`zend_std_get_static_property_with_info`), no hook and
  no `__get` answers one (`zend_compile_property_hooks`), `unset` throws (`zend_std_unset_static_property`), and a child
  redeclares a non-private one only with the same type (`do_inherit_property`, `Zend/zend_inheritance.c`), so
  `static::$c` reads that type whichever child is called.
- `self` in a trait's method is the using class (`zend_fixup_trait_method`), and each using class takes its own copy of
  the trait's static with the trait's type (`zend_do_traits_property_binding`), so the trait's declaration answers.
- `parent::$c` reads the parent's table past a redeclaration in the class's body, so the body's key is not its property.
- A method call on anything but an object throws (`zend_invalid_method_call`, `Zend/zend_execute.c`), so a call that
  runs on `?X` or `X|int` runs on `X` or a class below it, whose lookup the walk from `X` reads
  ([ADR 3.193](/design-docs/adr/3.193-receiver-class-members.md)). `iterable` compiles to `Traversable|array`
  (`zend_compile_single_typename`), so it counts as a second class beside `X` and alone gives no receiver, and a
  property takes neither `static`
  (`optional_type_without_static`, `Zend/zend_language_parser.y`) nor `callable` (`zend_compile_prop_decl`).
- An untyped property takes whatever is written, so the writes are all the bytes say of it, as a Quirrel field's are
  ([ADR 3.198](/design-docs/adr/3.198-quirrel-field-receivers.md)). The receiver names the class from the root, so a
  type outside the graph binds nothing and no namesake ([ADR 3.167](/design-docs/adr/3.167-php-outside-class-calls.md)).
- On Laravel and Symfony the rule adds 4,370 pairs, removes 1,874 and promotes 6,206 to 85. Of 30 sampled on each side
  all are right, and so are 30 more of the added pairs on a property with no type. A removed pair bound a namesake, the
  caller's own member, as a decorator's `$this->inner->encrypt()` did, or a class outside the graph's
  (2026-11-01, #899).
- On the same trees the static rule adds 25 pairs, removes 6 and promotes 17 to 85. All 25 and all 17 are right; 4 of
  the removed pairs bound the caller's own member or a namesake, and 2 an implementor of the declared interface
  (2026-11-01, #923).
- On the same trees a scoped call adds and removes no pair and promotes 129 from 70 to 85, all right of 30 sampled, as
  `$this->factory::response()` to `Factory::response` (2026-11-01, #931).
- Only the walk holds the declarations and the writes, and the graph already reads a receiver from the root, so nothing
  is stored per property.

## Consequences

- A property a parent or a trait declares or writes is outside what the class's body shows. A call in the child on a
  parent's typed property keeps the empty receiver, and an untyped property's writes in the child read as if they were
  all: a parent's or a trait's write of another class goes unseen, as does a write from outside the class,
  `$o->c = new Other`, or through a computed name, `$this->$n = 1`. Not counted. Accepted.
- `static::$c` on a `private` property reads the class a child's redeclaration of any type gives it, where the child is
  called, and the walk reads the private declaration: none of the 42 pairs the static rule added or promoted on the two
  trees is one (2026-11-01, #923). Accepted.
- `parent::$c->m()` and `Other::$c->m()` keep the empty receiver, since the table holds the class around the call alone:
  0 and 5 sites on Laravel and Symfony (2026-11-01, #923). Accepted.
- A `__get` answers a read of an untyped property `unset` cleared, with any class: 6 of the 39 files on the two trees
  that unset a property of `$this` hold one (2026-11-01, #899). Accepted.
- A declared type is the bound of the value, not its class: an interface's type binds the interface's declaration where
  an implementor overrides it, so `find_callers` of the implementor loses the call, about 326 of the 2,168 sites the
  rule moved on Laravel and Symfony (2026-11-01, #899), until a query reads through the interface (#929).
- A member only a child holds, past an `instanceof`, stays with the name tiers:
  `$this->accessDecisionManager->getVoters()`, on an interface that lacks it, still reaches no
  `TraceableAccessDecisionManager::getVoters`. Accepted.
- A type outside the graph binds nothing, so `?ContainerInterface $namedResolvers`, which holds a `ServiceLocator` at
  run time, loses `ServiceProviderInterface::get`: 1 of the 30 removed pairs sampled (2026-11-01, #899). Accepted.
- A property set from a variable the walk holds no class for names nothing, `$this->c = $c`, and so does one set from a
  call, `$this->container = Container::setInstance(new Container)`: 18 of the 54 Laravel pairs that still bind
  `ApplicationStub::instance` read that property (2026-11-01, #899). Accepted.
- A union of a class and `string`, `X|string`, reads `X` through `::`, where its string may name another class: none of
  the 12 properties the two trees call through `::` is one (2026-11-01, #931). Accepted.
- A cold Symfony build goes from 125.06 G to 125.37 G instructions and from 54.10 MB to 54.39 MB of heap at its peak,
  for a map and a list per file and the longer receivers (2026-11-01, #899). Accepted.

## Rejected

- **Writes ahead of the declared type** — a write in the class's body narrows a declared interface to one class, and a
  subclass's or an outside write can differ, where the type holds for every read.
- **A write of a typed property's class when the type names none, `int|X` or `A|B`** — the type states that another
  value is possible, which one class's body cannot rule out.
- **`Other::$c->m()` through the file's table** — built for a class of the same file, which all 5 sites have: 2 name a
  class outside the graph and 3 an untyped property, so it moves no pair on Laravel or Symfony, for a list per file and
  a scan per site (2026-11-01, #930).

## Revisit if

The extraction records a parent's or a trait's properties for the graph to read across files. High confidence for a
declared type, medium for the writes.

- 2026-11-01 — A static property: `self::`, `static::` and the class's own name take the table's reading, since the
