# Reach the engine through one JSON call over a small C ABI

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-23
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-ffi`, `crates/kartta-ffi/include/kartta.h`, `crates/kartta-ffi/src/wire/`, `bindings/go`
- **Pinned by:** `crates/kartta-ffi/tests/dispatch.rs`, `crates/kartta-ffi/tests/golden.rs`,
  `bindings/go/kartta/kartta_test.go`

Go and Node consumers reach the engine across a C boundary. `kartta-ffi` exports five functions, and every method is a
name and a JSON object of params answered in JSON, so one dispatch serves every binding and test and a new method is a
match arm, never a new export; each answer pays a JSON encoding that costs nothing next to the query.

## Decision

**The ABI.** `crates/kartta-ffi/include/kartta.h` is hand-written and committed, and declares `kartta_abi_version`,
`kartta_open`, `kartta_call`, `kartta_string_free` and `kartta_free`. The Go binding's cgo build compiles the header and
links every function it declares, in CI on Linux and macOS, so a header that drifts from the library fails there.

- `kartta_open` takes `{"root": <path>}` and answers a handle, or null with `{"code", "message"}` written to the error
  out-parameter, never a bare null for a caller that asks for the reason; a null out-parameter discards it.
- `kartta_call` takes a NUL-terminated method name and the params' bytes and answers `{"ok": <answer>}` or
  `{"err": {"code", "message"}}`, never a null string; null params with a zero length, empty text and `null` read `{}`.
- Arguments are borrowed for the call; every returned string is the caller's, freed once with `kartta_string_free`.
  Calls on one handle may run at once from any threads; `kartta_free` must not run beside a call on the same handle.
- `kartta_abi_version` returns 1, which `KARTTA_ABI_VERSION` must equal; the Go binding checks it at open, answering
  `ErrABI`. It changes only when a binding built against an older header would misuse the library.
- Every entry point runs under `catch_unwind`: `kartta_open` and `kartta_call` answer `internal` and the handle stays
  usable, and the frees drop a panic. That holds only for a library built with unwinding panics.
- The crate builds a `staticlib`, which cgo links into Kensai's static musl binaries, and an `rlib`, which a Rust shell
  such as the Node addon (ADR 4.3) builds on; it sets no global allocator
  ([ADR 4.31](./4.31-set-no-global-allocator-in-the-c-abi-s-archive.md)). serde lives in this crate alone.

**The wire** is kartta's own JSON. It keeps the method names Kensai already calls where the meaning holds and carries
no compatibility layer for the shapes Kensai reads today; Kensai migrates once. Each method's contract is a golden file
([ADR 4.36](./4.36-pin-each-wire-method-in-a-golden-file-both-bindings-replay.md)).

- Methods: `build`, `refresh`, `cancel`, `stats`, `version`, `resolution`; `callers`, `callees`, `call_path`,
  `references`, `definitions`, `sources`, `search`, `implementations`, `dead_code`, `outline`, `dependents`,
  `analyze_segment`, `analyze_change`; `list`, `glob`, `fuzzy`, `grep`. `version` lists the methods and languages a
  library answers, and an unknown method answers `unknown_method`, its message listing the methods.
- `paths`, `len`, `grep_index/build` and `validate_globs` are not methods: `len` is `stats`'s `entries`, the content
  index is a `build` option made in the same walk, and a bad glob answers `invalid_glob` from the call that takes it.
- A graph query names no graph by default and answers one part per graph its name selects a symbol in; `lang` names one
  graph by a language or its family, and one the build did not make answers `invalid_params`, listing those it did. A
  file query (`outline`, `dependents`, `analyze_segment`) answers the `graph` that claims the file and if it is `held`.
- Params are one type per method and refuse unknown fields; JSON that is neither an object nor `null` answers
  `invalid_params`. Answers may gain fields: a new key is additive, absent where it would say nothing.
- A bound left out or 0 takes the method's default: callers 3 calls deep, callees 1, a walk 500 symbols; a call path 8
  deep and 20,000 symbols; 500 references; 10 definitions or sources; 20 search hits; implementations 3 deep and 100
  implementors; dependents 3 deep and 100 files; a segment or a change 3 deep and 500 symbols; 100 dead definitions; 20
  unbound sites of `resolution`; a listing 1 level and 1,000 entries; 50 fuzzy matches; grep 100 matching lines, 1,024
  bytes a line and 4 MiB a file. The caps a caller can lift take 0 as none: a listing's depth and entries, glob's and
  grep's matches, dependents' files, and a source's lines and line bytes. `glob` has no default cap.

**Answers carry what they left out.** Every capped or bounded answer is an object with the engine's counts: `total`,
`truncated`, `turned_away`, `unexpanded`, `below_confidence`, `passed_over`, `unresolved`, grep's account of every
candidate and its `unsearched` (ADR 1.11), a listing's `excluded` and `unlisted`. Beside those:

- `callers`, `callees`, `references` and `implementations` take `path_prefix`, `call_path` `from_path_prefix` and
  `to_path_prefix` (ADR 3.35); a part that passed symbols over lists at most five `candidates`, a `symbol` and the
  `count` the query ranks by, per end for `call_path`.
- A callers part lists `file_scope`: each file whose top level calls or uses the root's name and sees the root, with
  its `confidence`, in path order, without a line (ADR 3.23); `below_confidence` counts those the floor drops.
- A callers part, a segment's symbol and a change's seed count `ambiguous`, the calls of the name that bound nothing
  because several definitions may be meant; a `references` part always carries it.
- A callers or callees part carries `self_call`, the `confidence` and `line` of the root's call of itself (ADR 3.7).
- A segment's field, variable or constant lists its `users`, a change's seed counts `user_count` (ADR 3.22), and
  `dead_code`'s `excluded` counts `reflected` (ADR 3.23).
- `glob` and `fuzzy` take `exclude` (ADR 1.4), and a glob answer counts `excluded`. A fuzzy query with terms counts
  `matched`, those past the limit included; an empty query never carries it (ADR 1.5).
- `search` answers a part for every graph with a hit, its fill-up hits marked `fuzzy` and counted in `fuzzy_total`.
- How a symbol method read a name and why it matched nothing is
  [ADR 4.34](./4.34-say-how-a-symbol-method-read-a-name-and-why-it-matched-nothing.md); a type's unrecorded uses,
  [ADR 4.35](./4.35-flag-a-type-s-references-where-its-language-records-no-use-as-a-type.md).

**Error codes.** `invalid_request`: a null handle or method, null params with a length, bytes not UTF-8, or params not
JSON. `invalid_params`, `unknown_method`. `invalid_root`: `open` could not read the root's metadata, or it is not a
directory. `not_built`: no build has finished, or the last failed or was cancelled; `building`: one is in flight.
`build_failed`, `build_cancelled`; `no_stamps`, `refresh_failed`, `refresh_cancelled`
([ADR 4.32](./4.32-refresh-the-wire-s-engine-in-place-where-its-build-kept-stamps.md)). `invalid_glob`,
`invalid_pattern`; `not_found`, `not_a_directory` for a `list` path. `internal`: the engine panicked, or an answer could
not be encoded.

**Lifecycle.** `open` names the tree and walks nothing. `build` walks it once and builds the index, the optional content
index and every graph (ADR 3.6), replacing what an earlier build made; it drops the old engine before it walks, so a
handle never holds two, and a query already running keeps the engine it asked until it returns. Queries run concurrently
with each other and with `cancel`. Builds run one at a time: a build empties the slot when its turn comes, so a query
answers `building` while it runs and answers from the last build's engine while it waits its turn. A query that finds no
engine looks again under the lock a build publishes under, so a build finishing beside it never reads as `not_built`. A
cancelled or failed build leaves no index, the file index included. Cancellation is
[ADR 4.30](./4.30-cancel-a-build-a-grep-or-a-refresh-by-the-id-it-names-even-before-it-enters.md), and following the
tree [ADR 4.33](./4.33-follow-the-tree-over-the-wire-only-when-a-build-asks.md).

**The Go binding,** module `github.com/GaijinEntertainment/kartta/bindings/go`, `go 1.27.2`, has no dependencies.

- `wire` holds the params, answers and error codes with no cgo, so code that only handles answers builds and tests
  without the library. A `wire.Code` is an error and a `*wire.Error` unwraps to its code, so
  `errors.Is(err, wire.NotBuilt)` matches.
- `kartta` links `libkartta_ffi.a` statically through cgo from the same checkout: the header from
  `crates/kartta-ffi/include`, the archive's directory from `CGO_LDFLAGS`. A `Kartta` is safe for concurrent use: calls
  share a read lock, and `Close` cancels what is in flight, waits for the calls to return under the write lock and
  frees the handle. A `runtime.AddCleanup` frees a handle nobody closed.
- Typed calls cover the methods Kensai calls, each answering its `wire` type, a graph query's as a `wire.Matches[T]`
  with one part per graph. `callees`, `dead_code`, `resolution` and `cancel` go through `Call`, with the wire types or
  raw JSON.

## Why

- One dispatch keeps the bindings thin: Go and Node translate JSON and decide nothing, so the rules live once, in Rust.
- Answers are kilobytes, where JSON costs nothing next to the query, and an object gives every count a place a bare
  array does not. `paths` answered 150 MB of JSON on three million entries, and no consumer called it.
- cbindgen is MPL-2.0, which `deny.toml` does not allow, and the surface is five functions.
- A silently ignored option is worse than an error; an added answer field breaks no consumer that reads what it knows.
- A cancelled walk holds whichever entries its threads reached, nothing worth keeping, and the consumer's own deadline
  is what cancels, so Kensai's rule that file tools outlive a failed graph build does not survive the fused build.

## Consequences

A failed or cancelled build leaves the file tools without an index until the next build finishes: accepted.

## Rejected

- **A drop-in for the ABI Kensai calls today** — its three-step open, grep-index build and graph build cannot map onto
  one fused walk without walking twice, the cost ADR 3.6 removed, and its bare arrays have nowhere to put a count.
- **Typed C structs, or a schema'd binary format** — every answer a C layout marshalled in Go and again in JS, and every
  new count an ABI break.
- **Keep the old engine until the new one is built** — two engines at the build's peak.
- **A `cdylib` beside the archive** — no consumer loads one, each crate type is a full link per build, and a shared
  library beside the archive makes `-lkartta_ffi` link dynamically on macOS.

## Revisit if

A consumer's answers grow large enough that encoding them as JSON shows beside the query that made them. High
confidence: every answer but a `glob` without a limit is bounded by default.
