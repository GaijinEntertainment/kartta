# Reach the engine through one JSON call over a small C ABI

- **Status:** accepted
- **Date:** 2026-10-18
- **Revised:** 2026-10-19
- **Initiative:** `04-consumer-surfaces`

Go and Node consumers reach the engine across a C boundary. `kartta-ffi` is that boundary: a static library exporting
five functions, every method a name and a JSON object of params, every answer JSON. One dispatch serves every binding
and every test, so a method is a match arm and never a new export, and a binding translates JSON and decides nothing.
serde lives in this crate alone; the library crates carry no wire derives.

## The ABI

`crates/kartta-ffi/include/kartta.h` is hand-written and committed: `kartta_abi_version`, `kartta_open`, `kartta_call`,
`kartta_string_free`, `kartta_free`. cbindgen is MPL-2.0, which `deny.toml` does not allow, and the surface is five
functions. The Go binding's cgo build compiles the header and links every function it declares, in CI on Linux and
macOS, so a header that drifts from the library fails there.

- **`kartta_open`** takes `{"root": <path>}` and answers a handle, or null with the structured error
  `{"code", "message"}` written to an out-parameter: never a bare null for a caller that asks for the reason.
- **`kartta_call`** takes a NUL-terminated method name and the params' bytes, and answers `{"ok": <answer>}` or
  `{"err": {"code", "message"}}`, never a null string.
- **Ownership:** arguments are borrowed for the call; every returned string is the caller's, freed once.
- **`kartta_abi_version`** returns 1, which the header's `KARTTA_ABI_VERSION` must equal; the Go binding checks it at
  open. It changes only when a binding built against an older header would misuse the library. The `version` method
  lists the methods and languages a library answers.
- **Panics:** every entry point runs under `catch_unwind`. `kartta_open` and `kartta_call` answer the code `internal`
  and the handle stays usable; the frees, which answer nothing, drop a panic. That holds only for a library built with
  unwinding panics.
- **Crate types:** `staticlib`, which cgo links, as Kensai's static musl binaries need, and `rlib`, which a Rust shell
  such as a napi-rs addon builds on. No `cdylib`: neither consumer loads one, each crate type is a full link per build,
  and a shared library beside the archive would make `-lkartta_ffi` link dynamically on macOS.

## The wire

kartta's own JSON, keeping the method names Kensai already calls where the meaning holds, with no compatibility layer
for the shapes it reads today; Kensai migrates once.

- **Lifecycle:** `build`, `cancel`, `stats`, `version`, `resolution`.
- **Graph:** `callers`, `callees`, `call_path`, `references`, `definitions`, `sources`, `search`, `implementations`,
  `dead_code`, `outline`, `dependents`, `analyze_segment`, `analyze_change`.
- **Files:** `list`, `glob`, `fuzzy`, `grep`.
- **Answers carry what they left out.** Every capped or bounded answer is an object with the engine's counts:
  `total`, `truncated`, `turned_away`, `unexpanded`, `below_confidence`, `passed_over`, `unresolved`, grep's
  `unsearched` and its account of every candidate, a listing's `excluded` and `unlisted`. A bare array for search,
  implementations, dead code or dependents would have nowhere to put them.
- **A graph query names no graph by default:** it answers one match per graph the name selects a symbol in; `lang`
  names one graph by a language or its family. A file query answers the graph that claims the file and whether it holds
  it.
- **Params refuse unknown fields,** one type per method, because a silently ignored option is worse than an error;
  answers may gain fields. A bound left out or 0 takes the method's default: callers 3 calls deep, callees 1, a walk
  500 symbols, a call path 8 deep and 20,000 symbols, 500 references, 10 definitions, 20 search hits, 100 implementors,
  dependents 3 deep and 100 files, 100 dead definitions, a listing 1 level and 1,000 entries, 50 fuzzy matches, and
  grep 100 matching lines, 1,024 bytes a line and 4 MiB a file. Only the caps a caller can lift take 0 as none: a
  listing's depth and entries, glob's and grep's matches, dependents' files, and the lines and line bytes of a source.
- **Dropped:** `paths` (150 MB of JSON on three million entries, and no consumer calls it), `len` (folded into
  `stats` as `entries`), `grep_index/build` (the content index is a `build` option, made in the same walk), and
  `validate_globs` (a bad glob answers `invalid_glob` from the call that takes it).
- **Golden files** under `crates/kartta-ffi/tests/golden`, one method each, pin a request on a fixture tree and its
  answer. A Rust test replays them through the dispatch and the Go binding's test through cgo. For a method with a
  typed call, the Go test decodes the request into its typed params and encodes the typed answer back, so a Go type
  that drops a field the wire sends fails it; the other methods replay as raw JSON through `Call`. Both read answers
  back exactly, so a score pinned there is the one the engine answered.

### Error codes

| Code | Meaning |
| --- | --- |
| `invalid_request` | A null handle or method, null params with a length, bytes not UTF-8, or params not JSON |
| `invalid_params` | JSON that is not the method's params: an unknown field or language, a wrong type |
| `unknown_method` | No method of that name; the message lists the methods |
| `invalid_root` | `open` could not read the root's metadata, or the root is not a directory |
| `not_built` | The method needs a build and none has finished, or the last failed or was cancelled |
| `building` | The method needs a build and one is in flight |
| `build_failed` | The build stopped on a failure that leaves no index |
| `build_cancelled` | A cancel stopped the build |
| `invalid_glob`, `invalid_pattern` | A glob or a content pattern does not compile |
| `not_found`, `not_a_directory` | `list` names a path the index does not hold, or one that is not a directory |
| `internal` | The engine panicked, or an answer could not be encoded |

## Lifecycle and concurrency

- **`open` names the tree; `build` walks it once** and builds the index, the optional content index and every graph
  (ADR 3.6), replacing what an earlier build made. It drops the old engine before walking, so a handle never holds two;
  a query already running keeps the engine it asked until it returns.
- **Queries run concurrently** with each other and with `cancel`, each reading the engine through a shared reference.
  **Builds run one at a time.** A build empties the slot when its turn comes, so while it runs a query answers
  `building`; while it still waits its turn, queries answer from the engine the last build left.
- **A fresh cancel per build.** A build enters the library under a token of its own, registered before it waits its
  turn, and the caller names it with an id it uses once. `cancel` with that id trips it, running or waiting; an id
  that has not entered yet is remembered, with no bound, so a context that fires before its build reaches the library
  still stops it, and a cancel that comes after its build finished stops a later build that reuses the id; `cancel`
  with no id stops every build in flight. A cancel with no id while no build is in flight never stops a later build,
  as one token per handle would. A build whose token was tripped answers `build_cancelled` even when its walk had
  finished, so a cancel that reported `stopped` always wins. A query that finds no engine looks again under the lock a
  build publishes under, so a build finishing beside it never reads as `not_built`.
- **A cancelled or failed build leaves no index,** the file index included: a cancelled walk holds whichever entries
  its threads reached, so there is nothing worth keeping, and the consumer's own deadline is what cancels. Kensai's
  rule that file tools outlive a failed graph build does not survive the fused build.

## The Go binding

`bindings/go`, module `github.com/GaijinEntertainment/kartta/bindings/go`, `go 1.27.2`, no dependencies.

- **`wire`** holds the params, answers and error codes with no cgo, so code that only handles answers builds and tests
  without the library, the split Kensai's tools rely on. A `wire.Code` is an error, and a `*wire.Error` unwraps to its
  code, so `errors.Is(err, wire.NotBuilt)` matches.
- **`kartta`** links `libkartta_ffi.a` statically through cgo, from the same checkout: the header is read from
  `crates/kartta-ffi/include`, the archive's directory comes from `CGO_LDFLAGS`. A `Kartta` is safe for concurrent use:
  calls share a read lock, `Close` cancels the builds in flight and takes the write lock. `Build(ctx, …)` gives its
  build an id and trips it once `ctx` is done; the error then matches both `wire.BuildCancelled` and the context's
  cause. A `runtime.AddCleanup` frees a handle nobody closed.
- **Typed calls cover the methods Kensai calls,** each answering its `wire` type, a graph query's as a
  `wire.Matches[T]` with one part per graph. `callees`, `dead_code` and `resolution`, which it does not call, go
  through `Call`, with the wire types or raw JSON.

## The allocator

The library crates stay allocator-neutral (ADR 1.18); `kartta-ffi`'s archive is a final artifact and could set one.
Kensai ships static musl, so the choice was measured under musl: cold engine builds of the game-engine tree, all
sixteen languages, no cache, `threads` 4, in an Alpine container (musl 1.2, aarch64) limited to 4 CPUs, the tree
mounted from the macOS host, variants interleaved, two rounds each on a host shared with other builds:

| | build | peak | resident after the build |
| --- | --- | --- | --- |
| musl's malloc | 99.0–100.3 s | 688–691 MB | 666–673 MB |
| mimalloc 3.3 | 89.2–89.3 s | 1,000–1,010 MB | 778–1,010 MB |
| mimalloc, purge delay 0 and a forced collect after the build | 88.4–91.6 s | 738–757 MB | 661–681 MB |

**The library sets no global allocator: musl's malloc stays.** mimalloc builds about 10% faster, and tuned to purge at
once and collect after the build it ends where musl does, but it peaks 50–70 MB higher, and it brings two crates and a
C build into the archive for it. Untuned, it peaks 45% higher and keeps up to half again as much resident. musl hands
freed memory back without a trim: it peaks below what glibc reached with both trims in ADR 1.18, 1,059–1,400 MB, and
ends where glibc did after them. The build times are not comparable to ADR 1.18's: under this session's load and mount,
neither allocator came near its 27–33 s, and no glibc build ran beside them.

Revisit when build time matters more to a consumer than its peak, or when a glibc build of the same session shows the
musl build's time is the allocator's.

**Revised 2026-10-19: a name's methods take a path prefix, and an answer lists what it passed over.** `callers`,
`callees`, `references` and `implementations` take `path_prefix`, and `call_path` takes `from_path_prefix` and
`to_path_prefix`, which keep the symbols a name selects to the files under them (ADR 3.35). A `callers`, `callees`,
`references` or `implementations` answer that passed symbols over carries `candidates`, at most five, each a
`symbol` and the `count` the query ranks by; a `call_path` match carries them per end, as `candidates.from` and
`candidates.to`. The key is absent when nothing was passed over, so every other answer keeps its bytes; the Go and
TypeScript wire types carry both.

## Considered Options

- **A drop-in for the ABI Kensai calls today** — its three-step open, grep-index build and graph build cannot map onto
  one fused walk without walking twice, the cost ADR 3.6 removed, and its bare arrays have nowhere to put a count.
- **Typed C structs, or a schema'd binary format** — every answer a C layout marshalled in Go and again in JS, and
  every new count an ABI break; answers are kilobytes, where JSON costs nothing next to the query.
- **A cancel token per handle** — one stray cancel stops every later build.
- **Keep the old engine until the new one is built** — two engines at the build's peak.
- **A `cdylib` beside the archive** — no consumer loads one, and it changes what `-lkartta_ffi` links on macOS.
