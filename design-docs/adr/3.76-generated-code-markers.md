# Count a generated-code marker only outside a code span

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-20
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang/src/banner.rs` (`kartta_lang::Banner`)
- **Pinned by:** `crates/kartta-lang/src/banner.rs` (`a_header_that_quotes_a_marker_only_mentions_it`,
  `a_marker_outside_every_backtick_span_announces_the_banner`, `a_marker_in_a_code_fence_only_mentions_it`,
  `a_backtick_span_closes_only_at_a_run_of_its_own_length`, `a_byte_order_mark_before_the_banner_hides_nothing`)

A generated file's symbols are flagged and kept out of dead-code analysis, and a file announces itself generated by a
marker, `@generated` or `DO NOT EDIT`, in the comments that open it. A file that documents the convention quotes the
marker there too. `kartta_lang::Banner`, which every language shares, counts a marker only outside a code span, at the
price of a banner a generator writes inside one.

## Decision

1. A file's banner is read in its leading run of blank lines and comments, after a UTF-8 byte order mark if it has one,
   up to the first line that starts with code; a marker below the first code is no banner.
2. A marker counts only outside a backtick span. A span opens at a run of backticks and closes at the next run of the
   same length, as Markdown and reStructuredText read one; a span that never closes runs to the end of its comment.
3. A span of three or more backticks that a comment leaves open is a code fence: it runs on through the next comments
   of the header until a run of its own length closes it. A shorter span ends with its comment.
4. A language that walks its own header, as Python, Lua, PHP, TypeScript and JavaScript do, reads each comment through
   `Banner::marks`, which carries no fence.

## Why

- A header that documents the convention quotes the marker, and a banner does not, though it may quote its tool: on a
  mixed-language repository 11 of the 12 files a plain substring test flagged carried the marker in backticks, and two
  of them lost 111 and 113 symbols to the flag (2026-10-16).
- A reStructuredText ``` ``@generated`` ``` span read backtick by backtick as two empty spans around a marker.
- A doc comment's example opens a fence on one line and closes it on a later one: the example of `Banner`'s own doc
  comment judged `banner.rs` generated and took its 32 symbols out of dead-code analysis (2026-10-20).
- A short span left open is most often prose, not code: a BSD license's ``` ``AS IS'' ``` leaves one open in 3,333 files
  of the C++ game-engine tree, and carrying it would hide any banner below the license.

## Consequences

- A banner a generator writes inside a code span is not seen, and the file's symbols are judged as hand-written.
  Accepted.

## Rejected

- **A plain substring test** — flags the files that document the convention.
- **A depth limit on the header** — does not separate the two: 78 generated files carry their banner at line 15,
  behind a license preamble, and a limit that keeps them excludes no mention.
- **Ignore doc comments, `///` and `//!`** — turns 520 files hand-written, 519 of them generated, the `//! DO NOT EDIT`
  of `objc2`'s header translator and of `tracing`'s `xtask`.
- **Count a marker only at the start of a comment's text** — turns 342 files hand-written, 341 of them generated, as
  `// !GENERATED FILE, DO NOT EDIT` and OpenSSL's `Generated by util/mkerr.pl DO NOT EDIT`.

## Revisit if

A generator in the trees kartta serves writes its banner inside backticks. Medium confidence that none does: the span
rules changed no generated flag but `banner.rs`'s over 106,779 files with symbols of kartta's tree, the game-engine
tree, a Go monorepo, the cargo registry, Homebrew, the Python standard library and Lua and Puppet projects
(2026-10-20).
