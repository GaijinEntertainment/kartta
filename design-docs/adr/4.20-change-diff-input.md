# Read a change from the new side of a unified diff

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-18
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-mcp/src/diff.rs`, `crates/kartta-mcp/src/server.rs` (`changed_regions`), the `regions`
  and `diff` parameters of `impact_of_change`
- **Pinned by:** `crates/kartta-mcp/src/diff.rs` (tests),
  `crates/kartta-mcp/tests/graph.rs::impact_of_change_reads_a_diff_and_counts_the_regions_no_symbol_holds`

An agent reviewing a change holds `git diff` output, and turning each hunk header into a line range by hand is a step
it gets wrong, most often for a deletion. `impact_of_change` takes the diff's text as it is, beside or instead of
explicit regions, and reads each hunk's lines on its `+` side, the tree the index holds.

## Decision

- **Input.** A change arrives as `regions`, each a file with an optional line range, as `diff`, the text of a unified
  diff, or both; the regions come first, then the hunks. A region naming only its file covers the whole file. A region
  whose end is before its start, a diff with no hunk under a `+++` header, and a call with neither are tool errors.
- **Reading.** The diff is read for its file and hunk headers, and each hunk's body by the counts its header gives, so a
  changed line that reads like a header is not taken for one. A body line that is no context, removed or added line, a
  hunk with no `+++` header before it, and a body shorter than its counts fail the call, naming the line. An empty
  line in a body is a context line whose leading space an editor stripped.
- **Lines.** A hunk covers its lines on the `+` side, under the path of its `+++` header less `b/`. A hunk that only
  deletes covers the line either side of the deletion: `@@ -40,2 +41,0 @@` covers lines 41 and 42. A deleted file is
  a whole-file region of its `---` path less `a/`, answered while the index still holds it.
- **Paths.** A path git writes quoted is not unquoted and counts in `unheld_regions`; the parameter says to pass such a
  file as a region.

## Why

- The `+` side names the tree with the change applied, the tree an index that has taken the change in holds.
- A deletion has no `+` lines; the lines either side are the code that now meets across the cut.
- Reading a body by its counts is the only way to tell a changed line that starts with `+++` or `@@` from a header.

## Consequences

- A diff of a tree the index has not taken in answers for lines that do not match the index; the description says to
  index the changed tree. Accepted.
- A quoted path, from a control or non-ASCII character, is answered as unheld. Accepted.

## Rejected

- **Regions alone** — an agent holding a diff turns each hunk header into a line range by hand, and a deletion's range
  is the one it gets wrong.
- **A diff's lines on its `-` side** — they name the tree before the change, which an index of the changed tree does
  not hold.

## Revisit if

Agents hand changes in a form other than a unified diff often enough that a second reader pays for its description
text.
