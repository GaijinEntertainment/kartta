# Reach the engine from Node through an addon over the same dispatch

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-node/src/lib.rs`, `bindings/node/src/kartta.ts`, `bindings/node/src/wire.ts`
- **Pinned by:** `bindings/node/test/kartta.test.ts`, `bindings/node/test/golden.test.ts`

Node consumers need the engine without a second wire to keep. A napi-rs addon calls `kartta-ffi`'s dispatch through its
rlib and translates nothing, and the npm package `@gaijin/kartta` types the wire and owns the JavaScript side of each
call's life; the trade is a native addon per platform and a thread or a pool slot per call in flight.

## Decision

- **The addon.** `crates/kartta-node` is a `cdylib` with `publish = false`, shipped inside the npm package. The method
  table, the error codes and the wire stay in `kartta-ffi` ([ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md)). It exports
  `open` and a handle with `build`, `refresh`, `call`, `cancel` and `close`; each but `close` takes the wire's params as
  a JSON string, and each of `build`, `refresh`, `call` and `cancel` answers the wire's envelope as the dispatch's
  bytes in a `Buffer`, which the package decodes as it parses.
- **Walks on threads of their own.** `build` and `refresh` each run on a thread of their own, named
  `kartta-<method>`, and settle a promise, whose deferred the addon makes once the thread has started.
- **Queries on the pool.** `call`, which answers every other wire method, runs on libuv's pool as a napi `AsyncTask`;
  neither a query nor a grep holds the event loop.
- **Cancel at once.** `cancel` answers at once on the calling thread, so a cancel is never queued behind the work it
  stops.
- **Open errors.** `open` answers the handle, or the wire's `{code, message}` error object, never a napi error, whose
  code would be napi's status rather than the wire's.
- **Close and the engine.** `close` drops the handle's engine. A call in flight holds its own reference and answers
  first, and the engine goes with the last of them; a handle the garbage collector takes frees its engine the same
  way. The engine's going ends the watch of a build that asked for one
  ([ADR 4.33](/design-docs/adr/4.33-wire-follow.md)), whose thread lets its watcher go within about a second.
- **Panics.** A panic answers `internal`: `Kartta::call` catches it, so the addon carries no guard of its own.
- **The package.** `bindings/node` answers one typed call per wire method, named in camelCase, its params and answer
  spelled field for field as the wire spells them, the shape the Go binding reads.
- **Untyped calls.** `call(method, params)` reaches the wire untyped. It runs `build`, `grep` and `refresh` as the
  typed calls do, and `cancel` at once.
- **Failures.** A failure rejects with a `KarttaError` carrying the wire's code, or `closed`, the binding's own, for a
  call on a closed handle. A failure of a call into a loaded addon or of reading its answer rejects with `internal`, the
  original error its `cause`: a thread that cannot start, an answer past V8's string limit. An addon that cannot load
  throws from `open` as [ADR 4.40](/design-docs/adr/4.40-node-addon-packaging.md) states.
- **The event loop.** Each call's params are serialized with `JSON.stringify`, and each answer decoded and parsed with
  `JSON.parse`, on the event loop. `open` runs there whole, its read of the root's metadata included, and so do `cancel`
  and `close`. A build, a refresh and a query run nothing else there.
- **Golden files.** The wire types are held to the golden files of `kartta-ffi` at compile time: the type check fails,
  naming the field, when a golden answer or params hold a field the type does not name, and when a golden answer is
  not of its type. The tests replay every golden file through its typed call, compare the answer as **Exact but a
  score** of [ADR 4.52](/design-docs/adr/4.52-wire-reference.md) states, and check that the typed calls cover the
  methods `version` lists.
- **Stopping, shipping and the toolchain.** [ADR 4.42](/design-docs/adr/4.42-node-cancellation.md) states how a
  signal and `close` stop a build, a grep or a refresh. [ADR 4.40](/design-docs/adr/4.40-node-addon-packaging.md)
  states the targets and how the package ships them, and [ADR 4.41](/design-docs/adr/4.41-node-toolchain.md) the
  toolchain.

## Why

- A walk of three million entries takes tens of seconds, and libuv's pool has four threads that every `fs` call of the
  process shares, so a build or a refresh on the pool would stall the process's file I/O.
- Spelling the wire as it is keeps one shape across bindings; renaming every field would copy every answer and part
  the types from the golden files.
- A panic that unwinds out of the dispatch into Node's runtime, through libuv's pool, aborts the process, so the
  dispatch catches it itself, for every caller and not only the C entry points (#76).
- A caller branches on `code`, and an addon failure carried napi's `GenericFailure`, which no `Code` names (#1047).
- A deferred holds Node's event loop open until it settles, so one made before a thread that never started kept the
  process alive past its last line (#1047).

## Consequences

- The event loop pays to serialize the params and parse the answer, by what the answer weighs: kilobytes for a capped
  answer, more for a grep or a listing whose cap the caller lifted. Accepted.
- `open` holds the event loop for one `stat` of the root, on a slow network mount for as long as that takes, once per
  open. Accepted.
- When `JSON.stringify` refuses the params, the call rejects with that error, not a `KarttaError`: the fault is in the
  caller's value, and no `Code` names it. Accepted.

## Rejected

- **koffi over the C ABI** — no Rust for Node, but a third party's native addon in the process, hand-written types, and
  every answer freed by hand.
- **`node:ffi`** — experimental, absent from Node 24, and synchronous only.
- **Builds or refreshes on libuv's pool** — each holds a pool thread for its whole walk, a whole refresh for seconds on
  a large tree, and four of them stall the process's file I/O and every cancel queued behind them.
- **An asynchronous `open`** — an API change for one `stat` (#1051).
- **A doc that narrows `KarttaError` to the engine's failures** — a caller would branch on `code` and on `instanceof`
  (#1047).
- **The addon answering its failure as a wire envelope** — the failures of reading the answer happen past the addon, so
  the package would wrap them all the same (#1047).

## Revisit if

Node gains a stable, asynchronous FFI that can call the C ABI without an addon. Medium confidence that none comes
soon: `node:ffi` is still experimental.

## History

- 2026-11-02 — Failures: a thread the addon could not start rejected with a plain `Error` and left the process running
  (#1047)
- 2026-11-02 — The event loop: the rule called JSON the only step there, and `open`, `cancel` and `close` run there too
  (#1051)
- 2026-10-22 — Close and the engine: nothing followed the tree for a Node consumer, which built again after every
  change (#154)
- 2026-10-21 — Golden files: Apple's libm and glibc round some scores apart in the last digit, so a golden that pinned
  every digit could pass on one OS and fail on the other (#294)
- 2026-10-21 — Walks on threads of their own: the addon had no refresh, and a refresh on libuv's pool would hold a pool
  thread for its whole walk (#154)
