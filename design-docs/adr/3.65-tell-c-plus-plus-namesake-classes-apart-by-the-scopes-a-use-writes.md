# Tell C++ namesake classes apart by the scopes a use writes

- **Status:** accepted
- **Date:** 2026-10-22
- **Updated:** 2026-10-22
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/twins.rs`, `crates/kartta-graph/src/members.rs` (the class tiers),
  `crates/kartta-lang-cpp/src/walk/sites.rs` (the path's scopes)
- **Pinned by:** `crates/kartta-graph/tests/graph/members.rs`
  (`a_member_on_a_declared_value_binds_the_field_of_the_namesake_its_declaration_s_scopes_name`,
  `a_member_of_the_own_receiver_binds_the_field_of_the_own_class_among_namesakes`,
  `a_method_taken_as_a_value_binds_the_first_of_namesakes_of_one_qualified_name`),
  `crates/kartta-lang-cpp/tests/data_sites.rs`

`a::Widget` and `b::Widget` share a bare name, as do a template and its specializations, so a use whose path kept the
bare name bound the field of the first class the file saw. A use's path keeps the scopes its declaration writes, and
the class tiers of ADR 3.64 take the namesake that spelling names, leaving the use ambiguous where the spelling cannot
choose, at the cost of uses that bound a namesake's field and now bind none.

## Decision

- A member use's path keeps the scopes the declaration writes, as a member call's receiver does
  ([ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md)). A qualified name
  read without a call keeps the scopes before its last name, `ns::Box` for `ns::Box<int>::empty`, or its last scope
  alone where one before it carries template arguments. The class tiers strip the path to the bare name a member's owner
  is, then choose among the classes of that name that hold the field in the tier.
- Of those, the one the spelling names from the use's scope outward binds, the method's class for the own receiver and
  a bare name; among those, a field the use's own file holds goes first. A tier with one class binds it whatever the
  spelling says.
- Where the namesakes share one qualified name, a template and its specializations or copies of one class, or where the
  spelling names none of them, the use counts as ambiguous, unless the use's function defines one of them or one's body
  holds the use.
- A method taken as a value, `&Box<T>::fill`, binds as a call to it does: the first of namesakes of one qualified name.
- Where no namesake holds the field, the bases of the one the spelling names are searched, else those of the first.
- Uses stay 16 bytes.

## Why

- Of the uses that moved to another field on the game-engine tree, 30 of 30 sampled are right; of those that went from a
  field to ambiguous, 57% of 30 sampled had bound the wrong class, and 10% the source does not settle (2026-10-22).
- Namesakes that hold no field of the name share the base that declares it, so the bases step binds right where the
  spelling names none.

## Consequences

- Namesakes of one qualified name, a template's specializations or a library's two vendored copies, leave a field use
  ambiguous, and a method taken as a value binds the first of them: telling them apart takes the template's arguments
  or the copy a file belongs to. Accepted.

## Rejected

- **A method taken as a value among namesakes of one qualified name answered as ambiguous** — lists the methods as
  unused, the specializations' `ResourceFactory<T>::try_alias` most often, since `find_unused` counts no ambiguous
  use as one that may reach a method.
- **The bases step's namesakes answered as ambiguous** — 26 of 30 sampled had bound right.
- **A tier with one class checked against the spelling** — 20 of 20 sampled had bound right, for the reasons
  [ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md) measures on calls.

## Revisit if

The extraction keeps a template's arguments or the vendored copy a file belongs to, so namesakes of one qualified name
can be told apart. Not planned.
