# Cancel a build, a grep or a refresh by the id it names, even before it enters

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-ffi/src/handle.rs` (`Calls`, `Kartta::cancel`), `crates/kartta-ffi/src/wire/build.rs`
  (`CancelParams`, `By`), `bindings/go/kartta.go` (`tracked`, `callTracked`, `Call`, `Close`)
- **Pinned by:** `crates/kartta-ffi/src/handle.rs` tests, `crates/kartta-ffi/tests/dispatch.rs`,
  `bindings/go/cancel_internal_test.go`

A consumer's deadline can fire before its call reaches the library, and a binding's close must stop calls of its own
without touching the ids its callers give. Each build, grep and refresh of
[ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md) runs under a token of its own, named by ids that a cancel can name before
the call enters, at the price of a short list of remembered ids per method.

## Decision

- **A token per call.** A build, a grep and a refresh each enter the library under a fresh cancel token, registered in
  a registry of its method's own; a build registers before it waits its turn. A call takes an `id`, which its caller
  gives, and a `binding_id`, which a binding gives, each a number the namer uses once.
- **`cancel`.** `cancel` takes `build`, `grep` and `refresh`, each an id, and `by`, `id` when absent or `binding_id`,
  the name its ids are compared with. It trips every call in flight of that method and that id, running or waiting its
  turn. An id by one name never stops a call by the other, and an id of one method never stops another method's call.
  `cancel` naming no call trips every build, grep and refresh in flight and remembers nothing. It answers `stopped`,
  whether it tripped a call in flight; a cancel only remembered answers false.
- **Remembered ahead.** An id that no call in flight holds is remembered, once, and the call of that method that later
  enters under it starts tripped; a cancel that comes after its call finished stops a later call that reuses the id.
  Each method keeps the latest 1,024 remembered ids for each name, a new one past them forgetting the oldest, which then
  stops nothing. A call scans the remembered ids of each name it carries as it enters.
- **What a tripped call answers.** A build whose token was tripped answers `build_cancelled` even when its walk had
  finished, so a cancel that reported `stopped` always wins, and leaves no index. A grep answers what it covered, with
  `cancelled` set and the files it did not open counted `unsearched`
  ([ADR 1.11](/design-docs/adr/1.11-content-search-limits.md)); a cancel that lands after it opened its last file still
  reports `stopped`, and the grep answers whole with `cancelled` false. A refresh stops only before its walk ends
  ([ADR 4.32](/design-docs/adr/4.32-wire-refresh.md)). Nothing `cancel` sends reaches a watch's follow
  ([ADR 4.33](/design-docs/adr/4.33-wire-follow.md)).
- **A binding's ids.** A binding names every build, grep and refresh it runs by a `binding_id` it picks and cancels by
  it, and passes the `id` a caller gives on as it is, in a raw call's params and a typed call's options alike. It adds
  no refusal and no mapping of its own. Both bindings follow this rule
  ([ADR 4.42](/design-docs/adr/4.42-node-cancellation.md)).
- **The Go binding.** `Build(ctx, …)`, `Grep(ctx, …)` and `Refresh(ctx, …)` cancel their call by its binding id once
  `ctx` is done. A `ctx` done before the method is called answers its cause alone, without entering the library; one
  done on the way there sends its cancel first, so the call starts stopped. A build or a refresh `ctx` stopped answers
  an error matching both `wire.BuildCancelled` or `wire.RefreshCancelled` and the context's cause, and a grep answers
  what it covered. `Call` runs a `build`, `grep` or `refresh` whose params encode as a JSON object or null under a
  binding id of its own the same way, so `Close` stops it; `Call` takes no context, so a cancel naming the caller's
  `id` is how it stops such a call short of `Close`. `Close` cancels each tracked call by its binding id, then sends
  `cancel` naming no call, and a build or a refresh it stops matches `ErrClosed` too.

## Why

- A context, a signal or a close can fire while its call is on its way to the library: a build between naming its id
  and entering, a Node query also while it waits for a libuv pool thread. Remembering the cancel is what stops such a
  call (#75); a close over a burst of builds found up to 156 cancels ahead of their build (`/usr/share`, bursts of 50 to
  2,000, 2026-10-19), and 1,024 stopped every one.
- A remembered id takes 8 bytes, so the lists take 16 KiB at most per method, and the scan as a call enters takes
  nanoseconds where a call takes microseconds at least.
- A grep is the one query long enough to need a cancel, about 12 s over a data volume, and a finished search is worth
  keeping, unlike a build a deadline cut.
- A token per call, not per handle, means a stray cancel never stops a later call it was not meant for.
- One id space per method could not tell a binding's call from its caller's: a cancel by the caller's id stopped the
  handle's call of the same id, and in Go a test under the race detector saw the handle's build stopped and the raw call
  left whole (#322).

## Consequences

- A close that lands while more than 1,024 calls of one method are on their way leaves all but the latest 1,024
  running: accepted.
- A cancel that came ahead of a call nobody makes stays remembered until 1,024 newer ones push it out: accepted.

## Rejected

- **A cancel token per handle** — one stray cancel stops every later build.
- **A bound that refuses a new remembered id** — once stale ids fill it, no early cancel is remembered again; telling a
  stale id from an early one would mean a second list of finished calls that every call writes.
- **A ring for the remembered ids** — it forgets the oldest faster, but scans the usual one or two remembered ids
  slower, and the scan runs on every call with an id while the forgetting runs only past the bound.
- **A bound of 64** — bursts of 100 and 200 builds left some uncancelled.
- **A handle id in place of the one a raw call's params give** — `Call` takes no context, so the caller's cancel by its
  id would stop nothing and stay remembered against the call the handle later gives that id.
- **The handle's ids from a range a caller's never take, a caller's id there refused** — a rule the library lacks, a
  bound only the bindings know, JavaScript holds no integer past 2^53 exactly, and a caller's cancel still reached the
  handle's range.
- **A caller's id mapped to the handle's** — a cancel that came before its raw call recorded the mapping reached
  nothing; keeping it would copy the library's remembered ids into each binding.

## Revisit if

A binding's close lands on more than 1,024 calls of one method still on their way to the library. Medium confidence:
the bursts measured reached 156.

## History

- 2026-10-21 — A binding's ids: a caller's ids and the ids a binding's handle picks shared one space, so a cancel by a
  caller's id stopped the wrong call or nothing (#322)
- 2026-10-21 — The Go binding: a raw `Call` of a build, grep or refresh picked no id, so `Close` could not stop one
  still on its way into the library (#318)
- 2026-10-21 — The Go binding: a grep that had not yet entered the library's registry missed a close's `cancel` and ran
  in full (#320)
- 2026-10-21 — A token per call: the wire gained a refresh, so a consumer takes a change in at the cost of the change
  instead of building again (#316)
- 2026-10-19 — Remembered ahead: every id that named no call in flight was kept for the life of the handle, and every
  call that carries an id scans the list (#126)
- 2026-10-19 — A token per call: nothing set a grep's cancel, and a grep of the data volume takes seconds (#111)
