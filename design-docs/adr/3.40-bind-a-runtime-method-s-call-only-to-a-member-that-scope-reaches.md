# Bind a runtime method's call only to a member that scope reaches

- **Status:** accepted
- **Date:** 2026-10-17
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `kartta_lang::Conventions::runtime_methods`, `crates/kartta-graph/src/resolve.rs`
  (`is_runtime_method`, `resolve_by_name`, `resolve_outside_scope`), `crates/kartta-graph/src/scope.rs`
  (`receiver_spells_owner`), the `runtime.rs` of `kartta-lang-jsts`, `kartta-lang-quirrel`, `kartta-lang-python` and
  `kartta-lang-rust`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs` (`a_member_call_of_a_runtime_method_binds_no_free_function`,
  `a_member_call_of_a_runtime_method_binds_a_member_only_where_scope_reaches_it`,
  `a_member_call_of_a_runtime_method_binds_the_one_callable_whose_owner_its_receiver_spells`,
  `a_member_call_of_a_runtime_method_binds_no_free_function_a_barrel_re_exports`), each language's
  `the_runtime_methods_ascend_without_a_repeat_and_name_*`,
  `crates/kartta-languages/tests/engine.rs::a_rust_call_on_a_value_binds_the_runtime_method_whose_owner_its_name_spells`

`line.trim()` calls the runtime's `trim`, not a function of the repository, and the method's name says nothing of which
type the value has. A member call of a method that a language's runtime gives its values binds a member of the name only
where scope reaches one, or the one callable whose owner its receiver spells.

## Decision

- `Conventions::runtime_methods` lists, in ascending order, the methods a language's runtime gives its own values:
  ECMAScript's built-in objects and the DOM's interfaces for TypeScript and JavaScript; the built-in types for Quirrel,
  with the methods the game engine binds on the values it hands its scripts
  ([ADR 3.145](./3.145-list-the-methods-the-game-engine-binds-on-quirrel-s-native-values.md)); the built-in types and
  the standard library's common values for Python; the standard library's methods and associated functions for Rust.
  Every other language lists none: Go's member calls take a member alone already (ADR 3.39), daslang's method syntax
  calls free functions, and Lua keeps no list.
- A member call whose callee is listed binds no free definition at any tier, and no re-export chain.
- A receiver that names an import binding names a module, not a value, and the module's export of the name binds, as
  `strings.trim()` after `import * as strings` does (ADR 3.7, tier 2).
- Such a call binds a member of its name only through the caller's file, imports, package and includes, the owner its
  receiver names, or the caller's own owner on a receiver the language allows (ADR 3.41). It binds the one callable of
  the name, at 60, only where the receiver's last segment spells that callable's owner in any case: `session.seek()`
  binds `Session.seek`, and Rust's `watcher.drain()` binds `Watcher::drain`.
- Otherwise the call binds nothing and counts as not admitted. It never binds by nearness.

## Why

- The runtime answers these calls on the value itself: every sampled Quirrel, Python and Rust site the lists unbound
  called the runtime (C++ game-engine tree and Go monorepo, 2026-10-17).
- A free function a barrel re-exports is no more what a value holds than one an include defines.
- The one callable and nearness still bound the runtime's namesakes, a Quirrel array's `append()` to a generated
  `OutputText.append` and Python's `str.format()` to a tool's `Identity.format`; of the sites the scope rule then
  unbound, under 1% were right (2026-10-19).

## Consequences

- A call of a repository member named like a runtime method binds nothing where scope does not reach the member:
  `reader.read()` on a `SockReader`, 6 sites in three copies of one tool, and seven Rust `Index::get` calls from `ix`
  values.
- Inside jQuery, the calls of jQuery's own methods that the DOM names too, `jQuery(this).replaceWith()`, bind nothing,
  the right ones with the wrong.

## Rejected

- **The lists at the proximity steps alone** — leaves the same calls bound by the caller's file, the one callable and
  the includes: 78% of the sites the lists unbind on both trees (2026-10-17).
- **The TypeScript and JavaScript list without the DOM's methods** — keeps jQuery's methods named like the DOM's at the
  price of 1,338 more sites bound to a namesake, `document.body.appendChild()` among them (2026-10-17).
- **A near free function only where the caller's file includes its file** — unbinds the right calls nearness finds
  with the wrong ones, and lets the members near the caller take 20,482 more guesses (2026-10-17).
- **A member in either near directory before a free function** — unbinds 182 sites on both trees and leaves every
  runtime call with no member near it bound (2026-10-17).
- **The members in the caller's directory alone** — at most a sixth of the sampled sites right in any language
  (2026-10-19).
- **A guess tier for every runtime call** — keeps every one of these sites, shown as a guess.
- **The receiver's spelling at every step** — binds 39% of its sites right (2026-10-19).

## Revisit if

A language's extraction records the type a value holds for its member calls, as Go's type paths and C++'s declared
locals do, so that the type rather than the name picks the member. High confidence that the name alone stays unsafe.
