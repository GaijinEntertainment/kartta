# Test the Go binding on musl against the archive a release ships

- **Date:** 2026-11-02
- **Governs:** `.github/workflows/ci.yml` (job `go-musl`), `scripts/go-musl.sh`, `rust-toolchain.toml` (`targets`)
- **Pinned by:** `.github/workflows/ci.yml` (job `go-musl`)

The archive exists for static musl consumers ([ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md)), and no job built it there.
One job builds it on each musl target of [ADR 4.46](/design-docs/adr/4.46-release-scope.md) and runs the Go binding's
tests against it; the trade is a cold build of the shipped profile on every run.

## Decision

- **Targets.** `x86_64-unknown-linux-musl` on `ubuntu-24.04` and `aarch64-unknown-linux-musl` on `ubuntu-24.04-arm`,
  each native. `rust-toolchain.toml` names both, so every `rustup toolchain install` fetches them.
- **The archive.** The job builds `dist` through `scripts/ffi-archive.sh`
  ([ADR 4.49](/design-docs/adr/4.49-distribution-profile.md)), never a debug archive, and runs the musl rows of
  `scripts/link-check.sh` ([ADR 4.58](/design-docs/adr/4.58-archive-symbols.md)) on it.
- **The image.** `scripts/go-musl.sh` runs in a `rust:*-alpine` image pinned by digest, which holds the Rust toolchain,
  gcc and musl's headers. The Go toolchain comes from `actions/setup-go`, mounted read-only, because its `go` is a
  static binary that runs on Alpine, and so the job installs nothing inside the image.
- **Two links.** `go test -race` runs the dynamic link a plain `go build` makes on Alpine, under the race detector as
  the `go` job does. `go test` with `-extldflags=-static` runs the static link Kensai ships, without the detector.

## Why

- A debug archive dies in `kartta_call`. A cgo thread takes the default stack, which `pthread_attr_getstacksize` answers
  as 131,072 bytes on this image, and a glob's regex compile overflows it, with SIGSEGV on the guard page. The same
  archive passes with `-Wl,-z,stack-size=262144` (2026-11-02, arm64 Alpine).
- `dist` passes dynamic and static on both targets, and passes a grep nested 124 groups deep and a glob nested 120 deep
  on arm64, where the next depths probed answer `invalid_pattern` and `invalid_glob` (2026-11-02). Each profile's frames
  decide the stack, so only the shipped profile proves the shipped archive.
- The race detector works on this image with Go 1.27.3: a planted race fails on both targets, dynamic and static.
  `cmd/dist/test.go` still skips it on Alpine, citing a Go issue closed in 2020.

## Consequences

- Every run compiles the archive with fat LTO and no cache: 1 min 47 s at 2 jobs on arm64 (2026-11-02). Accepted.
- Every `rustup toolchain install` downloads two more `rust-std` components, on all platforms. Accepted.
- A debug archive crashes a Go consumer on musl on its first glob; `kartta_call` cannot catch a stack overflow. Nothing
  ships it (#1101).
- The image's Rust repeats `rust-toolchain.toml`, and the Go version repeats the `go` job's. Dependabot moves neither
  pin. A stale Rust image passes, because rustup in the image installs the toolchain the file names.
- The job holds what the binding's tests reach. Their fixtures are small, so a stack bound on a real tree stays unproved
  here (#1101).

## Rejected

- **A job-level `container:`** — the runner refuses a JavaScript action in an Alpine container on arm64
  (`CheckPlatformForAlpineContainer` in `actions/runner`), so `actions/checkout` cannot run there.
- **`golang:*-alpine`** — it holds no C compiler, and `apk add` moves with the Alpine branch where a digest pins the
  rest.
- **The host with `musl-tools`** — an unpinned apt package, and musl's wrapper around the host's gcc, where the image is
  the toolchain a consumer on Alpine has.
- **A debug archive with a larger stack through the linker** — it hides the overflow and tests a build nobody ships.
- **`--release`** — as quick as `dist` on arm64, and not the archive a release ships.

## Revisit if

The binding's stack use grows past musl's default on `dist`, or a runner gains Alpine support for JavaScript actions on
arm64. High confidence in the image and the two links; medium in the stack margin, which no figure here bounds.
