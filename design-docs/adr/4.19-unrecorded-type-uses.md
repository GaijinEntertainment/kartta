# Name a language that records no use of a type in a type's references

- **Date:** 2026-10-20
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`reference_match`, `no_sites`), `kartta_lang::TypeUses`,
  `SymbolKind::is_type`, the `find_references` tool
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_references_says_the_rust_graph_records_no_use_of_a_type_as_one`,
  `find_references_keeps_its_answer_for_a_type_where_go_and_python_record_type_uses`,
  `find_references_states_both_gaps_of_a_rust_body_s_value_struct_and_the_type_gap_of_a_module_s`)

Several graphs record no use of a type where code names it as one, so a type's empty list of sites in such a language
says nothing of whether code uses it. A type's match in such a language says so by the language's name, as the
language itself states it.

## Decision

- **The statement.** A language states it as `TypeUses::Nowhere`, which its graph hands out
  ([ADR 3.1](/design-docs/adr/3.1-language-plugin-contract.md)). The match of a type in such a language,
  `SymbolKind::is_type`, names the language:
  - with no site: "no recorded site - the rust graph records no use of a type where code names it as one, such as a
    declaration, a signature, a generic argument or an import, so this does not show that nothing uses the type; grep
    finds where code names it", in place of the caveat;
  - with sites, a constructor's calls or reads of the type as a value: a `<note>` that every such use is missing.

  A struct a function body declares takes the body-local statement of
  [ADR 4.22](/design-docs/adr/4.22-unrecorded-data-uses.md) instead, which names its uses as a value too.
- **Text, not shape.** The text changes; no attribute or element is new. A type in Go, Python, DSHL or Quirrel keeps
  the caveat.
- **Which languages state it.** Rust, C and C++, TypeScript and JavaScript, PHP, Ruby, daslang and Puppet, each held to
  it by a test that extracts types its syntax names as types and finds no use of them. Go records a use wherever code
  names a type not local to a body, Python an annotation inside a body, DSHL the intervals, blocks and shaders its
  conditions and passes name; Quirrel names a repository class only in an expression, which the walk records as a read.
- **The description.** The description says a type's match names such a language, and names no language itself; a
  field's, a variable's and a constant's matches name theirs as
  [ADR 4.22](/design-docs/adr/4.22-unrecorded-data-uses.md) states.
- **The C ABI.** The C ABI's references part of such a type carries `type_uses_unrecorded`
  ([ADR 4.35](/design-docs/adr/4.35-wire-unrecorded-uses.md)).

## Why

- On this repository `Conventions`, `Widened`, `RefreshOutcome`, `Watcher` and `WatchError` answered `count="0"` while
  the Rust graph records no use of a type in a signature, a field, a `let`, a struct literal, an `impl` or a `use`
  (2026-10-20, #199).
- The language crate knows what its extraction records; a statement it makes cannot fall behind it. Of 30 replaced
  statements sampled across two trees, all are true.
- The statement reads one field of the conventions the graph already holds, and allocates only for such a type.

## Consequences

- A type in such a language still answers no use where code names it as a type; the note sends the agent to grep.
  Accepted until those extractions record type uses.

## Rejected

- **A list of family names in the server** — a language crate outside kartta could not state it, and such a list falls
  behind its languages, as the description's list of value reads had.
- **Reading the uses each graph holds, as `index_stats` counts them** — walks every file on each call, and a language
  that records value reads, as Rust does, holds uses while it records no use of a type.

## Revisit if

Every shipped language records the uses of a type where code names it as one, so no graph states `TypeUses::Nowhere`.
