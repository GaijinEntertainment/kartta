# List the types that name a parent the graph holds no definition of, one hop

- **Date:** 2026-11-06
- **Governs:** `crates/kartta-graph/src/implementations.rs`, `crates/kartta-mcp/src/server.rs` (`outside_graph`),
  `Graph::implementations_outside`, `OutsideImplementations`
- **Pinned by:** `crates/kartta-graph/tests/graph/implementations.rs`
  (`a_parent_the_graph_holds_no_type_of_lists_the_types_whose_parents_end_with_it`,
  `a_parent_that_names_a_type_the_graph_holds_is_not_outside_it`,
  `a_type_whose_parent_shares_its_name_names_no_type_of_itself`,
  `a_parent_that_names_a_defined_type_of_its_package_is_not_outside_the_graph`),
  `crates/kartta-graph/tests/graph/assertions.rs`
  (`an_assertion_of_an_interface_outside_the_graph_lists_the_type_it_names`), `crates/kartta-mcp/tests/graph.rs`
  (`find_implementations_of_a_trait_outside_the_graph_lists_the_types_whose_parents_name_it`,
  `find_implementations_of_an_interface_outside_the_graph_lists_the_type_an_assertion_names`)

A trait, an interface or a base class of a library outside the tree, as Rust's `Display` or Go's `io.Reader`, has no
definition, so [ADR 3.20](/design-docs/adr/3.20-implementor-resolution.md)'s query selects no root for it, though every
file keeps the parents it writes. `find_implementations` of such a name answers the types whose written parents spell
it, read from the files the graph already lists under the name, at the cost of one such read per miss.

## Decision

- **When it answers.** A `find_implementations` name that selects no type in any searched graph, with no `path_prefix`
  and no `line`, which look among a name's definitions, and that names no type there, is read as a parent the graph
  holds no definition of. A name held only as a function, a variable or another kind no type implements is read so
  too, ahead of ADR 3.20's answer that counts those kinds; a name that no parent spells keeps that answer, or the miss.
- **What spells it.** A written parent, an assertion's interface among them, spells the name when its last segments
  are the name's, whatever separators each writes: `fmt::Display` and `std::fmt::Display` spell `Display` and
  `fmt::Display`, and a bare `Display` spells only `Display`.
- **What is outside.** A parent counts only where it names no type of the graph, a Go defined type and an enum among
  them, read as ADR 3.20 reads a parent from the file that writes it.
- **The answer.** The envelope carries `outside_graph="true"`; the types and namespaces whose written parent or
  assertion spells it follow in path order, at most 500 with `total=` past that, and none that implements one of them.
  `namesakes=` counts the graph's types and namespaces of the name's last segment, every implementor found aside, past
  the limit too; no listed parent names one by the lookup, and the note says that a parent may still mean one.
- **Cost.** A miss reads the parents and assertions of the files listed under the name's last segment, a read of its
  own, since the root query reads those files only once it selects a root; it skips the search for suggestions when it
  lists a type. At most 0.33 ms per miss over every outside spelling of the snapshot and the game-engine tree
  (2026-11-06).

## Why

- "Who implements this library trait" is a first question an agent asks of a tree, and every parent it needs is held:
  the miss answered "no symbol matches" with unrelated suggestions for `Display`, `Default`, `ServerHandler` and
  `std::error::Error` on this repository and for `io.Reader` on the audit fixture (#1041).
- Every sampled listing was right: 30 of 30 in each of Rust, Go, C++, Python, TS/JS and Quirrel, and all 15 daslang and
  7 DSHL ones, over 3,583 listings on this repository, the Go monorepo snapshot and the game-engine tree (2026-11-06).
- A bare written parent names whatever its file binds: a Rust `use` (Rust Reference,
  `src/items/use-declarations.md:15`), a Go predeclared type (`doc/go_spec.html:2278`), the global `Error` a JavaScript
  class extends (ECMA-262, `spec.html:32413`). Read as spelling a longer name, it added 11 listings on this repository
  and the snapshot, all 11 wrong, as a TypeScript class that extends `Error` credited to `std::error::Error`
  (2026-11-06).

## Consequences

- A parent the tree does define reads as outside where ADR 3.20's lookup does not reach it or no graph holds it: a C++
  namespace alias (#1213), a namespace a using-directive brings in (#1214), a base's member type (#1215), a namespace a
  macro opens or a definition a macro makes (#839, #439), a Quirrel class a `require` binds to a local of another name
  (#1216), and a daslang class in a file without `options gen2`, which
  [ADR 3.8](/design-docs/adr/3.8-daslang-syntax-generation.md) leaves unextracted. In the samples, 11 of 30 C++ and 11
  of 15 daslang listings name such a parent, and 24 of all 32 Quirrel ones; the listed relation holds, and
  `namesakes=` flags the C++ and daslang ones.
- An implementor that writes the parent bare, `impl Error for E` after `use std::error::Error;`, is missing from the
  qualified name's listing: 14 of 27 on tokio, where the bare name lists them under the tree's own `struct Error`
  instead, because ADR 3.20's lookup does not read the file's `use` (#1211).
- A bare name lists every library's parent of that spelling, `Handler` both `http.Handler` and `slog.Handler`: at most
  83 of 166 bare listings on dagor name more than one written parent, and none on the Go snapshot or this repository.
  Accepted: each listed type writes a parent of that name, and the qualified name narrows.

## Rejected

- **Spell a written parent shorter than the name** — its 11 added listings were all wrong (2026-11-06).
- **Count only the namesakes a parent can name, not a Go defined type** — listed 151 more on the snapshot, embedders of
  a defined type of their own package, as outside the graph.
- **Read only a name with no definition of any kind** — dropped `error`'s 515 listings on the snapshot, where 85
  fields and 13 methods are named `error`.
- **Say only that the name has no definition** — the agent still greps for what the graph holds.
- **Walk the listed types' own implementors** — a type that implements a library trait through another of the tree's
  traits is a second query, of that trait's name, which the note names.

## Revisit if

An agent needs a library parent's transitive implementors in one call, or a language records the import path of a
bare parent, which would let a qualified name reach `impl Error for E`. Neither is planned.
