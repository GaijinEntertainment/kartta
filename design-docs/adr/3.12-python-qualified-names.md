# Qualify Python by the module its path names

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-python/src/resolve.rs`, `crates/kartta-lang-python/src/walk.rs`,
  `crates/kartta-lang-python/src/banner.rs`, `crates/kartta-lang-python/src/lib.rs` (`CONVENTIONS`)
- **Pinned by:** `crates/kartta-lang-python/tests/resolve.rs`, `crates/kartta-lang-python/tests/extract.rs`,
  `crates/kartta-languages/tests/engine.rs` (`a_python_call_through_a_module_outside_the_tree_*`)

A Python file declares no package: its module is its path, and an import names a module by a dotted path that the
interpreter looks up on `sys.path`, which no file of the repository states. `kartta-lang-python` qualifies every symbol
by the module its path names and probes an import from the repository root and the directories around the importing
file, a heuristic that reads no import root a configuration declares.

## Decision

**Modules.** The resolver qualifies every symbol by its module: the path with `/` turned to `.` and the `.py` or `.pyi`
extension dropped, in any case, so a method `greet` of `Service` in `pkg/service.py` is `pkg.service.Service.greet`. A
package's `pkg/__init__.py` is the module `pkg`, and a root `__init__.py` names no module. A `.pyi` stub names the
module of the source it describes, so a stub and its source define the same names. The extraction from the bytes keeps
the names local, `Service.greet`. An owner is the chain of classes alone, `Service` or `A.Worker`, joined at `.`.

**Symbols.** A function, a method and a class are symbols. A definition nested in a function is qualified by the module
alone, a nested class keeping its own methods under its name, is no member of a class around that function, and is
local to the function's body. A variable is a symbol only where a bare name is assigned at module level, the first name
of a chain alone: `a = b = 1` defines `a`, and `a, b = 1, 2` defines nothing. A class's fields follow
[ADR 3.103](/design-docs/adr/3.103-python-class-fields.md). A decorated
definition starts at its first decorator, and a name that starts with `_` is not exported.

**Calls.** A bare call records its name, and a member call its attribute with the receiver: the name where the object
is a name, `self.greet()`, and the empty receiver for anything else, `items[0].close()` or `make().run()`. A call
belongs to the function around it. A call in a class body outside every method, a lambda's, a comprehension's and a
method decorator's included, belongs to the class, and so does a call in the class's bases, which are looked up in the
scope around the class, where Python evaluates them; a class with no name, which only a broken parse leaves, keeps the
caller around it. A call outside every function and class, before the file's first definition too, is a call from file
scope ([ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)). A call in a default argument,
`def f(x=make()):`, belongs to `f`, and its name is looked up in the scope of `f`. Which bare calls are local calls, and
which record nothing, [ADR 3.102](/design-docs/adr/3.102-python-bare-calls.md) decides. Data
sites follow [ADR 3.63](/design-docs/adr/3.63-python-data-sites.md).

**Conventions.** Python sets `OwnMembers::Unreached`, so a bare call never reaches a method of the caller's class; `.`
as the owner chain separator; the built-in types' and the standard library's common methods as `runtime_methods`
([ADR 3.40](/design-docs/adr/3.40-runtime-method-calls.md)); `ValueUses::Imported`; and
`self`, `cls` and `other` as own-type receivers
([ADR 3.41](/design-docs/adr/3.41-own-owner-receivers.md)).

**Imports.** An `import` or `from ... import` that includes a file of the repository is an include alone; one that
includes none, a module of the standard library or a `from __future__ import`, is an import as written. A `__future__`
import is never probed.

- A module `a.b` is the first of `a/b.py`, `a/b/__init__.py`, `a/b.pyi` and `a/b/__init__.pyi` that exists, the stubs
  for a repository that ships only the types of a module.
- An absolute module is probed from the repository root, then from each directory around the importing file, nearest
  first. With `app/db.py` and `src/app/db.py` both present, `import app.db` from under `src/` takes the root one.
- A relative module climbs one directory for each leading dot after the first and names nothing above the root. It is a
  dependency whether or not its names are submodules.
- A from-import also includes each imported name that is a submodule, which only a package holds: no name below a plain
  module file is probed. A from-import of `*` or of no name resolves to the module alone.
- A module found nowhere may be a namespace package, a directory without an `__init__.py`: its names are probed under
  the same anchors, and the first anchor that holds one of them is the package, so a portion under a later anchor is
  not merged.
- A name that is a symbol of the module includes nothing. `import a.b.c` includes the module `a.b.c` alone, not the
  `__init__.py` files of `a` and `a.b` that the interpreter runs on the way.
- An absolute import that includes no file binds the names it writes to code the graph does not hold: `json` for
  `import json`, `np` for `import numpy as np`, `a` for `import a.b`, and `Field` for `from sphinx.util import
  Field`, so a call through or of such a name binds nothing
  ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md),
  [ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md)). It binds
  none where a module file of the repository at any depth, `a/b.py` or `a/b.pyi`, ends in the module's path or in
  that of a name it imports as a submodule, and `import a.b` binds no `a` that the probe or such a file finds.

**File roles.** A `test_*`, `*_test` or `conftest` file, or one below a `test` or `tests` directory in any case, is
test code, and so is every symbol in it, fixtures and helpers included; the rule follows pytest's naming conventions
and reads no pytest configuration. A `*_pb2` or `*_pb2_grpc` file is protobuf output. A `@generated` or
`DO NOT EDIT` marker outside a backtick span in the header marks other generated code: the comments and a
triple-quoted module docstring
before the first statement, read after a UTF-8 byte order mark, the docstring a plain, raw or unicode string, never a
bytes or formatted one, and one that an escaped quote does not close. A free `def main` directly at module level is the
entry point a script runs under `if __name__ == "__main__":`. A method whose name opens and ends with `__` is an entry
point, as is a method that `property` or `cached_property` decorates or that an accessor of the property of its name
decorates, `@size.setter` over `def size`. A free function is never one.

**Fingerprint.** The fingerprint covers the walk and the grammar, as
[ADR 3.4](/design-docs/adr/3.4-jsts-extraction.md) settles for TypeScript.

## Why

- A cache shares an extraction between every file with the same content, and two such files at two paths are two
  modules, so only the resolver, which sees the path, can qualify.
- An owner is what a receiver spells, so it is the chain of classes and not the module.
- The interpreter calls a special method, `__init__`, `__enter__` or `__eq__`, for an object it makes, a statement or an
  operator, and a property for an attribute read; no call spells their names, so a dead-code query would report each.
- A default argument's call is evaluated in the scope around the definition, and the pattern is rare enough to accept
  the wrong scope.
- A class body's calls at module level were file-scope calls: the class had no callees, `find_callers` listed the file,
  and ADR 3.112's file-scope rule let the name reach every namesake in the file. Of the 57 pairs the class's calls added
  on the game-engine tree, 49 were right, and each of the 8 wrong ones is a guess at 60 the same call already makes
  from a method (2026-10-23).
- The probe from the root and the directories around a file finds a module under a `src` layout without reading any
  of the configurations that spell import roots differently.
- A call through or of a name an import of outside code binds reaches that code: of the 792 pairs the outside bindings
  unbind on the game-engine tree, `json.dumps()` binding a project `dumps` the largest group, 60 of 60 sampled were
  false (2026-10-24).

## Consequences

- A root-first match can take the wrong one of two modules of a path, and an import root the probe does not reach
  includes nothing. Accepted (Revisit if).
- A special-method spelling is a heuristic: a class's own `__custom__`, which the interpreter never calls, is an entry
  point too. Accepted.
- Qualifying by the module costs one string per symbol in the resolver, which no cache shares. Accepted.
- A package that only its `__init__.py` holds, which the probe does not reach, counts as outside, and a call through
  its import binds nothing; on the game-engine tree no pair changes for it (2026-10-24). Accepted.

## Rejected

- **Qualifying in the extraction** — the module would depend on the path, and a cache could not share the extraction
  of two files with the same content.
- **Reading `sys.path` from the repository's configuration** — `pyproject.toml`, `setup.cfg` and a `src` layout each
  spell the import roots differently.
- **Binding outside every import the probe does not reach** — a script that extends `sys.path` reaches a module of the
  repository that way: 10 of 50 sampled unbound pairs on the game-engine tree were true (2026-10-24).
- **Looking for a package's `__init__.py` at any depth** — every initializer shares the name, so each import would
  read all of them, and no pair on the game-engine tree changes (2026-10-24).
- **Every assignment as a variable** — tuple targets and class state would add symbols that nothing imports by name.
- **Including the `__init__.py` of every package on an import's path** — an edge per level for code the import only
  runs, not code it names.
- **A synthetic initializer, `Settings.<body>`, owning a class body** — the same pairs and the same dead set, at the
  cost of 1,283 symbols in every outline and `find_symbols` on the game-engine tree, an entry flag so that `dead_code`
  does not report each, and impact walks that stop at it where the class's callers are what a change reaches
  (2026-10-23).

## Revisit if

An import root that the probe misses, or a root-first match that is wrong, shows up on a real tree. None has yet.
