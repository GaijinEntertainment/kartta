# Keep the depth a file picks off the call stack

- **Date:** 2026-11-02
- **Governs:** `crates/kartta-lang-go/src/walk`, `crates/kartta-lang-jsts/src/walk`, `crates/kartta-lang-rust/src/walk`,
  `crates/kartta-lang-php/src`, `crates/kartta-lang-python/src/walk.rs`, `crates/kartta-lang-cpp/src`
- **Pinned by:** `crates/kartta-languages/tests/file_depth.rs`

A language reads a file on a walk worker of 2 MiB, and a chain, a nesting or a qualified path in the file sets how deep
a reader recurses, so one file could end the process with every answer of the session: a stack overflow is no panic,
and nothing catches it. Every reader over such a depth is a loop, and the few that keep state per level recurse
under a bound, which trades what a file past the bound holds there for a reader that keeps its shape.

## Decision

- **A loop.** A reader of a node's chain or nesting holds its depth on the heap, in a loop or a list of what waits, and
  leaves nothing out at any depth. A new reader over a depth the file picks is written so.
- **A bound.** A reader that keeps state per level recurses only under a bound of its own, and what lies past it stays
  as no answer: Rust macro arguments stop reading at 128 nested token trees, a `cfg` operator 64 deep reads as an
  unknown atom keyed by its text, and a `macro_rules!` pattern nested 64 deep matches nothing, so its arm makes no item.
- **The test.** A source of a shape goes on a thread of 64 KiB at a depth of 4,000, a small part of what a recursion
  needs, so the test does not turn on a build's frame sizes. A bounded reader's test takes 1 MiB, which its bound fits
  in a debug build.

## Why

- A JavaScript line of 5,500 chained calls ended `kartta-mcp` at 8d03f399, a Rust macro argument of 2,000 parentheses
  and a Go chain of 2,000 calls did too, and 79 of 645 shapes over all languages ended it by a depth of 30,000
  (2026-11-02). A loop extracts every file of nine measured trees to the same bytes, so the recursion bought nothing.
- The runtime's guard-page handler prints the overflow and aborts the process, so no `catch_unwind` reaches it
  (`library/std/src/sys/pal/unix/stack_overflow.rs:129-130`, Rust 1.99.1).

## Consequences

- A loop allocates a list where a recursion took stack: at most one small list per reader call, on the path of a pattern
  or a name.
- A file past a bound says nothing of what it left out, because an extraction carries no count to an answer. No file of
  the measured trees moved under the bounds (2026-11-02). Accepted, until an extraction has a field to carry the count
  (#1137).
- A loop leaves a file its time: a reader that runs at each level of a chain costs the square of the depth, so a file
  that ended the process can now hold the build past 20 s, as a JavaScript object pattern 30,000 deep does (#1134).

## Rejected

- **A larger worker stack** — it moves the depth and leaves the file in charge of it, and a build's frame sizes move it
  again: 5,500 calls on one surface and 6,000 on another on 2026-11-02.
- **A depth check over each tree before the walk** — a pass over every node of every file, for a shape no real tree
  holds.
- **One loop for the three bounded readers** — each keeps a dozen values per level across the nested read, so a frame of
  its own would rewrite them for a depth no real tree writes.

## Revisit if

A real tree reaches a bound, which the extraction comparison of a language change would show. Confidence is high: the
bounds sit above what generated code writes, as far as the measured trees show.
