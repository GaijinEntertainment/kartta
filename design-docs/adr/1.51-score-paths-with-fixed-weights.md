# Score paths with fixed weights

- **Status:** accepted
- **Date:** 2026-08-11
- **Updated:** 2026-10-18
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fuzz/src/score.rs`, `crates/kartta-fuzz/src/class.rs`, `crates/kartta-fuzz/src/ranking.rs`
- **Pinned by:** `crates/kartta-fuzz/tests/ranking.rs` (`a_full_match_outranks_every_partial_match`,
  `contiguous_run_outranks_gapped_match`, `camel_hump_outranks_flat_match`, `shorter_candidate_wins_a_tie`,
  `case_folding_does_not_cross_the_ascii_boundary`, `a_backslash_is_part_of_a_name`)

The path scorer of [ADR 1.2](./1.2-own-the-path-scorer.md) could have exposed its whole scoring model, and no caller
set any of it. Its weights, separators, case policy and tiebreak are constants, which deletes the code that kept an
arbitrary configuration safe, at the price of bringing an option back when a caller first needs one.

## Decision

- Nothing in `kartta-fuzz` is configurable: the boundary bonuses, the consecutive and basename bonuses and the gap
  penalties are constants, and `Ranking::new` takes only the query and a limit.
- The score of a candidate a term matches in full is one more than the largest alignment the constants allow over the
  1024 aligned positions, so a full match outranks every alignment.
- Matching ignores case ASCII-first: an ASCII character folds only to its ASCII counterpart, and a pair of non-ASCII
  characters compares by Unicode lowercase.
- `/` alone ends a segment, so a `\` is a character of a name; `-`, `_` and a space separate words.
- Equal scores rank the shorter candidate first, by UTF-8 byte length, then the earlier one.
- The tests pin the orderings the constants produce, not their values; no property test ranges over a weight space.

## Why

- No caller set a weight, a case policy, a word separator or the length tiebreak. The one caller that set the segment
  separators, `kartta-fs`, set them to `/` alone, because in an indexed path `\` is a character of a name.
- Keeping the space open cost code the defaults never ran: gap clamps, saturation guards and clamps that existed only so
  an arbitrary weight could not break an ordering, separator slices consulted outside ASCII, a tiebreak switch on every
  comparison, and tests of configurations nobody used.
- Repository paths are ASCII-dominant and the case comparison sits in the scan of every candidate, so ASCII-first
  folding keeps that scan cheap.

## Consequences

- A character whose Unicode fold lands on ASCII, such as U+212A KELVIN SIGN against `k`, does not match it; accepted.

## Rejected

- **A configurable model with the shipped default as its one tested point** — the guards it needs run only for weights
  no caller sets, and property tests over the weight space test configurations nobody uses.
- **Full Unicode case folding** — a cost in the scan of every candidate, for paths that are ASCII-dominant.

## Revisit if

A caller needs another point in the scoring space; that option comes back measured against that caller. High
confidence: the one caller, `kartta-fs`, uses the defaults.
