# Read a qualified name with the other owner separator when it selects nothing

- **Status:** accepted
- **Date:** 2026-10-20
- **Updated:** 2026-10-20
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta/src/reading.rs` (`ask_reading`), `crates/kartta-mcp/src/server.rs`, the name parameters
  of `crates/kartta-mcp/src/params.rs`
- **Pinned by:** `crates/kartta-mcp/tests/names.rs`

Go, Python and TypeScript qualify a member with `.`, Rust and C++ with `::`, and a name selects by its separators as
written, so `Index.refresh_paths`, written for Rust's `Index::refresh_paths`, selects nothing as written though the
graph holds the symbol. A name that selects nothing is read once with the other separator, and the answer names the
reading.

## Decision

- **When.** A name that selects no definition of the kinds the tool takes, in the languages and under the path prefix
  it searches, in any graph searched, is read with each `.` as `::`, or else each `::` as `.`. The first reading that
  selects one is answered.
- **Never otherwise.** A name that selects as written in any graph searched is never read another way. With
  `languages` omitted, a dotted C++ or Rust name that a mirror in another language selects as written answers that
  mirror; `languages` narrows to the one meant.
- **The answer** names the reading as `read_as=` on the root of `find_callers`, `find_callees`, `find_references` and
  `find_implementations`, on the `<name>` of `read_definitions`, and as `from_read_as=` and `to_read_as=` on
  `find_call_path`. A name neither spelling selects is answered as
  [ADR 4.18](./4.18-answer-a-name-that-selects-nothing-with-what-it-does-match.md) decides.
- `find_symbols` searches the words of names and paths (ADR 3.21), which no separator divides, and reads nothing.
- **The parameters** give both spellings, `"Service.Greet"` in Go, Python or TypeScript and `"Service::greet"` in Rust
  or C++, and say how a name that selects nothing is read.
- **One reading.** The reading is the engine's `kartta::ask_reading`, which these tools and the C ABI's symbol methods
  both call, so a name reads one way on both surfaces
  ([ADR 4.34](./4.34-say-how-a-symbol-method-read-a-name-and-why-it-matched-nothing.md)).

## Why

- The two separators do not mix within a language: Rust and C++ qualify with `::` and hold no `.`, and of the C++
  game-engine tree's 991,234 C++ names only 60 conversion operators spell one, in `Args...`; Go, Python, TypeScript,
  JavaScript, Quirrel, daslang, DSHL and Lua hold no `::` (2026-10-20). A name read with the other separator is the
  name its language writes.
- The reading runs only where the answer would be "no symbol matches", so a name that selects costs nothing more.

## Consequences

- A dotted name that selects nothing where it was meant, a typo or a removed symbol, can be read into a `::` language
  that holds the name. Such an answer carries `read_as=` and the other language's `lang=`. On this repository 259 of 479
  TypeScript names of the Node binding mirror a Rust name so (2026-10-20). Accepted.
- Ruby's `Geo::Shape#area` and PHP's `App\Service::greet` keep a `#` or a `\` that neither reading writes, so such a
  name spelled with dots is answered with alternatives. Accepted.

## Rejected

- **Offering the own spelling among the alternatives alone** — the agent still asks again; `find_callers` listed it for
  1,559 of 1,685 sampled names, `read_definitions` for none, and five agents read the empty answer as a defect.
- **Each graph reading the name by its own separator, whatever the others select** — a dotted name a TypeScript or
  daslang mirror selects as written would also answer the Rust or C++ symbol, changing the answer of a name that
  matched.
- **Matching the segments of a name whatever separator joins them** — reaches Ruby's `#` and PHP's `\`, but selects
  definitions whose qualified names differ from any one spelling, so an answer cannot name what it read.
- **Checking the written name without the path prefix or the tool's kinds** — a name that selects only outside the
  prefix, or only kinds the tool does not take, answered "elsewhere" or "no symbol matches" while its reading selected
  inside.

## Revisit if

A shipped language mixes `.` and `::` within its qualified names, so a reading could select a definition the name does
not mean in its own language.
