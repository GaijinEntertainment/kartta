# Compare every crate's public API with the newest release tag

- **Date:** 2026-11-02
- **Governs:** `.github/workflows/ci.yml` (job `semver`), `scripts/semver.sh`
- **Pinned by:** `.github/workflows/ci.yml` (job `semver`)

Nothing failed a public API break, and from 0.1.0 on a break costs every consumer a major version. One job compares each
crate with the last release through `cargo-semver-checks`, from the first tag on; the trade is that the job holds what
that tool's lints see, which is not every break.

## Decision

- **Baseline.** The baseline is the newest `vX.Y.Z` tag, which is what each crate was published from. While the
  repository holds no such tag the job passes, so it starts at the cut with no edit. The `bindings/go/v*` tags and a
  tag with a pre-release suffix are no baseline.
- **Release type.** A workspace still at the tag's version is treated as heading to a minor release, so a major-level
  change fails and a deprecation or an addition passes. A commit that sets another version with `scripts/version.sh`
  decides the type itself, so a break lands after the commit that sets the next major.
- **Scope.** Every crate the tag holds is compared with all features on, on Linux. A crate new since the tag has no
  baseline and is left out until the next tag.
- **Tool.** The job installs a pinned `cargo-semver-checks` release, checks the archive's SHA-256, and runs it on the
  pinned toolchain. A bump of the tool moves its URL and its checksum together.
- **The lint.** `avoid-breaking-exported-api` in `clippy.toml` stays `false` until the cut, and #144 flips it.

## Why

- A tag is the same baseline before and after the cut, so a scratch copy with a tag runs the job's own path: there,
  hiding a public method exited 100 on `inherent_method_missing` and an added function exited 0, on the whole workspace
  (2026-11-02).
- crates.io cannot serve that path today: it holds `0.0.0` placeholders that the cut yanks, and two crates not at all.
- `cargo-semver-checks` refuses a whole `--workspace` run over a crate missing from the baseline, hence the exclusions.
- An equal version reads as a patch to the tool, which fails a `#[deprecated]` added between two cuts.

## Consequences

- A changed parameter or return type passes, because the tool has no lint for it: `Tree::is_empty` returning `u8` exited
  0 on the workspace (#1085). A workspace caller of the item fails the build instead.
- This script reads the Rust API alone. The job's second step replays the wire
  ([ADR 4.36](/design-docs/adr/4.36-wire-method-pinning.md)) from the same baseline, and the MCP answers keep their own
  goldens. A removed crate is not compared. Accepted.
- An API that a `cfg` gives only macOS or Windows is not compared. Accepted.
- A toolchain bump past what the tool supports fails this job until the tool moves. Accepted.

## Rejected

- **The registry as the baseline** — the published `0.1.0` holds the same source as its tag, and the path cannot run
  before the cut, so nothing could prove it.
- **A baseline revision written in the repository** — every release would move it by hand.
- **`--release-type` left to the tool** — every deprecation would need a version commit first.
- **`cargo-semver-checks-action`** — it adds an action around the same binary, and the job's script is what a scratch
  copy runs.

## Revisit if

The tool gains a lint for signature types (#1085), or a release can be published without a tag. High confidence in the
tag as the baseline; medium in the lint coverage, which changes with each release of the tool.
