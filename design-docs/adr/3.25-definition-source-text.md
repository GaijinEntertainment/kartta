# Read a definition's text and doc comment from its file when asked

- **Date:** 2026-10-17
- **Governs:** `crates/kartta/src/source.rs`, `Engine::sources`, `SourceOptions`, `Source`
- **Pinned by:** `crates/kartta/tests/sources.rs`

An agent that looks a definition up wants to read it, its lines and the comment that documents it, without a second
call that reads the file and counts lines. The graph holds where each definition starts and ends and keeps no file text
([ADR 3.5](/design-docs/adr/3.5-graph-file-storage.md)), so the engine reads the text from the file when asked, at the
lines the build found, and pays a read per file asked about instead of holding every file's text.

## Decision

- **The read.** `Engine::sources` answers each definition it is given with its text, in the order given, from the doc
  comment above it through its last line; [ADR 3.134](/design-docs/adr/3.134-doc-comment-forms.md) decides where the
  doc comment starts. It reads each file once for all the definitions in it, as a stream that stops at the last line
  one of them answers, its end, or the line the caller's line cap stops it at. It splits the lines without their
  endings, joined by `\n`, and a byte sequence that is not UTF-8 reads as U+FFFD. The query is the engine's, since the
  engine holds the index's root and the language of each path and the graph holds neither.
- **A file changed since the build.** The lines are those the build found the definition on, so a file edited since
  answers its new text there. `Source::resized` says whether the file's size differs from the size the build read,
  which the index keeps for every file it read; an edit that keeps the size goes unseen. A file that now ends before
  the definition starts answers no line, and one that ends sooner the lines it holds. A file that cannot be opened or
  read answers its error, the message naming the file, for each of its definitions; a file deleted since the build
  answers `NotFound`.
- **The caps are the caller's.** `SourceOptions::max_lines` bounds the lines of an answer, the doc comment's included.
  A definition longer than the cap keeps its head, and a doc comment too long to leave room loses its own head, so the
  text always holds the definition's first line. `SourceOptions::max_line_bytes` cuts a longer line on a character
  boundary, keeping its start, and never empties a line: a cap narrower than its first character keeps that character
  whole. `Source::cut_lines` names each cut line and the bytes it lost. Neither cap is set by default, and `0` lifts
  either as `None` does.
- **What a cap left out is in the answer.** `Source::doc_line` is where the doc comment and the lines the declaration
  carries start, a carried line with no comment above it included, or the definition's own line where there is none;
  `Source::first_line` is where the text starts and `Source::lines` how many lines it holds, so the definition's lines
  past them are the ones cut.

## Why

- The engine sets no bound its caller did not ask for, as content search cuts a line only at the caller's limit
  ([ADR 1.10](/design-docs/adr/1.10-content-search-engine.md)); the MCP tool sets its own caps.
- The size the index keeps makes `resized` free, and a read per query is cheap: a call answering up to 5 definitions
  took up to 1.9 ms at the 99th percentile on the C++ game-engine tree (2026-10-17, #63), and the build pays nothing.

## Consequences

- An edit that keeps a file's size answers the new text at the old lines without saying so. Accepted.
- Each call reads its files again; a consumer asking for the same definitions repeatedly pays each read. Accepted.

## Rejected

- **Keep the text of the files in the graph** — every answer without a read, at the cost of every claimed file's text
  held beside the 643 MB of heap the engine holds after building the C++ tree, for a query few calls make.
- **Detect any edit since the build by a hash of the file** — a hash kept per file and computed on every read the build
  makes, which the walk computes only for a build that shares a content cache, against a size check that is free.
- **Fixed caps, 400 lines and 1,024 bytes a line** — what an MCP tool renders, and a cut the engine would impose on
  every other consumer; the caps travel with the call instead.

## Revisit if

A consumer asks for text often enough that reading the file costs more than keeping it. No consumer does: the MCP
server reads text only for `read_definitions`, and the C ABI only for its own call of it.
