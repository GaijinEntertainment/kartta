`a::Widget` and `b::Widget` share a bare name, and a template and its specializations one qualified name; only the
scopes and the template arguments a declaration writes tell them apart. A use's path keeps both, and the class tiers of
ADR 3.64 take the namesake the scopes name and, of a template's classes, the one the arguments pick, leaving the use
ambiguous where the spelling cannot choose, at the cost of a binding for each use whose spelling names no one namesake.

## Decision

- A member use's path keeps the scopes and the template arguments the declaration writes, as a member call's receiver
  does ([ADR 3.75](/design-docs/adr/3.75-cpp-call-receivers.md)). A qualified
  name read without a call keeps the scopes before its last name, `ns::Box<int>` for `ns::Box<int>::empty`. The class
  tiers strip the path to the bare name a member's owner is, `Inner` past the last scope that takes arguments in
  `Outer<int>::Inner`, then choose among the classes of that name that hold the field in the tier.
- Of those, the one the spelling's scopes name from the use's scope outward binds, the method's class for the own
  receiver and a bare name; among those, a field the use's own file holds goes first. A tier with one class binds it
  whatever the spelling says.
- A member's class is the one whose body holds it or a declaration linked to it; where neither gives one, as for an
  out-of-line definition a using-directive lets name its class without the namespace, it is the one class of its
  owner's name nearest its file, and none where several tie, as for a call on the caller's own class. Its uses and
  calls look names up from it.
- Of a template and its specializations, a spelling's template arguments pick, scope by scope from its class outward:
  the explicit specialization whose head takes the same arguments one for one, whatever spaces they hold, else a
  partial specialization whose head takes them as written, else the primary template, which a spelling without
  arguments names too. Beside a partial specialization, whose pattern may take other arguments, a declaration's
  arguments that name only the primary pick none. A constrained partial specialization whose arguments are its own
  parameters, `requires is_void_v<T> class Expected<T, E>`, is picked by no spelling.
- A declaration's arguments pick first; then the class the use's function defines, or whose body holds the use; then
  the own class, the member's class above; then the arguments the scope of a member defined outside its class writes,
  `void Box<bool>::flip()`, which name its own class even beside a partial specialization. A call picks among
  namesakes the same way
  ([ADR 3.180](/design-docs/adr/3.180-cpp-declared-class-calls.md)).
- Where the namesakes share one qualified name and nothing above picks one, copies of one class among them, or where
  the spelling names none of them, the use counts as ambiguous.
- A method taken as a value, `&Box<T>::fill`, binds as a call to it does: where nothing picks one, the first of
  namesakes of one qualified name.
- Where no namesake holds the field, the bases of the one the spelling names are searched, else those of the first.
- Uses stay 16 bytes.

## Why

- Of the uses that moved to another field on the game-engine tree, 30 of 30 sampled are right; of those that went from a
  field to ambiguous, 57% of 30 sampled had bound the wrong class, and 10% the source does not settle (2026-10-22).
- Namesakes that hold no field of the name share the base that declares it, so the bases step binds right where the
  spelling names none.
- A definition's file includes its class's header, so the class of the owner's name nearest it is its own: of the uses
  that bind once such a member's class is located on the game-engine tree, 30 of 30 sampled are right (2026-10-24).
- Through the template arguments and the own class, 1,790 field uses of the game-engine tree that counted as ambiguous
  bind, 30 of 30 sampled right, and 143 calls bind another member or one where none bound, 30 of 30 sampled right
  (2026-10-24).

## Consequences

- A specialization a macro builds is no symbol, so its arguments name no class held, and the use stays ambiguous: most
  uses of `ecs::ComponentTypeInfo<T>::type`, whose specializations `ECS_DECLARE_TYPE` builds. Accepted.
- Arguments that are a template's own parameters, `Result<T>` inside a template over `T`, pick the primary, which the
  instantiations of a specialized argument do not reach. Accepted.
- A spelling that leaves trailing arguments to their defaults, `BsonType<const char *>`, names the primary and not
  the explicit specialization `BsonType<const char *, void>`: the graph holds no primary's head to read the default
  from. One use of the game-engine tree. Accepted.
- Copies of one class, a library's two vendored copies, still leave a field use ambiguous where the own class does not
  pick, and a method taken as a value binds the first of them. Accepted.
- A member whose own class the graph lacks takes the one namesake class nearest its file, another vendored copy's where
  that copy is the nearest: 1 of 30 sampled calls this adds binds physx's cloth `Factory` in another copy. Accepted.

## Rejected

- **Match explicit specializations only, the rest left to the first namesake** — binds 133 fewer uses, the members a
  primary defines outside its class most often, and binds `Result<T>`'s calls in `Result<void>`'s converting
  constructor to the specialization's own members.
- **Match a spelling whose arguments begin a longer explicit specialization's** — binds the one `BsonType` use, and
  binds `Box<int>` to `Box<int, bool>` wherever the primary's default is not `bool`.
- **Take the primary beside a partial specialization** — adds 189 uses and moves 14 calls, at least 10 of 30 sampled
  wrong: a pointer or an arithmetic argument that a partial specialization of `Sqrat::Var` takes.
- **A method taken as a value among namesakes of one qualified name answered as ambiguous** — leaves the use no edge
  to any of them, the specializations' `ResourceFactory<T>::try_alias` most often, where a call of the method binds
  the first.
- **The bases step's namesakes answered as ambiguous** — 26 of 30 sampled had bound right.
- **A tier with one class checked against the spelling** — 20 of 20 sampled had bound right, for the reasons
  [ADR 3.180](/design-docs/adr/3.180-cpp-declared-class-calls.md)
  measures on calls.

## Revisit if

A sample shows template arguments spelled through an alias or a macro, which name no specialization as written,
binding the primary wrongly in more than one use in ten. Medium confidence that they do not.
