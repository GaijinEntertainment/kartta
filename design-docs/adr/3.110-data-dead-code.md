ADR 3.23 judges a definition only where the graph can see it used. A field, a variable or a constant can be judged only
where the extraction records a use wherever code reads or writes one, which Go's does
([ADR 3.60](/design-docs/adr/3.60-go-data-sites.md)), so Go's data is judged, with rules for the uses
that bind nothing and for what a library or a plugin host reads by name, and every other language's data stays
`unobservable`.

## Decision

1. A language whose extraction records a use wherever code reads or writes a field or a package-level value says so in
   its conventions (`DataUses::Every`). Go does, and no other language. Its fields, variables and constants are judged
   through the calls and uses that reach them, as its types are; one local to a body stays `unobservable`.
2. A use of the name that binds nothing leaves a member of the name `uncertain` wherever the use is, and a free variable
   or constant where the use's file sees it, as a call does (ADR 3.23).
3. A call's receiver leaves no value `uncertain`: Go records the read of a value a call goes through, `cfg` in
   `cfg.Load()`, as a use (ADR 3.60).
4. The files of a name's unbound uses are kept as its uses are resolved, in a language that sets `DataUses::Every`.
5. A definition no call and no use reaches that a library or a host reads or writes by its name counts as
   `reflected`, after `live` and before `uncertain` and `dispatched` (ADR 3.23). The language marks it
   (`SymbolFlags::is_reflected`). Go marks:
   - a field whose struct tag holds a `key:"value"` pair of any value but `-`, or holds no such pair, since a library
     may read a tag whole; a tag whose every value is `-`, which `encoding/json`, `encoding/xml` and their kin skip,
     marks nothing;
   - an exported field of a package-level struct the file declares whose value the file passes to a call named
     `Marshal`, `MarshalIndent`, `MarshalWrite`, `Unmarshal`, `UnmarshalRead`, `Encode` or `Decode`, unless a tag
     skips the field, or to `ValueOf` or `TypeOf`, whatever its tags, since `reflect` honours none, where the walk
     names the value's type by the struct's name or by that of an alias or a container type of it; and the exported
     fields of the structs the file declares that such fields hold;
   - an exported function or package-level variable of a `package main` file that declares no `func main`, which the
     walk takes for a plugin's file: the go command builds a `package main` with no `func main` only as a plugin, whose
     host looks the definition up through `plugin.Lookup`.

## Why

- Every Go field, variable and constant was `unobservable`, while Go records each read and write: 34,296 Go definitions
  of the Go monorepo snapshot went unjudged, the constants and fields nothing reads among them (2026-10-23, #451).
- Without the uncertainty rules, a value read through what the graph cannot follow reads dead: in the snapshot's
  samples, 5 of 35 fields and 12 of 30 constants were used (2026-10-23).
- A marshaled field is read by reflection, which no extraction sees: of the fields Go marks on the snapshot, 1,343
  are reached by no use and would read dead
  (2026-10-23, #451).
- A field that only a decoder writes or `reflect` walks, and a plugin's export, have no recorded use either: they were
  8 of the 568 dead Go definitions of the snapshot, each read or written by name (2026-10-24, #447).

## Consequences

- A query over a whole Go graph binds the uses of every judged name: the snapshot's whole Go graph answers in a median
  0.78 s against 0.60 s before (2026-10-23, #451). The graph keeps nothing more. The build reads struct tags, and a
  file that passes a value to a marshal or reflect call scans its own symbols once for each type it follows.
- A field that a library reads through a map without a tag reads dead where no recorded use reaches it, as one that
  only a positional literal of another file's struct writes, and so does one of a struct that another file declares or
  whose value the walk types only through a call or a field, `json.Marshal(build())`. Accepted.
- A function of the repository named like a library's, `Decode(&item)`, marks the fields of its argument's struct.
  Accepted.
- A file of a program's `package main` that leaves `func main` to a sibling marks its exports as a plugin's, so a dead
  one counts as `reflected`; none of the 31 such exports of the snapshot is dead (2026-10-24). Accepted.
- The reflected mark takes the last free bit of the extraction codec's marks byte
  ([ADR 3.68](/design-docs/adr/3.68-use-storage-layout.md)): a further flag widens the codec.

## Rejected

- **Every language that records data uses** — none records one wherever code reads one, so thousands of used
  definitions would read dead: on samples of what judging would list, 10 of 30 C++ fields, all 20 TypeScript and
  JavaScript constants and 28 of 30 Python fields were used (C++ game-engine tree and Go monorepo snapshot,
  2026-10-23).
- **No uncertainty rules for data** — the used fields and constants of the samples above would read dead.
- **The exported fields of a struct with a reflected field counted reflected too** — a struct marshaled whole names some
  fields in tags and leaves others to their names, but the rule hid fields of configuration nothing reads.
- **Every exported field of a file that imports an encoding package** — 2 of the 7 fields it took out of the snapshot's
  dead list were read and written by nothing (2026-10-24).
- **Resolve a marshal call's argument in the graph, across files** — takes the same 4 fields out of the snapshot's dead
  list as the file's own structs do, for a record kept per call (2026-10-24).
- **Match a marshal call through an import of its library** — the same dead list as the name alone on the snapshot
  (2026-10-24), and it misses the repository's own wrappers of those libraries.
- **A plugin as a directory with no `func main` in any file** — takes the same 4 definitions out of the snapshot's dead
  list as the file rule, and needs the package's other files, which the walk does not read (2026-10-24).
- **Every exported function and variable of a `package main`** — marks 70 definitions of the snapshot where a plugin's
  are 4, for the same dead list (2026-10-24).
- **A call whose receiver spells a free value's name leaves it `uncertain`** — once Go records the read of the value a
  call goes through, the rule moves no definition of the Go monorepo snapshot, and costs a query a pass over every call
  (2026-10-23).

## Revisit if

A language besides Go records a use wherever code reads or writes its data, so that it can set `DataUses::Every`.
Medium confidence: C++, TypeScript and JavaScript, and Python miss reads through macros, destructuring and module-level
code.
