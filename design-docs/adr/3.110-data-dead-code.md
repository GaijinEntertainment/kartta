# Judge a language's data only where it records every read and write

- **Date:** 2026-10-23
- **Governs:** `crates/kartta-graph/src/dead.rs` (`is_observable`), `crates/kartta-graph/src/calls.rs`
  (`is_used_uncertainly`), `kartta_lang::DataUses`
- **Pinned by:** `crates/kartta-graph/tests/graph/dead_code.rs`
  (`fields_and_values_are_judged_by_their_reads_and_writes_where_the_language_records_each_one`,
  `a_use_that_binds_nothing_leaves_each_field_of_its_name_and_each_value_its_file_sees_uncertain`,
  `a_value_a_call_goes_through_is_kept_by_the_read_of_it_and_not_by_the_call_s_receiver`)

[ADR 3.23](/design-docs/adr/3.23-dead-code-judgment.md) judges a definition only where the graph can see it used. A
field, a variable or a constant can be judged only where the extraction records a use wherever code reads or writes one,
which Go's does ([ADR 3.60](/design-docs/adr/3.60-go-data-sites.md)), so Go's data is judged, with rules for the uses
that bind nothing and for what a library or a plugin host reads by name
([ADR 3.187](/design-docs/adr/3.187-reflected-definitions.md)), and every other language's data stays `unobservable`.

## Decision

- **Languages that record every use.** A language whose extraction records a use wherever code reads or writes a field
  or a package-level value says so in its conventions (`DataUses::Every`). Go does, and no other language. Its fields,
  variables and constants are judged through the calls and uses that reach them, as its types are; one local to a body
  stays `unobservable`.
- **Unbound uses.** A use of the name that binds nothing leaves a member of the name `uncertain` wherever the use is,
  and a free variable or constant where the use's file sees it, as a call does
  ([ADR 3.23](/design-docs/adr/3.23-dead-code-judgment.md)).
- **Call receivers.** A call's receiver leaves no value `uncertain`: Go records the read of a value a call goes through,
  `cfg` in `cfg.Load()`, as a use ([ADR 3.60](/design-docs/adr/3.60-go-data-sites.md)).
- **Unbound use files.** The files of a name's unbound uses are kept as its uses are resolved, in a language that sets
  `DataUses::Every`.
- **Reflected definitions.** A definition no call and no use reaches that a library or a host reads or writes by its
  name counts as `reflected`, as [ADR 3.187](/design-docs/adr/3.187-reflected-definitions.md) states with the marks Go
  sets.

## Why

- Every Go field, variable and constant was `unobservable`, while Go records each read and write: 34,296 Go definitions
  of the Go monorepo snapshot went unjudged, the constants and fields nothing reads among them (2026-10-23, #451).
- Without the uncertainty rules, a value read through what the graph cannot follow reads dead: in the snapshot's
  samples, 5 of 35 fields and 12 of 30 constants were used (2026-10-23).

## Consequences

- A query over a whole Go graph binds the uses of every judged name: the snapshot's whole Go graph answers in a median
  0.78 s against 0.60 s before (2026-10-23, #451). The graph keeps nothing more. The build reads struct tags, and a
  file that passes a value to a marshal or reflect call scans its own symbols once for each type it follows.

## Rejected

- **Every language that records data uses** — none records one wherever code reads one, so thousands of used
  definitions would read dead: on samples of what judging would list, 10 of 30 C++ fields, all 20 TypeScript and
  JavaScript constants and 28 of 30 Python fields were used (C++ game-engine tree and Go monorepo snapshot,
  2026-10-23).
- **No uncertainty rules for data** — the used fields and constants of the samples above would read dead.
- **A call whose receiver spells a free value's name leaves it `uncertain`** — once Go records the read of the value a
  call goes through, the rule moves no definition of the Go monorepo snapshot, and costs a query a pass over every call
  (2026-10-23).

## Revisit if

A language besides Go records a use wherever code reads or writes its data, so that it can set `DataUses::Every`.
Medium confidence: C++, TypeScript and JavaScript, and Python miss reads through macros, destructuring and module-level
code.
