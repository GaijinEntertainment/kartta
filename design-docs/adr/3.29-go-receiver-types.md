# Name a Go receiver by the type its declarations spell

- **Date:** 2026-10-17
- **Governs:** `crates/kartta-lang-go/src/walk/types.rs`, `crates/kartta-lang-go/src/walk/calls.rs`

- **Pinned by:** `crates/kartta-lang-go/tests/extract.rs` (`a_receiver_names_the_type_its_value_is_declared_with`,

A Go member call through a value names a method that thousands of types may define, and the value's name says
nothing of its type. The extraction records the path from a name the file sees to the value's type, as the file's
declarations spell it, and the graph follows the paths that definitions record, so the call binds the method of that
type, at the cost of a longer receiver per call site and a value type per definition.

## Decision

- **Type paths.** Go's `Conventions::receivers` is `Receivers::TypePaths`: a member call records its operand as a type
  path.
- **What a path spells.** A path starts at a name and goes on through `.field` or `.method`, a call's result `()` or its
  result `n` `()#n`, and a container's element `[]`. A name no local binds is spelled as written, for the package's
  declarations or an import to bind; a method's receiver variable spells its type, `w.draw()` in
  `func (w *Widget) run()` records `Widget`; a type a body declares is spelled as written. `s.client.Do()` in
  `func f(s *Server)` records `Server.client`. A local's call puts `~` before its `()`: `g()` with `g` a `G` records
  `G~()`, where a local's path would otherwise read as the conversion `G(f)`.
- **What a declaration gives.** A local, a parameter or a package-level variable records the path of what its
  declaration gives it: a type it names, a composite literal's type, `new(T)` or `make(T)`, a call's result, a range's
  element, held by its one name over a channel the value spells, an index or receive element, a type assertion's
  type, `&` and `*` passing through, and in a type switch the clause's one type, else the guard's value. An operand of
  no path, `(a + b).f()` or a call of a parameter of an unnamed function type, records the empty receiver.
- **Value types.** Every definition records the types of the values it yields, `Symbol::value_types`: a function's or a
  method's results, an interface method's too, a field's or a variable's type, an alias's target, and for a type defined
  over a function type its results, over a container that container, over a named type that type after a `~`. A field,
  a variable or a literal assigned to a name whose type is an anonymous struct records the struct as its owner's index,
  [ADR 3.170](/design-docs/adr/3.170-go-anonymous-structs.md) states.
- **Binding through a path.** The graph follows a path across files and packages and binds, at 85, the method the call
  names of the type the path reaches, or of a type that type embeds, the shallowest first
  ([ADR 3.201](/design-docs/adr/3.201-go-embedded-selectors.md)). A member is sought only in
  its type's own package, so a namesake in another directory or in the external test package beside it is not one.
- **A type defined over another.** A defined type has the methods of the interface its named type reaches, through
  other defined types and aliases, and none of any other type's methods: `type T S` with `func (S) M()` gives `t.M()`
  nothing. A struct's fields and what they promote stay ([ADR 3.201](/design-docs/adr/3.201-go-embedded-selectors.md)).
  A type defined over a pointer records nothing. A defined type or an alias whose path reaches an import the graph does
  not hold takes its members from outside the graph, an interface's or a struct's alike, so the call counts as
  `Miss::ExternalImport`.
- **A value of a defined type.** An index, a receive or a call reads the container or the function at the end of the
  type's chain of defined types and aliases: `t[0]` with `type T L` over `type L []E` yields `E`, as a map, an array and
  a channel do, and `g()` with `type G F` over `type F func() E` yields `E`. A call of a type's name converts, `G(f)`
  yields `G`. A chain that reaches an import reads outside the graph.
- **What binds nothing.** A path that reaches a type of code the graph does not hold, a name nothing declares, a builtin
  among them, or a type the graph holds with no method of the name binds nothing. A path the graph cannot follow leaves
  the call to the tiers that read no type ([ADR 3.7](/design-docs/adr/3.7-call-resolution.md)).
- **A name two files declare.** Only build constraints let two files of a package declare one name, and the graph holds
  no build configuration. A file's own declaration is the one it is built with, so a file that declares the name reads
  that one. Any other read, from a third file or another package, follows its path through every declaration, and what
  they reach decides by what it is, never by the path of its file: a type the graph holds, an alias read through to its
  target, else an import, else a path the graph cannot follow, else a name nothing declares, and of two held types the
  greater qualified name.
- **Types a body declares.** A name that neither the package nor an import declares is read from the types the
  function around the site declares,
  a closure's site reading its enclosing function's, and a path a local's value types spell from the types of the
  local's own function. A type another function of the file declares is out of scope and gives nothing, as in Go.
- **Bounds.** A path past 160 bytes is not recorded. A read follows 16 nested paths at most, counted through every
  declaration it passes, and spends 1024 evaluations at most, as does the member walk after it; a walk takes 32 embedded
  types of one type. Every recursion of `typed.rs` passes through `evaluate`, which holds the first two bounds, shortens
  the path it reads, or, where a rank follows an alias, stops at the depth itself.
- **A read past a bound binds nothing.** A path past a bound gives no type. Where another declaration of the name
  reaches one, that one answers; where none does, the site counts as `Miss::PastBound` and the tiers that read no type
  never see it. A cycle of declarations runs past a bound, and a cycle of aliases counts alike
  ([ADR 3.201](/design-docs/adr/3.201-go-embedded-selectors.md)). A member walk past a bound goes to those tiers.

## Why

- With the empty receiver, 421,957 of the 1.95M Go call sites ended ambiguous on the Go monorepo of 39,771 Go files;
  with type paths, 10,745 (2026-10-17, #68).
- A type's name is the owner a Go method is declared under, so a path that reaches it needs no guess.
- grpc's `type DepthLoggerV2 internal.DepthLoggerV2` left its calls unbound: reading through an interface adds 107
  caller and callee pairs on the Go monorepo snapshot, 30 of 30 sampled right, and removes none (2026-10-31, #499).
- A member walk that stopped at a type over an import miscounted 96 sites and bound 5 to a namesake on the Go monorepo
  snapshot; 100 of those 101 call the imported type (2026-10-31, #746).
- Go indexes and calls through the underlying type, and a type as the operand of a call converts (`doc/go_spec.html`,
  Index expressions, Calls; `cmd/compile/internal/types2/index.go:75`, `call.go:194`, `:252`). On the Go monorepo
  snapshot the read adds 151 uses, 30 of 30 sampled right, and moves no caller and callee pair (2026-11-01, #937).
- The Go monorepo snapshot holds 8,652 package-level names that several non-test files of a package declare, and of the
  228 distinct reads of such a name from outside those files, 15 reach something else through one declaration than
  through another (2026-11-01, #816).
- A package-level cycle gives its names no type: the compiler refuses it as an initialization cycle
  (`cmd/compile/internal/types2/initorder.go:165`), and a tree can still hold one mid-edit. The depth alone leaves a
  branching read at 25^8 evaluations; the most any of the 204,120 reads of the Go monorepo snapshot spends is 65, at
  depth 4 (2026-11-01, #868).

## Consequences

- The value types and the longer receivers cost 9 MB of heap and about 3% of the Go extraction on the monorepo
  (2026-10-17). Accepted.
- Whether a named type is an interface shows only in the graph, so each of the 8,434 defined types over a named type on
  the Go monorepo snapshot records a value type, 5,484 of them over a predeclared name that gives nothing there, which
  hold 51 KB of a 253 MB heap peak (2026-10-31, #747). Accepted.
- Two types of one name that sibling blocks of one function declare, or a function and a closure in it, are one scope:
  the first in the file gives the name. Accepted.
- Of two held types a read of a name reaches, the greater qualified name stands whether or not it has the member the
  site names, which 4 of the 15 reads on the Go monorepo snapshot can meet (2026-11-01, #816). A type two files declare
  takes its embedded types from one of them, and a member two files declare gives its value through one of them.
  Accepted.
- An alias of a function literal records the results an alias's target records, so `type A = func() F` reads `a()` as
  `F`'s results, and a function type whose first result is a container, `func() ([]E, error)`, loses its later results
  (#945).
- A valid chain of more than 16 values binds nothing, and a read that stops at the evaluation bound keeps what its
  earlier declarations reached and misses what the later ones would: the Go monorepo snapshot holds no such read
  (2026-11-01, #868). Accepted.

## Rejected

- **The empty receiver for a declared value** — no wrong edge from a name, and 421,957 ambiguous sites.
- **The operand as written** — reaches no tier: all 27,217 distinct Go owners on the Go repositories measured are
  bare type names (2026-10-16).
- **The operand's last segment** — a field name, matching a type name by convention: of 30,056 sites whose segment
  named a known type, 26,103 named one the calling directory does not define (2026-10-16).
- **The name of a value the caller declares, as written** — 11,161 of the 11,448 calls bound through an owner of the
  receiver's name had such a receiver, `span.End()` binding an unrelated vendored `span` type.
- **A guess by the method's name** — on sampled sites, guesses at confidence 80 to 95 reached the method called on
  none of 25: `bytes.Buffer.Write` bound to a namesake, an interface's method to one implementation.
- **The file's first type of the name any body declares** — test functions each declare `type fields struct`, which
  bound 127 field uses on the Go monorepo snapshot from another function, all of them wrong (2026-10-23, #426).
- **Type paths, then the one method of the name in reach at 15** — adds no site: the include tier binds that one
  method already, and the sites left ambiguous have none in reach or several.
- **The named type as a parent of the defined type** — needs no spelling of its own, and lists every `type T S` as an
  implementor of `S`.
- **No value type over a predeclared name** — moves no edge, use or implementor on the Go monorepo snapshot, and takes
  from a package that redeclares the name as an interface the methods of every type defined over it: a walk reads one
  file, so `type string interface` in a sibling file does not show (2026-10-31, #747).
- **The first declaration in path order** — renaming a file moves the answer, and a read of
  `decoder.NewStreamDecoder` counted as external through the file of `decoder_compat.go`, though `decoder_native.go`
  returns a type the graph holds (#816).
- **A visited check on declarations** — stops a cycle and no other branching: a valid chain of names two files each
  declare, and a struct's embedded paths, still multiply (#868).
- **A cycle left to the tiers that read no type** — binds the one method of the name in the repository, `a.Set()` to
  an unrelated `U.Set` (#868).

## Revisit if

A language other than Go spells its receivers as paths. High confidence in the rule for Go; the paths follow what the
compiler reads.
