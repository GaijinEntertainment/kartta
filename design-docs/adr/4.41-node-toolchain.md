# Check the Node package with the Vite+ that its lockfile pins

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-20
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `bindings/node/package.json`, `bindings/node/package-lock.json`, `bindings/node/.nvmrc`,
  `bindings/node/vite.config.ts`, `bindings/node/tsconfig.json`, `bindings/node/scripts/build.ts`, the `node` job of
  `.github/workflows/ci.yml`

The Node package ([ADR 4.3](/design-docs/adr/4.3-node-addon.md)) is built,
formatted, linted, type-checked and tested by tools whose versions the repository pins, as every build input here is.
It runs them through `vp`, the CLI of `vite-plus`, as the maintainers' other packages do; the trade is one large
development dependency for the whole toolchain.

## Decision

- `vp fmt` formats with oxfmt, and `vp lint` lints with oxlint and oxlint-tsgolint under the javascript, typescript,
  node and vitest presets of `@ver0/oxlint-config`, both set in `vite.config.ts`. `vp test` runs the tests on the
  vitest `vite-plus` pins, which transforms the tests' TypeScript itself.
- `tsc` type-checks and emits the declarations. It skips the libraries' declarations, because vitest's name DOM types a
  Node project has no lib for.
- The `build` script, `scripts/build.ts`, builds `crates/kartta-node` with `cargo build --locked` and copies the shared
  library beside the package as `kartta.<target>.node`; the Node `.nvmrc` pins runs it as it stands, and CI runs it as
  `vp run build`.
- napi, napi-derive and napi-build resolve through `Cargo.lock`. `typescript`, `@types/node`, `vite-plus` and
  `@ver0/oxlint-config` are exact in `package.json`, with the lockfile committed and installed with
  `npm ci --ignore-scripts`.
- `@types/node` is at the newest release of the line the `engines` floor names, and the floor and the types move
  together.
- CI runs the Node version `.nvmrc` pins, and takes `vp` from `node_modules/.bin`, so the toolchain's version is the
  lockfile's.

## Why

- One CLI for format, lint and test keeps this package's toolchain the one the maintainers' other packages run.
- A version that moves under the build breaks it without a change here; the lockfile and the exact versions keep it
  still.

## Consequences

- The toolchain moves only with the lockfile, so a fix in `vite-plus` or a preset reaches the package with a lockfile
  change and no sooner. Accepted.

## Rejected

- **`@napi-rs/cli`** — it brings its own dependency tree, a GitHub client and cross toolchains among it, for the same
  file copy, and generates a loader for every platform napi-rs knows on each build, where the package loads three
  targets in a dozen lines.
- **`voidzero-dev/setup-vp` in CI** — one more action to pin, whose `vp` would hand each command to the lockfile's
  `vite-plus` all the same.

## Revisit if

The maintainers' other packages leave Vite+. Medium confidence that they stay on it.
