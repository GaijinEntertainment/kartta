# Count a definition a library or a host reads by name as reflected

- **Date:** 2026-10-23
- **Governs:** `crates/kartta-graph/src/dead.rs`, `crates/kartta-lang-go/src/walk/syntax.rs`
  (`tag_hands_over_its_field`, `SERIALIZING_CALLS`, `INSPECTING_CALLS`), `crates/kartta-lang-go/src/walk.rs`
  (`mark_reflected_fields`, `is_plugin`), `SymbolFlags::is_reflected`
- **Pinned by:** `crates/kartta-graph/tests/graph/dead_code.rs`
  (`a_field_reflection_reads_is_counted_as_reflected_where_no_use_reaches_it`),
  `crates/kartta-lang-go/tests/extract.rs` (`a_struct_tag_that_hands_its_field_to_a_library_marks_the_field_reflected`,
  `a_struct_whose_value_a_marshal_or_reflect_call_takes_hands_its_exported_fields_to_reflection`,
  `a_skip_tag_hides_a_field_from_a_marshal_call_but_not_from_reflect`,
  `a_marshal_call_reaches_the_struct_fields_through_an_alias_or_a_container_type`,
  `a_package_main_file_with_no_func_main_hands_its_exported_values_to_a_plugin_host`)

A library or a plugin host reads a Go definition by its name, which no extraction records, so a field only a decoder
writes would read dead once Go's data is judged ([ADR 3.110](/design-docs/adr/3.110-data-dead-code.md)). Go marks such
definitions, and a dead-code answer counts them as `reflected`, at the cost of marks read from struct tags and from
calls by name.

## Decision

- **The reason.** A definition no call and no use reaches that a library or a host reads or writes by its name counts
  as `reflected`, after `live` and before `uncertain` and `dispatched`
  ([ADR 3.23](/design-docs/adr/3.23-dead-code-judgment.md)). The language marks it (`SymbolFlags::is_reflected`).
- **Struct tags.** Go marks a field whose struct tag holds a `key:"value"` pair of any value but `-`, or holds no such
  pair, since a library may read a tag whole; a tag whose every value is `-`, which `encoding/json`, `encoding/xml` and
  their kin skip, marks nothing.
- **Marshal and reflect calls.** Go marks an exported field of a package-level struct the file declares whose value the
  file passes to a call named `Marshal`, `MarshalIndent`, `MarshalWrite`, `Unmarshal`, `UnmarshalRead`, `Encode` or
  `Decode`, unless a tag skips the field, or to `ValueOf` or `TypeOf`, whatever its tags, since `reflect` honours none,
  where the walk names the value's type by the struct's name or by that of an alias or a container type of it; and the
  exported fields of the structs the file declares that such fields hold.
- **Plugins.** Go marks an exported function or package-level variable of a `package main` file that declares no
  `func main`, which the walk takes for a plugin's file: the go command builds a `package main` with no `func main`
  only as a plugin, whose host looks the definition up through `plugin.Lookup`.

## Why

- A marshaled field is read by reflection, which no extraction sees: of the fields Go marks on the snapshot, 1,343
  are reached by no use and would read dead (2026-10-23, #451).
- A field that only a decoder writes or `reflect` walks, and a plugin's export, have no recorded use either: they were
  8 of the 568 dead Go definitions of the snapshot, each read or written by name (2026-10-24, #447).

## Consequences

- A field that a library reads through a map without a tag reads dead where no recorded use reaches it, as one that
  only a positional literal of another file's struct writes, and so does one of a struct that another file declares or
  whose value the walk types only through a call or a field, `json.Marshal(build())`. Accepted.
- A function of the repository named like a library's, `Decode(&item)`, marks the fields of its argument's struct.
  Accepted.
- A file of a program's `package main` that leaves `func main` to a sibling marks its exports as a plugin's, so a dead
  one counts as `reflected`; none of the 31 such exports of the snapshot is dead (2026-10-24). Accepted.
- The reflected mark takes the last free bit of the extraction codec's marks byte
  ([ADR 3.68](/design-docs/adr/3.68-use-storage-layout.md)): a further flag widens the codec.

## Rejected

- **The exported fields of a struct with a reflected field counted reflected too** — a struct marshaled whole names some
  fields in tags and leaves others to their names, but the rule hid fields of configuration nothing reads.
- **Every exported field of a file that imports an encoding package** — 2 of the 7 fields it took out of the snapshot's
  dead list were read and written by nothing (2026-10-24).
- **Resolve a marshal call's argument in the graph, across files** — takes the same 4 fields out of the snapshot's dead
  list as the file's own structs do, for a record kept per call (2026-10-24).
- **Match a marshal call through an import of its library** — the same dead list as the name alone on the snapshot
  (2026-10-24), and it misses the repository's own wrappers of those libraries.
- **A plugin as a directory with no `func main` in any file** — takes the same 4 definitions out of the snapshot's dead
  list as the file rule, and needs the package's other files, which the walk does not read (2026-10-24).
- **Every exported function and variable of a `package main`** — marks 70 definitions of the snapshot where a plugin's
  are 4, for the same dead list (2026-10-24).

## Revisit if

A sample of the dead Go definitions finds more than a few that a library or a host reads by name in a way the marks do
not cover, a map without a tag or a repository's own codec. Medium confidence: 8 of the 568 dead Go definitions were
read by name before the marks (2026-10-24, #447).
