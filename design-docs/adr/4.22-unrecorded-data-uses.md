# Name a language that records no read or write of a data kind in its references

- **Date:** 2026-10-23
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`reference_match`, `Unrecorded`, `no_sites`,
  `PARTIAL_DATA_ACCESS`), `kartta_lang::Conventions::unrecorded_data`, the `find_references` tool
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_references_names_the_language_that_records_no_read_or_write_of_the_symbol_s_kind`), and in each language
  that states a kind, the test that reads and writes one and finds no use of it

Several languages record no read or write of a field, a variable or a constant, so `count="0"` on one says nothing of
whether code uses it. The language states those kinds, and a match of such a kind names the language in place of the
caveat that fits any language, as a type's match does ([ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md)).

## Decision

- **The statement.** A language lists in `Conventions::unrecorded_data` the kinds among field, variable and constant
  whose reads and writes it records nowhere, which its graph hands out
  ([ADR 3.1](/design-docs/adr/3.1-language-plugin-contract.md)). The match of a symbol of such a kind names the
  language:
  - with no site: "no recorded site - the rust graph records no read or write of a field, so this does not show that
    nothing uses the field; grep finds where code names it", in place of the caveat;
  - with sites, uses that spell the name as something else, as a Bash handler word does: a `<note>` that every such
    use is missing.
- **Which languages state it.** Bash variables; daslang fields, variables and constants; DSHL fields; PHP fields and
  constants; Ruby constants; Rust fields. Each is held to it by a test that reads and writes one and finds no use, or,
  for DSHL, only a bare name, which binds no field ([ADR 3.173](/design-docs/adr/3.173-data-use-binding.md)).
- **Partial field accesses.** A field of a language that records some field accesses keeps a note on what it leaves
  out, by the family's name: C++, TypeScript and JavaScript, Python, and Quirrel, which records a field only where a
  method of its owner names it bare.
- **The description.** The description names no language; it says a match names its language where that language
  records none of its symbol's uses.
- **Text, not shape.** The text changes; no attribute or element is new.

## Why

- Such a symbol answered `count="0"` under the caveat that fits any language, and code uses it: of 46 sampled matches
  that name the gap on the C++ game-engine tree and the Go monorepo, 40 symbols are named again in their own file
  (2026-10-23, #279).
- The language crate knows what its extraction records, so a statement it makes cannot fall behind it, where the
  server's list of the families that record field accesses had.
- The statement reads one field of the conventions the graph already holds, and allocates only for such a match.

## Consequences

- A use that spells such a name as something else, a Bash `trap` word that names a variable, still lists as a site,
  under the note. Accepted.
- The C ABI's references part carries no flag for it, as it does `type_uses_unrecorded` for a type. Accepted until a
  wire consumer asks.

## Rejected

- **The server's list of the families that record field accesses** — a language crate outside kartta could not state
  it, and it named Quirrel's fields as unrecorded while Quirrel records some.
- **A `DataUses` variant** — `DataUses` says where one language records its data uses for every kind, and Rust records
  constants while it records no field.

## Revisit if

Every shipped language records the reads and writes of every data kind it extracts, so no graph lists one.
