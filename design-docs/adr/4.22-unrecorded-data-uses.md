# Name a language that records no read or write of a data kind in its references

- **Date:** 2026-10-23
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`reference_match`, `Unrecorded`, `no_sites`,
  `PARTIAL_DATA_ACCESS`), `kartta_lang::Conventions::unrecorded_data`, `kartta_graph::References::local_value`, the
  `find_references` tool
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_references_names_the_language_that_records_no_read_or_write_of_the_symbol_s_kind`,
  `find_references_says_that_no_read_of_a_function_s_local_is_recorded`,
  `find_references_says_that_no_use_of_a_function_s_local_function_as_a_value_is_recorded`),
  `crates/kartta-graph/tests/graph/calls.rs`
  (`references_of_a_body_s_local_value_say_that_no_use_binds_it`), and in each language that states a kind, the test
  that reads and writes one and finds no use of it

Several languages record no read or write of a field, a variable or a constant, so `count="0"` on one says nothing of
whether code uses it. The language states those kinds, and a match of such a kind names the language in place of the
caveat that fits any language, as a type's match does ([ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md)).

## Decision

- **The statement.** A language lists in `Conventions::unrecorded_data` the kinds among field, variable and constant
  whose reads and writes it records nowhere, which its graph hands out
  ([ADR 3.1](/design-docs/adr/3.1-language-plugin-contract.md)). The match of a symbol of such a kind names the
  language:
  - with no site: "no recorded site - the rust graph records no read or write of a field, so this does not show that
    nothing uses the field; grep finds where code names it", in place of the caveat;
  - with sites, uses that spell the name as something else, as a Bash handler word does: a `<note>` that every such
    use is missing.
- **Which languages state it.** Bash variables; daslang fields, variables and constants; DSHL fields; PHP fields and
  constants; Ruby constants; Rust fields. Each is held to it by a test that reads and writes one and finds no use, or,
  for DSHL, only a bare name, which binds no field ([ADR 3.173](/design-docs/adr/3.173-data-use-binding.md)).
- **Body locals.** A variable, a constant or a function local to a function body, one of the extraction's
  `local_symbols`, has no read or write in any graph, since no use binds a local
  (`kartta_lang::Extraction::local_symbols`); the graph's `References::local_value` says so for the match, which names
  its language in the same two forms: "the jsts graph records no read or write of a constant local to a function
  body", and of a function, whose calls from the body list, "the rust graph records no use as a value of a function
  local to a function body". A kind the language lists above takes that statement instead, which holds of the module's
  values too. A method of a type a body declares is outside it: a use of a member binds one.
- **Partial field accesses.** A field of a language that records some field accesses keeps a note on what it leaves
  out, by the family's name: C++, TypeScript and JavaScript, Python, and Quirrel, which records a field only where a
  method of its owner names it bare.
- **The description.** The description names no language; it says a match names its language where that language
  records none of its symbol's uses, and that no language records the reads of a body's local value or the uses as a
  value of a body's local function.
- **Text, not shape.** The text changes; no attribute or element is new.
- **The C ABI.** The C ABI's references part of such a symbol carries `data_uses_unrecorded`
  ([ADR 4.35](/design-docs/adr/4.35-wire-unrecorded-uses.md)).

## Why

- Such a symbol answered `count="0"` under the caveat that fits any language, and code uses it: of 46 sampled matches
  that name the gap on the C++ game-engine tree and the Go monorepo, 40 symbols are named again in their own file
  (2026-10-23, #279).
- The language crate knows what its extraction records, so a statement it makes cannot fall behind it, where the
  server's list of the families that record field accesses had.
- The statement reads one field of the conventions the graph already holds, and allocates only for such a match.
- A TS/JS body's `const` binds in the call's own environment (ECMA-262 FunctionDeclarationInstantiation), so it is a
  local the walk records no read of, and its match answered `count="0"` under the caveat that fits any symbol (#615).
  The language states each local by listing it, so the graph tells it from a module's value with no statement of its
  own; the test is one lookup in the file's locals per `find_references` match.
- A Rust function a block declares is scoped to that block (Rust Reference, `items/functions.md` and `statements.md`,
  "Declaring an item within a statement block restricts its scope to the block"), and a Python `def` binds its name in
  the local namespace (Python reference, `compound_stmts.rst`, Function definitions). Either is named as a value,
  `.map(double)` or `map(double, v)`, and the match of a nested `fn double` or `def double` listed its call alone with
  no note, where a module's function of the same shape lists its read (#1223).

## Consequences

- A use that spells such a name as something else, a Bash `trap` word that names a variable, still lists as a site,
  under the note. Accepted.
- A Ruby `let` or `subject` is a function local to its example group, so its match carries the statement, though a
  bare Ruby name that no local binds calls the method (`parse.y`, "method call without arguments"): no use of it as a
  value spells it bare. 3,702 on Homebrew's library and 3,668 on RuboCop (2026-11-06). Accepted.
- A TS/JS function declared in a body is not among the extraction's locals, so its uses as a value bind nothing and its
  answer keeps the caveat that fits any symbol (#614).
- A Python class declared in a body is outside **Body locals**: its calls from the body list, its uses as a type or a
  value bind nothing, and its answer keeps the caveat that fits any symbol (#1229).

## Rejected

- **The server's list of the families that record field accesses** — a language crate outside kartta could not state
  it, and it named Quirrel's fields as unrecorded while Quirrel records some.
- **A `DataUses` variant** — `DataUses` says where one language records its data uses for every kind, and Rust records
  constants while it records no field.
- **A conventions field for body locals** — every language that lists locals would state the same thing, which the
  extraction contract already says of every local, and the field could not tell a local from a module's value.
- **Binding a body's local function from its uses as a value** — a use carries a name and no target, and the extraction
  contract binds no local by one, so each language that lists locals would record a new kind of use its own scoping
  binds, as `LocalCall` is for a call, through the extraction, its cache and the graph's sites (#1230).

## Revisit if

Every shipped language records the reads and writes of every data kind it extracts, so no graph lists one.
