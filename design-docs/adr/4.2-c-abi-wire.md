# Reach the engine through one JSON call over a small C ABI

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-ffi`, `crates/kartta-ffi/include/kartta.h`, `crates/kartta-ffi/src/wire/`, `bindings/go`
- **Pinned by:** `crates/kartta-ffi/tests/dispatch.rs`, `crates/kartta-ffi/tests/golden.rs`,
  `bindings/go/kartta/kartta_test.go`

Go and Node consumers reach the engine across a C boundary. `kartta-ffi` exports five functions, and every method is a
name and a JSON object of params answered in JSON, so one dispatch serves every binding and test and a new method is a
match arm, never a new export; each answer pays a JSON encoding that costs nothing next to the query.

## Decision

- **The header.** `crates/kartta-ffi/include/kartta.h` is hand-written and committed, and declares
  `kartta_abi_version`, `kartta_open`, `kartta_call`, `kartta_string_free` and `kartta_free`. The Go binding's cgo
  build compiles the header and links every function it declares, in CI on Linux and macOS, so a header that drifts
  from the library fails there.
- **Opening.** `kartta_open` takes `{"root": <path>}` and answers a handle, or null with `{"code", "message"}` written
  to the error out-parameter, never a bare null for a caller that asks for the reason; a null out-parameter discards
  it.
- **Calling.** `kartta_call` takes a NUL-terminated method name and the params' bytes and answers `{"ok": <answer>}` or
  `{"err": {"code", "message"}}`, never a null string; null params with a zero length, empty text and `null` read `{}`.
- **Ownership and threads.** Arguments are borrowed for the call; every returned string is the caller's, freed once
  with `kartta_string_free`. Calls on one handle may run at once from any threads; `kartta_free` must not run beside a
  call on the same handle.
- **ABI version.** `kartta_abi_version` returns 1, which `KARTTA_ABI_VERSION` must equal; the Go binding checks it at
  open, answering `ErrABI`. It changes only when a binding built against an older header would misuse the library.
- **Panics.** Every entry point runs under `catch_unwind`: `kartta_open` and `kartta_call` answer `internal` and the
  handle stays usable, and the frees drop a panic. That holds only for a library built with unwinding panics.
- **Crate types.** The crate builds a `staticlib`, which cgo links into Kensai's static musl binaries, and an `rlib`,
  which a Rust shell such as the Node addon ([ADR 4.3](/design-docs/adr/4.3-node-addon.md)) builds on; it sets no
  global allocator ([ADR 4.31](/design-docs/adr/4.31-c-abi-allocator.md)). serde lives in this crate alone.
- **The wire.** The wire is kartta's own JSON. It keeps the method names Kensai already calls where the meaning holds
  and carries no compatibility layer for the shapes Kensai reads today; Kensai migrates once. Each method's contract is
  a golden file ([ADR 4.36](/design-docs/adr/4.36-wire-method-pinning.md)).
- **Methods.** The methods are the names [`Kartta::call`](/crates/kartta-ffi/src/handle.rs) answers, the queries of
  [`query.rs`](/crates/kartta-ffi/src/query.rs) among them. `version` lists the methods and languages a library
  answers, and an unknown method answers `unknown_method`, its message listing the methods. `paths`, `len`,
  `grep_index/build` and `validate_globs` are not methods: `len` is `stats`'s `entries`, the content index is a `build`
  option made in the same walk, and a bad glob answers `invalid_glob` from the call that takes it.
- **Graph and file queries.** A graph query names no graph by default and answers one part per graph its name selects a
  symbol in; `lang` names one graph by a language or its family, and one the build did not make answers
  `invalid_params`, listing those it did. A file query (`outline`, `dependents`, `analyze_segment`) answers the `graph`
  that claims the file and if it is `held`. `search` answers a part for every graph with a hit, a graph whose hits all
  come from the fill-up included.
- **Params and answers.** Params are one type per method and refuse unknown fields; JSON that is neither an object nor
  `null` answers `invalid_params`. Answers may gain fields: a new key is additive, absent where it would say nothing.
- **Default bounds.** A bound left out or 0 takes the method's default, a constant of
  [`wire/params.rs`](/crates/kartta-ffi/src/wire/params.rs) or [`wire/files.rs`](/crates/kartta-ffi/src/wire/files.rs):
  callers 3 calls deep, callees 1, a walk 500 symbols; a call path 8 deep and 20,000 symbols; 500 references; 10
  definitions or sources; 20 search hits; implementations 3 deep and 100 implementors; dependents 3 deep and 100 files;
  a segment or a change 3 deep and 500 symbols; 100 dead definitions; 20 unbound sites of `resolution`; a listing 1
  level and 1,000 entries; 50 fuzzy matches; grep 100 matching lines, 1,024 bytes a line and 4 MiB a file. The caps a
  caller can lift take 0 as none: a listing's depth and entries, glob's and grep's matches, dependents' files, and a
  source's lines and line bytes. `glob` has no default cap.
- **Answers carry what they left out.** Every capped or bounded answer is an object with the engine's counts: `total`,
  `truncated`, `turned_away`, `unexpanded`, `below_confidence`, `passed_over`, `unresolved`, grep's account of every
  candidate and its `unsearched` ([ADR 1.11](/design-docs/adr/1.11-content-search-limits.md)), a listing's `excluded`
  and `unlisted`. An answer mirrors the engine's answer type, so it carries every count the engine's docs state, those
  [ADR 3.112](/design-docs/adr/3.112-file-scope-names.md), [ADR 3.37](/design-docs/adr/3.37-call-walk-cut-counts.md),
  [ADR 3.132](/design-docs/adr/3.132-data-symbol-reach.md), [ADR 3.110](/design-docs/adr/3.110-data-dead-code.md),
  [ADR 1.55](/design-docs/adr/1.55-path-query-exclusion.md) and
  [ADR 1.56](/design-docs/adr/1.56-ranking-match-count.md) add included; the view types of
  [`wire/graph.rs`](/crates/kartta-ffi/src/wire/graph.rs) and [`wire/files.rs`](/crates/kartta-ffi/src/wire/files.rs)
  name each field. A `references` part carries `ambiguous` at zero too.
- **Symbol selection.** `callers`, `callees`, `references` and `implementations` take `path_prefix` and `line`, and
  `call_path` `from_path_prefix`, `from_line`, `to_path_prefix` and `to_line`
  ([ADR 3.35](/design-docs/adr/3.35-shared-name-selection.md)); a part that passed symbols over lists at most five
  `candidates`, a `symbol` and the `count` the query ranks by, per end for `call_path`. How a symbol method read a name
  and why it matched nothing is [ADR 4.34](/design-docs/adr/4.34-wire-name-misses.md); a type's unrecorded uses,
  [ADR 4.35](/design-docs/adr/4.35-wire-unrecorded-type-uses.md).
- **Error codes.** `invalid_request`, `invalid_params`, `unknown_method`, `invalid_root`, `not_built`, `building`,
  `build_failed`, `build_cancelled`, `no_stamps`, `refresh_failed`, `refresh_cancelled`
  ([ADR 4.32](/design-docs/adr/4.32-wire-refresh.md)), `invalid_glob`, `invalid_pattern`, `not_found`,
  `not_a_directory` and `internal`. [`ErrorCode`](/crates/kartta-ffi/src/error.rs) states when each is answered.
- **Lifecycle.** How a build replaces a handle's engine is
  [ADR 4.45](/design-docs/adr/4.45-wire-build-lifecycle.md); cancellation is
  [ADR 4.30](/design-docs/adr/4.30-wire-cancellation.md), and following the tree
  [ADR 4.33](/design-docs/adr/4.33-wire-follow.md).
- **The Go binding.** The module `github.com/GaijinEntertainment/kartta/bindings/go`, `go 1.27.2`, has no
  dependencies. Its `wire` package holds the params, answers and error codes with no cgo, so code that only handles
  answers builds and tests without the library; a `wire.Code` is an error and a `*wire.Error` unwraps to its code, so
  `errors.Is(err, wire.NotBuilt)` matches. Its `kartta` package links `libkartta_ffi.a` statically through cgo from
  the same checkout: the header from `crates/kartta-ffi/include`, the archive's directory from `CGO_LDFLAGS`. A
  `Kartta` is safe for concurrent use. Typed calls cover the methods Kensai calls, each answering its `wire` type, a
  graph query's as a `wire.Matches[T]` with one part per graph, and `Call` reaches the rest with the wire types or raw
  JSON; [the package](/bindings/go/kartta/kartta.go) documents each call, `Close` and the cleanup that frees a handle
  nobody closed.

## Why

- One dispatch keeps the bindings thin: Go and Node translate JSON and decide nothing, so the rules live once, in Rust
  (#75).
- Answers are kilobytes, where JSON costs nothing next to the query, and an object gives every count a place a bare
  array does not. `paths` answered 150 MB of JSON on three million entries, and no consumer called it.
- cbindgen is MPL-2.0, which `deny.toml` does not allow, and the surface is five functions.
- A silently ignored option is worse than an error; an added answer field breaks no consumer that reads what it knows.

## Consequences

- Each answer pays a JSON encoding, which costs nothing next to the query. Accepted.

## Rejected

- **A drop-in for the ABI Kensai calls today** — its three-step open, grep-index build and graph build cannot map onto
  one fused walk without walking twice, the cost [ADR 3.6](/design-docs/adr/3.6-graph-build-pass.md) removed, and its
  bare arrays have nowhere to put a count.
- **Typed C structs, or a schema'd binary format** — every answer a C layout marshalled in Go and again in JS, and every
  new count an ABI break.
- **A `cdylib` beside the archive** — no consumer loads one, each crate type is a full link per build, and a shared
  library beside the archive makes `-lkartta_ffi` link dynamically on macOS.

## Revisit if

A consumer's answers grow large enough that encoding them as JSON shows beside the query that made them. High
confidence: every answer but a `glob` without a limit is bounded by default.

## History

- 2026-10-23 — Symbol selection: `path_prefix` selects by file only, so no argument reached one of several definitions
  that share a name and a file (#401)
- 2026-10-23 — Answers carry what they left out: the walks never listed a symbol's call of itself and said nothing of
  leaving it out, so recursion and a false self-edge were both invisible (#205)
- 2026-10-23 — Answers carry what they left out: the answers that judge code ignored the recorded reads and writes, so
  an edit to a field reported no reach (#149)
- 2026-10-21 — Graph and file queries: `search` dropped every graph whose hits all came from the fill-up, so a query
  only the fill-up reaches answered no match (#329)
- 2026-10-20 — Answers carry what they left out: the callers, segment and change answers carried no count of the
  ambiguous calls, so a wire consumer read an empty caller list as dead code (#252)
- 2026-10-20 — Answers carry what they left out: a fuzzy answer said nothing of the matches its limit turned away,
  though counting them costs nothing for a query with terms (#153)
- 2026-10-20 — Answers carry what they left out: `glob` and `fuzzy` took no exclusion, so a caller dropped results
  after a capped query, which leaves a short answer with a wrong `truncated` (#152)
- 2026-10-19 — Answers carry what they left out: file-scope calls are kept as names only, so a function called only
  from a module's top level showed no caller (#113)
- 2026-10-19 — Params and answers: an array was read by position, so `["ignored"]` failed a build with "expected u64"
  and `version` accepted `[]` (#111)
- 2026-10-19 — Symbol selection: a query took the top-ranked symbol of a name, so copies that share a qualified name
  could be reached by no name (#106)
