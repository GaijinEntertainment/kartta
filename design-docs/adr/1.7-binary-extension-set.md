# Let a caller compose the binary extension set

- **Status:** accepted
- **Date:** 2026-10-13
- **Updated:** 2026-10-18
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fs/src/binary.rs` (`BinaryExtensions`, `BinaryExtensionsError`),
  `BuildOptions::binary_extensions`
- **Pinned by:** `crates/kartta-fs/src/binary.rs` (`an_extension_no_file_name_can_carry_is_refused_by_name`,
  `a_given_extension_drops_one_leading_dot_and_its_case`, `union_adds_to_a_set`,
  `the_builtin_set_is_every_listed_extension_and_the_default`), `crates/kartta-fs/tests/index.rs`
  (`an_extension_the_caller_adds_settles_its_files_without_them_being_read`,
  `a_built_in_extension_a_set_of_the_caller_s_own_leaves_out_is_read_instead`)

The extensions that settle a file as binary without the file being read are a set the caller chooses, not a fixed
list: the built-in set extended by the caller's extensions, or a set of the caller's own. A project that disputes one
built-in extension states a whole set, restating the built-in extensions it keeps.

## Decision

- `BinaryExtensions` travels on `BuildOptions::binary_extensions`, one set per index. The default is
  `BinaryExtensions::builtin`.
- A caller extends the built-in set with `BinaryExtensions::builtin().union(&own)`, or states a set of its own with
  `BinaryExtensions::new`. No constructor removes an extension or names a group.
- `BinaryExtensions::new` refuses, by name and as given, the first extension no extension of a file name can equal: one
  that is empty once one leading dot is dropped, one holding another dot, and one holding `/` or a NUL.
- An extension no file in the tree carries is accepted.
- Only the last extension of a name is compared, without regard to ASCII case. A name whose only dot leads it, such as
  `.gitignore`, carries no extension.
- A set compares and hashes by its members, not by how it was composed.
- The built-in extensions are kept in the groups they came from, inside `binary.rs`, so a later change can name the
  groups again once a consumer needs them.

## Why

1. A public crate meets projects with asset formats the list does not know, such as a studio's packed archives, and
   projects that dispute what it holds, such as a tree whose `.dag` files are Condor job scheduler workflows, which are
   text.
2. The index caches each file's binary verdict on the first ask, and the name settles part of it. One set per index
   keeps that cache answering by one policy.
3. Only the last extension of a name is compared, so an entry such as `tar.gz` could never match; `gz` already does.
4. Most of the built-in set is absent from any one tree, so refusing an absent extension would make the default
   unusable.
5. Two configurations that differ only in how their sets were built compare equal, which a cache keyed on a
   configuration needs.
6. The consumers ask for the two shapes only: the C ABI's wire offers extend and replace, and no consumer composed a
   set from groups or took an extension out.

## Consequences

- A project that disputes one built-in extension restates every other built-in extension it keeps, and misses each one
  a later version adds. Accepted until a consumer asks for removal.
- A misspelled extension in a caller's set classifies nothing and says nothing. Accepted.
- `BuildOptions` is not `Copy`, because the set owns the caller's extensions. Accepted.

## Rejected

- **A fixed list** — it serves neither a project with formats the list lacks nor one that disputes an entry.
- **The set as an argument of each query** — two sets over one index would leave the cached verdicts answering by
  whichever set asked first.
- **Refusing an extension no file carries** — the built-in set would fail on almost every tree.
- **Named groups composed with `union` and `difference`** — they let a caller remove one extension without restating
  the rest, and no consumer composed a set from groups or removed anything, so the surface carried no caller.
- **A count of the files each extension settled** — it showed a misspelling as a zero, and no consumer read it.

## Revisit if

A caller needs a classification rule richer than a name's last extension, such as a compound suffix or a path prefix.
High confidence: no consumer had asked for one when the surface was cut to its callers on 2026-10-18.
