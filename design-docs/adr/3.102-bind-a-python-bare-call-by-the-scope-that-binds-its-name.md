# Bind a Python bare call by the scope that binds its name

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-python/src/walk.rs` (`Frame`, `Binding`, `close`, `scope_frame`)
- **Pinned by:** `crates/kartta-lang-python/tests/extract.rs` (the `local_calls` module)

Python binds a name for the whole of the scope that binds it, and the graph's cascade
([ADR 3.7](./3.7-resolve-calls-when-a-query-asks.md)) binds a recorded call by its name alone. The Python walk
([ADR 3.12](./3.12-qualify-python-by-the-module-its-path-names.md)) decides each bare call by Python's own scoping
before the graph sees it: a call of a definition its scope holds becomes a local call, and a call of a value records
nothing. The walk keeps no order of execution, so where a scope binds a name two ways it picks by kind, not by line.

## Decision

1. A bare call is decided when the walk leaves a scope, because a name binds for the whole of that scope: first the
   scope that makes the call, then each function around it, a class body skipped, as the interpreter resolves a free
   name. A call made in a class body sees the names that body binds, and a function nested in it does not. The first
   iterable of a comprehension, and a class's bases, are looked up in the scope around them.
2. A nested `def` or `class` binds its name to itself. A parameter, an assignment, a `for`, `with` or `except` target,
   a `case` capture, a comprehension's or a lambda's variable and an assignment expression bind the name to a value;
   an assignment expression in a comprehension binds it in the scope around the comprehension. An import binds it to
   the import. A `global` declaration sends the name to the module, and a `nonlocal` one past the scope that declares
   it.
3. Where one scope binds a name more than one way, an import or a `global` declaration wins, then a `nonlocal` one,
   then a definition, then a value: of `def f` and `f = wrap(f)`, the definition is the target, and of an import and
   an assignment of `None` in an `except`, the import. Of two definitions of a name in one scope, the later is the
   target, as the later `def` rebinds the name.
4. Where the scope that decides a call binds its name to a definition, and that scope is a function or lies inside
   one, the call is a local call to that definition, made by the call's own caller: a class inside a function makes
   the local calls of its body. A definition in a class body at module level is no local, and a call of it there is
   recorded as a call.
5. Where a function, a class body or a comprehension that decides a call binds its name to a value, the call records
   nothing, as a computed callee, `handlers[0]()`, does, so a walk over callees does not count it among the calls it could not resolve.
6. A call whose name no scope around it binds, or binds to an import or the module, is recorded as a call for the
   graph to resolve across files: a call from a function of a name assigned at module level is recorded. A bare call
   at module level, outside every function and class, is recorded whatever the module binds its name to.

## Why

- The graph knows no Python scope, and a bare call of a nested definition bound by its name alone takes a namesake: of
  the 1,471 local calls on the 1,215 Python files of the game-engine tree, 78 bound a function of the same name in
  another file that way (2026-10-17).
- A parameter, `f(source, tags)`, or a name a function assigns holds a value that no symbol of the graph is, so
  binding its call by name binds a function that only shares the name: 52 of the 786 such calls on that tree had bound
  a definition, each through a parameter or an assigned name, `cls(...)` in a class method among them (2026-10-17).
- A definition is what a scope that binds a name both ways means: each of the 8 such calls on that tree reaches the
  definition, made after a `def` that follows an unrelated assignment or after an `if` whose other branch assigns it
  (2026-10-17). An import wins because it reaches its module whenever it succeeds.

## Consequences

- The walk keeps the names each open scope binds until it closes, about 2% of extracting Python on one thread. Accepted.
- A call made before an assignment of the same name in its scope, or after a `def` the scope later rebinds, takes the
  stronger binding rather than the one in force at the call. Accepted.

## Rejected

- **Binding a nested definition by its name anywhere in its file** — a call in one function would bind a definition of
  the same name nested in another: on the game-engine tree, 26 nested definitions that share a name with one nested in
  an earlier function of the same file would lose their callers to it.

## Revisit if

A real tree shows the stronger binding of a scope wrong at the call often enough to need an order of execution. Each
of the 8 calls the game-engine tree holds of a name bound both ways reached the definition.
