# Exclude from a path query before its limit

- **Status:** accepted
- **Date:** 2026-08-24
- **Updated:** 2026-10-20
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fs/src/filter.rs` (`Filter`), `crates/kartta-fs/src/glob.rs` (`GlobOptions`, `Capped`),
  `crates/kartta-fs/src/fuzzy.rs` (`FuzzyOptions`), `crates/kartta-fs/src/index.rs` (`Index::candidates`)
- **Pinned by:** `crates/kartta-fs/tests/index.rs`
  (`a_glob_exclusion_removes_a_file_and_a_directory_with_everything_beneath_it`,
  `a_glob_limit_stays_exact_under_an_exclusion`,
  `a_fuzzy_exclusion_removes_a_file_and_a_directory_with_everything_beneath_it`),
  `crates/kartta-fs/src/fuzzy.rs::chunks_ranked_apart_answer_and_count_as_one_chunk_does`

A path query selects with one pattern set and leaves out with another, and its limit is an option of the query. The
index removes what an exclusion matches, a directory with its whole subtree, before the limit is spent, so a glob's
`truncated` stays exact and a ranking's order and `matched` count cover only what the exclusion leaves. A glob pays
one filter match per non-directory path beneath an excluded directory to count what the exclusion removed in the unit
of its answer.

## Decision

- A `Filter` selects. It is a disjunction of its patterns, so a filter with no patterns matches nothing; selecting
  everything is a different question, spelled `None` where an option takes a filter.
- Leaving out is its own argument: a second `Filter`, compiled in the same dialect (ADR 1.4), never `excludes` inside
  the selecting filter. What git's rules hide is `ignore` (ADR 1.3), and a name the build never indexes is pruned
  (ADR 1.19).
- The limit is an option of the query (`limit` on `GlobOptions`, `FuzzyOptions` and `ListOptions`), never a field of
  the filter.
- `GlobOptions::exclude` and `FuzzyOptions::exclude` remove a file the exclusion matches, and a directory it matches
  together with everything beneath it, before the limit is spent. A listing's exclusion is ADR 1.8's, a content
  search's ADR 1.11's.
- A ranking neither matches nor scores a path beneath an excluded directory. The index is depth-first, so the subtree is
  one run, which the query skips by binary search. A run of the parallel ranking that starts inside an excluded
  directory reads its first path to find that directory among its ancestors.
- A glob matches its filter against each non-directory path beneath an excluded directory once, and
  `Capped::excluded` counts the non-directory paths the filter selects that the exclusion removed. An excluded
  directory is no match of its own. The count ends where the answer ends, so a glob the limit cut says nothing about
  exclusions past the cut (ADR 1.5).

## Why

1. A limit is not a predicate, and two callers sharing one compiled filter each want their own limit and their own
   exclusions.
2. A caller that drops paths after a capped query gets a short answer whose `truncated` describes the paths before the
   drop. To stay correct it lifts the cap and holds every match: 64 MiB for a glob of `**` excluding `**/node_modules`
   on the macOS data volume, 6.2M entries, which the index answers under a cap of 100 in 22 KiB (2026-10-20).
3. A caller's filter over the returned file paths never removes what lies beneath a matched directory: `**/Library`
   removed none of the 846K files there (2026-10-20).
4. A count of what a cut answer left out is only worth reading in the unit of the answer, and a glob answers matches.

## Consequences

A query that excludes matches the exclusion against each directory it visits and each file its filter selects. Beneath
an excluded directory a glob still pays its one filter match per non-directory path, so the exclusion saves it only the
rest of that work; a ranking, which counts no exclusions, skips the subtree unmatched. Accepted.

## Rejected

- **A `Filter { includes, excludes, max_results }`** — three jobs in one value: a caller sharing a compiled filter
  would share its exclusions and its cap, and the cap would read as a predicate.
- **Leaving exclusion to the caller** — the smaller surface, and it moves the work rather than removing it: the caller
  asks for everything, filters and caps again, and walks a subtree only to throw it away.
- **Counting an excluded directory's run, as a listing does** — free, since the skip lands on the run's end, and it
  states entries as matches: 1,083,753 for about 1,870 matching paths on the data volume (2026-10-20).

## Revisit if

The one match per path beneath an excluded directory shows in a glob's profile on a large tree. Moderate confidence:
measured only for `**/*.rs` capped at 100 excluding each home's `Library` and `.cache`.

## History

- 2026-10-20 — glob and fuzzy queries take an exclusion that removes a directory with its subtree before the limit,

- 2026-10-13 — a query excludes through a second pattern set, outside its filter (#15)
