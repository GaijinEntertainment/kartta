# Take the one file that differs only in case where a game's vromfs loads it

- **Status:** accepted
- **Date:** 2026-10-17
- **Updated:** 2026-10-17
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-quirrel/src/resolve.rs` (`loaded`)
- **Pinned by:** `crates/kartta-lang-quirrel/tests/resolve.rs`
  (`a_target_in_another_letter_case_loads_its_sole_case_variant`)

A game reads its shipped scripts from a vromfs, whose lookup lowercases the path over names the packer stores
lowercased, so a specifier that differs from its file only in letter case loads in the game. Where the loader's place
names no file exactly, the resolver takes the one file that differs from it only in ASCII case, so such an include
binds, at the price of a lookup without case for each exact miss.

## Decision

1. Under a governing `.sqconfig` ([ADR 3.9](./3.9-resolve-a-quirrel-import-through-the-nearest-sqconfig.md)), each place
   the loader tries is asked in the loader's order, the file beside the script, then each base path, or the place below
   a mount: exactly first, then through `Repository::files_ignoring_case`
   ([ADR 3.30](./3.30-look-a-repository-path-up-without-case-through-a-table-built-when-first-asked.md)). A file in
   another case beside the script therefore wins over a base path's exact one, as the loader takes it.
2. Several files of one place that differ only in case name nothing there, and the next place is asked.
3. A mount name keeps its case, as the engine reads it, so `%DARG/x.nut` names no file where the config mounts `darg`;
   and so does the `.nut` suffix that tells a script from a native module, so `x.NUT` is a native module. The rest of a
   path, a mounted path's suffix too, matches without case.
4. A script no `.sqconfig` governs matches case.

## Why

- The vromfs lookup lowercases, so a script written with a specifier in another case loads in the game, and the loader
  takes the first place that holds the file in any case.
- Without a config the mounts are a guess from the directories around the script, and a lookup without case would widen
  the guess.
- Only an exact miss asks the lookup without case, so a specifier that matches its file costs nothing more.

## Consequences

- On the game-engine tree no Quirrel include changes (2026-10-17): under a config every specifier that names a file
  names it in its own case. The rule holds for the trees that do not keep their case.
- A tree with two files that differ only in case at one place loses the include there. Accepted.

## Rejected

- **Case-insensitive matching through a scan of every file** — a pass over the tree per resolver for the few
  specifiers that differ only in case.
- **A lookup without case for the guessed form too** — gains no include on that tree, measured with the lookup, and a
  match in another case under a guessed mount is a guess on a guess.

## Revisit if

A script no `.sqconfig` governs names a file in another case alone. Not seen on the tree measured.
