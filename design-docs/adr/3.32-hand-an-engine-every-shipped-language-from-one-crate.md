# Hand an engine every shipped language from one crate, and select them by name

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-22
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-languages/src/lib.rs` (`all`, `select`, `NAMES`, `UnknownLanguages`)
- **Pinned by:** `crates/kartta-languages/tests/select.rs`

[ADR 3.1](./3.1-plug-languages-in-through-a-trait.md) keeps every language in a crate of its own and has the engine
handed the languages to build with. kartta ships sixteen languages from fourteen crates, `kartta-lang-jsts` holding
three, and the C ABI for Go and Node.js and the MCP server each build an engine with them, taking the list of languages
from their own callers at run time. `kartta-languages` holds the set and selects from it by name, at the price of
compiling every grammar into each consumer of the crate.

## Decision

**`kartta-languages` holds the set.** `all()` gives every language kartta ships, and a new language crate joins it.
Each language is a value without state, so the set allocates only the vector that holds it. The engine stays without a
language of its own: a consumer that brings its own language, or wants fewer grammars compiled into its build, depends
on the language crates it wants.

**The set's order is the order the languages joined kartta in:** `go`, `cpp`, `typescript`, `tsx`, `javascript`,
`daslang`, `quirrel`, `blk`, `rust`, `python`, `bash`, `php`, `ruby`, `lua`, `puppet`, `dshl`. Each claims its files by
extension, in any case, and no two claim the same file, so the engine's rule that a file goes to the first language
claiming it never chooses between two of them. The order decides only the order in which `Engine::graphs` and
`Engine::stats` list them, and that a language a consumer appends after the set gets only the files none of them
claims; one that should take a shipped language's files goes before the set. The `jsts` family resolves under the
conventions of its first language, and its three languages state the same ones.

**A selection is a set of names.** `select(names)` takes each name exactly as the language reports it, the names
`NAMES` lists, and gives the named languages in the set's order, each once however often named, so two selections of
the same languages build the same engine. A name that is not one of them fails the whole selection with
`UnknownLanguages`, whose message names every unknown name once and lists `NAMES`, so a caller with several wrong names
corrects them in one step. The error exposes no list of the names apart from its message; the C ABI and the MCP server
hand the message on. No name selects no language, and the engine then indexes the tree and holds no graph.

**A family is selected a language at a time.** `typescript` without `tsx` builds the `.ts`, `.mts` and `.cts` files
into the `jsts` graph and leaves the `.tsx` files in the index alone: nothing they define is in a graph, and a call from
a `.ts` file into one counts as unresolved. The family resolves through the one resolver its first selected language
builds ([ADR 3.122](./3.122-resolve-a-language-family-through-the-resolver-its-first-language-builds.md)); the three
build the same resolver, so a selection changes only which files the family's graph holds.

## Why

- Three consumers listing sixteen crates each drift apart in order and in names; one list keeps their engines alike.
- A selection by set rather than by sequence keeps two callers that name the same languages from getting graphs and
  counts in two orders, since a list of names carries no order its caller means.

## Consequences

- Every grammar is compiled into a consumer of `kartta-languages`, whatever it selects; a consumer that wants fewer
  depends on the language crates directly; accepted.
- A selection of part of a family leaves the rest of its files out of every graph, and calls into them unresolved;
  accepted, since the caller named the languages.

## Rejected

- **Each consumer lists the crates itself** — three lists of sixteen entries, which drift apart in order and in names.
- **The set inside `kartta`** — the engine would name languages, which ADR 3.1 keeps it from, and every consumer of the
  engine would compile every grammar, one that brings its own languages included.
- **A cargo feature per language** — trims the grammars a build compiles, but the FFI and the MCP server take their list
  at run time and ship every grammar either way, and sixteen features multiply the builds CI checks.
- **A selection in the order it names** — the same languages named in two orders would list their graphs and counts in
  two orders.
- **Names matched without case, or aliases such as `golang`, `c++` and `ts`** — every alias is one more name to keep
  and document, and the error already lists the names a caller can correct to.
- **Failing at the first unknown name** — a caller with two wrong names needs two attempts.
- **The unknown names as a field of `UnknownLanguages`** — no consumer read them apart from the message.

## Revisit if

A consumer needs a build without some of the grammars, or two shipped languages come to claim the same file, so the
order decides which one extracts it. High confidence for both: every consumer ships every grammar, and the extensions
are disjoint.
