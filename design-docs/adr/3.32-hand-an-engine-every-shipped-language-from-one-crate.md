# Hand an engine every shipped language from one crate, and select them by name

- **Status:** accepted
- **Date:** 2026-10-18
- **Initiative:** `03-code-graph`

ADR 3.1 keeps every language in a crate of its own and has the engine handed the languages to build with. kartta ships
sixteen languages from fourteen crates, `kartta-lang-jsts` holding three. The C ABI for Go and Node.js and the MCP
server each build an engine with them, and the FFI and the MCP server take the list of languages from their own callers
at run time.

**`kartta-languages` holds the set.** `all()` gives every language kartta ships, and a new language crate joins it. The
engine stays without a language of its own: a consumer that brings its own language, or wants fewer grammars compiled
into its build, depends on the language crates it wants.

**The set's order is the order the languages joined kartta in:** `go`, `cpp`, `typescript`, `tsx`, `javascript`,
`daslang`, `quirrel`, `blk`, `rust`, `python`, `bash`, `php`, `ruby`, `lua`, `puppet`, `dshl`. Each claims its files by
extension and no two claim the same file, so the engine's rule that a file goes to the first language claiming it never
chooses between two of them. The order decides only the order in which `Engine::graphs` and `Engine::stats` list them,
and that a language a consumer appends after the set gets only the files none of them claims; one that should take a
shipped language's files goes before the set. The `jsts` family resolves under the conventions of its first language,
and its three languages state the same ones.

**A selection is a set of names.** `select(names)` takes each name exactly as the language reports it, the names `NAMES`
lists, and gives the named languages in the set's order, each once however often named, so two selections of the same
languages build the same engine. A name that is not one of them fails the whole selection with `UnknownLanguages`, which
carries every unknown name and whose message lists `NAMES`, so a caller with several wrong names corrects them in one
step. No name selects no language, and the engine then indexes the tree and holds no graph.

**A family is selected a language at a time.** `typescript` without `tsx` builds the `.ts`, `.mts` and `.cts` files
into the `jsts` graph and leaves the `.tsx` files in the index alone: nothing they define is in a graph, and a call
from a `.ts` file into one counts as unresolved.

## Considered Options

- **Each consumer lists the crates itself** — three lists of sixteen entries, which drift apart in order and in names.
- **The set inside `kartta`** — the engine would name languages, which ADR 3.1 keeps it from, and every consumer of the
  engine would compile every grammar, one that brings its own languages included.
- **A cargo feature per language** — trims the grammars a build compiles, but the FFI and the MCP server take their list
  at run time and ship every grammar either way, and sixteen features multiply the builds CI checks. A consumer that
  wants fewer grammars depends on the language crates directly.
- **A selection in the order it names** — the same languages named in two orders would list their graphs and counts in
  two orders, though a list of names carries no order its caller means.
- **Names matched without case, or aliases such as `golang`, `c++` and `ts`** — every alias is one more name to keep
  and document, and the error already lists the names a caller can correct to.
- **Failing at the first unknown name** — a caller with two wrong names needs two attempts.

Revisit when a consumer needs a build without some of the grammars, or when two shipped languages come to claim the same
file, since the order would then decide which one extracts it.
