# Bind a C++ call on a declared class through the class nearest the caller's file

- **Date:** 2026-10-19

The C++ walk records a member call's receiver as the class its operand is declared as, spelled with the scopes the
declaration writes
([ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md)). A class's bare name
does not say which class, so the graph binds the member of the class of that name nearest the caller's file, chooses
among namesakes by the spelling as C++ lookup does, and searches the class's bases where it declares no member of the
name, at the price of a class the file reaches only through a header that includes it.

## Decision

Where scopes nest, as C++'s do, a receiver that names a class binds the member of a class of that bare name nearest the
caller's file through its includes: its own file, then the files it includes, then the rest of their closure. Where the
file reaches none, the call resolves as one on a value. Of the classes in the nearest tier that hold the member:

- a tier of one class binds it whatever the spelling says;
- else the ones whose qualified name the spelling names, looked up from the caller's scope outward, a member's class
  first, then its namespaces, the global scope last, so a bare `Widget` inside `namespace b` names `b::Widget`; where
  the spelling names none, all of them go on;
- of the classes left, those whose member the caller's own file holds, where any does;
- of those, the class in the caller's file that the caller's function defines, else the one whose body holds the
  caller, binds;
- else classes of one qualified name, a template and its specializations, a class under each branch of a conditional or
  copies of one class, bind the first;
- namesakes of other qualified names leave the call ambiguous.

Where the file reaches the class but no member of the name in it, `this->f()` in a template over a dependent base or
`d.f()` on a local of a derived class, the call binds the member of the class's bases that the lookup of a bare call in
its member finds: a nearer base's member hides a farther one's, and members of two bases neither derives from leave the
call ambiguous. A class of a base's bare name whose body is not that base's, `xray::Unit` beside `Unit`, holds another
class's member. A base the graph locates only through a guess leaves the call to resolve as one on a value.

## Why

- A class's name alone does not say which class: `vector` names EASTL's and a vendored PhysX one, `Unit` the game's and
  `xray::Unit`. Through the nearest class, 73,589 calls of the C++ game-engine tree of 43,356 files that bound nothing
  bound a member, 39 of 40 sampled right (2026-10-19).
- Two classes of one bare name a file includes at one depth, `a::Widget` and `b::Widget`, were left to path order;
  with the spelled scopes, 1,153 calls moved to another member, 30 of 30 sampled right (2026-10-22).
- C++ looks a member the class does not declare up in its bases, and in a template over a dependent base it requires
  `this->f()`. Through the bases, 16,374 more calls of the game-engine tree bind; all 90 sampled pairs added or moved
  name the right class, and none of 60 sampled pairs they replaced was right (2026-10-24).

## Consequences

- A class the file meets only through the header that includes it is not reached.
- Reading a class's bases holds 5.5 MiB more heap at the peak of a whole-graph resolution of the game-engine tree, and
  that resolution runs 11% faster, since fewer calls reach the tiers for a value (2026-10-24). Accepted.
- Of a base's overloads of the name, the call binds the first, whatever its arguments: 4 of 90 sampled pairs to a base
  were the right class's wrong overload or specialization (#443).

## Rejected

- **Bind through the nearest class alone, with no fallback to a call on a value** — lost 14,693 calls.
- **Bind the caller's own class where the file reaches no class of the name** — added 1,142 calls at about half right.
- **Make namesakes of one qualified name ambiguous** — took 1,160 more calls, 24 of 30 sampled of those sharing a file
  had bound right.
- **Check a tier's one class against the spelling** — took 5,667 calls, 18 of 20 sampled had bound right; a
  using-directive or a macro read as the class's name leaves the spelling short.
- **Spell a specialization's arguments into its class's qualified name** — told `Box<bool>` from `Box` but moved the
  resolution of bases and lost 3,702 to 4,026 calls (#374).
- **Search a class's bases in the order they are written, the first that declares the name, as a use of `this->f`
  does** — bound 7,108 fewer pairs: it reads no base inside a namespace.
- **Leave the call to a value's tiers where a namesake of a base lies outside that base's body** — bound 3,979 fewer
  pairs, the namesake most often a class of another project.

## Revisit if

The class nearest the caller's file is the wrong class in more than one sampled call in ten, as a namesake the
caller's includes reach before the class the build compiles would be. High confidence: 39 of 40 sampled were right.
