# Resolve a C++ include to the copy nearest the including file

- **Date:** 2026-10-17
- **Governs:** `crates/kartta-lang-cpp/src/resolve.rs` (`include`, `enclosing_copy`, `nearest_copy`)
- **Pinned by:** `crates/kartta-lang-cpp/src/resolve.rs`
  (`an_include_several_copies_end_in_names_the_copy_that_holds_the_includer_else_the_nearest`,
  `an_include_outside_every_copy_names_the_copy_sharing_the_most_directories`,
  `include_resolver_matches_segment_suffix_and_sole_candidate`, `quoted_include_prefers_the_including_files_directory`)

kartta resolves an `#include` without the include path a build sets, and a large tree vendors several copies of one
library, so one specifier often ends the paths of several files. The resolver names the copy the including file's
build most likely sets, and none where two are as likely, since a missing include is better than a wrong one.

## Decision

- **The specifier's file.** A `./` or `../` specifier names a file from the including file's directory, probing `.h`,
  `.hpp`, `.c`, `.cpp` and `.cc` after the bare path; a quoted one names a file in that directory first. A specifier
  then names the file at its own path, else the one file whose path ends in it at a `/`, else the one file of its last
  component's name, else the first of the specifier with those extensions added.
- **The enclosing copy.** Of several files that end in the specifier, the one whose root, its path less the specifier,
  holds the including file is named, the deepest root where roots nest.
- **The nearest copy.** Where no root holds the including file, the one whose directory shares the most leading
  directories with the including file's directory is named, and none where two share as many.
- **A system header.** A bare name in angle brackets, without a `/`, that several files end in and no root of which
  holds the including file names none: it spells a system header, `<time.h>`.
- **Letter case.** Every probe matches letter case, because a build on a case-sensitive file system finds no file
  whose path differs from the specifier in case alone.
- **No file.** An include that names no file is kept as an unresolved import with the specifier as written; a computed
  `#include MACRO` records nothing.

## Why

- A file of a vendored copy reaches its own copy's headers; read so, 10,805 more includes of the C++ game-engine tree
  of 43,356 files resolved, 9 of 10 sampled right (2026-10-17, #67).
- A file of PhysX, APEX, OpenSSL or libtorrent reaches a header of a sibling directory of its own copy through the
  include path its build sets, `"PsArray.h"` from `Source/GeomUtils/src`, which no root of the copy holds: the nearest
  copy resolved 16,815 such includes, 30 of 30 sampled inside the includer's first three directories naming its own
  copy (2026-10-23, #172).
- The rule reads only the few files of the specifier's name that a tie already listed.

## Consequences

- An include from beyond a copy's directories can reach another project's copy: 2 of 30 sampled among the 288 that
  leave the includer's first three directories, a copy of jsoncpp reached from another's amalgamation (2026-10-23,
  #172).
- A header newly reached can bring a namesake that leaves a call or a use ambiguous. Accepted.
- A conditional of the file's own includes that turns an include off is not read, so the include still resolves
  (#458).

## Rejected

- **Rank every copy by shared directories alone, without the enclosing root first** — loses 240 includes the enclosing
  rule makes and gains 61 (#172).
- **Take a bare angle-bracket name as well** — resolves 497 includes more, about half of them a system header,
  `<math.h>` to a maya plugin's (#172).
- **Rank by the root, the path less the specifier, instead of the directory** — changes nothing.
- **Break a tie by the shallower copy** — resolves 1,115 more, 8 of 30 sampled a platform's compatibility header,
  `<sys/time.h>` to beanstalk-client's `win32/` (#172).

## Revisit if

kartta reads a build's include path, from a compile database or a build file, which would replace every guess here.
Medium confidence that it will not soon.
