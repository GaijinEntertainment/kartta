# Keep a symlink's target in a list beside the walk's tree

- **Status:** accepted
- **Date:** 2026-10-21
- **Updated:** 2026-10-21
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fs/src/policy.rs` (`Payload`, `TargetId`, `Report::targets`),
  `crates/kartta-fs/src/index.rs` (`symlink_targets`)
- **Pinned by:** `crates/kartta-fs/src/policy.rs` (`a_node_holds_its_kind_and_one_id_in_eight_bytes`)

An index build peaks as the walk starts to flatten its tree, when it holds each entry's payload twice: in each
directory's recorded entries and in the slots they are flattened into. A symlink's target, which few entries have, waits
in a list beside the tree, so every node's payload takes 8 bytes; the index takes the targets out of the list as it
lays out their entries.

## Decision

- A node's payload holds the entry's kind and either a read file's `ContentId` or the place of a symlink's target in a
  list the walk keeps beside its tree, in 8 bytes.
- The index takes each target out of that list as it lays its entry out
  ([ADR 1.9](./1.9-front-code-the-stored-paths.md)).

## Why

- The payload, 24 bytes in a recorded entry and again in a slot, took 358 MiB of the build's 1,040 MiB heap peak, and
  16 of its bytes were an optional boxed target that 0.48% of the entries set (dhat, data volume, 7.82M entries,
  2026-10-21).
- With the target in a list, the heap peak fell to 805 MiB from 1,045 MiB (data volume, 2026-10-21).

## Consequences

On macOS with the large-allocation cache on, the footprint after the build stays near its peak, about 86 MiB above the
24-byte payload's; with the cache off both builds end at 188–191 MiB, so the difference is memory the allocator keeps
for reuse, not memory the index holds. Accepted.

## Rejected

- **The target behind a second box, a thin pointer in a 16-byte payload** — half the saving of the list: a median heap
  peak of 954 MiB against the list's 830 MiB on the data volume, for a second allocation per symlink.
- **The target read again as the index lays its entry out** — no list, but a second `readlink` per symlink on one
  thread after the walk, which can see a link the walk did not. Not built.

## Revisit if

A node must carry a second id beside its kind, which 8 bytes cannot hold. High confidence: no entry kind needs more than
one.
