# Count what the confidence floor dropped in place of an empty answer's verdict

- **Date:** 2026-10-20
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`below_the_floor`, `no_callers`, `callee_match`,
  `reference_match`, `path_match`), the `find_callers`, `find_callees`, `find_references` and `find_call_path` tools
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_callers_says_how_many_callers_bind_below_the_floor_in_place_of_a_verdict`,
  `find_callers_names_the_floor_only_where_it_dropped_callers`,
  `find_callees_counts_the_calls_that_bound_nothing_and_the_callees_below_the_floor`,
  `find_references_counts_the_sites_below_the_floor_and_names_it_only_where_it_dropped_some`,
  `find_call_path_counts_the_callers_below_the_floor_that_it_did_not_follow`,
  `find_call_path_names_the_floor_only_where_it_dropped_callers`)

A `min_confidence` floor can empty an answer the graph has records for, and an empty answer's note is read as a
verdict: no callers, so dead code. Where the floor dropped what the answer would list, the note says how many and which
call lists them; where it dropped nothing, the note reads as it does without a floor.

## Decision

- **Where the floor dropped some.** A match the floor left empty states only the count and the call that lists it:
  - `find_callers`: "no callers at this confidence floor - 2 callers bind below it, and min_confidence "any" lists
    them", or "1 caller binds below it, and min_confidence "any" lists it". The walk expanded the root alone, so the
    count is its direct callers and the files whose top level calls it. The note takes the place of the ambiguous
    calls' note ([ADR 4.12](/design-docs/adr/4.12-ambiguous-call-counts.md)), and `ambiguous=` still counts those
    calls.
  - `find_callees`: "no callees at this confidence floor - 2 callees bind below it, ...".
  - `find_references`: "no recorded site at this confidence floor - 2 uses bind below it, and min_confidence "any"
    lists them". `below_confidence=` counts the sites and the file-scope files
    ([ADR 3.112](/design-docs/adr/3.112-file-scope-names.md)) the floor dropped whatever `access` keeps, so the note
    names uses, and with `access` it names min_confidence "any" without access.
  - `find_call_path`, a match without a chain whose search the node cap did not stop: "no call chain within 8 calls at
    this confidence floor - 2 callers bind below it, and min_confidence "any" follows them". It counts what
    `below_confidence=` counts: the callers the floor dropped at each callable whose callers the search looked at.
- **A count note stands alone.** The call it names lists the records, and that answer carries the caveat they need: a
  method's or a field's note, or the note of a language that records no use of a type.
- **Where the floor dropped nothing.** A lower floor lists nothing more, and the empty answers of the four tools read
  as they do without a floor and do not name it.
- **The node cap.** A `find_call_path` search the node cap stopped keeps the cap's note, whose remedy is fewer hops or a
  higher floor; its `below_confidence=` still counts the callers dropped.
- **Text, not shape.** The notes change text, not attributes or elements. The `initialize` instructions say what
  `below_confidence=` counts, and each note says the rest.
  `impact_of_edit` and `impact_of_change` take no floor. The C ABI carries the counts as `below_confidence` and no note
  ([ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md)).

## Why

- On this repository `caught_up` at `certain` answered "no callers - entry point, dead code, or dynamic dispatch" beside
  `below_confidence="3"`, while its three callers bind it `likely` (2026-10-20, #250): a dead-code verdict about a
  symbol with callers. Of 60 such replaced verdicts sampled on two trees, 59 symbols had a real call among those the
  floor dropped.
- A note that names the floor where the floor dropped nothing points an agent at a lower floor that lists nothing more.
- Each count is one the walk already holds, and only an empty match builds the note.

## Consequences

- A count says how many records bind below the floor, not in which band: the note names `any`, which always lists them.
  Accepted.
- A count can include false edges the graph holds at `guess`, such as a UI library's JSX elements bound to namesakes in
  the tree; the note counts them as the graph holds them. Accepted.

## Rejected

- **Naming the floor that lists them** — the walk counts the callers it dropped but not the band of each, so the note
  cannot say whether `likely` would list them, and `any` always does.
- **Counting only the sites of the access kept** — `below_confidence=` and the C ABI's count would change meaning, and
  each such call would split the dropped sites by access.
- **Keeping the caveat after a count note** — it explains an absence the count already explains, and the answer of the
  call the note names carries it beside the records it is about.
- **Counting the dropped callers in the node cap's note** — that note's remedy narrows the search, and naming
  min_confidence "any" there points an agent at a wider search the same cap stops sooner.
- **Counting "calls" below the floor** — `below_confidence=` counts a caller that calls from several lines once.

## Revisit if

A walk records the band of each record it drops, so a note can name the highest floor that lists them.
