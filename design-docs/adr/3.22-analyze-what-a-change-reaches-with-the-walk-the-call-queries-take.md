# Analyze what a change reaches with the walk the call queries take

- **Status:** accepted
- **Date:** 2026-10-17
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/analyze.rs`, `crates/kartta-graph/src/change.rs`, `Graph::analyze_segment`,
  `Graph::analyze_change`, `Change::merge`, `ReachBand`, `Engine::analyze_change`
- **Pinned by:** `crates/kartta-graph/tests/graph/analyze.rs`

An agent about to edit a range of lines asks what the edit reaches, and a reviewer asks the same of a whole change and
where its symbols' reaches meet. A blast is the walk `callers` takes, with a visitor in place of the list, under one
resolution memo for the whole query, so a walk that meets no field, variable or constant reaches what `callers`
lists, and a name's call sites resolve once; each query still pays that resolution, since calls resolve when a query
asks (ADR 3.7).

## Decision

**The walk.** The reach of a change to a symbol is the breadth-first walk over its callers that `callers` runs, under
the same `Limits`: the depth bound, the symbol cap and the confidence floor. The walk gives each symbol it reaches to a
visitor: `callers` and `callees` push a `Reached` into their list, and the analyses count the depth and the file of
each symbol and read no definition for a symbol they do not list. A blast's reach is the length of the list `callers`
returns for the same symbol and limits while the walk meets no field, variable or constant; from one of those the
walk takes its users, which [ADR 3.132](./3.132-walk-from-a-field-a-variable-or-a-constant-to-its-users.md) decides.
A blast counts the symbols the walk reached and never the root's call of itself, which the walk gives apart
([ADR 3.37](./3.37-count-what-a-call-walk-leaves-out.md)); a symbol's direct callers and callees read its edges, not
a walk, and list that call.

**One query resolves each name once.** A segment or a change keeps one resolution memo for every symbol it analyzes, so
a name's call sites resolve once, whichever symbol or walk asks first. A walk borrows the memoized caller edges of each
symbol it expands; the callees of a body are resolved for that body, as `callees` does. Nothing outlives the query.

**A declaration answers for its definition.** A segment over a header lists a prototype with the callers and callees
of the definition its callable identity links it to. A change counts a declaration and its definition as one changed
symbol, answered as the occurrence the regions overlap first in path order.

**A segment.** `analyze_segment` answers `None` for a file the graph does not hold. It lists the symbols whose lines
overlap the range, by the line each starts on, one that encloses others first; `1..=u32::MAX` is the whole file. Each
symbol carries its direct callers and callees, the count of its body's calls that bound nothing (ADR 3.37), and its
blast. The segment lists the files its file includes and is included by, directly, in path order. A segment is one file,
which one language family holds, so the engine reaches it through `graph_of`.

**A change.** `analyze_change` answers the symbols its regions overlap, each changed symbol with its walk, and:

- `footprint`, the symbols the walks reach, each once, and `footprint_files`, their files; `transitive_sum`, the reaches
  summed, so what exceeds `footprint` is where they overlap;
- hotspots, the symbols two or more changed symbols reach, each with how many reach it, its nearest depth and whether it
  is itself changed;
- `unheld_regions`, the regions whose file the graph does not hold, and `regions_outside_symbols`, those that overlap
  no symbol.

**Every count takes one floor.** The floor of `Limits` filters the direct callers and callees, the walk, and a changed
symbol's caller count and consumers. `below_confidence` counts the direct calls under it, and for a walk the edges it
turned down at each symbol it expanded.

**A cut answer says how much it cut.**

- Direct calls list at most 50 callers and 50 callees in path order, each side with its `total` and
  `below_confidence`.
- A blast and a changed symbol report `truncated` when the cap stopped the walk, `turned_away`, the callers or users
  the cap turned away at the symbol where it stopped, and `unexpanded`: the symbols at the depth bound, the symbol
  itself at a depth of 0, and those the cap left in the queue.
- A change lists at most 300 changed symbols and 300 hotspots, and counts all of them in `changed_symbols` and
  `total_hotspots`; `truncated_seeds` counts the walks the cap stopped.
- A changed symbol lists its direct callers while 30 or fewer pass the floor, in path order with test, generated and
  entry code last, and past that counts them by directory, the most first; a field, a variable or a constant lists its
  users in their place (ADR 3.132).
- A segment's symbol and a changed symbol count in `ambiguous` the calls of their name that `Graph::callers` counts in
  `Walk::ambiguous`, which bound no definition because several of the name may be meant; the count ranks nothing.
  ADR 4.12, a split of [ADR 4.1](./4.1-answer-agents-through-an-mcp-server-with-the-tools-their-prompts-name.md),
  states how the tools show it.

**Ranking.** Changed symbols rank by reach, then by direct callers; hotspots by the changed symbols that reach them,
then by the nearest depth; ties break by qualified name, file and line. Test, generated and entry code ranks after all
other code in both lists. A change keeps at most 600 listed changed symbols at a time, each with its definition and
consumers, and cuts them back to the best 300; past the list it keeps only the position of each changed symbol and of
each symbol the walks reach.

A blast's `affected_files` counts the files of its callers and of its file's includers, as
[ADR 3.133](./3.133-count-a-blast-s-files-from-its-callers-and-its-file-s-includers-apart.md) decides.

**Bands.** A reach under 10 is `Low`, 10 to 49 `Medium`, 50 to 199 `High`, and 200 or more `Critical`. An exported
symbol is `High` from 20 to 199, and an interface `Critical` from 50. No reach falls in two bands.

**Across language families.** `Engine::analyze_change` sends each region to the family whose language claims its file,
and a region whose file no language claims counts as unheld. Each family's graph analyzes its regions, and
`Change::merge` sums the counts and ranks the changed symbols and hotspots of all families under one cut. The families
hold different symbols, so no symbol counts twice in a sum.

## Why

- One walk answers both, so the reach of a walk that meets no data symbol cannot part from the callers `callers` lists:
  of the segment symbols whose name selects the same symbol for `callers`, 1,263 of 1,266 on the C++ game-engine tree
  reported the length of its list, every exception a name several definitions share on one minified line (2026-10-17).
- A memo per query resolves each name once across the walks of one change, whose five regions reached 2,606 symbols on
  the C++ tree, and keeps nothing after it, so the build pays nothing for the analyses.
- Test, generated and entry code ranks last because how it is run, not what it calls, sets its reach.
- An interface is `Critical` sooner because each of its implementors answers for its contract.

## Consequences

- Each symbol pays its name's resolution: a segment over a whole vendored header of 310 symbols with common names took
  0.3 s on the C++ tree, about 1 ms a symbol (2026-10-17). Accepted.
- A blast is as right as the call bindings behind it; the defects of ADR 3.7's tiers move reaches with them.

## Rejected

- **A walk of the analyses' own** — a second breadth-first walk to keep in step with `callers`, so the reach a blast
  reports and the callers `callers` lists could part.
- **Each walk returns its list, and the analyses count it** — a definition read and built for every symbol reached,
  where a changed symbol lists only its direct callers and a blast lists none.
- **A memo for each symbol analyzed** — each walk resolves again the names the walk before it resolved.
- **A segment on the engine** — a file belongs to one family, so the engine would only route the call that `graph_of`
  already routes.

## Revisit if

A consumer needs a whole large header analyzed faster than per-query resolution answers it, 0.3 s on the C++ tree, or
changes of thousands of symbols make the per-query memo outgrow the few megabytes a query holds. Neither is asked for.
