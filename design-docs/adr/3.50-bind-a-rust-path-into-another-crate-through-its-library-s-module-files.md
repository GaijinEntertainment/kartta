# Bind a Rust path into another crate through its library's module files

- **Status:** accepted
- **Date:** 2026-10-22
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-rust/src/walk/imports.rs`, `crates/kartta-lang-rust/src/manifest.rs`,
  `crates/kartta-lang-rust/src/resolve.rs` (`Crates::new`, `Crates::library`, `Crates::crate_binding`, `Crates::reach`)
- **Pinned by:** `crates/kartta-lang-rust/tests/crates.rs`, `crates/kartta-lang-rust/src/manifest.rs::tests`,
  `crates/kartta-languages/tests/engine.rs`
  (`a_rust_call_through_another_workspace_crate_binds_the_function_that_crate_exports`,
  `a_rust_tuple_struct_s_constructor_binds_the_struct_its_use_names_among_namesakes`,
  `a_rust_glob_binds_the_items_its_module_s_file_shows_the_caller`,
  `a_rust_macro_invocation_through_another_crate_binds_the_macro_it_exports_at_its_root`)

A `use` and a path name a module, and a Rust module is a file, so a call into another crate of the repository binds only
where the extraction keeps the path and the resolver walks it to the module's file. The walk keeps one path per name,
and a path reads from each `Cargo.toml` only its library's name and root; a name with two paths, a type's member, a
module that `#[path]` places and a crate outside the tree bind nothing through a path. The packages a manifest names
gate the calls that bind by name, as
[ADR 3.179](./3.179-bind-a-rust-call-by-name-only-within-the-crates-its-crate-is-built-with.md) decides.

## Decision

**What the walk keeps.** Each name a `use` binds is kept with the path it reaches, an alias by its alias and `self` in a
list by the module the list is under; so is the receiver of a path call, `kartta_walk::walk::run()` for `walk`, and the
name of a macro invoked through a path, `other_crate::mac!()` for `mac`. The first segment of a path call's or a macro's
path is read through the file's `use` of that name. The kept paths sit among the file's directives in source order.

- A path keeps nothing where its first segment is capitalised or is `std`, `core`, `alloc` or `_`, and `as _` keeps
  nothing. [ADR 3.51](./3.51-start-a-rust-path-through-crate-self-or-super-at-the-caller-s-crate-root-or-module.md)
  decides the paths through `crate::`, `self::` and `super::`.
- A file's bindings hold one path per name. A name the file declares at its top level keeps none, and neither does a
  path whose first segment the file declares without importing it; ADR 3.51 keeps a `use` of a name the file declares
  only as a module. A name bound to two paths anywhere in the file keeps neither.
  [ADR 3.52](./3.52-scope-a-rust-use-inside-a-block-to-that-block.md) decides what a `use` inside a block binds.
- A path that ends at a capitalised item, through a `use` or as a path call's receiver, is kept only where the file
  calls its name bare, as `Wrapper(1)` calls a tuple struct's constructor; a call through a type, `Wrapper::new()`,
  names a member, which the module's file does not answer at its top level.
- A glob outside every function body and inline module keeps the module path it ends at, one directive per glob, by the
  rules of a `use`. A glob inside a block, of a capitalised item or of the standard library keeps nothing.

**What the resolver reads.** A package's library is named by its manifest's `[lib] name`, else by its `[package] name`,
`-` read as `_`, and lies at its `[lib] path`, else at `src/lib.rs`. Each value is read only from a `key = "value"` or
`key = 'value'` on one line under its table's header, the form Cargo writes; a manifest without a `[package] name`
declares no library. A kept path starts at the library its first segment names: the caller's own package's, else the
one whose package shares the most leading directories with the caller's, and none where two share as many or the
library's root is not in the tree. Each segment after names `NAME.rs` or `NAME/mod.rs` by the module layout of ADR 3.11,
asked of the tree as the file resolves. A path that ends at a module imports that module's file, one that ends a segment
further, at an item, imports the file of the module that holds it, and a longer rest imports nothing; so does a module
that a `#[path]` places, since the resolver reads no file the path leads through. A glob imports the file of the module
it ends at as a dot import, and nothing for a path that ends past a module.

**What a call binds through it** is
[ADR 3.45](./3.45-bind-a-call-through-a-module-s-file-as-the-module-s-paths-see-it.md)'s.

## Why

- Without the path a call into another workspace crate bound only by its name: `kartta_lang::tree::text` had no caller
  and 198 calls of `text` counted as ambiguous (this repository, 2026-10-22).
- A published crate names its dependencies by version, and a workspace's directories need not spell its crates, so the
  library's own name is what a path starts with.
- One path per name is what a file's bindings hold. A name two `use`s bind to two paths is mostly a pair of `cfg`
  alternatives with no one answer, getrandom's `rdrand_step`; side by side in a registry, the versions of one crate are
  as near as each other, 88 crates of one registry; and the modules `#[path]` places are per-architecture alternatives,
  460 of the 486 a registry places so (cargo registry of 488 crates, 2026-10-22).
- A path that ends at a capitalised item bound nothing until a bare call needed it: `Wrapper(1)` after `use
  other_crate::m::Wrapper;` took the caller crate's own `struct Wrapper` at 70 (#386). Keeping such a path only for a
  bare call cut the paths kept to about a third (this repository, 2026-10-23).

## Consequences

- A crate outside the tree binds nothing through its path, as `serde::` does; so a root file's `pub use dep::foo;` from
  outside the tree is no definition of `foo` there for ADR 3.45's macro fallback (#236).
- The library is chosen by directory nearness, not by the caller's dependencies (#228).
- A file that calls a capitalised name bare and also through it as a receiver reads that receiver as the type's module
  file, where a top-level item of the member's name would answer. Accepted: no file of three measured trees binds so.
- A `[lib]` `name` or `path` spread over lines or kept in an inline table is not read. Accepted.

## Rejected

- **A package's path dependencies name its crates** — in a registry of 488 crates it adds 1,545 pairs where the
  library names add 2,325, since a published crate names its dependencies by version (2026-10-22).
- **A package's directory names its crate** — binds nothing in tree-sitter, whose `crates/highlight` holds
  `tree-sitter-highlight`, or in any workspace whose directories do not spell its crates.
- **Every path that ends at a capitalised item imports its module's file** — the pairs it adds in the registry are
  mostly wrong, as `TokenTree::Group(...)` taking proc-macro2's `struct Group` (2026-10-22); with no bare call asked it
  keeps a quarter to a half more paths and unbinds the right `Index::build(...)` of kartta-fs (2026-10-23).
- **No module-file answer through a receiver that the module's file declares as a type** — binds the same pairs and
  misses a type the file re-exports, as `Index`.
- **A glob inside a block too, bound for the whole file** — a glob of another module there would reach calls outside
  its block.

## Revisit if

The call record carries a path per call (#236), so that a name need not hold one path for its whole file. Open.
