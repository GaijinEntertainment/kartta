A macro invocation, a member's macro or a label that costs a C++ file its declarations is harmless on the same line of
a file that parses, so only the first tree's errors show which ones to blank. Where the first tree holds an error, the
file is parsed again from a copy that blanks those alone, at the price of a second parse of the few such files.

## Decision

Where the first tree holds an error and a repair below blanks something, the file is parsed again from a copy of the
first parse's copy ([ADR 3.3](./3.3-repair-what-the-c-plus-plus-grammar-cannot-parse.md)) that also blanks the
following, to spaces with every newline kept. The same copy takes the conditionals that
[ADR 3.71](./3.71-read-a-conditional-that-splits-a-brace-with-its-first-branch-taken.md) repairs.

1. **A spill.** The macro invocation that opens any line of an error, its first included, whose last row lies three
   rows or more past its first: an upper-case name of three or more characters, alone on its line or with its
   arguments where no `;` follows, with the macros between it and a `{` on its line,
   `TEST(Suite, Case) NO_ANALYSIS {`, and not the rest of the line, which holds the declaration a macro annotates. An
   error that opens at a class head runs to the brace that closes the class in the source. An invocation that ends an
   enum, its last enumerator alone on a line, is blanked too and is inert, since no enumerator is a symbol.
2. **A misread class.** Where a tree that parses at its top level holds a class member whose opening macro the grammar
   reads as the member's type and cannot read past: the macro that opens each member of that class, up to the brace
   that closes the class in the source, past `static`, `inline`, `virtual`, `friend`, `constexpr`, `explicit` and
   `extern`, before a type and a declarator, a destructor, a conversion operator or a constructor's initializer list.
   A member the first tree reads as written keeps its macro, and so does a macro beside another macro or a compiler's
   own `__` word. The signature of a member whose macro is blanked starts past the macro. A file whose first tree
   fails at its top level is left as it is.
3. **A label before an `#endif`.** The label and colon of a label the grammar reads an `#endif` under, `skip:` right
   before the `#endif` that closes its branch, where the first tree holds that `#endif` as an error in the label's
   statement.

The spill and the misread class never blank a line of a `#define`, its first line or a continuation. A second parse
that yields no tree leaves the walk to the first copy, parsed again
([ADR 3.31](./3.31-parse-a-c-or-c-plus-plus-table-without-its-numbers.md)): the repair is an improvement, never a
precondition.

## Why

- A line identical to a harmful one is harmless in a file that parses, so only the first tree's errors show which
  invocations cost something; a macro invocation spans one to three rows, so a shorter error consumed nothing else.
- A macro left before a body reads as a compound literal's type, which takes the body's locals past its first
  statement to namespace scope: 4 of abseil's `mutex_test.cc` locals read as file variables (2026-10-24).
- A misread member closes its class at its own brace, and the members after it parse outside the class; the source's
  brace, not the tree's, bounds the class, and a member read as written beside its macro keeps it.
- A label that ends a branch takes the `#endif` for its statement, and the conditional never closes: duktape's
  `duk_hobject_enumerator_create` spanned lines 52384 to 77150, not 52737. A label is no symbol, call or use, and
  blanking it brings back a lost function in 5 game-engine files and changes no other file (2026-10-24).

## Consequences

- A second parse of the files whose first tree shows a misreading, 1,608 of the 43,357 game-engine files (2026-10-24).
- The spill repair drops the calls written inside a blanked invocation's arguments; 123 of 621 such calls named a
  definition elsewhere (2026-10-16). Accepted.
- A class a macro builds, or one that breaks at a conditional inside a constructor's initializer list, still parses
  apart (#439, #407); PhysX's `Facet` reads as an error at `PX_ALIGN(16, PxVec3 m_closest);` once its macros are
  blanked.
- A file whose first tree fails at its top level, as `vulkan_structs.hpp`'s does, keeps its misread members (#412).

## Rejected

- **Re-parse wherever an error holds a macro invocation** — 855 files parsed twice instead of 163, for 12% of the
  recovered symbols.
- **Require an argument list of a blanked invocation** — spares the last enumerator but costs 62 symbols and doubles
  the losses.
- **Blank the macros after an invocation to the end of its line** — brings back 4 jemalloc functions and drops 68
  calls of macro runs such as pcre's `LBL( 1) LBL( 2)` (2026-10-24).
- **Blank every member macro of the file, not the misread class's** — changed 919 files and lost 72 callables the
  second parse misread elsewhere; without the check that keeps a member read as written, 6,863 signatures changed
  instead of 2,156.

## Revisit if

A `tree-sitter-cpp` release moves where the first tree's errors fall, or the files parsed twice grow well past 4% of a
tree's C++ files. High confidence that 0.23.4 stays the latest for the near term.
