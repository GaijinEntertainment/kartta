# Bind a use of a field or a value by what its receiver names

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`resolve_use`, `member_use`, `value_use`, `bare_use`,
  `imported_value`), `crates/kartta-graph/src/{members,typed}.rs`,
  `kartta_lang::{ValueUses, UntypedMembers, OwnMembers}`
- **Pinned by:** `crates/kartta-graph/tests/graph/typed.rs`, `crates/kartta-graph/tests/graph/members.rs`

A use of a field or a value names its target as written: bare, through a qualifier, on the member's own receiver, or
on a path. [ADR 3.34](./3.34-record-each-read-and-write-of-a-field-or-a-value.md) records each use and binds it when a
query asks; each receiver binds at the tiers below, where the source reads it, and a use that only the field's name
would bind is left ambiguous rather than guessed.

## Decision

Past the class-scope lookup, a bare or qualified use binds no field, enum variant or local symbol, but a qualifier read
as a path does.

- **Bare:** the class-scope lookup first where the language sets `OwnMembers::First` (ADR 3.64), then by `ValueUses`:
  `Declared`, the definition outside every owner and body its own file declares at 80, a dot-imported package's at 95,
  its package directory's at 75 where packages are directories; `Imported`, its own file's at 80, then the one included
  file that exports the name at 70 (two bind none), a re-export chain from them at 65, then the one included file that
  declares it unexported at 70; `Included` is C++'s (ADR 3.64).
- **Qualifier:** through the file's import of that module, an exported package-level definition at 95. Where
  receivers are type paths (Go), a qualifier that no import of the file binds is a path of one name, and the use binds
  as one on a path does: a walk that sees one file takes a sibling file's package value for a qualifier
  ([ADR 3.60](./3.60-record-every-go-data-site-its-walk-can-place.md)). Elsewhere a qualifier that names the module
  its own file declares, daslang's `coverage::f` inside `module coverage`, binds as a bare name under `Declared` does,
  since that module is the file; one that names the module an included file declares binds that file's definition, as
  [ADR 3.140](./3.140-find-a-daslang-module-by-its-file-name.md) states; any other binds nothing.
- **Own receiver:** under `OwnMembers::First` the class-scope lookup; otherwise the member of the class around the use
  at 85, else one a base declares at 80 where every base searched before it was found without a guess. No class around
  the use, or an unseen base before the find, counts as ambiguous.
- **A path, where receivers are type paths (Go):** a field or a method of the type the path reaches, or of a type it
  embeds, at 85; a path that reaches a field or a variable whose struct is anonymous reaches the fields it owns
  ([ADR 3.170](./3.170-own-a-go-anonymous-struct-s-fields-by-the-field-or-the-variable-it-types.md)). A path into code
  outside the graph, an undeclared name, or a type without the member binds nothing and stops. A path the graph cannot
  follow goes to the untyped tier.
- **A non-empty path, where receivers name owners:** the member of that owner its file or one included file declares at
  85 (two included files count as ambiguous); else the definition outside every owner of the one included module whose
  name the path ends, at 85; else a type of that name the file or one include declares at 85, then its bases at 80 under
  the same no-guess rule. Otherwise it binds nothing, and no untyped tier is tried; C++ reads includes further
  (ADR 3.64).
- **The empty path, the untyped tier:** by `UntypedMembers`. `FileField`, the one field of the name its file declares
  outside every body but the use's own, at 80, none or several counting as ambiguous; `Unbound`, nothing, counted as
  ambiguous; `IncludedField` is C++'s (ADR 3.64).

## Why

- The type path binds what the source reads: 64 of 64 sampled sites on the Go monorepo were right (2026-10-18).
- A daslang macro quotes its own module's functions as `module::f`, and with that qualifier unbound `find_unused`
  listed 5 such functions on the game-engine tree (2026-10-24).

## Consequences

- An untyped member under `FileField` can bind a namesake field of its file, as a value of an anonymous struct did.
  Accepted.

## Rejected

- **Fields by name only, no type paths** — bound 12 of 24 sampled sites right where the path was cut.
- **The one field of the name in the family** — 2 of 7 right in C++: the field is the only one because the real struct
  was not extracted.

## Revisit if

A language's walk names the type of the values whose path it leaves empty, so its untyped tier could give way to a
path, or the type path stops binding what the source reads. Held with high confidence on the 64 sampled sites.
