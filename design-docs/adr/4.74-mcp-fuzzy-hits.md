# Answer find_symbols with fuzzy hits only when no keyword matches

- **Date:** 2026-11-27
- **Governs:** `crates/kartta-mcp/src/server.rs` (`find_symbols`), `crates/kartta-mcp/src/render/symbols.rs` (`hits`)
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_symbols_answers_fuzzy_hits_only_when_no_keyword_matches_and_counts_them_apart`),
  `crates/kartta-mcp/tests/names.rs` (`find_symbols_lists_a_suggested_definition_once_and_counts_it_among_its_matches`)

`Graph::search` tops up word matches that underfill the limit with the fill-up's hits
([ADR 3.21](/design-docs/adr/3.21-definition-search.md)), names that spell the query's characters in order.
`find_symbols` lists those hits only for a query no keyword matches, counts them apart, and lists a suggested
definition once. An agent whose meant definition only the fill-up reached beside other keyword matches asks again.

## Decision

- **When fuzzy hits answer.** The fill-up's hits answer a `find_symbols` query only when no graph it searched holds a
  keyword match for it. An answer with a keyword match lists keyword matches alone.
- **The counts.** `total=` counts the keyword matches. A fill-up answer carries `total="0"` and counts the fill-up's
  matches in `fuzzy_hits=` and those it lists in `fuzzy_hits_shown=`, a second kind of record as
  [ADR 4.71](/design-docs/adr/4.71-mcp-count-vocabulary.md) names one; a limit that cuts it leaves the limit's last
  line.
- **A suggestion is listed once.** A definition that a `<suggestion/>` record lists
  ([ADR 4.18](/design-docs/adr/4.18-mcp-name-misses.md)) is not listed again as a hit. The counts still count it, so
  they do not move with the limit, and the shown counts count the `<hit/>` records alone.

## Why

- Over 2,112 queries on this repository and the Go monorepo snapshot, each written from one of 600 sampled
  definitions as its name, its name less its middle character, its first 60% or its words' initials, the top-up put
  1,712 fuzzy hits beside keyword matches, and was the only place of the sampled definition for 9 queries
  (2026-11-27, #1310).
- The fill-up's score, how densely a name spells the query, does not tell a meant name from a scattered one: the 9
  meant definitions scored 0.29 to 0.86, and unrelated hits reach 0.625, `function` for `union`.
- On this repository the top-up listed 701 hits that a suggestion of the same answer already listed, 520 of them for
  the 277 typos.

## Consequences

- A query whose meant definition only the fill-up reaches, beside keyword matches of other definitions, answers
  without it: 9 of the 2,112 sampled, prefixes such as `decl` for `declare`. The agent asks the whole name or a word of
  it; a top-up of the names the query starts is #1339.
- A graph whose words match fewer definitions than the limit still runs the fill-up, a read of every definition's name,
  and the answer drops its hits when another graph, or this one, holds a keyword match (#1337).

## Rejected

- **A top-up bounded by the fill-up's score** — at 0.5 it kept 938 of the 1,712 fuzzy hits beside keyword matches and
  lost 1 of the 9; at 0.6 the snapshot kept 531 of its 943 and lost 2 of its 3.
- **The fill-up's rule moved into `Graph::search`** — the C ABI wire's `search` and the other symbol tools' miss
  suggestions read the same search, so their answers would move with it.

## Revisit if

Agents reach their meant definition only through the fill-up, beside keyword matches, for more than a few queries in a
hundred. The sampled queries are written from names, not taken from agents: medium confidence.
