# Keep the names a file's top level calls and uses

- **Status:** accepted
- **Date:** 2026-10-17
- **Updated:** 2026-10-19
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/graph.rs` (`store_file_scope_names`, `named_at_file_scope`),
  `crates/kartta-graph/src/calls.rs` (`file_scope_callers`), `Walk::file_scope`, `kartta_lang::FILE_SCOPE`, each
  language's walker
- **Pinned by:** `crates/kartta-graph/tests/graph/dead_code.rs`
  (`a_call_at_file_scope_reaches_its_file_and_the_files_it_includes`,
  `a_use_at_file_scope_reaches_the_types_its_package_defines`), `crates/kartta-graph/tests/graph/calls.rs`
  (`callers_list_the_files_whose_top_level_names_a_function_by_how_each_sees_it`,
  `callers_list_a_package_file_whose_top_level_names_a_function_at_the_package_s_confidence`,
  `callers_of_a_field_list_no_file_whose_top_level_names_it`)

A call or a use made at a file's top level has no symbol to resolve from, so a script that calls its functions from
its top level had every one reported dead. The graph keeps the names a file's top level spells, and a name reaches the
definitions of it that the file sees, for both the dead-code query and `callers`; it keeps no line.

## Decision

1. A call or a use made outside every definition is made at file scope, and so is one made before the file's first
   symbol. Each language's walker records it so.
2. Each file keeps the distinct names of its file-scope calls and uses, a call by its listing key (ADR 3.38), and the
   graph lists the files under each name, as it lists includers (ADR 3.19). No line and no site is stored.
3. Such a name reaches every definition of it that its file sees: in its own file, in the files it includes, and where
   a package is a directory, in its package. ADR 3.23 counts each one so reached as `live`.
4. A walk over callers lists each file whose top level names the root and sees it, in path order, with the confidence
   of how it sees it: 80 for its own file, 75 for its package, 70 for an include. The confidence floor drops and counts
   them as it does calls (ADR 3.37). Only a root a call can bind gets them, so `callers` of a field or an enum variant
   lists no file.

## Why

- A script runs its functions from its top level, as a shell script's `main "$@"` does.
- `dead_code` and `callers` ask the same question of a file-scope name, so the two cannot disagree on a definition: a
  function called only from a top level had no caller in `callers` while `dead_code` judged it reached.
- Ten walkers dropped every call made while their file had no symbol yet, so a function that a file named only above
  its first definition read dead (2026-10-19, #110).

## Consequences

- The names cost 9.0 MB of the C++ game-engine tree's 643 MB heap after the build, 1.4%, and keep 21,521 definitions
  off the dead list (2026-10-17).
- A name reaches every definition of it the file sees, a namesake the top level does not mean included. Accepted.
- A file-scope caller carries no line, and nothing tells a call from a use.

## Rejected

- **Drop file-scope calls** — every function a script calls only from its top level reads dead.
- **Record the file as a symbol and resolve its calls** — a file holds no symbol, and a walk would go on past it; the
  names alone answer both queries.

## Revisit if

The file-scope names grow past a few percent of a build's heap on a large tree, or an agent needs the line of a
file-scope call. High confidence: 1.4% on the C++ game-engine tree.
