# Name a Rust call's receiver only where its syntax spells it

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-rust/src/walk/calls.rs` (`call_target`, `member_target`, `path_receiver`,
  `value_receiver`), `crates/kartta-lang-rust/src/walk/settle.rs` (`settle_paths`),
  `crates/kartta-lang-rust/src/resolve.rs` (`read_renamed_types`)
- **Pinned by:** `crates/kartta-languages/tests/engine.rs`
  (`a_rust_call_through_a_type_a_use_renames_binds_the_member_of_the_type_the_use_names`,
  `a_rust_rename_stays_as_spelled_where_its_file_declares_the_type_s_name_or_impls_the_rename`),
  `crates/kartta-lang-rust/tests/extract.rs`
  (`a_call_belongs_to_the_function_around_it_and_self_names_the_impl_type`,
  `a_scoped_or_macro_call_names_its_last_segment`, `a_member_call_on_an_unnamed_expression_keeps_an_empty_receiver`,
  `a_member_call_on_a_lowercase_value_records_its_name_after_a_dot_and_on_an_item_or_other_its_name`),
  `crates/kartta-lang-rust/tests/modules.rs`

A call's receiver is what the cascade binds through
([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md)), and one
file's bytes tell a value from a type or a module only by how the call is written. The Rust walk records a receiver
that the syntax spells, marks a lowercase value's name so that it names no module, and resolves no path through a
`use`, which the resolver binds instead; only a parameter's, a field's, a local's or a chain's type reads the file's
`use`s, to tell whether the tree may hold it ([ADR 3.55](/design-docs/adr/3.55-rust-parameter-receivers.md)). The
resolver, which knows the tree, reads a type's `use … as` back to the name the owner tier finds.

## Decision

- **`self` and `Self`.** `self.m()` and `Self::f()` name the owner of the `impl` or `trait` around them, and follow it
  when an impl's owner settles ([ADR 3.11](/design-docs/adr/3.11-rust-item-names.md)).
- **Scoped calls.** A scoped call names the type or module its path names in the file under the inline-module chain,
  `a::Worker::run()` naming `a::Worker` and `super::W::new()` in `a::inner` naming `a::W`, and otherwise the path's last
  segment, `Graph::build()` naming `Graph`. A path whose last segment is `self`, `super` or `crate` names a module and
  records no receiver. The walk resolves no receiver through a `use`.
- **Bare and chained calls.** A bare call, `helper()`, records no receiver. A member call on anything but a name, a
  named field of `self` or a chain that names a type, `x.y.z()` or `f().g()`, records the empty receiver.
- **A lowercase value.** A member call on a lowercase name other than `other` records the name after a `.`, `.socket`
  for `socket.connect()`, which names no module, import or owner; how the graph binds it is
  [ADR 3.184](/design-docs/adr/3.184-rust-module-path-calls.md)'s and
  [ADR 3.40](/design-docs/adr/3.40-runtime-method-calls.md)'s. A capitalised name, a unit struct or a static,
  `Fish.write()` or `SETTINGS.get()`, records the name, and so does `other`, the receiver the conventions list for a
  value of the caller's own type.
- **A parameter, a field, a local or a chain of a named type.** A method call on a parameter, on a named field of
  `self`, on a local or on a chain records the type its declaration, initializer or return type names, or the path of
  calls that reaches one, else the name after a `.` or the empty receiver, as
  [ADR 3.55](/design-docs/adr/3.55-rust-parameter-receivers.md) decides.
- **A renamed type.** A receiver, the start of a path of calls or a return type spelled by a name a `use … as` binds to
  a capitalised item of the tree reads as that item: `ClapError::make()` after `use crate::error::Error as ClapError;`
  names `Error`. A file that declares a type of the item's name or holds an `impl` of the rename keeps the spelling, and
  so does a rename into code the tree does not hold, which binds nothing
  ([ADR 3.176](/design-docs/adr/3.176-rust-outside-type-calls.md)).
- **Macro invocations.** A macro invocation is a call of the macro, with no receiver.
- **Local calls and macro arguments.** [ADR 3.53](/design-docs/adr/3.53-rust-local-calls.md) decides the calls
  that bind a body's own item and the calls through a value, and
  [ADR 3.54](/design-docs/adr/3.54-rust-macro-arguments.md) the calls a macro's arguments
  write.

## Why

- A value's name alone reads as the module a path call names: a value named like an imported module bound through the
  import, tokio's `socket.connect()` taking nix's `connect`, and one named like an owner bound that owner's members, a
  value `str` taking the `len` of nix's `impl ... for str` (cargo registry of 488 crates, 2026-10-22, #249).
- A capitalised operand is an item the graph holds by that name, and `other` is the conventional name of a second value
  of the caller's own type.
- The owner tier finds a type by its own name, so a renamed type's calls bound nothing: wasmtime's `self.inner` under
  `SecondaryMap as Inner` among them. On six Rust trees the rule adds 61 pairs, removes 5 and moves 37: 30 of 30 sampled
  added, all 5 removed and 34 of the 37 moved are right (2026-10-31, #515).

## Consequences

- A call on a chain, a local or a field whose type ADR 3.55 does not keep names no type, and binds only a runtime method
  or by the tiers that need no receiver.
- A rename of a type whose methods come through `Deref` names a type that lacks them, and they fall to a lower tier:
  4 pairs of rust-analyzer's `InferenceTyLoweringContext as TyLoweringContext`, 3 right ones demoted and one that binds
  the caller's own method of the name. Accepted.
- In a file that renames a type to `Builder`, a path `settings::Builder` reads as the rename too, since a receiver keeps
  only its last segment. Accepted: no measured tree moves through this.
- A renamed type keeps one binding, and each file that holds one takes a pass over its calls.

## Rejected

- **Read every rename, whatever the file declares** — a wrapper renames the type it wraps, so the rename reads as the
  wrapper: tokio's `Driver::park` then called itself through `SignalDriver`, among 11 further pairs (2026-10-31).
- **Read the rename in the walk** — one file's bytes do not tell a crate of the tree from one outside it, so
  `use anyhow::Error as AnyError;` would bind the tree's `Error`.
- **Resolving a receiver through a `use` in the extraction** — `use crate::m::Worker; Worker::run()` would name
  `m::Worker` only by reading the files the path leads to, which one file's extraction does not have; the resolver
  binds the kept path instead
  ([ADR 3.50](/design-docs/adr/3.50-rust-cross-crate-paths.md)).

## Revisit if

One file's extraction sees what a `use` resolves to, so a receiver could name its module path. Not planned.
