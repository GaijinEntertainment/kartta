The members of `new class { ... }` sit in a class the source gives no name, and `$this->m()` inside it calls one of
them. Such a class becomes an unexported class named by the names that lead to it, which owns its members, so a call
through `$this` binds its own member, at under 2.3 KB of heap for each.

## Decision

- **The name.** An anonymous class is an unexported class symbol named by the names that lead to it joined by `·` in
  braces, which no PHP name holds. The names are the callable that creates it, then the variable or the property it is
  assigned to: `{testRun·job}` for `$job = new class {}` in `Suite::testRun`, and `{class}` where no name leads to it,
  as for a migration's `return new class extends Migration` at file scope. An instance or a static property of any
  class names it, `$o->job` and `Other::$job` alike; a name PHP computes, `self::$$job` or `$this->{JOB}`, does not.
- **A repeated name.** A name the file has given already takes a count, `{testRun·2}`.
- **Members, parents and creation.** Its members are owned by the name and qualified by it,
  `App\{testRun·job}::handle`. Its `extends`, `implements` and trait uses are its parents. Its creation is a call of
  it, as `new Foo()` calls `Foo`.
- **A variable that holds the class.** A call on a variable that holds an anonymous class records the class's name as
  its receiver, so `$job->handle()` binds the class's member. What a variable holds is
  [ADR 3.199](/design-docs/adr/3.199-php-variable-classes.md).

## Why

- With an owner, the caller's owner binds `$this->m()`, and a base the graph holds binds `$this->attach()` in a class
  extending `Mailable`.
- Without an owner, calls bound the anonymous method by proximity from outside the class: all 30 sampled on each of
  Laravel's framework and Symfony were wrong, a validator's `$v->passes()` among them (2026-10-23, #246).
- A name built from the callable and the variable stays put when lines are written above the class.
- The name reaches other files as the receiver of a call on a variable that holds the class, where a member the class
  inherits meets the same name in another file. With the callable in the name no such pair exists on Laravel's
  framework and Symfony (2026-10-31, #532), and the caller's owner tier prefers the caller's file
  ([ADR 3.41](/design-docs/adr/3.41-own-owner-receivers.md)), so the callable's owner adds nothing to the name but its
  bytes: the classes' and their members' names take 22% less, 621 KB down to 485 KB.

## Consequences

- The heap after a build holds under 2.3 KB more for each anonymous class, the name and its members' longer qualified
  names (Symfony, 2026-10-23, #246). Accepted.
- A qualified name repeats across files more often, as `{castUsing}` in one namespace's casts: 42 names over 115 files
  on the two trees, for 5 over 27 with the owner in the name. A lookup of such a name reports the others it passed over
  (2026-10-31, #532). Accepted.
- Every anonymous class stays a symbol with a name no source holds, so it takes its slot in a capped list. Accepted:
  no name a source holds binds as this one does, below.

## Rejected

- **A name by the line, `{class·12}`** — the name moves with every line written above it, and 199 of Symfony's 522
  such names occur in several files.
- **The name with the callable's owner, `{Suite·testRun·job}`** — binds the same pairs at 28% more name bytes.
- **The variable alone in braces, `{job}`** — all 10 pairs it adds are wrong and 7 of the 8 it removes are right: a call
  on `$middleware` holding `new class extends TrimStrings` binds another file's `{middleware}::handle` over the base's
  (Laravel and Symfony, 2026-10-31, #532).
- **The class owned by its variable, `$job`** — the receiver's owner tier reads that name in every file:
  `$client->request()` across Symfony binds a test's anonymous client. None of 30 sampled of the 4,256 pairs it adds is
  right, and 17 of 30 of the 2,164 it removes are (2026-10-31, #532).
- **The class named by its bare variable, `job`** — a word that also names methods and functions: `$prices->one()` and
  `Type::object()` bind the class. None of 30 sampled of the 171 pairs it adds is right (2026-10-31, #532).
- **Members owned, with no receiver for a variable that holds the class** — 55 true calls on such a variable bind
  nothing, and 32 bind by proximity.

## Revisit if

The tier binding through a receiver's owner stops reading a name of the walk's making in other files. A name the source
holds, or the variable alone, would then keep the classes apart, and the made-up symbol could go. Medium confidence: a
tree whose tests repeat one callable and one variable would show the false pair the callable keeps out here.
