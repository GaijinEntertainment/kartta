# Qualify Python by the module its path names

- **Status:** accepted
- **Date:** 2026-10-16
- **Initiative:** `03-code-graph`

A Python file declares no package: its module is its path, `pkg/service.py` being `pkg.service`, and an import names a
module by a dotted path that the interpreter looks up on `sys.path`, which no file of the repository states. ADR 3.1
makes Python a language of its own; this decides how `kartta-lang-python` qualifies what it extracts and which files an
import includes.

**The resolver qualifies every symbol by the module its path names.** The path with `/` turned to `.` and the `.py` or
`.pyi` extension dropped, in any case as the language claims it, is the module, and every qualified name starts with
it: `pkg.service.Service.greet`. A package's `pkg/__init__.py` is the module `pkg`, as the interpreter names it, and a
root `__init__.py` names no module. The extraction from the bytes keeps the names local, `Service.greet`, because a
cache shares it between every file with the same content, and two such files at two paths are two modules. A `.pyi`
stub names the module of the source it describes, so a stub and its source define the same names. An owner is the chain
of classes alone, `Service` or `A.Worker`, which a receiver spells; the graph joins the chain at `.`.

**A symbol is what another module can name.** A function, a method and a class are symbols; a function or a class nested
in a function is qualified by the module alone, a nested class keeping its own methods under its name, is no member of a
class around that function, and is local to the function's body, so a call of its name from another module or function
never reaches it. A variable is a symbol only when it is assigned to a bare name at module level: `a = b = 1` defines
`a`, and `a, b = 1, 2` defines nothing. In a class body, only an annotated attribute, `name: str = ""`, is a field,
because the annotation is what declares the fields of a dataclass or a pydantic model and an unannotated attribute is
commonly state. A decorated definition starts at its first decorator, which a reader takes as part of it. A name that
starts with `_` is not exported.

**A call names its target only where the syntax spells it.** A bare call records its name, and a member call its
attribute with the receiver: the name when the object is a name, as in `self.greet()`, and the empty receiver for
anything else, `items[0].close()` or `make().run()`, as ADR 3.2 decides for Go. A call belongs to the function around
it; a class opens no scope, so a call in a class body belongs to the function around the class, or to the module when
the class is at its top level, and one made before the file's first definition is dropped, because it has no symbol to
hold it. A call in a default argument, `def f(x=make()):`, belongs to `f`, though Python evaluates it in the scope
around the definition; the pattern is rare enough to accept the wrong scope. A bare call never reaches a method of the
caller's class, because Python reaches one only through `self` or `cls`.

**An import includes the files of the repository it names, and one that names none is recorded as written.** An `import`
or `from ... import` that includes a file is an include alone, as a C++ or TypeScript directive that resolves is, and a
`from __future__ import` or a module found nowhere, as one of the standard library is, is an import. A module is the
file `a/b.py` or the package `a/b/__init__.py`, and failing both its stub, `a/b.pyi` or `a/b/__init__.pyi`, which a
repository that ships only the types of a module holds; the probe takes the first of `a/b.py`, `a/b/__init__.py`,
`a/b.pyi` and `a/b/__init__.pyi` that exists, and the stub probe adds 3.7 ms to resolving the 1,149 Python files of a
game-engine tree, which hold no stub. An absolute module is probed from the repository root, then from each directory
around the importing file, nearest first, which finds a module under a `src` layout; with `app/db.py` and
`src/app/db.py` both present, `import app.db` from under `src/` takes the root one, a heuristic and not the
interpreter's search path. A relative module climbs one directory for each leading dot after the first and names nothing
above the root. A from-import also includes each name that is a submodule, which only a package can hold, so no name
below a plain module file is probed. A module found nowhere may be a namespace package, a directory without an
`__init__.py`: its names are probed under the same anchors, and the first anchor that holds one of them is the package,
so a portion under a later anchor is not merged. On the 1,149 Python files of a game-engine tree this adds 101 includes
and 2.9 ms to resolving them all. A name that is a symbol of the module includes nothing. `import a.b.c` includes the
module `a.b.c` alone, `a/b/c.py` or `a/b/c/__init__.py`, not the `__init__.py` files of `a` and `a.b` that the
interpreter runs on the way. A `__future__` import is a compiler directive and is never probed.

**A file is test, generated or entry code by Python's conventions.** A `test_*`, `*_test` or `conftest` file, or one
below a `test` or `tests` directory, is test code, and every symbol in it is, fixtures and helpers included; the rule is
a heuristic after pytest's naming conventions, and it does not read which files a pytest configuration collects. A
`*_pb2` or `*_pb2_grpc` file is protobuf output, and a `@generated` or `DO NOT EDIT` marker in the header — the comments
and a triple-quoted module docstring before the first statement, a plain, raw or unicode string, never a bytes or
formatted one, which an escaped quote does not close — marks other generated code, but only outside a backtick span,
where documentation of the convention quotes it. A free `def main` directly at module level is the entry point a script
runs under `if __name__ == "__main__":`.

**The fingerprint covers the walk and the grammar**, as ADR 3.4 settles for TypeScript.

## What it costs

On the Python trees this was built against, 1,480 files yield 31,846 symbols, 166,710 calls and 9,443 import
statements, which give 2,514 includes of files of the repository. On the 1,149 Python files of the game-engine tree,
7,515 statements give 2,096 includes and 5,694 imports. One thread on macOS extracts 1,216 of the files in 0.90 s.
Qualifying by the module costs one string per symbol in the resolver, which no cache shares.

## Considered Options

- **Qualifying in the extraction** — the module would depend on the path, and a cache could not share the extraction
  of two files with the same content.
- **Reading `sys.path` from the repository's configuration** — `pyproject.toml`, `setup.cfg` and a `src` layout each
  spell the import roots differently, and the probe from the root and the directories around a file reads none of
  them.
- **Every assignment as a variable** — tuple targets and class state would add symbols that nothing imports by name.
- **Including the `__init__.py` of every package on an import's path** — an edge per level for code the import only
  runs, not code it names.

Revisit when an import root that the probe misses, or a root-first match that is wrong, shows up on a real tree.
