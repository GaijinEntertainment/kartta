# Own a Go anonymous struct's fields by the field or the variable it types

- **Date:** 2026-10-24
- **Governs:** `crates/kartta-lang-go/src/walk/anonymous.rs`, `crates/kartta-lang-go/src/walk/types.rs`,
  `crates/kartta-graph/src/typed.rs` (a path's first name, its `{N}` and the members of an owner)
- **Pinned by:** `crates/kartta-lang-go/tests/extract.rs`
  (`a_field_of_an_anonymous_struct_a_field_declares_is_owned_by_that_field`,
  `a_literal_assigned_to_a_name_declares_its_anonymous_struct_s_fields`,
  `a_name_a_short_declaration_assigns_again_owns_no_second_struct`,
  `an_anonymous_struct_without_a_field_takes_no_name`),
  `crates/kartta-graph/tests/graph/typed.rs`

  `a_body_s_values_of_one_name_own_the_fields_their_lines_hold_and_the_types_their_structs_embed`),
  `crates/kartta-languages/tests/go_anonymous_struct.rs`

A field typed `struct{...}`, a variable declared with one and a test table's literal hold fields no named type stands
for, and `s.Limits.MaxConns`, `settings.Timeout` and `tt.name` reach them through a type path
([ADR 3.60](/design-docs/adr/3.60-go-data-sites.md)). The field or the variable the struct types owns those fields under
its own name, and its value names its own index in the file, so
[ADR 3.34](/design-docs/adr/3.34-field-and-value-uses.md)'s path tier binds them with no symbol whose name the source
does not hold.

## Decision

- **The owner.** A struct with a field that a field's type, a variable's declared type, or a literal that `:=` or `var`
  assigns to a name spells, behind pointers, `&`, parentheses and containers too, takes an owner: the field or the
  variable, the first that is not blank of its declaration. A `:=` name that declares such a value is a variable symbol
  of its body.
- **Field names.** Its fields are owned by the owner's name and qualified by the names that lead to them,
  `app.Server.Limits.MaxConns`; a value a body declares adds its callable, `app.TestRun.tests.name`, since a file's
  bodies often declare one name. The owner holds the types the struct embeds as its parents.
- **The struct in a path.** The owner's value spells the struct as `{N}`, N the owner's index among its file's symbols,
  behind containers as any type: `[]{4}`. A literal's keys, or its elements in their places, write the fields.
- **Structs with no owner.** `struct{}` and a struct with no field take no owner, nor does a literal assigned to no
  name, an argument or a returned value, nor one a `:=` assigns to a name its block declares already. Such a literal's
  keys and elements record nothing.
- **A path's first name.** The graph reads a path's first name up to a `.`, `(` or `[`. A `{N}` is read as below; any
  other name is found among the file's import bindings, then its package's declarations, then a dot import's, then the
  types of the file's bodies by name.
- **Reading `{N}`.** The graph reads a path's first name `{N}` as symbol N of the path's file, the file every path is
  read in. An owner's member is the field of the name it owns inside its own lines, else one its parents promote. A
  type's member is one qualified by the type, so a field an owner of the type's name owns is not the type's.

## Why

- Giving an anonymous struct's fields an owner made the uses of their names that counted as ambiguous fall from 13,025
  to 2,197 on the Go monorepo snapshot, and every sampled site that moved binds the field the source reads
  (2026-10-23, #189).
- A named struct put a name no source file holds into answers and capped lists: 438 of 3,513 `find_symbols` answers
  on the Go monorepo snapshot listed one, and none does now (2026-10-24, #427).
- The heap after a build of the snapshot holds 0.25 MB less, with 5,393 structs gone and 1,518 `:=` names become
  symbols (2026-10-24, #427).
- An index is unique in its file with no count, whatever the owner's name or length, and costs a path a few bytes; the
  owner's lines tell apart two values of one name in one body, which share their owner's name and qualified names.
- Every use the named structs bound stays bound, and each of the 16,341 that bound a namesake field of a sibling
  file's table, as `zerrors_linux_arm.go`'s `errorList` took `zerrors_aix_ppc.go`'s, binds the field its own file
  declares (2026-10-24, #427).

## Consequences

- A `:=` name that owns a struct is a symbol, so `find_symbols` and outlines list it where they list no other `:=`
  name: 1,518 on the snapshot. Accepted.
- An anonymous struct that embeds an interface implements nothing in `find_implementations`, since its owner is no
  type. Accepted.
- A literal assigned to no name, about 200 structs on the snapshot, or a parameter of an anonymous struct, records the
  empty path, and its member uses count as ambiguous or take the file's one field. Accepted.
- A type defined over another struct type records no fields, so a use through it finds no field there
  ([ADR 3.29](/design-docs/adr/3.29-go-receiver-types.md)). Accepted.

## Rejected

- **A struct symbol named by the names that lead to it, `{Server·Limits}`** — 5,393 names no source holds, in answers
  and in capped lists.
- **The owner found by its scope's name instead of its index** — two structs of one scope in one file, 71 on the
  snapshot, then need a count no source holds.
- **The fields owned by `Server.Limits` with no path, left to the file's one field** — binds a sixth of the sites,
  since a file then holds two fields of the name.
- **Owners only for fields and package-level variables, not a body's values** — binds a sixth of the sites, since a
  test table holds most.

## Revisit if

A path is read outside the file that spells it, which would make an index name another file's symbol. Not planned.
