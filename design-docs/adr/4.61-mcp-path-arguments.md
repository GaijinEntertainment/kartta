# Read an MCP path argument from the index, and answer a miss with its fault and the paths near it

- **Date:** 2026-11-03
- **Governs:** `crates/kartta-mcp/src/paths.rs`, `crates/kartta-mcp/src/render.rs`,
  `crates/kartta-mcp/src/render/files.rs`, `crates/kartta-mcp/src/server.rs`
- **Pinned by:** `crates/kartta-mcp/tests/paths.rs`, `crates/kartta-mcp/tests/stdio.rs`
  (`an_empty_file_answer_names_the_globs_that_name_a_directory`,
  `a_listed_answer_and_a_name_below_the_root_name_the_glob_that_names_a_directory`,
  `a_glob_of_several_names_names_the_directories_whose_path_it_ends`, `list_dir_counts_what_it_did_not_enter`,
  `a_list_dir_exclude_excludes_a_held_directory_whatever_its_name_holds`)

Agents pass paths spelled for their host, and a miss that reads as a valid call over nothing sends them to retry the
same mistake. Every MCP path argument is read from the index root, and a path or prefix the index does not hold is a
wrong call that names the spelling's fault and the held paths near it, at one pass over the index's paths and a lookup
per edit of a name per miss.

## Decision

- **Path arguments.** A file, a directory, a region's file, `from` and every `path_prefix` are read from the root with
  `/` between names, a leading `./` dropped. A path the index does not hold, or a prefix that starts no held path, is a
  wrong call: its error names the spelling's fault, absolute, a drive such as `C:`, a `\` between names or a `..` name,
  by the `kartta_fs::PathFault` a refresh refuses ([ADR 1.16](/design-docs/adr/1.16-scoped-refresh.md)), or else that
  nothing is indexed there, and lists up to 5 held paths near it: the path its names spell with `\` read as `/`, the
  deepest held directory they lead to, its entries one edit from the next name, as
  [ADR 3.131](/design-docs/adr/3.131-missed-name-suggestions.md) edits a missed symbol name, for a name of 3 characters
  or more, and its entries that start as the next name does, then the entries anywhere named as its last name is. A held
  name that holds a `\` answers as any other. A held file outside every graph gets a count of zero and a note naming
  why: it is a symlink, it is a socket, a fifo or a device node, whose note names no graph and asks for no read, a
  language leaves it out for the reason it states, a language `index_root`'s `languages` filter left out claims it,
  whose note names the language and the filter, no language kartta ships claims it, or the graph that claims it holds no
  record of it; a language the filter left out is asked as a built one is. A symlink's note names its target as stored
  and, where the target names a held entry as [ADR 4.69](/design-docs/adr/4.69-wire-file-query-graph.md) reads one, that
  path to pass instead for a file or a symlink, one of its files for a directory, and no path for a socket, a fifo or a
  device node; `impact_of_change` counts such regions, a symlink's in `symlink_regions`, and names each language that
  leaves their files out, with its reason, and each language the filter left out that claims them, in an `<unbuilt>`
  record apart from `unclaimed_regions`. A diff's paths are git's and go unchecked: a file the index lacks counts in
  `unheld_regions` and `missing_regions`. `refresh` takes paths the index does not hold yet
  ([ADR 4.44](/design-docs/adr/4.44-mcp-refresh-tool.md)).
- **Globs and names.** A glob selects files alone, and one that holds no `* ? [ ] { }` nor `\` names one path from the
  root, a trailing `/` dropped. Every `glob_files`, `grep` or `find_files` answer, a listed one included, names each of
  its `globs` or `includes` whose path is a held directory, or is a path the index does not hold whose names end the
  paths of directories below the root, with the glob that selects what they hold: `<dir>/**` for one directory,
  `**/<names>/**` and their count for more. A `list_dir` exclude is a name matched literally at any depth, `pkg/deep`
  included, and one that names a held directory matches it whatever its name holds; one that holds `* ? [ ] { }` or a
  `\` and names no held directory is a wrong call that names the character.

## Why

- A missed path answered a zero count with a note of three causes, a `path_prefix` or a `from` that held nothing
  answered as if it selected nothing, and `list_dir` alone answered an error, so an agent passing a Windows spelling, a
  `..` path or a misplaced file retried another spelling of the same mistake (#684, #1040). A hit pays one index
  lookup per path, and a miss one pass over the index's paths: 98 ms on the 4.14M files of the macOS data volume
  (2026-11-03).
- A typo in the first three characters of a name, `mian.rs` for `main.rs`, named nothing near, while a symbol name with
  the same fault got the definitions one edit from it (#1308). Each edit is one index lookup, so a 256-character name,
  the longest edited, took a miss from 5 ms to 15 ms on dagor's 171k files and holds no more memory (2026-11-27). One
  edit of a shorter name than 3 characters makes every short name beside it near, and crowds out a misplaced file.
- A directory passed as a glob selected nothing while an exclude of the same text dropped it, and `grep` sent the agent
  to `glob_files`, which answered only that no file matched; a `list_dir` exclude of `**/deep` excluded nothing,
  silently (#1040). A name below the root, `deep` for `pkg/deep`, and a directory beside a glob that matched files
  went unnamed too (#1159), and so did names of several, `kartta-mcp/src` for `crates/kartta-mcp/src` (#1181). The
  hint costs one index lookup per such glob, and a path the index does not hold one pass over the index's directories,
  whatever its count of names: 48 ms on the 9.02M files of the macOS data volume (2026-11-06).
- A directory's name may hold a glob character, so refusing one before the lookup left such a directory no exclude
  (#1160). A `\` that names no held directory matched nothing on any platform, and on Windows it is every `\`: globset
  turns each `\` of a candidate path into `/` before it matches (globset 0.4.21 `src/pathutil.rs:66-77`, called from
  `Candidate::from_cow` at `src/lib.rs:645`). The lookup costs at most one pass over the index's paths per call, for
  every exclude that holds such a character, and none when no exclude does.
- After a build that filtered languages, a file of a language left out answered that no indexed language claims it,
  true and silent on the filter, so an agent could not tell a language left out from one kartta does not ship (#1041).
  Asking the shipped languages costs a claim check per language, only for a file or region no built language takes.

## Consequences

- A file made since the index last read the tree, while the watch is off, is a wrong call to the file tools until a
  `refresh` takes it in. Accepted.

## Rejected

- **A missed path as a zero-count envelope with a note** — it reads as a valid call over nothing, which
  [ADR 4.1](/design-docs/adr/4.1-mcp-server-tools.md)'s answers rule keeps for a call that is right.
- **A fuzzy search for the near paths** — a pattern of common names matches most of a large tree: 1.2 s for one miss
  on the data volume.
- **A set of the names one edit from the asked one, matched against the directory's entries** — the same answers, and
  18 MB held at once for a 256-character name.
- **Refusing a `\` before the lookup, as `refresh` does** — costs these tools a held file whose name holds a `\`, legal
  outside Windows.
- **`includes` taking a directory, as `excludes` does** — changes the dialect of
  [ADR 1.4](/design-docs/adr/1.4-query-glob-dialect.md), where a glob names files.
- **A `list_dir` exclude read as a glob** — a second dialect inside one parameter; refusing `/` instead removes
  `pkg/deep`, which works.
- **Refusing every `list_dir` exclude that holds a glob character** — leaves a held directory named so no exclude.

## Revisit if

A tree where one pass over the index's paths makes a miss pass 500 ms. High confidence: 98 ms on 4.14M files.
