# Cut one 1.0.0 of every artifact for macOS, Linux and Windows

- **Date:** 2026-10-31
- **Governs:** `.github/workflows/`, `Cargo.toml` (`workspace.package.version`), `scripts/version.sh`,
  `crates/kartta-ffi`, `crates/kartta-mcp`, `bindings/go`, `bindings/node`
- **Pinned by:** `scripts/version.sh --check`, in the `versions` job of `.github/workflows/ci.yml`
- **Implementation:** pending — nothing is released, and the channels do not cover the support matrix yet (#138, #144)

kartta has no released version, and packaging, CI and the docs each depend on what the first release covers. 1.0 is one
cut of every artifact for one support matrix, with every surface settled; the trade is that a defect in any channel,
on any target, holds back all of them, and that language-engine defects of lower weight ship.

## Decision

- **Consumers.** 1.0 serves two consumers: the MCP server, for anyone who runs an agentic workload through MCP, and the
  C ABI, which dedicated tools integrate. Their surfaces freeze at the cut, so an open decision on either one blocks
  1.0.
- **Artifacts.** 1.0 ships the crates on crates.io, the static library with `kartta.h`, the Go module `bindings/go`, and
  the npm package `kartta` with its platform packages. The MCP server ships as its crate alone, which a user builds with
  `cargo install --locked kartta-mcp`. The static library is `libkartta_ffi.a`, and `kartta_ffi.lib` on Windows with
  MSVC ([ADR 4.55](/design-docs/adr/4.55-release-workflow.md)).
- **Signing.** No artifact is signed or notarized on any platform. The static library ships on the GitHub release page.
- **One version.** The release is cut once, as `1.0.0`, in lockstep for every published artifact, the Rust crates
  included, when the work is ready. `scripts/version.sh` lists each site that repeats the version, one line per site,
  and sets them all in one step; CI fails when one differs from the workspace version. The Go module has no such site:
  its version is its tag.
- **Support matrix.** Every channel supports the same targets. A target outside them gets no artifact.
  - macOS on arm64.
  - Linux on x64 and arm64, each with glibc, from 2.28 ([ADR 4.55](/design-docs/adr/4.55-release-workflow.md)), and with
    musl.
  - Windows on x64, with MSVC. The Go module alone links a `x86_64-pc-windows-gnu` archive, because MinGW-w64, the
    linker cgo uses on Windows, refuses the MSVC one ([ADR 4.60](/design-docs/adr/4.60-go-windows-link.md)).
- **What blocks the cut.** The `v1.0` milestone holds the release work, every issue that needs a human, and each open
  decision or defect on the surfaces of the MCP server, the C ABI and the bindings or in a mechanic a consumer meets. Of
  the language engine it holds only what the board weighs Blocker. Every other issue takes the `v1.x` milestone, stays
  off organization project 1, and ships open.

## Why

- The maintainer set the consumers, the artifacts, the version and the platforms on 2026-10-22 (#120), and what blocks
  the cut on 2026-11-02: the language engine already serves as the baseline, so its other issues improve on it.
- The maintainer chose no signing on 2026-11-02 (#1057), and the MCP server as its crate alone, because GitHub Actions
  gives no secure way to sign and publish a binary of it.
- The backlog gave the cut no date: 291 issues of the milestone closed while each unit filed more, and 187 stayed open.
- Each architecture follows a runner CI can test on, so the matrix promises only what a check can hold.

## Consequences

- A crate at `1.0.0` that takes or returns third-party types follows that dependency's majors until #124 settles them.
- A macOS x64 or a Windows arm64 host gets no artifact. Accepted.
- A user of the MCP server builds it, with a Rust toolchain at the workspace's `rust-version` or newer and a C compiler
  for the grammars: a cold `cargo install --locked` takes 47 s at 4 jobs on macOS arm64 (2026-11-03). The README's
  install step waits on #1035.
- The defects in `v1.x` ship in 1.0, those the board weighed Major included: a false or missing edge costs an agent one
  read or leaves it blind on that shape. Accepted.
- The cut does not wait for Kensai's migration, so the wire freezes with no real consumer on it, and a shape mistake the
  migration finds costs a major version (#143). Accepted.

## Rejected

- **No issue open at the cut** — the count did not fall as units closed issues, so the cut had no date (2026-11-01).
- **The language engine's Major defects, and any of 1,000 sites or more, in `v1.0`** — the maintainer counts them as
  improvements on the baseline (2026-11-02).
- **`1.0` for the MCP server, the C ABI and the bindings, with the library crates at `0.x`** — the maintainer chose one
  cut for every artifact (#120).
- **A first release at `0.1.0`** — the release is cut as 1.0 when it is ready (#120).
- **Windows for the Rust crates only** — every channel supports the same targets, the Go and Node bindings included
  (#120).
- **macOS x64 and Windows arm64** — CI has no runner to test them (#120).
- **A Developer ID and a Windows certificate** — the maintainer chose no signing (#1057).
- **`kartta-mcp` binaries on the release page** — GitHub Actions gives no secure way to sign and publish them.

## Revisit if

CI gains a runner for a target outside the matrix, or a consumer needs one, or GitHub Actions gains a secure way to sign
and publish a binary. High confidence in the channels and the
single version; medium in the architectures, which follow today's runners.
