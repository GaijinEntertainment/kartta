# Cut one 1.0.0 of every artifact for macOS, Linux and Windows

- **Date:** 2026-10-31
- **Governs:** `.github/workflows/`, `Cargo.toml` (`workspace.package.version`), `crates/kartta-ffi`,
  `crates/kartta-mcp`, `bindings/go`, `bindings/node`
- **Implementation:** pending — nothing is released, and the channels do not cover the support matrix yet (#132, #135,
  #138, #144, #345, #346)

kartta has no released version, and packaging, CI and the docs each depend on what the first release covers. 1.0 is one
cut of every artifact for one support matrix, with every surface fully functional; the trade is that a defect in any
channel, on any target, holds back all of them.

## Decision

- **Consumers.** 1.0 serves two consumers: the MCP server, for anyone who runs an agentic workload through MCP, and the
  C ABI, which dedicated tools integrate. Every surface is fully functional at the cut, so an answer-quality defect in
  either one blocks 1.0.
- **Artifacts.** 1.0 ships the crates on crates.io, the `kartta-mcp` binaries, `libkartta_ffi.a` with `kartta.h`, the
  Go module `bindings/go`, and the npm package `kartta` with its platform packages.
- **One version.** The release is cut once, as `1.0.0`, in lockstep for every published artifact, the Rust crates
  included, when the work is ready.
- **Support matrix.** Every channel supports the same targets. A target outside them gets no artifact.
  - macOS on arm64.
  - Linux on x64 and arm64, each with glibc and with musl.
  - Windows on x64, with MSVC.
- **Open issues.** No issue stays open at the cut: the backlog closes before 1.0, and no item moves to a later
  milestone.

## Why

- The maintainer set the consumers, the artifacts, the version and the platforms on 2026-10-22 (#120), and the open
  issues on 2026-10-24.
- Each architecture follows a runner CI can test on, so the matrix promises only what a check can hold.

## Consequences

- The channels fall short of the matrix: the Go binding and the Node addon are not tested on Windows (#345, #346), the
  npm packages for musl are missing (#132), and the C ABI and the Go binding are not tested on musl (#135).
- A crate at `1.0.0` that takes or returns third-party types follows that dependency's majors until #124 settles them.
- A macOS x64 or a Windows arm64 host gets no artifact. Accepted.

## Rejected

- **`1.0` for the MCP server, the C ABI and the bindings, with the library crates at `0.x`** — the maintainer chose one
  cut for every artifact (#120).
- **A first release at `0.1.0`** — the release is cut as 1.0 when it is ready (#120).
- **Windows for the Rust crates only** — every channel supports the same targets, the Go and Node bindings included
  (#120).
- **macOS x64 and Windows arm64** — CI has no runner to test them (#120).

## Revisit if

CI gains a runner for a target outside the matrix, or a consumer needs one. High confidence in the channels and the
single version; medium in the architectures, which follow today's runners.
