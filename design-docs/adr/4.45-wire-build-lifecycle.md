# Drop a handle's engine before its next build walks, and keep what a cancel leaves

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-ffi/src/handle.rs` (`Kartta::build`, `Kartta::built`, `Kartta::on_index`),
  `crates/kartta-ffi/src/built.rs` (`Held`, `StoppedBuild`), `crates/kartta-fs/src/index.rs` (`Stopped`)
- **Pinned by:** `crates/kartta-ffi/tests/dispatch.rs` (`a_query_before_any_build_answers_not_built`,
  `a_build_cancelled_before_its_walk_reached_an_entry_leaves_nothing_behind`,
  `a_build_that_fails_leaves_the_file_queries_not_built`,
  `a_query_racing_a_build_to_its_end_never_answers_not_built`), `crates/kartta-ffi/src/handle.rs` tests,
  `crates/kartta-fs/tests/content.rs` (`a_cancelled_build_hands_back_the_index_of_what_its_walk_reached`)

A handle of the C ABI ([ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md)) holds one engine, and a `build` replaces it. The
build drops the old engine from the handle before it walks, so the handle never holds two, though a query already
running keeps the old one until it returns. A build a cancel stops leaves the index it holds, which the file queries
answer from and name; the trade is a cut index that can lack what a caller looks for.

## Decision

- **Open walks nothing.** `open` names the tree and walks nothing.
- **A build replaces the engine.** `build` walks the tree once and builds the index, the optional content index and
  every graph ([ADR 3.6](/design-docs/adr/3.6-graph-build-pass.md)), replacing what an earlier build made. It drops the
  old engine before it walks, so a handle never holds two, and a query already running keeps the engine it asked until
  it returns.
- **Queries and builds.** Queries run concurrently with each other and with `cancel`. Builds run one at a time: a build
  empties the slot when its turn comes, so a query answers `building` while a build runs, whether or not another waits
  behind it, and answers from the last build's engine until the next build's turn comes. A query that finds no engine
  looks again under the lock a build publishes under, so a build finishing beside it never reads as `not_built`.
- **A build a cancel stops.** It leaves the index of what it reached, until the next build's turn comes: the entries its
  walk reached, no content index, when the cancel landed in the walk; the whole tree, and the content index when the
  build finished one, when it landed past the walk. `glob`, `list`, `fuzzy`, `grep` and `stats` answer from that index,
  each with `stopped_build`, the entries it holds and the entries the walk listed and turned away. `stats` holds no
  language and no graph.
- **What it cannot answer.** A graph query and a `refresh` answer `not_built`, and that message and the build's own
  `build_cancelled` say what still answers and how much it holds. A `list` of a path a cut index lacks answers
  `not_found` and says the tree may hold it. The index follows nothing.
- **A build that leaves nothing.** A build cancelled before its walk reached an entry and a build that fails leave
  nothing, so every query answers `not_built`, or `building` while a later build runs, until a build finishes. A cancel
  that comes after the last file resolved stops nothing: the build answers `build_cancelled`
  ([ADR 4.30](/design-docs/adr/4.30-wire-cancellation.md)) and leaves its engine.

## Why

- Keeping the old engine until the new one is built holds two engines at the build's peak.
- A consumer cancels a build at its own deadline, and on a first build holds nothing older to fall back on, so a review
  whose build ran out of time had no tool left at all (#1028). Its file tools work from any index, and a partial one
  that says so beats none.
- Extraction runs on the walk's threads, so a deadline can land in the walk, and the walk's tree is in memory when it
  does: a cancel 25 s into the macOS data volume answered in 330 to 390 ms with 3.6M to 5.3M entries held, at 2 threads
  (2026-11-02). No finished build pays for any of this.

## Consequences

- A cut index holds whichever entries the walk's threads reached, which depends on scheduling, so two stopped builds of
  one tree answer differently. `unvisited` is a floor: a directory among them hides what it holds. Accepted: every
  answer says so.
- A stopped build holds its index until the next build's turn or the handle's free, and a file query in flight holds it
  to the query's end, at what a finished index costs per entry. It lays the index out while its extractions are still
  held: about 100 MB more at the peak of a cancel 60 s into the data volume with 0.93M entries held. Accepted.
- A panic in a build and a `build_failed` leave no index, a resolver's panic past the walk included: no such failure is
  known (#1117).

## Rejected

- **Keep the old engine until the new one is built** — two engines at the build's peak, and nothing to keep on a first
  build, which is where a deadline lands.
- **Keep only the old index through a build** — two indexes at the walk's peak, and nothing on a first build.
- **`not_built` after a cancel in the walk, an index only past it** — the walk reads and extracts every file, so it is
  where a deadline lands, and that consumer stays with no tool.
- **Finish the walk without reads once a cancel lands** — a whole tree, at up to the 33 to 49 s a walk of the data
  volume takes at 2 threads, on a cancel a close joins.
- **`stats` answers `not_built` too** — it is the call that says what the handle holds, and the only one that lists the
  failures the walk collected.

## Revisit if

A consumer needs the graph queries to answer through a cancelled build, or a cut index misleads one in spite of
`stopped_build`. Medium confidence: no consumer has run against it yet.
