# Place a Ruby file in the library above its outermost `lib` or source root

- **Date:** 2026-10-25
- **Governs:** `crates/kartta-lang-ruby/src/resolve.rs` (`library`)
- **Pinned by:** `crates/kartta-lang-ruby/tests/ruby.rs`
  (`a_file_under_lib_belongs_to_the_library_its_outermost_lib_roots`,
  `a_file_under_no_lib_belongs_to_the_library_above_its_outermost_source_root`)

A tree that vendors Ruby code copies whole libraries side by side, as Homebrew keeps six copies of Ruby's standard
library, and a monorepo of gems keeps a test double of one gem's owner in another gem's tests, as Rails does, so a call
on an owner reaches every copy of that owner. The resolver places a file in the library its path names, so the owner of
the caller's own library binds first, at the cost of no package for a file whose path names none.

## Decision

- **Library.** A file whose directory holds a `lib` component belongs to the library that the directory above its
  outermost `lib` roots, as its package: `vendor/ruby/3.4` for `vendor/ruby/3.4/lib/ruby/3.4.0/set.rb`, and for a gem
  that copy bundles, `vendor/ruby/3.4/lib/ruby/gems/3.4.0/gems/rake-13.3.1/lib/rake.rb`, too. A `lib` at the root is the
  library of the empty path. The component matches `lib` exactly, so `Library` and `library` root none.
- **Source roots.** A file under no `lib` whose directory holds a `test`, `spec` or `app` component belongs to the
  library above the outermost of them: `railties` for `railties/test/application/routing_test.rb`, and the empty path
  for `spec/models/user_spec.rb`. A `lib` wins wherever it sits, so `gems/rake/test/lib/helper.rb` belongs to
  `gems/rake/test`.
- **No library.** A file under none of these, a tool's own code or Homebrew's, has no package.
- **What it moves.** The package decides only where tier 5 of
  [ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md) takes an owner's member outside the caller's directory;
  Ruby reads no dependency list, so no call is kept from a package.

## Why

- A library keeps its code under `lib`, and a vendored copy keeps its own bundled gems under its own `lib`, so the
  outermost one names the copy: once a call on a constant names its class (#465), the owner tier bound 11,402 pairs
  on Homebrew's library to another copy's method, and 3,013 with these packages (2026-10-25).
- A package is kartta's concept, and Ruby's loader holds none: `require` searches `$LOAD_PATH` (`load.c:1063`), and a
  gem's default require path is `lib` (`lib/rubygems/specification.rb:150`), which a suite widens with `test` by its
  Rakefile. `test`, `spec` and `app` are the roots the resolver already searches for a `require`, and they sit beside a
  gem's `lib`, so they name the same library: on Rails, 117 pairs move off another gem's test double or a namesake,
  109 of them to the copy the caller runs with (2026-11-01).

## Consequences

- A call from a file under no `lib`, as Homebrew's own code, into a library copied twice takes the first copy in path
  order: 615 distinct caller and name pairs on Homebrew, among its copies of Ruby. No package separates them. Accepted.
- A vendored file under neither, Homebrew's `vendor/portable-ruby/4.0.9/.brew/portable-ruby.rb`, has no package, so it
  takes the first copy too. Accepted.
- A library file whose own gem holds an owner only as a test double binds the double, as `actionpack/lib` binds
  `Rails.root` of `actionpack/test/abstract_unit.rb`: 8 pairs on Rails, each of which bound another gem's double before.

## Rejected

- **No package for Ruby files** — the 11,402 pairs above bind another copy's method.
- **One package for every file under no `lib`** — it moves no pair on Homebrew, Rails or RuboCop: a test in one gem and
  a test in another stay together, and Homebrew's ties run between copies that all sit under `lib` (2026-11-01).

## Revisit if

The resolver reads a `Gemfile`, a `.gemspec` or the load path, so a library can be named by the gem that declares it.
Not planned.
