# Bind a Rust call by name only within the crates its crate is built with

A Rust crate reaches only the code of the crates it is built with, and its manifests say which, while the walk
records no `use` of a crate outside the tree. A call that no import or path places binds another crate's definition
only where the caller's crate is built with that crate, at the cost of the calls that reach a crate through a feature
the caller's manifest does not name.

## Decision

- **Built with.** The Rust resolver hands every file of a package the manifests of the packages it is built with: each
  package the tree holds of every name its dependency tables list, of every kind and target, renamed by a `package`
  key, its own or that of the entry it inherits from its nearest workspace's `[workspace.dependencies]`, `-` read as
  `_`; then, however deep, each package those list under `[dependencies]` that is not `optional`. The versions of one
  crate side by side in a cargo registry are all of its name. The manifest syntax read is
  [ADR 3.50](/design-docs/adr/3.50-rust-cross-crate-paths.md)'s, with an inline
  table on its key's line and a dependency's own `[dependencies.<name>]` table read as well. The graph keeps each
  package's list once, as the last of its files to arrive brought it.
- **What it gates.** Where the caller's file carries that list, the tiers that bind by name, the owner tier of
  [ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md) and the tiers
  of [ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md), take
  a definition of another package only from one of them and only outside its test code. A definition of no package
  and one of the caller's own package pass. An import, a path, a dot import or a re-export binds wherever it lies.
- **What a turned-away name binds.** Where the gate turned a call target of the name away, the name is no project's
  own: the one callable of the name (60) and the code outside vendored code (15) bind nothing, and a call through an
  owner whose members of the name lie only outside the caller's reach binds nothing, as `Vec::new()` beside
  allocator-api2's `Vec` does. The type check of
  [ADR 3.176](/design-docs/adr/3.176-rust-outside-type-calls.md) counts only types and values the
  caller's package can reach.
- A file of no package, or one whose language reads no dependencies, is not gated.

## Why

- A crate's code can call only what it is built with, so a namesake elsewhere is a wrong edge. On the cargo
  registry the rule unbinds 18,613 pairs, 100% of 70 sampled wrong (2026-10-24); kartta-fs's `Config::default()` of
  `notify` took kartta-mcp's.
- A name a crate out of reach also defines is mostly the standard library's, `Ok`, `finish` or `Error::new`, so the
  one in reach is no likelier the callee than the one turned away.
- A dependency's optional dependencies come in only through a feature, and following them took web-sys to 141 of the
  registry's 496 packages, where its required ones take 39.

## Consequences

- A call into a crate an enabled feature brings in, an optional dependency of a dependency, binds by name nothing.
  Accepted: the caller's own optional dependencies are read.
- A package's dev- and build-dependencies count for every file of it, as the graph keeps one list per package, so a
  call outside its tests and build script still binds by name a crate only they are built with. Accepted: the rule
  keeps that pair from before rather than adding it.
- Of the 3,224 pairs the rule adds on the registry, mostly on lines whose old binding it removes, 20 of 40 sampled at
  85 are right (2026-10-24).
- A crate that pins one version of a dependency the registry holds in two can bind by name the other version's
  definition: 671 added pairs take web-sys 0.3.106's `::js_sys::Object::new()` to js-sys 0.3.104's (#623).
- A call through a standard type binds a reachable owner of the receiver's name, `Box::into_raw` binding
  futures-task's impl for `Box`: 4 of the 40 sampled (#622).
- A `pub(crate)` item of another crate still binds by name where that crate is reached, since the walk reads
  `pub(crate)` as exported (#621).
- The graph holds one sorted list of interned manifests per package, and a file stores nothing for it: the build's
  heap peak grows 0.5 MB, 0.2%, on the registry's 29,441 files (dhat, 2026-10-24).

## Rejected

- **Direct dependencies alone** — unbinds right calls through a re-export chain, kartta-mcp's `Selector::new`
  through `kartta`: 117 removed pairs at 85 on this repository (2026-10-24).
- **Following optional dependencies transitively** — reaches most of a registry through one crate, as above.
- **Each file interning its package's list as one joined string** — raised the heap peak 7.6 MB on the registry
  (dhat, 2026-10-24).
- **Binding no owner outside the caller's package by path order** — unbinds right calls into a dependency, kartta's
  `Symbol::new` of kartta-lang among them: 533 removed pairs at 85 on this repository (2026-10-24).
- **Keeping the one callable and the tree-wide step for a turned-away name** — of the 6,321 pairs they add at 60 on
  the registry, about three in four of a sample are right, `Ok` and `finish` binding a crate's own namesakes.

## Revisit if

The Rust walk records the crate each `use` brings in, so that a name's crate is read from the file rather than from
the manifests. Medium confidence; #236 covers the call paths.
