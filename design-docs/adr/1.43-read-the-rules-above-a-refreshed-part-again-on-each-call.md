A part that `Index::refresh_paths` (ADR 1.16) walks again sits below directories the call does not list, and their
`.gitignore` files decide what the part holds. A call reads those rules again, each directory once, and keeps nothing
between calls; it reads them on the calling thread until a directory answers as slowly as a network mount, then side by
side on the index's threads.

## Decision

- **What is read.** While ignore rules apply, each directory above a part that is on disk is asked for `.git` and
  `.gitignore` by name, two stats a directory, and a `.gitignore` it holds is read and parsed; a `.git` there starts a
repository, which drops the rules from above it, as a walk does. A walk learns which
  control files a directory holds from the listing it already made, and these directories were not listed.
- **Once a call, in tree order.** A call stats every part first, then works out the directories above the parts on disk
  in tree order, each once a call however many parts lie below it.
- **In turn, then side by side.** The calling thread reads the directories' rules one after another until one directory
  takes 200 µs or more, then hands the rest to the index's threads. Each directory's own layers join below its parent's
  in tree order, so every part gets the rules a read in turn gives it.
- **Not handed over.** The visitor is not handed those `.gitignore` files, which lie outside the parts.
- **Nothing kept.** Nothing is kept between calls: the index holds no rules.

## Why

- A kept rule for a `.gitignore` that changed without being named would hide files without a trace.
- Reading each directory once a call, rather than once a path, took a batch of 1,000 paths on the game-engine checkout
  from 53–121 ms to 15–19 ms (2026-10-15).
- On a network mount each ask is a round trip, so asking in turn paid every one: the rules above 100 spread files took
  630 ms in a process's first call over NFSv3 with 1 ms added to each round trip, and 17.8 ms read side by side
  (2026-10-22).
- A local directory answers in 7–39 µs and a network one in 0.4–5.6 ms, so a local call stays on the calling thread,
  where waking the threads costs more than the reads they would spread (2026-10-22).

## Consequences

- A call over a network mount still stats its parts one after another on the calling thread, most of such a call:
  593 of 608 ms on NFSv3 with 1 ms (#339).
- A local directory the cache does not hold can take past 200 µs and hand the rest to the threads (accepted).

## Rejected

- **Keep each directory's parsed rules between calls**, checked by the `.gitignore`'s stamp or the directory's — saves
  nothing on a process's first call and still asks every directory for a stamp; it won 0.7–11.8 ms on repeated paths or
  where a client answered stamps from its cache, lost on paths no call had read, at 152 KiB to 3.0 MiB held for the
  index's life on the game-engine checkout. On the mounts measured the stamp is no fresher than a read.
- **Take the parts' rules from the index's last walk** — the index keeps no rules, and keeping them costs as above.
- **Read every directory above the parts on the index's threads** — wakes the threads on a local call: one path took
  0.43–0.61 ms against 0.28–0.36 ms under a load average of 5–7.
- **Start a call's reads on the threads when the last call met a slow directory** — saves at most the one directory read
  in turn before the hand-off, at a state kept between calls that a process's first call never has.

## Revisit if

The parts' own stats are taken off the calling thread (#339), so that the rules become the larger share of a call over a
network mount and a kept rule may pay. Medium confidence.
