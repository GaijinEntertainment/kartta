# Bind a bare call through the scope that offers its name, then the nearest callable

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`resolve_by_tiers`, `resolve_by_name`, `resolve_outside_scope`,
  `bodies_values`, `imports_from_outside`), `crates/kartta-graph/src/scope.rs` (`resolve_by_proximity`),
  `kartta_lang::Conventions` (`own_members`, `inherited_members`)
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`

A call that its receiver or qualifier does not place, past tiers 2 to 5 of
[ADR 3.7](./3.7-resolve-calls-when-a-query-asks.md), names a definition by name alone. Tiers 1, 6 and 7 bind it where
the language's scope finds the name, then guess the one callable nearest the caller, at the confidence of a guess.

## Decision

Each tier binds at the confidence given, from `kartta_graph::confidence`:

- **Tier 1:** a local call binds the local its scope declares, at 80.
- **Tier 6, scope:** the caller's file (80); then, where a package is not a directory, a bare call of a name that an
  import of code the graph does not hold binds ends the cascade with nothing bound, as `useState()` with `useState`
  from `react` binds no project namesake; then its dot imports (95), a glob of a module's file (95, ADR 3.45), its
  package directory (75), the one file it includes that offers the name (70), and the re-export chains of those files
  (65). A file that offers the name on two owners, or two files that offer it, leave the call to the tiers below. Where
  a package is a directory, a bare call that these tiers do not bind binds nothing.
  [ADR 3.42](./3.42-read-transitive-includes-for-a-name-few-definitions-share.md) reads includes through the files
  they include. A PHP static call on a class outside the graph binds through these tiers but the caller's file alone,
  and binds nothing below them
  ([ADR 3.167](./3.167-bind-a-php-static-call-on-a-class-outside-the-graph-through-imports-alone.md)).
- **Tier 7:** where the call's shape admits a candidate at all, a member of the caller's own owner (80,
  [ADR 3.41](./3.41-bind-the-caller-s-own-owner-only-on-the-receivers-a-language-lists.md)), the one callable of the
  name (60), then the nearest of the caller's directory (50), its parent directory (30) and the code outside vendored
  code (15) that holds a callable of the name: its one callable binds, and several bind nothing. Where values are call
  targets, a variable or a constant local to a body counts among the callables of its name at each of these steps
  that would hold it, though it binds nothing, except against a macro invocation. These ADRs narrow what these tiers
  take:
  - [3.39](./3.39-bind-a-member-call-to-a-free-function-only-where-a-value-can-hold-one.md), a member call and a free
    function;
  - [3.40](./3.40-bind-a-runtime-method-s-call-only-to-a-member-that-scope-reaches.md), a runtime method;
  - [3.43](./3.43-guess-no-member-near-the-caller-for-a-c-plus-plus-call-on-a-value.md), a C++ call on a value;
  - [3.44](./3.44-bind-no-call-to-a-namespace-where-a-language-s-calls-name-none.md), a namespace;
  - [3.46](./3.46-bind-no-test-definition-by-name-for-a-call-from-outside-test-code.md), a test definition;
  - [3.42](./3.42-read-transitive-includes-for-a-name-few-definitions-share.md), a callable no include reaches;
  - [3.179](./3.179-bind-a-rust-call-by-name-only-within-the-crates-its-crate-is-built-with.md), a Rust definition of
    a crate the caller's crate is not built with, which also gates tier 6.

A dot import comes before the package directory for every call without a receiver. `own_members` and
`inherited_members` decide what a bare call inside a member reaches, as their doc comments in
`crates/kartta-lang/src/language.rs` state, and the vendored flag keeps vendored code out of the last proximity step.

## Why

- The scope tiers follow how the language's own scope finds a bare name, the file before its imports and its imports
  before its includes, and the nearness steps rank the guesses below every tier that scope decides.
- Go rejects a package that declares a name a dot import also brings in, so a dot import and the package meet only in a
  test package beside the one it tests, where the dot import is meant.
- A bare call of a name an import of outside code binds goes to that code, never to a project namesake.
- A body's value of the name says calls of that name may call values the graph does not follow: with the TS/JS
  locals left out of the count, 21 of 49 new guesses on the Go monorepo snapshot were right (2026-10-24).

## Consequences

- An unqualified C++ operator call binds by name, not through its argument types (#303).
- A callable whose name a body's value elsewhere shares binds by no guess at the step that holds that value, though
  the value is not what the call calls. Accepted.

## Rejected

- **A package index of every declared name** — took 51 MB on the Go monorepo of 119,888 Go files (2026-10-16), where
  the name index filtered by directory answers the same.

## Revisit if

A language's scope finds a bare name through a step these tiers do not model, or ranks its steps in another order.
Medium confidence, since each new language brings its own lookup.
