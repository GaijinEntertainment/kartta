# Bind a PHP static call on a class outside the graph through imports alone

- **Status:** accepted
- **Date:** 2026-10-24
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `kartta_lang::BareReceivers`, `crates/kartta-graph/src/resolve.rs` (`resolve_by_name`,
  `names_a_class_outside_the_graph`), `crates/kartta-lang-php/src/lib.rs` (`CONVENTIONS`)
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`
  (`a_bare_receiver_naming_no_class_of_the_graph_binds_through_includes_alone_where_it_names_a_class`),
  `crates/kartta-languages/tests/php_static_call.rs`

A PHP static call names its class, `Mockery::mock()`, and a class from a Composer package is one the graph does not
hold, so a method of that name in the tree belongs to another class. Such a call binds only through what the file
imports, which is how an alias, `use Model as Eloquent;`, reaches a class the graph holds; it binds nothing by its name
alone, at the cost of the inherited method an alias's class reaches from another file.

## Decision

- Where `Conventions::bare_receivers` is `BareReceivers::Classes`, as PHP's is, a receiver written as a bare name, of
  letters, digits and `_`, names a class, except for the scope keywords the language lists, compared without case:
  PHP lists `parent`, `self` and `static`. A PHP value is written `$value` and is no bare name.
- A call on such a name that no type of the graph is named, once the receiver's owner tier
  ([ADR 3.171](./3.171-bind-a-call-through-the-import-type-qualified-name-or-owner-it-is-written-on.md), tier 5)
  binds nothing, binds through the file's imports, its includes and the re-export chains of those alone
  ([ADR 3.172](./3.172-bind-a-bare-call-through-the-scope-that-offers-its-name-then-the-nearest-callable.md), tier 6).
  It binds no definition of the caller's own file, no member of the caller's own owner, and neither the one callable
  of the name nor the one nearest the caller (tier 7). The miss
  counts as not admitted, through a receiver.
- `BareReceivers::Any`, the default, reads a bare name as a value, a module or a type alike.

## Why

- A class the graph does not hold has no member in the graph, so a definition its name alone finds is a namesake:
  99.6% of the 1,184 caller-callee pairs the rule unbinds on Laravel and Symfony are wrong, `Mockery::mock()` binding a
  testing trait's `mock` among them (2026-10-24).
- PHP maps a `use` to the file of the class it names (ADR 3.14), so a call on an alias binds that class's file at the
  include tier, as no tier below it can.

## Consequences

- A call on an alias whose class inherits the method from another file, `Eloquent::withoutTimestampsOn()` on
  `Model as Eloquent` reaching a trait's method, loses its one-callable edge: 5 of the 1,184 unbound pairs. Open until
  the extraction reads the alias (#524).
- A static call on a class outside the graph still binds a namesake that an imported file defines, at the include tier
  (ADR 3.14). Accepted.
- A call through a scope keyword spelled otherwise than PHP spells it, or a receiver whose class is declared in
  another letter case, `str::of()` for `Str`, binds nothing. Accepted.

## Rejected

- **Also bind nothing through the file's imports** — 214 of the 287 further pairs it unbinds on Laravel and Symfony
  are calls on a `use … as` alias of a class the graph holds (2026-10-24).
- **Hold back only the one callable of the name** — keeps the namesakes the caller's file and directory hold, 53 wrong
  pairs on the same trees.

## Revisit if

The PHP extraction reads a `use … as` alias, so a receiver can be resolved to the class it names. Planned (#524).
