# Resolve implementors from the parents written when a query asks

- **Date:** 2026-10-17
- **Governs:** `crates/kartta-graph/src/implementations.rs`, `Graph::implementations`, `kartta_graph::is_parent`
- **Pinned by:** `crates/kartta-graph/tests/graph/implementations.rs`, `crates/kartta-graph/tests/graph/assertions.rs`,
  `crates/kartta-mcp/tests/graph.rs` (`find_unused_counts_a_method_another_file_of_its_package_asserts_as_dispatched`,
  `find_unused_lists_a_method_whose_namesake_type_in_another_package_is_asserted`,
  `find_unused_lists_a_method_whose_namesake_an_external_test_package_asserts`,
  `find_unused_lists_a_method_no_interface_declares_whatever_its_type_is_named`,
  `find_unused_lists_a_method_whose_namesake_embeds_a_type_outside_the_graph`)

A type keeps the parents its language records as written, and which type a parent names depends on the file that
writes it: its package, its imports, the namespaces around the type, its includes. Implementors are resolved from those
written parents when a query asks, as [ADR 3.7](/design-docs/adr/3.7-call-resolution.md) resolves calls, so no edge
goes stale; each query pays the lookups.

## Decision

- **What the graph keeps.** A slot keeps each of its types' parents as written, a C++ parent written from the root
  marked so, and the type name and the interface of each of its assertions as written. The graph lists each file under
  the last segment of every parent its types write and of every interface its assertions name, a file at a time. No
  slot keeps an edge to another slot.
- **What a query reads.** `implementations` reads the files listed under the bare name of the type it asks about, and
  keeps each of their types whose written parent names that type. Only a type or a namespace that records a parent is
  an implementor; a parent recorded on a function or a variable names nothing. Where a query counts several types of
  one name, as choosing the root does, it reads those files once for all of them, and each parent looks up the types of
  its name once for every counted type it names: counting N types of a name costs the name's parents times N.
- **Which type a parent names.** A parent names the type its language's scopes reach from the file that writes it,
  through the lookup of its language's shape:
  - **Directory package.** Where a package is a directory (`directory_packages`, Go), a bare parent names a type of its
    own directory and a qualified one a type of the directory its import binds. Nothing else is tried.
  - **Owner chain.** Where a language joins an owner chain (`owner_chain_separator`: Ruby, Python, Rust, TypeScript and
    JavaScript), the parent is looked up from the scope around the type that writes it, inside out, as the call queries
    look up a type's bases. A bare parent that lookup does not reach names nothing; a qualified one goes on to the
    nested-scope lookup and the nearest file. Where a module imports a name from the module that exports it
    (`ValueUses::Imported`: TypeScript, JavaScript, Python), the lookup reaches only the types of the writing file and
    of the files it imports, however deep, so a barrel's re-export counts.
  - **Nested scopes.** Where a language nests scopes (`scope_separator`, C++), the lookup runs from the scope around the
    type out to the root, and the innermost scope that holds a type of the parent's spelling decides. A parent written
    from the root names the type of that qualified name.
  - **Written from the root.** Where the extraction writes every parent in full (`ParentSpelling::FromRoot`, PHP), the
    parent names the type of exactly that qualified name, the nearest where copies share it, and no other: a parent the
    graph holds no such type for is outside the tree.
  - **Nearest file.** Elsewhere, and for a parent those lookups do not reach, the parent names the type of its name
    nearest the writing file: in that file, in the files it includes, in its directory, then anywhere, among the types
    whose qualified name ends with what a qualified parent spells. Types tied at the nearest of those each count the
    parent.

  A parent that reaches a type alias names the alias, which
  [ADR 3.130](/design-docs/adr/3.130-type-alias-parents.md) decides.
- **Assertions.** A Go assertion, `var _ io.Reader = (*File)(nil)`, is a statement its file makes of a type it need not
  declare, and stays one: it is no parent of the type, so nothing that walks parents for members reads it
  ([ADR 3.201](/design-docs/adr/3.201-go-embedded-selectors.md)). A query reads the interface from the asserting file as
  a parent that file writes. A bare type name the file itself declares names that type; any other is read the same way
  among the types of that name, and one that reaches several types, as an external test package that declares a namesake
  of its own package's type, or none, adds nothing. When `find_unused` asks what may dispatch a method, it reads every
  assertion the method's package writes of the owner's name, in the files of its directory under its package clause,
  beside the parents of the owner's types, of that package alone where a package is a directory. It reads each interface
  and each such parent from the file that writes it, through the lookup above;
  [ADR 3.23](/design-docs/adr/3.23-dead-code-judgment.md) states what each may declare. An assertion on a type qualified
  from another package is not read there. An assertion is recorded where each side spells a name, through parentheses
  and an instantiation (`doc/go_spec.html:810`): `pkg.I[T, U]` asserts `pkg.I`, and the value names its type as `T{}`,
  `&T{}`, `new(T)` or a conversion, `(*T)(x)`, `(T)(x)` or `T(x)` (`doc/go_spec.html:5410`). A call of one operand reads
  as a conversion, and a function's name then reaches no type, as no type of its package shares it
  (`doc/go_spec.html:2182`); a local function of a type's name reads as that type (#989). An interface literal (408
  sites on the Go monorepo snapshot), a value held in a variable (14) and a function's result (16) name nothing, all of
  them generated, vendored or test code there (2026-11-01). Each blank name reads the value at its position
  (`doc/go_spec.html:6230`), and a spec whose counts differ records nothing. A Rust impl of a type its file does not
  declare ([ADR 3.11](/design-docs/adr/3.11-rust-item-names.md)) reads each name from the file its path reaches, else
  from the one glob's module that declares it, else from the asserting file, among the non-member types of what the
  file's package is built with, and counts only where each reaches one type, an enum included.
- **The root.** A name selects among the kinds `is_parent` admits as `Graph::definitions` does, an enum among them,
  which no parent names; of several types the root is the one the most distinct types name as a direct parent, the
  first in path order on a tie; [`Graph::implementations`](/crates/kartta-graph/src/implementations.rs) states the
  selection, and `passed_over` counts the other types `definitions` lists for the name.
  [ADR 3.35](/design-docs/adr/3.35-shared-name-selection.md) gives the path prefix that reaches any copy and the
  `candidates` the answer lists.
- **The walk.** Implementors come a depth at a time, each type once, at the depth where it is nearest, in path order
  within a depth. Every implementor within the depth is found before the limit applies; the fields of
  [`Implementations`](/crates/kartta-graph/src/implementations.rs) count what the limit and the depth bound left out.

## Why

- A C++ base names a class type (C++ draft, `source/classes.tex:3493`) and a Rust impl a trait (Rust Reference,
  `src/items/implementations.md:94`). A lookup that reached enums credited an enum with impls of an outside trait of
  its name: all 3 pairs it added on this repository and the Go monorepo snapshot (2026-11-03, #724).
- A stored edge goes stale when any file its parent's resolution read changes: a package, an import, an include, a
  namespace anywhere in the family. That is the invalidation [ADR 3.7](/design-docs/adr/3.7-call-resolution.md)
  declined for calls.
- A parent is a name the writing file's scopes resolve, so the lookup follows those scopes. In C++ the namespace lookup
  took the one-deep implementors of the game-engine tree's 59,619 qualified type names from 23,537 to 21,610, by
  parents a tie had credited to every type of their name, as a `Visitor` written in namespace `SQCompilation` was to
  each of 100 types named `Visitor` (2026-10-17, #53).
- The lookups are cheap where they run: a one-deep C++ query took at worst 10.8 ms on the game-engine tree, and the
  parent listing with the assertions took 1.4 MB on each of that tree and the Go monorepo (2026-10-17, #53). Read once
  per counted type, they cost the square of the types a name shares: the root of 1,494 types named `Type` took 364 ms,
  and 1.1 ms read once (game-engine tree, 2026-10-24, #452).
- An assertion is often the only place Go writes that a type implements an interface it never embeds.
- An assertion declares a blank variable and no field: the compiler's member walk descends embedded fields alone
  (`cmd/compile/internal/types2/lookup.go:231`; `doc/go_spec.html`, Struct types). Read as a parent, one bound 28 calls
  on the Go monorepo to an interface's declaration past the method Go selects (2026-11-01, #907).
- A Go type name is scoped to its package (`doc/go_spec.html:2211`), a method to its receiver type's package
  (`doc/go_spec.html:3001`), and `go test` builds an `_test` package apart (`src/cmd/go/internal/test/test.go:72`), so
  all of a package's files speak of a type and no other package's bare name does. Read per type of the owner's bare
  name, assertions of namesakes kept 10 methods of the Go monorepo snapshot off the list, 10 of 10 unused by the source
  (2026-11-01, #940). Read by bare names with a namesake's parent counted, the interfaces and parents kept 50 more off,
  29 of 30 sampled unused (2026-11-01, #950).
- A TypeScript module's top-level type is qualified by its bare name, so the owner-chain lookup alone reached every
  namesake in the tree. Keeping the imported ones removed 14 of 57 one-deep TS/JS implementor pairs on the Go
  monorepo, the game-engine tree and a bug-tracker monorepo, all 14 crediting a namesake in an unrelated project, while
  each child kept the type it imports (2026-10-24, #453).

## Consequences

- Ties stay where a lookup cannot see what the compiler sees: 1,789 of 8,462 C++ implementors of shared names were
  credited to more than one type, mostly specializations of one template and nested types, which the extraction
  qualifies by their enclosing class alone (game-engine tree, 2026-10-17). Accepted.
- A TypeScript parent declared globally, in an ambient `.d.ts` or a script that no file imports, names nothing: no
  child in the 57 pairs lost its only parent (2026-10-24). Accepted.
- A type that implements an interface without naming it, as Go's structural typing allows, is not found (#1169).

## Rejected

- **An index of implementors keyed by the parent as written** — answers a string: on the Go monorepo it listed 4,680
  implementors of 104 types where the lookup lists 2,116, most of the rest implementing a namesake, and it misses
  parents written bare inside the type's own package or partly qualified.
- **Resolved edges stored at insert** — the invalidation [ADR 3.7](/design-docs/adr/3.7-call-resolution.md) declined
  for calls.
- **Credit a tied parent to no type** — the type the parent names loses it with the others: a fifth of the implementors
  that share a bare name on the game-engine tree.
- **Answer the union of every type the name selects** — mixes copies and unrelated namesakes into one list;
  `passed_over` and `candidates` name them, and a longer name or a path prefix reaches each.
- **Read the parents once per counted type, skipping a type the writing scope cannot reach** — still the square where
  the scopes reach many types of the name: 102 ms for the root of the 1,494 `Type`s.
- **Rank an imported parent's types by the nearest file, as elsewhere** — the same pairs on the three trees, but a
  child that imports none of the types is credited to every far namesake.
- **Direct implementors only** — three levels listed 22% more implementors on the game-engine tree for 26 to 41 µs more
  at the median.
- **Keep an assertion in the parents, marked** — a mark per parent to carry through the extraction and its cache, for
  every reader of parents to skip, where the file's assertions already hold the pair (#907).
- **Read `var _ = I(x)` as an assertion** — built, it moved no pair and no definition on the Go monorepo snapshot, whose
  6 sites of the shape all sit in vendored code; 2 of them call a function, which the walk cannot tell from a conversion
  and which then reads as an interface that may declare anything (2026-11-01, #988).

## Revisit if

A family's parents make one query exceed tens of milliseconds, or the C++ extraction qualifies a nested type by its
whole namespace chain or reads using-directives, which changes what a lookup reaches. The query cost holds with margin;
the extraction changes are not planned.
