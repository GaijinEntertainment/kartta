# Read a PHP variable's class from the `new` or the type the walk can show it still holds

- **Date:** 2026-11-01
- **Governs:** `crates/kartta-lang-php/src/walk.rs` (`object_creation`, `receiver_class`, `hold`, `hold_parameters`,
  `declared_class`, `held_class`, `held_receiver`, `closure`, `arrow_function`, `forget_writes`, `forget_written`,
  `branch_end`)
- **Pinned by:** `crates/kartta-lang-php/tests/held_classes.rs`, `crates/kartta-languages/tests/php_new_receivers.rs`,
  `crates/kartta-languages/tests/php_parameter_receivers.rs`

`$c = new Container; $c->instance()` calls `Container::instance`, and so does `$c->instance()` under
`function f(Container $c)`; a call that names only its variable leaves the choice to the name tiers, where a nearer
file's method of the name takes it. The walk records the class as the call's receiver wherever the file alone shows the
variable still holds it, and leaves the variable as it is everywhere else, at the price of the calls a branch or a
reference leaves unread.

## Decision

- **The class.** A call on a variable that holds what `$v = new X` assigned has `X` from the root as its receiver,
  `\App\Container`, read through the file's `use` map as a parent is
  ([ADR 3.14](/design-docs/adr/3.14-php-includes.md)), and the graph reads that name
  ([ADR 3.193](/design-docs/adr/3.193-receiver-class-members.md)). `new self`, `new static` and `new parent` in any case
  give the receiver of that word, as a static call does. An anonymous class gives its name
  ([ADR 3.156](/design-docs/adr/3.156-php-anonymous-classes.md)). Only a `new` that is the whole right side counts: a
  `new $class`, a `(new X)->m()`, `$c ? new X : null` and `$v ??= new X` give no class.
- **Parameters.** A parameter holds the class its type names, read as a `new`'s name is, from the start of its function,
  a method's, a closure's or an arrow function's alike. `X`, `?X`, `X|null` and `X $v = null` name `X`, and `self` and
  `parent` in any case give the receiver of that word. A built-in type in lower case, a union of two types besides
  `null`, an intersection and a variadic parameter give no class. A promoted parameter holds it in the constructor as
  any other does, and a by-reference one on entry.
- **From where.** A variable holds the class from the end of the assignment, so `$v = $v->with()` and
  `$v = new X($v->m())` read the value before it.
- **Until where.** The class ends at the next write to the variable: an assignment, a compound assignment, a list or a
  key of one, `=&` on either side, `foreach`'s value or key, `catch`, `unset`, or a closure's `use (&$v)`. A write to
  what the variable reaches, `$v->p = 1` or `$v['k'] = 1`, leaves it.
- **Branches.** An assignment under an `if` or `else`, a loop's body, a `case`, a `try`, a `catch`, a `finally`, a
  `match` arm, a `?:` or either operand of a binary operator holds to the end of that part, where another path may have
  left another value. A class from before the branch stands in the branch, and a write in the branch ends it for good.
- **Functions.** A variable is its function's own, a closure's too whether or not the closure opens a symbol. A closure
  starts with its parameters and what its by-value `use` copies, and an arrow function with its parameters and what the
  function around it holds of any other name. What either writes stays inside it.

## Why

- PHP's `new` makes an object of exactly the class it names, and a `self`, `static` or `parent` word fetches the class
  at run time (`zend_compile_new`, `zend_get_class_fetch_type` in php-src 8.5.12 `Zend/zend_compile.c`; php-langspec
  `spec/10-expressions.md`, The `new` Operator), so `X` holds the method lookup of any call on the object.
- A closure's `use` copies the value as the closure is created, and `use (&$v)` shares the variable
  (`zend_compile_closure_uses`, `ZEND_BIND_LEXICAL`; php-langspec `spec/10-expressions.md`, Anonymous Function
  Creation); an arrow function binds each outer variable it names but for its parameters (`find_implicit_binds`).
- A function checks each argument against its type before the body runs, through a reference too (`ZEND_RECV`,
  `ZEND_RECV_INIT` in `Zend/zend_vm_def.h`; `zend_verify_recv_arg_type`, `zend_check_type` in `Zend/zend_execute.c`),
  and an object passes by `instanceof_function`, so the value is of `X` or a class below it, whose lookup the walk from
  `X` reads. A local variable carries no type after that (`zend_assign_to_variable` in `Zend/zend_execute.h`), so a
  write ends the class as it ends a `new`'s.
- `?X` and a default of `null` add `null` to the type (`zend_compile_typename_ex`, `force_nullable` in
  `zend_compile_params`, `Zend/zend_compile.c`), and a member call on null throws (`zend_invalid_method_call`), so a
  call that runs holds `X`. A value passes a union through any one member and an intersection through all of them
  (`zend_check_type_slow`, `zend_check_intersection_type_from_list`), so neither settles the one class a receiver can
  name. `self` and `parent` are class fetches (`zend_compile_single_typename`, `zend_get_class_fetch_type`), and PHP's
  grammar admits no `static` on a parameter (`optional_type_without_static`, `Zend/zend_language_parser.y`).
- The name from the root keeps an outside class apart from a namesake of the tree, as
  [ADR 3.167](/design-docs/adr/3.167-php-outside-class-calls.md) has for an alias, which a bare name could not:
  `use Symfony\Component\Mime\Email; $m = new Email; $m->sender()` no longer binds Laravel's `Message::sender`.
- On Laravel and Symfony the rule adds 11,582 pairs, removes 3,064 and promotes 24,667 to 85. Of 30 sampled on each side
  all are right, 30 of 30 added, 30 of 30 removed and 30 of 30 moved (2026-11-01, #831).
- On the same trees a parameter's class adds 2,799 pairs, removes 864 and moves 7,667, nearly all to 85. Of 30 sampled
  on each side, 30 added, 29 removed and 30 moved are right (2026-11-01, #898).

## Consequences

- A loop's second pass is not read: `$v = new A; foreach ($x as $y) { $v->m(); $v = new B; }` reads `A` at the call,
  where a later pass holds `B`. At most 41 such writes on the two trees (2026-11-01, #831). Accepted.
- A function that passes `$v` by reference, `extract`, `$$name` and an `include` can write it where the file spells no
  write, and the class stands. Not counted. Accepted.
- `global $v` and `static $v` after a `new` of the name are no writes the walk reads. Not counted. Accepted.
- A later operand of `&&` is read as past the branch, so `$a && ($v = new X) && $v->m()` keeps the variable: 5 such
  assignments on the two trees (2026-11-01, #831). Accepted.
- A property's class, `$this->c = new Container` or the `$this->c` a promoted parameter sets, is no variable's: the rule
  leaves it, and only the parameter `$c` holds the class. `$this->container->instance()` reads as before.
- A type is the bound of the value, not its class: `Base $b; $b->m()` binds `Base::m` where a child overrides it, an
  interface's type binds the interface's declaration, and a member only a child holds, past an `instanceof`, stays with
  the name tiers. Not counted. Accepted.
- A type outside the graph binds nothing, so `CacheItemInterface $item` loses `CacheItem::getKey`, an implementor the
  tree holds: 1 of the 30 removed pairs sampled (2026-11-01, #898). Accepted.
- A union of one class and scalars, `Model|int $v`, settles `->` but leaves the variable: about 670 such parameters on
  the two trees (2026-11-01, #898). A string also names a class to `$v::m()` (`ZEND_INIT_STATIC_METHOD_CALL`). Accepted.
- PHP reads a built-in type in any case and the grammar `string` in lower case alone, so `String $v` gives a class
  receiver. PHP reserves the name in any case (`zend_assert_valid_class_name`), so no type of the graph holds it and the
  call binds nothing where the name tiers would have guessed: no such parameter on the two trees (2026-11-01, #898).
  Accepted.
- A write in a branch ends a parameter's class for good, so `if (!$c) { $c = make(); } $c->m();` keeps the variable.
  Not counted. Accepted.
- A facade's method, which `__callStatic` forwards, bound the concrete class of the facade's last name at 85 through a
  bare receiver, and an alias of the facade now binds it at 70: 63 Laravel pairs one tier lower, the 7 read all right.
  Accepted.
- A cold Symfony build goes from 122.89 G to 124.37 G instructions and from 104.05 MiB to 106.05 MiB at its peak, for
  the holders of the walk and the longer receivers (2026-11-01, #831). A parameter's class takes the same build to
  124.82 G instructions and its heap at the peak from 54.10 MB to 54.30 MB (2026-11-01, #898). Accepted.

## Rejected

- **The bare last name as the receiver** — an outside class then binds a namesake of the tree, the pairs
  [ADR 3.167](/design-docs/adr/3.167-php-outside-class-calls.md) rejects for an alias, and two classes of one name meet
  in `nearest`.
- **The last name where PSR-4 maps the `use`, else from the root** — a class in a file of its own name alone reads; a
  test's classes beside the test, and any tree without a `composer.json`, bind nothing.
- **Holding a branch's class past the branch** — `if ($a) { $v = new A; } else { $v = new B; } $v->m()` then reads the
  last `new` as the class. The file does not settle it.

## Revisit if

The extraction records a call's by-reference arguments, or the walk gains a flow pass that joins two branches of one
class. Medium confidence that the branch rule pays for its misses: joining them would need the pass.
