# List a symbol's callers by hop, test and generated code last within each

- **Date:** 2026-11-27
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`caller_match`, `listed_last`),
  `crates/kartta-graph/src/analyze.rs` (`DirectCalls`, `listed_last`), `crates/kartta-graph/src/change.rs`
  (`consumers`)
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_callers_counts_every_role_and_lists_consumers_and_entries_ahead_of_tests_within_a_hop`),
  `crates/kartta-graph/tests/graph/analyze.rs`
  (`a_symbol_lists_its_test_and_generated_callers_after_the_rest_up_to_the_call_limit`,
  `a_constant_lists_its_test_users_after_the_rest`, `a_seed_lists_its_test_and_generated_callers_after_the_rest`)

A list of callers that a limit cuts keeps its head, and where tests outnumber the code that ships, a list in walk or
path order spends that head on tests. Every caller list puts consumer and entry code ahead of test and generated code
within each hop, and `find_callers` counts every match's callers per role, at the price of a sort per answer.

## Decision

- **The order.** A caller list runs nearest first where it spans several hops, and within a hop lists the consumer
  and entry callers ahead of the test and generated ones, each part in the order the engine holds them. The rule holds
  for `find_callers`' refs, for `impact_of_edit`'s direct callers and users, which the engine orders before it cuts
  them at the call limit, and for an `impact_of_change` seed's callers or users. A symbol's callees keep path order.
- **The counts.** Each `find_callers` match counts the callers its walk reached per role in `consumers=`, `tests=`,
  `entries=` and `generated=`, each only when it is not zero
  ([ADR 4.24](/design-docs/adr/4.24-mcp-omission-counts.md)), whether or not the call passes `role`: `role` picks what
  a match lists, not what it counts.

## Why

- A change must not break the code that ships: a consumer and an entry point, such as `main` or a registered handler,
  ship; a test breaks where the tests run, and generated code is generated again. On this repository `find_callers` of
  `Limits::new` listed 99 tests and 1 consumer in the first 100 of its 499 callers (2026-11-27, #1309).
- The walk holds every caller's role before the server cuts the list, so the counts tell the agent what a call kept to
  one role would list, at no further walking.

## Consequences

- Within a hop the list is in path order only within each part, so a test caller reads after consumers further down
  the path. Accepted.
- `find_callers` collects and sorts the callers its `role` keeps, at most the walk's 500 a match, and `impact_of_edit`
  reads the role of each direct caller and user before the cut. Accepted.

## Rejected

- **Entry code last with test and generated code, as changed symbols and hotspots rank** — that ranking orders what a
  change reaches through a symbol ([ADR 3.22](/design-docs/adr/3.22-change-impact-analysis.md)), and an entry point
  reaches nothing past itself; a caller list names what the change breaks, and an entry point breaks as a consumer does.
- **The role order across the whole list, ahead of hops** — a consumer three hops out would come before a test that
  calls the symbol directly, and the hop order an agent follows outward is lost.
- **The counts only under `role`** — the first answer gives no sign that a call kept to consumers lists more of them.

## Revisit if

Agents ask for a symbol's test callers more often than for its consumers, so that the order puts the wrong part first.
Medium confidence: how often agents pass `role` is not measured.
