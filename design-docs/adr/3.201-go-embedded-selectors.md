A Go selector takes the name at its shallowest depth, and an imported type's fields and methods are unknown to the
graph. The read walks the embedded types the graph holds, shallowest first, and answers from any type that gives the
name, so an import beside it costs no edge; only a name no held type gives counts as the import's, at the cost of a
wrong edge where an import nearer the receiver really holds the name.

## Decision

- **One walk by depth.** A read of a member, a selector's last step included, walks the type and its embedded types
  breadth first, and at each type takes the member it declares, or the embedded field of the name, an embedded `Base` or
  `*pkg.Base` being named `Base`. A compile-time assertion embeds nothing, so the walk never reads one
  ([ADR 3.20](/design-docs/adr/3.20-implementor-resolution.md)).
- **An embedded field's symbol.** An embedded field has no symbol, so the type it is named after stands for it: a use of
  the field is a use of that type, an alias when the field embeds an alias, and a call through the field binds nothing.
- **An interface.** An interface embedded in an interface names no field, so only a struct's embedded types are read by
  name.
- **An import at the same depth.** A held type at the depth an import's members sit at answers. An imported member of
  that name at that depth would make the selector illegal, so a tree that compiles cannot hold both.
- **An import shallower than the name.** A held member deeper than an imported type's members also answers. The
  imported type shadows it when it holds the name, which the graph cannot see, and that pair is wrong.
- **An embedded field beside an import.** The field sits at the depth of the struct that embeds it, one above the
  members of the imported type beside it, so the field answers whatever the import holds.
- **A name no held type gives.** The read reaches outside the graph, also for a name no symbol holds, and the call
  counts as `Miss::ExternalImport` ([ADR 3.29](/design-docs/adr/3.29-go-receiver-types.md) states what such a path
  binds).
- **A cycle of aliases.** A walk that finds no member and meets an alias whose chain of aliases comes back to it has
  read no type: the site counts as `Miss::PastBound`, and a selector past it binds nothing, as a read past a bound does.
  An import the walk reached still answers. A type two aliases meet at, or a chain a type definition breaks, as
  `type Link = Node` with `Node` embedding `*Link`, is no cycle, and such a type stays one without the member.
- **A type defined over a struct.** A defined type holds at its own depth the fields and the embedded fields of the
  struct its named type reaches, through other defined types and aliases, and none of the methods declared on that
  struct or on a type in between: `type T S` with `func (S) M()` gives `t.M()` the `M` an embedded field of `S`
  promotes, and nothing where none does. An alias, `type T = S`, is `S` and keeps them.

## Why

- The spec's selector rule: `x.f` denotes the `f` at the shallowest depth, and more than one there makes the selector
  illegal (`doc/go_spec.html`, Selectors). `lookupFieldOrMethodImpl` searches one depth at a time, a struct's embedded
  fields among its fields, and answers a collision at a depth with no object
  (`cmd/compile/internal/types2/lookup.go:174`, `:212`, `:215`). The unqualified type name acts as the field's name
  (`doc/go_spec.html`, Struct types), and the `*Interface` branch reads methods alone
  (`cmd/compile/internal/types2/lookup.go:240`).
- A rename of the type renames the field, so an agent that asks for the type's references has to see the field's reads.
- go1.27.3 refuses `o.Transport` on `struct { http.Client; Mid }` with `Mid` embedding `Transport`,
  `ambiguous selector`, and takes `http.Client`'s field past a `Transport` embedded a level deeper.
- On the Go monorepo snapshot the walk adds 195 caller and callee pairs, 30 of 30 sampled right, and removes 59, all of
  them `c.Config.M()` bound through `base.Config`'s named field `Config` past the embedded `base.Config` itself
  (2026-11-01, #815).
- A cycle of types with no type definition in it expands without end, and the compiler refuses it as
  `invalid recursive type` (`cmd/compile/internal/types2/decl.go:243`, `:286`), so a tree that builds holds none, and
  the walk's visited list alone reads such a cycle as a type searched to the end (#904).
- At a selector's last step the walk adds 7,277 uses on the snapshot, 30 of 30 sampled right, and removes 217, 30 of 30
  sampled right, 203 of them `base.Config.Config` past the embedded `base.Config`; no call pair moves
  (2026-11-01, #906).
- A defined type keeps the composition of the type it names and inherits none of the methods bound to it
  (`doc/go_spec.html`, Type definitions). `lookupFieldOrMethodImpl` takes a named type's own methods, then at the same
  depth its underlying struct's fields (`cmd/compile/internal/types2/lookup.go:195`, `:209`). go1.27.3 runs `t.M()` to
  the embedded field's `M` past `func (S) M()`.
- On the Go monorepo snapshot reading the struct under a defined type adds 25 caller and callee pairs and 2,099 uses,
  all 25 and 30 of 30 sampled right, and removes 4 pairs, all wrong (2026-11-01, #745).

## Consequences

- A held member past a nearer import that holds its name binds wrongly. Of the snapshot's 3,060 reads of an embedded
  field, none has an import at or above its depth, and of its declared members 2 calls have one nearer, both of
  `MarshalJSON` through an alias of two build declarations, and both right (2026-11-01, #815). Accepted.
- A method promoted through an import stays unbound, counted as `Miss::ExternalImport`. Accepted.
- A walk holds the pair of each alias it passes, 16 bytes each and 32 at most, for as long as the walk runs. Accepted.
- A type defined over a cycle of aliases, `type T A`, takes no member from it, so a call on it stays not admitted. A
  tree that builds holds none. Accepted.
- A type's `find_references` holds reads and writes of the fields that embed it, beside its type sites. Accepted: they
  name it.
- A field read through a type defined over a pointer, `type P *S`, binds nothing, though Go selects it
  (`cmd/compile/internal/types2/lookup.go:103`), since such a type records no value type. The Go monorepo snapshot's 4
  types over a pointer to a named struct hold no such read (2026-11-01, #745). Accepted.

## Rejected

- **Answer from outside the graph once the walk meets an import** — binds nothing for `o.Base.M()` beside `http.Client`,
  the 136 pairs the import alone hid on the snapshot (#815).
- **Answer from outside the graph past a nearer import only** — needs a depth per walked type, for no read of an
  embedded field on the snapshot (#815).
- **Declared members first, embedded names in a second walk** — a deeper promoted member hides a shallower embedded
  field, the 59 wrong pairs (#815).
- **An alias that meets a walked alias closes a cycle** — counts valid aliases of one type, `type Top = Mid` beside
  `type Side = Mid`, as stopped reads (#904).
- **Reading each alias's chain again where a walk closes** — a second walk over declarations the first already read
  (#904).
- **Bind nothing for a read of an embedded field** — no symbol stands for the field then, and a rename of its type shows
  none of the 7,277 uses on the snapshot (#906).
- **The struct under a defined type at the end of the walk's queue** — a field at that type's depth loses to a deeper
  one the queue holds first, in `struct { Far; Sib }` with `type Sib Under` (#745).

## Revisit if

The graph learns the members of imported types, which decides what this rule assumes. High confidence in the rest: it
follows the compiler's walk.
