# Bind a call through the import, type, qualified name or owner it is written on

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`resolve_by_tiers`, `through_binding`,
  `written_inside_an_enclosing_scope`, `nested_in_written_owner`, `member_of_the_written_class`),
  `crates/kartta-graph/src/scope.rs` (`member_of_a_reached_owner`, `member_of_the_receiver_s_owner`),
  `crates/kartta-lang-rust/src/walk/calls.rs`, `crates/kartta-lang-cpp/src/walk.rs` (`record_call`),
  `kartta_lang::Conventions` (`scope_separator`, `class_member_separator`), `kartta_lang::CallRef::calls_a_method`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`, `crates/kartta-languages/tests/engine.rs`
  (`a_rust_method_call_binds_no_constant_of_its_name_while_a_path_call_binds_one`,
  `a_rust_method_named_for_its_own_type_binds_through_a_method_call`),
  `crates/kartta-languages/tests/cpp_member_call_types.rs`, `crates/kartta-lang-rust/tests/extract.rs`
  (`a_method_call_is_marked_apart_from_a_path_call_in_a_body_and_in_a_macro_s_arguments`)

A call written on an import, a type, a qualifier or an owner names where its callee lives, as the language's own lookup
reads it. Tiers 2 to 5 of the cascade of [ADR 3.7](/design-docs/adr/3.7-call-resolution.md) bind such a call there
before any tier binds by name alone, at the cost of the calls whose receiver is a value of no type the graph records.

## Decision

Each tier binds at the confidence given, from `kartta_graph::confidence`:

- **Tier 2, an import binding.** A receiver that names an import binding binds the target's export, at 95. A directory
  that exports no callable of the name, or an import of code the graph does not hold, ends the cascade with nothing
  bound. [ADR 3.45](/design-docs/adr/3.45-module-file-bindings.md) binds a target that is a module's file.
- **Tier 3, a type path.** A receiver that is a type path binds the method of the type the path reaches, at 85
  ([ADR 3.29](/design-docs/adr/3.29-go-receiver-types.md)).
- **Tier 4, a qualified callee.** A callee written qualified binds, inside a namespace, the definition its innermost
  enclosing scope names that the caller's file sees, at 88; else the symbol of that qualified name, the first in path
  order, at 90; else its trailing owner and name where the language joins scopes with a separator, at 88. Of the
  namesake classes that hold that member, the one the written scope names from the scopes around the call outward
  binds, by the lookup of [ADR 3.65](/design-docs/adr/3.65-cpp-namesake-classes.md); the first in path order binds
  where the scope names none of them, or where the graph locates no class of the first. A callee written from its
  owner alone, `Widget::Kind`, binds the member of that owner whose longer qualified name ends in it, the one the
  caller's file sees first, at 88. A callee written from the root names a global symbol.
- **Tier 5, an owner.** A receiver that names the caller's base class binds the base's member, at 85, or nothing
  ([ADR 3.168](/design-docs/adr/3.168-base-receiver-calls.md)). A receiver that names an owner binds that owner's
  member, at 85: the owner in the caller's file, then in its directory, then in its package where a package is not a
  directory, then the first in path order. A receiver that spells the end of an owner's chain, `Shape` for `Geo::Shape`,
  where every member of the name with such an owner has the one owner, takes that owner's copies in the same order.
  [ADR 3.180](/design-docs/adr/3.180-cpp-declared-class-calls.md) binds the class a C++ operand is declared as, and
  [ADR 3.47](/design-docs/adr/3.47-cpp-field-calls.md) the class of the caller's class's field a C++ call names. A Rust
  call through a type the graph holds no definition of binds nothing past this tier
  ([ADR 3.176](/design-docs/adr/3.176-rust-outside-type-calls.md)), and a Rust owner of a crate the caller's crate is
  not built with binds nothing ([ADR 3.179](/design-docs/adr/3.179-rust-crate-reach.md)). A Ruby call on a constant
  or a literal binds only within the class it names ([ADR 3.190](/design-docs/adr/3.190-ruby-constant-receivers.md)).
- **Separators.** `scope_separator` gates tier 4 and the calls written from the root. Where `class_member_separator`
  keeps a class's own methods apart, a receiver that ends in it is the class, and every tier that takes one of an
  owner's members of the name takes the kind its receiver reaches first
  ([ADR 3.15](/design-docs/adr/3.15-ruby-member-names.md)). A file's package is the one
  [ADR 3.7](/design-docs/adr/3.7-call-resolution.md) names.
- **Value receivers.** A receiver that is a value names no owner; each language's extraction says what it records for
  one: TypeScript and JavaScript in [ADR 3.101](/design-docs/adr/3.101-jsts-value-receivers.md), Rust in
  [ADR 3.56](/design-docs/adr/3.56-rust-call-receivers.md) and
  [ADR 3.55](/design-docs/adr/3.55-rust-parameter-receivers.md), C++ in
  [ADR 3.75](/design-docs/adr/3.75-cpp-call-receivers.md), and Go in
  [ADR 3.29](/design-docs/adr/3.29-go-receiver-types.md). A Rust, TypeScript or JavaScript receiver that spells a path
  of calls reaches these tiers as the owner the path returns.
- **Method calls.** A call its language marks `calls_a_method` names a member. At every tier it binds no variable or
  constant, where `values_are_call_targets` admits one for its other calls, and no type or constructor, so neither ties
  with a member of its name. Rust marks every `x.f()` and `x.f::<T>()`, those in a macro's arguments included; a path
  call, `F()` of a `const F: fn()`, keeps the value. C++ marks every call through `.` or `->`; a bare or a qualified
  call keeps the type. Other languages leave the mark false, since their member call can reach a class a module holds.
- **A type beside the include tier.** The one member an included file offers a method call binds at 15, not 70, where
  another file the caller includes directly offers a type or a constructor of the name.

## Why

- A receiver or a qualifier is where the language's own lookup starts for the call, so the tier that reads it is the
  surest one the call has.
- A crate names its own types far more often than another crate's of the same name, and a cargo registry keeps the
  versions of one crate side by side: of the Rust pairs the package step rebinds to the caller's own package on a
  registry of 496 crates, 29 of 30 sampled were right (2026-10-24, #202). Where a package is a directory, the directory
  step is the package's, and a package of the same declared name elsewhere, as Go's many `main`s, is another package.
- A C++ member's qualified name keeps only its class's bare name
  ([ADR 3.72](/design-docs/adr/3.72-cpp-name-qualification.md)), so `b::Widget::draw` matches
  `a::Widget`'s method as well, and the written scope is what tells them apart: all 76 C++ call sites it moves on the
  game-engine tree bind the class the scope names (2026-10-24, #377).
- Rust calls a method as `x.f()` and the value a field holds as `(x.f)()`, so a method call never calls a value: once
  a file's own `macro_rules!` items were recorded, such calls made 192 of 1,655 added pairs on a cargo registry, gimli's
  `self.D8(0)` binding a register constant (2026-10-24, #609).
- C++ reaches a type through a scope, never through `.` or `->`, so on the game-engine tree all 107 pairs the rule
  removes were false, and the 40 it adds outside the include tier beside a type were right. The 36 of that tier were 18
  right, so they bind as a guess (every pair read, 2026-10-31, #415).

## Consequences

- The stored call keeps the method mark in a spare bit of its caller index, so it keeps its size, and a call inside a
  definition past the 2^27th of its file is not kept. Accepted.
- A namespace-relative C++ call written in a member function binds nothing (#457).
- A qualified C++ callee whose first namesake is an out-of-line definition the graph locates no class of keeps the first
  in path order whatever its scope names: physx 3.4's `Gu::PersistentContactManifold::drawPolygon` (#604).
- A C++ call through a function pointer in a field binds nothing where the name is also a type, as it does where no
  type shares it: the graph takes no value as a C++ call target. Accepted.

## Rejected

- **Set a type aside and keep the include tier's 70** — 18 of the 53 pairs it binds there beside a type are false,
  12 of them `(++position).base()` on an iterator (2026-10-31, #415).
- **The guess wherever an included file offers a type, the member's own file among them** — moved 9 right pairs from 70
  to 15, as `my_hash_compare.hash(key)` (2026-10-31, #415).
- **The guess for a type in any file the includes reach** — moved 14 more pairs from 70 to 15, every one right, as
  `value.is_array()` (2026-10-31, #415).
- **Values as no call target for every Rust call** — drops `F()` of a `const F: fn()`, which calls the value.
- **The method mark in the receiver's spelling** — `self.f()` records the owner it names, which tier 5 reads.
- **One slot per qualified name, the last in path order** — an insert or a removal cannot keep it, so the slot becomes
  a read over the name's definitions.
- **Bind the class the written scope names wherever the first namesake has no located class** — moved about 30 calls
  from a definition to its own declaration, the same method at a worse location (2026-10-24).

## Revisit if

A language's calls name another package's owner of a name about as often as their own package's, so the nearest owner
stops being the likelier callee. Held with high confidence on the registry sample.

## History

- 2026-10-31 — Method calls, A type beside the include tier: a C++ call through `.` or `->` bound a class, an alias or
  a constructor of its name, as `args->visitor()` a struct of another library, and such a definition tied with the
  member of the name (#415)
- 2026-10-25 — Tier 5, an owner: a receiver that spells the end of an owner's chain bound the owner's first copy in
  path order whatever copy the caller lay in, as a Ruby call in one vendored copy of the standard library bound another
  copy's method (#465)
- 2026-10-24 — Method calls: a Rust method call bound a constant of its name, `self.D8(0)` an unrelated type's
  associated constant, which `x.f()` can never call (#609)
- 2026-10-24 — Tier 4, a qualified callee: a C++ member's qualified name keeps only its class's bare name, so
  `b::Widget::draw` matched `a::Widget`'s method as well, and the written scope is what tells them apart (#377)
- 2026-10-24 — Tier 5, an owner: a Rust call on a standard-library, external or prelude type bound a namesake of the
  caller's file, `Vec::new()` in `Following::plan` binding `Following::new` (#219)
- 2026-10-24 — Tier 5, an owner: `base`, `super` and `parent` calls bound the caller's own override, which the name
  tiers reach first (#186)
- 2026-10-24 — Tier 5, an owner: of several Rust definitions of one name, the tier took none of the caller's own crate
  first, so a call inside `hashbrown` 0.15.5 bound 0.14.5's definition (#202)
- 2026-10-23 — Separators: a Ruby class that declares `def build` and `def self.build` holds two methods of one owner

- 2026-10-22 — Value receivers: a Rust method call bound free functions of its name, which `x.f()` can never call
  (#249)
- 2026-10-19 — Tier 4, a qualified callee: a call to `detail::f()` written inside the enclosing namespace bound nothing
  (#114)
- 2026-10-17 — Tier 4, a qualified callee: once members kept their full nested names, a callee written from its class
  alone, `QueryPool::BlockMask_t(1)`, bound nothing at 307 sites (#67)
