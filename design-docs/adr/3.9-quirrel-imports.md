# Resolve a Quirrel import through the nearest .sqconfig

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-quirrel/src/resolve.rs`, `crates/kartta-lang-quirrel/src/sqconfig.rs`,
  `crates/kartta-lang-quirrel/src/walk.rs` (`BANNER`)
- **Pinned by:** `crates/kartta-lang-quirrel/tests/resolve.rs`

Quirrel imports name files through mounts that the script tooling reads from a `.sqconfig` file, not through paths a
reader can follow from the script alone. A script resolves through the one config the tooling reads for it, and where
none governs, through a guess from the specifier's shape; what the tooling would not load is no include, so a mount
the resolver cannot read leaves the import unresolved.

## Decision

- **Directives.** An `import`, a `from ... import` with the names it takes, and a `require("spec")` or
  `require_optional("spec")` with one string literal each name a module. A directive that names a file is an include
  of it; one that names no file is an import, kept as written with its names, so a dependency on a native module stays
  visible.
- **The governing config.** The nearest `.sqconfig` in the script's directory or above it governs the script, and
  that file alone. A config that cannot be read still governs, with no mount and no base path.
- **Under a config.** A specifier resolves in the loader's form, reading `\` as `/`, and the loader appends no
  extension:
  - `%name/rest` names `rest` below the directory the config mounts as `name`, and no file where it mounts no
    `name`;
  - any other specifier that ends in `.nut` names the file beside the script, else the file below the first of the
    config's base paths that holds it;
  - any other specifier is a native module.

  A config never falls back to the specifier's shape. Each place takes the one file that differs from the path only
  in ASCII case where no file matches it exactly, as
  [ADR 3.142](/design-docs/adr/3.142-vromfs-case-lookup.md) states.
- **What a config states.** Only its `mount` and `base_path` lines are read, each relative to the config's directory.
  A mount name may start with `%`, and one is dropped; the rest is ASCII letters, digits and `_`, shorter than 64
  bytes. A later mount of a name replaces an earlier one; an absolute base path is dropped. The tooling also follows
  a config's `include` lines and `\` line continuations, which the resolver does not, so a mount or a base path
  stated through either resolves nothing.
- **Without a config.** The specifier's shape is the guess, matched in its own case: `%root/rest` and any other
  slashed or `.nut` specifier name the file under the nearest directory of the script that holds them, `./` and `../`
  name the file relative to the script, each with `.nut` appended when the path as written names none, and a bare name
  names no file.
- **Test and generated code.** A file with a `test`, `tests` or `testData` directory in its path, each matched
  whole and in any case, or whose stem ends in `_test` or starts with `test_`, is test code, so `latestData/`
  stays product code. A file whose name holds `.gen.` or `_gen.`, or whose leading comments carry `@generated`,
  `DO NOT EDIT` or `Code generated`, is generated code.
- **What the resolver keeps.** The resolver keeps only the mounts and base paths it derived, and a followed engine
  resolves no script again for an edit that changes neither, as
  [ADR 3.82](/design-docs/adr/3.82-followed-resolver-rebuilds.md) states.

How a script's own code extracts is the rule of
[ADR 3.143](/design-docs/adr/3.143-quirrel-function-names.md),
[ADR 3.144](/design-docs/adr/3.144-quirrel-value-calls.md) and
[ADR 3.145](/design-docs/adr/3.145-quirrel-runtime-methods.md).

## Why

- The script tooling reads the `.sqconfig` nearest the script and that file alone, and what it mounts decides which
  file a specifier loads: 7,661 of 8,785 scripts on the game-engine tree sit under one of 82 configs (2026-10-16,
  #36).
- A config that cannot be read mounts something unknown, and a guess from another config or from the shape could name
  a file the tooling never loads.
- Without a config each game mounts its own roots, so the nearest directory that holds the path is the likeliest
  mount.
- The Quirrel compiler keeps its test scripts under `testData/`, and AssetViewer's `Tests/` holds a script that
  registers its test cases. Their stubs, counted as product code, bound the game scripts' calls of `Computed`, `Point2`
  and `cos`; with the test flag, the name tiers keep them off product calls
  ([ADR 3.46](/design-docs/adr/3.46-test-definition-binding.md)).

## Consequences

- A mount stated through a config's `include` line or a `\` continuation resolves nothing. Accepted.
- A specifier no file provides, a native module such as `math`, `eventbus` or `dagor.workcycle`, stays an import.
  Accepted.

## Rejected

- **Every `.sqconfig` above the script merged** — finds more files, and some of them the tooling never loads for that
  script, which is a wrong edge.
- **Shape fallback under a governing config** — resolves specifiers the config does not mount, again to files the
  tooling would not load.

## Revisit if

A script tree mounts its roots somewhere other than a `.sqconfig`. Held with moderate confidence: on the game-engine
tree the scripts no config governs, about one in eight, resolve by the guess.
