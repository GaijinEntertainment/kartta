# Name a Rust method call's receiver by its parameter's declared type

- **Status:** accepted
- **Date:** 2026-10-23
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-rust/src/walk/declared.rs`, `crates/kartta-lang-rust/src/walk/bindings.rs`

- **Pinned by:** `crates/kartta-lang-rust/tests/extract.rs`

  `a_method_call_on_a_parameter_keeps_the_value_s_receiver_where_the_file_cannot_tell_its_type_is_the_tree_s`,

A method call on a parameter, `ranking.offer()` in `fn offer(ranking: &mut Ranking)`, names a value whose type its
signature spells. The walk records that type as the receiver, which the owner tier binds, but only where the file shows
the type may be one of the tree, since that tier binds by name and crates declare namesakes of the standard library's
types.

## Decision

- The walk keeps the type each parameter of a `fn` is declared as, for a name or `mut name` pattern. A method call on
  the name records the type's last segment, which the receiver-owner tier of
  [ADR 3.7](./3.7-resolve-calls-when-a-query-asks.md) binds at 85.
- The shapes that name a type: `T`, `&T`, `&mut T` and a path; the base of `T<..>`, lifetimes alone included; the
  pointee of `Box`, `Rc` and `Arc`; the type of the `impl` or trait around the call for `Self`; and the trait of an
  `impl Trait` or `dyn Trait` of one bound. A type parameter of the function or of the `impl` or trait around it, a path
  through one or through `Self`, `T::Item`, a tuple, and any pattern other than a name give no type.
- The innermost binding decides: a `let`, a closure's parameter or a pattern that binds the name again hides the type,
  and a name a closure in a macro's arguments binds is no parameter.
- A type is kept only where the file shows it may be the tree's. A name a `use` brings is shown where the `use`'s first
  segment is no toolchain crate, `std`, `core`, `alloc`, `test` or `proc_macro`; a `use` inside a function body reaches
  no signature, and inside an inline module that module's `use`s decide before the file's. A path is shown where its
  first segment is `crate`, `self`, `super` or a module the file declares, or is no toolchain crate, by itself or
  through the file's `use` of it. A name no `use` brings is shown where the file declares a type of the name, or where
  the file has a top-level glob and the name is none of the prelude's `Box`, `Option`, `Result`, `String` and `Vec`.
  Any other type leaves the receiver the value's name after a `.`
  ([ADR 3.56](./3.56-name-a-rust-call-s-receiver-only-where-its-syntax-spells-it.md)).

## Why

- `ranking.offer()` recorded `.ranking`, which names no owner, so `find_callers` of `Ranking::offer` listed 6 callers
  and counted the call of kartta-fs's `offer` ambiguous, while the same call written `Ranking::offer(ranking)` bound
  (this repository, 2026-10-23).
- The owner tier binds by name, and a registry's crates declare namesakes of the standard library's types: a parameter
  of `std::fs::File` bound tokio's `File`, a `Vec` allocator-api2's (cargo registry of 488 crates, 2026-10-23).
- 446 of the 464 pairs the rule added or raised on this repository are right, 96% (2026-10-23).

## Consequences

- The owner tier picks the owner of the name in the caller's file, then its directory, then the first in path order,
  never by crate: in the registry 1,022 added pairs take another crate's namesake where the caller's crate declares a
  type of the name, and 1,287 another version's copy (#202).
- A call on a typed `let`, a field or a chain keeps the value's name (#484, #248, #485).

## Rejected

- **A type parameter's bound** — binds serde's `Serializer`, `Deserializer` and `Visitor` to whichever of ciborium,
  postcard or serde_json is nearest: 19 of 30 sampled pairs right in the registry (2026-10-23).
- **A closure's typed parameter** — about 18 of 30 sampled right.
- **A typed `let`** — 19 of 30 sampled right; it is #484's case.
- **A type surviving a shadowing `let`** — the pairs it adds are right mostly by chance.
- **No type through any glob** — the pairs it removes are mostly right.

## Revisit if

The owner tier tells crates apart (#202), so that a namesake of a standard library type no longer takes the call. Open.
