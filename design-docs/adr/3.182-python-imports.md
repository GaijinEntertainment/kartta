# Resolve a Python import by probing the root and the directories around the file

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-python/src/resolve.rs`
- **Pinned by:** `crates/kartta-lang-python/tests/resolve.rs`, `crates/kartta-languages/tests/engine.rs`
  (`a_python_call_through_a_module_outside_the_tree_*`)

An import names a module by a dotted path that the interpreter looks up on `sys.path`, which no file of the repository
states. The Python resolver ([ADR 3.12](/design-docs/adr/3.12-python-qualified-names.md)) probes an import from the
repository root and the directories around the importing file, and binds the names of an import of outside code
outside the repository, a heuristic that reads no import root a configuration declares.

## Decision

- **Includes and imports.** An `import` or `from ... import` that includes a file of the repository is an include
  alone; one that includes none, a module of the standard library or a `from __future__ import`, is an import as
  written. A `__future__` import is never probed.
- **Module files.** A module `a.b` is the first of `a/b.py`, `a/b/__init__.py`, `a/b.pyi` and `a/b/__init__.pyi` that
  exists, the stubs for a repository that ships only the types of a module.
- **Absolute modules.** An absolute module is probed from the repository root, then from each directory around the
  importing file, nearest first. With `app/db.py` and `src/app/db.py` both present, `import app.db` from under `src/`
  takes the root one.
- **Relative modules.** A relative module climbs one directory for each leading dot after the first and names nothing
  above the root. It is a dependency whether or not its names are submodules.
- **Submodules.** A from-import also includes each imported name that is a submodule, which only a package holds: no
  name below a plain module file is probed. A from-import of `*` or of no name resolves to the module alone.
- **Namespace packages.** A module found nowhere may be a namespace package, a directory without an `__init__.py`: its
  names are probed under the same anchors, and the first anchor that holds one of them is the package, so a portion
  under a later anchor is not merged.
- **What an import includes.** A name that is a symbol of the module includes nothing. `import a.b.c` includes the
  module `a.b.c` alone, not the `__init__.py` files of `a` and `a.b` that the interpreter runs on the way.
- **Outside bindings.** An absolute import that includes no file binds the names it writes to code the graph does not
  hold: `json` for `import json`, `np` for `import numpy as np`, `a` for `import a.b`, and `Field` for
  `from sphinx.util import Field`, so a call through or of such a name binds nothing
  ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md),
  [ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md)). It binds none where a module file of the repository at
  any depth, `a/b.py` or `a/b.pyi`, ends in the module's path or in that of a name it imports as a submodule, and
  `import a.b` binds no `a` that the probe or such a file finds.

## Why

- The probe from the root and the directories around a file finds a module under a `src` layout without reading any
  of the configurations that spell import roots differently.
- A call through or of a name an import of outside code binds reaches that code: of the 792 pairs the outside bindings
  unbind on the game-engine tree, `json.dumps()` binding a project `dumps` the largest group, 60 of 60 sampled were
  false (2026-10-24, #464).

## Consequences

- A root-first match can take the wrong one of two modules of a path, and an import root the probe does not reach
  includes nothing. Accepted (Revisit if).
- A package that only its `__init__.py` holds, which the probe does not reach, counts as outside, and a call through
  its import binds nothing; on the game-engine tree no pair changes for it (2026-10-24, #464). Accepted.

## Rejected

- **Reading `sys.path` from the repository's configuration** — `pyproject.toml`, `setup.cfg` and a `src` layout each
  spell the import roots differently.
- **Binding outside every import the probe does not reach** — a script that extends `sys.path` reaches a module of the
  repository that way: 10 of 50 sampled unbound pairs on the game-engine tree were true (2026-10-24, #464).
- **Looking for a package's `__init__.py` at any depth** — every initializer shares the name, so each import would
  read all of them, and no pair on the game-engine tree changes (2026-10-24, #464).
- **Including the `__init__.py` of every package on an import's path** — an edge per level for code the import only
  runs, not code it names.

## Revisit if

An import root that the probe misses, or a root-first match that is wrong, shows up on a real tree. None has yet.
