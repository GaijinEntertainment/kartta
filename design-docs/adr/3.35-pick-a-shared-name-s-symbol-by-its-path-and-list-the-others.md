A name several symbols share selects one of them: the call queries of
[ADR 3.7](./3.7-resolve-calls-when-a-query-asks.md) take the one with the most callers or sites, and
[ADR 3.20](./3.20-resolve-implementors-from-the-parents-written-when-a-query-asks.md) the most implemented. A selector
carries a path prefix that reaches any of them, and an answer lists the most ranked of those it passed over, so an
agent learns which copy it got and asks again for another at the cost of one more call.

## Decision

**A selector carries a path prefix.** `Selector` is a name and an optional start of a root-relative path: one file's
path, or a directory's with its closing `/`; `None` looks in every file, and a `&str` converts to a selector without
one. Every selection tier keeps only the symbols in the files under the prefix before it ranks them, so a prefix
reaches any copy of a symbol, copies that share one qualified name included, and narrows an owner-qualified name that
several symbols end with to the one under it. A declaration under the prefix answers as the callable it links to,
wherever its definition lives. `callers`, `callees`, `references`, `implementations` and both ends of `call_path` take
one.

**An owner-qualified name only its suffix matches.** Where a name with a separator matches no qualified name and no
bare name whole, the call queries select it only when every symbol that ends with it is one callable, and select
nothing otherwise; `implementations` takes the most implemented of the types that end with it.

**An answer lists the most ranked of what it passed over.** A walk over calls, `references` and `implementations` carry
`candidates`, and a call path carries them for each end. `candidates` holds at most five of the symbols `passed_over`
counts, the highest count first, then path order, each with the count the query ranks by: callers for a walk over calls
and for each end of a call path, sites for references, direct implementors for implementations. `passed_over` counts
the other symbols `Graph::definitions` lists for the name. The counts come from the name's resolution, which ranking the
root already did for every symbol of the name, and implementations reuse the counts their selection took.

**The kinds a query selects among are part of its contract.** `is_referent`, every kind but an enum's variants, and
`is_parent`, classes, structs, interfaces, traits, namespaces and type aliases, state what `references` and
`implementations` pick among, so a consumer that explains a name that selected nothing lists only definitions a prefix
could pick.

## Why

- A count told an agent that something was passed over, not what, so it had to search to learn which copy it got, and
  copies that share a qualified name, as a vendored package beside the same package in a second checkout, were reached
  by no name at all.
- A call path takes a prefix at each end, so an agent that sees the copy it meant among an end's candidates asks again
  with that copy's path instead of settling the end with another tool first.

## Consequences

- Ranking the passed-over symbols costs a name with many of them their counts: `find_implementations` of `Iterator` on
  the C++ game-engine tree counts the implementors of the 45 types it passes over, 0.86 ms where it took 0.10 ms
  (2026-10-19). Accepted.
- The call queries and `implementations` part on an owner-qualified name several symbols end with: the first select
  none, the second the most implemented (#506).

## Rejected

- **Answer the union of the symbols a name selects** — one list that mixes copies and namesakes (ADR 3.20).
- **Pick the first of an owner-qualified name's suffix matches** — an answer where the name names none for certain; a
  listing and a prefix pick the one meant at the cost of one more call.
- **A selector by file only** — a directory prefix also tells a vendored tree from the checkout, and a file's path is a
  prefix of itself.
- **List every passed-over symbol** — `Provider` passes over 59 types on the Go monorepo snapshot and `visit` 1,773
  callables on the C++ tree; five, with `passed_over` counting the rest, keep an answer's growth to a few hundred bytes.

## Revisit if

Agents asking again after a shared name's answer pick a copy past the fifth candidate often enough that five is too few.
Not measured.
