# Pick a shared name's symbol by its path, and list the others

- **Status:** accepted
- **Date:** 2026-10-19
- **Initiative:** `03-code-graph`

A name that several symbols share selects one of them: the queries of ADR 3.7, 3.20 and 3.34 take the one with the
most callers, sites or implementors, and count the others in `passed_over`. The others were reachable only by a longer
name, and copies that share a qualified name, as a vendored package beside the same package in a second checkout, by
no name at all. The count told an agent that something was passed over, not what, so it had to search to learn which
copy it got. An owner-qualified name that several symbols end with selected none, and the MCP server answered "no
symbol matches" although several did.

**A selector carries a path prefix.** `Selector` is a name and an optional start of a root-relative path: one file's
path, or a directory's with its closing `/`. Every selection tier keeps only the symbols in the files under it before
it ranks them, so a prefix reaches any copy, and narrows an owner-qualified name that several symbols end with to the
one under it. A declaration under the prefix still answers as the callable it links to, wherever its definition lives.
`callers`, `callees`, `references`, `implementations` and both ends of `call_path` take one; a `&str` converts.

**An answer lists the most ranked of what it passed over.** A walk over calls, references and implementations carry
`candidates`, and a call path carries them for each end. `candidates` holds at most five of the symbols `passed_over`
counts, the highest count first, then path order, each with the count the query ranks by: callers for a walk over
calls and for each end of a call path, sites for references, direct implementors for implementations. A call path
takes a prefix at each end, so an agent that sees the copy it meant among an end's candidates asks again with that
copy's path instead of settling the end with another tool first. `passed_over` keeps its meaning, the
other symbols `Graph::definitions` lists for the name. The counts come from the name's resolution, which ranking the
root already did for every symbol of the name, and implementations reuse the counts its selection took.

**The kinds a query selects among are part of its contract.** `is_referent` (every kind but an enum's variants) and
`is_parent` (classes, structs, interfaces, traits, namespaces) state what `references` and `implementations` pick
among, so a consumer that explains a name that selected nothing lists only definitions a prefix could pick.

## Measured

The parity plan on the C++ game-engine tree (21,096 calls) and the Go monorepo snapshot (7,189 calls), against `main`,
2026-10-19. Every differing answer differs only by the added records, except two `find_call_path` answers on the C++
tree that name the end that selected nothing, where `main` gave one line for both ends:

| `find_callees` | 534 | 219 |
| `find_references` | 886 | 397 |
| `find_implementations` | 102 | 17 |

Counting the candidates costs a query little: the fifteen shared-name calls of each tree that pass the most symbols
over answer within noise of `main`, warm, alternating, except `find_implementations` of `Iterator` on the C++ tree,
which counts the implementors of the 45 types it passes over (0.10 → 0.86 ms at the fastest).

The C ABI answers of a build and every query method differed in 295 of 1,672 on the C++ tree and 128 of 1,075 on the
Go snapshot (77 and 30 of them `call_path`), each by its `candidates` alone, and the one unknown-field error by naming
`path_prefix` among the fields.
The key is absent where nothing was passed over.

No answer here holds less than it did. Against upstream, measured 2026-10-19: the plan's shared-name calls, every
`find_callers`, `find_references` and `find_implementations` call whose answer passed symbols over, asked of
upstream's engine on the same trees. Upstream lists nothing of what it passes over, and takes no path prefix.

| callers, references | C++ tree (443, 461 calls) | Go snapshot (188, 197) |
| --- | --- | --- |
| upstream takes the same root | 67, 31 | 36, 22 |
| upstream's root is one of kartta's candidates | 191, 208 | 88, 105 |
| upstream's root is past kartta's five, counted in `passed_over` | 96, 95 | 43, 49 |
| upstream's root is a header declaration kartta lists as its definition | 3, 3 | 0, 0 |
| upstream answers nothing | 86, 124 | 21, 21 |

The roots differ because upstream returns the one entry its index keeps for a qualified name stored whole, and ranks
by callers only among bare names. Kartta ranks every symbol of the name, so it answers for the most called or used
copy. Where upstream answers nothing and kartta selects a symbol, the names are mostly DSHL on the C++ tree (187 of
210) and TS/JS on the Go snapshot (34 of 42), and the rest shell and C++.

`find_implementations` differs by design (ADR 3.20). Upstream unions the implementors of every type of the name, while
kartta answers for one root and now names the other types with their counts.

| implementations | C++ tree (84 calls) | Go snapshot (16) |
| --- | --- | --- |
| the same implementors | 66 | 14 |
| kartta's are fewer: the union mixes the types | 6 | 0 |
| kartta finds implementors upstream misses | 4 | 0 |
| each holds some the other lacks | 8 | 2 |

The plan asks no owner-qualified name that several symbols end with. Upstream's code refuses one, as kartta's graph
does, and kartta's MCP answer lists the definitions instead.

## Considered Options

- **Answer the union of the symbols a name selects** — ADR 3.20 declined it: one list that mixes copies and namesakes.
- **Pick the first of an owner-qualified name's suffix matches** — an answer where the name names none for certain; a
  listing and a prefix pick the one meant at the cost of one more call.
- **A selector by file only** — a directory prefix also tells a vendored tree from the checkout, and a file's path is a
  prefix of itself.
- **List every passed-over symbol** — `Provider` passes over 59 types on the Go snapshot and `visit` 1,773 callables
  on the C++ tree; five, with `passed_over` counting the rest, keep an answer's growth to a few hundred bytes.
