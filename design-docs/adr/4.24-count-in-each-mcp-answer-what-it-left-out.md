# Count in each MCP answer what it left out

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-23
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-mcp/src/render.rs`, `crates/kartta-mcp/src/render/`, `crates/kartta-mcp/src/llmxml.rs`
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`, `crates/kartta-mcp/tests/graph.rs`

An agent reads a cut answer as complete unless the answer says what it cut. Each answer of
[ADR 4.1](./4.1-answer-agents-through-an-mcp-server-with-the-tools-their-prompts-name.md)'s server counts, as
attributes of its envelope, what the engine turned away where it made the cut, and lists what a match passed over, so
a count costs no work the query does not already do.

## Decision

Where the engine counts what an answer left out, the answer says so, each count only when it is not zero:

| Tool | Counts |
| --- | --- |
| `index_repo`, `index_stats` | `unheld`, `files_without_symbols`; `<errors>`, the walk's failures |
| `grep` | `truncated`, `unsearched`, `excluded`, `binary`, `oversized`, `ruled_out`, `symlinks` (ADR 1.11) |
| `list_dir` | `unlisted` beneath a directory not entered, `total` and `excluded` (ADR 1.8) |
| `find_symbols` | `total` past the limit, `unmatched` query words, `dropped_words` |
| `find_callers` | `passed_over`, `unexpanded`, `ambiguous`, `below_confidence`, `turned_away`, `file_scope` |
| `find_callees` | `unresolved`, `passed_over`, `unexpanded`, `below_confidence`, `turned_away` |
| `find_call_path` | `at_depth_bound`, `below_confidence`, `turned_away`, `passed_over_from`, `passed_over_to` |
| `find_references` | per-kind counts, `shown`, `files`, `files_shown`, `ambiguous`, `below_confidence`, `passed_over` |
| `find_implementations` | `total` past 500, `passed_over`, `depth=` on an implementor through another |
| `find_importers` | `unexpanded` at the hop limit, `depth=` on an importer through another |
| `read_definitions` | `shown`, `resized` for a file changed since the build, `error=` for one that would not read |
| `impact_of_edit` | `ambiguous`, `unresolved`, `unexpanded`, `truncated`, `users`; `shown`/`of` on each list |
| `impact_of_change` | `truncated_walks`, `unheld_regions`, `regions_outside_symbols` |
| an `impact_of_change` seed | `truncated`, `turned_away`, `unexpanded`, `ambiguous`, `users`; `shown`/`of` on lists |
| `find_unused` | `total` past the limit, `live`, `<excluded/>` by reason, `reflected` among them |

A match that passed symbols over lists up to five as `<candidate/>` records with the `callers=`, `sites=` or
`implementors=` each has; `find_implementations` names the type it took in a `<root/>`, and `find_call_path` marks each
`end="from"` or `end="to"`. A file whose top level calls a `find_callers` root is a `<file_scope path=/>` record after
the refs, with a call's confidence mark and no line, since the graph keeps only the names a top level spells; the walk
goes no further, `role` lists none of them, and `below_confidence=` counts those the floor dropped. `find_callers` of a
field points at `find_references`. The impact answers of a field, a variable or a constant count `users=` and list
`<users>`, or past 30 `<user_dirs>`, in place of callers, which its users hold. Own ADRs decide what a floor dropped
([4.13](./4.13-count-what-the-confidence-floor-dropped-in-place-of-an-empty-answer-s-verdict.md)), the calls of a name
that bound nothing ([4.12](./4.12-count-the-calls-of-a-symbol-s-name-that-several-definitions-leave-unbound.md)), a call
of itself ([4.14](./4.14-list-a-symbol-s-call-of-itself-apart-from-its-callers-and-callees.md)), an outline's holders
([4.15](./4.15-name-the-definition-that-holds-an-unowned-symbol-in-an-outline.md)), a name that selects nothing
([3.48](./3.48-read-a-qualified-name-with-the-other-owner-separator-when-it-selects-nothing.md),
[3.49](./3.49-select-a-name-whose-last-part-holds-a-separator-by-its-longer-parts.md),
[4.18](./4.18-answer-a-name-that-selects-nothing-with-what-it-does-match.md)) and a type's unrecorded uses
([4.19](./4.19-name-a-language-that-records-no-use-of-a-type-in-a-type-s-references.md)).

## Why

- An agent reads a cut answer as complete unless the answer says what it cut, and picks its next call from what the
  answer holds (CLAUDE.md, `<answers>`); the engine counts each cut where it makes it.
- A count absent at zero keeps the bytes of an answer that cut nothing.

## Consequences

- A count says how much was cut, not which: an agent that needs those repeats the call wider. Accepted.

## Rejected

- **A data symbol's callers beside its users in the impact answers** — its users hold its callers, so a
  function-valued variable that is called would list each caller twice.

## Revisit if

A count stops riding on the work its answer already does, so it costs each call. Held: every count is taken where the
engine makes the cut.
