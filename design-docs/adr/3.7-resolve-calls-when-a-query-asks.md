# Resolve calls when a query asks

- **Status:** accepted
- **Date:** 2026-10-16
- **Revised:** 2026-10-19
- **Initiative:** `03-code-graph`

ADR 3.5 keeps the graph a file at a time and leaves open when its calls are resolved. A call names its callee as
written, `parse` or `lib.Parse` or `ns::Widget::draw`, and which definition that is depends on files other than the
caller's: the imports and includes of the caller's file, the package of its directory, every definition of the name in
the family. Resolving every call when a file goes in stores edges that a change to any of those files invalidates;
resolving the calls of a name when a query asks keeps every file's data its own.

**Calls and uses are resolved when a query asks, and no edge is stored.** A file's slot keeps what resolution reads:
its calls, local calls and uses as written, its includes, re-exports with the file each names, import bindings, package,
callable identities, folded declarations, the holders of its locals, and the parents of its types. The graph keeps, a
file at a time, the indexes that find them: definitions by name, in path order; for each call key, the last segment of
a callee as written, the files whose calls use it; for each name, the files whose uses name it; callable identities to
their occurrences; re-exported names to the names they are renamed to; and, where a package is a directory, the files
of each directory. `callers` resolves the call sites listed under the name of the selected callable, and keeps those
that land on it; `callees` resolves the sites of the callable's own body; `references` adds the uses of the name;
`call_path` walks callers from the far end.

**The cascade is one function of a call site and the graph.** A local call binds the local its scope declares. A
receiver that names an import binding binds an export of the bound directory and stops the cascade; an import of code
the graph does not hold binds nothing, and no later tier guesses at it. A callee written qualified binds the symbol of
that qualified name, the first in path order where several share it, then its trailing owner and name where the language
joins scopes with a separator, and a callee written from the owner alone, `Widget::Kind`, the member of that owner whose
longer qualified name ends in it, `ns::Widget::Kind`, the one the caller's file sees first. A receiver that names an
owner, `Widget.draw`, binds that owner's member before any scope, because the call names its owner outright and a
`draw` of another owner in the caller's file is not it; of owners of that name in several directories, the one in the
caller's file wins, then the one in its directory, as a package's own type beats a copy of it vendored elsewhere. A
receiver that is a value names no owner, and the extraction records the empty receiver for it: the parameters and
variables a Go caller declares (ADR 3.2), every C++ member-call operand but `this` (ADR 3.3), and the values a
TypeScript or JavaScript file declares (ADR 3.4). Otherwise the cascade looks in
the caller's file, its dot imports, its package directory, the files it includes, and the re-export chains of those
files, then — when the shape of the call admits a candidate at all — at a member of the caller's own owner (in Python
only on `self`, `cls` or `other`, in Ruby and Rust on `other`, and in daslang on `self`, revised below), the one
callable of the name, and the one callable in the caller's directory, its parent directory, and outside vendored code. A
dot import comes before the package directory for every call without a receiver: Go rejects a file whose package
declares a name a dot import also brings in, so the two meet only where they cannot both be in scope, as in a test
package beside the one it tests, where the dot import is. Each tier states a confidence, from 95 down to 15, public as
`kartta_graph::confidence`, so a caller sets a floor by the tier it trusts. What a tier needs from a language arrives as
extraction data or as `Conventions`: `directory_packages` gates the package tiers, `scope_separator` the qualified tiers
and the root-qualified calls, `include_reach` how far the include tier reads, the test flag keeps test code out of a
package's names, and the vendored flag out of the last proximity step. A file names its directory's package only when
it holds code outside test code, the first in path order. A re-export hop goes to the file the resolver named for its
specifier; a barrel that re-exports a name by name is not searched through its star re-exports for it, and the walk
searches each barrel once under each name, so a chain binds however many barrels rename it, and the callers of a
definition are looked up under every name a chain gives it.

**Files keep their path order however they arrive.** Path order is the file index's tree order, and the cascade and the
answers break their ties by it. The graph keeps its files in blocks of a few hundred, labelled with gaps, so an insert
out of that order renumbers one block, and every file only when a run of at least four thousand inserts at one place
uses up the room between two labels. Renumbering every file after the insert made a build grow with the square of the
files it took out of order: of 1.46M files, a shuffled build took 387 s that way; in blocks it takes 6.9 s, a reversed
one 1.9 s, and one in path order 1.0 s.

**A name with many definitions is indexed once per query.** On a Go monorepo, a call of `String` has 21,647
definitions of the name to choose among, and every one of the tiers above scans them: by owner for the receiver, by
directory for the package and proximity, by file for the includes. A query's cascade indexes the candidates of a name
with 64 definitions or more, once, by owner, directory, parent directory and file; a name with a definition local to a
body keeps a scan for the calls inside that body. On that monorepo, then of 119,888 Go files, this took
`callers(String)` from 6.5 s to 45 ms, and resolving all 5.87M Go call sites on one thread from 39 s to 3.2 s.

**An answer says what it left out.** A walk over callers or callees reports the symbols the cap turned away at the
symbol where it stopped, the symbols at the depth bound whose calls it did not follow, the symbols the confidence floor
dropped, each once where its calls collapse to the most confident, and the other callables the name selects that it did
not start from; the cap and the floor are tested after the visited check, so a walk that only meets symbols it already
holds is not cut and counts nothing. A walk over callees also counts the calls of its bodies that bound nothing, so a
body whose calls all reach code outside the graph does not read as a body that calls nothing. `references` reports the
sites the floor dropped and the total before its limit, the limit bounding the answer and not the work; `call_path` what
the cap turned away, the callers it reached at the depth bound, counted when reached so a chain found early leaves none
out, and the callers the floor dropped.

**Revised 2026-10-17: nearness binds a member call to no free function beyond the caller's parent directory.** The last
proximity step takes the one callable of a name outside vendored code anywhere in the family, and for a member call it
bound a free function there whenever that was the one: `line.trim()` the `trim` of an emscripten bundle, `JSON.parse()`
a `parse` of a bundled script, once the vendored copies of the name were left out. Nothing ties a free function that far
from the caller to what the receiver holds, so that step takes a member alone for a member call; the one definition of a
name still binds such a call wherever it lies, as a table's or a module's only function of the name does. In the
caller's directory and the one above it a free function can be what a value holds, because the extractions read an
object's property, a table's slot, a module that a name holds and a Rust path as free functions: jQuery UI calls the
`addClass` of the jQuery beside it, a Quirrel table hands out `mkContextMenuButton`, a Python script calls a module it
loaded by path. Where a language reads none of those as free, `Conventions::member_calls` is `MemberCalls::Members` and
a member call takes a member alone at every tier, the one definition of the name and the caller's file, package and
includes as much as nearness: a Go member call calls a method or a field of its value and reaches a function only
through an import, which binds before them. C++ calls no free function through a member call either, but keeps
`MemberCalls::NearbyFreeFunctions`: the members of a class whose head the extraction still cannot read,
`class [[nodiscard]] AABox`, are read as free functions, and the caller's file and includes are where a call on a value
reaches them. Once export-macro class heads parse (ADR 3.3), `MemberCalls::Members` on the C++ game-engine tree moves
22,658 sites from a free function to none, 5,188 of them at the two proximity steps, and loses 18,911 caller and callee
pairs by location while gaining 3,812. Of 30 sampled lost pairs 19 bound the method called, read as free, and 10 a
wrong free function, and of 30 gained about half bind the member called, so the switch would drop about 12,000 true
pairs to shed about 6,600 false ones. A later revision takes nearness from a C++ call on a value altogether. Measured
again on 2026-10-19, once class heads that macros and attributes hide parse, the switch drops 13,283 pairs, about 70%
of them true, and adds 4,117, about 60% true, so C++ keeps `MemberCalls::NearbyFreeFunctions`.

**Revised 2026-10-17: a member call binds no free value, and no free function for a method the runtime gives a
value.** The steps that let a member call take a free function also took a variable or a constant, which no property of
a value reads: `Date.now()` bound `const now = Date.now()`, `data.splice()` bound `var splice = arrayProto.splice`.
They also took a free function of a name that the runtime answers on the value itself: `line.trim()` the `trim` of a
bundled script, `name.slice(1)` the `slice` of a Quirrel string module, `ext.symbols.iter().find()` a Rust `fn find`.
A member call admits a free function and never a value, and `Conventions::runtime_methods` names, in ascending order,
the methods that a language's runtime gives its own values: ECMAScript's built-in objects and the DOM's interfaces for
TypeScript and JavaScript, the built-in types for Quirrel, the built-in types and the standard library's common values
for Python, and the standard library's methods and associated functions for Rust. A member call of a listed name takes
a member alone at every tier after the import binding its receiver may name, the re-export chains included. A receiver
that names an import binding names a module, not a value, and the module's export of the name is what the call
reaches: `strings.trim()` after `import * as strings` calls that module's `trim`. A free function that a barrel
re-exports is no more what a value holds than one an include defines. Lua binds no member call to a free function, and
daslang's method syntax calls free functions, so neither lists one; Go takes a member alone already, and C++ keeps the
guess above.

**Revised 2026-10-17: where includes are transitive, the include tier reads through the files the includes include.** A
C++ `#include` pastes the included text in place, so a file sees every header its headers include, and most C++ code
reaches the engine's logging, math and container headers through a module header of its own. Read through direct
includes alone, such a call fell to nearness or bound nothing, and nearness took a namesake in another namespace:
`debug()` bound a `statsd::debug` two directories away. Where `Conventions::include_reach` is
`IncludeReach::Transitive`, as C++'s is, and the files the caller's file includes offer no candidate, the one file of
those the includes reach in turn that offers the name binds at the include tier's 70, under the direct tier's rule: a
file that offers the name on two owners, or two files that offer it, leave the call to later tiers. Three limits keep
guesses out, each measured against what it turns away:

- A name more than 32 definitions share is read through direct includes alone, because its one definition among the
  files the includes reach is most often a namesake of code outside the graph. Raised to 64, the limit binds 6,659
  more caller and callee pairs, 14 of 20 sampled right, `Point3` constructors among them, and the rest an overload of
  another type where the template meant sits behind an `INLINE` macro the extraction does not read, `lerp` and
  `clamp`, or `eastl::function` for a call of a callable parameter named `function`; raised to 64 for member calls, 11
  of 20 sampled are right.
- A member call on a value takes a member alone there. A C++ member call reaches no free function, and a free function
  the closure offers it is either a member of a class whose head the extraction misreads, `DataBlock`'s
  `getBlockByNameEx` read as a free `getBlockByNameEx`, or a namesake, `ecs::getStr` for a `DataBlock`'s `getStr`: of
  20 sampled bindings to one, 13 are the first and 7 the second.
- A call whose receiver names an owner or an import is not read through includes: the receiver and import tiers answer
  it.

**Revised 2026-10-18: a use says how it touches its target and what its name is written on, and a member taken on a
value binds a field.** A use is marked a read, a write or an update, and its name is bare, qualified by a module, on
the enclosing member's own receiver, or on a value whose type a path spells. A member on a value binds through that
path at 85, else the one field of the name in the use's own file at 80, and a use the graph could not tell apart is
counted, not guessed. Uses stay unresolved until a query asks, in the 16 bytes a use took. ADR 3.34 records the
decision and its measurements.

**Revised 2026-10-19: a runtime method's call binds a member only where scope reaches it.** The lists kept a runtime
method's call to members, yet the one callable of the name and the members near the caller still bound a namesake of
the runtime's method. On the C++ tree a Quirrel array's `append()` bound a generated `OutputText.append` at 6,639
sites, and Python's `str.format()` bound a crashpad tool's `Identity.format` at 1,818. On the Go monorepo Rust's
`.as_str()` bound one `CallerRole::as_str` at 269 sites, and `String.replace()` a `Markdown.replace` at 135.

Such a call now binds a member only through:

- the caller's file, imports, package and includes;
- the caller's own owner, in Python only on `self`, `cls` or `other`, in Ruby and Rust on `other`, and in daslang on
  `self`;
- the one callable of the name, where the call's receiver spells that callable's owner in any case: `session.seek()`
  binds the one `seek`, `Session.seek`.

Otherwise it counts as not admitted. The reference engine binds the same namesakes: 3,402 callers of
`OutputText.append`, 511 of `Identity.format`, 232 of `CallerRole::as_str` and 102 of `Markdown.replace`. Its history
narrowed nearness three times for this kind of edge: abstaining between several near candidates, binding by the call's
shape, and binding no member for a bare call. It never narrowed by the method's name.

## Considered Options

- **Eager: resolve every site at build and store edges in both slots** — queries in microseconds, and a build that
  resolves every site whether any query asks, a transient peak 1.3 to 1.7 times the lazy one, edges kept beside the
  sites they came from, and on every change a re-resolution of each caller of every name the file defines, every file
  binding its directory and, for C++, every file that includes it: up to seconds of CPU per edit, and invalidation keys
  that must cover each tier a change can reach.
- **Lazy with a memo of resolved sites, invalidated by eager's keys** — repeated queries cost what eager's do, and the
  first query of a name pays what lazy's does; the gap it closes is the tail of lazy queries, under 0.3 s on these
  trees, at the price of eager's invalidation and a memo that grows with what is asked.
- **One slot per qualified name, the last in path order** — what a build in path order can keep, and what an insert or a
  removal cannot: the slot becomes a read over the name's definitions, a call target before any other, the first in path
  order, as a selected root is.
- **A hop bound on re-export chains and on the renames a caller is looked up under** — caps the work of one call, and
  drops without a count the callers a longer chain reaches, where the visited barrels already end every chain.
- **Dense path ranks renumbered on each insert** — one integer per file and no blocks, and a build out of path order
  that grows with the square of the files.
- **A member alone at every tier, in every language** — what Go takes, and elsewhere it unbinds what a value holds in
  the caller's own file and includes: 12,488 TypeScript and JavaScript pairs and 14,334 Quirrel pairs on the C++ tree,
  jQuery UI's `this._adjustDate()` to the `_adjustDate` its widget's object literal defines among them.
- **A member alone at every proximity step, in every language** — also unbinds the right calls that nearness finds: of
  the TypeScript and JavaScript sites it would unbind on the C++ tree, 941 call no runtime method, jQuery's methods
  from jQuery UI among them; Quirrel's table slots, Python's modules loaded by path, Rust's paths, and 2,047 C++ calls
  of members read as free, `m_Bounds.GetSize()` to `ImRect`'s, go with them.
- **A member call's shape from every candidate of the name** — keeps a free function wherever no member of the name
  exists, so `path.join()` still binds the `join` of a bundle and 511 of the 1,151 pairs only kartta held stay, while
  a member elsewhere unbinds a near function that a value holds.
- **A C++ call on a value binds a member of the caller's own class** — the reference engine's tier at 80, with or
  without the members its class inherits, before or after the include tier: at most 1 of 20 sampled is right, and
  before the include tier it takes the member called from 9 of 20.
- **A C++ call on a value guesses nearby, everywhere or where the caller's includes reach** — 3 and 7 of 20 right.
- **A member alone at the one callable of the name too** — unbinds the one definition of a name that a value holds:
  4,820 Quirrel pairs, among them `events.getEventByEconomicName()` to the function that `eventsState.nut` exports.
- **The runtime lists at the proximity steps alone** — leaves `(x * 0.5).tointeger()`, `"".join()` and
  `name.slice()` bound to a namesake by the caller's file, the one callable of the name and the includes: 12,656 of the
  16,182 sites the lists unbind on both trees.
- **The TypeScript and JavaScript list without the DOM's methods** — keeps the jQuery methods named like the DOM's,
  `find`, `closest`, `remove`, at the price of 1,338 more sites bound to a namesake, `document.body.appendChild()` among
  them.
- **A near free function only where the caller's file includes its file** — unbinds the right nearness binds with the
  wrong ones, jQuery UI's calls of jQuery and daslang's `log::info()`, and lets the members near the caller take 20,482
  more guesses, 18,909 of them at the last proximity step.
- **A member in either near directory before a free function** — unbinds 182 sites on both trees and leaves every
  runtime call with no member near it bound.
