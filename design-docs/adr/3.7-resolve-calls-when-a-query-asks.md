# Resolve calls when a query asks

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-22
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/resolve.rs`, `crates/kartta-graph/src/scope.rs`,
  `crates/kartta-graph/src/calls.rs`, `crates/kartta-graph/src/candidates.rs`, `crates/kartta-graph/src/confidence.rs`,
  `kartta_lang::Conventions`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`

A call names its callee as written, and which definition that is depends on files other than the caller's. Each file
keeps its call sites as written, and a query resolves the sites of the name it asks about, so no file's data goes stale
when another file changes; each query pays the resolution that a stored edge would pay once.

## Decision

**What the graph keeps.** Calls and uses are resolved when a query asks, and the graph stores no edge. A file's slot
keeps what resolution reads: its calls, local calls and uses as written, its includes, its re-exports with the file each
names, its import bindings, its package, its callable identities, its folded declarations, the holders of its locals and
the parents of its types. The graph keeps, a file at a time: definitions by name, in path order; for each call key, the
files whose calls use it; for each name, the files whose uses name it; callable identities to their occurrences;
re-exported names to the names they rename; and, where a package is a directory, the files of each directory. A call
key is the last segment of the callee as written;
[ADR 3.38](./3.38-list-a-call-under-the-last-part-of-its-callee-s-own-name.md) keys a callee that ends in a separator.
Path order breaks every tie, as [ADR 3.36](./3.36-keep-a-graph-s-files-in-path-order-through-labelled-blocks.md) keeps
it.

**What a query resolves.** `callers` resolves the sites listed under the selected callable's name and under every name
a re-export chain gives it, and keeps those that land on it. `callees` resolves the sites of the callable's own body.
`references` adds the uses of the name, which ADR 3.34 records. `call_path` walks callers from the far end.
[ADR 3.37](./3.37-count-what-a-call-walk-leaves-out.md) states what each answer counts of what it left out.

**The cascade.** A call binds at the first tier that binds it, with that tier's confidence from
`kartta_graph::confidence`, 95 down to 15, so a caller sets a floor by the tier it trusts. In order:

1. A local call binds the local its scope declares, at 80.
2. A receiver that names an import binding binds the target's export, at 95. A directory that exports no callable of
   the name, or an import of code the graph does not hold, ends the cascade with nothing bound.
   [ADR 3.45](./3.45-bind-a-call-through-a-module-s-file-as-the-module-s-paths-see-it.md) binds a target that is a
   module's file.
3. A receiver that is a type path binds the method of the type the path reaches, at 85 (ADR 3.29).
4. A callee written qualified binds, inside a namespace, the definition its innermost enclosing scope names that the
   caller's file sees, at 88; else the symbol of that qualified name, the first in path order, at 90; else its trailing
   owner and name where the language joins scopes with a separator, at 88. A callee written from its owner alone,
   `Widget::Kind`, binds the member of that owner whose longer qualified name ends in it, the one the caller's file sees
   first, at 88. A callee written from the root names a global symbol.
5. A receiver that names an owner binds that owner's member, at 85: the owner in the caller's file, then in its
   directory, then the first in path order.
   [ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md) binds the class a
   C++ operand is declared as, and
   [ADR 3.47](./3.47-bind-a-c-plus-plus-call-on-a-field-through-the-class-the-field-is-declared-as.md) the class of
   the caller's class's field a C++ call names.
6. Scope: the caller's file (80), its dot imports (95), a glob of a module's file (95, ADR 3.45), its package directory
   (75), the one file it includes that offers the name (70), and the re-export chains of those files (65). A file that
   offers the name on two owners, or two files that offer it, leave the call to the tiers below. Where a package is a
   directory, a bare call that these tiers do not bind binds nothing.
   [ADR 3.42](./3.42-read-transitive-includes-for-a-name-few-definitions-share.md) reads includes through the files
   they include.
7. Where the call's shape admits a candidate at all: a member of the caller's own owner (80,
   [ADR 3.41](./3.41-bind-the-caller-s-own-owner-only-on-the-receivers-a-language-lists.md)), the one callable of the
   name (60), then the nearest of the caller's directory (50), its parent directory (30) and the code outside vendored
   code (15) that holds a callable of the name: its one callable binds, and several bind nothing. These ADRs narrow
   what these tiers take:
   - [3.39](./3.39-bind-a-member-call-to-a-free-function-only-where-a-value-can-hold-one.md), a member call and a free
     function;
   - [3.40](./3.40-bind-a-runtime-method-s-call-only-to-a-member-that-scope-reaches.md), a runtime method;
   - [3.43](./3.43-guess-no-member-near-the-caller-for-a-c-plus-plus-call-on-a-value.md), a C++ call on a value;
   - [3.44](./3.44-bind-no-call-to-a-namespace-where-a-language-s-calls-name-none.md), a namespace;
   - [3.46](./3.46-bind-no-test-definition-by-name-for-a-call-from-outside-test-code.md), a test definition.

A dot import comes before the package directory for every call without a receiver. A receiver that is a value names no
owner; each language's extraction says what it records for one: TypeScript and JavaScript in
[ADR 3.101](./3.101-name-no-type-for-a-typescript-or-javascript-call-on-a-value-the-file-declares.md), Rust in
[ADR 3.56](./3.56-name-a-rust-call-s-receiver-only-where-its-syntax-spells-it.md) and
[ADR 3.55](./3.55-name-a-rust-method-call-s-receiver-by-its-parameter-s-declared-type.md), C++ in
[ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md), and Go in
[ADR 3.29](./3.29-name-a-go-receiver-by-the-type-its-declarations-spell.md).

**What a language supplies.** A tier reads extraction data and `Conventions`: `directory_packages` gates the package
tiers, `scope_separator` the qualified tiers and calls written from the root, and the rest of the fields the ADRs named
above; `own_members` and `inherited_members` decide what a bare call inside a member reaches, as their doc comments in
`crates/kartta-lang/src/language.rs` state. The test flag keeps test code out of a package's names, and the vendored
flag keeps vendored code out of the last proximity step. A file names its directory's package only where it holds code
outside test code, the first such file in path order.

**Re-exports.** A hop goes to the file the resolver named for the re-export's specifier. A barrel that re-exports a name
by name is not searched through its star re-exports for that name. Each barrel is searched once under each name, so a
chain of any length ends, and binds however many barrels rename it.

**Many definitions.** A query indexes the candidates of a name with 64 definitions or more once, by owner, directory,
parent directory and file, and every tier reads that index. A call inside a body that holds a definition of the name
local to it keeps a scan. Nothing a query derives outlives the query.

## Why

- An edge stored at build goes stale when any file the call read changes: the caller's imports and includes, its
  directory's package, every definition of the name. Re-resolving after one edit took up to 1.66 s of CPU on a Go
  monorepo of 79,964 Go files (2026-10-16).
- The tiers follow how a language's own scope finds a name, the surest first, and the confidence lets a caller drop the
  guesses.
- Every tier scans the definitions of the name: without the index, `callers(String)` and its 21,647 definitions took
  6.5 s, and take 45 ms with it (Go monorepo of 119,888 Go files, 2026-10-16).
- Listing each file once per call key, rather than each site, keeps that listing at 14 MB where per-site lists took
  72 MB on the same tree.
- Go rejects a package that declares a name a dot import also brings in, so a dot import and the package meet only in a
  test package beside the one it tests, where the dot import is meant.

## Consequences

- A query pays the resolution: `callers` of the 100 most-called Go names took at worst 264 ms on the Go monorepo of
  79,964 Go files, and `len`'s 279k sites 0.55 s when it held 119,888 (2026-10-16).
- The call sites and their indexes hold memory a graph of definitions alone does not: the live heap after a C++
  game-engine tree build grew from 246 MB to 486 MB.
- An unqualified C++ operator call binds by name, not through its argument types (#303).
- A namespace-relative C++ call written in a member function binds nothing (#457).

## Rejected

- **Resolve every call at build and store edges in both slots** — answers in microseconds, but resolves every site
  whether asked or not, peaks at up to 1.7 times the lazy footprint, keeps edges beside the sites, and re-resolves up
  to seconds of CPU per edit under invalidation keys that must cover every tier.
- **A memo of resolved sites, invalidated by eager's keys** — closes only the tail of lazy queries, under 0.3 s on the
  measured trees, at the price of eager's invalidation and a memo that grows with what is asked.
- **One slot per qualified name, the last in path order** — an insert or a removal cannot keep it, so the slot becomes
  a read over the name's definitions.
- **A hop bound on re-export chains and renames** — drops without a count the callers a longer chain reaches, where the
  visited barrels already end every chain.
- **A package index of every declared name** — took 51 MB on the Go monorepo of 119,888 Go files (2026-10-16), where
  the name index filtered by directory answers the same.

## Revisit if

A family's names carry enough call sites that a lazy `callers` of one exceeds a second, or agents' queries repeat the
same names often enough that a memo would pay for its invalidation. The first holds with margin on the measured trees,
whose worst name took 0.55 s; how often agents repeat a name is not measured.
