# Bind a runtime method's call to an included file's member only where its receiver or caller reaches the owner

- **Date:** 2026-10-23
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`offered`, `spelled_or_own`), `crates/kartta-graph/src/scope.rs`
  (`receiver_spells_owner`, `owner_derives_from`), `crates/kartta-lang-quirrel/src/lib.rs` and
  `crates/kartta-lang-jsts/src/lib.rs` (`CONVENTIONS`), `kartta_lang::IncludedRuntimeMembers`,
  `kartta_lang::Conventions::included_runtime_members`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`
  (`a_runtime_method_s_call_binds_an_included_member_its_receiver_spells_or_its_caller_s_owner_reaches`),
  `crates/kartta-languages/tests/quirrel_tables.rs`
  (`a_runtime_method_s_call_on_a_value_binds_no_member_of_an_imported_file`), `crates/kartta-languages/tests/engine.rs`
  (`a_javascript_runtime_method_s_call_binds_only_the_imported_member_its_receiver_spells`,
  `a_typescript_runtime_method_s_call_binds_an_imported_interface_s_member_on_any_value`)

A runtime method's call binds a member that scope reaches
([ADR 3.40](/design-docs/adr/3.40-runtime-method-calls.md)), and an include is part of that scope. In Quirrel,
TypeScript and JavaScript the values such a call is made on are most often the runtime's or the engine's own, so an
included file's member of the name binds only where the receiver or the caller's own owner reaches its owner, at the
price of the calls on instances of an included class whose names spell nothing.

## Decision

- **Spelled or own.** Where `Conventions::included_runtime_members` is `IncludedRuntimeMembers::SpelledOrOwn`, as it is
  for Quirrel, TypeScript and JavaScript, a member that a file the caller includes declares binds only where the
  receiver's last segment spells its owner in any case, the caller's own owner is that owner or derives from it, or the
  owner is an interface or a type alias: `obj.setValue(1)` binds no `PanelSettings.setValue` of an imported file,
  `panelSettings.setValue(1)` does, and so does `this.remove()` in a class derived from the member's; `$icon.get(0)`
  binds no imported class's `get`, and `drawer.open(1)` binds the `open` of an imported interface.
- **Any.** Every other language keeps `IncludedRuntimeMembers::Any`, where an included file's member binds as the
  caller's own file's does.

## Why

- A Quirrel script calls the engine's methods on the native values it holds, GUI objects and watched state, far more
  often than on the classes of the files it imports: of the 338 pairs the narrowed include tier unbinds on the
  game-engine tree, 38 of 40 sampled were such calls bound to a namesake (2026-10-23, #396).
- A JavaScript value a runtime method is called on is most often a Map, a Set, an array, `JSON` or a DOM node: of the
  pairs the narrowed include tier unbinds in SillyTavern, 36 of 39 sampled bound such a call to an imported class's
  namesake. An interface or a type alias makes no value, so a file imports one to type the values it holds: 26 of the 29
  pairs through one that the narrowing would unbind on the Go monorepo snapshot and react-hookz were right
  (2026-10-24).

## Consequences

- A Quirrel class a script defines in place of a native value loses the calls on its instances from other files,
  `gsid.get()` on the launcher's `Observable`, 14 pairs on the game-engine tree. Accepted.
- A TypeScript or JavaScript call on an instance of an imported class binds nothing where the value's name does not
  spell the class and the caller's class does not derive from it, `memoryCache.delete()` on a `new MemoryLimitedMap()`
  and `this.settings.save()`: about 1 in 9 of the pairs the narrowing unbinds in SillyTavern. Accepted.

## Rejected

- **The narrowed include tier for every language** — about two thirds of 30 sampled Python pairs it unbinds were right,
  calls on instances of an imported module's class (2026-10-23); Rust's `mod` files stay with #356.
- **The engine's every GUI-object method in Quirrel's list instead** — leaves the include tier binding `setValue` and
  `show`, which the list already names, and unbinds the scripts' own `isValid` and `isEmpty` with the engine's
  ([ADR 3.145](/design-docs/adr/3.145-quirrel-runtime-methods.md)): about half of 40 sampled were right (2026-10-23).
- **Keep an included owner the caller's file names anywhere** — the files that call `g_live_panel.show()` on a GUI
  object name the table too, so about a third of the 83 pairs it keeps are right (2026-10-23).
- **The narrowed include tier for an interface's and a type alias's members too** — unbinds 26 right pairs of 29 on
  the TypeScript trees, calls on the value a hook returns (2026-10-24).
- **Keep a TypeScript or JavaScript receiver an import of the owner's file binds** — no answer moves: such a receiver
  binds through its import before the include tier (2026-10-24).
- **Keep every named TypeScript or JavaScript receiver** — keeps 108 calls on the runtime's globals bound to a
  namesake, `JSON.parse()`, `console.log()` and `document.createElement()` (2026-10-24).
- **Narrow a class's members alone** — keeps 70 namesakes in minified libraries, `array.indexOf()` bound to an
  object's `indexOf` in `epub.min.js` (2026-10-24).

## Revisit if

A language's extraction records the type a value holds for its member calls, so that the type rather than the
receiver's spelling picks the included member, as [ADR 3.40](/design-docs/adr/3.40-runtime-method-calls.md) expects of
every runtime method's call. High confidence that the name alone stays unsafe.
