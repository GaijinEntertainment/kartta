# Read the class a Quirrel field of `this` holds from the writes its owner's body makes

- **Date:** 2026-11-01
- **Governs:** `crates/kartta-lang-quirrel/src/walk.rs` (`name_field_receivers`, `field_write`, `hold`, `built_class`,
  `file_name`)
- **Pinned by:** `crates/kartta-languages/tests/quirrel_field_receivers.rs`

A Quirrel call on a field of `this` names no owner, so it binds the caller's own member
([ADR 3.41](/design-docs/adr/3.41-own-owner-receivers.md)), though the field holds another class. A slot has no declared
type, and what the bytes do say sits in the writes around it, so the walk reads those writes and records the class they
build as the call's receiver. That binds the calls those writes settle, and it leaves every other field where it stood.

## Decision

- **The receiver.** A member call on `this.slot` records as its receiver the name the slot's value is built from, where
  the caller's owner is a class or a module table and every write that owner's body makes to `slot` settles on that one
  name. `slot = Part()` makes `this.slot.f()` a call on `Part`, which the receiver tiers then bind
  ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md),
  [ADR 3.193](/design-docs/adr/3.193-receiver-class-members.md)).
- **The writes read.** A slot in the owner's body, a default, and `this.slot =` in any function of the body, a function
  value inside a member among them, are the writes, and so is `this.slot <-` in a table's. A write on any other receiver
  is none.
- **What a write says.** `null` says nothing, so a field cleared with it keeps its class. A call of a bare name that no
  parameter or local of an enclosing function declares names that name. Any other value leaves the slot unnamed.
- **Two classes.** Writes that name two names, or a name beside any other value, leave the slot unnamed: the call keeps
  `this.slot` and the tiers of a receiver that names no owner.
- **The name.** The name must be one the file binds at file scope: a class, a `let` or `local` of anything but a
  function, a destructured name or a `from` import. A function returns a value of any class, whatever class shares its
  name. The walk does not know that any other name is a class, and the graph treats one that is none as a receiver that
  names no owner, as it treated the field.

## Why

- A script field takes whatever is written, with no check of its type (`SQInstance::Set`, `squirrel/sqclass.h`, at
  quirrel 19f17df9), and an annotation goes on a parameter, a return or a binding and names one of the base types
  (`doc/content/pages/language/annotations.md`), so the writes are the only type a field has in the bytes.
- An instance holds exactly the slots its class declares: a default is copied in (`SQInstance::SQInstance`,
  `squirrel/sqclass.cpp`) and `<-` on an instance throws unless its class's `_newslot` takes it (`SQVM::NewSlot`,
  `squirrel/sqvm.cpp:2653`; `doc/content/pages/language/classes.md`, Edge cases). A write therefore lands on a slot the
  class or a base declares, and `<-` says nothing of one.
- Of the game-engine tree's Quirrel, all 21 pairs the rule adds, all 65 it promotes to 85 and all 14 it removes read
  right against the source: a promoted or added pair's field is built from the class that holds the member, and a
  removed pair bound the caller's own member or a namesake (2026-11-01, #879).
- Only the walk holds the writes, and the graph already binds a receiver that names a class, inherited members included,
  so the extraction alone carries the rule: nothing is stored per field.
- A class the file binds no name for comes from the runtime or a star import. `Watched`, which the game's scripts take
  from the runtime, has a namesake in the compiler's bench, and all 5 pairs that bound it were false (2026-11-01, #879).

## Consequences

- A field set from a parameter names nothing, so its call keeps the caller's own member, wrong where the value is of
  another class: `WwArmyView.formation`, set from `constructor(v_formation)`, binds 16 such pairs. 115 pairs on
  `this.slot` stay at 80 on that tree, most of them on fields the bytes hold no type for (2026-11-01, #879). Accepted.
- A field a derived class writes stays unnamed in its base's calls, and the other way round, since the walk reads one
  owner's body: `WwFormation` reads `artilleryAmmo`, which `WwArmy` writes, in 4 pairs on that tree. Accepted.
- A write from outside the owner's body, `view.slot = Other()`, goes unseen, so the receiver can name a class the field
  no longer holds. Accepted.
- A class a file binds from a native module, `let { Watched } = require("frp")`, still reads a namesake in the tree, and
  so does a value a file binds under the name of a class elsewhere, `let Part = OtherClass`: telling the two from
  `let Part = require("part.nut")` takes reading another file. No pair of that tree turns on either. Accepted.
- A class built through a member, `this.slot = ui.Part()` or `::Part()`, or a default in an expression, `v || Part()`,
  names nothing. Accepted.

## Rejected

- **Store a value type per field and read it in the graph** — a stored value and a graph path for what a rewritten
  receiver binds; it reaches a field across a base, and the rule met the bar without it (#879).

## Revisit if

A language version lets an annotation name a class, or a field's write comes to reach across a base often enough to
move the bar. High confidence for the writes the rule reads.
