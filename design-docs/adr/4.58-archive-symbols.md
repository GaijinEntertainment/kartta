# Keep only the C ABI global in the macOS and Linux static libraries, and test each target's link command

- **Date:** 2026-11-02
- **Governs:** `crates/kartta-ffi/WIRE.md` (Linking), `scripts/ffi-archive.sh`, `scripts/link-check.sh`
- **Pinned by:** `scripts/link-check.sh`, in `scripts/dist.sh` on every target and in `scripts/go-musl.sh`

The archive defined tree-sitter, the grammars, blake3 and compiler-builtins under their own names, so a C consumer that
links its own tree-sitter could not link it. A step of the release build leaves `kartta_*` as the only global
definitions on macOS and Linux, and the table in `WIRE.md`, which every release build runs, is each consumer's link
line; the trade is one more tool step per target, and a Windows library that keeps its names.

## Decision

- **Global names.** `libkartta_ffi.a` defines the C ABI's functions and nothing else. Every other definition in it is
  local, which leaves a consumer free to link its own tree-sitter of any version.
- **The partial link.** `scripts/ffi-archive.sh` builds the archive of
  [ADR 4.49](/design-docs/adr/4.49-distribution-profile.md), links what the exports reach into one object, localizes the
  rest and archives that object: `cc -r` with `-exported_symbol` on macOS, `ld -r` then `objcopy --keep-global-symbol`
  on Linux.
- **Windows.** `kartta_ffi.lib` keeps every name. `LINK` makes only an image, and `lld-link` lists no partial link, so
  the members cannot merge, and a name made local in one member would leave the others unresolved.
- **Link commands.** The Linking table of `WIRE.md` holds each target's commands, in the file that ships beside the
  archive. They come from the links run, not from `rustc --print native-static-libs`.
- **The check.** `scripts/link-check.sh` runs every row of its target, and runs the program, in a directory laid out as
  a tarball unpacks: the unpacked tarball itself in `scripts/dist.sh`, the build directory in `scripts/go-musl.sh`.
  Outside Windows it links each row again beside a C file that defines `ts_parser_new`.

## Why

- On the shipped archives, `ts_parser_new` in a C program fails with `multiple definition` under GNU ld on Linux arm64,
  glibc and musl, and with `1 duplicate symbols` under ld64 on macOS (2026-11-02). Each holds 5 `kartta_` definitions
  beside 259 `ts_`, 97 `tree_sitter_` and hundreds of others.
- Code tools are the integrators likeliest to hold tree-sitter.
- A partial link of the whole archive pulls what no export reaches, and adds 1.3 MB to a linked program on macOS.
  Pulling only what the exports reach leaves that program's size, and the archive falls from 38.3 MB to 31.2 MB.
- On musl, rustc's line names `-lunwind`, and gcc on Alpine answers `cannot find -lunwind`.

## Consequences

- A tool that links its own tree-sitter meets the Windows library's 259 `ts_` and 97 `tree_sitter_` names beside the 5
  `kartta_` ones. No `link.exe` run has tried that clash. Accepted for 1.0 (#1122).
- A debug archive of `cargo build` keeps every name; only `scripts/ffi-archive.sh` hides them.
- Local names stay in the archive's symbol table, so a linked program's size is the consumer's to strip. Accepted.
- A pull request reaches a non-musl row only through `.github/workflows/release.yml`, which does not feed `ci-ok`, and
  only when it touches the paths that job names. Accepted, as in
  [ADR 4.55](/design-docs/adr/4.55-release-workflow.md).

## Rejected

- **Documenting the clash** — a tool with its own tree-sitter could not link kartta at all.
- **A shared library** — [ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md) rejected one, and it adds an artifact per target.
- **`--whole-archive` or `-force_load` in the partial link** — a linked program grows, and `-dead_strip` cannot run with
  `-r`.
- **`llvm-objcopy` on the Windows library** — it refuses `--keep-global-symbol`, `--localize-symbol` and
  `--prefix-symbols` on COFF, and refuses this `.lib` whole for `--redefine-syms`, since the library holds short import
  members (`llvm-objcopy` 19.1.7).
- **`rustc --print native-static-libs` as the table** — the line does not link on Alpine.

## Revisit if

A Windows consumer needs its own tree-sitter, or a linker refuses a partially linked object. High confidence on macOS
and on Linux arm64, where the check and a caught panic ran; medium on x64 Linux until a release build runs them, and on
the Windows row, which only that run tries.
