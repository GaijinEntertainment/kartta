# Name the type alias a parent's lookup reaches

- **Date:** 2026-10-23
- **Governs:** `crates/kartta-graph/src/implementations.rs`, `kartta_graph::is_parent`
- **Pinned by:** `crates/kartta-graph/tests/graph/implementations.rs`
  (`a_parent_names_the_alias_its_scopes_reach_and_not_the_aliased_type`,
  `a_struct_that_namesakes_an_alias_keeps_only_its_own_copys_implementors`)

A C++ base is often written through a typedef, as `struct is_void : true_type` inside `namespace eastl`. A parent that
reaches a type alias names the alias, and the alias's implementors are its own; a query of the aliased type does not
count the alias's derivers.

## Decision

- **Aliases are parents.** A type alias is a type that a name selects for `implementations` (`is_parent` admits it) and
  that every parent lookup of [ADR 3.20](/design-docs/adr/3.20-implementor-resolution.md) reaches, as it reaches a
  class.
- **Alias implementors.** An alias's implementors are the types whose parent reaches the alias. They are not
  implementors of the type the alias names, and the alias is not one.
- **Inherited members.** The call queries' lookup of a type's bases for inherited members counts no alias: an alias has
  no body for a member to come from.
- **A struct and an alias of one name.** Where one file declares a struct and an alias of one qualified name, as C's
  `typedef struct S {} S;`, the name selects both and the answer counts the one it did not take among those it passed
  over.

## Why

- Before aliases counted, the lookup reached no type for `true_type` inside `eastl`, fell back to the nearest type of
  the name and credited each doctest copy's `true_type` struct tied there, while no query selected `eastl::true_type`.
- Of the C++ implementors that moved to an alias on the game-engine tree, all 30 sampled were right
  (2026-10-23, #171).

## Consequences

- A name many aliases share costs what one many classes share costs: `CppType::Type`, shared by 1,255 aliases of the
  Vulkan headers, takes 0.35 s. Accepted.
- A parent's template arguments are dropped before the lookup, so a parent that writes them can reach a non-template
  alias, which no argument fits: 18 of 31,742 one-deep C++ implementor pairs on the game-engine tree, all false, and
  no template lost a child to them (2026-10-31, #454). A template alias takes such a parent rightly.
- An agent that asks for the aliased type does not see the alias's derivers; it asks for the alias. The class a C++
  alias records
  ([ADR 3.75](/design-docs/adr/3.75-cpp-call-receivers.md)) is read by the
  call queries alone. Accepted.

## Rejected

- **Count an alias only where a lookup reaches it** — the alias shadows its namesakes, which no longer take its
  derivers, while no query selects it: 786 C++ implementors went to no type.
- **Credit nothing where a lookup reaches an alias** — `find_implementations true_type` fell from 317 to 9, and the
  answer counted none of the derivers it left out.
- **Make an alias an implementor of the type it aliases** — 39,857 more direct implementors on the game-engine tree,
  every `using NativeType = VkFoo` among them, and the implementors credited to several namesakes rose from 834 to
  5,691, as each copy's alias of a vendored type took every copy of it.
- **Pass over every alias for a parent written with template arguments** — takes 110 one-deep pairs from template
  aliases, which those arguments fit, and credits 30 pairs to far namesakes on the game-engine tree (#454).

## Revisit if

Agents ask for a type that aliases name and miss the aliases' derivers, which the class an alias records would let a
query count without listing the alias. Not planned.
