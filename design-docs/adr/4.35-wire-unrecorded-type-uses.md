# Flag a type's references where its language records no use as a type

- **Status:** accepted
- **Date:** 2026-10-20
- **Updated:** 2026-10-20
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-ffi/src/wire/graph.rs` (`ReferencesView`), `bindings/go/wire/graph.go`
  (`References.TypeUsesUnrecorded`)
- **Pinned by:** `crates/kartta-ffi/tests/golden/references.json`

Several languages record no use of a type where code names it as one, so a `references` answer of ADR 4.2 for such a
type held no site and a `total` of 0, which a consumer reads as an unused type. The part says so with one flag, read
from what the graph already holds, so only the parts it is true of grow.

## Decision

- A `references` part whose `symbol` is a type, by `SymbolKind::is_type`, in a graph whose conventions state
  `TypeUses::Nowhere` (ADR 3.1), carries `type_uses_unrecorded`, true: its `sites` hold only the calls that name the
  type and, where the language records them, its reads as a value. Rust, C and C++, TypeScript and JavaScript, PHP,
  Ruby, daslang and Puppet state it.
- The key is absent otherwise: for the part of a type whose language records some or every use of one, as Go, Python,
  DSHL and Quirrel do, and for every symbol that is no type. A language that records some uses, as Python records an
  annotation inside a body, carries no key: its sites hold the uses it records.
- `SymbolKind::is_type` is the test the graph tells a type by, which the MCP tools read too
  ([ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md)), so both surfaces tell
  a type the same way.
- Go's `wire.References.TypeUsesUnrecorded` and the TypeScript type carry it.

## Why

- What a consumer acts on is whether one part's `sites` can stand for every use of the type. A flag on the part reads
  the answer the consumer holds and needs no list of kartta's languages, which would fall behind them.
- Every type the key marked in the samples was true, 27 of 27 distinct types (C++ game-engine tree and Go monorepo
  snapshot, 2026-10-20).
- The test costs a read of the graph's conventions and a match on the symbol's kind per part, with no allocation.

## Consequences

A type in a `Nowhere` language still answers no site for its uses as a type; the flag says the sites are partial, not
where the uses are: accepted.

## Rejected

- **The conventions' label on every type's part, `type_uses` as `nowhere`, `partial` or `every`** — every Go and Python
  type's part gains a key, and a consumer learns what each label leaves out to act on the one value that matters.
- **The conventions per graph in `stats`** — a consumer joins them to each part by its graph and has to know they bear
  on a type's sites alone.
- **A note in words, as the MCP answer carries** — the wire answers facts a program reads;
  [ADR 4.19](/design-docs/adr/4.19-unrecorded-type-uses.md) words them for an agent.

## Revisit if

Every shipped language records the uses of a type as a type, so no graph states `TypeUses::Nowhere`. High confidence:
seven language families state it today.
