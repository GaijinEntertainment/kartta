# Reach the engine from Node through an addon over the same dispatch

- **Status:** accepted
- **Date:** 2026-10-18
- **Revised:** 2026-10-21
- **Initiative:** `04-consumer-surfaces`

Node consumers reach the engine through a napi-rs addon that calls `kartta-ffi`'s dispatch directly, through its rlib
(ADR 4.2): the method table, the error codes and the wire stay in that crate, and the addon translates nothing. The
npm package `kartta` in `bindings/node` types the wire in TypeScript and owns the JavaScript side of the lifecycle:
the ids of the builds, greps and refreshes, the signal, and closing.

## The addon

`crates/kartta-node` is a `cdylib`, `publish = false`: npm is its channel. It answers five calls, each taking the
wire's params as a JSON string and answering the wire's envelope as the dispatch's bytes in a `Buffer`, which the
package decodes as it parses.

- **`build` and `refresh` each run on a thread of their own** and settle a promise. A walk of three million entries
  takes tens of seconds, and libuv's pool has four threads that every `fs` call of the process shares. Revised
  2026-10-21: `refresh` is new (ADR 4.2), and runs as `build` does, under an id the package gives it, which `close`
  cancels whether or not the refresh has entered the library, within the latest 1,024. A whole refresh holds its
  thread for seconds on a large tree, 6.4–8.0 s over 2.9 million entries, which on the pool would stall the process's
  file I/O as a build would.
- **Every other method runs on libuv's pool,** as a napi `AsyncTask`. A query is short, but a grep over the whole tree
  is not, and neither holds the event loop. Revised 2026-10-21: a grep runs there under an id the package gives it,
  which `close` cancels whether or not the grep has entered the library, within the latest 1,024. A grep still queued
  for a pool thread holds its own reference to the engine, and `close`'s `cancel {}` trips only the calls that have
  entered, so it ran in full after `close`, as did one waiting in the library for a refresh under way. A grep queued
  behind four busy pool threads answered 9.5–16.0 s after `close` over dagor's 182,714 entries, having read all 168,876
  files, and 35.6–36.8 s over a directory of checkouts of 465,682 entries, having read 388,308; under an id it answers
  as soon as a pool thread takes it, cancelled, every candidate unsearched. The id costs a map entry per grep in
  flight: a grep's median call on the fixture took 101–348 µs, against 105–348 µs without it, under the same load.
- **`cancel` answers at once on the calling thread,** so a cancel is never queued behind the work it stops.
- **`open` answers the handle or the wire's error object,** never a napi error, whose code would be napi's status rather
  than the wire's.
- **`close` drops the handle's engine;** a call in flight holds its own reference and returns first, and the engine
  goes with the last of them. A handle the garbage collector takes frees its engine the same way.
- **A panic answers `internal`:** `Kartta::call` catches it itself, so the addon carries no guard of its own.

## The package

- **One typed call per wire method,** named in camelCase, its params and answer spelled field for field as the wire
  spells them, the shape the Go binding reads. Renaming every field would copy every answer and part the types from
  the golden files. `call(method, params)` reaches the wire untyped; it runs `build`, `grep` and `refresh` as the typed
  calls do, under a binding id the handle picks in place of any the params give, and `cancel` at once. Revised
  2026-10-21: `grep` too. Revised 2026-10-21: `call` replaced the `id` the params gave with one the handle picked,
  so a cancel by the caller's id stopped nothing and stayed remembered against the call the handle later gave that
  id. The handle names its own calls by `binding_id` and passes the `id` a caller gives on as it is, in `call`'s
  params and in a typed call's options alike, the one rule both bindings follow (ADR 4.2).
- **Failures reject with a `KarttaError`** carrying the wire's code, or `closed`, the binding's own, for a call on a
  closed handle.
- **`build(options, { signal })`** gives each build a binding id; an abort cancels that binding id, so it stops the
  build waiting or running, and the rejection carries the signal's reason as its cause. A signal aborted before the
  call rejects with its reason and leaves the handle as it was, as a done context does in the Go binding.
- **`refresh(options, { signal })`** does the same under ids of its own, which the library keeps apart from the
  builds' (ADR 4.2), except that a cancel stops a refresh only before its walk ends: a refresh it stops rejects with
  `refresh_cancelled`, and one past its walk answers what it changed. Revised 2026-10-21: the method is new.
- **`grep(options, { signal })`** does the same under ids of its own, except that a grep an abort stops answers what it
  covered, `cancelled` set and the files it did not open counted `unsearched`, as the wire answers a cancelled grep
  (ADR 4.2), and one that opened its last file answers whole. Revised 2026-10-21: a grep took the id its params gave;
  the handle names it by one of its own, so that `close` can name every grep, and the signal is how a caller stops
  one. Revised 2026-10-21: the handle's own is its `binding_id`, and the `id` the params give passes on.
- **`close` cancels each build, grep and refresh in flight by its binding id,** which the library remembers for a call
  that has not entered, then every build, grep and refresh that has, then drops the handle. A build it cancels rejects
  with `build_cancelled` and a refresh it stops with `refresh_cancelled`, a `closed` error the cause of each; a refresh
  past its walk answers, and a grep answers what it covered. Revised 2026-10-19: the library remembers the last 1,024
  ids (ADR 4.2), so a `close` that lands while more than 1,024 builds have yet to enter leaves all but the latest 1,024
  of them running. Revised 2026-10-21: the same holds of the refreshes and of the greps, each apart from the others.
  Revised 2026-10-21: and of the binding ids apart from the ids callers give, so a caller's stale cancels never push
  out those a `close` sent ahead.
- **The wire types are checked against the golden files at compile time:** the type check fails, naming the field,
  when a golden answer or params hold a field the type does not name, and when a golden answer is not of its type. The
  tests replay every golden file through its typed call and compare the answer exactly but a `score`, which agrees
  when it is within a relative 1e-12 of the pinned one, and check that the typed calls cover the methods `version`
  lists. Revised 2026-10-21: the scores were compared exactly too, which an OS whose libm rounds `ln_1p` apart from
  the blessing one's fails (ADR 4.2).
- **Each answer is decoded and parsed on the event loop** with `JSON.parse`, the only step that runs there. Its cost
  follows the answer's size: kilobytes for a capped answer, more for a grep or a listing whose cap the caller lifted.

## Platforms and distribution

The addon ships for macOS on arm64 and for Linux with glibc on x64 and arm64, each built and tested in CI on its own
runner. N-API is stable across Node majors, so one build per target serves every Node the package supports.

- **One package per target,** `kartta-<target>` with `os`, `cpu` and `libc` set, holding `kartta.<target>.node`: the
  naming napi-rs's tooling uses. Their manifests are committed under `bindings/node/npm`. The package loads the file a
  checkout builds beside it, then the target's package. A release adds the targets' packages to the package's
  `optionalDependencies` at its own version and publishes each; nothing is published yet.
- **Left out:** Windows, which no consumer asks for and which nothing here tests; and Linux with musl, whose Rust
  target links the C runtime statically and builds no shared library until told not to.
- **Node:** `engines` asks for 24 or later; CI runs the version `.nvmrc` pins, which runs the tests' TypeScript without
  a build step. Revised 2026-10-20: vitest transforms the tests' TypeScript itself, and the pinned Node runs
  `scripts/build.ts` as it stands. The floor stays at 24, the newest LTS line, with `@types/node` at that line's newest
  release; the floor and the types move together.
- **Pinning:** napi, napi-derive and napi-build resolve through `Cargo.lock`; `typescript` and `@types/node` are exact
  in `package.json`, with the lockfile committed and installed with `npm ci --ignore-scripts`. `npm run build` is a
  script of forty lines over `cargo build`; `@napi-rs/cli` would bring its own tree, a GitHub client and cross
  toolchains among it, for the same file copy. Revised 2026-10-20: `vite-plus` and `@ver0/oxlint-config` are exact as
  well, and the script runs as `vp run build`.

**Revised 2026-10-20: the package formats, lints and tests through Vite+.** The maintainers' other packages run their
toolchain through `vp`, the CLI of `vite-plus`, and so does this one. `vp fmt` formats with oxfmt, and `vp lint` lints
with oxlint and oxlint-tsgolint under the javascript, typescript, node and vitest presets of `@ver0/oxlint-config`, both
set in `vite.config.ts`; `vp test` runs the tests on the vitest `vite-plus` pins, in place of `node:test`. `tsc` still
type-checks and emits the declarations; it skips the libraries' declarations, because vitest's name DOM types a Node
project has no lib for. CI takes `vp` from `node_modules/.bin`, so the toolchain's version is the lockfile's.

## Considered Options

- **koffi over the C ABI** — no Rust for Node, but a third party's native addon in the process, hand-written types, and
  every answer freed by hand.
- **`node:ffi`** — experimental, absent from Node 24, and synchronous only.
- **The signal handled in the addon** — napi's `AsyncTask::with_signal` only drops a task that has not started; the
  build's id, cancelled from JavaScript, stops one running or waiting alike.
- **Builds on libuv's pool** — a build holds a pool thread for its whole walk, and four of them stall the process's file
  I/O and every cancel queued behind them.
- **A refresh on libuv's pool, as a query** — with no id, `close`'s `cancel {}` trips only the calls that have entered
  the library, so a refresh still queued for a pool thread runs in full after it, and an abort has nothing to name it
  by. Given an id, it would still hold a pool thread for the whole refresh.
- **A grep stopped by `cancel {}` alone** — it trips only the greps that have entered the library, so `close` left a
  grep queued for a pool thread, or waiting for a refresh under way, to run in full.
- **`@napi-rs/cli` with its generated loader** — a loader for every platform napi-rs knows, regenerated on each build,
  where the package loads three targets in a dozen lines.
- **`voidzero-dev/setup-vp` in CI** — the action the maintainers' other packages set Vite+ up with: one more action to
  pin, whose `vp` would hand each command to the lockfile's `vite-plus` all the same.
