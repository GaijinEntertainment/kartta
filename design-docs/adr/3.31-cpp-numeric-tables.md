# Parse a C or C++ table without its numbers, and hold one tree at a time

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-22
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-cpp/src/repair.rs` (`for_parse`, `scan_data`, `DATA_GROUP_MIN`),
  `crates/kartta-lang-cpp/src/lib.rs` (`extract`)
- **Pinned by:** the tests of `crates/kartta-lang-cpp/src/repair.rs` named for a table, and
  `crates/kartta-lang-cpp/tests/tree_memory.rs`
  (`a_reparse_after_recovery_never_holds_the_first_tree_beside_the_second`)

tree-sitter keeps a node for every literal of an initializer, so a large numeric table parses into far more tree than
the file holds, and the largest such trees set a build's peak. A table's numbers are blanked before the C++ parse and an
extraction holds one tree at a time, at the price of a scan of each brace group's bytes and a copy of each file that
holds such a table.

## Decision

**A brace group of 4 KiB or more that holds only numeric data is blanked before the first parse.** Numeric data is
numeric literals, with their signs, suffixes, exponents and digit separators, between commas, whitespace, comments and
nested groups of the same. The group keeps its braces and every newline and loses the rest, as every repair of
[ADR 3.3](/design-docs/adr/3.3-cpp-parse-repair.md) does, so each line and byte offset outside it stays
where it was, and the extraction reads every name and signature from the original bytes.

**One scan judges each brace once.** The scan that opens at a brace runs until a byte that is no numeric data. A group
that turns out to name something keeps blanked the outermost all-numeric groups of 4 KiB or more that closed inside it
before that byte, and a brace before the scan's end is not judged again.

**In a parser tree-sitter generates for a grammar**, the group may also hold names, macro calls, designators, strings
and character literals: [ADR 3.165](/design-docs/adr/3.165-generated-parser-tables.md).

**The extraction frees the first tree before the second parse** of the repairs that read the first tree, those of
ADR 3.3 and [ADR 3.71](/design-docs/adr/3.71-cpp-brace-splitting-conditionals.md). Where the second
parse yields no tree, the first copy is parsed again, and that tree is walked.

## Why

- The trees follow what a file holds, not its size: on the game-engine tree a 30 MB table of network weights parsed
  into 586 MB of trees and held two definitions (2026-10-18). tree-sitter allocates its trees through the C library,
  where a profiler of the Rust heap does not see them, so this peak stayed after
  [ADR 1.67](/design-docs/adr/1.67-extraction-memory.md).
- No definition, call or use is written among a table's literals, so blanking them changes no answer.
- A large table after a syntax error defeats tree-sitter's error recovery for the whole file: dav1d's `tables.c`
  declares a table through a macro-wrapped declarator, and its 20 definitions are extracted only with the table blanked.
- A file the repairs parse twice held both of its trees at once; freed, the largest tree left on the game-engine tree is
  code, the Vulkan header's 95 MB (2026-10-18).

## Consequences

- A file that holds such a table pays a copy of its bytes for the repaired text. Accepted.
- A table of 4 KiB or more that spells one name outside a generated parser parses in full, every literal a node.
  Accepted.
- The answers are those of the file parsed as written, but where a table had defeated the error recovery: those files
  gain their definitions.

## Rejected

- **Parse files of 1 MiB or more one at a time** — once the tables are blanked, the large trees left are rarely live at
  once, and the gate moved the peak by under 2%.
- **Leave a file above a size unparsed, held in the index and counted** — the peak is the blanking's, and above 4 MiB
  nine files of the game-engine tree lose 13,698 definitions.
- **Leave unparsed a file of 1 MiB or more whose first 64 KiB are 90% numeric literals** — the same peak, and the six
  tables it catches take 9 definitions, 10 call sites and an edge with them.
- **Blank only** — the game-engine tree's build peak is the same, but a file parsed twice holds both of its trees: the
  Vulkan header 187 MB against 95 MB with the first freed.
- **Free the first tree only** — the peak stays at the tables' trees.
- **Blank groups of 64 bytes or more** — two more files of the game-engine tree gain one definition each, the peak is
  the same, and each file with such a group pays a copy of its bytes.

## Revisit if

A tree kartta serves peaks again at the parse tree of a table this rule leaves, one that spells names outside a
generated parser. Medium confidence: the largest tree left on the game-engine tree is code (2026-10-18).
