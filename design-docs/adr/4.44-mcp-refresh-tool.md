# Refresh on request, and list what the tree fails now

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-mcp/src/server.rs` (the `refresh` tool), `crates/kartta-mcp/src/render.rs` (`refresh`,
  `failures`), `kartta::replace_failures`
- **Pinned by:** `crates/kartta-mcp/tests/refresh.rs`, `crates/kartta-mcp/src/state.rs`
  (`a_failure_names_its_path_from_the_root`)

The MCP server's index follows its tree ([ADR 4.4](/design-docs/adr/4.4-mcp-index-follow.md)), but a watch can be
off, and some changes raise no notification. A `refresh` tool takes those in and says what it changed, and every
refresh replaces the failures of the parts it walked, so the failures an answer lists are the tree's now; the trade is
a pathless failure that stays until a whole refresh.

## Decision

- **What it takes in.** The `refresh` tool takes in what the watch does not: any change while the watch is off, and a
  change made where notifications do not reach, such as a network mount or a container bind mount. Its description
  names `watch="off: <reason>"` as the cue.
- **Paths.** It takes optional repo-relative `paths` with `/` between names, none for the whole tree, and a path need
  not be held, since a refresh is how a new one comes in. It refuses the call, refreshing nothing, when a path starts
  with `/` or `\`, starts with a drive such as `C:`, or holds a `\` or a `..` name; the error names the path's fault by
  the check the other tools' path arguments use ([ADR 4.61](/design-docs/adr/4.61-mcp-path-arguments.md)), and how to
  pass it.
- **The answer.** It answers a `<refresh>` envelope: `walked`, the number of parts walked again or `tree`; each only
  when it is not zero, `added`, `removed`, `extracted`, `resolved_again` and `dropped`; `reconfigured`, the families
  resolved again, and `rebuilt`, when they hold; and, only when the paths named came to more parts than the engine
  walks apart, so it walked the tree, `widened`, the number of paths named, `parts`, the parts they came to, and
  `limit` ([ADR 3.80](/design-docs/adr/3.80-named-refresh-widening.md)); `elapsed_ms`; and the refresh's failures as
  `<errors>`, five listed and the rest counted. A refresh that changed nothing and failed nothing says so.
- **Failures replaced.** `kartta::replace_failures` replaces the stored failures under the parts a refresh walked, the
  follow's included, and those it met again, so the index answer's list holds a path once. A failure that names no
  path in the tree, such as an unwritable cache, stays until a whole refresh or until a refresh meets it again. The
  index answer lists five and counts the rest.

## Why

- A watch that is off or stopped, and a change notifications never report, would otherwise leave no recovery short of
  a rebuild, 13 s on the C++ game-engine tree (2026-10-18, #80).
- The parts a widened refresh came to tell an agent how far past the limit a call went and whether naming fewer paths
  would have kept it apart: 60 paths inside an ignored `target/` are one part, and 60 files of a source directory are
  60. The engine works the parts out before it chooses to walk the tree, so `parts` adds no work to a call.
- The list is bounded by the paths the tree fails, however many refreshes a watch drives.
- The index splits a path on `/` alone, so a drive or a `\` path, as a Windows editor shows it, reads as one name at the
  root, matches nothing, and the refresh answered that nothing changed (#498).

## Consequences

- A failure that names no path stays listed after its cause is gone, until a whole refresh or a refresh meets it
  again. Accepted.
- A file whose name holds a `\` or starts with a drive, legal outside Windows, cannot be named; a whole refresh still
  takes it in. Accepted.

## Rejected

- **No `refresh` tool** — a watch that is off or stopped, and a change notifications never report, would leave no
  recovery short of a rebuild.
- **Append each refresh's failures** — the list would grow with every refresh a watch drives and keep failures the tree
  no longer has.
- **Read a `\` as `/`** — it guesses at what the agent meant, refreshes the wrong part of a tree that holds a name with
  a `\`, and leaves the drive path unanswered.

## Revisit if

Notifications come to reach every place a followed tree lives, network and container bind mounts included, and a
watch can no longer be off. Low confidence that both will hold.
