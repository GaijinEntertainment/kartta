# Ship kartta-fs on the newest notify release candidate

- **Date:** 2026-10-20
- **Governs:** `crates/kartta-fs/Cargo.toml` (`notify`), `crates/kartta-fs/src/watch/notified.rs`

The macOS and Windows watcher of [ADR 1.17](/design-docs/adr/1.17-change-notifications.md) goes through
notify, and the one notify that reports an overflowed Windows buffer is the unreleased 9.0 line. kartta-fs 1.0 requires
the newest 9.0 candidate under a caret requirement, so the lock CI tests holds what a fresh downstream build takes; the
trade is that a downstream build takes every later candidate and 9.x release unasked.

## Decision

- **The requirement.** kartta-fs requires `notify = "9.0.0-rc.6"`, the newest candidate on crates.io, as a caret
  requirement, optional under the `watch` feature and built only for macOS and Windows. Linux builds no notify.
- **Upgrades.** Move to 9.0.0 once crates.io publishes it, and to a later candidate before then. Before raising the
  requirement and the lock, check in notify's changelog that a Windows completion with no bytes, or
  `ERROR_NOTIFY_ENUM_DIR`, is still a rescan that names no path; that an `FSEvents` rescan still names the directory the
  system names; that an `FSEvents` root change still carries the `root changed` info; and that a deleted Windows root is
  still reported as the removal of its path. Then run the watch tests, on Windows through CI.

## Why

- notify 8.2.0, the newest release, ignores the byte count a Windows completion reports, so an overflowed buffer loses
  its changes with no sign; the 9.0 candidate reports it as a rescan, which the watcher turns into a lost batch.
- A requirement on a candidate is a caret one: a downstream build that resolves afresh takes every later candidate, and
  9.0.0 and each 9.x release once published, whatever this repository's lock holds (#127). Naming the newest candidate
  keeps CI on the version a new consumer downloads.
- A later version that changes what the watcher calls fails that build, and one that changes what a rescan or a root
  change means changes the watcher's answers; the checks above are the meanings the watcher reads.

## Consequences

- A notify release that breaks the build or changes a meaning reaches downstream builds before this repository sees
  it, and costs a release of kartta-fs. Accepted.

## Rejected

- **notify 8.2.0 everywhere** — the silent loss of an overflowed Windows buffer, and on Linux an event for every open
  and close: one read of every file on 1.8 million entries raised 1,690,730 of them, past a distribution's queue.
- **notify 8.2.0 on Windows alone** — back to the silent loss the candidate was taken for, with two major versions of
  one crate to keep.
- **An exact `=9.0.0-rc.6` requirement** — Cargo keeps one version of a crate per compatible range, so a consumer that
  requires any other notify 9, 9.0.0 included, fails to resolve, and no consumer takes a notify fix without a release
  of kartta-fs.
- **Own `FSEvents` and `ReadDirectoryChangesW` backends** — the same system calls the crate makes, as unsafe code to
  keep, for no measured difference, and the Windows backend would be code only CI runs.

## Revisit if

notify publishes 9.0.0, or a candidate after rc.6. High confidence that one will come, with no date.
