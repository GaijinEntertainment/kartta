# Extract only the daslang a file opts into gen2

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-daslang/src/walk.rs` (`opts_into_gen2`)
- **Pinned by:** `crates/kartta-lang-daslang/tests/extract.rs` (`a_file_without_the_gen2_option_extracts_to_nothing`,
  `each_spelling_of_the_gen2_option_opts_in`)

Daslang has two syntaxes, and the only tree-sitter grammar, `tree-sitter-daslang`, reads the second generation alone. A
file that does not opt into gen2 extracts to nothing, so a first-generation file gives no false symbols, at the price of
giving none at all.

## Decision

- **The opt-in.** A daslang file extracts to nothing unless it opts into the second-generation syntax with a top-level
  `options gen2`.
- **Read from the tree.** The option is read from the parse tree: an `options_declaration` at the root of the file
  whose arguments name `gen2`. An `options gen2` inside a comment or a string is no such node, and a byte order mark or
  a header above the option does not hide it.
- **An opt-out wins.** An explicit `options gen2 = false` anywhere at the root wins over any opt-in in the same file,
  and the file extracts to nothing.

Which code a call of a file that opts in belongs to is the rule of
[ADR 3.141](/design-docs/adr/3.141-daslang-call-attribution.md), and how its directives resolve the rule of
[ADR 3.140](/design-docs/adr/3.140-daslang-module-lookup.md).

## Why

- The compiler reads that one option to choose its parser. The first generation is indentation-delimited and has no
  tree-sitter grammar; the gen2 grammar parses it to errors, and a walk over that tree gives symbols that no source
  declares.
- A first-generation file extracted costs wrong symbols, and a second-generation file dropped costs only its absence,
  so an explicit opt-out wins over an opt-in (#36).
- Reading the option from the tree keeps a commented-out or quoted `options gen2` from passing a first-generation file.

## Consequences

- Every first-generation file is absent from the graph: 3,629 of 8,794 `.das` files on the game-engine tree
  (2026-10-16, #36), in whole projects, since the syntax follows project lines. Accepted.

## Rejected

- **A first-generation grammar** — covers the files gated out, but means porting the compiler's bison grammar and an
  off-side external scanner, and owning a grammar no one else maintains.
- **The compiler's own AST dump** — exact for both generations, but puts a C++ build and a process boundary into an
  engine that has neither.

## Revisit if

First-generation files appear in reviews as often as second-generation ones. Held with moderate confidence: how often
each generation appears in reviews has not been counted.
