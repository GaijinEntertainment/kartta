# Read a declarator a macro misjoins in the walk

- **Status:** accepted
- **Date:** 2026-10-17
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-cpp/src/walk/declarator.rs`, `crates/kartta-lang-cpp/src/walk.rs`
  (`misread_definition_body`)
- **Pinned by:** `crates/kartta-lang-cpp/src/walk.rs` (`a_macro_before_the_return_type_keeps_the_function`,
  `a_macro_between_the_return_type_and_the_name_names_no_scope`,
  `a_macro_before_a_scoped_return_type_keeps_the_namespace`,
  `a_macro_before_a_pointer_return_type_keeps_the_function`,
  `a_macro_before_a_name_set_apart_from_its_parameters_keeps_the_name`,
  `a_macro_before_a_conversion_operator_keeps_the_operator`, `trailing_annotation_macros_never_name_the_symbol`,
  `a_declaration_keeps_the_macro_after_its_parameters`, `a_definition_whose_body_the_grammar_reads_apart_keeps_it`)

An annotation macro before a function, `JPH_INLINE`, `IMGUI_API` or `VULKAN_HPP_INLINE`, parses as the function's type,
which pushes the real return type into the declarator and joins it to the name. The tree still holds every word in a
fixed place, so the C++ walk reads the function out of that shape instead of blanking the macro and parsing again.

## Decision

1. A macro before the return type, `static OPUS_INLINE int f()` or `VECTORCALL VECMATH_FINLINE vec4f v_splat_x()`,
   keeps the function it annotates, and so does an upper-case return type before a calling convention, `BOOL WINAPI
   DllMain()`. A trailing annotation macro, `void load() LOCKS(mtx) {}`, never names the symbol it annotates.
2. A macro between the return type and the name, `XMMATRIX XM_CALLCONV XMMatrixRotationZ()`, and a return type written
   with a scope after a macro, `VULKAN_HPP_INLINE std::string to_string()`, parse as a scope of the name joined by a
   `::` the source does not hold. The declared name follows the last such seam and names no owner, so the function
   keeps its namespace; a scope the definition writes after the seam, `std::string Widget::label() const`, names its
   owner. Where a calling convention strands that scope's first name in an error before the real `::`, `LRESULT
   CALLBACK Window::wndProc()`, the stranded name heads the written scope, so the definition's key matches its
   in-class declaration.
3. A pointer return type after a macro, `IMGUI_API ImGuiTabItem* FindTab()`, parses as a scope joined by a `::` the
   source does not hold to a pointer declarator whose function's name reads as a type identifier; the walk follows the
   seam to the function.
4. A name a space or a line break sets apart from its parameters after a macro and a return type, `GLM_FUNC_QUALIFIER
   typename genType::row_type row\n(`, is evicted into an error after the declarator; the walk names the function
   after that error's one identifier, found among the function's own children, unless the identifier is spelled as a
   macro.
5. A conversion operator after a macro, `ML_INLINE double4::operator int4() const`, reads with its class and target
   type as one qualified name and the `operator` keyword in an error between them; it is `operator int4`, a method of
   `double4`. A target that pulls a parenthesis, a brace or a `;` into that name names nothing.
6. The walk joins what the parser reads apart: a declaration without a body keeps the macros after its parameters in
   its signature, `static LUAU_NORETURN void raise(const char* format, ...) LUAU_PRINTF_ATTR(2, 3);`, which the parser
   reads as a declaration of their own on the same line; a definition keeps the body the parser reads apart after an
   initializer list that follows a macro, `PX_INLINE Sc::CoreInteraction::CoreInteraction(bool b)` `: mFlags(0)` `{`,
   or after a macro call that follows a scoped parameter type, `void lockReadContended(::da_profiler::desc_id_t
   token) DAG_TS_ACQUIRE_SHARED()` `{`.
7. A function-like macro is no symbol: a definition without a return type outside a class, `TEST(Suite, Case) {}`, is
   dropped, and so is one inside a class that is no constructor, destructor or operator.

## Why

- Kept, macro-annotated functions were 54,037 definitions and 128,650 call sites of the C++ game-engine tree of 43,356
  files that the extraction had dropped (2026-10-17).
- The shape a macro leaves is fixed, so reading it costs no parse, and the walk reads it where the original bytes and
  positions are already at hand.
- A key that keeps a stranded or joined scope folds a definition into its in-class declaration
  ([ADR 3.74](./3.74-fold-a-c-plus-plus-declaration-into-the-one-definition-its-file-reaches.md)); one that loses it
  splits them, or names a method of the return type.
- The repair that keeps a class open ([ADR 3.3](./3.3-repair-what-the-c-plus-plus-grammar-cannot-parse.md)) reads
  apart what the misread first parse had held together; without the joins it lost the trailing macro of 96 members and
  the bodies of the constructors it repaired (2026-10-23).

## Consequences

- The definitions these rules keep make a unique free namesake ambiguous where it bound before: `strcmp` beside PhysX's
  own, among 23,608 pairs lost against 100,169 gained (2026-10-17). Accepted.
- A macro before a multi-word or scoped pointer return type still loses the function (#411), and a calling convention
  between the return type and the name loses it in a class body, a prototype and some free definitions (#402).
- A destructor after a macro in a class is named after its class (#410), and an out-of-line conversion operator led by
  `constexpr` or `inline` is not named after `operator` (#404).

## Rejected

- **Blank the macro and parse again** — finds 119 fewer of the pointer-return functions, `CGD3D10DLL_API ID3D10Device *
  CGD3D10ENTRY cgD3D10GetDevice()` among them, moves the start of a definition whose macro stands on its own line to
  the line below, renames only the two `typename` sites, and takes the class off an operator of `int128_t_base`
  (2026-10-23).
- **Look the evicted name up as the declarator's next sibling** — tree-sitter finds a sibling through its parent, which
  it finds by descending from the root, for every callable of every file; the function's own children hold the error.

## Revisit if

The grammar reads an annotation macro before a declaration as an attribute, or a tree-sitter release recovers from
these shapes differently; the seams are read from tree-sitter-cpp 0.23.4's recovery. High confidence while it is
pinned.
