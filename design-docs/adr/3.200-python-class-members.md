# Walk a Python class's parents up to the field that hides a member, within what the file imports

- **Date:** 2026-11-01
- **Governs:** `crates/kartta-graph/src/scope.rs` (`held_at_level`, `field_held_by`, `past_the_imports`),
  `crates/kartta-lang-python/src/lib.rs` (`CONVENTIONS`), `kartta_lang::ReceiverMembers::InheritedUpToFields`
- **Pinned by:** `crates/kartta-languages/tests/python_inherited_members.rs`

Python's lookup reads a class's `__dict__` and then each class of its order, and values and methods share that dict, so
the walk every language shares ([ADR 3.193](/design-docs/adr/3.193-receiver-class-members.md)) needs three rules of its
own. The walk stops at a field that hides a member, reads a parent only within what the file imports, and stands in for
C3 level by level, at the price of the few pairs where the order and the levels differ.

## Decision

- **Python's fields.** Under `InheritedUpToFields`, a field of the name that the class or a type of the walk holds ahead
  of the member hides it: the call binds nothing, and no tier after the walk reads the name. A value the class body
  writes and an attribute a method gives the instance are such fields, and a class-body annotation with no value is
  not, so the walk goes past it. A field with no member above it hides nothing, and the tiers read the call as before.
- **Imported names.** Where `Conventions::value_uses` is `ValueUses::Imported`, a type past what the file imports is no
  parent and no receiver's class, and a parent whose first name the file binds outside the repository stands for no
  type, as `db.Base` under `import django.db as db`.
- **C3.** For Python this walk approximates the language's C3 method resolution order: the two differ where a first
  base's ancestor outranks a second base.

## Why

- Python's lookup takes the first class of `tp_mro` whose `__dict__` holds the name (`find_name_in_mro`,
  `Objects/typeobject.c:6193` in cpython v3.15.2), and `tp_mro` is the C3 merge of the bases' orders (`pmerge`,
  `:3401`). Of the 17,035 pairs the walk adds or promotes on three venvs' site-packages, judged by each venv's
  interpreter against the class's `__mro__`, 98.0% are right (2026-11-01, #856).
- A Python class's values and methods share its `__dict__`, so that lookup stops at a value, a function and a `property`
  alike, `codegen_annassign` (`Python/codegen.c:5695`) stores nothing for an annotation with no value, and `self.x`
  reads the instance's dict ahead of a class attribute that is no data descriptor (`_PyObject_GenericGetAttrWithDict`,
  `Objects/object.c:1888`). Of the 18 pairs the stop removes on a 9,556-file site-packages, 17 are right, and dagor's
  Python moves none (2026-11-01, #886).

## Consequences

- A parent's lookup builds the file's include closure: resolving every call of a 9,556-file site-packages takes 0.56 s
  where it took 0.19 s, and peak footprint goes from 264 MB to 292 MB, for 10,956 more pairs at 85 (2026-11-01).
  Accepted.
- Python's C3 order answers a first base's ancestor ahead of a second base where the walk takes the nearer level:
  `GenericClass(DefineGenericBaseClass, ClassMixin)` binds `ClassMixin.py__name__`, not `HelperValueMixin`'s. 8 pairs of
  the six Python trees. Accepted.
- A Python field binds nothing whatever it holds: `can_fuse_horizontal = can_fuse` loses `can_fuse`, and a field that
  wraps the parent's own method, as `Tensor.detach`, loses 2 right pairs. An instance attribute also stops `cls.m()`,
  on no pair of four venvs, and stops ahead of a parent's `property` with a setter, on 2. Accepted.
- A Python base's last name ties across the namesakes the imports reach, so `class Linear(nn.Linear, TinyLoraLayer)`
  reaches peft's other `Linear`. `self.m()` in a nested class stays with the tiers, since `class_of` reads no chain, and
  `class Child(B)` under `from base import Base as B` has no parent, which is 187 of the 38,149 bases written as a
  bare name on the three venvs. Accepted.

## Rejected

- **C3 for Python's walk** — built: 16,690 of the 17,033 judged pairs right against 16,697, because a tie among a base's
  namesakes puts the wrong one's ancestors ahead of the second base: of the 24 pairs of the six trees where the orders
  differ, 14 are right under the level walk, 8 under C3 and 2 under neither (2026-11-01).
- **A Python annotation with no value as a stop** — jedi's `as_context: Any` hides nothing: 3 of 27 sites (2026-11-01).

## Revisit if

A Python base resolves through its import to one type, which takes away C3's loss. Medium confidence.
