# Extract TypeScript and JavaScript as one family

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-jsts/src/walk.rs`, `crates/kartta-lang-jsts/src/walk/calls.rs`,

  `crates/kartta-lang-jsts/src/lib.rs` (`CONVENTIONS`)
- **Pinned by:** `crates/kartta-lang-jsts/src/tests/extraction.rs`, `crates/kartta-lang-jsts/src/tests/identity.rs`

TypeScript, TSX and JavaScript are three tree-sitter grammars over one module system, and much of what a review asks
about in a frontend, a component, a handler or a hook, is a function with no declaration of its own. `kartta-lang-jsts`
extracts the three as one family and gives such a function a scope of its own, and it leaves CommonJS exports
unmodelled.

## Decision

**One family.** `TypeScript`, `Tsx` and `JavaScript` each parse with their own grammar and share one walk and the
family `jsts`, so their files resolve against each other in one graph. Imports and re-exports resolve as
[ADR 3.100](./3.100-resolve-a-typescript-or-javascript-import-as-the-compiler-and-bundlers-do.md) decides.

**Scopes.** A function bound to a name is a function symbol that owns the calls of its body: an arrow or a function in
a `const`, `let` or `var`, one wrapped in `memo`, `forwardRef`, `useCallback`, `useMemo`, `observer` or `debounce`, an
object property, named by its key and owned by nothing, a class field, a method of the class, and an anonymous
`export default` function, named `default`. An anonymous callback, such as an inline JSX prop arrow, opens no scope,
and its calls belong to the function around it. A class declaration, and an anonymous `export default class`, owns the
calls of its body outside those functions: a field's initializer, a decorator and a static block. A class expression,
`const Box = class {}`, leaves its body's calls to the scope around it.

**Test registrations.** A call of `describe`, `it`, `test`, `xdescribe`, `xit`, `xtest`, `fdescribe`, `fit`, `ftest`,
`suite` or `bench`, bare or behind one of the modifiers `.skip`, `.only`, `.todo`, `.concurrent`, `.sequential` and
`.failing`, opens a scope over the function it is passed: a function symbol named by its description, flat as object
keys are, never qualified by the `describe` around it. A bare `beforeEach`, `afterEach`, `beforeAll` or `afterAll` is
one named for itself. A description that is not a plain string, a template literal or a variable, names nothing, and a
shape outside the list, `it.each(rows)(...)`, is no registration; either way the body stays with the scope around it.
A registration in a production file opens its scope too; the file's name alone decides whether it is test code.

**Owners.** A member is owned by the chain of names that encloses it: `A.Worker.run` in
`namespace A { class Worker { run() {} } }`. A `const`, `let` or `var` that a `namespace` or a `declare module` block
declares is its member, `A.limit`. A class with no name goes by the name that binds it, `default` for an anonymous
`export default class` and `A.Box` for `const Box = class {}` inside `namespace A`, and that name owns its methods. A
body owns no member: a function's body and a class's static block start no chain, so a class declared inside a
function starts a new one.

**Calls.** A capitalised JSX tag is a call of its component, and `new Foo()` a call of `Foo`. A call on a value the
file declares records the empty receiver, and a call on `this` the class, as
[ADR 3.101](./3.101-name-no-type-for-a-typescript-or-javascript-call-on-a-value-the-file-declares.md) decides. Data
sites follow [ADR 3.62](./3.62-record-typescript-and-javascript-data-sites-through-what-a-value-declares.md).

**What is not modelled.** Export assignments, `module.exports = …` and `exports.f = …`, are ordinary assignments, so a
CommonJS module has no export surface and a function that exists only on the right side of one has no symbol. No symbol
is an entry point.

**File roles.** A file is test code, with every symbol in it, when its name holds `.test.` or `.spec.`, or a directory
on its path is `__tests__` or `tests`; a directory named `test` is not enough. A file is generated code when a
`@generated` or `DO NOT EDIT` banner stands outside a backtick span in the comments before its first line of code, read
after a UTF-8 byte order mark; when that first line of code runs past 500 bytes; or when its name holds `.gen.` or
`.generated.` or its stem ends in `_pb`, `.pb` or `.min`. A `.d.ts` file is not generated. A file under a
`node_modules` or `vendor` directory is vendored code.

**Conventions.** The family sets `OwnMembers::Unreached`, `.` as the owner chain separator, a bare call that reaches
the owners enclosing the caller's own (a `namespace` is a lexical scope of what it holds), ECMAScript's and the DOM's
methods as `runtime_methods` ([ADR 3.40](./3.40-bind-a-runtime-method-s-call-only-to-a-member-that-scope-reaches.md)),
`ValueUses::Imported`, `UntypedMembers::Unbound` and `TypeUses::Nowhere` (ADR 3.34).

**Fingerprint.** A language's fingerprint holds the crate's name and version, a digest of its sources from the build
script, and its grammar's declared version, node types, ABI version and counts of node kinds, parse states and fields.
A change in `kartta-lang` is covered by `kartta_lang::FINGERPRINT`, which a cache keys beside it. The fingerprint
cannot see a change in the tree-sitter runtime, or in a grammar that keeps all of those equal: a maintainer who updates
either bumps the crate's version.

## Why

- React frontends keep shared code in `.ts` and the components that use it in `.tsx`, so most imports and calls cross
  grammars: three separate graphs severed 34% of the resolved import edges on the frontends this was built against
  (2026-10-16).
- Without a scope, every call in an arrow body belongs to the file, and a caller query dead-ends on exactly the
  components and handlers a review is about. An inline callback has no name to address, and the component around it
  is the consumer a reviewer asks about.
- A test file is built from registrations whose bodies bind no name: without a scope their calls are file-scope calls
  that the graph keeps only as names
  ([ADR 3.112](./3.112-keep-the-names-a-file-s-top-level-calls-and-uses.md)), and no test is their caller. A class
  body's calls were file-scope calls in the same way, so the class had no callees and ADR 3.112's file-scope rule let
  the name reach every namesake in the file; of the pairs a class body's calls added, 46 of 47 were right on three
  trees (2026-10-23).
- A variable a namespace declares was a symbol with no owner while a function beside it was a member, so `Ns.limit`
  selected nothing.
- A program's entry is a bundler's or a `package.json`'s notion, and it names a file, not a symbol.
- A minifier writes a whole module on a few lines, and four committed vendor bundles carried about 10% of the symbols
  on the frontends this was built against (2026-10-16). Documentation of the banner convention quotes it in backticks.
  `test` is a common name for a feature or a command directory.
- The three languages differ in their grammars, so the language's name adds nothing to the fingerprint.

## Consequences

- A CommonJS module's exports have no symbol. Accepted until a consumer asks (Revisit if).
- A class expression's body has no caller of its own: 7 such expressions with a body on three frontends (#466).
- A registration named by its description can take the calls of a function of that name (#474).
- Extracting the 172,660 scripts of a monorepo checkout of 374,827 files takes 74.5 s on one macOS thread
  (2026-10-16).

## Rejected

- **A family per grammar** — severs the imports between `.ts` and `.tsx` files, a third of a frontend's edges.
- **Modelling CommonJS exports** — gains a symbol for a function assigned to `exports`, at the cost of an arm for every
  assignment shape; nothing that consumes the graph has asked for it.
- **Matching `-min.js` names as generated** — no such file was found, and hand-written names end in `-min`.
- **Marking `.d.ts` files generated** — such files are commonly written by hand.

## Revisit if

A consumer needs the export surface of CommonJS modules. None asks yet.
