# Answer a missed name with the definitions one edit from it

- **Date:** 2026-10-21
- **Governs:** `crates/kartta-graph/src/one_edit.rs`, `Graph::definitions_one_edit_from`, `kartta_graph::each_one_edit`
- **Pinned by:** `crates/kartta-graph/tests/graph/one_edit.rs`

A name that names no definition is most often a typo of one that does, and the word search of
[ADR 3.21](/design-docs/adr/3.21-definition-search.md) rarely reaches the meant definition
from a typo's words. The graph looks up every name one edit from the missed name, as `definitions` reads a name, at a
cost in the square of the name's length, paid only on a miss.

## Decision

- **Edits.** `Graph::definitions_one_edit_from` answers the definitions that the names one edit from a name select, as
  `Graph::definitions` reads a name, each once. An edit swaps a character with the next, drops one, or replaces or adds
  one; a replacing or added character is an ASCII letter, a digit, `_` or a character the name holds. The empty name is
  not looked up. `each_one_edit` hands the same edits to any caller, as a missed path argument of
  [ADR 4.61](/design-docs/adr/4.61-mcp-path-arguments.md) takes them.
- **Owner edits.** An edit to the owner of a qualified name keeps its last segment, so the definitions of that segment
  are sorted once by the qualified names they end with, and each edited name is a binary search among them.
- **Length bound.** A name of more than 256 characters looks up nothing, and `each_one_edit` makes no edit of it.
- **Order.** The definitions come outside test code first, then outside vendored code, then by path, line and qualified
  name.
- **When it runs.** The lookup runs only for a name that selected nothing and names no definition of any kind; the build
  and the word search run none of it. How the consumers answer with it, `kartta::unmatched`'s `one_edit` case and the
  alternatives `find_symbols` lists ahead of its hits, is [ADR 4.18](/design-docs/adr/4.18-mcp-name-misses.md)'s.

## Why

- A typo's words rarely leave the word matches short of the limit, so the fill-up, which forgives only characters left
  out, ran in the graph of the meant name for 18 of 500 typos on the C++ game-engine tree, and `hadnle` got unrelated
  test functions for its alternatives.
- Of 500 typos per tree, one edit each, the meant definition was among the names one edit away for 496 on the C++ tree
  and 498 on the Go monorepo snapshot (2026-10-21, #308).
- The 256-character bound costs no typo of a real name, the longest qualified name of the 2.3 million definitions on
  those trees holding 189 characters, and keeps a pasted line from costing seconds.

## Consequences

- A name costs a probe of the graph's strings for itself and one for each part after a separator, so a lookup costs in
  proportion to the square of the name's length; a miss took 25.6 ms at p99 on the C++ tree (2026-10-21). Accepted;
  [ADR 4.34](/design-docs/adr/4.34-wire-name-misses.md) measures it by length.
- A typo two edits from every definition finds nothing. Accepted.

## Rejected

- **A scan of every name for one edit** — close in recall, and it reads every name of the graph on each miss, above
  100 ms at p99 on the C++ tree.
- **The lookup without added characters** — a third of the cost at the median, and it loses the typos that dropped a
  character, 46 and 61 of 500.
- **One edit forgiven by the fill-up** — the fill-up seldom runs for a typo: 10 and 13 more of 500.
- **The lookup inside the search** — it has to decide per graph, so a query one graph matches pays for it in the
  others, 3.4 ms on a match.
- **Each edited name looked up through `definitions`** — the same answers, and up to 2.7 s for a typo of an owner over
  a common last segment, as one over the 6,641 definitions of `UnmarshalJSON`.
- **Any character as a replacing or added one** — a name's own characters already cover a swapped, dropped or doubled
  character outside ASCII, and an open set has no bound on the names looked up for each character.

## Revisit if

The meant definition falls outside the names one edit away for more than a few of 500 sampled typos, or a miss's lookup
outgrows tens of milliseconds at p99. Both held with margin on the measured trees.
