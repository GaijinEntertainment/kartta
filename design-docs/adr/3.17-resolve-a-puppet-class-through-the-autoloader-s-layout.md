# Resolve a Puppet class through the autoloader's layout

- **Status:** accepted
- **Date:** 2026-10-16
- **Initiative:** `03-code-graph`

Puppet code refers to a class by name: `include apache`, `contain apache::service`, a resource of a qualified type such
as `apache::vhost { 'example.com': }`. No import statement says which file defines the class. The module autoloader
finds it by a fixed layout: `foo` is in `foo/manifests/init.pp`, and `foo::bar::baz` in `foo/manifests/bar/baz.pp`,
under a module directory. The extraction reads one file and has only that name.

**A class reference is a call of the class, and an include of its manifest.** The graph binds the call to the
reference's symbol, the class or the defined type of that name, as it binds any call to a definition of the same name.
The include adds a file edge to the manifest that the autoloader's layout names — for a module under two roots, the one
under the first root of the list below, which an `environment.conf` can order otherwise — and unlike the call, the edge
does not depend on which definitions share the class's name. An `include`, `require` or `contain` statement, with a
bare or a quoted name, and a `contain(...)` call are class references, and so are a resource whose type has a `::` and
the class that a class `inherits`: Puppet declares the parent class before the child, so the parent is a call and an
include as well as the class's parent. The grammar reads `include` and `require` as keywords and parses no call of them,
so `include('foo')` is a parse error and records nothing. A resource of a one-segment type is a call of the type only:
`file` and `package` are built-in types, and a built-in type shadows a module of the same name.

**A reference that names no class records nothing.** A class name is lowercase segments joined by `::`, with an
optional leading `::`. `Class['foo']` is a type reference, and `$name` or a `*` is a computed name. The extraction
cannot read a computed name, and a call of `Class` binds to nothing that the reference means.

**A manifest is found at a module root first, and by its tail only when one file matches.** The module roots are the
repository root, `modules/`, `site/`, `site-modules/` and `dist/`: the layouts of a single module and of a control
repository. Their order decides only for a module that sits under two of them, and there the `modulepath` of
`environment.conf` sets the order, which the extraction does not read; the first root in the list wins. A manifest
elsewhere is taken when it is the only file whose path ends in the autoloader's layout. A repository with directory
environments holds the same module once in each environment, and the extraction cannot know which environment loads
the file, so two matches give no include. A wrong include is worse than a missing one: an agent that follows it reads
code that the reference never loads.

**Test code is code beside `manifests/`.** A file under `spec`, `tests`, `test` or `examples` is test code when the
directory sits beside a `manifests/` that holds a file, which makes its parent a module. Inside `manifests/`, the same
name is part of a class name, `mymod::test::foo`; a directory of that name that holds `manifests/` is a module,
`modules/test/manifests/init.pp`; and one with no `manifests/` beside it holds modules, as the environment
`environments/spec/` does.

On the `stdlib`, `apache`, `mysql` and `postgresql` modules, laid out under `modules/`, the 314 manifests give 504 class
references and 432 includes. Of each, 35 come from an `inherits`, and 19 from a quoted name,
`include 'mysql::server::config'`.

## Considered Options

- **Every file whose path ends in the layout** — finds a module in any layout, but gives one include for each
  environment that holds it.
- **A call of the keyword, `include`** — binds every class reference to one name that no symbol has.
- **A class reference for a one-segment resource type** — names a manifest for `file` and `package` when a module of
  that name exists, which the built-in type shadows.

Revisit when the extraction reads `environment.conf` or a `Puppetfile`, which name the module path.
