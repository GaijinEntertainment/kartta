# Name the type alias a parent's lookup reaches

- **Status:** accepted
- **Date:** 2026-10-23
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/implementations.rs`, `kartta_graph::is_parent`
- **Pinned by:** `crates/kartta-graph/tests/graph/implementations.rs`
  (`a_parent_names_the_alias_its_scopes_reach_and_not_the_aliased_type`,
  `a_struct_that_namesakes_an_alias_keeps_only_its_own_copys_implementors`)

A C++ base is often written through a typedef, as `struct is_void : true_type` inside `namespace eastl`. A parent that
reaches a type alias names the alias, and the alias's implementors are its own, because the extraction does not record
what an alias names; a query of the aliased type does not count the alias's derivers.

## Decision

- A type alias is a type that a name selects for `implementations` (`is_parent` admits it) and that every parent lookup
  of [ADR 3.20](./3.20-resolve-implementors-from-the-parents-written-when-a-query-asks.md) reaches, as it reaches a
  class.
- An alias's implementors are the types whose parent reaches the alias. They are not implementors of the type the alias
  names, and the alias is not one.
- The call queries' lookup of a type's bases for inherited members counts no alias: an alias has no body for a member to
  come from.
- Where one file declares a struct and an alias of one qualified name, as C's `typedef struct S {} S;`, the name selects
  both and the answer counts the one it did not take among those it passed over.

## Why

- Before aliases counted, the lookup reached no type for `true_type` inside `eastl`, fell back to the nearest type of
  the name and credited each doctest copy's `true_type` struct tied there, while no query selected `eastl::true_type`.
- Of the C++ implementors that moved to an alias on the game-engine tree, 29 of 30 sampled were right (2026-10-23).

## Consequences

- A name many aliases share costs what one many classes share costs: `CppType::Type`, shared by 1,255 aliases of the
  Vulkan headers, takes 0.35 s. Accepted.
- A non-template alias shadows a class template of its name that a parent writes with template arguments, since the
  arguments are dropped before the lookup: 1 of 30 sampled (#454).
- An agent that asks for the aliased type does not see the alias's derivers; it asks for the alias. Accepted until the
  extraction records what an alias names.

## Rejected

- **Count an alias only where a lookup reaches it** — the alias shadows its namesakes, which no longer take its
  derivers, while no query selects it: 786 C++ implementors went to no type.
- **Credit nothing where a lookup reaches an alias** — `find_implementations true_type` fell from 317 to 9, and the
  answer counted none of the derivers it left out.
- **Make an alias an implementor of the type it aliases** — 39,857 more direct implementors on the game-engine tree,
  every `using NativeType = VkFoo` among them, and the implementors credited to several namesakes rose from 834 to
  5,691, as each copy's alias of a vendored type took every copy of it.

## Revisit if

The extraction records what an alias names, which lets a query of the aliased type count the alias's derivers without
listing the alias. Not planned.
