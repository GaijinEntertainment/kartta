# Name the ignore files an index applied

- **Date:** 2026-10-20
- **Governs:** `crates/kartta-mcp/src/state.rs` (`Gitignore`), `crates/kartta-mcp/src/render.rs` (`index`)
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`
  (`an_index_inside_a_repository_names_the_top_whose_rules_it_did_not_read_unless_it_applies_none`)

An agent read the MCP server's `gitignore="respected"` as the view of the tree `git status` gives, and a root below a
repository's top is where the two part. The `index_root` and `index_stats` answers name the ignore files a build
applied, and the top above the root whose files it did not read, at one path resolution and a few `lstat` calls a
build.

## Decision

- **The attribute.** The `index_root` and `index_stats` answers carry `gitignore="in-tree"` when the build applied the
  `.gitignore` files inside the root, the level of [ADR 1.3](/design-docs/adr/1.3-ignore-sources.md), and
  `gitignore="ignored"` when `index_ignored` applied no rule.
- **A root inside a repository.** A root inside a repository whose top is above it reads `gitignore="in-tree: the root
  is inside the repository at <top>, whose .gitignore files above the root were not read"`.
- **The index is unchanged.** What the index holds does not change with the attribute.
- **The top.** The top is the nearest directory, the root or one above it, that holds an entry named `.git`, a
  directory or a linked worktree's file, since git's discovery stops at the first.
- **Links resolved.** The look runs on the root's path with its links resolved, as git reads the directory it runs in.
- **Once a build.** The server looks once a build, after the walk: one `realpath`, then one `lstat` a directory, up to
  the first `.git` or `/`.

## Why

- git applies the `.gitignore` files from the repository's top down to the directory above the root, and the build
  reads none of them, so `respected` claimed git's view where the index can hold files git hides. With the C++
  game-engine tree's `samples` directory as the root, 4 of its 491 indexed files are hidden that way (2026-10-20,
  #209).
- The walk lists the root's `.git` but looks at nothing above the root, and `kartta-fs` answers no question about
  repositories, so the server makes the look itself.

## Consequences

- The index of a root below a repository's top holds the files the `.gitignore` files above the root hide; whether it
  reads them is part of how kartta meets git's layouts (#145).
- The look costs one path resolution and one `lstat` per directory above the root, once a build; accepted.

## Rejected

- **Read the `.gitignore` files above the root** — the index would match git's view, but what it holds would change,
  and that belongs to the decision on git's layouts (#145).
- **Look above the root's path as given** — a root given relative has no directory above it to look in, and one reached
  through a link would be looked above at the link rather than at the tree.

## Revisit if

kartta reads the `.gitignore` files above a root (#145), which makes the second form of the attribute false. High
confidence that it holds until that decision lands.
