# Publish the wire as a hand-written reference a test holds to the code

- **Date:** 2026-11-02
- **Governs:** `crates/kartta-ffi/WIRE.md`, `crates/kartta-ffi/tests/reference.rs`
- **Pinned by:** `crates/kartta-ffi/tests/reference.rs`
- **Implementation:** pending — the release archive does not exist yet, so nothing carries `WIRE.md` beside the header
  (#136)

Dedicated tools integrate the C ABI ([ADR 4.46](/design-docs/adr/4.46-release-scope.md)) and read neither Go nor
TypeScript. `WIRE.md` states the wire for them by hand, and a test fails on any name the code and the reference do not
share; the trade is a third copy of the field docs, whose meanings no test reads.

## Decision

- **The reference.** `crates/kartta-ffi/WIRE.md` states every method, field, default, error code and enumerated value of
  the wire ([ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md)). It ships in the crate and beside the header in the release
  archive, and the header and the crate's README name it.
- **The check.** `tests/reference.rs`, in the `test` job on every platform, fails on a name either side lacks. It reads
  `src/` with `syn`: each struct and enum that derives `Serialize` or `Deserialize` by the serde attributes that decide
  what the wire spells, each `match` that answers string literals, the `label` functions of the engine's enums, and each
  numeric constant with its value. It takes the methods and languages from `version`, each method's params from serde's
  refusal of an unknown field, and every key of the golden files, each within the sections its method's row links.
- **One section per object.** Each object and value set is a `###` section whose bullets open with the backticked name,
  so the check holds a field to its object, never to the file. A field's bullet states if it is always there, which the
  check compares with the serde attributes.
- **A serde key it does not read fails.** A new attribute that changes what the wire spells stops the check until the
  check reads it.

## Why

- Later units change this surface, so a reference that only a reader checks would go stale before the cut. Each of 18
  seeded changes failed the check: a new method, field, code, value and bound among them (2026-11-02).
- A consumer of the archive holds no ADR and no binding, and `tests/golden` shows shapes, not what a field means
  (#1051).
- `syn` is already in the lockfile through serde's derive, and a dev-dependency adds no code to the shipped library.

## Consequences

- The field docs live in `WIRE.md`, `bindings/go/wire` and `bindings/node/src/wire.ts`, and a meaning can drift between
  them. Accepted: the names cannot, and a consumer of one surface reads one copy.
- The check reads no field's type, no default that is not a numeric constant, and not which field a bound serves: the
  first two changed in a scratch copy and passed (2026-11-02). Accepted: the golden test fails on a type a golden
  reaches, and the other two hold by review.
- A key a hand-written `Serialize` adds passes unless a golden reaches it. Accepted: the crate has none that writes
  keys.

## Rejected

- **Point at `wire.ts`** — a C integrator would read TypeScript, and it leaves bounds and engine labels in a binding.
- **Generate the Go and TypeScript docs from the reference** — tooling for three surfaces, for text that is right today.
- **Generate the reference from the code** — the view types hold names and no meanings.
- **Check only that the file names each method and code** — a substring passes for a field another object holds, and
  fields and values are what the later units add.

## Revisit if

A fourth surface needs the field docs, which would pay for generating them. High confidence that none comes before the
cut.
