# Hold the wire to a hand-written reference and to golden answers every binding replays

- **Date:** 2026-11-02
- **Governs:** `crates/kartta-ffi/WIRE.md`, `crates/kartta-ffi/tests/reference.rs`, `crates/kartta-ffi/tests/golden/`,
  `crates/kartta-ffi/tests/fixture/`, `crates/kartta-ffi/tests/golden.rs`, `bindings/go/golden_test.go`,
  `bindings/node/test/golden.test.ts`
- **Pinned by:** `crates/kartta-ffi/tests/reference.rs`, `crates/kartta-ffi/tests/golden.rs`,
  `bindings/go/golden_test.go`, `bindings/node/test/golden.test.ts`
- **Implementation:** pending — the release archive does not exist yet, so nothing carries `WIRE.md` beside the header
  (#136)

Dedicated tools integrate the C ABI ([ADR 4.46](/design-docs/adr/4.46-release-scope.md)) and read neither Go nor
TypeScript. `WIRE.md` states the wire for them by hand, a test fails on any name the code and the reference do not
share, and golden answers that the Rust, Go and Node tests replay hold every key to a request that spells it. The trade
is a third copy of the field docs, whose meanings no test reads, and a score that agrees only within a relative 1e-12.

## Decision

- **The reference.** `crates/kartta-ffi/WIRE.md` states every method, field, default, error code and enumerated value of
  the wire ([ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md)). It ships in the crate and beside the header in the release
  archive, and the header and the crate's README name it.
- **The check.** `tests/reference.rs`, in the `test` job on every platform, fails on a name either side lacks. It reads
  `src/` with `syn`: each struct and enum that derives `Serialize` or `Deserialize` by the serde attributes that decide
  what the wire spells, each `match` that answers string literals, none with a catch-all arm
  ([ADR 4.53](/design-docs/adr/4.53-public-type-growth.md)), the `label` functions of the engine's enums, and each
  numeric constant with its value. It takes the methods and languages from `version`, each method's params from serde's
  refusal of an unknown field, and every key of the golden files, each within the sections its method's row links.
- **One section per object.** Each object and value set is a `###` section whose bullets open with the backticked name,
  so the check holds a field to its object, never to the file. A field's bullet states if it is always there, which the
  check compares with the serde attributes, and an enum's `(default)` mark is compared with its `#[default]`.
- **The other copies.** The same test holds the error codes of `bindings/go/wire` and `bindings/node/src/wire.ts` to the
  reference's, and `include/kartta.h` to the library: it spells each `extern` function's signature in C and compares the
  declarations both ways, a parameter's name included.
- **A serde key it does not read fails.** A new attribute that changes what the wire spells stops the check until the
  check reads it.
- **Golden files.** Every method has a file under `tests/golden`, named after it, holding `method`, `params` and
  `answer` on the fixture tree under `tests/fixture`. A request that reaches keys the first does not, or one the method
  refuses, has a file of its own named after the method and what it pins, as `references-unmatched.json` or
  `list-not_found.json`. The goldens test the tree against itself: `KARTTA_FFI_BLESS=1` writes the answers the dispatch
  gives now in place of the pinned ones.
- **The replays.** `tests/golden.rs` replays every golden through the dispatch on one handle, `build.json` first and
  the rest in file-name order, and `every_method_answers_its_golden_request_as_pinned` fails unless every method
  `version` lists has a golden. The Go test replays them through cgo in the same order, and the Node test
  ([ADR 4.3](/design-docs/adr/4.3-node-addon.md)) `build` first, then each method's own golden, the further requests
  and the refusals. Each goes through its method's typed call, so a binding type that lacks a field the wire sends
  fails, and each fails when a typed call has no golden or a method `version` lists has no typed call.
- **Exact but a score.** A replayed answer matches its golden exactly, except a value under a `score` key, which agrees
  within a relative 1e-12 of the pinned one: `SCORE_TOLERANCE` in Rust and `scoreTolerance` in Go and Node. Each
  binding's score tests fail when a score that differs in its last digit stops agreeing, when one that differs in a real
  digit agrees, and when a number outside a score agrees though it differs. The Rust test parses the files with
  serde_json's `float_roundtrip`, so a file it blesses pins the score the engine answered on the blessing OS to the last
  bit.
- **Every key.** `every_key_of_the_wire_is_in_a_golden_or_listed_with_the_test_that_pins_it` fails on a key of a wire
  struct no golden spells. A key counts for a struct only in an object that holds every key the struct always holds;
  for a struct with no such key, only in a golden of a method whose `WIRE.md` row names the struct as its answer; and
  for a struct of params, only in its method's requests. A key that answers to a state no fixture can hold, as a file
  removed after the build, a symlink on a Windows checkout or a watcher that failed, is listed in `PINNED_ELSEWHERE`
  with the file whose test pins it, and
  `every_key_pinned_elsewhere_is_in_the_file_that_pins_it_and_in_the_bindings` compares its spelling with the Go and
  Node types.

## Why

- Later units change this surface, so a reference that only a reader checks would go stale before the cut. Each of 18
  seeded changes failed the check: a new method, field, code, value and bound among them (2026-11-02).
- A consumer of the archive holds no ADR and no binding, and `tests/golden` shows shapes, not what a field means
  (#1051).
- `syn` is already in the lockfile through serde's derive, and a dev-dependency adds no code to the shipped library.
- cgo links what Go code names and reads a signature from the header alone: a header that declared a sixth function
  built and passed the Go suite (2026-11-02).
- A binding compares a code by the string it holds, so a code spelled apart matches nothing and fails no suite.
- Every binding reads the same files, so one golden pins a method's shape for Rust, Go and Node at once, and a binding
  that has no typed call for a method fails rather than replaying it as raw JSON (#1048).
- Each replay asks what the `build` golden built, so the build runs first, and the goldens after a `refresh` golden pin
  that a refresh of the unchanged fixture changes no answer.
- `search`'s scores pass through `ln_1p` in `inverse_frequency`, and Apple's libm and glibc 2.41 rounded it one ulp
  apart for 76 of the 820 pairs sampled, so a golden blessed on macOS failed on Linux (2026-10-21, #294).
- 1e-12 holds thousands of ulps of a score and less than a change in its twelfth significant digit, and is exact for any
  integer score below 1e12, such as fuzzy's.
- A rename that reaches `WIRE.md` too fails no name check: `hit_count` renamed both ways passed every `kartta-ffi` test
  and the Go suite, where the control `total_hotspots`, which a golden holds, failed (2026-11-02, #1046).
- A key a struct shares by name is not pinned by another struct's golden: by name across the files 15 answer keys and
  30 params were in no golden, and within each struct 34 and 52 were (2026-11-02).
- A struct with no always-there key matched every object: `SymlinkView`'s `path` and `kind` read as held by
  `ListedView`'s objects, which no symlink answer reached (2026-11-06, #1186).

## Consequences

- The field docs live in `WIRE.md`, `bindings/go/wire` and `bindings/node/src/wire.ts`, and a meaning can drift between
  them. Accepted: the names cannot, and a consumer of one surface reads one copy.
- The check reads no field's type, no default of a field that is not a numeric constant, and not which field a bound
  serves: the first changed in a scratch copy and passed (2026-11-02). Accepted: the golden test fails on a type a
  golden reaches, a dispatch test pins each enum's default, and the rest holds by review.
- A key a hand-written `Serialize` adds passes unless a golden reaches it. Accepted: the crate has none that writes
  keys.
- The header's check reads the source, not the archive, and not the fields of `KarttaString`. Accepted: the Go suite
  fails on a field order that drifts, and a `no_mangle` function reaches the archive.
- A score that moves by less than a relative 1e-12 passes unnoticed: accepted.
- A listed key meets the bindings' types as a spelling in its named type, not as a field's own type. Accepted: each is
  spelled through a named test, and the goldens hold the rest.
- A struct whose always-there keys another struct's objects also hold counts that struct's objects as its own, so
  `OpenParams`'s `root` reads as held by a walk's. Accepted: `kartta_open` is no method, and its dispatch tests pin it.
- A struct with no always-there key that sits inside another struct's answer is held by no golden, even one that
  spells it, so its keys are listed in `PINNED_ELSEWHERE`, as `SymlinkView`'s inside `FileView`. Accepted: a listing
  names the test that pins each key.
- An enumerated value no golden answers is held by `WIRE.md` alone: 18 of the 63 outside the error codes, so the entry
  kind `other` renamed in the code and the reference passes (2026-11-02) (#1115).

## Rejected

- **`nm` over the archive against the header's names** — it passes a widened return type, and its output differs by
  platform.
- **Point at `wire.ts`** — a C integrator would read TypeScript, and it leaves bounds and engine labels in a binding.
- **Generate the Go and TypeScript docs from the reference** — tooling for three surfaces, for text that is right today.
- **Generate the reference from the code** — the view types hold names and no meanings.
- **Check only that the file names each method and code** — a substring passes for a field another object holds, and
  fields and values are what the later units add.
- **Scores matched exactly** — a golden blessed on macOS failed on Linux.
- **A tolerance on every number** — a count or a line that differs is a real change, and must fail.
- **Keys alone, every value free** — a count that stops being counted keeps its key, and a consumer reads it as zero.
- **A key checked by name across every golden** — `message` and `path` of a failure read as pinned by other structs.
- **A struct with no always-there key placed by the field whose type it is** — no golden holds such a struct under a
  field, so the rule decided no key (2026-11-06).
- **A schema generated from the views, diffed with the Go and TS types** — a dependency for what goldens nearly do.

## Revisit if

A fourth surface needs the field docs, which would pay for generating them; high confidence that none comes before the
cut. A score other than through `ln_1p` comes to differ between platforms by more than 1e-12; high confidence, as the
difference measured is one ulp.
