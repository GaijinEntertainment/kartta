# Search content through ripgrep's engine

- **Date:** 2026-10-14
- **Updated:** 2026-10-19
- **Initiative:** `01-kartta-fs-port`

Agents write content-search patterns for `rg`. `Index::grep` matches and streams lines through ripgrep's own crates, and
opens each file itself so that one read serves the binary rule and the search. The cost is a dependency that links an
encoding library this crate never uses.

## Decision

- `Index::grep` searches the content of regular files line by line. It compiles the pattern union through `grep-regex`
  and streams each file through `grep-searcher`, so a pattern written for `rg` means the same here.
- **Streaming.** The searcher grows its buffer only to fit the longest line, so a search's memory scales with a line,
  not a file. No size bound applies by default; `GrepOptions::max_file_bytes` sets one. A line longer than 256 MiB fails
  its file whatever the bound, so a file with no line breaks cannot grow the buffer to its own size.
- **Bytes as on disk.** Byte-order-mark sniffing is off. The bytes searched are the file's bytes, and a UTF-16 file,
  which holds NULs, is binary, as `Index::is_binary` answers for it.
- **Line endings.** The matcher runs in CRLF mode: `$` matches before `\r\n` as well as `\n`, and a reported line drops
  either ending.
- **One open per file.** A candidate is opened with a symlink refused on unix, so a link that replaced the file since
  the walk is not read through; on Windows the open still resolves one, the gap the crate states for every late read.
  The stat of the opened file gives its size. Unless the index already knows the file is text, its first 64 KiB settle
  it by `Index::is_binary`'s rule
  ([ADR 1.60](./1.60-settle-a-file-as-binary-by-its-extension-else-by-a-nul-in-its-first-64-kib.md)). The searcher
  is then handed those bytes followed by the rest of the file, so nothing is read twice. The size and the verdict are
  kept, and a later search skips a known binary or oversized file without opening it. A NUL past the first 64 KiB does
  not make a file binary.
- **Name, then size, then content.** A binary extension skips a file unopened. Otherwise a file over the caller's bound
  is oversized, and only then does a NUL make it binary. The planning pass that settles candidates from kept facts and
  the open that learns them keep this order, and an open that answers `Index::is_binary` keeps the size its stat
  reported.
- **Long lines.** A matching line longer than `GrepOptions::max_line_bytes` is cut around its first match, and a long
  context line keeps its start. A cut never splits a character, and `Line::cut` says how much each side lost.
- Candidates are searched in batches folded in index order, by
  [ADR 1.70](./1.70-search-content-in-batches-folded-in-index-order.md).

## Why

- `grep-searcher` already carries a partial line across reads, keeps leading context across buffer refills and counts
  lines as it goes. Ripgrep maintains that code and has hardened it.
- A default size bound would turn away files no caller chose to skip, and the consumer the index is built for reads
  whole files.
- With BOM sniffing on, the searcher would search transcoded bytes. The binary rule and the content index (ADR 1.14)
  read raw bytes, so all three must see the same bytes.
- One concept with two answers is the defect. The NUL rule and the judging order are `Index::is_binary`'s, so a file
  is binary or oversized in the same way however it was first read. The size goes first because it lets a search skip a
  file unread.
- On the 171,628-file game-engine checkout, a whole-tree search took 2.6–2.7 s against `rg`'s 2.8 s, which includes its
  own walk, with identical answers (2026-10-14).

## Consequences

- `grep-searcher` links `encoding_rs` unconditionally, about 138k lines, for the BOM sniffing this crate turns off, and
  with it the conjunctive licence `(Apache-2.0 OR MIT) AND BSD-3-Clause`, which `deny.toml` allows. Accepted.
- A UTF-16 source cannot be searched. Accepted.
- On Windows a symlink that replaced a file since the walk is read through. Accepted until a Windows host proves the
  reparse-point open.

## Rejected

- **Own the line scanner over `grep-regex`** — drops `encoding_rs`, and maintains a second copy of the searcher's whole
  job to save a dependency that costs compile time, not run time.
- **Read each file whole and search the slice** — makes every file's size a memory cost, so it needs a default size
  bound, which the consumer cannot afford.
- **Leave BOM sniffing on** — UTF-16 becomes searchable, and the search and `is_binary` then disagree about those files,
  and a content index keyed on raw bytes cannot narrow them.
- **Let the searcher open files by path** — follows a symlink that replaced a file since the walk, reading through a
  link this crate reports and never reads through.
- **Keep a long line's start rather than a window around its match** — on a minified line it routinely reports a line
  that does not contain the match it was reported for.

## Revisit if

The dependency's weight starts to matter more than the code it saves, or agents need to search UTF-16 sources. Medium
confidence: neither has come up.
