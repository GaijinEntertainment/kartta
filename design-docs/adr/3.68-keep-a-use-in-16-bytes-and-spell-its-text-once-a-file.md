# Keep a use in 16 bytes and spell its text once a file

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang/src/codec.rs` (uses, marks), `crates/kartta-graph/src/stored.rs` (the stored use),
  `crates/kartta-graph/src/graph.rs` (the used-name index), `kartta_lang::FINGERPRINT`
- **Pinned by:** `crates/kartta-graph/src/stored.rs::a_use_keeps_its_site_apart_from_its_receiver_and_its_access`,
  `crates/kartta-lang/src/codec.rs::a_text_the_uses_spelled_before_is_written_once`

A large tree holds millions of uses: 4.03M in the Go monorepo's graph and 3.52M in the C++ game-engine tree's
(2026-10-18). Each stored use takes 16 bytes, its receiver's form and access packed into bits its site leaves free,
and each encoded extraction spells a repeated name or path once, so the data's cost is the uses themselves, at the
price of a site limit of 2^28 definitions a file and a marks byte with no free bit.

## Decision

- The graph keeps a use in 16 bytes: the receiver's form and the access in the top four bits of `site_of`, the
  qualifier or the path interned in one slot, the name and the line in the rest. A use whose site's zero-based
  index among its file's definitions is 2^28 or more is not kept, and a use at file scope keeps only its name.
- The graph keeps an index from each used name to the files whose uses spell it, as ADR 3.7 lists.
- The codec writes a name or a path that an earlier use of the file spelled as the index of that text, names and paths
  sharing one table a file. Any codec change moves `kartta_lang::FINGERPRINT`, so a cache never serves an extraction
  of an older contract.
- The codec's marks byte holds every symbol mark, `SymbolFlags::is_reflected` the sixth (ADR 3.60), and has no free
  bit: one more mark takes a byte of its own and the codec's layout with it.

## Why

- The access and the form fit in bits `site_of` does not use: a layout with fields of their own takes 20 bytes, 16 MB
  more for the Go monorepo's uses (2026-10-18).
- One value's path and one field's name repeat across a file, and the build holds every file's encoded extraction
  until it resolves the file (ADR 1.18): spelled in full, the warm Go monorepo build's encoded extractions took 271 MB
  against 218 MB (2026-10-18).
- `find_unused` and the impact walks bind the uses of every name they weigh, and the name index keeps each to the files
  that spell it.

## Consequences

- The allocator holds more than the uses' bytes, since a block takes its whole size class: on the C++ tree 15 MB of
  power-of-two capacity around the stored uses (2026-10-18). Accepted.
- The name index takes 22 MB on the C++ tree and 9 MB on the Go monorepo. Accepted.

## Rejected

- **Access and form in fields of their own** — 4 bytes a use more, 16 MB on the Go monorepo, for no answer.
- **A 12-byte use without the path slot** — saves at most 14 MB on the C++ tree and drops the fifth of its uses that
  bind through a declared class.
- **Each use's name and path spelled in full in the encoding** — 53 MB more encoded on the warm Go monorepo build.
- **Each file's uses stored at their exact size** — the same heap, and a footprint after the build higher about as
  often as lower: the freed capacity stays among live blocks.
- **One arena a graph for every file's uses, or fewer files resolved at once** — kept the footprint within the noise,
  or raised it.
- **A decoded use with boxed strings** — 4 to 8 MB of the batch at the peak, for a `UseRef` that holds its texts unlike
  every other extracted site.
- **A prefixed qualifier string** (`@r` + path) — a string per distinct receiver and access.
- **Leaving the name index out** — saves 22 MB on the C++ tree, but a scan of every file's uses, or of the files that
  include the field's, pays its milliseconds once a name in `find_unused` and the impact walks.

## Revisit if

A language records a use that needs more than the receiver's four forms and three accesses, or a file holds 2^28
definitions. Neither is in sight.
