# Pin each wire method in a golden file both bindings replay

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-ffi/tests/golden/`, `crates/kartta-ffi/tests/fixture/`,
  `crates/kartta-ffi/tests/golden.rs`, `bindings/go/golden_test.go`, `scripts/wire-freeze.sh`
- **Pinned by:** `crates/kartta-ffi/tests/golden.rs`, `crates/kartta-ffi/tests/reference.rs`,
  `bindings/go/golden_test.go`, `bindings/node/test/golden.test.ts`

The wire of [ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md) is one contract that Rust, Go and Node each hold. Each
method's contract is a golden file, a request on a fixture tree and the answer it must get, which every binding's test
replays, so a binding type that drops a field fails; the comparison is exact but for a search score, which agrees within
a relative 1e-12. Every key of the wire stands in a golden or in a named test, and from the first release tag on the
goldens of the newest release replay as a subset, so a break needs the next major; the trade is a value the fixture
answers, which a minor release cannot move without saying so.

## Decision

- **One file per method.** Every method has a file under `crates/kartta-ffi/tests/golden`, named after it, holding
  `method`, `params` and `answer` on the fixture tree under `crates/kartta-ffi/tests/fixture`. A method whose keys only
  a second request reaches has a second file named after the method and what it pins, as `references-unmatched.json`,
  and a request a method refuses pins the `err` envelope the same way, as `list-not_found.json`.
- **Every key.** `tests/reference.rs` fails on a key of a wire struct no golden spells. A key counts for a struct only
  in an object that holds every key the struct always holds; for a struct with no such key, only in a golden of a method
  whose `WIRE.md` row names the struct as its answer; and for a struct of params, only in its method's requests. A key
  that answers to a state no fixture can hold, as a file removed after the build, a symlink on a Windows checkout or a
  watcher that failed, is listed in `PINNED_ELSEWHERE` with the file whose test pins it, and the same test compares its
  spelling with the Go and Node types.
- **The freeze.** `scripts/wire-freeze.sh`, a step of the `semver` job, replays the goldens of the newest `vX.Y.Z` tag
  on that tag's fixture through today's wire. Every key, list item in its order and value the release answered stays,
  and a key or a list item it did not hold passes. A score agrees within the tolerance, and `MAY_MOVE` of
  `tests/golden.rs` names the keys whose value may change while their key and JSON type stay: a message, `version` and
  the content index's `bytes`. The baseline and its exclusions are [ADR 4.51](/design-docs/adr/4.51-semver-gate.md)'s:
  no tag passes, and a workspace at another major than the tag passes, so a break lands after the commit that sets the
  next major.
- **The Rust replay.** The Rust test replays them through the dispatch on one handle, `build.json` first and the rest
  in file-name order, so the goldens after the refreshes pin that a refresh of the unchanged fixture changes no answer,
  and fails unless every method `version` lists has a golden. `KARTTA_FFI_BLESS=1` writes the answers the dispatch
  gives now in place of the pinned ones.
- **The Go replay.** The Go test replays them through cgo in the same order, each through its method's typed call: it
  decodes the request into the typed params, refusing unknown fields, and encodes the typed answer back, so a Go type
  that drops a field the wire sends fails. It fails when a typed call has no golden, and when `version` lists a method
  that has no typed call. The Node binding's test does the same ([ADR 4.3](/design-docs/adr/4.3-node-addon.md)).
- **Exact but a score.** Every value must match exactly, except a value under a `score` key, which agrees when it is
  within a relative 1e-12 of the pinned one. The Rust test parses the files with serde_json's `float_roundtrip`, so a
  file it blesses pins the score the engine answered on the blessing OS to the last bit.

## Why

- `search`'s scores pass through `ln_1p` in `inverse_frequency`, and Apple's libm and glibc 2.41 round it one ulp apart
  for 76 of the 820 pairs sampled, so an exact score passed only on an OS whose libm rounds as the blessing one did
  (2026-10-21).
- 1e-12 holds thousands of ulps of a score and less than a change in its twelfth significant digit, and is exact for any
  integer score below 1e12, such as fuzzy's.
- A rename that reaches `WIRE.md` too fails no name check: `hit_count` renamed both ways passed every `kartta-ffi` test
  and the Go suite, where the control `total_hotspots`, which a golden holds, failed (2026-11-02).
- `KARTTA_FFI_BLESS` rewrites any answer, so a break read as an ordinary golden change. A tag sits out of a blessing's
  reach and is the baseline [ADR 4.51](/design-docs/adr/4.51-semver-gate.md) already takes; its fixture comes with it,
  so growing the fixture after a release moves no frozen answer.
- A key a struct shares by name is not pinned by another struct's golden: by name across the files 15 answer keys and
  30 params were in no golden, and within each struct 34 and 52 were (2026-11-02).
- A struct with no always-there key matched every object: `SymlinkView`'s `path` and `kind` read as held by
  `ListedView`'s objects, which no symlink answer reached (2026-11-06).

## Consequences

- A score that moves by less than a relative 1e-12 passes unnoticed: accepted.
- A listed key meets the bindings' types as a spelling in its named type, not as a field's own type. Accepted: each is
  spelled through a named test, and the goldens hold the rest.
- A struct whose always-there keys another struct's objects also hold counts that struct's objects as its own, so
  `OpenParams`'s `root` reads as held by a walk's. Accepted: `kartta_open` is no method, and its dispatch tests pin it.
- A struct with no always-there key that sits inside another struct's answer is held by no golden, even one that
  spells it, so its keys are listed in `PINNED_ELSEWHERE`, as `SymlinkView`'s inside `FileView`. Accepted: a listing
  names the test that pins each key.
- A fix that means to move a value on the fixture names its key in `MAY_MOVE`, which frees that key wherever it lists
  it. Accepted: that edit is the visible part of the promise.
- A golden added after a tag is frozen by the next tag alone, and the freeze replays on Linux alone. Accepted.
- An enumerated value no golden answers is held by `WIRE.md` alone: 18 of the 63 outside the error codes, so the entry
  kind `other` renamed in the code and the reference passes (2026-11-02) (#1115).

## Rejected

- **Scores matched exactly** — a golden blessed on macOS failed on Linux.
- **A tolerance on every number** — a count or a line that differs is a real change, and must fail.
- **A key checked by name across every golden** — `message` and `path` of a failure read as pinned by other structs.
- **A struct with no always-there key placed by the field whose type it is** — no golden holds such a struct under a
  field, so the rule decided no key (2026-11-06).
- **A copy of the goldens in a frozen directory** — an edit at every cut for what the tag already holds.
- **A schema generated from the views, diffed with the Go and TS types** — a dependency for what goldens nearly do.
- **Keys alone, every value free** — a count that stops being counted keeps its key, and a consumer reads it as zero.

## Revisit if

A score other than through `ln_1p` comes to differ between platforms by more than 1e-12, or `MAY_MOVE` grows past the
keys that name no behavior. High confidence: the difference measured is one ulp.

## History

- 2026-11-25 — The Go replay: a method with no typed call replayed as raw JSON, so a missing call passed (#1048)

- 2026-11-06 — Every key: a struct with no always-there key counted every golden object as its own (#1186)

- 2026-11-02 — Every key and the freeze: a rename of an answer key no golden reached passed all three suites, and a
  blessing could rewrite a break (#1046)

- 2026-10-21 — Exact but a score: a fixture change could make the search golden pass on one OS and fail on another,
  since Apple's libm and glibc round some scores apart in the last digit (#294)
