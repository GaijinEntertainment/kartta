# Read a shell script's commands as calls and its sources as includes

- **Status:** accepted
- **Date:** 2026-10-16
- **Initiative:** `03-code-graph`

Bash has no modules, no namespaces and no declaration of what a script provides: `declare` assigns a variable and sets
its attributes as the script runs. A script calls a function, an alias, a builtin and a program on the `PATH` with one
syntax, and it reaches another script only through `source` or `.`. ADR 3.1 makes Bash a language of its own; this
decides what `kartta-lang-bash` extracts and how it resolves the files a script sources.

**Every command is a call of its name.** The extraction does not tell a function from a builtin or a program: a
function can come from a sourced script whose bytes the file does not hold, and the graph matches a callee against the
symbols it holds, so a list of builtins could only drop names that no symbol carries. The call belongs to the function
around it. A subshell, a loop, a `case` arm or a command substitution opens no scope, because none of them has a name
to address. A command outside every function is a call from file scope, which the graph drops; one made before the
first definition of the script is dropped by the extraction. `alias` with definitions, `source` and `.` are no calls.

**A symbol is what another script can reach by name.** A function definition is a function symbol, and so is each name
that `alias name=value` defines, because a script calls an alias like a function. A variable assigned outside every
function, bare or behind `export`, `declare`, `readonly` or `typeset`, and inside a top-level `if` or loop too, is a
variable symbol. An assignment that prefixes a command, `LANG=C sort`, sets the variable for that command alone, and
one inside a function happens only when the function runs, so neither is a symbol. With no namespaces, the qualified
name of a symbol is its name. Only a `main` function at the top of the script is the entry point, by the common style
of a script that ends in `main "$@"`.

**A sourced path is resolved from what the script spells.** A literal argument is the path. An argument that starts
with expansions, as in `"$DIR/lib/x.sh"`, `"$DIR"/lib/x.sh` or `"$(dirname "$0")/lib.sh"`, names its literal tail
without the leading `/`, and an argument that is only an expansion names nothing; so does an ANSI-C `$'...'` string,
which is essentially never a path, and so does an argument with an expansion after a literal part, `"prefix$DIR/x.sh"`,
because the tail alone would drop the literal part of a path that the extraction cannot spell. A path that starts with
`./` or `../` is relative to the sourcing script and names nothing when it climbs above the repository root. Any other
path is relative to the root, or else matches the one file whose path ends in it at a segment boundary; two such files
resolve to neither, because a wrong include is worse than a missing one. Each candidate is probed as written, then with
`.sh` and `.bash`, and the files a suffix matches are counted across all three spellings, so `lib.sh` in two
directories keeps `source lib` unresolved even when one `lib.bash` exists.

**A file is test or generated code by its name or its banner.** A `*_test.sh`, `*_test.bash` or `test_*` name, or a
`test` or `tests` directory, is test code. A `@generated`, `DO NOT EDIT` or `generated by` marker in the comment lines
that open the file is generated code, but only outside a backtick span, where documentation of the convention quotes
it.

**The fingerprint covers the walk and the grammar**, as ADR 3.4 settles for TypeScript: the crate's name, version and
source digest, and the grammar's version, node types, ABI version and table counts.

## What it costs

On three trees, the 145 shell scripts of a game engine, the 92 of a monorepo and the 45 of Homebrew's `Library`, the
282 files yield 1,210 symbols and 6,146 calls; 381 of the symbols are globals that a top-level `if` or loop assigns,
which reading only the program's direct assignments missed. One thread on macOS extracts them in 35 ms. Of the 60
`source` arguments with a literal path, 55 resolve.

## Considered Options

- **Dropping builtins and common programs from the calls** — a fixed list of names, against calls the graph already
  leaves unmatched.
- **Resolving the tail after an expansion from the sourcing script's directory** — `"$(dirname "$0")/lib.sh"` names a
  sibling of the script, but `"$ROOT/lib.sh"` names a file at the root, and the expansion does not tell which.
- **A scope per subshell or command substitution** — a scope with no name, which no query can address.

Revisit when a checkout shows sourced siblings that fail to resolve because their tails are ambiguous.
