# Read a shell script's commands as calls and its sources as includes

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-bash/src/walk.rs`, `crates/kartta-lang-bash/src/resolve.rs`
- **Pinned by:** `crates/kartta-lang-bash/tests/extract.rs`, `crates/kartta-lang-bash/tests/resolve.rs`

Bash has no modules, no namespaces and no declaration of what a script provides, and it calls a function, an alias, a
builtin and a program with one syntax. `kartta-lang-bash`, a language of its own under
[ADR 3.1](./3.1-plug-languages-in-through-a-trait.md), reads every command as a call of its name and resolves a sourced
path from what the script spells, at the price of calls that bind nothing and of sources it cannot spell.

## Decision

- Every command is a call of its name; the extraction does not tell a function from a builtin or a program. The call
  belongs to the function around it: a subshell, a loop, a `case` arm or a command substitution opens no scope.
- A command outside every function is a call from file scope wherever it stands, before the script's first definition
  too, and the graph keeps the name it spells
  ([ADR 3.112](./3.112-keep-the-names-a-file-s-top-level-calls-and-uses.md)).
- `alias` with definitions, `source` and `.` are no calls; a bare `alias` lookup is a call. The handler of `trap` and
  the completer of `complete -F`, named as one word, are uses of them
  ([ADR 3.67](./3.67-record-a-function-a-string-or-a-symbol-names-as-a-use.md)).
- A function definition is a function symbol, and so is each name that `alias name=value` defines. A variable assigned
  outside every function, bare or behind `export`, `declare`, `readonly` or `typeset`, inside a top-level `if` or loop
  too, is a variable symbol. An assignment that prefixes a command, `LANG=C sort`, and one inside a function are no
  symbols.
- The qualified name of a symbol is its name, and every symbol is exported. Only a `main` function directly at the top
  of the script is the entry point.
- A `source` or `.` argument names a path as follows. A literal argument is the path. An argument that starts with
  expansions, `"$DIR/lib/x.sh"`, `"$DIR"/lib/x.sh` or `"$(dirname "$0")/lib.sh"`, names its literal tail without the
  leading `/`. An argument that is only an expansion names nothing, and neither does an ANSI-C `$'...'` or a
  translated `$"..."` string, nor an argument with an expansion after a literal part, `"prefix$DIR/x.sh"`.
- A path that starts with `./` or `../` is relative to the sourcing script and names nothing when it climbs above the
  repository root. Any other path is relative to the root, or else names the one file whose path ends in it at a
  segment boundary; two such files resolve to neither.
- Each candidate is probed as written, then with `.sh` and `.bash`, and the suffix matches are counted across all three
  spellings, so `lib.sh` in two directories keeps `source lib` unresolved even where one `lib.bash` exists.
- A `*_test.sh`, `*_test.bash` or `test_*` file, or a file below a `test` or `tests` directory in any case, is test
  code. A `@generated`, `DO NOT EDIT` or `generated by` marker in the comment lines that open the file, outside a
  backtick span, marks it generated.
- The fingerprint covers the crate and the grammar as
  [ADR 3.120](./3.120-derive-a-language-s-fingerprint-from-its-code-and-its-dependencies-versions.md) states for every
  tree-sitter language.

## Why

- `declare` assigns a variable and sets its attributes as the script runs, and a script reaches another only through
  `source` or `.`, so the names a script can reach and the files it sources are all the structure there is.
- A function can come from a sourced script whose bytes the file does not hold, and the graph matches a callee against
  the symbols it holds, so a list of builtins could only drop names that no symbol carries.
- A subshell, a loop, a `case` arm or a command substitution has no name to address, so a scope for it could not be
  queried.
- A script calls an alias like a function. A command prefix sets the variable for that command alone, and an assignment
  inside a function happens only when the function runs. On a game engine's 145 scripts, a monorepo's 92 and Homebrew's
  `Library` 45, 381 of 1,210 symbols are globals a top-level `if` or loop assigns (2026-10-16).
- A script by the common style ends in `main "$@"`, so a top-level `main` is where it starts.
- An ANSI-C string is essentially never a path, and the tail after an interior expansion would drop the literal part of
  a path the extraction cannot spell. A wrong include is worse than a missing one, so an ambiguous suffix names nothing.

## Consequences

- A source the extraction cannot spell, or whose tail two files share, adds no include; on the three trees 5 of 60
  literal `source` arguments resolve to nothing (2026-10-16). Accepted.
- A call of a builtin or a program binds nothing and stays in the graph as an unmatched name. Accepted.
- `generated by` matches case-sensitively, so a capitalised banner is missed until a tree shows one common. Accepted.

## Rejected

- **Dropping builtins and common programs from the calls** — a fixed list of names, against calls the graph already
  leaves unmatched.
- **Resolving the tail after an expansion from the sourcing script's directory** — `"$(dirname "$0")/lib.sh"` names a
  sibling of the script, but `"$ROOT/lib.sh"` names a file at the root, and the expansion does not tell which.
- **A scope per subshell or command substitution** — a scope with no name, which no query can address.

## Revisit if

A checkout shows sourced siblings that fail to resolve because their tails are ambiguous. Medium confidence: three trees
were measured.
