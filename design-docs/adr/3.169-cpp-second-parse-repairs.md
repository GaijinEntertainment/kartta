# Repair from the first C++ tree's errors before a second parse

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-cpp/src/repair.rs` (`after_recovery`, `recovery_of`, `macro_invocation_len`,
  `annotation_macro`, `label_before_an_endif`, `misread_data_macro`), `crates/kartta-lang-cpp/src/lib.rs` (`extract`)
- **Pinned by:** `crates/kartta-lang-cpp/src/repair.rs` (`macro_repair_declines_a_local_error`,
  `macro_repair_spares_define_bodies_and_preserves_length`,
  `only_an_upper_case_name_of_three_or_more_opens_a_macro_invocation`,
  `a_function_whose_label_stands_before_an_endif_ends_at_its_own_brace`,
  `a_macro_before_a_members_scoped_return_type_keeps_the_class_open`,
  `a_class_whose_head_opens_an_error_keeps_every_member_past_its_macros`,
  `only_a_misread_classes_annotations_are_blanked`, `only_a_misread_variables_macro_is_blanked`),
  `crates/kartta-lang-cpp/src/walk.rs`
  (`an_export_macro_before_a_variables_type_keeps_the_variable`,
  `an_export_macro_before_a_variables_type_keeps_it_inside_conditionals_and_blocks`,
  `a_declaration_whose_error_outlives_the_macro_repair_emits_no_data`)

A macro invocation, a member's macro or a label that costs a C++ file its declarations is harmless on the same line of
a file that parses, so only the first tree's errors show which ones to blank. Where the first tree holds an error, the
file is parsed again from a copy that blanks those alone, at the price of a second parse of the few such files.

## Decision

- **The second parse.** Where the first tree holds an error and a repair below blanks something, the file is parsed
  again from a copy of the first parse's copy ([ADR 3.3](/design-docs/adr/3.3-cpp-parse-repair.md)) that also blanks
  the following, to spaces with every newline kept. The same copy takes the conditionals that
  [ADR 3.71](/design-docs/adr/3.71-cpp-brace-splitting-conditionals.md) repairs.
- **A spill.** The macro invocation that opens any line of an error, its first included, whose last row lies three
  rows or more past its first: an upper-case name of three or more characters, alone on its line or with its arguments
  where no `;` follows, with the macros between it and a `{` on its line, `TEST(Suite, Case) NO_ANALYSIS {`, and not
  the rest of the line, which holds the declaration a macro annotates. An error that opens at a class head runs to the
  brace that closes the class in the source. An invocation that ends an enum, its last enumerator alone on a line, is
  blanked too and is inert, since no enumerator is a symbol.
- **A misread class.** Where a tree that parses at its top level holds a class member whose opening macro the grammar
  reads as the member's type and cannot read past: the macro that opens each member of that class, up to the brace
  that closes the class in the source, past `static`, `inline`, `virtual`, `friend`, `constexpr`, `explicit` and
  `extern`, before a type and a declarator, a destructor, a conversion operator or a constructor's initializer list. A
  member the first tree reads as written keeps its macro, and so does a macro beside another macro or a compiler's own
  `__` word. The signature of a member whose macro is blanked starts past the macro. A file whose first tree fails at
  its top level is left as it is.
- **A misread variable.** The macro the grammar reads as the type of a declaration at namespace scope, inside
  namespaces, `extern "C"` blocks and conditionals alone, past `extern`, `static` and qualifiers before it,
  `extern KRNLIMP Map *map;`, `DAS_API uint32_t flags = 0;`, `EXPORT_API extern int u;`: an upper-case name with a
  word after it on its line, where the declaration holds an error or a missing node outside its initializers, each
  error holds only a type's words, and no part outside its initializers declares a function, takes parameters or
  misses its `;`. Its name decides nothing: any such macro, `MACRO_BEGIN int x = 1;`
  included, reads as an annotation of the variable after it. The signature of a variable whose macro opens it starts
  past the macro.
- **A label before an `#endif`.** The label and colon of a label the grammar reads an `#endif` under, `skip:` right
  before the `#endif` that closes its branch, where the first tree holds that `#endif` as an error in the label's
  statement.
- **A `#define` stays.** The spill and the misread class never blank a line of a `#define`, its first line or a
  continuation.
- **An improvement, never a precondition.** A second parse that yields no tree leaves the walk to the first copy,
  parsed again ([ADR 3.31](/design-docs/adr/3.31-cpp-numeric-tables.md)).

## Why

- A line identical to a harmful one is harmless in a file that parses, so only the first tree's errors show which
  invocations cost something; a macro invocation spans one to three rows, so a shorter error consumed nothing else.
- A macro left before a body reads as a compound literal's type, which takes the body's locals past its first
  statement to namespace scope: 4 of abseil's `mutex_test.cc` locals read as file variables (2026-10-24, #369).
- A misread member closes its class at its own brace, and the members after it parse outside the class; the source's
  brace, not the tree's, bounds the class, and a member read as written beside its macro keeps it.
- A namespace-scope declaration holds only declarations, so the words after a macro that stands before a type and a
  declarator name a variable whatever the macro expands to; the walk takes no data from a declaration holding an
  error, and blanked, the variable reads as written. On the game-engine tree 997 data symbols came back in 139 files,
  30 of 30 sampled right, and no symbol was lost (2026-10-29, #406).
- A label that ends a branch takes the `#endif` for its statement, and the conditional never closes: duktape's
  `duk_hobject_enumerator_create` spanned lines 52384 to 77150, not 52737. A label is no symbol, call or use, and
  blanking it brings back a lost function in 5 game-engine files and changes no other file (2026-10-24, #368).

## Consequences

- A second parse of the files whose first tree shows a misreading, 1,464 of the 43,356 game-engine files (2026-10-24,
  #370).
- The spill repair drops the calls written inside a blanked invocation's arguments; 123 of 621 such calls named a
  definition elsewhere (2026-10-16, #30). Accepted.
- A class a macro builds, or one that breaks at a conditional inside a constructor's initializer list, still parses
  apart (#439, #407); PhysX's `Facet` reads as an error at `PX_ALIGN(16, PxVec3 m_closest);` once its macros are
  blanked.
- A file whose first tree fails at its top level, as `vulkan_structs.hpp`'s does, keeps its misread members (#412).
- The misread variable parses 280 more game-engine files twice, 1,745 against 1,465 without it, for 0.85% more
  instructions of C++ extraction (2026-10-29, #406). A function whose parameter is a function pointer, `KRNLIMP void
  set_pump(void (*pump)());`, reads as a variable, 2 on that tree. Accepted.

## Rejected

- **Re-parse wherever an error holds a macro invocation** — 855 files parsed twice instead of 163, for 12% of the
  recovered symbols (#30).
- **Require an argument list of a blanked invocation** — spares the last enumerator but costs 62 symbols and doubles
  the losses (#30).
- **Blank the macros after an invocation to the end of its line** — brings back 4 jemalloc functions and drops 68
  calls of macro runs such as pcre's `LBL( 1) LBL( 2)` (2026-10-24, #369).
- **Blank only a variable's macro named as an export macro, `_API`, `_EXPORT`, `IMP` and the like** — keeps 176 of the
  997 symbols, losing annotations such as `XMGLOBALCONST` and `ABSL_CONST_INIT` (2026-10-29, #406).
- **Blank a namespace-scope declaration's macro wherever an error follows it** — lost 81 symbols in 45 files, as
  `static STACK_OF(BIO) *f();` and in-class constructors folded into their definitions (2026-10-29, #406).
- **Blank a variable's macro alone on its line too** — renamed 390 functions of 5 files and lost 2 symbols, as a
  namespace's closing macro above `STDAPI f(`, for 104 symbols more (2026-10-29, #406).
- **Blank every member macro of the file, not the misread class's** — changed 919 files and lost 72 callables the
  second parse misread elsewhere; without the check that keeps a member read as written, 6,863 signatures changed
  instead of 2,156 (#365).

## Revisit if

A `tree-sitter-cpp` release moves where the first tree's errors fall, or the files parsed twice grow well past 4% of a
tree's C++ files. High confidence that 0.23.4 stays the latest for the near term.
