# Keep a graph's files in path order through labelled blocks

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-16
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/order.rs`, `crates/kartta-graph/src/graph.rs` (`tree_order`, `path_rank`)
- **Pinned by:** `crates/kartta-graph/src/order.rs` (`ranks_follow_the_paths_whatever_order_the_files_arrive_in`,
  `files_that_arrive_before_every_other_split_and_relabel_the_blocks`, `a_removal_keeps_the_order_of_the_rest`),
  `crates/kartta-graph/tests/graph/calls.rs::the_first_in_path_order_wins_however_the_files_arrived`

The call cascade and the answers break their ties by path order (ADR 3.7), and a refreshed or followed tree inserts
files out of that order. Each file's rank is its block's label above its place in the block, so an insert renumbers one
block, and a relabel of every block waits for thousands of inserts at one place.

## Decision

- Path order is the file index's tree order, in which `/` sorts below every other byte, whatever order the files
  arrive in.
- A file's rank is the label of its block above its place in that block. A block splits past 512 files into one of
  256 and the rest, and takes a label halfway to the next block's, at most 2^16 above its own.
- An insert or a removal renumbers the files of one block. Every block is relabelled, evenly spaced, only when the room
  between two labels runs out, after at least sixteen splits at one place, about 4,000 inserts.

## Why

Renumbering every file after an insert out of order made a build grow with the square of the files it took out of
order: a shuffled build of 1.46M files took 387 s that way, and takes 6.9 s in blocks (2026-10-16). Refresh and watch
(ADRs 1.15, 1.17 and 4.4) insert files out of order.

## Consequences

Each slot holds a 64-bit rank beside its block's list of slots; one insert out of order at 2.9M files costs about 2 ms.

## Rejected

- **Dense path ranks renumbered on each insert** — one integer per file and no blocks, but a build out of path order
  grows with the square of the files.

## Revisit if

A followed tree inserts at one place in runs long enough that full relabels show in a refresh's profile. Not measured
on a watch stream; the shuffled and reversed builds of 1.46M files relabel without cost.
