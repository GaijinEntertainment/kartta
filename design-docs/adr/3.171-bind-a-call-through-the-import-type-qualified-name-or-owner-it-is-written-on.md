# Bind a call through the import, type, qualified name or owner it is written on

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`resolve_by_tiers`, `through_binding`,
  `written_inside_an_enclosing_scope`, `nested_in_written_owner`, `member_of_the_written_class`),
  `crates/kartta-graph/src/scope.rs` (`member_of_a_reached_owner`, `member_of_the_receiver_s_owner`),
  `kartta_lang::Conventions` (`scope_separator`, `class_member_separator`)
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`

A call written on an import, a type, a qualifier or an owner names where its callee lives, as the language's own lookup
reads it. Tiers 2 to 5 of the cascade of [ADR 3.7](./3.7-resolve-calls-when-a-query-asks.md) bind such a call there
before any tier binds by name alone, at the cost of the calls whose receiver is a value of no type the graph records.

## Decision

Each tier binds at the confidence given, from `kartta_graph::confidence`:

2. A receiver that names an import binding binds the target's export, at 95. A directory that exports no callable of
   the name, or an import of code the graph does not hold, ends the cascade with nothing bound.
   [ADR 3.45](./3.45-bind-a-call-through-a-module-s-file-as-the-module-s-paths-see-it.md) binds a target that is a
   module's file.
3. A receiver that is a type path binds the method of the type the path reaches, at 85 (ADR 3.29).
4. A callee written qualified binds, inside a namespace, the definition its innermost enclosing scope names that the
   caller's file sees, at 88; else the symbol of that qualified name, the first in path order, at 90; else its trailing
   owner and name where the language joins scopes with a separator, at 88. Of the namesake classes that hold that
   member, the one the written scope names from the scopes around the call outward binds, by the lookup of
   [ADR 3.65](./3.65-tell-c-plus-plus-namesake-classes-apart-by-the-scopes-a-use-writes.md); the first in path order
   binds where the scope names none of them, or where the graph locates no class of the first. A callee written from
   its owner alone, `Widget::Kind`, binds the member of that owner whose longer qualified name ends in it, the one the
   caller's file sees first, at 88. A callee written from the root names a global symbol.
5. A receiver that names the caller's base class binds the base's member, at 85, or nothing
   ([ADR 3.168](./3.168-bind-a-call-through-the-base-receiver-to-the-base-class-s-member.md)). A receiver that names
   an owner binds that owner's member, at 85: the owner in the caller's file, then in its directory, then in its
   package where a package is not a directory, then the first in path order.
   [ADR 3.180](./3.180-bind-a-c-plus-plus-call-on-a-declared-class-through-the-class-nearest-the-caller-s-file.md)
   binds the class a C++ operand is declared as, and
   [ADR 3.47](./3.47-bind-a-c-plus-plus-call-on-a-field-through-the-class-the-field-is-declared-as.md) the class of
   the caller's class's field a C++ call names. A Rust call through a type the graph holds no definition of binds
   nothing past this tier ([ADR 3.176](./3.176-bind-no-rust-call-through-a-type-outside-the-graph.md)), and a Rust
   owner of a crate the caller's crate is not built with binds nothing
   ([ADR 3.179](./3.179-bind-a-rust-call-by-name-only-within-the-crates-its-crate-is-built-with.md)).

`scope_separator` gates tier 4 and the calls written from the root. Where `class_member_separator` keeps a class's own
methods apart, a receiver that ends in it is the class, and every tier that takes one of an owner's members of the name
takes the kind its receiver reaches first ([ADR 3.15](./3.15-qualify-a-ruby-member-by-its-whole-namespace-chain.md)).
A file's package is the one ADR 3.7 names.

A receiver that is a value names no owner; each language's extraction says what it records for one: TypeScript and
JavaScript in
[ADR 3.101](./3.101-name-no-type-for-a-typescript-or-javascript-call-on-a-value-the-file-declares.md), Rust in
[ADR 3.56](./3.56-name-a-rust-call-s-receiver-only-where-its-syntax-spells-it.md) and
[ADR 3.55](./3.55-name-a-rust-method-call-s-receiver-by-its-parameter-s-declared-type.md), C++ in
[ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md), and Go in
[ADR 3.29](./3.29-name-a-go-receiver-by-the-type-its-declarations-spell.md).

## Why

- A receiver or a qualifier is where the language's own lookup starts for the call, so the tier that reads it is the
  surest one the call has.
- A crate names its own types far more often than another crate's of the same name, and a cargo registry keeps the
  versions of one crate side by side: of the Rust pairs the package step rebinds to the caller's own package on a
  registry of 496 crates, 29 of 30 sampled were right (2026-10-24). Where a package is a directory, the directory step
  is the package's, and a package of the same declared name elsewhere, as Go's many `main`s, is another package.
- A C++ member's qualified name keeps only its class's bare name
  ([ADR 3.72](./3.72-qualify-c-plus-plus-names-the-way-the-graph-matches-them.md)), so `b::Widget::draw` matches
  `a::Widget`'s method as well, and the written scope is what tells them apart: all 76 C++ call sites it moves on the
  game-engine tree bind the class the scope names (2026-10-24).

## Consequences

- A namespace-relative C++ call written in a member function binds nothing (#457).
- A qualified C++ callee whose first namesake is an out-of-line definition the graph locates no class of keeps the first
  in path order whatever its scope names: physx 3.4's `Gu::PersistentContactManifold::drawPolygon` (#604).

## Rejected

- **One slot per qualified name, the last in path order** — an insert or a removal cannot keep it, so the slot becomes
  a read over the name's definitions.
- **Bind the class the written scope names wherever the first namesake has no located class** — moved about 30 calls
  from a definition to its own declaration, the same method at a worse location (2026-10-24).

## Revisit if

A language's calls name another package's owner of a name about as often as their own package's, so the nearest owner
stops being the likelier callee. Held with high confidence on the registry sample.
