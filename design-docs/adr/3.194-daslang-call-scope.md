# Bind a bare daslang call only within what its file reaches

- **Date:** 2026-11-01
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`can_bind_by_name`, `is_in_the_caller_s_scope`),
  `crates/kartta-lang-daslang/src/lib.rs` (`CONVENTIONS`), `kartta_lang::Conventions::module_seen_everywhere`
- **Pinned by:** `crates/kartta-languages/tests/engine.rs`
  (`a_bare_daslang_call_binds_no_definition_its_file_does_not_reach`,
  `a_bare_daslang_call_binds_no_type_its_file_does_not_reach`,
  `a_bare_daslang_call_binds_the_definition_a_module_it_requires_requires`,
  `a_bare_daslang_call_binds_the_definition_a_file_it_includes_includes`,
  `a_bare_daslang_call_binds_the_builtin_module_with_no_require`,
  `a_daslang_member_call_binds_a_method_of_a_file_it_does_not_reach`)

A script definition enters a daslang file's scope only through a `require` or an `include`, and native code is outside
the graph, so a bare call of a native function bound any script namesake by the name alone. Where a language names the
module every file sees, a call with no receiver binds by its name alone only what its file reaches. The trade: a
`require` the resolver cannot name hides what stands behind it.

## Decision

- **Scope.** Under `Conventions::module_seen_everywhere`, a call with no receiver binds at the name's one callable, one
  type or nearest definition (tiers 60, 50, 30 and 15) only a definition of a file its own file reaches through
  includes, however deep, or of the file whose package that convention names. Elsewhere it binds nothing. The rule only
  turns away: it raises no pair, and the tiers above it read what they read.
- **The module every file sees.** Daslang names `builtin`, the module clause of `daslib/builtin.das`. The compiler
  compiles that file into module `$`, which every other module requires (`src/ast/ast_module.cpp:414`).
- **The transitive closure.** The rule reads every file the includes reach, though the compiler sees past a direct
  `require` only through a `public` one: the graph keeps no `public`, and a wider reach keeps a pair.
- **A member call.** A call with a receiver is out of the rule: `u.twist()` reads its object's type, which no `require`
  of the caller's file has to name.

## Why

- 7,430 of the 69,551 daslang pairs on the game-engine tree name a function with a native binding of the call's count
  (2026-11-01, #739). 2,345 of them sit in a file no `require` reaches, as `cross(a, b)` bound a shader stub, `int(x)` a
  test fixture and `slice(s, 0, 8)` an audio pattern library's `slice`.
- With the sibling lookup of [ADR 3.140](/design-docs/adr/3.140-daslang-module-lookup.md), the rule removes 2,836 pairs,
  58 of 60 sampled false. The lookup adds 16, all right, and moves 336 up a tier, 30 of 30 sampled right.

## Consequences

- A `require` the resolver leaves unnamed hides its module, since a `require` of two candidates names neither: the 39
  of 26,161 on that tree that [ADR 3.140](/design-docs/adr/3.140-daslang-module-lookup.md) leaves to a project's table,
  as `require danetlibs.dm.dm_events`. Accepted (#845).
- A file without `options gen2` extracts to nothing, so a `require` of one ends the reach there. Accepted: a module such
  a file re-exports loses its name-only pairs, and the sampled pairs behind one, `approach` and `deg_to_rad`, were
  false.
- The rule costs one include closure per calling file, which `reaches` computes when a query asks. Accepted.

## Rejected

- **The rule alone, without the sibling lookup** — removes 5,769 pairs, about half of a 40-pair draw right, because
  `require testing` in `dastest/testing_boost.das` named nothing and hid `success` from every test.
- **Only a direct `require`** — turns away what a `public` require re-exports, among the 3,723 pairs that bind at 60
  past a direct `require`.
- **A list of the native names** — the names live in each project's C++ modules, 8,885 on the game-engine tree, and a
  name in the list says nothing of which overload a call reaches.

## Revisit if

The compiler puts a script definition in scope another way than a `require`, an `include` or `module builtin`, or a tree
leaves many `require`s unnamed. Held with moderate confidence: the removed pairs were sampled, not read whole.
