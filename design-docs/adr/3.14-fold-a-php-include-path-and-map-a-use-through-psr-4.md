# Fold a PHP include path and map a use through PSR-4

- **Status:** accepted
- **Date:** 2026-10-16
- **Initiative:** `03-code-graph`

PHP names a dependency in two ways. Legacy code loads a file at run time with `include` or `require` and a path
expression, often `__DIR__ . '/x.php'` or `dirname(__FILE__) . '/../x.php'`. Composer code writes `use App\Foo`, and the
autoloader finds the class's file through the PSR-4 map of a `composer.json`. The extraction sees only the bytes of a
file, and a cache shares that result between every file with the same bytes, so the extraction cannot know the path that
`__DIR__` names.

**An include path folds to a constant, with the path constants left as markers.** A string, `__DIR__`, `__FILE__`, a `.`
concatenation of those, and `dirname` of one fold to a path. Any other operand, a variable, an interpolated string or a
call of another function, folds to nothing, and the include adds nothing. `__DIR__` and `__FILE__` fold to markers that
the resolver substitutes with the file's directory and path. A literal that holds the marker byte folds to nothing, so a
substitution cannot make a path that the source did not write.

**A path constant names a file only at the start of the path.** `__DIR__` and `__FILE__` are absolute at run time, so
`'inc/' . __DIR__` names no file, and the extraction drops it. A substitution there would put a relative directory in
the middle of a path and could reach a file that PHP never opens.

**`dirname` is lexical, as in PHP.** It removes the trailing separators and cuts at the last `/` as written, without
applying `.` and `..`. The fold cuts the path itself where that `/` follows the last marker. Where the cut would fall
inside a marker, `dirname(__DIR__)`, the fold adds a climb marker, which the resolver writes as `/..` and applies
against the real path. The climb is a marker of its own, not a written `/..`, because a later `dirname` strips a
written `..` but composes with a climb: `dirname(__DIR__ . '/..')` is the file's directory, and
`dirname(dirname(__DIR__))` is two levels up. `dirname(__FILE__)` is `__DIR__`. `dirname(__DIR__)` in a file at the
root names the parent of the checkout, and includes nothing.

**A folded path resolves from where PHP would find it first.** A `./` or `../` path and a path under the file's own
directory resolve from that directory. Any other path resolves from the root, or else to the one file of the repository
whose path ends in it. Two such files resolve to nothing, because a guess between them is a wrong edge.

**A `use` resolves through the PSR-4 map of the project's `composer.json` files.** The resolver reads every
`composer.json` outside a `vendor` or `node_modules` directory, and takes the `psr-4` mappings of `autoload` and
`autoload-dev`, with their directories relative to that `composer.json`. A longer prefix maps first, and the empty
prefix, Composer's fallback, maps any name after every other prefix. A name maps to its remaining segments under the
prefix's directory, `App\Models\User` to `src/Models/User.php`. A function or a constant lives in the file of its
namespace, so the name of a `use function` or a `use const` that maps to no file maps once more without its last
segment. A class name maps only to its own file, because the file of its namespace is a different class's file, and an
edge to it would be wrong. A grouped `use App\{Foo, Bar}` resolves each name with the shared prefix, and each clause of
a mixed group by its own kind.

**A mapped `use` is an include, and any other `use` an import.** A `use` that maps to a file of the repository is an
include of that file. A `use` of a vendored package or of an extension maps to nothing, and stays an import as written.

**A member is qualified by the namespace, and owned by its type's bare name.** `App\Service::greet` is the qualified
name of a method, and `Service` its owner, the name that a static call writes as its receiver after a `use`. A
qualified scope, `\App\Service::make()`, records its last segment as the receiver, so that it names the same owner.
Two classes of one name in different namespaces share an owner. A bare call never reaches a method of its own class,
because PHP calls one only through `$this`, `self` or `static`. A closure assigned to a variable is a callable, which
makes the calls in its body. A closure passed as an argument is not, and the calls in its body are calls of the
callable around it.

On Laravel, 1,570 PHP files give 17,694 symbols, 38,392 calls and 5,465 uses: 3,508 includes and 1,957 imports. On
Composer, 314 files give 1,895 uses, of which 1,350 are includes. On WordPress, 1,931 files give 189 includes and
requires that fold, of which 188 resolve.

## Considered Options

- **An import for every `use`, also one that maps** — keeps the name as written beside the include, but states one
  dependency twice, and the contract keeps an import for a module that names no repository file.
- **Fold `__DIR__` to the path at extraction** — no markers, but the result then depends on the path, and the cache
  could not share it between files with the same bytes.
- **`dirname` as a climb every time** — one rule instead of two, but a climb applies `..` where PHP's `dirname` strips
  it, and an include with a written `..` resolves one level too high.

Revisit when the extraction reads the PSR-0, `classmap` or `files` autoload of a `composer.json`, or the constants,
such as `ABSPATH`, that a project defines for its include paths. Revisit the bare owner when two classes of one name in
different namespaces join their members on a real tree.
