A member call `x.f()` calls what `x` holds. Some extractions read what a value holds as a free function, so near the
caller a free function can be the one called; far from it, nothing ties one to the receiver. `Conventions::member_calls`
says per language where a member call may take a free function, and no member call takes a free variable or constant.

## Decision

- A member call admits a free function and never a free variable or constant.
- At the last proximity step, the one callable outside vendored code, a member call takes a member alone.
- `MemberCalls::NearbyFreeFunctions`, the default: where no member of the name is a candidate, a member call takes a
  free function that the caller's file, imports, package or includes offer, the one definition of its name wherever it
  lies, or the one in the caller's directory or the one above it. C++ keeps this mode, as does every language that sets
  no other; a C++ call on a value still takes no proximity step (ADR 3.43).
- `MemberCalls::Members`: a member call takes a member alone at every tier. Go sets it.
- `MemberCalls::ModulePaths`: a member call takes a free function only through a receiver whose last segment starts in
  lower case or with `_` and is not one of `Conventions::own_type_receivers` (ADR 3.41), a module's receiver, and there
  only where `NearbyFreeFunctions` takes one. Every other receiver takes a member alone at every tier: the empty one,
  an own-type receiver, a type written capitalised, and a value's name, which the Rust walk writes after a `.` so that
  it names no module, import or owner
  ([ADR 3.56](/design-docs/adr/3.56-rust-call-receivers.md)). Rust sets it.
- Under `ModulePaths` a module's receiver takes a member only through the owner it names, at the receiver's tier, and
  of the caller's own file, at every tier, only the item whose qualified name ends with the receiver: `walk::join()`
  takes the `walk::join` of an inline `mod walk`, and no other `join` of the file, free or a member, not even as the
  one definition of its name.
- A member call still counts the free functions of its name against the one callable of the name: beside a free
  namesake it binds no member that way, and counts as ambiguous.

## Why

- Extractions read an object's property, a table's slot, a module that a name holds and a Rust path through a module as
  free functions, so near the caller a free function can be what a value holds: jQuery UI calls the `addClass` of the
  jQuery beside it, and a Quirrel table hands out `mkButton`.
- Far from the caller the one free function of a name is a namesake: 90% of the TypeScript and JavaScript sites the
  last step bound to one on the C++ game-engine tree call a method of the JavaScript runtime (2026-10-17).
- A Go member call reaches a method or a field of its value, and a package's function only through the import, which
  binds before any tier that takes a member.
- A Rust method call never calls a free function; a path through a module does. Every sampled pair the mode removed in
  this repository bound a wrong free function (2026-10-22).
- A Rust path through a module names an item of its own file only through the item's inline modules, and a member
  only through its type: each of the 60 pairs a module's path bound to another item of its own file or to a member, in
  this repository, tree-sitter and the Go monorepo snapshot, was a namesake, as `std::mem::take(..)` binding a file's
  `Backend::take` (2026-10-23).
- C++ calls no free function through a member call, but its extraction still reads some class heads' members as free:
  with the heads that macros and attributes hide parsed, `Members` dropped 13,283 pairs, about 70% true, and added
  4,117, about 60% true (C++ game-engine tree, 2026-10-19).

## Consequences

- A C++ member call can still take a free namesake where a misread class head turns the member into a free function
  (#439).
- About 20 Rust calls of js-sys functions that wasm-bindgen makes a type's static method, `Number::is_nan(x)`, read as
  free and lose their binding (#357).
- A member call beside a free namesake binds nothing and counts as ambiguous, as `index.refresh_paths()` beside a test
  helper of that name does.
- A trait's function called through a primitive type, which the walk spells as it does a module, binds nothing:
  zerocopy's `u32::read_from(..)` loses `FromBytes::read_from`, about half of 185 such registry pairs right (40
  sampled). Accepted.

## Rejected

- **A member alone at every tier, in every language** — unbinds what a value holds in the caller's own file and
  includes: 12,488 TypeScript and JavaScript pairs and 14,334 Quirrel pairs on the C++ game-engine tree (2026-10-17).
- **A member alone at every proximity step, in every language** — also unbinds the calls nearness finds right: 941
  TypeScript and JavaScript sites that call no runtime method, and 2,047 C++ calls of members read as free (C++ tree,
  2026-10-17).
- **A member alone at the one callable of the name too** — unbinds the one definition of a name that a value holds:
  4,820 Quirrel pairs, `events.getEventByName()` among them (C++ tree, 2026-10-17).
- **A member call's shape from every candidate of the name** — keeps a far free function wherever no member of the name
  exists, so `path.join()` binds a bundle's `join`: 44% of the far pairs stay (C++ tree, 2026-10-17).
- **`MemberCalls::Members` for Rust** — also drops the calls through a module: 4,885 more pairs in a cargo registry of
  488 crates, every sampled one right, as tree-sitter's `ffi::ts_tree_root_node()` (2026-10-22).
- **The empty receiver for a Rust call on a lowercase value** — names nothing a runtime method's owner could be spelled
  by, and drops right pairs: the 18 callers of `Watcher::drain` (2026-10-22).
- **The empty receiver for a capitalised Rust operand too** — drops 27 pairs at 85 in the registry, nearly all right
  (2026-10-22).
- **A member alone only on a value, a path through a type keeping nearby free functions** — keeps 1,983 of the
  registry's removed pairs through a type, every sampled one wrong (2026-10-22).
- **A primitive's path read as a type's, `str::from_utf8()`** — drops 24 more registry pairs, about half of them right,
  since `str` and `char` also name modules (2026-10-22).
- **The path checked at the same-file tier alone** — leaves a member of the caller's file to the one callable of its
  name: 6 of tree-sitter's pairs fall from 80 to 60 rather than unbind, each a namesake (2026-10-23).
- **A module's receiver kept from members alone** — keeps the members a runtime method's name admits, so
  `usize::from(..)` still binds a `From` impl of the caller's file: 14 pairs on the three trees (2026-10-23).
- **A primitive's path kept apart from a module's, its members admitted** — keeps the 185 registry pairs above, about
  half wrong, as `u16::to_be(..)` binding num-traits' `PrimInt::to_be`, at the cost of the primitive names in the graph
  (2026-10-24).
- **A trait's member admitted through any module's path** — binds `axum::serve(..)` to a trait's `serve`, and a trait
  namesake beside an inline module unbinds `small::normalize(..)`: 263 pairs added and 41 removed in the registry,
  mostly wrong (2026-10-24).
- **The tiers past the same-file one left to count the file's free namesake** — bind the same pairs on the three trees,
  and leave `outside::shared()` the file's own `shared` as the one definition of its name (2026-10-23).
- **A flag on each call that its receiver is a value** — binds as the marked name does, at the cost of a field that
  every language's walk and the extraction cache's encoding would carry.

## Revisit if

The C++ extraction reads every class head, so that no member reaches the graph as a free function; `Members` for C++
then needs a new measurement. The 2026-10-19 measurement holds for the class heads the extraction parsed that day.
