# Bind a member call to a free function only where a value can hold one

- **Date:** 2026-10-17
- **Governs:** `crates/kartta-graph/src/scope.rs` (`shape`, `takes_a_member_alone`, `one_callable`,
  `receiver_names_a_type`, `resolve_by_proximity`), `crates/kartta-graph/src/resolve.rs` (`resolve_by_name`),
  `crates/kartta-lang-go/src/lib.rs`, `crates/kartta-lang-jsts/src/lib.rs` (`CONVENTIONS`), `kartta_lang::MemberCalls`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`
  (`a_member_call_takes_a_free_function_in_the_caller_s_directory_and_none_beyond_its_parent`,
  `a_member_call_takes_the_one_member_beyond_its_parent_directory`,
  `a_member_call_that_calls_members_alone_binds_no_free_function_at_any_tier`,
  `a_member_call_binds_a_free_function_its_file_defines_or_the_one_of_its_name`,
  `a_member_call_binds_no_free_value_and_a_bare_call_still_does`), `crates/kartta-languages/tests/engine.rs`
  (`a_javascript_call_through_a_class_binds_no_function_outside_every_type`)

A member call `x.f()` calls what `x` holds. Some extractions read what a value holds as a free function, so near the
caller a free function can be the one called; far from it, nothing ties one to the receiver. `Conventions::member_calls`
says per language where a member call may take a free function, and no member call takes a free variable or constant.

## Decision

- **No free value.** A member call admits a free function and never a free variable or constant. A method call admits
  no type either ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md)).
- **The last proximity step.** At the last proximity step, the one callable outside vendored code, a member call takes
  a member alone.
- **Nearby free functions.** `MemberCalls::NearbyFreeFunctions`, the default: where no member of the name is a
  candidate, a member call takes a free function that the caller's file, imports, package or includes offer, the one
  definition of its name wherever it lies, or the one in the caller's directory or the one above it. C++ keeps this
  mode, as does every language that sets no other; a C++ call on a value still takes no proximity step
  ([ADR 3.43](/design-docs/adr/3.43-cpp-calls-on-values.md)).
- **Calls through a type.** `MemberCalls::NearbyFreeFunctionsUnlessTyped`: as above, but a receiver that names a type
  the caller's file holds or includes takes a member alone at every tier, unless that file is generated. TypeScript and
  JavaScript set it.
- **Members alone.** `MemberCalls::Members`: a member call takes a member alone at every tier. Go sets it.
- **Module paths.** `MemberCalls::ModulePaths`: a member call takes a free function only through a module's path, as
  [ADR 3.184](/design-docs/adr/3.184-rust-module-path-calls.md) decides. Rust sets it.
- **A free namesake.** A member call still counts the free functions of its name against the one callable of the name:
  beside a free namesake it binds no member that way, and counts as ambiguous.

## Why

- Extractions read an object's property, a table's slot, a module that a name holds and a Rust path through a module as
  free functions, so near the caller a free function can be what a value holds: jQuery UI calls the `addClass` of the
  jQuery beside it, and a Quirrel table hands out `mkContextMenuButton`.
- Far from the caller the one free function of a name is a namesake: 90% of the TypeScript and JavaScript sites the
  last step bound to one on the C++ game-engine tree call a method of the JavaScript runtime (2026-10-17, #61).
- A Go member call reaches a method or a field of its value, and a package's function only through the import, which
  binds before any tier that takes a member (#61).
- A type's call reaches its members, yet an object literal's property reads as a free function, so with the type a
  parameter's annotation spells ([ADR 3.101](/design-docs/adr/3.101-jsts-value-receivers.md)) `options.onSuccess()`
  still bound the literal around it. A type of the name only elsewhere is a namesake, a minified bundle's `class $` of
  jQuery's `$`, and a minifier's names say nothing of a type: without the generated exception the rule removed 48 pairs
  in SillyTavern's bundles, an object's `ne.isFile()` for an unrelated `class ne` among them (2026-10-31, #475).
- C++ calls no free function through a member call, but its extraction still reads some class heads' members as free:
  with the heads that macros and attributes hide parsed, `Members` dropped 13,283 pairs, about 70% true, and added
  4,117, about 60% true (C++ game-engine tree, 2026-10-19).

## Consequences

- A C++ member call can still take a free namesake where a misread class head turns the member into a free function
  (#439).
- A member call beside a free namesake binds nothing and counts as ambiguous, as `index.refresh_paths()` beside a test
  helper of that name does.

## Rejected

- **Calls through a type in every language** — removed 14 pairs on the game-engine tree, every one true: Python's nested
  `DataBlock.Parser()`, and Quirrel's `clanRewardsModal.open()` through a table that shares a class's name (2026-10-31).
- **A member alone at every tier, in every language** — unbinds what a value holds in the caller's own file and
  includes: 12,488 TypeScript and JavaScript pairs and 14,334 Quirrel pairs on the C++ game-engine tree (2026-10-17).
- **A member alone at every proximity step, in every language** — also unbinds the calls nearness finds right: 941
  TypeScript and JavaScript sites that call no runtime method, and 2,047 C++ calls of members read as free (C++ tree,
  2026-10-17).
- **A member alone at the one callable of the name too** — unbinds the one definition of a name that a value holds:
  4,820 Quirrel pairs, `events.getEventByEconomicName()` among them (C++ tree, 2026-10-17).
- **A member call's shape from every candidate of the name** — keeps a far free function wherever no member of the name
  exists, so `path.join()` binds a bundle's `join`: 44% of the far pairs stay (C++ tree, 2026-10-17).

## Revisit if

The C++ extraction reads every class head, so that no member reaches the graph as a free function; `Members` for C++
then needs a new measurement. The 2026-10-19 measurement holds for the class heads the extraction parsed that day.
