# Read the BLK mount table from the files that state it by name

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-16
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-blk/src/mounts.rs`, `crates/kartta-lang-blk/src/resolve.rs` (`BlkResolver::new`,
  `MOUNT_FILE_NAMES`), `crates/kartta-lang-blk/src/walk.rs` (`record_mounts`)
- **Pinned by:** `crates/kartta-lang-blk/tests/resolve.rs`

A BLK `%name/rest` include names `rest` below the directory a mount table maps `name` to, and the engine takes that
table from whatever file an application names. A resolver sees only the `Repository`, which finds a file by its name
and cannot list files by extension, so it reads the table from the files of four conventional names, one read each; a
mount stated in a file of another name is not seen.

## Decision

1. The mount table is the first `mountPoints` block at the root of each file named `settings.blk`, `application.blk`,
   `aot_config.blk` or `libs_aot_config.blk`. A `mountPoints` block anywhere else, and any later one, states nothing.
2. A child block maps its name to its first parameter named `forSource`, which must be a `t` string: a first
   `forSource` of another type maps nothing, whatever follows it. That directory is relative to the working directory
   of an application, which no file states: a path that climbs out of it with leading `..` names the part after them
   below an ancestor of the stating file, and exactly one ancestor must hold the target. A path that does not climb
   lies inside the working directory and names no repository directory.
3. A `t` parameter of the block maps its name to a directory relative to the stating file, as an AOT compiler reads its
   `--config` file.
4. A mount name drops one leading `%` and must be ASCII letters, digits and `_`, shorter than 64 bytes; within a file a
   later entry of a name replaces an earlier one, and a block that maps nothing erases it. A directory that is
   absolute, starts with `%` or holds `:` names no repository directory. A mapping that names no repository directory
   still counts as stated: where it is among the nearest, the include names no file.
5. The mappings stated nearest the including file, the stating files that share the most leading path components with
   it, decide, and every one of them must place the same file; otherwise the include names none. The engine reads the
   name up to the first `/` of the path, in its letter case.
6. The resolver keeps only the mount table it derived, and a followed engine resolves no BLK file again for an edit
   that changes no mount, as
   [ADR 3.82](./3.82-build-a-followed-family-s-resolver-again-only-when-a-refresh-reaches-what-it-read.md) states.

## Why

- A second read of every BLK file breaks the single read per file that the index gives (ADR 1.12), and a resolver
  cannot list the files its language claims.
- The four names are the conventions of a game's settings file, a tool's configuration and the `--config` files of the
  daScript AOT compilers.
- On the game-engine tree every mount-path include is in one game whose three `settings.blk` files state its mounts,
  and no include resolves differently without the six other files that open a root `mountPoints` block (2026-10-16).
  The four names cost 44 reads there.

## Consequences

- A mount stated only in a file of another name, such as `eden.settings.blk` or `wt_aot_config.blk`, is not seen, and
  its includes stay imports. No include on the tree measured. Accepted.

## Rejected

- **A second read of every BLK file in the resolver** — the full table, at the cost of 82,254 more reads per build on
  that tree.
- **A resolver built over the raw extractions of the files its language claims** — the full table without a second
  read, because every BLK extraction already holds its mount directives; it changes the `kartta-lang` contract of
  ADR 3.1, so it needs a decision of its own.

## Revisit if

A resolver can see the extractions of the files its language claims, or a tree states the mounts its includes need in
a file of another name. Held with high confidence for the tree measured, where no include depends on another name.
