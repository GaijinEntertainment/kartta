# Bind a C++ call on a field through the class the field is declared as

- **Status:** accepted
- **Date:** 2026-10-23
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/scope.rs` (`member_of_a_reached_owner`, `class_of_own_field`,
  `nearest_base_fields`), `kartta_lang::Receivers`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`
  (`a_cpp_call_on_a_field_of_the_caller_s_class_binds_the_member_of_the_class_it_is_declared_as`,
  `a_cpp_call_on_a_field_of_a_base_binds_the_member_of_the_class_it_is_declared_as`,
  `a_cpp_call_through_a_class_template_field_s_arrow_binds_the_member_of_the_class_it_reaches`,
  `a_cpp_call_on_a_field_declared_through_a_typedef_binds_the_member_of_the_aliased_class`)

A C++ call on a value inside a member most often calls a member of the class of a field the caller's class declares,
and the call names the field, not its class. The receiver tier of ADR 3.171 finds that field as C++ name lookup does, in
the caller's class and then its bases, and binds the member of the class the field is declared as; where the lookup
finds no one class, the call stays a call on a value.

## Decision

- In a member, the C++ walk spells a name the body does not declare after its operator, `.lock` or `->lock`, and
  records the class a field is declared as as its value type
  ([ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md)). The rule reads
  both where the language has a scope separator; outside a member a spelled name is no field.
- The field is one of the caller's class whose name the call spells. Where the class declares none of the name, its
  bases are read one distance at a time, and the nearest that declares the name hides the farther ones; fields of the
  name in two bases at one distance give no class.
- Of those fields, the ones nearest the caller's file are taken, as for a class: its own file, its includes, then the
  files those reach. They must all name one value type.
- `.` takes a value type written plain, a value or a reference. `->` takes one written after `*`: a pointer, or the
  class a class template's first argument names, which its `operator->` reaches. So `.` on a smart-pointer field
  reaches the template's own members.
- The member of a class of that name that the caller's file reaches, the nearest first, binds at 85, where a typedef
  or an alias the value type spells stands for the class it names, as
  [ADR 3.180](./3.180-bind-a-c-plus-plus-call-on-a-declared-class-through-the-class-nearest-the-caller-s-file.md)
  follows it for any receiver. Of namesake classes equally near, the one the value type's spelling names binds, and
  namesakes it cannot tell apart leave the call ambiguous.
- A class that declares no member of the name binds the member of its bases, as
  [ADR 3.180](./3.180-bind-a-c-plus-plus-call-on-a-declared-class-through-the-class-nearest-the-caller-s-file.md)
  states for any declared class.
- A name no field answers, fields that name different classes, or a class whose bases hold no member of the name
  either leave the call to the tiers that read no class, with the empty receiver, where ADR 3.43 guesses nothing near
  the caller. A namespace's value the walk spelled as a field binds as such a call.

## Why

- C++ finds a name a member's body does not declare in the member's class before any namespace, then in its bases, and
  rejects a name that two bases at one distance declare. The tier follows that lookup, so a namesake member elsewhere,
  `SpinLock::unlockRead` beside `Lock::unlockRead`, does not take the call.
- On the C++ game-engine tree (2026-10-23), the pairs the rule adds were 30 of 30 sampled right, and the pairs it
  removes 30 of 30 sampled wrong. Every other language binds the same pairs, since only C++ declares a scope separator.
- The lookup runs only for a call whose receiver spells a field, and walks the bases only where the caller's class
  declares none of the name. A field of a class type stores its value type, the one new allocation.

## Consequences

- A field's class keeps only the scopes its declaration writes, so a namesake class in another namespace that the file
  reaches first can bind: crashpad's `std::vector` field bound EASTL's `vector`. Accepted.
- A field the walk records no class for leaves its call on a value: an element of an array field (#478), and a field
  used in a member that an inline implementation header defines (#482).
- A member a template calls through its parameter is called by no tier, so where its name's other calls now bind, the
  dead-code answer judges it unused. Accepted.

## Rejected

- **A field rule for the fields the caller's file declares** — binds only 52 sites the kept rule misses on the C++
  game-engine tree, each a field whose declaration fails to parse.
- **One of two bases' fields at one distance** — C++ rejects the name as ambiguous, so either pick binds a call that
  does not compile.
- **`->` on a smart-pointer local through its first template argument** — a local, not a field: its receiver is the
  declared class ADR 3.75 records.
- **A member of the caller's own class** — ADR 3.43 records why.

## Revisit if

A sample of the pairs this tier binds finds the field's class wrong more than once in ten, as a class kept without the
namespaces its declaration omits is. High confidence: every sampled pair it added was right.
