# Name no type for a TypeScript or JavaScript call on a value the file declares, unless its declaration leads to one

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-jsts/src/walk.rs` (`Binding`, `Held`, `Declared`, `declare_*`),
  `crates/kartta-lang-jsts/src/walk/calls.rs` (`value_receiver`, `returned_path`, `this_class`),
  `crates/kartta-lang-jsts/src/walk/context.rs`, `crates/kartta-graph/src/resolve.rs` (`returned_owner`)
- **Pinned by:** `crates/kartta-lang-jsts/src/tests/extraction.rs`, `crates/kartta-languages/tests/engine.rs`
  (`a_typescript_call_on_a_parameter_typed_by_its_context_binds_the_method_of_that_type`,
  `a_typescript_call_on_a_typed_parameter_binds_a_member_of_that_type_and_no_namesake`,
  `a_typescript_call_on_a_local_a_static_call_initializes_binds_no_literal_of_its_file`,
  `a_typescript_call_on_a_local_a_free_function_initializes_binds_no_literal_beside_it`,
  `a_typescript_call_on_a_local_follows_the_return_types_of_the_calls_that_initialize_it`,
  `a_typescript_call_on_a_typed_or_constructed_local_binds_a_member_of_that_type`,
  `a_javascript_call_on_a_local_a_package_class_constructs_keeps_the_binding_of_a_value`)

A TypeScript or JavaScript call `x.f()` spells its receiver by a name, and the name of a value says nothing of the type
the value holds. The `jsts` walk ([ADR 3.4](/design-docs/adr/3.4-jsts-extraction.md)) records the
empty receiver for a value the file declares and keeps the name of a type, at the cost of a miss wherever it cannot
tell the two apart in one read. A value whose declaration leads to a type takes it: a parameter from its annotation or
its function's context, a local from its annotation, its `new`, or the return annotations of the calls that initialize
it, which the graph follows past the file.

## Decision

- **Values the file declares.** A call `x.f()` records `x` as its receiver unless the file declares `x` as a value in a
  scope that is open at the call: a parameter, a `let`, `const` or `var`, a destructured name, a catch binding, a loop
  variable, a function declared inside a function body, or the name of a function expression inside its own body. Such a
  call records the empty receiver, which [ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md) resolves as a
  value of no known type, unless a rule below gives the value a type. A capitalised JSX
  tag and a `new` expression written through such a name, `<x.Item>` or `new x.Pool()`, do the same; one written as a
  bare name, `<Item>` or `new Pool()`, records no receiver.
- **Parameters an annotation types.** A parameter written as one name records the one type its annotation spells, one
  name, qualified or not, its type arguments aside, unless that name is a type parameter of a declaration around it;
  `options` in `options: Callbacks<Data>` records `Callbacks`. A predefined type, a union, an array, an inline object
  type and a destructured parameter spell no one type, so such a parameter stays a value.
- **Locals an annotation types.** A variable written as one name records the one type its annotation spells, as a
  parameter does.
- **Locals a call or a `new` initializes.** A variable written as one name with no annotation, whose value is a call, an
  `await` of a call, or a `new` of one name, records a path of calls, `Receivers::ReturnPaths`: `opened()`,
  `Kartta::open()`, `Kartta::open()::child()`, `connect()?` and `Plane()`. A path starts from what the receiver the call
  is written on records, `this` and a value included, a call written on a call's result goes on from that call's path,
  and a call on a value of no known type records the empty receiver. The graph binds a bare start as the bare call
  binds, takes a type that start reaches as the owner, and reads each other step's return type from its value type: a
  function, a method, a signature, and a variable or a field a function is the value of record the one type their return
  annotation spells, or `?` and the one type a `Promise` holds, as a parameter's annotation spells one. A path that
  reaches no type records the empty receiver.
- **Parameters a context types.** A parameter written as one name with no annotation records the one type its context
  gives it, as the compiler types it: the function is a declaration's value, or a property or a method of an object
  literal whose type an annotation, `as` or `satisfies` writes beside it, and that type leads to a function type through
  an object type, an interface, an index signature, a mapped type, or a type alias or an interface the file declares at
  its top level, eight names deep at most. The parameter at the same position there names the type, unless it names a
  type parameter; `kartta` in `{ [M in keyof Methods]: Replay<M> }`'s `build: (kartta) => kartta.build()` records
  `Kartta`.
- **Names that stay.** An import binding, a class, a namespace, a class declared in a nearer scope, a `const` bound to a
  class expression and a function at module or namespace level keep their name.
- **`this`.** A call on `this` records the class around the method. In a class body outside every method it records the
  class itself, which is an instance in a field's initializer and the class in a static one. In a class expression's
  body it records the name that owns the class's members: its own name, or the name that binds it when it has none. An
  arrow keeps the `this` of the scope it is written in; a function expression or a function outside a class gives a
  `this` of no known type, which records the empty receiver.
- **One read.** The walk reads the file once. It holds each declared name while the function, block, catch clause, loop
  or `switch` that declares it is open, and restores the name it shadowed when it closes. A name declared below its
  first use, a module-level `const` under the function that calls it, therefore keeps its name, and a `var` is held to
  its block, so a call after the block keeps the name too.

## Why

- An owner is a class, an interface or a namespace, so a value's name names no type, and the empty receiver keeps the
  graph from binding it as one.
- A function at module or namespace level keeps its name because TypeScript merges it with a namespace of that name,
  and a class bound to a `const` is a type whose static members a call on the name reaches.
- `this` in a class body is the class's own instance or the class, so `run: () => this.apply()` in a field binds the
  class's method.
- Holding names to the scope that declares them makes every error of the one read a miss, never a wrong empty
  receiver.
- A parameter typed by its context holds the type the compiler gives it, and its empty receiver bound the object
  literal's own property of the call's name: 18 of the Node binding's 23 golden replays bound themselves
  (`bindings/node`, 2026-10-23, #319).
- A parameter's annotation is what the compiler types it by, and an empty receiver there bound whatever member of the
  name lay nearest: `options?.onSuccess?.()` bound the object literal's `onSuccess` around it. Naming the type, with
  [ADR 3.39](/design-docs/adr/3.39-member-call-free-functions.md)'s **Calls through a type**, removed 56 pairs on the Go
  monorepo snapshot, this repository and SillyTavern, 51 of them false, and added 2, both right (2026-10-31, #475).
- A local's declaration is what the compiler types it by too, and only the graph holds a call's definition past the
  file: `const kartta = opened(large); kartta.build()` bound a test's replay table beside it. Over the Go monorepo
  snapshot, this repository, SillyTavern and the game-engine tree's TypeScript and JavaScript the rule removes 36 pairs,
  all false, adds 451, 30 of 30 sampled right, and raises 288 to `RECEIVER`, 30 of 30 sampled right (2026-10-31, #510).
- A `new` is a path, not a name, because an import of code the graph does not hold ends the cascade: a package's class
  imported by a bare specifier keeps what a value binds, as `new Plane()` of a vendored three.js does
  (2026-10-31, #510).

## Consequences

- A name declared below its first use, and a `var` used after its block, keep their name as a receiver, so the call can
  bind an owner of that name. Accepted.
- A context the file does not spell gives no type: a callback an imported function's parameter types, as
  `useMutation({ onSuccess(data) {} })`, or an alias another file declares. Accepted.
- An alias of what a function returns holds no member the graph sees, so a call through a parameter of that type binds
  nothing where its empty receiver bound the function's own: 5 pairs on the Go monorepo snapshot, `tabs.saveTab()` with
  `tabs: ReturnType<typeof useFilterTabs>` by an alias. Accepted.
- A parameter spelled through a utility type keeps the utility's name, which names no type of the graph, so
  `options.onSuccess()` with `options: Pick<Options, 'onSuccess'>` still binds the literal around it, as does a rest
  element of a destructured parameter. Accepted.
- A definition with no return annotation gives no type, nor does a call through an import namespace, so a local a call
  of either initializes stays a value, as do a destructured local, `const {kartta} = await stamped()`, and a variable
  assigned after its declaration. Five pairs in this repository still bind a replay table that way. Accepted.
- A path starts from the call on the local, not from its initializer, so a namesake of the initializing function that a
  nearer scope declares takes the bare start. Accepted.

## Rejected

- **A value's name as an owner** — bound 220 calls on the TypeScript and JavaScript of the game-engine tree, mostly in
  minified bundles where a one-letter variable shares a one-letter class name (2026-10-16, #47).
- **`this` of no known type in a class body** — loses 23 sites on SillyTavern, every one right, such as
  `this.favFilter.bind(this)` (2026-10-23, #187).
- **A call through a value that would bind the free function holding it, counted as ambiguous** — unbinds 94
  self-calls on the Go monorepo snapshot, about a quarter of them true recursions of JavaScript object-literal methods,
  `this.parent.expandParent()` and jQuery's `jQuery(this).addClass()` (2026-10-23, #319).
- **A `new` local as the class's name** — lost 7 of the 43 pairs it removed, every one true: a vendored three.js's
  `_plane.setFromNormalAndCoplanarPoint()`, whose class comes from the bare specifier `three` (2026-10-31, #510).

## Revisit if

The graph infers what a function returns where no annotation spells it, or the type of a destructured name: the
locals this rule leaves as values could then bind. Nothing plans it.
