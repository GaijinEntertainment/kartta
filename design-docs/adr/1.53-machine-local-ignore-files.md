# Find git's machine-local ignore files through git itself

- **Date:** 2026-08-24
- **Governs:** `crates/kartta-fs`, `kartta_fs::IgnoreSources` (the levels above `InTree`)
- **Implementation:** pending — no level above `IgnoreSources::InTree` is built, so no code runs either git call (#169)

The machine-local ignore levels of [ADR 1.3](/design-docs/adr/1.3-ignore-sources.md) need two paths that only
git's configuration and repository discovery settle. When those levels arrive, a build asks `git` for both and keeps
matching in process, so it depends on a `git` binary for those levels rather than on an in-process configuration stack.

## Decision

- **Two git calls.** A build that honours a level above `InTree` resolves the files through two subprocess calls, once
  a build: `git rev-parse --git-dir` for the repository-local `info/exclude`, and
  `git config --path --get core.excludesFile` for the global file. The first call is a known defect of the plan, open
  until #169 settles its replacement.
- **Matching in process.** Matching stays in process with `gix-ignore`
  ([ADR 1.50](/design-docs/adr/1.50-gitignore-matcher.md)), which reads `info/exclude` itself and takes
  `core.excludesFile` as an `Option<PathBuf>` the caller supplies.
- **Without git.** Where `git` is absent, the build degrades to the in-tree level.

## Why

- Supplying `core.excludesFile` faithfully needs git-config precedence with `include` and `includeIf`, the XDG
  fallback, and real `$GIT_DIR` discovery, where `$GIT_DIR` can be a file holding `gitdir: ...` for a worktree or a
  submodule. Two subprocess calls are exact by construction.
- `gix-config` with `gix-discover` resolves to 60 crates (2026-08-24, #4), and brings `walkdir` and `same-file` into a
  build without the `watch` feature, which holds neither.

## Consequences

- `--git-dir` names a linked worktree's own git directory, which holds no `info/exclude`, and an inherited `GIT_DIR`
  points the subprocess at another repository; the plan needs `git rev-parse --git-path info/exclude` and a cleared git
  environment before it is built (#169).

## Rejected

- **Resolve git configuration in process with `gix-config` and `gix-discover`** — 60 crates, `walkdir` among them,
  to compute two strings a subprocess prints exactly.
- **Hand-roll git-config parsing** — precedence, `includeIf` and worktree `gitdir:` files are the whole difficulty, and
  getting them subtly wrong gives a silently different index rather than a failure.

## Revisit if

`gix-ignore` grows its own `core.excludesFile` resolution without the configuration dependency tree behind it. High
confidence that it has not: it takes the path from its caller.
