# Name a Go anonymous struct by the names that lead to it

- **Status:** accepted
- **Date:** 2026-10-23
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-go/src/walk/anonymous.rs`, `crates/kartta-lang-go/src/walk/types.rs`,
  `crates/kartta-graph/src/typed.rs` (the first name of a path)
- **Pinned by:** `crates/kartta-lang-go/tests/extract.rs`
  (`a_field_of_an_anonymous_struct_a_field_declares_is_owned_by_the_struct_s_own_name`,
  `a_variable_a_body_declares_names_its_anonymous_struct_after_the_callable_too`,
  `a_literal_assigned_to_a_name_declares_its_anonymous_struct_s_fields`,
  `a_name_the_file_has_given_an_anonymous_struct_takes_a_count`,
  `an_anonymous_struct_whose_name_would_pass_a_type_path_s_bound_takes_none`,
  `an_anonymous_struct_without_a_field_takes_no_name`)

A field typed `struct{...}`, a variable declared with one and a test table's literal held fields no symbol stood for,
so `s.Limits.MaxConns`, `settings.Timeout` and `tt.name` had no type path to follow (ADR 3.60): they counted as
ambiguous, or bound an unrelated struct's field of the name. Such a struct becomes a struct symbol named by the names
that lead to it, so ADR 3.34's path tier binds its fields with no change to the graph, for 5,393 more structs and
26,241 more fields in the Go monorepo snapshot's graph.

## Decision

- A struct with a field that a field's type, a variable's declared type, or a literal that `:=` or `var` assigns to a
  name spells, behind pointers, `&`, parentheses and containers too, is a struct symbol.
- Its name is the names that lead to it joined by `·` in braces: `{Server·Limits}` for a field, `{settings}` for a
  package variable, `{TestRun·tests}` for a value a body declares, which adds its callable, and `{Server·Run·limits}`
  for a method's. The file's second struct of one name takes a count, `{row·Cell·2}`.
- Its fields are owned by that name and qualified by the names, `app.Server.Limits.MaxConns`; the host's value type is
  the name; a literal's keys write the fields.
- `struct{}` and a struct with no field take no name, nor does a literal assigned to no name, an argument or a returned
  value, nor a name past a type path's 160 bytes, braces included. Such a literal's keys record nothing.
- The graph reads a path's first name up to a `.`, `(` or `[` and finds it among the file's import bindings, then the
  package's declarations, then a dot import's, then the types of the file's bodies by name.

## Why

- The name holds a rune no Go identifier holds and no path step starts with, so the path lookup finds it and nothing
  else; its braces keep it apart from the variable it types, and a body's value adds its callable so two bodies' tables
  of one name stay apart.
- Uses of the names those fields take that counted as ambiguous fell from 13,025 to 2,197 on the Go monorepo snapshot,
  and every sampled site that moved binds the field the source reads (2026-10-23).
- The heap after a build holds 1.9 MB more (2026-10-23).

## Consequences

- `find_symbols` lists the named structs, and one can take the last place of a capped list from another match. Accepted.
- A literal assigned to no name, about 200 structs on the snapshot, or a parameter of an anonymous struct, records the
  empty path, and its member uses count as ambiguous or take the file's one field. Accepted.
- A type defined over another struct type records no fields, so a use through it finds no field there (ADR 3.29).
  Accepted.

## Rejected

- **The fields owned by `Server.Limits` with no struct symbol and no path, left to the file's one field** — binds a
  sixth of the sites and loses 413 that bound right, since a file then holds two fields of the name.
- **Structs only for fields and package-level variables, not a body's values** — binds a sixth of the sites, since a
  test table holds most.
- **Owning the fields by `Server.Limits` with no struct symbol** — needs the graph's type tier to take a field or a
  variable as the owner of its struct's fields, a tier every language shares.

## Revisit if

The graph's type tier takes a field or a variable as the owner of its anonymous struct's fields, which would spare
`find_symbols` the named structs. Not planned.
