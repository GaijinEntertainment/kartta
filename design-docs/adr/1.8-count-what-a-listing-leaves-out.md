# Count what a listing leaves out

- **Status:** accepted
- **Date:** 2026-10-13
- **Initiative:** `01-kartta-fs-port`

kartta answers LLM agents first, and an agent cannot see what it was not given. A listing therefore says how much it
left out, wherever counting is free.

A listing takes two pattern sets beside its bounds, both compiled in the query glob dialect (ADR 1.4) and matched
against index-relative paths. **`exclude` drops what it matches** — a file, or a directory together with its subtree.
**`collapse` lists a matched directory without descending into it.** Exclusion wins where both match. The directory
being listed is exempt from both, so naming a directory by path always shows what is inside it. Hiding dot entries is
the pattern `**/.*`, not a flag of its own.

A directory listed without its contents — because it sits at the depth bound, or because it was collapsed — carries the
number of indexed entries beneath it, zero included, so an unexpanded directory never reads as an empty one. The listing
also reports how many indexed entries its exclusion removed before the listing ended, and how many entries the index
holds under the listed directory, which bounds what a cap turned away.

Every one of these counts is free. Index order is depth-first, so a subtree is one contiguous run, and the binary search
that skips it — which a depth-limited listing already does — lands on its size. The total is the listed directory's own
run, whose end the listing finds once to know where to stop, so it costs one search per call whether or not a cap ends
the listing early. The counts are therefore the index's own: a collapsed directory's count includes entries an exclusion
would have removed, because subtracting them means visiting the subtree the skip exists to avoid. Dropped entries and a
collapsed directory's contents never count toward the cap, and `truncated` keeps the meaning ADR 1.5 gives it.

## Considered Options

- **Bare directory names for collapse** — the unit both current consumers pass, and a cheaper comparison than a glob. It
  gives the two pattern sets two matching units; a bare name is the glob `**/name`.
- **A file count instead of an entry count** — closer to what a reader usually means by "how big", and it costs either a
  scan of the skipped subtree or four bytes per entry for a running count. Revisit when a consumer needs files rather
  than entries.
- **A flag that a directory was not descended** — the same cost as the count and strictly less information.
- **Leave the counts out and let the caller list the directory again** — a second call to learn what the first one could
  have said.

Revisit if counting stops being free — an index layout without contiguous subtrees, for one — in which case each count
is measured before it is kept.
