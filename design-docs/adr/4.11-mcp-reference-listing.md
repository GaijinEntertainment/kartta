# Group a symbol's references by file, the busiest first

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-23
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`references`, `reference_match`, `Listing`, `site_records`), the
  `find_references` tool
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_references_lists_a_hot_field_by_file_most_sites_first_and_counts_what_it_leaves_out`,
  `find_references_lists_the_reads_and_writes_of_a_field_and_keeps_the_writers_on_request`,
  `find_references_labels_a_member_read_through_a_type_a_read_and_not_a_use_as_a_type`)

A hot symbol has thousands of sites, and an answer that lists them in path order spends its size on the alphabetically
first files. `find_references` groups its sites by file, lists the files with the most sites first, lists 100 sites one
by one and names 50 more files by their count, and counts every site and file it leaves out.

## Decision

- **Sites.** Every site of the symbol is counted. A caller is one site, at one of its calls; every other use is one site
  per line and kind. A site is marked by what its record says it does (ADR 3.34): `call`, `type` where code names the
  symbol as a type, `read` where code reads it, a member taken through a type, `EventType.Created`, reading the type,
  `write` or `update` (`+=`, `++`); `access` of `read` or `write` keeps the uses that read or set the symbol, an update
  being both, a use as a type a read, and a call neither. The match counts every site by kind, `calls=`, `types=`,
  `reads=`, `writes=` and `updates=`, whatever `access` keeps.
- **Files.** Sites come in `<file path= sites=N>` records, the files with the most sites first and ties in path order.
  Inside a file, one `<ref>` holds the sites one enclosing symbol has of one kind and confidence band, in line order,
  carrying the enclosing symbol's name, `qn` and `line=`, its `role=`, `site=`, `at=` the lines, and the confidence
  mark.
- **Limits.** A match lists 100 sites one by one; a file it lists part of carries `shown=`. Then it names 50 more files
  with their `sites=` alone. `count=` and `shown=` count the sites, `files=` and `files_shown=` the files, each shown
  only where the match lists fewer.
- The C ABI's references answer takes the caller's `limit` and keeps its shape (ADR 4.2).

## Why

- An agent that asks where a symbol is used wants where it is used most: the busiest files carry the change's weight,
  and a path-order list showed only the first of them.
- On the C++ game-engine tree `Point3::x`, 4,276 sites in 980 files, answered 63,590 bytes, about 16k tokens, as 500
  sites in path order, each `<ref>` carrying its file twice; grouped, it answers 6,745 bytes (2026-10-19).
- Counting every site costs nothing more: the query resolves every site to answer any of them.

## Consequences

- A file past the 50 named is counted in `files=` alone; an agent narrows with `path_prefix`, `access` or
  `min_confidence`. Accepted.

## Rejected

- **A cap of 100 in the path-order shape** — 10 to 37 KB on the same names, and still the alphabetically first files
  only.
- **Grouping alone, at 500 sites** — about 30% smaller, where grouping with 100 sites listed answers about a tenth.

## Revisit if

An agent's next call depends on the sites of a file past the 50 named often enough that the answer should name more.
Not measured.
