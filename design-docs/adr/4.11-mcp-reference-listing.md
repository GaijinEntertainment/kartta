# Group a symbol's references by file, the busiest first

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`references`, `reference_match`, `Listing`, `site_records`), the
  `find_references` tool
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_references_lists_a_hot_field_by_file_most_sites_first_and_counts_what_it_leaves_out`,
  `find_references_lists_the_reads_and_writes_of_a_field_and_keeps_the_writers_on_request`,
  `find_references_labels_a_member_read_through_a_type_a_read_and_not_a_use_as_a_type`,
  `find_references_keeps_the_uses_as_a_type_alone_or_among_the_reads`,
  `find_references_sites_under_lists_the_sites_past_the_named_files_and_counts_what_it_left_out`,
  `find_references_sites_under_filters_the_file_scope_users_and_says_when_it_keeps_nothing`)

A hot symbol has thousands of sites, and an answer that lists them in path order spends its size on the alphabetically
first files. `find_references` groups its sites by file, lists the files with the most sites first, lists 100 sites one
by one and names 50 more files by their count, and counts every site and file it leaves out.

## Decision

- **Sites.** Every site of the symbol is counted. A caller is one site, at one of its calls; every other use is one site
  per line and kind. A site is marked by what its record says it does
  ([ADR 3.34](/design-docs/adr/3.34-field-and-value-uses.md)): `call`, `type` where code names the symbol as a type,
  `read` where code reads it, a member taken through a type, `EventType.Created`, reading the type, `write` or `update`
  (`+=`, `++`); `access` of `read` or `write` keeps the uses that read or set the symbol, an update being both, a use as
  a type a read, and a call neither, and `type` keeps the uses as a type alone, as the engine's `SiteQuery` does
  ([ADR 3.175](/design-docs/adr/3.175-data-references-by-access.md)). The match counts every site by kind, `calls=`,
  `types=`, `reads=`, `writes=` and `updates=`, whatever `access` keeps.
- **Files.** Sites come in `<file path= sites=N>` records, the files with the most sites first and ties in path order.
  Inside a file, one `<ref>` holds the sites one enclosing symbol has of one kind and confidence band, in line order,
  carrying the enclosing symbol's name, `qn` and `line=`, its `role=`, `site=`, `at=` the lines, and the confidence
  mark.
- **Limits.** A match lists 100 sites one by one; a file it lists part of carries `shown=`. Then it names 50 more files
  with their `sites=` alone. `count=` and `shown=` count the sites, `files=` and `files_shown=` the files, each shown
  only where the match lists fewer.
- **Sites under a prefix.** `sites_under`, a path prefix the index holds, lists only the sites and the file-scope users
  in files under it, from the sites the query resolved; `path_prefix` still picks the symbol. The counts stay whole,
  and `excluded=`, `files_excluded=` and `file_scope_excluded=` count the sites, files and file-scope users it left
  out. A prefix that keeps none of them answers a note saying so.
- **The C ABI.** The C ABI's references answer takes the caller's `limit` and keeps its shape
  ([ADR 4.2](/design-docs/adr/4.2-c-abi-wire.md)).

## Why

- An agent that asks where a symbol is used wants where it is used most: the busiest files carry the change's weight,
  and a path-order list showed only the first of them.
- On the C++ game-engine tree `Point3::x`, 4,276 sites in 980 files, answered 63,590 bytes, about 16k tokens, as 500
  sites in path order, each `<ref>` carrying its file twice; grouped, it answers 6,745 bytes (2026-10-19).
- Counting every site costs nothing more: the query resolves every site to answer any of them.
- `path_prefix` picks the symbol, so a directory of sites past the files named answered that no definition is there:
  on the game-engine tree a hot function's 3,120 sites in 1,467 files named 55 (2026-11-06).
- Before a site carried its kind, `find_references` could not select a field, so who reads or sets `Config.Timeout`
  answered nothing (#82).

## Consequences

- A file past the 50 named is counted in `files=` alone; an agent narrows with `sites_under`, `access` or
  `min_confidence`. Accepted.
- A `sites_under` answer copies the sites it keeps, one record each, where an answer without it borrows them. Accepted.

## Rejected

- **A cap of 100 in the path-order shape** — 10 to 37 KB on the same names, and still the alphabetically first files
  only.
- **Grouping alone, at 500 sites** — about 30% smaller, where grouping with 100 sites listed answers about a tenth.
- **`read` without the uses as a type, so that `read` and `type` do not overlap** — the engine and the wire keep them
  among the readers ([ADR 3.174](/design-docs/adr/3.174-type-use-access.md)), and the MCP answer would then say less
  under one word than the wire does.
- **A `limit` to reach the sites past the cap** — the size this ADR's cap was chosen against.
- **`sites_under` narrowing the counts too** — the counts would then say less about the symbol than the call without it.

## Revisit if

An agent's next call depends on the sites of a file past the 50 named often enough that the answer should name more.
Not measured.

## History

- 2026-11-06 — Sites under a prefix: the remedy named `path_prefix`, which picks the symbol, so the sites past the
  files named were out of reach (#1038)
- 2026-11-03 — Sites: `access` took `read` and `write` alone, so no call kept the uses as a type apart, while the
  engine and the wire filter them (#1120)
- 2026-10-23 — Sites: a member read through a type, such as `EventType.Created`, was marked a use as a type, not a
  read (#278)
- 2026-10-19 — Files and Limits: a hot field's answer at the 500-site cap took about 63 KB, roughly 16k tokens, and
  showed only the alphabetically first files (#113)
