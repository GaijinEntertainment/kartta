# List a call under the last part of its callee's own name

- **Status:** accepted
- **Date:** 2026-10-21
- **Updated:** 2026-10-21
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-graph/src/graph.rs` (`qualified_tail`, `listing_key`, `intern_listing_key`)
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`
  (`the_callers_of_an_operator_whose_name_holds_a_separator_include_a_call_written_qualified`)

`callers` finds a call through the key its callable's name gives (ADR 3.7). A callee written with a name that ends in a
separator, C++'s `das::operator/(a, b)`, has an empty last segment, a key no query asks for, so it is listed under the
part its own name ends with.

## Decision

- A call site is listed under the last segment of its callee as written, cut at `.`, `:`, `\`, `#` and `/`.
- A callee whose written name ends in one or more separators is listed under the part after the separator that precedes
  its trailing ones, those kept: `das::operator/` under `operator/`, daslang's `decs.operator .` under `operator .`.
- A name that ends in no separator keeps its key, and so does one with no separator before those it ends in:
  `operator/` itself, and Bash's `:`.
- The names a file calls at its top level, and the parents and interfaces its types name, are keyed by the same rule,
  so the file-scope callers and the implementors of such a name are found alike.

## Why

A call and its definition must give one key, or `find_callers` misses a call that `find_callees` binds through the
qualified lookup: `find_callers` of `das::operator/` answered no callers while `find_callees` bound the call.

## Consequences

None measured: neither the C++ game-engine tree nor the Go monorepo snapshot writes such a call, so no key moved and
every call bound as before (2026-10-21).

## Rejected

- **Find the qualified callees when `callers` asks** — no build change, but a name that ends in a separator scans every
  call key and file-scope key: over a thousand times slower per `callers` on the C++ tree's 221,820 call keys
  (2026-10-21), and the scan grows with the tree.
- **List such a call under both keys** — keeps a key no query reads and a check per qualified callee in a build.

## Revisit if

A language's callable names hold a separator inside them, not only at their end, so that the part after the last
separator is no longer the name a definition gives. Medium confidence; no shipped language writes one.
