# Read a file's own facts on demand, not during the walk

- **Status:** accepted
- **Date:** 2026-08-24
- **Updated:** 2026-10-18
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fs/src/inspection.rs`, `Index::size`, `Index::is_binary`, `Listed::size`,
  `Listed::is_binary`
- **Pinned by:** `crates/kartta-fs/tests/index.rs` (`a_size_is_read_once_and_answered_from_the_index_after_that`,
  `a_size_asked_for_the_first_time_reads_the_file_as_it_is_now`, `a_file_replaced_by_a_directory_has_no_size`)

A walk that stats or probes every file pays for answers most callers never read. The walk records a tree's structure,
and a file's size and binary verdict are read the first time a caller asks and kept, so a build that reads no content
costs only the structure; two answers from one index may then describe two different moments.

## Decision

**What the walk records and what waits.** The walk records structure: which entries exist, the kind of each, and where
a symlink points. A regular file's size and its binary verdict are its own facts: `Index::size` and `Index::is_binary`
read them on the first ask for that entry and keep the answer, so a second ask reads nothing. Both are `Index` methods
keyed by path, since an `Entry` holds no root to read through. A build that reads no content reads no file's size: it
stats only the ignore files it reads and takes each entry's kind from the directory listing, so no build error names a
size. A reading build (ADR 1.12) keeps the size and verdict of each file it reads.

**What an answer is.** A size or a verdict belongs to the moment it was first read, not to the walk, and it is not read
again while the index lives; every surface that reads late says so. A file that will not stat or will not open answers
`None` at the ask, and that `None` is kept like any answer. Only an entry the walk found a regular file answers, and
only from a regular file on disk: a symlink or a directory that replaced it since the walk answers `None` for its size,
and for a verdict its name does not settle; a link is never followed. A file some open already read — a reading build
(ADR 1.12), a content search, or the probe of `is_binary` — answers its size from that open.
[ADR 1.60](./1.60-settle-a-file-as-binary-by-its-extension-else-by-a-nul-in-its-first-64-kib.md) states how a verdict
is settled.

**How the answers are kept.** Two tables of atomics, one slot per entry and aligned with the entry list: an `AtomicU64`
for the size and an `AtomicU8` for the verdict, nine bytes per entry. Unread is zero in both, a size is stored plus one,
and unreadable has its own value, so a new table is a zeroed allocation whose pages cost resident memory only once a
query fills a slot in them. Queries take `&self` and fill slots with relaxed atomics and no lock. The first read to
publish wins: each publishes through `compare_exchange`, and a thread that loses answers the value already in the slot.

**No public sweep.** The crate pairs entries with their facts by position inside itself — a listing's `Listed::size`
and `Listed::is_binary`, and a content search — and offers no method that walks every entry with its facts.

## Why

- Stat'ing every file during the walk took about half a build, 3.7 s of 6.5 s on a home directory of 1,418,788 entries,
  and classifying every file during the walk took one to seven minutes on the same tree (2026-08-24).
- A caller's own reads are small and clustered: one directory's entries stat in about 0.3 ms cold on the same tree, and
  a listing drawn twice reads nothing the second time.
- Nothing is published alongside a fact, so no reader depends on another write becoming visible with it, and relaxed
  atomics suffice. A file rewritten between two racing reads has two truthful sizes; the first publish keeps one answer
  per entry, as the contract promises the first answer and then holds it.

## Consequences

- Two facts from one index may describe two moments, and a kept fact is never read again; only a refresh that walks
  the changed file again (ADR 1.15, ADR 1.16) or a rebuild answers anew. Accepted.
- The tables cost nine bytes per entry, about 12 MB on the home directory above, allocated in about a millisecond.
- A caller that wants every file's facts asks per path and pays a lookup each: about 300 ms on an index of 1.1M files
  whose facts were all read. Accepted.

## Rejected

- **Read both during the walk** — one coherent snapshot, at half a build spent on sizes nobody reads, and a full-tree
  classification could never join it.
- **A `BuildOptions` flag choosing eager or lazy reads** — every caller must know which kind of index it holds, and one
  method would mean two things.
- **A `RwLock<HashMap>` keyed by entry** — no table, at a lock and a hash on every read the table answers with one load.
- **A `OnceLock` per slot** — 24 bytes a slot against nine, for an exactly-once guarantee a repeated, idempotent read
  does not need.
- **A `Result` from the late reads** — says why an answer is missing, and a failure no longer fits a byte, so a caller
  looping over an unreadable directory pays the syscall on every pass.
- **Refresh a kept answer when the file changes** — needs a watcher or a stat before every read, the cost this design
  exists to avoid.
- **A public sweep pairing every entry with its facts** — nothing outside the crate swept with it.

## Revisit if

A caller needs file facts coherent with the walk's structure for files a build did not read; ADR 1.12 already gives
that for the files it reads. High confidence: no consumer has asked.
