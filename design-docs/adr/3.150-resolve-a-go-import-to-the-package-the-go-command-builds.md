# Resolve a Go import to the package the go command builds

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-17
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-go/src/resolve.rs`, `crates/kartta-graph/src/resolve.rs` (`read_bindings`,
  `in_package_of`, `is_external_test_of`, `in_tested_package`)
- **Pinned by:** `crates/kartta-lang-go/tests/resolve.rs`, `crates/kartta-graph/tests/graph/packages.rs`

A Go import names a module path, and which directory holds that package depends on the `go.mod` files, the vendor
directories and the replace directives of the build. The resolver reads them as the go command reads them for the
module that builds the importing file, and the graph binds a bare call only in the package the file's clause declares,
at the cost of the builds that `go.mod` files alone do not describe.

## Decision

- The resolver reads the `module` path and the `replace` directives onto local directories of every `go.mod` outside a
  `vendor` directory.
- A file is built by its own module, the one whose directory is the longest that holds the file. A module with no
  `vendor/modules.txt` of its own that another module replaces onto its directory is built by that module instead: one
  that vendors first, then the one of the longest directory.
- An import names `vendor/<import path>` under the building module's directory where the repository holds files there.
  Otherwise the module whose path is the longest prefix of the import decides alone, among every module and the local
  replaces of the building module. Where several modules declare that path, as a checkout's nested copies of itself
  do, the importing file's own module wins. An import that no module matches, or whose directory holds no files, is
  external.
- A replace onto `./` or `../` is a module at that directory; one onto another module path, or onto a directory above
  the repository root, names no directory. A replace that names a version applies to every version of the module.
- A resolved import includes every file of the directory whose name ends in `.go`, in lower case, and not in
  `_test.go`, except the importing file itself.
- An import binds its alias as written. Without one it binds the name the imported directory's package clause
  declares, and for code the graph does not hold the element of the path before a major version suffix, `rand` for
  `math/rand/v2` and `yaml` for `gopkg.in/yaml.v3`, else its last element. `_` binds nothing; `.` is a dot import.
- A test file's import of its own directory, from an external test package, sees the tested package's test files too,
  `export_test.go` among them.
- A bare call binds in its directory only among the files whose package clause is its own file's, and among test files
  only from a test file. No tier past the package reaches another package's function
  ([ADR 3.7](./3.7-resolve-calls-when-a-query-asks.md), tier 6).

## Why

- A vendored build prefers the vendored copy, and the go command applies only the main module's vendor directory and
  replace directives, building a replaced dependency with the module that replaces it.
- A package clause need not match the import path, and a major version suffix is no part of the package's name.
- The go command compiles a package's test files into the package that its external test package imports, and a
  directory can hold both packages.

## Consequences

- Two nested modules that declare modules of their own and that no replace reaches leave their imports of each other
  external: 427 include pairs on the Go monorepo of 39,771 Go files (2026-10-17). Accepted.
- A `go.work` file is not read, and a versioned replace covers every version. Accepted.

## Rejected

- **Read the `go.mod` files under `vendor`** — they belong to third-party packages, and a checkout can hold thousands.
- **Apply every module's replaces to every file** — the go command applies only the main module's.
- **The longest prefix alone, where several modules declare the path** — a checkout's nested copy of itself would take
  the imports of the module that builds the file.
- **Bind an unaliased import by its path's last element** — misses every package whose clause differs from its path.

## Revisit if

The indexed Go trees build through files the resolver does not read, a `go.work` or a replace by version. Medium
confidence; the trees measured build from `go.mod` and vendor directories.
