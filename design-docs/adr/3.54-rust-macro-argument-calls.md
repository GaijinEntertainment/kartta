# Read the calls a Rust macro's arguments write from its tokens

- **Updated:** 2026-10-23

tree-sitter-rust parses a macro invocation's arguments as a token tree, so a call inside `assert!`, `format!`,
`vec![..]` or a user macro is no call expression. The walk reads the calls out of the tokens, by the shapes a call
expression takes, for the macros of every crate; what the tokens cannot tell, where a closure or an arm ends, it bounds
by the token tree.

## Decision

- **A word before a `(` tree is a call**, a call of the function around the macro, with the receiver and the path a call
  expression of that shape records ([ADR 3.56](/design-docs/adr/3.56-rust-call-receivers.md)):
  a name, `helper(x)`; a path, `crate::m::f(x)`, `Vec::<u8>::new()` or `::root::f()`, its turbofish skipped; and a
  member, `C.opens(x)`, `self.name()` or `x.collect::<Vec<_>>()`, a chained operand recording the empty receiver. A
  word before `!` is a nested macro invocation, whose arguments are read the same way. A bare call binds an item its
  block declares as a local call, and a path call keeps its path as one outside a macro does. A call takes the line of
  its name.
- **A bare call of a name a pattern binds is no call**, as
  [ADR 3.53](/design-docs/adr/3.53-rust-local-calls.md) decides: a
  parameter or a local of the function around the macro; a name that a closure's parameters, a `let` after its
  initializer or a match arm in the arguments bind, to the end of the token tree it is written in; and a name an
  `if let`, a `while let` or a `for` binds, in the block it opens. A constructor, a path or a field's label in such a
  pattern, `Some(x)` or `Point { x: at }`, binds nothing.
- **A pattern holds no call.** `matches!`'s pattern, from the first `,` to its guard; a `let` or `for` pattern; and a
  `(` tree before `=`, a guard's `if` or an unguarded arm's `=>` name constructors, `Some(Kind::A(_))`. A
  `macro_rules! matches` that the file defines before the invocation, in the block or module around it, reads as any
  macro.
- **Code the macro generates holds no call of the site**: arguments that interpolate, `#name` or `#(..)*` as `quote!`
  writes them, drop every call of their macro and of none around it; an attribute, `#[derive(Debug)]`; and the
  parameters and body of a `fn` the arguments declare.
- **A keyword is no callee.** A token tree keeps `in`, `move`, `ref`, `dyn`, `else` and a few more as identifiers, so
  `for x in (items)` calls nothing; `r#in(x)` is a call.
- The bodies of `macro_rules!` definitions, templates each expansion fills, are not read.

## Why

- No call in a macro's arguments was recorded, and nothing in an answer said so: `find_callers` of `Banner::opens`
  listed its 7 callers outside tests and none of the 7 tests in `banner.rs` that call it 24 times through `assert!`
  (this repository, 2026-10-23).
- Reading the tokens finds the same calls as re-parsing each tree but for a few shapes, at less cost: one thread
  extracted this repository's Rust in 0.304 s against 0.381 s re-parsing and 0.282 s reading no arguments
  (2026-10-23).
- A pattern names constructors, which a pattern outside a macro records no call for.

## Consequences

- A closure's, a `let`'s or an arm's names hide a bare call to the end of the token tree, past where the binding ends.
  Accepted.
- The calls in `macro_rules!` bodies and in `quote!` templates are not read: 19 call shapes here and 82 in tree-sitter
  in macro bodies. Accepted.
- A name the arguments read where no call takes it, `assert_eq!(x, LIMIT)`, is no use (#436).
- A `matches` macro that a `use` imports reads as the standard one. Accepted: no file of the measured trees does so.

## Rejected

- **Re-parsing each token tree through an included range** — a parse per tree costs about 16 µs whatever its length,
  and it still misses the initialisers of `thread_local!` statics and the receivers in `json!` objects.
- **The standard expression macros alone** — misses right calls in other macros, `tree_sitter_fingerprint!(grammar(),
  ..)`, the log crate's `info!` and tree-sitter's `add_line!`, and reading every macro costs nothing more per call.
- **No pattern rule** — records each constructor in a pattern as a call.

## Revisit if

tree-sitter-rust parses a macro's arguments as expressions where they are ones. Unlikely, since a macro's arguments
need not be expressions at all.
