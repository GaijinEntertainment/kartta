# Name a Go call's target only where the syntax spells it

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-go/src/walk/calls.rs`, `crates/kartta-lang-go/src/walk.rs` (`push_value_callers`,
  `type_spec`)
- **Pinned by:** `crates/kartta-lang-go/tests/extract.rs`
  (`a_member_call_on_a_chain_records_the_type_path_of_its_operand`,
  `a_call_of_a_local_value_with_no_symbol_records_no_call`, `an_instantiation_call_names_the_generic_it_instantiates`,
  `an_index_by_or_of_a_package_value_calls_an_element`,
  `the_initializer_of_a_package_level_variable_calls_as_that_variable`,
  `a_type_named_in_a_declaration_or_a_composite_literal_is_a_use_and_in_a_conversion_a_call`,
  `an_alias_is_a_type_alias_and_a_defined_non_struct_type_a_defined_type`)

The Go extraction reads one file, and a call's target is a name the graph resolves later. A name the syntax does not
spell matches some definition by accident, so the extraction records a call only where the syntax names its target,
and leaves out the calls it cannot name.

## Decision

- **Member calls.** A member call's receiver is the type path of its operand's value, as
  [ADR 3.29](/design-docs/adr/3.29-go-receiver-types.md) states. A chained call records every call
  in the chain: `s.Findings().Verdict()` records `Findings` on `S` and `Verdict` on `S.Findings()`.
- **Computed callees and values.** A computed callee, `(*p)()` or `fns[i]()`, records no call. A bare call of a local
  value that has no symbol, a parameter, a result, a receiver, or a `:=`, range, receive or type-switch variable,
  records none either. A bare call of a `var`, `const` or `type` a body declares is a local call of that symbol.
- **Conversions and parentheses.** A conversion written as a call, `B(x)`, is a call of the type, since the syntax
  cannot tell it from a call. A parenthesized callee, `(T)(x)` or `(f)(x)`, records a use of what the parentheses hold
  and no call.
- **Index calls.** An index call names the generic it instantiates, `f[T](x)` calls `f` and `v.F[T](x)` calls `F` on
  `v`, when its indices are type arguments. Two indices or more are type arguments; one index is a type argument unless
  the file declares it as a value: a local binding, or a package-level `var` or `const` of the file. An index by such a
  value, or any index of a bare operand the file declares as one, calls an element and records no call.
- **Package-level initializers.** A function literal bound to a package-level variable, `var Handler = func() {}`, gives
  the variable and no function. The calls of a package-level `var` or `const` initializer, the literal's body among
  them, are calls of the name each value initializes. Where the values do not line up with the names, as one call's
  results do, and for a blank name's value, they are calls of the spec's first name.
- **Type kinds.** A type defined over a struct is a struct and one over an interface an interface; a type defined over
  anything else, `type Duration int64` or `type H func()`, is a `SymbolKind::DefinedType`. Only `type X = Y` is a
  `TypeAlias`.
- **Imports and packages.** [ADR 3.150](/design-docs/adr/3.150-go-import-resolution.md) states the package an import
  names and the package a bare call binds in.

## Why

- A wrong edge is worse than a missing one: an agent that follows it reads code the call never reaches.
- The syntax cannot tell a type from a value. The file's own declarations are the only values one file's bytes show.
- Crediting an initializer's calls to the variable keeps them; a body that was no caller dropped them as file scope.
- A defined type has a method set of its own, where an alias shares its target's, so the two kinds bind differently.

## Consequences

- A package-level variable that another file of the package declares, indexed and called, reads as an instantiation
  of a generic of that name. Accepted: no call on the Go monorepo calls a package variable through an index
  (2026-10-17).
- `callers` of a function called inside a closure bound to a package-level variable names the variable. Accepted.

## Rejected

- **A function symbol and a caller for a closure bound to a variable** — keeps the calls in its body, which crediting
  the variable keeps too, for a form that is rare in Go next to the declared `func`.
- **The package variables of a sibling file in `vars[K]()`** — needs the package's other files, which one file's bytes
  do not hold.
- **A conversion of a generic type, `T[int](x)`, as a use** — a conversion written as a call is a call of the type, as
  `B(x)` is, because the syntax cannot tell it from a call.

## Revisit if

A Go file's walk can see its package's other files, so an index operand that a sibling declares is known to be a
value. Not planned.
