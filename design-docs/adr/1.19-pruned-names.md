# Prune editor and OS clutter by name during the walk

- **Date:** 2026-10-17
- **Governs:** `crates/kartta-fs/src/pruned.rs`, `BuildOptions::pruned_names`, `crates/kartta-fs/src/policy.rs`
  (`pruned`, `Indexing::visit`), `Index::refresh_paths`
- **Pinned by:** `crates/kartta-fs/tests/index.rs` (`a_pruned_name_prunes_an_entry_of_any_kind`,
  `no_ignore_rule_brings_a_pruned_name_back`, `the_root_is_never_pruned_whatever_its_name`),
  `crates/kartta-fs/tests/refresh.rs`
  (`a_path_through_a_pruned_name_changes_nothing`,
  `a_changed_pruned_gitignore_walks_again_the_directory_its_rules_govern`)

Editors keep their state inside the tree they edit and macOS leaves a `.DS_Store` in every folder Finder opens, and few
repositories ignore them, since each developer's global excludes do. A build prunes such names during the walk, before
and outside the ignore rules, so no answer carries them; a name is compared exactly, and nothing counts what it pruned.

## Decision

- **The set.** `BuildOptions::pruned_names` holds the names a build neither indexes nor descends, as a `PrunedNames`.
  `PrunedNames::builtin`, the default, holds `.DS_Store`, `.fleet`, `.idea` and `.vscode`. A caller adds names with
  `union` or states a set of its own with `PrunedNames::new`; an empty set prunes nothing beyond `.git`. A name no entry
  in a tree carries is no error, and a name no entry can carry — empty, `.` or `..`, or holding a path separator or a
  NUL — is refused by name. `BuildOptions` compares and hashes the set by its members, so a cache keyed on a build's
  configuration covers it.
- **What a name prunes.** A name prunes an entry of any kind, at any depth, by the entry's own name, compared exactly
  with case included. The root a build is given is never pruned, whatever its name.
- **Before and outside the ignore rules.** The walk drops a pruned entry by the name it decoded from the listing, before
  it checks that the name decoded without loss and before any `.gitignore` match, so a pruned directory costs one name
  check and its listing is never read. No negation brings a pruned name back, and `IgnoreSources::None` keeps it out
  too. While ignore rules apply, a pruned `.gitignore` still applies its rules, and no visitor is handed it, since the
  index does not hold it ([ADR 1.12](/design-docs/adr/1.12-build-content-reads.md)).
- **`.git`.** `.git` is not in the set and is pruned whatever the set holds; a set that holds it prunes exactly as one
  that does not. On Windows `.git` matches without regard to ASCII case, as git folds its control names there. Which
  directories that hold a `.git` the index keeps is [ADR 1.74](/design-docs/adr/1.74-git-layouts.md).
- **Refresh and watch.** The index keeps its set, and `Index::refresh` walks with it. A path given to
  `Index::refresh_paths` through a pruned name is skipped, not widened to the pruned directory, which would index it. A
  pruned `.gitignore` is the exception: its rules apply, so it widens to the directory it governs. The Linux watcher
  watches no directory named `.git` or in the set
  ([ADR 1.20](/design-docs/adr/1.20-linux-directory-watches.md)); the macOS and
  Windows backends report pruned paths, and a refresh skips them at no pass over the index
  ([ADR 1.16](/design-docs/adr/1.16-scoped-refresh.md)).
- **What answers say.** [ADR 1.62](/design-docs/adr/1.62-pruned-path-listing.md) states
  how a listing reports a pruned name, and that nothing counts what a name pruned.

## Why

- A repository's global excludes are machine-local sources the reproducible level of
  [ADR 1.3](/design-docs/adr/1.3-ignore-sources.md) leaves out, so without pruning a build indexes workspace layouts and
  Finder records as files of the tree.
- The tools that write these names spell them one way, so a case fold would cost a fold per entry for spellings no tool
  writes; editor state is a directory and Finder's record a file, so a kind check buys nothing.
- `IgnoreSources` stays the ladder of git's own sources that [ADR 1.3](/design-docs/adr/1.3-ignore-sources.md) draws
  reproducibility on; pruning is the caller's statement of what the index is for.
- `.git` is not clutter: one below the root marks a nested repository, where the inherited rules reset, a refresh widens
  a changed `.git` to its directory ([ADR 1.16](/design-docs/adr/1.16-scoped-refresh.md)), and it holds the object
  store, often larger than the tree.

## Consequences

- The check costs a comparison with `.git` and a binary search over the set's names for each entry, inside the noise
  of every measured build (PR #70).
- An answer loses what the set prunes: the Go monorepo's file set loses the 8 files of its two `.idea` scope lists.
- What a pruned directory holds is unreachable through the index, by any query. Accepted.

## Rejected

- **Glob patterns, as `ListOptions::exclude` takes** — a glob set matched against every path the walk finds, where
  clutter is named by its name wherever it lies; a path pattern stays the query's, through `Filter`.
- **The names as a synthetic `.gitignore` layer** — `IgnoreSources::None` would index them again, git's rules and the
  caller's would share one ladder, and every entry would pay a `wildmatch` per name.
- **A flag that turns a fixed list on or off** — serves neither a caller with clutter of its own nor one that wants a
  name back, as [ADR 1.7](/design-docs/adr/1.7-binary-extension-set.md) settled for binary extensions.
- **Leave it to the consumer to filter answers** — the walk would still descend every pruned directory, and every query
  would filter every answer.
- **A wider default** — `Thumbs.db`, `desktop.ini`, `.vs`, `__MACOSX` and `.history` occur on none of the measured
  trees but the data volume's two `.history` directories, and a default past the editors and the OS in common use would
  prune names some tree uses for content.
- **`.git` in the set, removable** — it bounds the ignore rules and the refresh and holds the object store, and a set
  that let a caller take it out would have to say what the index means by a repository's bookkeeping.
- **`PrunedNames::difference`, `PrunedNames::none` and a reader of the names** — the C ABI offers extend and replace,
  and no consumer took a name out or read the names back.

## Revisit if

A consumer needs what a pruned directory holds without listing it by name, a name outside the default proves common on
the trees this engine serves, or a caller needs a path-shaped prune at walk time. Medium confidence.
