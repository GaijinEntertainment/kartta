# Resolve calls when a query asks

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-graph/src/resolve.rs`, `crates/kartta-graph/src/scope.rs`,
  `crates/kartta-graph/src/calls.rs`, `crates/kartta-graph/src/candidates.rs`, `crates/kartta-graph/src/confidence.rs`,
  `kartta_lang::Conventions`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`, `crates/kartta-languages/tests/rust_cfg_twins.rs`

A call names its callee as written, and which definition that is depends on files other than the caller's. Each file
keeps its call sites as written, and a query resolves the sites of the name it asks about, so no file's data goes stale
when another file changes; each query pays the resolution that a stored edge would pay once.

## Decision

- **What the graph keeps.** Calls and uses are resolved when a query asks, and the graph stores no edge. A file's slot
  keeps what resolution reads: its calls, local calls and uses as written, its includes, its re-exports with the file
  each names, its import bindings, its package, its callable identities, its folded declarations, the holders of its
  locals and the parents of its types. The graph keeps, a file at a time: definitions by name, in path order; for each
  call key, the files whose calls use it; for each name, the files whose uses name it; callable identities to their
  occurrences; names a re-export or a binding renames to their new names; and, where a package is a directory, the files
  of each directory. A call key is the last segment of the callee as written;
  [ADR 3.38](/design-docs/adr/3.38-callee-listing-key.md) keys a callee that ends in a separator. Path order breaks
  every tie, as [ADR 3.36](/design-docs/adr/3.36-graph-file-order.md) keeps it.
- **What a query resolves.** `callers` resolves the sites listed under the selected callable's name and under every name
  a re-export chain or a renaming binding gives it, and keeps those that land on it. `callees` resolves the sites of the
  callable's own body. `references` adds the uses of the name, which
  [ADR 3.34](/design-docs/adr/3.34-field-and-value-uses.md) records. `call_path` walks callers from the far end.
  [ADR 3.37](/design-docs/adr/3.37-call-walk-cut-counts.md) states what each answer counts of what it left out.
- **The cascade.** A call binds at the first tier that binds it, with that tier's confidence from
  `kartta_graph::confidence`, 95 down to 15, so a caller sets a floor by the tier it trusts. In order: tier 1, a local
  call (80); tier 2, a receiver that names an import binding (95); tier 3, a receiver that is a type path (85); tier 4,
  a callee written qualified (90 or 88); tier 5, a receiver that names the caller's base class or an owner (85); tier
  6, the scope that offers the name, the caller's file, its imports, package and includes (95 down to 65); tier 7, the
  caller's own owner, the one callable of the name and the nearest one (80 down to 15).
  [ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md) states tiers 2 to 5, and
  [ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md) tiers 1, 6 and 7.
- **What a language supplies.** A tier reads extraction data and `Conventions`, as the ADRs of its tiers name.
  `directory_packages` gates the package tiers, and the test flag keeps test code out of a package's names.
  `MacroInvocations::Apart` keeps a macro invocation and a call apart at every tier
  ([ADR 3.177](/design-docs/adr/3.177-macro-invocation-binding.md)). A file names its directory's package only where it
  holds code outside test code, the first such file in path order. A file's package is the one it declares, or the one
  its resolver places it in: a Rust file's is the Cargo package around it, and a Ruby file's the library
  [ADR 3.189](/design-docs/adr/3.189-ruby-libraries.md) names.
- **Twins.** Where a language's `Conventions` set `Twins::Every`, a call that the caller's file or its receiver's type
  binds also binds that definition's twins: the definitions of its qualified name, kind and holder in its file, and,
  where the caller's file reaches it through a file it includes, in every file the caller's file includes. A member has
  twins only where it and they are exported, and in its own file only where the file defines its type more than once; a
  free function's twins have any visibility. A call made inside the definition or a twin binds no twin. Each branch of a
  Rust `cfg` defines such a twin, and some build compiles each one.
- **Re-exports.** A hop goes to the file the resolver named for the re-export's specifier. A barrel that re-exports a
  name by name is not searched through its star re-exports for that name. Each barrel is searched once under each name,
  so a chain of any length ends, and binds however many barrels rename it.
- **Many definitions.** A query indexes the candidates of a name with 64 definitions or more once, by owner, directory,
  parent directory and file, and every tier reads that index. A call inside a body that holds a definition of the name
  local to it keeps a scan. Nothing a query derives outlives the query.

## Why

- An edge stored at build goes stale when any file the call read changes: the caller's imports and includes, its
  directory's package, every definition of the name. Re-resolving after one edit took up to 1.66 s of CPU on a Go
  monorepo of 79,964 Go files (2026-10-16, #52).
- The tiers follow how a language's own scope finds a name, the surest first, and the confidence lets a caller drop the
  guesses.
- Every tier scans the definitions of the name: without the index, `callers(String)` and its 21,647 definitions took
  6.5 s, and take 45 ms with it (Go monorepo of 119,888 Go files, 2026-10-16, #50).
- Listing each file once per call key, rather than each site, keeps that listing at 14 MB where per-site lists took
  72 MB on the same tree (#50).
- A tier that holds several definitions equal binds the first, so every other `cfg` branch's definition read as dead
  code in `find_callers`. Binding the twins adds 167 call edges on five Rust trees and removes none, 98% of 146
  classified right against the source (2026-10-29, #239).

## Consequences

- A query pays the resolution: `callers` of `len`, the busiest Go name with 279k sites, took 0.55 s on the Go monorepo
  of 119,888 Go files (2026-10-16). Accepted.
- The call sites and their indexes hold memory a graph of definitions alone does not: the live heap after a C++
  game-engine tree build grew from 246 MB to 486 MB (#47). Accepted.
- A Rust method whose own `cfg`, or its impl's, makes the twin of a type the file defines once keeps one binding, as
  tokio's two `SignalKind::io` do, and a call under one `cfg` binds the twins of every other branch too. Accepted.

## Rejected

- **Resolve every call at build and store edges in both slots** — answers in microseconds, but resolves every site
  whether asked or not, peaks at up to 1.7 times the lazy footprint, keeps edges beside the sites, and re-resolves up
  to seconds of CPU per edit under invalidation keys that must cover every tier.
- **A memo of resolved sites, invalidated by eager's keys** — closes only the tail of lazy queries, under 0.3 s on the
  measured trees, at the price of eager's invalidation and a memo that grows with what is asked.
- **A hop bound on re-export chains and renames** — drops without a count the callers a longer chain reaches, where the
  visited barrels already end every chain.
- **Binding the first twin and naming the others in the answer** — a twin's own `find_callers` and `find_unused` still
  answer that nothing calls it.
- **Twins by qualified name and kind alone** — one type's impls of a trait for several arguments are twins then: 1,750
  edges added on rust-analyzer, most of them `Expr::from` and other `From` impls of one type (#239).
- **Twins only where the signatures match** — misses the branches that differ in a parameter's type, as `RawFd` beside
  `RawHandle`, where the member rules already keep impls of one type apart (#239).

## Revisit if

A family's names carry enough call sites that a lazy `callers` of one exceeds a second, or agents' queries repeat the
same names often enough that a memo would pay for its invalidation. The first holds with margin on the measured trees,
whose worst name took 0.55 s; how often agents repeat a name is not measured.
