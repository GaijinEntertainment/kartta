# Bind nothing for a PHP call on a class outside the graph

- **Date:** 2026-10-24
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`resolve_by_name`, `names_a_class_outside_the_graph`,
  `constructs_outside_the_graph`), `crates/kartta-graph/src/scope.rs` (`inherits_from_outside_the_graph`),
  `crates/kartta-lang-php/src/lib.rs` (`CONVENTIONS`), `kartta_lang::BareReceivers`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`
  (`a_bare_receiver_naming_no_class_of_the_graph_binds_nothing_where_it_names_a_class`),
  `crates/kartta-languages/tests/php_static_call.rs`, `crates/kartta-languages/tests/php_static_aliases.rs`,
  `crates/kartta-languages/tests/php_inherited_members.rs`, `crates/kartta-languages/tests/php_use_names.rs`,
  `crates/kartta-languages/tests/php_new_counts.rs`

A PHP static call names its class, `Mockery::mock()`, and a class from a Composer package is one the graph does not
hold, so a method of that name in the tree belongs to another class. Such a call binds nothing, since the extraction
writes an alias under the class's name from the root, which no type outside the tree holds
([ADR 3.14](/design-docs/adr/3.14-php-includes.md)), at the cost of an outside class whose bare name the tree also
declares. A call on a class of the tree that extends such a class binds nothing either, at the cost of the classes an
outside class extends that the tree holds.

## Decision

- **Bare receivers.** Where `Conventions::bare_receivers` is `BareReceivers::Classes`, as PHP's is, a receiver written
  as a bare name, of letters, digits and `_`, or from the root, names a class, except for the scope keywords the
  language lists, compared without case: PHP lists `parent`, `self` and `static`. A PHP value is written `$value` and is
  no bare name.
- **Classes outside the graph.** A call on such a name that no type of the graph is named, or written from the root and
  no type of the graph holds that qualified name, once the receiver's owner
  tier ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md), tier 5) binds nothing, binds no definition of the
  caller's file, of its imports, of its includes or of the re-export chains of those
  ([ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md), tier 6), no member of the caller's own owner, and neither
  the one callable of the name nor the one nearest the caller (tier 7). The miss counts as not admitted, through a
  receiver.
- **Parents outside the graph.** Where `Conventions::parent_spelling` is `ParentSpelling::FromRoot`, as PHP's is, a call
  whose receiver's class ([ADR 3.193](/design-docs/adr/3.193-receiver-class-members.md), The class) holds no member of
  the name, whose walk finds none, and of which the class or a type above it writes as its first parent a name no type
  of the graph is named, binds nothing, a miss not admitted, unless a member of the name sits in a trait of the graph.
  The extraction writes the class a type extends first, so the first parent stands for it, and a class with no `extends`
  has its first interface there.
- **A construction counts once.** A `new` of a class the graph does not hold is two calls that bind nothing
  ([ADR 3.14](/design-docs/adr/3.14-php-includes.md)), and the class's call alone counts: a call of
  `Conventions::constructor` on such a class, right after the file's call of the class's last name on the class written
  from the root, counts in neither `unresolved` nor a [coverage](/design-docs/adr/3.24-graph-stats-and-coverage.md)
  site. A constructor called by hand counts, and a class of the graph counts each of its calls that bound nothing.
- **The default.** `BareReceivers::Any`, the default, reads a bare name as a value, a module or a type alike.

## Why

- A class the graph does not hold has no member in the graph, so a definition its name alone finds is a namesake:
  99.6% of the 1,184 caller-callee pairs the rule unbinds on Laravel and Symfony are wrong, `Mockery::mock()` binding a
  testing trait's `mock` among them (2026-10-24, #460).
- An imported file's method of the name is a namesake too: each of the 31 of the 83 such pairs read on Laravel and
  Symfony is wrong, as `\WeakReference::create()` binding `Request::create` (2026-11-01, #524).
- A class's method table holds what its parents gave it (`zend_std_get_method` in php-src 8.5.12
  `Zend/zend_object_handlers.c`), so a member the tree's part of the chain lacks stands in the outside class:
  56 of 60 pairs read of the 430 the rule unbinds on Laravel and Symfony are wrong, as `$this->assertEmpty()` binding
  `FilesystemAdapter::assertEmpty` (2026-11-01, #862).
- `unresolved` says what an answer left out, and a construction of an outside class leaves one class unread: counting
  both calls added 12,530 sites on Laravel and Symfony that the source holds as one (2026-11-01, #955).

## Consequences

- A call through a scope keyword spelled otherwise than PHP spells it, or a receiver whose class is declared in
  another letter case, `str::of()` for `Str`, binds nothing. Accepted.
- A plain `use` keeps a bare receiver, so `use Vendor\Thing; Thing::f()` binds a namesake of the tree: 53 pairs on
  Laravel and Symfony (2026-11-01, #862). Of those 19 are wrong; 34 are `UserFactory::new()` of Testbench, whose class
  extends the tree's `Factory`, right through a namesake in `types/`. Accepted.
- A class with no `extends` whose first interface lies outside the graph reads as extending it: `$this->getContent()`
  in `TestResponse`, which `__call` forwards, binds nothing. 3 of the 60 pairs read. Accepted.
- A member a trait of the graph holds stays with the tiers, a namesake's trait included: 1,191 pairs on Laravel and
  Symfony, about 450 of them testing concerns a Testbench test case does hand a test. Accepted.
- A method named as its class, called on a value of an outside class right before a constructor called by hand on that
  value, `$x->Gone(); $x->__construct();`, reads as a construction, so the constructor's call counts nowhere: no site on
  Laravel and Symfony (2026-11-01, #955). Accepted.

## Rejected

- **Hold back only the one callable of the name** — keeps the namesakes the caller's file and directory hold, 53 wrong
  pairs on the same trees.
- **Write an alias of a class outside the tree under that class's last name too** — binds a namesake of the tree: `use
  Faker\Factory as FakerFactory; FakerFactory::create()` bound Eloquent's `Factory::create` at 85 (2026-11-01).
- **Write every plain `use` of a class outside the tree from the root too** — 19 of the 53 pairs it unbinds are wrong,
  and by PSR-4 alone it also unbinds the `DB` of `use DB;`, a global alias, and a class no `composer.json` maps
  (2026-11-01, #862).
- **Count every parent outside the graph** — a class's outside interface hands it no body: `Post::create()` through
  `Model implements \ArrayAccess` was lost, among 634 more pairs (2026-11-01).
- **Bind nothing for a trait's member too** — 1,191 more pairs, a Testbench test case's concerns among them
  (2026-11-01).
- **Leave out every constructor call on an outside class written from the root** — `\Exception::__construct()` holds no
  `new`, so its caller read as leaving nothing out: 1 site on Laravel and Symfony (2026-11-01, #955).
- **Mark a construction's constructor call in the extraction** — a field on every language's call record, where the
  file's calls already stand in source order (2026-11-01, #955).

## Revisit if

A static call on a plain `use` starts to carry the class's full name as an alias's does, which would close the bare
name's reach to a namesake, or the extraction marks the class a type extends apart from its interfaces. Not planned.
