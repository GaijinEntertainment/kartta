# Name Rust items by their module chain and resolve modules by Cargo's layout

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-rust/src/walk.rs`, `crates/kartta-lang-rust/src/walk/settle.rs`,
  `crates/kartta-lang-rust/src/walk/attributes.rs`, `crates/kartta-lang-rust/src/resolve.rs`,
  `crates/kartta-lang-rust/src/lib.rs` (`CONVENTIONS`)
- **Pinned by:** `crates/kartta-lang-rust/tests/modules.rs`, `crates/kartta-lang-rust/tests/resolve.rs`,
  `crates/kartta-lang-rust/tests/extract.rs`

A Rust file names what it declares through inline modules, `impl` blocks and paths, and reaches other files only through
`mod` declarations, whose targets Cargo's layout decides. `kartta-lang-rust` qualifies an item by the chain of its
inline modules and finds crate roots from the conventional layout and each manifest's library, so a target that a
manifest places elsewhere is no crate root.

## Decision

**Names.** An item is qualified by the chain of its inline modules: an item of `mod a { mod b { .. } }` is
`a::b::Worker`. A member of a `trait`, or of an `impl` whose target names a type, is owned by that type and qualified
under it, `a::b::Worker::run`, and a field or a variant under its struct or enum. Outside a function body an `impl` for
a tuple, `dyn` or function type opens no type, so its functions are free; inside a body the type as written owns them,
`(u8, u8)::show`.
A function of an `extern` block is free, except that one `#[wasm_bindgen(method)]` marks is owned by the type its first
parameter, `this`, refers to. A `constructor` is owned by the type it returns, `T` of a `Result<T, E>`, and a
`static_method_of = T` function by `T`, written as a name or a string. A `macro_rules!` keeps its
bare name and no owner, and only `#[macro_export]`, with or without arguments, exports one, at its crate's root path
whatever module defines it. A file's own module is no part of any qualified name. An item a function body declares
inside an `impl` is qualified under the type but is no member of it. `pub` exports an item, but `pub(self)` and
`pub(in self)` do not; a trait's members take the trait's visibility and a variant its enum's.

**Impl owners and trait parents.** An impl's owner is the type its path names in the file, `impl super::W` inside
`mod inner` of `mod a` naming `a::W` where the file declares `a::W`, and otherwise the path as written; a path through
`crate::`, a leading `::` or a `super::` past the file's root keeps its spelling too. The owner settles after the walk,
and what the walk recorded under the impl — its members, the items nested in them, its `self` receivers and its trait
pair — follows it; settling one impl renames nothing of another. `impl Trait for Type` adds `Trait` to the parents of
the struct, enum or trait the file declares under that path, else under that name, the first the file declares; a path
that names no declaration of the file, `impl Trait for other::Foo`, adds no parent.

**Calls and paths.** [ADR 3.56](./3.56-name-a-rust-call-s-receiver-only-where-its-syntax-spells-it.md) decides what a
call records as its receiver, and ADRs
[3.50](./3.50-bind-a-rust-path-into-another-crate-through-its-library-s-module-files.md),
[3.51](./3.51-start-a-rust-path-through-crate-self-or-super-at-the-caller-s-crate-root-or-module.md) and
[3.52](./3.52-scope-a-rust-use-inside-a-block-to-that-block.md) which paths a `use`, a path call and a macro invocation
keep for the resolver. Neither a `use` nor `extern crate` adds an include, and `extern crate` adds nothing.

**Modules.** A bodiless `mod NAME;` includes `NAME.rs` or `NAME/mod.rs`: beside a crate root or a file named `lib.rs`,
`main.rs` or `mod.rs`, under the directory named for any other file's stem, and one directory deeper for each inline
module around the declaration, so `mod inner { mod child; }` in `src/lib.rs` pulls in `src/inner/child.rs`. A `#[path]`
override is relative to the declaring file's directory, or inside an inline module to that module's directory, read as
written without decoding escapes; an inline module's own `#[path]` is not read. A directory that holds a `Cargo.toml`
is a package. Its crate roots, judged against the nearest package, are the file its manifest's `[lib] path` names,
`src/lib.rs`, `src/main.rs`, `build.rs`, and each target under `src/bin/`, `examples/`, `tests/` and `benches/`, as a
file or as a directory with a `main.rs`. A top-level `fn main` in a crate root of that layout other than `src/lib.rs` is
the entry point, in each of its `cfg` alternatives; the `[lib] path` file is none. The resolver lists the packages once
and reads each manifest only for its library (ADR 3.50), so another target that a manifest places off the layout is no
crate root and no entry. It keeps only what it derived, the packages and each library's name and root, and compares
that on a rebuild, as
[ADR 3.82](./3.82-build-a-followed-family-s-resolver-again-only-when-a-refresh-reaches-what-it-read.md) decides.

**Test and generated code.** An item is test code, with everything in it, when an attribute whose path ends in `test`
or `bench` marks it, `#[tokio::test]` included, or a `cfg` gates it that holds only under `test`; a file-top
`#![cfg(test)]` marks the file, and an inline module's inner gate the module. A `cfg` predicate is evaluated over every
assignment of the atoms it repeats, one truth per distinct atom, leaving an atom written once unknown: `cfg(all(test,
not(miri)))` gates, while `cfg(any(test, feature = "x"))`, `cfg(not(test))` and the never-true `cfg(any())` do not.
Past 12 repeated atoms the rest stay unknown. A file below a `tests` directory outside `src`, counted from the
repository root or from any package around the file, is integration-test code. A test-gated `mod`, or any `mod` of a
test file, makes the file it pulls in a test include, since that file is extracted on its own and cannot see the gate;
[ADR 3.5](./3.5-keep-the-graph-a-file-at-a-time.md) decides when the graph marks such a file. A `*.gen.rs` or
`*_generated.rs` file, or one with a `@generated` or `DO NOT EDIT` marker in its leading comments outside a backtick
span, is generated code.

**Conventions and fingerprint.** Rust's `Conventions` set `MemberCalls::ModulePaths`
([ADR 3.39](./3.39-bind-a-member-call-to-a-free-function-only-where-a-value-can-hold-one.md)),
`NamespaceCalls::Unbound` ([ADR 3.44](./3.44-bind-no-call-to-a-namespace-where-a-language-s-calls-name-none.md)), the
standard library's most-called methods as `runtime_methods`
([ADR 3.40](./3.40-bind-a-runtime-method-s-call-only-to-a-member-that-scope-reaches.md)), `other` alone as an own-type
receiver ([ADR 3.41](./3.41-bind-the-caller-s-own-owner-only-on-the-receivers-a-language-lists.md)),
`MacroInvocations::Apart`
([ADR 3.177](./3.177-bind-a-macro-invocation-only-to-a-macro-where-a-language-writes-it-apart.md)),
`OwnMembers::Unreached` and `TypeUses::Nowhere`. The fingerprint covers the walk and the grammar, as
[ADR 3.4](./3.4-extract-typescript-and-javascript-as-one-family.md) settles for TypeScript.

## Why

- A file's module path depends on its location and on its crate's `mod` tree, which the extraction from the bytes does
  not see; the inline-module chain is in the bytes and keeps two modules' same-named items apart.
- A scoped impl path leads where the file cannot tell, so matching it by its last segment hands the trait to an
  unrelated local type of that name.
- web-sys and js-sys declare their methods as `#[wasm_bindgen(method)]` functions whose `this` names the type, and
  their constructors and static methods as functions Rust calls through the type, `Number::is_nan(x)`: owning them
  binds 63 calls of js-sys 0.3.106 (2026-10-24).
- The packages turn the conventional targets into crate roots: against crate roots told by file names alone they add
  355 includes, the `mod common;` of integration tests, and 104 entry points of build scripts, benchmarks and tests
  without the default harness (cargo registry of 16,978 Rust files, 2026-10-16).
- Every `lib.rs` off the layout in a registry of 447 crates is a library that a `[lib] path` places, as the
  `bindings/rust/lib.rs` of each tree-sitter grammar (2026-10-16); a `[lib] path` of another name,
  tree-sitter's `crates/cli/src/tree_sitter_cli.rs`, included none of its 17 modules until it was a crate root
  (2026-10-23).
- A `macro_rules!` is in scope by text order rather than by path, and `#[macro_export]` places it at the crate root.
- The `cfg` check decides a predicate exactly however many atoms it writes once, and the bound of 12 repeated atoms
  keeps it under 2^12 assignments.

## Consequences

- A target that `[[bin]]`, `[[test]]` or an `auto*` key places off the layout is no crate root: its `mod`s look under
  its stem and its `fn main` reads as dead code. The registry loses 6 entry points of a fuzzing directory whose manifest
  the published package left out. Accepted.
- A wasm-bindgen static method joins its type's namesakes, so a call on a value of a generic type whose trait declares
  that name, `promises.all()` under `T: PromiseTuple` beside `Promise::all`, binds nothing: 2 calls of js-sys. Accepted.
- Past 12 repeated atoms a `cfg` check can miss a gate that holds through a thirteenth, or mark as test code an item no
  build compiles. Accepted.
- A `#[path]` value with an escape names the wrong file; none of the registry's 1,601 `#[path]` attributes writes one.
  Accepted.

## Rejected

- **Crate roots by file names alone** — a crate root such as `tests/it.rs` or `build.rs` looks for its submodules under
  its own stem, where none is, and a build script's `fn main` reads as dead code.
- **Reading every manifest target** — finds what `[[bin]]` and the `auto*` keys place off the layout, at the cost of a
  TOML parser and a read of every target key whenever the resolver is built.
- **Matching a scoped impl target by its last segment** — gives `From` to the file's own `Error` for
  `impl From<Error> for io::Error`, and a trait implemented for `std::fs::DirEntry` to a local `DirEntry` (registry,
  2026-10-16).
- **Qualifying by the file's module path** — every name would change with the file's location, and the extraction
  could not carry it.
- **A `tests` directory in any case** — Cargo finds integration tests under `tests` alone, so a `Tests/` directory
  holds no target Cargo builds as a test.

## Revisit if

A consumer needs the targets that a manifest places off Cargo's layout. None asks yet; every off-layout `lib.rs` of the
447-crate registry was a `[lib] path` library, which the manifest read covers.
