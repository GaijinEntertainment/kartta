# Hold a path a notification in a batch, each at its length

A batch of [ADR 1.17](./1.17-follow-a-tree-through-its-change-notifications.md) is gathered from every notification a
drain or a wait reads, and a flood of writes to a few files raises one per write. Each notification that names a path
holds it until the batch closes, allocated at its length, and the close drops the repeats; the trade is memory that
follows the notifications, not the paths they name.

## Decision

- Every notification a poll reads that names a path holds that path until the batch closes; the notice of a released
  watch and the overflow marker name none. On Linux each path is allocated at its length as it is read; on macOS and
  Windows the batch holds the paths notify hands over.
- The close names each path from the root, each name allocated at its length, then sorts them and drops the repeats.

## Why

- `Path::join` and a name grown a component at a time over-allocate: grown that way, a drain of 1,000,000 queued
  notifications, each the truncation of one of 1,000 files, peaked 121.88 MiB above where it began, and 96.64 MiB with
  each path and name at its length, on 1.8 million entries (2026-10-21). Exact paths and exact names each
  show nothing alone: the close collects every name, repeats included, before it sorts them.
- An exact set of the paths as they are read costs a batch of a million distinct paths a probe of a table of a million
  slots a notification, a cache miss each that a faster hash does not remove, and the table's slots beside the paths.

## Consequences

- A batch holds a path for every notification read that names one, however few files they name: about 97 MiB for a
  million on 1.8 million entries (2026-10-21). Accepted.

## Rejected

- **De-duplicate the paths as they are read** — a flood of writes to a few files would hold a path a file, 0.14 MiB for
  1,000 files, but a batch of a million distinct paths took 1.2–1.8 s to drain against about 0.5 s.
- **Allocate exact paths alone, or take the close's names in one at a time** — each leaves the peak where it was, since
  the other half still over-allocates.

## Revisit if

A consumer raises `fs.inotify.max_queued_events` far past a million, so one drain can hold a path for each of many
millions of notifications. Medium confidence: a Docker VM's default is 1,048,576.
