# Bind a use of a field or a value by what its receiver names

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`resolve_use`, `member_use`, `value_use`, `bare_use`,
  `imported_value`, `expanded_value`), `crates/kartta-graph/src/members.rs`, `crates/kartta-graph/src/typed.rs`,
  `kartta_lang::{ValueUses, UntypedMembers, OwnMembers}`
- **Pinned by:** `crates/kartta-graph/tests/graph/typed.rs`, `crates/kartta-graph/tests/graph/members.rs`,
  `crates/kartta-mcp/tests/graph.rs`

A use of a field or a value names its target as written: bare, through a qualifier, on the member's own receiver, or
on a path. [ADR 3.34](/design-docs/adr/3.34-field-and-value-uses.md) records each use and binds it when a
query asks; each receiver binds at the tiers below, where the source reads it, and a use that only the field's name
would bind is left ambiguous rather than guessed.

## Decision

- **Fields and locals.** Past the class-scope lookup, a bare or qualified use binds no field, enum variant or local
  symbol, but a qualifier read as a path does.
- **Bare.** The class-scope lookup first where the language sets `OwnMembers::First`
  ([ADR 3.64](/design-docs/adr/3.64-cpp-data-sites.md)), then by `ValueUses`: `Declared`, the definition outside every
  owner and body its own file declares at 80, a dot-imported package's at 95, its package directory's at 75 where
  packages are directories; `Imported`, its own file's at 80, then the one included file that exports the name at 70
  (two bind none), a re-export chain from them at 65, then the one included file that declares it unexported at 70;
  `ImportedThenReached`, those, then the one file the includes reach in turn that declares it at 70 (two bind none),
  then the one file sharing an include root with the use's file that declares it at 60 (two bind none), DSHL's
  ([ADR 3.18](/design-docs/adr/3.18-dshl-extraction.md));
  `Expanded`, daslang's, those of `Imported`, then at 60 the one definition the files including the use's file bind
  under `Imported`, since a macro's quoted code names what the expanding file reaches (two bind none);
  `Included` is C++'s ([ADR 3.64](/design-docs/adr/3.64-cpp-data-sites.md)). Where only a module's path reaches a free
  item (Rust), the own file's tier binds the first item of the innermost inline module that holds the use's line and
  declares the name, and a module of the name is no value.
- **Qualifier.** Through the file's import of that module, an exported package-level definition at 95. Where
  receivers are type paths (Go), a qualifier that no import of the file binds is a path of one name, and the use binds
  as one on a path does: a walk that sees one file takes a sibling file's package value for a qualifier
  ([ADR 3.60](/design-docs/adr/3.60-go-data-sites.md)). Elsewhere a qualifier that names the module
  its own file declares, daslang's `coverage::f` inside `module coverage`, binds as a bare name under `Declared` does,
  since that module is the file; one that names the module an included file declares binds that file's definition, as
  [ADR 3.140](/design-docs/adr/3.140-daslang-module-lookup.md) states; any other binds nothing.
- **Own receiver.** Under `OwnMembers::First` the class-scope lookup; otherwise the member of the class around the use
  at 85, else one a base declares at 80 where every base searched before it was found without a guess. No class around
  the use, or an unseen base before the find, counts as ambiguous.
- **Paths on type paths.** Where receivers are type paths (Go), a path binds a field or a method of the type the path
  reaches, or of a type it embeds, at 85; a path that reaches a field or a variable whose struct is anonymous reaches
  the fields it owns ([ADR 3.170](/design-docs/adr/3.170-go-anonymous-structs.md)). A path into code outside the graph,
  an undeclared name, or a type without the member binds nothing and stops. A path the graph cannot follow goes to the
  untyped tier.
- **Paths on owners.** Where receivers name owners, a non-empty path binds the member of that owner its file or one
  included file declares at 85 (two included files count as ambiguous); else the definition outside every owner of the
  one included module whose name the path ends, at 85; else a type of that name the file or one include declares at 85,
  then its bases at 80 under the same no-guess rule. Otherwise it binds nothing, and no untyped tier is tried; C++ reads
  includes further ([ADR 3.64](/design-docs/adr/3.64-cpp-data-sites.md)).
- **The untyped tier.** The empty path binds by `UntypedMembers`: `FileField`, the one field of the name its file
  declares outside every body but the use's own, at 80, none or several counting as ambiguous; `Unbound`, nothing,
  counted as ambiguous; `IncludedField` is C++'s ([ADR 3.64](/design-docs/adr/3.64-cpp-data-sites.md)).

## Why

- The type path binds what the source reads: 64 of 64 sampled sites on the Go monorepo were right (2026-10-18, #82).
- A daslang macro quotes its own module's functions as `module::f`, and with that qualifier unbound `find_unused`
  listed 5 such functions on the game-engine tree (2026-10-24, #434).
- A Rust bare read names its own module's item, and all 9 reads the module rule moved on six Rust trees bound that item
  in place of a namesake of another module or `#[cfg]` block (2026-10-31, #492).
- The graph expands no macro, and a daslang macro's quoted code compiles in the file that expands it, so a name only
  that file requires stays unbound in the macro's own: 2 of the 2,296 definitions `find_unused` listed on the
  game-engine tree. The files that require the macro's file stand in for the expanding one, and binding what they agree
  on holds 48 of 52 pairs right (2026-10-31, #538).

## Consequences

- An untyped member under `FileField` can bind a namesake field of its file, as a value of an anonymous struct did.
  Accepted.
- A quoted name that means a native function binds a namesake an including file reaches, 2 of the 52 pairs, and 2 more
  bind another overload of the right name, because a use counts no arguments. Accepted.
- A name the including file reaches only through further requires stays unbound: 33 sites of `testing.accept` on the
  game-engine tree. Accepted.

## Rejected

- **Fields by name only, no type paths** — bound 12 of 24 sampled sites right where the path was cut.
- **The one definition of a quoted name in the family** — adds 133 pairs, and 62 of them bind daslang's native `range`
  to a script's namesake.
- **Mark a quoted use apart from an address** — every pair the rule adds is quoted code, so the mark would move nothing.
- **The one field of the name in the family** — 2 of 7 right in C++: the field is the only one because the real struct
  was not extracted.
- **A module's chain stored on each Rust bare use** — the use's line and the extents of the modules around it already
  tell it, and a use stays 16 bytes.

## Revisit if

A language's walk names the type of the values whose path it leaves empty, so its untyped tier could give way to a
path, or the type path stops binding what the source reads. Held with high confidence on the 64 sampled sites.
