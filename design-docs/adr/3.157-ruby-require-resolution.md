# Resolve a Ruby require under the load roots projects set

Ruby finds a required file through the load path, which a project sets at run time and the extraction cannot read. The
resolver tries the load roots Ruby projects set most often, so a require of a repository file is an include and any
other an import, at the cost of the files a project reaches through a root it adds itself.

## Decision

- A `require` or `require_relative` with no receiver and a string argument of plain text names a file, with or
  without its `.rb`. A string with an interpolation, `"cmd/#{name}"`, or an escape names nothing. A require with a
  receiver, `config.require 'x'`, is a method of its own and loads nothing.
- `require_relative` resolves from the requiring file's directory. `require` resolves under the first of `lib`, the
  root, `test`, `spec` and `app` that holds the file.
- A require that names a file of the repository is an include. Any other, of a gem or of the standard library, is an
  import as written.

## Why

- These roots hold most required files: on Homebrew, 3,897 of 4,846 requires are includes (2026-10-16).
- An interpolation builds the path at run time, and an escape spells it apart from its value, so either would name
  the wrong file or an import of a spelling no module has.

## Consequences

- A Rails application loads most of its files by autoloading, without a require, so many of its files have no
  include. Accepted.
- A file reached only through a root the project adds to `$LOAD_PATH` stays an import. Accepted.

## Rejected

- **An import for every require, also one that resolves** — states one dependency twice, and keeps an import for a
  module that names no repository file.

## Revisit if

The extraction reads a `Gemfile` or the `$LOAD_PATH` additions of a project. Not planned.
