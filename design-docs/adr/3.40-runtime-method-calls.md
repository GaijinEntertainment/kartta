- **Date:** 2026-10-17

`line.trim()` calls the runtime's `trim`, not a function of the repository, and the method's name says nothing of which
type the value has. A member call of a method that a language's runtime gives its values binds a member of the name only
where scope reaches one, or the one callable whose owner its receiver spells.

## Decision

- `Conventions::runtime_methods` lists, in ascending order, the methods a language's runtime gives its own values:
  ECMAScript's built-in objects and the DOM's interfaces for TypeScript and JavaScript; the built-in types for Quirrel,
  with the methods the game engine binds on the values it hands its scripts
  ([ADR 3.145](/design-docs/adr/3.145-quirrel-runtime-methods.md)); the built-in types and
  the standard library's common values for Python; the standard library's methods and associated functions for Rust.
  Every other language lists none: Go's member calls take a member alone already (ADR 3.39), daslang's method syntax
  calls free functions, and Lua keeps no list.
- A member call whose callee is listed binds no free definition at any tier, and no re-export chain.
- A receiver that names an import binding names a module, not a value, and the module's export of the name binds, as
  `strings.trim()` after `import * as strings` does
  ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md), tier 2).
- Such a call binds a member of its name only through the caller's file, imports, package and includes, the owner its
  receiver names, or the caller's own owner on a receiver the language allows (ADR 3.41). It binds the one callable of
  the name, at 60, only where the receiver's last segment spells that callable's owner in any case: `session.seek()`
  binds `Session.seek`, and Rust's `watcher.drain()` binds `Watcher::drain`.
- Where `Conventions::included_runtime_members` is `IncludedRuntimeMembers::SpelledOrOwn`, as it is for Quirrel,
  TypeScript and JavaScript, a member that a file the caller includes declares binds only where the receiver's last
  segment spells its owner in any case, the caller's own owner is that owner or derives from it, or the owner is an
  interface or a type alias: `obj.setValue(1)` binds no `PostFxSettings.setValue` of an imported file,
  `postFxSettings.setValue(1)` does, and so does `this.remove()` in a class derived from the member's; `$icon.get(0)`
  binds no imported class's `get`, and `drawer.open(1)` binds the `open` of an imported interface. Every other language
  keeps `IncludedRuntimeMembers::Any`, where an included file's member binds as the caller's own file's does.
- Otherwise the call binds nothing and counts as not admitted. It never binds by nearness.

## Why

- The runtime answers these calls on the value itself: every sampled Quirrel, Python and Rust site the lists unbound
  called the runtime (C++ game-engine tree and Go monorepo, 2026-10-17).
- A free function a barrel re-exports is no more what a value holds than one an include defines.
- The one callable and nearness still bound the runtime's namesakes, a Quirrel array's `append()` to a generated
  `OutputText.append` and Python's `str.format()` to a tool's `Identity.format`; of the sites the scope rule then
  unbound, under 1% were right (2026-10-19).
- A Quirrel script calls the engine's methods on the native values it holds, GUI objects and watched state, far more
  often than on the classes of the files it imports: of the 338 pairs the narrowed include tier unbinds on the
  game-engine tree, 38 of 40 sampled were such calls bound to a namesake (2026-10-23).
- A JavaScript value a runtime method is called on is most often a Map, a Set, an array, `JSON` or a DOM node: of the
  pairs the narrowed include tier unbinds in SillyTavern, 36 of 39 sampled bound such a call to an imported class's
  namesake. An interface or a type alias makes no value, so a file imports one to type the values it holds: 26 of the 29
  pairs through one that the narrowing would unbind on the Go monorepo snapshot and react-hookz were right
  (2026-10-24).

## Consequences

- A call of a repository member named like a runtime method binds nothing where scope does not reach the member:
  `reader.read()` on a `SockReader`, 6 sites in three copies of one tool, and seven Rust `Index::get` calls from `ix`
  values.
- Inside jQuery, the calls of jQuery's own methods that the DOM names too, `jQuery(this).replaceWith()`, bind nothing,
  the right ones with the wrong.
- A Quirrel class a script defines in place of a native value loses the calls on its instances from other files,
  `gsid.get()` on the launcher's `Observable`, 14 pairs on the game-engine tree. Accepted.
- A runtime method's call on a value still binds a namesake member of the caller's own file, as `plateObj.show()` binds
  `g_hud_live_stats.show` in its own file. Accepted.
- A TypeScript or JavaScript call on an instance of an imported class binds nothing where the value's name does not
  spell the class and the caller's class does not derive from it, `memoryCache.delete()` on a `new MemoryLimitedMap()`
  and `this.settings.save()`: about 1 in 9 of the pairs the narrowing unbinds in SillyTavern. Accepted.

## Rejected

- **The lists at the proximity steps alone** — leaves the same calls bound by the caller's file, the one callable and
  the includes: 78% of the sites the lists unbind on both trees (2026-10-17).
- **The TypeScript and JavaScript list without the DOM's methods** — keeps jQuery's methods named like the DOM's at the
  price of 1,338 more sites bound to a namesake, `document.body.appendChild()` among them (2026-10-17).
- **A near free function only where the caller's file includes its file** — unbinds the right calls nearness finds
  with the wrong ones, and lets the members near the caller take 20,482 more guesses (2026-10-17).
- **A member in either near directory before a free function** — unbinds 182 sites on both trees and leaves every
  runtime call with no member near it bound (2026-10-17).
- **The members in the caller's directory alone** — at most a sixth of the sampled sites right in any language
  (2026-10-19).
- **A guess tier for every runtime call** — keeps every one of these sites, shown as a guess.
- **The receiver's spelling at every step** — binds 39% of its sites right (2026-10-19).
- **The narrowed include tier for every language** — about two thirds of 30 sampled Python pairs it unbinds were right,
  calls on instances of an imported module's class (2026-10-23); Rust's `mod` files stay with #356.
- **The engine's every GUI-object method in Quirrel's list instead** — leaves the include tier binding `setValue` and
  `show`, which the list already names, and unbinds the scripts' own `isValid` and `isEmpty` with the engine's
  ([ADR 3.145](/design-docs/adr/3.145-quirrel-runtime-methods.md)): about half of 40
  sampled were right (2026-10-23).
- **Keep an included owner the caller's file names anywhere** — the files that call `g_hud_live_stats.show()` on a GUI
  object name the table too, so about a third of the 83 pairs it keeps are right (2026-10-23).
- **The narrowed include tier for an interface's and a type alias's members too** — unbinds 26 right pairs of 29 on
  the TypeScript trees, calls on the value a hook returns (2026-10-24).
- **Keep a TypeScript or JavaScript receiver an import of the owner's file binds** — no answer moves: such a receiver
  binds through its import before the include tier (2026-10-24).
- **Keep every named TypeScript or JavaScript receiver** — keeps 108 calls on the runtime's globals bound to a
  namesake, `JSON.parse()`, `console.log()` and `document.createElement()` (2026-10-24).
- **Narrow a class's members alone** — keeps 70 namesakes in minified libraries, `array.indexOf()` bound to an
  object's `indexOf` in `epub.min.js` (2026-10-24).

## Revisit if

A language's extraction records the type a value holds for its member calls, as Go's type paths and C++'s declared
locals do, so that the type rather than the name picks the member. High confidence that the name alone stays unsafe.
