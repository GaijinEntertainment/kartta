# Match gitignore rules with gix-ignore

- **Status:** accepted
- **Date:** 2026-08-11
- **Updated:** 2026-08-11
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fs/src/rules.rs`
- **Pinned by:** `crates/kartta-fs/tests/index.rs` (`a_root_gitignore_hides_matching_entries`,
  `a_nested_gitignore_applies_only_below_its_own_directory`,
  `an_ignored_directory_drops_its_whole_subtree_and_no_negation_reaches_inside`)

kartta owns the walk ([ADR 1.1](/design-docs/adr/1.1-filesystem-walk.md)) but not the gitignore dialect, which is a
compatibility surface with git. `kartta-fs` matches gitignore rules with `gix-ignore`, and accepts a dependency it
cannot reach inside.

## Decision

- `kartta-fs` matches gitignore rules with `gix-ignore`: one base-relative pattern list per `.gitignore` file, git's own
  `wildmatch`, and matching on the exact relative path.
- The lists form a stack, shallowest first, that lives in the walk's inherited policy state, so each directory adds its
  own `.gitignore` to the stack its parent handed it.

## Why

- A gitignore dialect that drifts from git's gives a silently wrong index rather than a crash, so the matcher comes from
  a crate that implements git's own `wildmatch`.
- `gix-ignore`'s lists are base-relative and match exact relative paths, so a stack of layers fits the walk's inherited
  state with no conversion.

## Consequences

- A matching defect is `gix-ignore`'s to fix, and kartta waits for its release; accepted.

## Rejected

- **Hand-roll the gitignore matcher** — the dialect is a compatibility surface with git, so a divergence is a silently
  wrong index rather than a crash.
- **Reuse part of an existing gitignore crate** — the obvious candidate keeps its compiled patterns private, so it is
  all or nothing.

## Revisit if

`gix-ignore` stops being maintained or diverges from git's matching. High confidence: it is part of gitoxide.
