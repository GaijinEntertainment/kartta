# Count the calls of a symbol's name that several definitions leave unbound

- **Status:** accepted
- **Date:** 2026-10-20
- **Updated:** 2026-10-20
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-mcp/src/render/calls.rs` (`caller_match`, `no_callers`, `reference_match`, `impact`,
  `seed`), `Walk::ambiguous`, the `find_callers`, `find_references`, `impact_of_edit` and `impact_of_change` tools
- **Pinned by:** `crates/kartta-mcp/tests/graph.rs`
  (`find_callers_counts_the_calls_of_a_shared_method_name_it_could_not_bind`,
  `find_callers_kept_to_one_role_still_counts_every_call_of_the_name_it_could_not_bind`,
  `find_references_counts_the_calls_find_callers_could_not_bind`,
  `the_impact_tools_count_the_calls_find_callers_could_not_bind`)

A call the cascade leaves ambiguous, because several definitions of its name may be meant, binds no caller, though it
may call any of them. Each answer about a symbol's callers counts those calls of its own name, and a symbol with no
caller says first that they may call it.

## Decision

- **What counts.** `ambiguous=` counts the calls of the root's own name that the cascade left ambiguous (ADR 3.24), made
  as a call of the root can be made: for a member, through a receiver; for a free definition, bare, or through a
  receiver where no member of the name is a call target; for a definition local to a body, none, since only a call in
  that body can mean it and it binds as a local call.
- **Whose count.** The count is the root's alone, so `hops` 1 and 3 give the same count, whatever `role` keeps.
- **The note.** A `find_callers` match with no caller and `ambiguous=` states that no call binds it, that those calls
  may, and that grep finds them; it then names, for a function, a method or a macro, an entry point, dead code or
  dynamic dispatch, and for another kind the uses `find_references` lists. Where the floor dropped callers, the count
  note of [ADR 4.13](/design-docs/adr/4.13-confidence-floor-notes.md) takes
  its place.
- **The other tools.** `find_references` adds the count to its `ambiguous=`, beside the uses of a member's name on a
  value whose type the graph could not follow, so both tools give one number. `impact_of_edit` carries it on a
  `<symbol>` and `impact_of_change` on a `<seed>`, beside a `callers=` and a reach that count none of those calls.
- **The number of definitions** those calls could reach is not answered. The C ABI carries the count as `ambiguous`
  (ADR 4.2).

## Why

- On this repository `CancelToken::cancel` answered "no callers" against 17 calls of `cancel` the graph left unbound,
  `token.cancel()` among them, on values whose type the Rust graph does not follow (2026-10-20).
- Each of these queries already resolves every call of the root's name and records each one that binds nothing; the
  count is two counters on that record.
- The count says that calls may reach the symbol, not which: of 40 replaced verdicts read by hand, 9 had a real caller
  among the counted calls, and the rest were generic names whose calls mostly reach other types or arrive by dynamic
  dispatch, which the note keeps naming.
- The engine holds no count of the definitions an ambiguous call could reach: the cascade leaves a call ambiguous when
  the definitions its shape admits are not one callable and nearness picks none, and neither counts nor keeps them.

## Consequences

- A bare call left ambiguous where the language looks a member up first counts for no member. Accepted.
- A call bound by proximity to another definition of the name counts as that definition's caller, not here. Accepted.
- `ambiguous=` does not say whether the calls split between two definitions or two hundred; `Module::init` counts 39,273
  calls on the C++ game-engine tree. Accepted.

## Rejected

- **Every unbound call of the name, whatever the miss** — a call into an external import, an undefined name or a
  receiver whose type has no such method cannot reach a definition the graph holds.
- **Checking each ambiguous call against the root's own shape** — exact, but a second resolution of those calls in
  every query; the forms above follow the shape the cascade gives each form.
- **A count summed over every symbol the walk expands**, as `find_callees` sums `unresolved=` — an answer at 3 hops is
  then dominated by the names of the callers in between, and differs from the 1-hop answer.
- **A note naming only the ambiguous calls** — drops the dynamic-dispatch reading, which holds for most generic names.
- **Counting the definitions of the root's name of its kind** — costs nothing measurable, but it is another number: on
  the 50 of 787 sampled roots where it differs from the exact count, it is over in 45, up to 33 times (2026-10-20).
- **The exact number of definitions the counted calls admit** — each answer pays for it and each walk holds it: at
  best, a set per name built once per shape, 2.9% slower walks and 8.8% more heap on the C++ game-engine tree
  (2026-10-20).

## Revisit if

An agent's next call depends on how many definitions split the ambiguous calls; then weigh the exact count's time and
heap against the cheap count under a name that says what it counts.
