The operand of a C++ `.` or `->` is a value, and a value's name names no type. Where the walk sees the operand
declared, it records the class the declaration spells as the call's receiver, a field the class it is declared as, and
a type alias the class it names, for the graph to bind; elsewhere it records no class, at the price of the calls a type
the walk does not see would bind.

## Decision

- **What the walk records for a call.**
  - **A declared operand.** A member call on a local or a parameter declared as a value of a class or a reference to
    it, for `.`, or as a pointer to it, for `->`, records that class as its receiver, spelled with the scopes and the
    template arguments the declaration writes, `b::Widget`, `::b::Widget` or `ns::Box<int>`, as `owner_spelled` in
    [`walk/sites.rs`](/crates/kartta-lang-cpp/src/walk/sites.rs) spells it. A class specialization records its head,
    `template <> struct Box<bool>`, as its signature, which tells it from its primary template under their one
    qualified name. A field's value type is spelled without the template arguments, so a call through a field names no
    specialization.
  - **A call on `this`.** It records the bare name of the caller's own class; outside a member it keeps `this`.
  - **A name the body does not declare.** In a member, a call on a name that no local, parameter or enclosing template
    parameter of the body declares, or on `this->name`, records `.name` or `->name`, with the operator that takes the
    member called, so `this->lock.unlockRead()` records `.lock`: the class body usually lives in another file, so the
    walk cannot tell a field from a namespace's value. A call on an element of such a name records a `[]` after it,
    `locks[i].unlockRead()` as `.locks[]`. How the graph binds it through the field's class is
    [ADR 3.47](/design-docs/adr/3.47-cpp-field-calls.md)'s.
  - **Any other operand.** A member call on it records the empty receiver, an element of a local or of a parameter
    among them, since the class it is declared as is not the element's where a template's `operator[]` hands it back.
  - **No call through a value.** A bare call of a name a local, a parameter or a capture of the body declares, or of a
    parameter of an enclosing template, is not recorded: it calls through the value it holds, a function pointer, a
    lambda or a callable object. No `find_callees` answer counts it as unresolved. A `new` of an enclosing template's
    parameter is not recorded either, and such a parameter, `: public Compare`, is no base of a class.
  - **A base initializer.** A name in a constructor's initializer list records a bare call of its bare name where the
    class around the constructor lists a base of that name, or where it spells a scope or a template's arguments,
    `ns::B(x)` or `B<int>(x)`, which no field takes. It carries no receiver and no method mark, so it binds the base's
    constructor, else the class or the alias the base names, as `B(1)` does. A name that names a base and a field
    records the call beside the field's write, and any other bare name records the write alone
    ([ADR 3.64](/design-docs/adr/3.64-cpp-data-sites.md)). A name of the caller's own class records its constructor in
    full where it spells a scope, `a::B::B` for `B(int x) : a::B(x)`, which a bare call of `B` would bind to the caller,
    and no call elsewhere, and neither does a parameter of an enclosing template. A constructor defined outside its
    class body has no class at hand, so its bare names record the write alone.
- **What the walk records for a field.** A field of a class type, or a reference to one, records that class as its
  value type, spelled as a receiver spells it, after a `*` for each pointer and each array dimension, as C++ reads an
  array: `Obj *objs[4]` records `**Obj`. A field of a class template records too, one `*` further, the class its first
  template argument names, which `operator->` reaches on `eastl::unique_ptr<Effect>` and a sequence's `operator[]` on
  `Tab<Effect>`, and two `*` further for an argument written as a pointer, `Tab<Effect *>`. A type behind more than two
  pointers is left out, since a call goes through `->` and one `[]` at most.
  `field_value_types` in [`walk/data.rs`](/crates/kartta-lang-cpp/src/walk/data.rs) lists the fields that record none.
  A field that a `#if` or an `#ifdef` holds in its class body is a field of that class.
- **What the walk records for a type alias.** A `typedef` or a `using` alias of a class records that class as its
  value type, spelled as a receiver spells it: `List` for `typedef List<Node> NodeList`, `::ns::Lock` for
  `using Alias = ::ns::Lock`, `Base::iterator` for `typedef typename Base::iterator base_iterator`. `push_type_alias`
  and `aliased_class` in [`walk.rs`](/crates/kartta-lang-cpp/src/walk.rs) list the aliases that record none, a scope
  after template arguments, `std::vector<Node>::iterator`, among them.
- **How the graph binds a declared class.** Through the aliases its spelling names, the class nearest the caller's
  file and the namesake the receiver's scopes name, it is
  [ADR 3.180](/design-docs/adr/3.180-cpp-declared-class-calls.md)'s, and through the class's bases
  [ADR 3.188](/design-docs/adr/3.188-cpp-inherited-member-calls.md)'s.

## Why

- In a member, `lock.unlockRead()` most often calls a member of the class a field of the caller's class is declared as.
- A call through a value bound any definition of that name in the tree: the SPIR-V node visitors bound libtorrent's
  `struct visitor`; of the pairs that left with the rule, 40 of 40 sampled were such calls (2026-10-23, #394).
- A template parameter names what the instantiation supplies, so `Compare()` in a template over `Compare` calls no
  definition of that name: 6 of 6 sampled such pairs were wrong (2026-10-17, #67).
- A base's constructor runs in every constructor of the class that names it, so reading the name as a write left
  `find_callers` of the constructor blind to its derived classes: the rule adds 6,467 pairs and removes none on the
  game-engine tree, 30 of 30 sampled right (2026-10-31, #418).
- An initializer of the caller's own name bound the caller: 59 pairs, 50 of them a specialization of `das_iterator`
  deriving another one and bound to itself on its own line (2026-10-31, #418).

## Consequences

- A constructor defined outside its class body binds no bare base: 2,004 of the game-engine tree's 9,079 base
  initializers, read against every class's bases (2026-10-31, follow-up of #418).
- A scoped base of the caller's own name that lies outside the graph binds the caller or a constructor beside it, as
  `tcp(...) : sim::asio::ip::tcp(p)` does: 10 of the game-engine tree's 33 such pairs (2026-10-31). Accepted.
- A delegating constructor, `D() : D(0) {}`, calls nothing in the graph: 539 bare initializers on the game-engine tree
  (2026-10-31, follow-up of #418).
- A name that names a base and a field records a call C++ does not make, since the field hides the base. No class of
  the game-engine tree holds one (2026-10-31). Accepted.
- The rule adds 7,075 calls to the extraction of the game-engine tree's 2,871,705, in 2,101 files, one `CallRef`
  each, of which 6,467 bind; a build retires the same instructions within 0.1% (2026-10-31, #418).
- A call through an alias of a scope after template arguments, `It i; i->f();` with
  `typedef std::vector<T>::iterator It`, stays ambiguous among the namesake iterators and binds none, `T::f` included.
  Accepted.
- An alias's class adds 31,867 value types, 0.59 MB of spelling, to the extraction of the game-engine tree
  (2026-10-24, #378).
- A call through a local that the grammar misreads drops a true call: `debug("[submit]")` after `VERBOSE
  debug(...)`, and a call through a block-scope `extern` function pointer (#420).
- The spelled scopes add 7,545 strings and 0.25 MB to the graph's arena on the game-engine tree, with the field uses of
  [ADR 3.64](/design-docs/adr/3.64-cpp-data-sites.md) (2026-10-22, #176, #180).

## Rejected

- **Record the operand's name as its type** — 3,090 calls bound by coincidence to a type the name spelled,
  `buffer.resize()` to libtorrent's `buffer::resize`, and more to a member of the caller's class, 5 of 20 sampled right
  (#47).
- **Keep the scopes past a scope's template arguments, `Outer::Inner` for `Outer<int>::Inner`** — respelled 1,607
  receivers to bind 5 calls; such a spelling more often names an alias or a class a macro builds (#176, #180).
- **Prefix the receiver with the walk's own namespace** — rebound 1,135 calls and misread a spelling a scope around the
  walk's namespace holds (#176, #180).
- **Record a call through a value as a call of a local symbol made for it** — adds 5,829 variable symbols the graph
  lists as roots, keeps the site counted, and loses pairs to the shifted symbol order (#394).
- **Read the classes of the caller's own file's fields during the walk** — binds 52 sites the graph's lookup does not,
  each a field whose declaration the grammar does not parse, and nothing in a file that includes its class (#173).

## Revisit if

A sample shows calls on operands the walk does not see declared, `auto` locals and expressions, binding wrongly often
enough to want a type for them, which needs the walk to type expressions. Medium confidence that it does not.
