# Name a C++ call's receiver by the class its operand is declared as

- **Date:** 2026-10-16
- **Updated:** 2026-10-24

  `a_member_call_on_an_operand_the_walk_saw_no_class_for_names_no_type`,

The operand of a C++ `.` or `->` is a value, and a value's name names no type. Where the walk sees the operand
declared, it records the class the declaration spells as the call's receiver, a field the class it is declared as, and
a type alias the class it names, for the graph to bind; elsewhere it records no class, at the price of the calls a type
the walk does not see would bind.

## Decision

**What the walk records for a call.**

1. A member call on a local or a parameter declared as a value of a class or a reference to it, for `.`, or as a
   pointer to it, for `->`, records that class as its receiver, spelled with the scopes and the template arguments the
   declaration writes, `b::Widget`, `::b::Widget` or `ns::Box<int>`, and by its bare name where the spelling holds a
   space outside its template arguments. A class specialization records its head, `template <> struct Box<bool>`, as
   its signature, which tells it from its primary template under their one qualified name. A field's value type is
   spelled without the template arguments, since a list of value types joined at a comma cannot hold them, so a call
   through a field names no specialization.
2. A call on `this` records the bare name of the caller's own class; outside a member it keeps `this`.
3. In a member, a call on a name that no local, parameter or enclosing template parameter of the body declares, or on
   `this->name`, records `.name` or `->name`, with the operator that takes the member called, so
   `this->lock.unlockRead()` records `.lock`: the class body usually lives in
   another file, so the walk cannot tell a field from a namespace's value. How the graph binds it through the field's
   class is [ADR 3.47](/design-docs/adr/3.47-cpp-field-calls.md)'s.
4. A member call on any other operand records the empty receiver.
5. A bare call of a name a local, a parameter or a capture of the body declares, or of a parameter of an enclosing
   template, is not recorded: it calls through the value it holds, a function pointer, a lambda or a callable object.
   No `find_callees` answer counts it as unresolved. A `new` of an enclosing template's parameter is not recorded
   either, and such a parameter, `: public Compare`, is no base of a class.

**What the walk records for a field.** A field of a class type, or a reference or a pointer to one, records that class
as its value type, spelled as a receiver spells it, after a `*` for a pointer. A field of a class template records too,
after a `*`, the class its first template argument names, which `operator->` reaches on `eastl::unique_ptr<Effect>`. A
field of a builtin type, of a template parameter, an array or a pointer to a pointer records none. A field that a `#if`
or an `#ifdef` holds in its class body is a field of that class.

**What the walk records for a type alias.** A `typedef` or a `using` alias of a class records that class as its value
type, spelled as a receiver spells it: `List` for `typedef List<Node> NodeList`, `::ns::Lock` for
`using Alias = ::ns::Lock`, `Base::iterator` for `typedef typename Base::iterator base_iterator`. An alias of a pointer
or a reference, of a builtin or an unnamed type, of a template parameter or a scope of one, `typename T::iterator`, or
of a scope after template arguments, `std::vector<Node>::iterator`, records none.

**How the graph binds a declared class,** through the aliases its spelling names, the class nearest the caller's file,
the namesake the receiver's scopes name and the class's bases, is
[ADR 3.180](/design-docs/adr/3.180-cpp-declared-class-calls.md)'s.

## Why

- In a member, `lock.unlockRead()` most often calls a member of the class a field of the caller's class is declared as.
- A call through a value bound any definition of that name in the tree: the SPIR-V node visitors bound libtorrent's
  `struct visitor`; of the pairs that left with the rule, 40 of 40 sampled were such calls (2026-10-23).
- A template parameter names what the instantiation supplies, so `Compare()` in a template over `Compare` calls no
  definition of that name: 6 of 6 sampled such pairs were wrong (2026-10-17).

## Consequences

- An array field's element is not read (#478).
- A call through an alias of a scope after template arguments, `It i; i->f();` with
  `typedef std::vector<T>::iterator It`, stays ambiguous among the namesake iterators and binds none, `T::f` included.
  Accepted.
- An alias's class adds 31,867 value types, 0.59 MB of spelling, to the extraction of the game-engine tree
  (2026-10-24).
- A call through a local that the grammar misreads drops a true call: `debug("[submit]")` after `VERBOSE
  debug(...)`, and a call through a block-scope `extern` function pointer (#420).
- The spelled scopes add 7,545 strings and 0.25 MB to the graph's arena on the game-engine tree, with the field uses of
  [ADR 3.64](/design-docs/adr/3.64-cpp-data-sites.md) (2026-10-22).

## Rejected

- **Record the operand's name as its type** — 3,090 calls bound by coincidence to a type the name spelled,
  `buffer.resize()` to libtorrent's `buffer::resize`, and more to a member of the caller's class, 5 of 20 sampled right.
- **Keep the scopes past a scope's template arguments, `Outer::Inner` for `Outer<int>::Inner`** — respelled 1,607
  receivers to bind 5 calls; such a spelling more often names an alias or a class a macro builds.
- **Prefix the receiver with the walk's own namespace** — rebound 1,135 calls and misread a spelling a scope around the
  walk's namespace holds.
- **Record a call through a value as a call of a local symbol made for it** — adds 5,829 variable symbols the graph
  lists as roots, keeps the site counted, and loses pairs to the shifted symbol order.
- **Read the classes of the caller's own file's fields during the walk** — binds 52 sites the graph's lookup does not,
  each a field whose declaration the grammar does not parse, and nothing in a file that includes its class.

## Revisit if

A sample shows calls on operands the walk does not see declared, `auto` locals and expressions, binding wrongly often
enough to want a type for them, which needs the walk to type expressions. Medium confidence that it does not.
