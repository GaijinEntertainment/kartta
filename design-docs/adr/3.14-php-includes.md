# Fold a PHP include path, map a use through PSR-4, and read a class name through the file's uses

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-php/src/fold.rs`, `crates/kartta-lang-php/src/resolve.rs`,
  `crates/kartta-lang-php/src/psr4.rs`, `crates/kartta-lang-php/src/walk.rs` (`include`, `namespace_use`, `class_name`,
  `aliased_class`, `object_creation`, `class_constant_scope`), `crates/kartta-graph/src/resolve.rs`
  (`constructs_a_class_written_from_the_root`), `kartta_lang::Conventions::constructor`
- **Pinned by:** `crates/kartta-lang-php/tests/php.rs` (the `include`, `dirname`, path and `use` tests),
  `crates/kartta-lang-php/tests/parent_names.rs`, `crates/kartta-languages/tests/php_use_names.rs`,
  `crates/kartta-languages/tests/php_static_aliases.rs`, `crates/kartta-languages/tests/php_new_aliases.rs`

PHP names a dependency by a path that legacy code builds for `include` or `require`, or by a `use` that Composer's
autoloader maps through the PSR-4 map of a `composer.json`. The extraction folds an include path to a constant with the
file's own path left as a marker, so a cache can share it between files of the same bytes, and the resolver maps a
`use` to the file PSR-4 names; a path built at run time, and any other autoload form, includes nothing. A `use` also
binds a name, so the extraction writes a parent, a call on an alias and a construction of one as the class PHP compiles
the name to, which the graph reads exactly.

## Decision

- **An include path folds to a constant.** A string, `__DIR__`, `__FILE__`, a `.` concatenation of those, a
  parenthesized one and `dirname` of one fold to a path. Any other operand, a variable, an interpolated string or a call
  of another function, folds to nothing, and the include adds nothing. `__DIR__` and `__FILE__` fold to markers that the
  resolver substitutes with the file's directory and path. A literal that holds the marker byte folds to nothing, so a
  substitution cannot make a path that the source did not write.
- **A path constant names a file only at the start of the path.** `__DIR__` and `__FILE__` are absolute at run time, so
  `'inc/' . __DIR__` names no file, and the extraction drops it.
- **`dirname` is lexical, as in PHP.** It removes the trailing separators and cuts at the last `/` as written, without
  applying `.` and `..`. The fold cuts the path itself where that `/` follows the last marker. Where the cut would fall
  inside a marker, `dirname(__DIR__)`, the fold adds a climb marker, which the resolver writes as `/..` and applies
  against the real path. A later `dirname` strips a written `..` but composes with a climb: `dirname(__DIR__ . '/..')`
  is the file's directory, and `dirname(dirname(__DIR__))` is two levels up. `dirname(__FILE__)` is `__DIR__`.
  `dirname(__DIR__)` in a file at the root names the parent of the checkout, and includes nothing. A `levels` argument,
  by position or by name, applies `dirname` that many times, so `dirname(__DIR__, 2)` is `dirname(dirname(__DIR__))`;
  a `levels` other than a decimal integer literal from 1 to 255 folds to nothing.
- **`dirname` is written `dirname` or `\dirname`, in any letter case.** Both fold alike, inside a namespace too. Any
  other qualified name, `\Foo\dirname`, `Foo\dirname` or `namespace\dirname`, folds to nothing.
- **`__DIR__` and `__FILE__` fold in any letter case; a named argument matches exactly.** `__dir__` is `__DIR__`, and
  `dirname(PATH: __DIR__)` folds to nothing.
- **A folded path resolves from where PHP would find it first.** A `./` or `../` path and a path under the file's own
  directory resolve from that directory. Any other path resolves from the root, or else to the one file of the
  repository whose path ends in it. Two such files resolve to nothing.
- **A `use` maps through the PSR-4 map of the project's `composer.json` files.** The resolver reads every
  `composer.json` outside a `vendor` or `node_modules` directory, and takes the `psr-4` mappings of `autoload` and
  `autoload-dev`, with their directories relative to that `composer.json`. A longer prefix maps first, a prefix with
  several directories tries them in the order written, and the empty prefix, Composer's fallback, maps any name after
  every other prefix. A name maps to its remaining segments under the prefix's directory, `App\Models\User` to
  `src/Models/User.php`. The name of a `use function` or a `use const` that maps to no file maps once more without its
  last segment, since a function or a constant lives in the file of its namespace. A class name maps only to its own
  file. A grouped `use App\{Foo, Bar}` resolves each name with the shared prefix, and each clause of a mixed group by
  its own kind.
- **A mapped `use` is an include, and any other `use` an import.** A `use` that maps to a file of the repository is an
  include of that file. A `use` of a vendored package or of an extension maps to nothing, and stays an import as
  written.
- **A parent is the class PHP compiles it to.** The walk writes each name in `extends`, `implements` and a class-body
  `use` in full: a name from the root as it stands, `namespace\X` under the namespace alone, any other name through the
  class `use`s the walk has passed since the last `namespace` declaration, by its first segment and in any case, else
  under the namespace. `ParentSpelling::FromRoot` then has the graph read the name exactly
  ([ADR 3.20](/design-docs/adr/3.20-implementor-resolution.md)). A `use function` or a `use const` imports no class.
- **A call on an alias names the class.** The walk writes a static call on a name a `use ... as` binds in that namespace
  under the class's name from the root, `\App\Model`, as it does a qualified scope
  ([ADR 3.155](/design-docs/adr/3.155-php-member-owners.md)), which the graph reads as the type of exactly that name
  ([ADR 3.193](/design-docs/adr/3.193-receiver-class-members.md)), since an outside class's last name or its alias can
  be a class of the tree: `use Faker\Factory as FakerFactory`.
- **A construction of an alias runs the class's constructor.** `new C` after `use A\B as C` calls
  `Conventions::constructor`, `__construct`, on `\A\B`, which binds what that class's table holds, the constructor it
  inherits included, at 85. A call of that name on a class written from the root ends there, so a class whose table
  holds none binds nothing, and an outside class binds nothing as any such call does.
- **A callable on an alias reads the class.** `[C::class, 'm']` is a use of `m` of `B`, the last name of the class the
  alias imports, which owns a member as a name written `[B::class, 'm']` does
  ([ADR 3.155](/design-docs/adr/3.155-php-member-owners.md)).
- **Members and anonymous classes.** How a member and its calls are named is
  [ADR 3.155](/design-docs/adr/3.155-php-member-owners.md), and the name of an anonymous class is
  [ADR 3.156](/design-docs/adr/3.156-php-anonymous-classes.md).

## Why

- The extraction sees only a file's bytes, and a cache shares that result between every file with the same bytes, so
  it cannot know the path that `__DIR__` names; the resolver, which knows the path, substitutes it.
- Folding covers the legacy code: on WordPress, 188 of the 189 includes and requires that fold resolve (2026-10-16,
  #36).
- Composer code names most dependencies by `use`: on Laravel, 3,508 of 5,465 uses map to a file (2026-10-16, #36).
- A path marker after a literal would put a relative directory in the middle of a path, and could reach a file that
  PHP never opens.
- Two files whose paths end in the same path give a guess between them, and a wrong guess is a wrong edge.
- The file of a class's namespace is a different class's file, so mapping a class name once more would add a wrong
  edge.
- PHP resolves `\dirname` to the global function in any namespace, and an unqualified `dirname` falls back to it at run
  time; `Foo\dirname` always lands in a namespace, and the global function is what the fold models (`zend_compile.c`,
  `zend_resolve_non_class_name`, php-8.5.12). On Symfony, `\dirname` adds 8 includes, all 8 right (2026-11-01, #686).
- PHP lowers a function's name before its lookup (`zend_compile.c:5196`) and builds its scanner with `--case-inverted`
  (`Zend/Makefile.frag:9`), so a magic constant matches in any case, while `zend_get_arg_offset_by_name` compares a
  named argument exactly (`zend_execute.c:5497`, php-8.5.12). Neither PHP tree writes another case (2026-11-01, #841).
- PHP resolves a class name at compile time through the file's imports, which each `namespace` declaration resets
  (`zend_resolve_class_name`, `zend_compile_use` and `zend_compile_namespace` in php-src 8.5.12 `Zend/zend_compile.c`;
  php-langspec `spec/18-namespaces.md`, Namespace Use Declarations), so the file alone settles what a parent names.
- Reading the written name by its last segment bound 12,033 implementor pairs PHP does not hold on Laravel and Symfony,
  30 of 30 sampled wrong: `extends TestCase` under `use PHPUnit\Framework\TestCase` listed under every `TestCase` the
  tree defines (2026-11-01, #524).
- `new` compiles to `ZEND_NEW` on the class the imports give, and `ZEND_NEW` runs that class's `ce->constructor` or
  nothing (`zend_compile_new`, `Zend/zend_vm_def.h:5977`, `zend_std_get_constructor`, php-8.5.12), so no other class's
  constructor can run. On Laravel and Symfony the rule adds 510 pairs at 85, all 510 read right against each file's
  `use` map and the class chain, and removes 7 namesakes, all right (2026-11-01, #861).

## Consequences

- An include built from a variable, a constant such as `ABSPATH`, or a call other than `dirname` adds nothing.
  Accepted.
- A name that only PSR-0, `classmap` or `files` autoload maps stays an import. Accepted.
- A `dirname` whose `levels` is a variable, a constant or an expression leaves its include unresolved rather than
  naming a guessed directory (#500). Accepted.
- `namespace\dirname` outside a namespace is the global function, and folds to nothing: the fold reads no namespace, and
  neither PHP tree writes it. Accepted.
- A plain `dirname` folds as the global function even where a `use function` or the file's namespace supplies another
  one; neither PHP tree does. `\dirname` has no such case. Accepted.
- PHP reads a class name in any case and the graph reads a parent's exact spelling, so a parent written in another case
  than its class names no type. Accepted.
- A `new` of any name no `use ... as` binds still calls the class by its last name, which binds the type and no
  constructor ([ADR 3.155](/design-docs/adr/3.155-php-member-owners.md)), so a class's constructions split between the
  type and its constructor. Accepted.
- A class of no constructor of its own or above it shows no construction through an alias. Accepted.
- A callable on an alias reads the class's last name, so an outside class binds a member of a namesake the file itself
  reaches. Neither PHP tree holds one (2026-11-01, #861). Accepted.

## Rejected

- **An import for every `use`, also one that maps** — states one dependency twice, and keeps an import for a module
  that names no repository file.
- **Fold `__DIR__` to the path at extraction** — the result then depends on the path, and the cache could not share it
  between files with the same bytes.
- **The name tiers for a class that holds no constructor** — 43 of the 553 pairs that reading added bound another
  class's constructor.
- **`dirname` as a climb every time** — a climb applies `..` where PHP's `dirname` strips it, so an include with a
  written `..` resolves one level too high.

## Revisit if

The extraction reads the PSR-0, `classmap` or `files` autoload of a `composer.json`, or the constants, such as
`ABSPATH`, that a project defines for its include paths. Not planned.
