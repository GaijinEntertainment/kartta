# Name no type for a TypeScript or JavaScript call on a value the file declares

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-jsts/src/walk.rs` (`Binding`, `Declared`, `declare_*`),
  `crates/kartta-lang-jsts/src/walk/calls.rs` (`value_receiver`, `this_class`)
- **Pinned by:** `crates/kartta-lang-jsts/src/tests/extraction.rs`

A TypeScript or JavaScript call `x.f()` spells its receiver by a name, and the name of a value says nothing of the type
the value holds. The `jsts` walk ([ADR 3.4](./3.4-extract-typescript-and-javascript-as-one-family.md)) records the
empty receiver for a value the file declares and keeps the name of a type, at the cost of a miss wherever it cannot
tell the two apart in one read.

## Decision

1. A call `x.f()` records `x` as its receiver unless the file declares `x` as a value in a scope that is open at the
   call: a parameter, a `let`, `const` or `var`, a destructured name, a catch binding, a loop variable, a function
   declared inside a function body, or the name of a function expression inside its own body. Such a call records the
   empty receiver, which [ADR 3.7](./3.7-resolve-calls-when-a-query-asks.md) resolves as a value of no known type. A
   capitalised JSX tag and a `new` expression written through such a name, `<x.Item>` or `new x.Pool()`, do the same;
   one written as a bare name, `<Item>` or `new Pool()`, records no receiver.
2. An import binding, a class, a namespace, a class declared in a nearer scope, a `const` bound to a class expression
   and a function at module or namespace level keep their name.
3. A call on `this` records the class around the method. In a class body outside every method it records the class
   itself, which is an instance in a field's initializer and the class in a static one. An arrow keeps the `this` of
   the scope it is written in; a function expression or a function outside a class gives a `this` of no known type,
   which records the empty receiver.
4. The walk reads the file once. It holds each declared name while the function, block, catch clause, loop or `switch`
   that declares it is open, and restores the name it shadowed when it closes. A name declared below its first use, a
   module-level `const` under the function that calls it, therefore keeps its name, and a `var` is held to its block,
   so a call after the block keeps the name too.

## Why

- An owner is a class, an interface or a namespace, so a value's name names no type, and the empty receiver keeps the
  graph from binding it as one.
- A function at module or namespace level keeps its name because TypeScript merges it with a namespace of that name,
  and a class bound to a `const` is a type whose static members a call on the name reaches.
- `this` in a class body is the class's own instance or the class, so `run: () => this.apply()` in a field binds the
  class's method.
- Holding names to the scope that declares them makes every error of the one read a miss, never a wrong empty
  receiver.

## Consequences

- A name declared below its first use, and a `var` used after its block, keep their name as a receiver, so the call can
  bind an owner of that name. Accepted.
- An empty receiver on a typed parameter can bind a same-file member of the name (#475), and a parameter typed only by
  its context has no type at all (#319).

## Rejected

- **A value's name as an owner** — bound 220 calls on the TypeScript and JavaScript of the game-engine tree, mostly in
  minified bundles where a one-letter variable shares a one-letter class name (2026-10-16).
- **`this` of no known type in a class body** — loses 23 sites on SillyTavern, every one right, such as
  `this.favFilter.bind(this)` (2026-10-23).

## Revisit if

The walk learns the type a value's declaration spells for its calls, as it does for its data sites
([ADR 3.34](./3.34-record-each-read-and-write-of-a-field-or-a-value.md)) (#475, #319). Nothing plans it yet.
