# Repair what the C++ grammar cannot parse instead of vendoring it

- **Status:** accepted
- **Date:** 2026-10-16
- **Revised:** 2026-10-23
- **Initiative:** `03-code-graph`

`kartta-lang-cpp` extracts C and C++ through `tree-sitter-cpp` 0.23.4, which is both the pinned version and the latest
release. Real C++ is full of what the grammar cannot reduce — function-like macros where a declaration belongs,
annotation macros after a declarator, compiler extensions — and tree-sitter's error recovery does not always stay local:
an error can consume the declarations after it to the end of the file. A gap is worth closing only when it costs
symbols, so each decision below is measured in symbols, on the C++ code base this was built against: 17,408 first-party
files, where 30.31% of the files carry at least one parse error.

**The parser reads a repaired copy; the walk reads the original bytes.** A repair rewrites the copy without changing its
length, so every node position still addresses the original, and every name, signature and text is taken from the
original. No repaired byte can reach a symbol, a call or a snippet, which is what makes a byte-level repair safe: it
fires inside comments and string literals too, over a thousand such sites against the files whose extraction changes,
and there it is inert.

**An empty trailing call argument is repaired before the first parse.** `CHECK(ptr, )` — a void `return` spelled as a
macro argument — has no production in the grammar, so the statement fails and takes the enclosing function's
declaration with it, and recovery does not resync: one such line cost a file the 50 symbols after it. Blanking the comma
turns `f(x, )` into the equivalent `f(x )` and invents no token. 97% of the files have nothing to repair, and for them
the scan allocates nothing. The repair gains 515 symbols in 29 files, another 184 symbols gain the class owner or
namespace prefix that exists only once their file parses, and 143 phantom calls are gone, where the shredded parse read
`if`, `for` and `return` as callees. That is the whole gain deleting the construct outright buys: filling the slot is
enough for the enclosing declaration to reduce, so nothing has to be mined out of the error.

**A function-like macro in declaration position is repaired after the first parse, and only where the error spilled.**
`DECL_REPLICATION(Wrap, Unit)` in a class body, an annotation macro alone on its line, an argument-less field block: an
identical line in a file that parses is ordinary, so only the first tree's error spans show which ones cost something.
Where an error spans three rows or more past its first — a macro invocation is one to three rows, so a shorter error
consumed the construct and nothing else — the upper-case invocation that opens each of its lines is blanked, not the
whole line, which would take the declaration a macro annotates with it, and the file is parsed again. The spill gate
cuts the re-parses from 855 files to 163 and keeps 88% of the recovered symbols. Those 163 files gain 878 symbols, 740
of them members that find the owner which exists only once their class parses — one header alone moves 489 methods out
of being unowned free functions — and 117 genuinely new. The price is 621 calls, the blanked invocations and the real
calls nested in their arguments, 123 of which name something defined elsewhere, and a handful of macro names that were
phantom symbols. Two imprecisions are deliberate and measured: an enum's last enumerator alone on a line reads as an
argument-less macro and is blanked, which is inert because no enumerator symbol is emitted, while requiring an argument
list costs 62 symbols and doubles the losses; and a `#define` body is never blanked, because blanking a continuation
line rewrites the macro and the declarations around it pay. Both repairs together take the code base from 346,651
symbols to 347,099. A re-parse that fails keeps the first tree: the repair is an improvement, never a precondition.

**A restrict qualifier on a reference parameter stays unparsed.** `const Event &__restrict evt`, which generated ECS
code emits, does not parse: the grammar takes the three restrict spellings after `*` and none after `&`. It is a GCC
and MSVC extension, not standard C++, and there is no newer release to take. Patching the four reference-declarator
rules lowers the share of files with an error from 30.31% to 28.48% — 318 files, none newly failing. Blanking the
qualifier through the repair mechanism reaches the same parse in the same 318 files and recovers one symbol, with no
call changed, because the errors it removes were already local: the reference parameter fails to reduce, the
declarations around it do not. Even at no cost the gap would not be worth closing, and closing it costs vendoring the C
grammar that the C++ grammar's source requires as well, and a re-application of the patch on every update.

**The claimed extensions are measured, not assumed.** `.hh` files are plain C++ headers (1,968 symbols per MB, 1.5%
phantom symbols), and `.inc` fragments parse better than the classic set (27% of the files with an error against
30.7%, 3,112 symbols per MB), so both are claimed. Objective-C++ `.mm` and `.m` (72% and 90% of the files with an
error, 990 and 95 symbols per MB) and CUDA `.cu` and `.cuh` (96% and 100%, under 300 symbols per MB) measured
net-negative and are not claimed; in Objective-C++ the Objective-C syntax islands defeat the C++ grammar. Each is to be
measured again before it is claimed.

**Names are qualified the way the graph can match them.** A symbol outside every class takes the enclosing named
namespaces, so a qualified call `d3d::clearview()` matches its qualified name and a bare call still matches its bare
one. A member keeps `Class::member` without the namespace, because the graph's match of a call on `this` to the caller's
own class and its lookup of a trailing `Owner::name` pair depend on that form. No namespace symbol is emitted: every
file that reopens `namespace ns` would add a duplicate of it, and the prefix on what it holds carries the namespace
already. A callee written with a named scope keeps the scope: reducing `Class::m()` to `m` was tried and rejected,
because a short name then binds to another class's method of that name in the same file — a wrong edge, worse than a
missing one. For the same reason an `#include` not written relative to its file, that no file's path spells exactly,
and that two files' paths end in, resolves to the one whose root holds the including file, the deepest if the roots
nest, as a vendored copy of a library includes its own headers, else to the one whose directory shares the most
leading directories with the including file's, and to neither where two share as many or a bare name in angle
brackets spells a system header (the revision of 2026-10-23 below); every include probe matches letter case, because
a build on a case-sensitive file system finds no file whose path differs from the specifier only in case.

**A member call's operand names no type.** The operand of `.` or `->` is a value, so a member call on a named operand
records the empty receiver, as one on any other expression does, and only `this` names an owner, the caller's own.
Recorded by name, the operand bound calls by coincidence on the game-engine tree of 43,356 C++ files: 3,090 at the
receiver tier to a type the name happened to spell, `buffer.resize()` to libtorrent's `buffer::resize`, and more at 80
to a member of the caller's own class whatever the operand held, 5 of 20 sampled right. With the empty receiver the
receiver tier binds no C++ call, 10,436 fewer calls bind at 80 and 11,830 more bind nothing. The callers of 337 sampled
names against the reference extraction are unchanged, and 18 calls of those names that a same-named type had taken, of
`begin`, `end`, `clear` and `data` among them, bind through the includes again.

**Revised 2026-10-19: a member call names the class its operand is declared as.** Where the walk sees the operand
declared, a local or a parameter of a class, a reference to it for `.` or a pointer to it for `->`, the call records
the class's bare name, as a use of the operand already did, and a call on `this` records the caller's own class, as a
TypeScript call on `this` does. A class's name alone does not say which class: `vector` names EASTL's and a vendored
PhysX one, `Unit` the game's and `xray::Unit`, and a typedef names none. The graph binds the member of the class of that
name nearest the caller's file through its includes, its own file first, then the files it includes, then the rest of
their closure, where a namesake in another namespace comes in deeper, and resolves the call as one on a value where the
file reaches none. On the game-engine tree, against the extraction before it, 73,589 calls that bound nothing bind a
member at the receiver tier, 39 of 40 sampled right; 11,905 move to another member of the name, 37 of 40 sampled right
and most of them away from a namesake class; 134,046 keep their member and rise to the receiver tier; and 135 bind
nothing, about half of them a wrong copy of a vendored library. The rest call a member the class inherits, `this->f()`
in a template over a dependent base, or a class the file meets only through the header that includes it, which the
lookup does not follow. Binding through the nearest class alone, with no fallback to a call on a value, lost 14,693
calls, and binding through the caller's own class where the file reaches none added 1,142 calls at about half right.

**Revised 2026-10-22: a member call tells namesake classes apart by the scopes its operand's declaration writes.** Two
classes of one bare name in two namespaces that a file includes at one depth, `a::Widget` and `b::Widget`, left the
choice to path order, so `void paint(b::Widget &w) { w.draw(); }` bound `a::Widget::draw`. The receiver now keeps the
scopes the declaration writes, `b::Widget` or `::b::Widget`, without its template arguments, `ns::Box` for
`ns::Box<int>`, and keeps the bare name where a scope carries template arguments or the spelling a space. Members keep
`Class::member`, so no qualified name moves. Of the classes that hold the member in the nearest tier, the graph binds
the one whose qualified name the spelling names from the caller's scope outward, a member's class first, then its
namespaces, the global scope last, as C++ looks a name up, so a bare `Widget` inside `namespace b` names `b::Widget`; a
class nearer the file still wins over a farther twin, and a tier with one class binds it whatever the spelling says.
Namesakes of one qualified name, a template and its specializations, a class under each branch of a conditional or
copies of one class, bind the first as before, unless the caller's function defines one of them or one's body holds
the caller; namesakes of other names that the spelling names none of leave the call ambiguous.

On the game-engine tree 1,153 calls move to another member, 30 of 30 sampled right, 1,036 of them from `xray::Unit` to
the game's own `Unit`, and 960 calls that bound a member count as ambiguous, 28 of 30 sampled on the wrong class,
FMOD's `DynamicSortedArray::iterator` for a list that is a typedef of another container most often. Making namesakes
of one qualified name ambiguous too took 1,160 more calls, and of the 877 whose namesakes share a file, 24 of 30
sampled had bound right, the primary of `eastl::unique_ptr` most often. Checking a tier's one class against the
spelling took 5,667 calls, 18 of 20 sampled had bound right, the two wrong `std::vector` on EASTL's: the rest miss the
spelling where a using-directive, a namespace the graph does not attach to an out-of-line method, or a macro read as
the class's name leaves the scope or the qualified name short. Keeping the scopes past a scope's template arguments,
`Outer::Inner` for `Outer<int>::Inner`, respelled 1,607 receivers and bound 5 more calls, FMOD's `HashMap::iterator`,
and no use: such a spelling names an alias or a class a macro builds more often than one the graph holds, so the
receiver keeps the bare name there. Prefixing the receiver with the walk's own namespace rebound 1,135 calls and
misread a spelling that a scope around the walk's namespace holds, and spelling a specialization's arguments into its
class's qualified name told `Box<bool>` from `Box` but moved the resolution of bases and lost 3,702 to 4,026 calls.
With the field uses of ADR 3.34's revision of the same day, 299,427 call and use sites keep a scope, adding 7,545
strings and 0.25 MB to the graph's arena; the engine build's Rust heap peaks at 749.9 MiB against 749.8 and holds
718.5 MiB after it on both sides. Through the MCP binary, eight alternating rounds at 8 threads under a load of 10 to
13, the cold build takes 15.0–19.3 s against 14.9–19.9 s and the warm one 3.95–4.30 s against 3.95–4.16 s, and the
peak footprint's median stays within 2% of `main`'s.

**Revised 2026-10-23: a bare call of a name a local, a parameter or a capture declares is no call.** `visitor(x)` in
`template <typename T> void visitRefs(T visitor)` calls through what the parameter holds, a function pointer, a lambda
or a callable object, yet the walk recorded a call of `visitor`, and the graph bound it to any definition of that name
in the tree: the SPIR-V node visitors bound libtorrent's `struct visitor` once no namesake left the name ambiguous. The
walk records no such call, as it records no use of such a name and as the Go and Python walks drop a call through a
value, so no tier of ADR 3.7's cascade sees it: the call of a callable parameter named `function` that ADR 3.7 counts
binding `eastl::function` is no call any more. On the game-engine tree 3,156 files change, by their calls alone, and
23,935 call sites leave; 196 pairs leave, 40 of 40 sampled a call through a parameter, a local or a lambda that had
bound a namesake elsewhere. Two true pairs found leave with them: a call of `debug` after `VERBOSE debug("[submit]");`,
whose macro the grammar reads as the type of a local `debug`, and a call through a block-scope `extern long
(*_mindot_large)(...)`, which names a function of the namespace. `find_callees` no longer counts the sites in its
`unresolved=`, as for Go and Python. Recording the site as a call of a local symbol made for the local, which binds
nothing and keeps the site counted, adds 5,829 variable symbols the graph lists as roots, and the shifted symbol order
loses 2 pairs more and moves 2. The fix costs no measurable time or memory: against the build without it, at 6 threads
over 6 alternating rounds cold, the median takes 1.5% more where both sides spread over 16% and more, and the peak
footprint is 1.5% lower.

**A declaration without a body is emitted only where the file defines no callable of its identity.** Prototypes are
queued during the walk and flushed after it, so a header keeps its declarations while a source file that declares and
defines a function keeps one symbol for it; an in-class declaration whose out-of-line definition the same file holds is
recorded as folded into that definition. A queued prototype takes its namespace when it is queued, since the namespace
scopes have closed by the time it flushes. Its id comes after every definition's, and it opens no scope that a call is
attributed to, so the ids of the callers stay in source order.

**Revised 2026-10-23: a declaration links to the definition its own file reaches.** The graph linked a declaration
only to the definition whose file reaches the declaration's file, so the members an inline implementation header
defines, the `details/uri.hpp` or `.inl` a class header includes at its end, linked to nothing: a call of such a member
bound the declaration, whose body is empty, the definition had no callers, and a bare call in its body met no class. An
`#include` pastes the text in place, so a definition the declaration's own file reaches is in every translation unit
that declares it, and it qualifies too where a language's includes are transitive, which only C++'s are. The link
still takes only the one definition either way qualifies: a header that reaches a platform's conditional
alternatives, PhysX's scalar and SIMD `PsVecMath` bodies or `dag_vecMath`'s per-platform headers, links none, and a
copy of the implementation header in another checkout, which no file of the class reaches, stays apart. On the
game-engine tree, counting pairs by the locations they join, 554 pairs arrive and 497 leave, each of those at a line
that binds another callee. Of the arrivals 28 of 30 sampled are right, among them acl's `*.impl.h`, Jolt's
`MotionProperties.inl`, glTF's `.inl` and the ECS `entityManagerImplementations.h`; the two wrong are an SSE intrinsic
bound to a NEON shim's definition in an unrelated source, and a tcmalloc call that bound mini_chromium's copy of
`Acquire_Load` before and moves from its declaration to its definition; 57 arrive at a call that bound nothing. The
departures leave rightly, 30 of 30 sampled: 469 give way to the definition of the same name, and 28 are bare calls in
glTF2's `.inl` members that bound `glTFCommon`'s free namesakes and bind the base `Object`'s members once the member's
class is found. 3 pairs move tier. Every other language's call pairs and every file's extraction stay the same on
the tree and on the Go monorepo snapshot. Two other rules were measured beside this one on an earlier `main`: a
definition only the declaration's file includes directly binds 207 pairs this rule does not, each an arbitrary one of
a declaration's platform alternatives that its header happens to include directly, `dag_vecMath_neon.h` for
`dag_vecMath.h` or PhysX's scalar bodies, which this rule sees beside the others; and a definition whose includer
reaches the declaration, through the includers index of ADR 3.19, binds 360 pairs more, 7 of 20 sampled those PhysX
alternatives again. The reference engine shares the defect: its `uri::reset` has no callers. A member call on an
operand of a class the file meets only through the header that includes it, the gap the revision of 2026-10-19 names,
stays open: the receiver tier reads the caller's own includes. The cost is the closure of the declaration's file,
which a query builds only where a definition of the identity misses the first test, and which ADR 3.34's revision of
the same day reads again: at 2 threads, alternating against `main` under a load of 9 to 15 from other work, the cold
build takes 54.0 to 60.7 s against 54.2 to 64.2 s over 6 rounds with a peak footprint of 1,053 to 1,142 MiB against
1,047 to 1,145, and the warm one 6.67 to 7.83 s against 6.62 to 8.71 with 857 to 870 MiB against 853 to 932; over two
runs a side of the parity plan, `find_callers` takes 1.52 to 1.58 s summed against 1.52 to 1.79, `find_references`
0.92 to 0.97 s against 0.87 to 1.03, and `find_unused` 4.96 to 4.98 s against 5.02 to 6.40.

**A generated-code marker counts only outside a backtick span.** A header that documents the convention quotes the
marker; a banner does not, though it may quote its tool. On a mixed-language repository, 11 of the 12 files a plain
substring test flagged carried the marker in backticks, and in two of them the flag took 111 and 113 symbols out of
dead-code analysis. A depth limit was the other candidate and does not separate the two: 78 generated files carry their
banner at line 15, behind a license preamble, and a limit generous enough to keep them excludes no mention.

**Revised 2026-10-19: a backtick span closes only at a run of its own length.** The rule, which every language
shares through `kartta_lang::Banner`, read each backtick as opening or closing a span, so a reStructuredText
``` ``@generated`` ``` span read as two empty spans around a marker and announced a banner. A span now opens at a run of
backticks and closes at the next run of the same length, as Markdown and reStructuredText read one; a span that never
closes still runs to the end of the comment. No file's generated flag changes over the 300,555 files with symbols of
the game-engine tree, the Go monorepo, the cargo registry, the Python standard library, a PHP service, Homebrew and two
Lua and Puppet projects.

**Revised 2026-10-20: a code fence is a span across lines.** The scan read each comment on its own, so the example of a
doc comment, whose fence of three backticks opens on one line and closes on a later one, read as prose between its
fences. The doc comment of `kartta_lang::Banner` builds a banner from `"@generated"` and `"DO NOT EDIT"` in its example,
which judged its own `banner.rs` generated and took its 32 symbols out of dead-code analysis. A span of three or more
backticks that a comment leaves open now runs on through the next comments of the header until a run of its own length
closes it. A shorter span still ends with its comment: a BSD license's ``` ``AS IS'' ``` leaves one open in 3,333 files
of the game-engine tree, and carrying it would hide any banner below the license. Over the 106,779 files with symbols of
kartta's own tree, the game-engine tree, the Go monorepo, the cargo registry, Homebrew, the Python standard library and
the Lua and Puppet projects, `banner.rs` is the one file whose flag changes, and no other part of any extraction
changes. Carrying every span a comment leaves open changes no other file of these trees either. Two other rules were
measured and rejected, because generators write the banner where each one stops reading it:

- A doc comment, `///` or `//!`, that never carries the banner turns 520 files hand-written, and 519 of them are
  generated: the `//! DO NOT EDIT` of `objc2`'s header translator in 471 files of the registry, and of `tracing`'s
  `xtask` in 48.
- A marker that counts only at the start of a comment's text turns 342 files hand-written, and 341 of them are
  generated: the game-engine tree's `// !GENERATED FILE, DO NOT EDIT` in 128 files, OpenSSL's `Generated by
  util/mkerr.pl DO NOT EDIT` in 111, `// This file is @generated by syn-internal-codegen.` in 40, tree-sitter's
  `Automatically @generated by tree-sitter` in 18, and the Python standard library's `stringprep.py`.

The languages that walk their own header, Python, Lua, PHP, TypeScript and JavaScript, read each comment through
`Banner::marks` and carry no fence; no generated flag of these trees comes from a marker inside a fence of such a
header.

- A file-scope constant of a `.c` file is exported, 525 of them, and a generated banner counts after a byte order mark,

- Revised 2026-10-22: a macro before a return type written with a scope, `VULKAN_HPP_INLINE std::string to_string()`,
  keeps the namespace of the function it annotates and the class of an out-of-line member, `VULKAN_HPP_INLINE

- Revised 2026-10-23: a macro that opens a class member before a scoped return type, `PX_FORCE_INLINE const

## Considered Options

- **Vendor and patch the grammar** — closes each gap at its root, but regenerating `tree-sitter-cpp` needs the C grammar
  vendored with it, both join the set of crates that must move with tree-sitter in lockstep, and every patch is
  re-applied on each update. The measured gains above are reached without it.
- **Delete the offending constructs** — what the repairs measure against; filling the empty argument slot gains as much,
  and blanking only the macro invocation keeps the declaration a macro annotates, which deleting the line loses.
- **Re-parse wherever an error holds a macro invocation** — without the spill gate, 855 files are parsed twice instead
  of 163, for the 12% of the recovered symbols the gate gives up.
- **Read a misread conditional some other way** — measured on the game-engine tree against the extraction before the
  repair. Taking the first branch of every conditional the tree misread, whatever its braces, changes 136 files and
  drops 671 definitions, most of them alternatives the grammar would have read. Taking their last branch instead loses
  4,049 calls where the first gains 122. Keeping every branch and blanking only the braces a branch leaves unmatched,
  so that no code drops out, binds 53 calls more, ends 7 definitions fewer at their brace, `Curl_netrc_scan` and
  PhysX's `stab` among them, and leaves 76 more names without their namespace.

Revisit when `tree-sitter-cpp` publishes a release, or when the share of files with an error grows on a new code base.
