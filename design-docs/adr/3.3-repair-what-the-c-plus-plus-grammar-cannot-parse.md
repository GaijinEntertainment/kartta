# Repair what the C++ grammar cannot parse instead of vendoring it

- **Status:** accepted
- **Date:** 2026-10-16
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `crates/kartta-lang-cpp/src/repair.rs`, `crates/kartta-lang-cpp/src/lib.rs` (`extract`, `EXTENSIONS`),
  `crates/kartta-lang-cpp/Cargo.toml` (`tree-sitter-cpp`)
- **Pinned by:** the tests of `crates/kartta-lang-cpp/src/repair.rs`, and those of `crates/kartta-lang-cpp/src/walk.rs`
  named for a macro, a class head or a lone macro line

`kartta-lang-cpp` reads C and C++ through `tree-sitter-cpp`, whose error recovery on real code does not stay local: one
construct the grammar cannot reduce can take every declaration after it to the end of the file. The parser reads a
repaired copy of the file instead of a patched grammar, at the price of a byte scan per file and a second parse of the
few files whose first tree shows a misreading.

## Decision

**The parser reads a repaired copy; the walk reads the original.** `tree-sitter-cpp` is pinned at 0.23.4. A repair
blanks bytes to spaces and keeps every newline, so the copy has the original's length and every node position
addresses the original bytes, from which every name, signature and text is taken. The copy is made at the first blank,
so a file with nothing to repair allocates nothing. A repair also fires inside comments and string literals, where it
is inert. The repairs and the walk's own reading of what a repair leaves misread are scoped as follows:

- [ADR 3.70](./3.70-read-a-declarator-a-macro-misjoins-in-the-walk.md) reads a declarator a macro misjoins without a
  repair.
- [ADR 3.71](./3.71-read-a-conditional-that-splits-a-brace-with-its-first-branch-taken.md) repairs a conditional
  whose branches split a brace.
- [ADR 3.31](./3.31-parse-a-c-or-c-plus-plus-table-without-its-numbers.md) blanks a table's data.

**Before the first parse**, one pass over the bytes blanks:

1. The comma of an empty trailing call argument, `CHECK(ptr, )`, which turns it into the equivalent `CHECK(ptr )`.
2. In a class head that goes on to a base list or a body, the upper-case macros before the name, `class TORRENT_EXPORT
   torrent : base`, macro calls among them, `struct DECLSPEC_ALIGN(16) N {`, and the macros after the name where the
   name shares the key's line, `class Builder FLATBUFFERS_FINAL_CLASS {`, whatever line those macros stand on; where
   the name stands on a later line than the key, the macros after it are left, since a key that ends a comment line,
   `// a list class`, would take the next line's key for the name. The scan reads past a specialization's
   arguments, `struct RTM_DEPRECATED("...") float_traits<float> {`, holding a parenthesized expression's `<` and `>`
   apart, and leaves the attributes the grammar reads, `alignas`, `__declspec`, `__attribute__` and `[[...]]`. `struct
   STAT st;` declares a variable and is left.
3. A macro call around the key, `ATTRIBUTE_ALIGNED16(class) btCollisionObject {`: its name and parenthesis before the
   key and the parenthesis after it, where one name and a body or a base list follow.
4. A macro name alone on its line where the code below it, past comments and other such lines, opens a `template`, a
   class key or a `namespace`, as `RTM_IMPL_FILE_PRAGMA_PUSH` above `namespace rtm {`. Above a function such a macro is
   read as the return type and stays; a macro call alone on its line, `TABLE_END(name)`, and a `#define`'s
   continuation line stay.

**After the first parse**, where the tree holds an error, the file is parsed again from a copy that also blanks:

5. The macro invocation that opens each line of an error spanning three rows or more past its first: an upper-case
   name of three or more characters, alone on its line or with its arguments where no `;` follows, and not the rest
   of the line, which holds the declaration a macro annotates. An error that opens at a class head runs to the brace
   that closes the class in the source. An invocation that ends an enum, its last enumerator alone on a line, is
   blanked too and is inert, since no enumerator is a symbol.
6. Where a tree that parses at its top level holds a class member whose opening macro the grammar reads as the
   member's type and cannot read past: the macro that opens each member of that class, up to the brace that closes
   the class in the source, past `static`, `inline`, `virtual`, `friend`, `constexpr`, `explicit` and `extern`, before
   a type and a declarator, a destructor, a conversion operator or a constructor's initializer list. A member the first
   tree reads as written keeps its macro, and so does a macro beside another macro or a compiler's own `__` word. The
   signature of a member whose macro is blanked starts past the macro. A file whose first tree fails at its top level
   is left as it is.
7. The label and colon of a label the grammar reads an `#endif` under, `skip:` right before the `#endif` that closes
   its branch, where the first tree holds that `#endif` as an error in the label's statement.

A line of a `#define` body is never blanked. A second parse that yields no tree leaves the walk to the first copy,
parsed again ([ADR 3.31](./3.31-parse-a-c-or-c-plus-plus-table-without-its-numbers.md)): the repair is an improvement,
never a precondition.

**A restrict qualifier on a reference parameter stays unparsed.** `const Event &__restrict evt` is a GCC and MSVC
extension the grammar takes only after `*`.

**The claimed extensions are measured.** `cpp`, `cc`, `cxx`, `h`, `hpp`, `hxx`, `hh`, `c`, `inl` and `inc`, in any
letter case. Objective-C++ `mm` and `m` and CUDA `cu` and `cuh` are not claimed, and each is measured again before it
is.

**What the walk names and records** is decided apart: names in
[ADR 3.72](./3.72-qualify-c-plus-plus-names-the-way-the-graph-matches-them.md), includes in
[ADR 3.73](./3.73-resolve-a-c-plus-plus-include-to-the-copy-nearest-the-including-file.md), declarations in
[ADR 3.74](./3.74-fold-a-c-plus-plus-declaration-into-the-one-definition-its-file-reaches.md), receivers and calls in
[ADR 3.75](./3.75-name-a-c-plus-plus-call-s-receiver-by-the-class-its-operand-is-declared-as.md), and the
generated-code banner every language shares in
[ADR 3.76](./3.76-count-a-generated-code-marker-only-outside-a-code-span.md).

## Why

- A gap is worth closing only where it costs symbols: 30.31% of 17,408 first-party C++ files carried a parse error
  (2026-10-16), and one `CHECK(ptr, )` line cost a file the 50 symbols after it.
- A blank invents no token and keeps every position, so no repaired byte can reach a symbol, a call or a snippet, and
  a repair firing inside a comment or a string changes nothing.
- A line identical to a harmful one is harmless in a file that parses, so only the first tree's errors show which
  invocations cost something; a macro invocation spans one to three rows, so a shorter error consumed nothing else.
- What the grammar misreads as a heading, a class head or a namespace, fails with errors of a row or two, under the
  spill gate, and the bytes alone show it; repaired before the first parse, it costs a check at each line's start in
  the pass the empty argument already makes, and saves second parses.
- A misread member closes its class at its own brace, and the members after it parse outside the class; the source's
  brace, not the tree's, bounds the class, and a member read as written beside its macro keeps it.
- A label that ends a branch takes the `#endif` for its statement, and the conditional never closes: duktape's
  `duk_hobject_enumerator_create` spanned lines 52384 to 77150, not 52737. A label is no symbol, call or use, and
  blanking it brings back a lost function in 5 game-engine files and changes no other file (2026-10-24).

## Consequences

- A second parse of the files whose first tree shows a misreading, 1,608 of the 43,357 game-engine files (2026-10-24).
- The spill repair drops the calls written inside a blanked invocation's arguments; 123 of 621 such calls named a
  definition elsewhere (2026-10-16). Accepted.
- A macro alone on its line above a member that writes its own return type stays, so the 9 `TORRENT_DEPRECATED`
  members of libtorrent's `torrent_info` are read as fields (#438).
- A class a macro builds, or one that breaks at a conditional inside a constructor's initializer list, still parses
  apart (#439, #407); PhysX's `Facet` reads as an error at `PX_ALIGN(16, PxVec3 m_closest);` once its macros are
  blanked.
- A file whose first tree fails at its top level, as `vulkan_structs.hpp`'s does, keeps its misread members (#412).
- An `#include` inside a class body is not recorded (#440).

## Rejected

- **Vendor and patch the grammar** — regenerating it needs the C grammar vendored as well, both then move with
  tree-sitter in lockstep and every patch is re-applied on each update; for `&__restrict`, patching took the error
  share from 30.31% to 28.48% and recovered one symbol, because the reference parameter's error stays local.
- **Delete the offending construct** — filling the empty slot gains as much, and blanking only the macro keeps the
  declaration it annotates, which deleting the line loses.
- **Re-parse wherever an error holds a macro invocation** — 855 files parsed twice instead of 163, for 12% of the
  recovered symbols.
- **Require an argument list of a blanked invocation** — spares the last enumerator but costs 62 symbols and doubles
  the losses.
- **Blank a class head's macros, or a lone macro line, after the first parse** — recovers 8 of 48 heads with a macro
  after the name and 53 of 130 around the key, and parses 3,135 files twice against 1,596 (2026-10-23).
- **Blank every member macro of the file, not the misread class's** — changed 919 files and lost 72 callables the
  second parse misread elsewhere; without the check that keeps a member read as written, 6,863 signatures changed
  instead of 2,156.
- **Blank a lone macro line above a member with its own return type** — brings back 8 of the 9 `torrent_info` members,
  loses 9 members of 4 other files and moves about 1,400 definitions' start to the line below their macro.
- **Claim `mm`, `m`, `cu` and `cuh`** — 72%, 90%, 96% and 100% of such files carried an error, at 990, 95 and under
  300 symbols per MB, where `hh` holds 1,968 and `inc` 3,112 (2026-10-16).

## Revisit if

`tree-sitter-cpp` publishes a release, or the share of files with a parse error grows on a new code base. High
confidence that 0.23.4 stays the latest for the near term.
