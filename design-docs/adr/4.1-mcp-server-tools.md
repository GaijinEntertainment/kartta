# Answer agents through an MCP server with the tools their prompts already name

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-mcp`, `crates/kartta-mcp/src/server.rs`, `crates/kartta-mcp/src/params.rs`,
  `crates/kartta-mcp/src/render.rs`, `crates/kartta-mcp/src/render/`, `crates/kartta-mcp/src/llmxml.rs`
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`, `crates/kartta-mcp/tests/graph.rs`

Agents reach a code graph through MCP, and the prompts in use name the tools and pass their arguments. kartta answers
under those names, so those prompts call it unchanged, and writes each answer for its consumer, anyone's agent
([ADR 4.46](/design-docs/adr/4.46-release-scope.md)), in one vocabulary
([ADR 4.71](/design-docs/adr/4.71-mcp-count-vocabulary.md)) that counts as attributes what each answer left out. Every
tool is a name each session loads and description text each session that loads the tool pays for, so a tool exists only
for a question no other tool answers in one call.

## Decision

- **The server.** `kartta-mcp` is a binary crate with a library part, built on the engine directly, with no C ABI
  between them. It speaks MCP over stdio through `rmcp` 3.11.0 with tools alone: no resources, no prompts, no HTTP
  transport. The tests drive the binary over its stdio as a client does. It holds one repository's engine
  ([ADR 4.21](/design-docs/adr/4.21-mcp-engine-slot.md)), and reads its settings from the environment
  ([ADR 4.62](/design-docs/adr/4.62-mcp-server-environment.md)).
- **The tools.** The names, inputs and defaults are those the prompts use: `index_repo`, `index_stats`, `find_files`,
  `glob_files`, `grep`, `list_dir`, `find_symbols`, `read_definitions`, `file_outline`, `find_callers`,
  `find_call_path`, `find_references`, `find_implementations`, `find_importers` and `impact_of_edit`. Four more answer
  what the engine holds and no other tool answers in one call: `find_callees`, `impact_of_change`, `find_unused`, and
  `refresh` ([ADR 4.44](/design-docs/adr/4.44-mcp-refresh-tool.md)). A tool's description says when to prefer it over
  its neighbors and what it cannot see. Each tool's default limits are
  [ADR 4.23](/design-docs/adr/4.23-mcp-default-limits.md)'s.
- **Instructions.** The `initialize` instructions hold what kartta answers, to call `index_repo` only when
  `index_stats` shows no index of the repository, built or building, that no tool follows a link from one language
  into another, what a path the index does not hold answers, and a map from each question to the tool that answers it,
  naming every tool. A fact a tool's description or a parameter's text carries stays there.
- **Hints.** A tool that changes nothing, every query tool, carries `readOnlyHint`. `index_repo` and `refresh` change
  the index the server holds, and over a tree that has not changed a second call with the same arguments has no effect
  beyond the first, so they carry `idempotentHint`. No tool carries another hint.
- **Parameters.** Every tool refuses an unknown argument, and reads a null optional argument as omitted. An
  argument of the wrong type or value is a tool error that names the parameter by its path inside the arguments, such
  as `regions[0].start_line`, then says what the parameter takes; a required argument left out is named in the message
  alone, as ``missing field `name` ``. The server reads the arguments through `serde_path_to_error`, because
  `serde_json` reports no path. A limit is
  `NonZero`, so a zero is a wrong call, except the `max_results` of `find_files` and `glob_files`, where zero lists
  every match. A line number is `NonZero` too, in one shape for `impact_of_edit` and a region of `impact_of_change`:
  an omitted or null `end_line` reaches the end of the file. `languages` takes the name of every
  language kartta ships and the family key `jsts`; an unknown name fails the call with every name it takes. The floors
  `likely` and `certain` are the tiers `SAME_DIR` and `SAME_FILE` of
  [ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md), and an answer marks a call bound below 80 `likely` and below
  50 `guess`. The `access` of `find_references` takes `read`, `write` and `type`, each keeping what the engine's filter
  of that name keeps ([ADR 4.11](/design-docs/adr/4.11-mcp-reference-listing.md)). `find_callers`, `find_callees`,
  `find_references` and `find_implementations` take `path_prefix` and `line`, and `find_call_path` `from_path_prefix`,
  `from_line`, `to_path_prefix` and `to_line`, to pick one of the symbols a name selects
  ([ADR 3.35](/design-docs/adr/3.35-shared-name-selection.md)). How a path or a glob argument reads, and what a miss
  answers, is [ADR 4.61](/design-docs/adr/4.61-mcp-path-arguments.md)'s.
- **The answers.** An answer is one root element named for the question, counts as attributes in
  [ADR 4.71](/design-docs/adr/4.71-mcp-count-vocabulary.md)'s words, one record a line, and an attribute marking the
  unusual only where it applies. A wrong call is a tool error naming the fix; a valid call over nothing is an envelope
  with a count of zero and a hint. The path searches answer plain paths, one a line
  ([ADR 4.10](/design-docs/adr/4.10-mcp-path-list-cuts.md)). What each answer counts of what it left out, and the
  records it lists of what a match passed over, are [ADR 4.24](/design-docs/adr/4.24-mcp-omission-counts.md)'s.

## Why

- A server under the names and inputs the prompts in use already call serves them without a rewrite (#74). The words of
  its answers rest on the consumer the release serves, anyone's agent
  ([ADR 4.46](/design-docs/adr/4.46-release-scope.md)), who reads every tool's answer with one reader, and the release
  is the last point where a rename costs no major version (#1037).
- Every session loads every tool's name, and the description of each tool it loads, so a tool that answers what
  another answers costs sessions and answers nothing new.
- An agent cannot see whether the server was launched with a root, so instructions that sent it to `index_repo` first
  rebuilt an index already built or building: about a minute at 2 threads on 171,628 files (2026-11-06, #1033).
- Claude Code's tool search, on by default, loads only the tools' names and the servers' instructions at session
  start, and cuts instructions past 4,096 characters; its MCP documentation, read 2026-11-06, asks a server's
  instructions to say when to search for its tools. The map is what sends a question to its tool before a description
  loads, and with the parameters' facts left to their own text the `initialize` answer is 1,743 bytes.
- Claude Code runs `readOnlyHint` calls in parallel with one another, and repeats a `readOnlyHint` or `idempotentHint`
  call that a closed connection left unanswered; its MCP documentation, read 2026-11-03, names no use of another hint.
- A client that fills unset fields with null failed its first `index_repo` while a `bool` refused null, and
  `impact_of_edit` read an `end_line` of 0 as the end where a region refused it (#1036).
- The SDK's own extractor passed `serde_json`'s error through as is, so a call that sent several numbers answered
  "expected a nonzero u32" with no word of which one to fix (#1152). Tracking the path costs about 0.17 µs per
  `find_callers` read, measured 2026-11-04, beside a call that answers in milliseconds.

## Consequences

- A `find_unused` listing is a candidate: function values, outside callers and dynamic dispatch are unseen. Accepted.

## Rejected

- **A server over the C ABI** — adds a serialization round trip to every answer the engine's own types already serve.
- **Envelopes in the vocabulary the prompts in use read** — it gave one word several meanings across tools, as `count=`
  for the records listed and for every record, so an agent needed a reader per tool
  ([ADR 4.71](/design-docs/adr/4.71-mcp-count-vocabulary.md)).
- **An HTTP transport** — its server stack brings dependencies `deny.toml` has not reviewed, for no consumer that needs
  one.
- **A separate tool for reads and writes** — `find_references` already promises "where is this used", and a tool costs
  every session its name and each session that loads it its description.
- **A kinds filter on `find_unused`** — each record names its kind, and the parameter is description text each session
  that loads the tool pays for.
- **`openWorldHint` and `destructiveHint` set to false** — both would hold, but no client served documents a use of
  them, and each is `tools/list` text each session that loads the tool pays for.
- **An `end_line` of 0 for the end of the file** — a magic value, where the `NonZero` rule already makes a zero a wrong
  call and omission says the same.
- **Instructions without the map, since its lines repeat the tools' descriptions** — under tool search an agent sees
  the instructions and the tools' names alone until it loads a tool, so the map is what picks the tool.
- **A path tracker of kartta's own** — it would rewrite the deserializer wrapper `serde_path_to_error` already is.
- **Reading without a path first, and again with one only on a failure** — a second read path to save about 0.17 µs
  per call, which no call's time shows.

## Revisit if

A consumer needs a transport other than stdio; held while the agents served launch MCP servers as child processes.

  total on others; they rest on anyone's agent, the release's consumer
  ([ADR 4.71](/design-docs/adr/4.71-mcp-count-vocabulary.md), #1037)

  rebuilt the index a launch root had built, and they repeated what the tools' parameters say (#1033)
- 2026-11-04 — Parameters: a wrong argument's error named no parameter, so an agent could not tell which to fix
  (#1152)
- 2026-11-03 — Hints: `tools/list` marked no tool read-only, so a client ran no call in parallel and repeated none
  (#1036)
- 2026-11-03 — Parameters: some optional parameters refused null, and the two impact tools took `end_line` 0 in two
  ways (#1036)
- 2026-11-03 — Parameters: `find_references` refused `access` `type`, which the engine and the wire take (#1120)
- 2026-10-23 — Parameters: `path_prefix` selects by file only, so no argument reached one of several definitions that
  share a name and a file, such as C++ overloads (#401)
- 2026-10-19 — Parameters: a query took the top-ranked symbol of a name, so copies that share a qualified name could
  be reached by no name (#106)
- 2026-10-18 — The tools: `find_references` could not select a field, and a separate tool for reads and writes would
  cost every session's description text (#82)
- 2026-10-18 — The tools: the server answered the snapshot `index_repo` took, so its answers went stale after the
  agent's first edit (#80)
- 2026-10-18 — The tools: no tool answered what a symbol calls, what a change reaches, which definitions nothing
  reaches, or how well the graph's calls bind (#77)
