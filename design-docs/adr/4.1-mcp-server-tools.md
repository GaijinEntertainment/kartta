# Answer agents through an MCP server with the tools their prompts already name

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-mcp`, `crates/kartta-mcp/src/server.rs`, `crates/kartta-mcp/src/params.rs`,
  `crates/kartta-mcp/src/render.rs`, `crates/kartta-mcp/src/render/`, `crates/kartta-mcp/src/llmxml.rs`,
  `crates/kartta-mcp/src/config.rs`, `crates/kartta-mcp/src/paths.rs`
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`, `crates/kartta-mcp/tests/graph.rs`,
  `crates/kartta-mcp/tests/paths.rs`

Agents reach a code graph through MCP, and the prompts in use name the tools, pass their arguments and read their
envelopes. kartta answers under those names and envelopes, so those prompts work unchanged, and adds as attributes the
counts of what each answer left out. Every tool is description text each session pays for, so a tool exists only for a
question no other tool answers in one call.

## Decision

- **The server.** `kartta-mcp` is a binary crate with a library part, built on the engine directly, with no C ABI
  between them. It speaks MCP over stdio through `rmcp` 3.5.1 with tools alone: no resources, no prompts, no HTTP
  transport. The tests drive the binary over its stdio as a client does. It holds one repository's engine
  ([ADR 4.21](/design-docs/adr/4.21-mcp-engine-slot.md)).
- **The tools.** The names, inputs and defaults are those the prompts use: `index_repo`, `index_stats`, `find_files`,
  `glob_files`, `grep`, `list_dir`, `find_symbols`, `read_definitions`, `file_outline`, `find_callers`,
  `find_call_path`, `find_references`, `find_implementations`, `find_importers` and `impact_of_edit`. Four more answer
  what the engine holds and no other tool answers in one call: `find_callees`, `impact_of_change`, `find_unused`, and
  `refresh` ([ADR 4.44](/design-docs/adr/4.44-mcp-refresh-tool.md)). A tool's description says when to prefer it over
  its neighbors and what it cannot see. Each tool's default limits are
  [ADR 4.23](/design-docs/adr/4.23-mcp-default-limits.md)'s.
- **Hints.** A tool that changes nothing, every query tool, carries `readOnlyHint`. `index_repo` and `refresh` change
  the index the server holds, and over a tree that has not changed a second call with the same arguments has no effect
  beyond the first, so they carry `idempotentHint`. No tool carries another hint.
- **Parameters.** Every tool refuses an unknown argument, and reads a null optional argument as omitted. A limit is
  `NonZero`, so a zero is a wrong call, except the `max_results` of `find_files` and `glob_files`, where zero lists
  every match. A line number is `NonZero` too, in one shape for `impact_of_edit` and a region of `impact_of_change`:
  an omitted or null `end_line` reaches the end of the file. `languages` takes the name of every
  language kartta ships and the family key `jsts`; an unknown name fails the call with every name it takes. The floors
  `likely` and `certain` are the tiers `SAME_DIR` and `SAME_FILE` of
  [ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md), and an answer marks a call bound below 80 `likely` and below
  50 `guess`. The `access` of `find_references` takes `read`, `write` and `type`, each keeping what the engine's filter
  of that name keeps ([ADR 4.11](/design-docs/adr/4.11-mcp-reference-listing.md)). `find_callers`, `find_callees`,
  `find_references` and `find_implementations` take `path_prefix` and `line`, and `find_call_path` `from_path_prefix`,
  `from_line`, `to_path_prefix` and `to_line`, to pick one of the symbols a name selects
  ([ADR 3.35](/design-docs/adr/3.35-shared-name-selection.md)).
- **Path arguments.** A file, a directory, a region's file, `from` and every `path_prefix` are read from the root with
  `/` between names, a leading `./` dropped. A path the index does not hold, or a prefix that starts no held path, is a
  wrong call: its error names the spelling's fault, absolute, a drive such as `C:`, a `\` between names or a `..` name,
  or else that nothing is indexed there, and lists up to 5 held paths near it: the path its names spell with `\` read as
  `/`, the deepest held directory they lead to and its entries that start as the next name does, then the entries
  anywhere named as its last name is. A held name that holds a `\` answers as any other. A held file outside every
  graph gets a count of zero and a note naming why: no indexed language claims it, or the graph that claims it holds
  no record of it. A diff's paths are git's and go unchecked: a file the index lacks counts in `unheld_regions`.
  `refresh` takes paths the index does not hold yet ([ADR 4.44](/design-docs/adr/4.44-mcp-refresh-tool.md)).
- **Globs and names.** A glob selects files alone. An empty `glob_files`, `grep` or `find_files` answer names each of
  its `globs` or `includes` that holds no `* ? [ ] { }` nor `\` and, a trailing `/` dropped, is a held directory, with
  the `<dir>/**` that selects what it holds. A `list_dir` exclude is a name matched literally at any depth, `pkg/deep`
  included; one holding `* ? [ ] { }` is a wrong call.
- **The answers.** An answer is one root element named for the question, counts as attributes, one record a line, and
  an attribute marking the unusual only where it applies. A wrong call is a tool error naming the fix; a valid call
  over nothing is an envelope with a count of zero and a hint. The path searches answer plain paths, one a line
  ([ADR 4.10](/design-docs/adr/4.10-mcp-path-list-cuts.md)). What each answer counts of what it left out, and the
  records it lists of what a match passed over, are [ADR 4.24](/design-docs/adr/4.24-mcp-omission-counts.md)'s.
- **Configuration.** The server reads the environment: `KARTTA_CACHE_DIR` the shared cache
  ([ADR 2.1](/design-docs/adr/2.1-shared-cache-store.md)), `KARTTA_CACHE_ENTRY_TTL_SECS` an entry's time to live as
  [ADR 2.3](/design-docs/adr/2.3-cache-entry-expiry.md) reads it, which also leaves `KARTTA_CACHE_SWEEP` unread,
  `KARTTA_GREP_INDEX` `memory`, `file` or `mmap` and `KARTTA_GREP_INDEX_DIR` the trigram index
  ([ADR 1.14](/design-docs/adr/1.14-content-search-narrowing.md)), `KARTTA_THREADS` the thread bound
  ([ADR 1.13](/design-docs/adr/1.13-index-threads.md)), and `KARTTA_WATCH` the watch
  ([ADR 4.4](/design-docs/adr/4.4-mcp-index-follow.md)). Unset, `KARTTA_CACHE_DIR` is `kartta` under the user's cache
  directory, `~/Library/Caches` on macOS, `%LOCALAPPDATA%` on Windows and an absolute `$XDG_CACHE_HOME`, else
  `~/.cache`, elsewhere, and `KARTTA_GREP_INDEX` is `mmap` in the temporary directory; an empty value turns either off.
  A server with no user cache directory warns and builds without a cache. A value that does not read warns on stderr and
  keeps the default. The walk prunes the engine's default `PrunedNames`
  ([ADR 1.19](/design-docs/adr/1.19-pruned-names.md)).

## Why

- A server under the names, inputs and envelopes the prompts in use already read serves them without a rewrite, and
  every fact kartta adds fits an attribute of those envelopes (#74).
- Every session loads every tool's description, so a tool that answers what another answers costs each session and
  answers nothing new.
- Claude Code runs `readOnlyHint` calls in parallel with one another, and repeats a `readOnlyHint` or `idempotentHint`
  call that a closed connection left unanswered; its MCP documentation, read 2026-11-03, names no use of another hint.
- A missed path answered a zero count with a note of three causes, a `path_prefix` or a `from` that held nothing
  answered as if it selected nothing, and `list_dir` alone answered an error, so an agent passing a Windows spelling, a
  `..` path or a misplaced file retried another spelling of the same mistake (#684, #1040). A hit pays one index
  lookup per path, and a miss one pass over the index's paths: 98 ms on the 4.14M files of the macOS data volume
  (2026-11-03).
- A directory passed as a glob selected nothing while an exclude of the same text dropped it, and `grep` sent the agent
  to `glob_files`, which answered only that no file matched; a `list_dir` exclude of `**/deep` excluded nothing,
  silently (#1040). The hint costs one index lookup per such glob, on an empty answer alone.
- A client that fills unset fields with null failed its first `index_repo` while a `bool` refused null, and
  `impact_of_edit` read an `end_line` of 0 as the end where a region refused it (#1036).
- A session starts its own server, so every session pays a build, and an agent greps many times in one. On a
  171,628-file C++ checkout a warm cache cut the build from 27-31 s to 5.8 s, and the mapped index answered a literal
  `grep` of the whole tree in 4 ms against 3.4 s, adding no footprint and no measurable build time (macOS, 4 threads,
  2026-11-03, #1034).

## Consequences

- A `find_unused` listing is a candidate: function values, outside callers and dynamic dispatch are unseen. Accepted.
- A server writes to the user's cache directory unasked: 590 MiB for the checkout and 8.1 GiB for a 4.1M-file data
  volume, whose payloads [ADR 2.3](/design-docs/adr/2.3-cache-entry-expiry.md)'s expiry holds within about twice what
  its unexpired entries take, an entry staying until its pack is rewritten. Accepted.
- The index reads every text file each build: on the data volume a warm build took 276 s against 158 s, and the scratch
  file held 3.7 GiB. Accepted: a literal `grep` there took 3.2 s against 158 s without it.
- Where the temporary directory is a memory filesystem, the mapped index occupies memory. Accepted.
- A pattern with no three-byte literal still reads every candidate: 3.2-5.5 s on the checkout. Accepted.
- A file made since the index last read the tree, while the watch is off, is a wrong call to the file tools until a
  `refresh` takes it in. Accepted.
- A glob that names a directory below the root by its name alone, `deep` for `pkg/deep`, gets no hint, nor does an
  answer another glob filled (#1159); a directory whose name holds a glob character cannot be a `list_dir` exclude,
  and on Windows, whose names hold no `\`, an exclude holding one matches nothing (#1160).

## Rejected

- **A server over the C ABI** — adds a serialization round trip to every answer the engine's own types already serve.
- **Answers in kartta's own vocabulary** — the prompts in use break on every tool, while every fact kartta adds fits an
  attribute.
- **An HTTP transport** — its server stack brings dependencies `deny.toml` has not reviewed, for no consumer that needs
  one.
- **A separate tool for reads and writes** — `find_references` already promises "where is this used", and a tool costs
  every session.
- **A kinds filter on `find_unused`** — each record names its kind, and the parameter is description text every session
  pays for.
- **`openWorldHint` and `destructiveHint` set to false** — both would hold, but no client served documents a use of
  them, and each is `tools/list` text every session pays for.
- **A missed path as a zero-count envelope with a note** — it reads as a valid call over nothing, which the answers
  rule keeps for a call that is right.
- **A fuzzy search for the near paths** — a pattern of common names matches most of a large tree: 1.2 s for one miss
  on the data volume.
- **Refusing a `\` before the lookup, as `refresh` does** — costs these tools a held file whose name holds a `\`, legal
  outside Windows.
- **`includes` taking a directory, as `excludes` does** — changes the dialect of
  [ADR 1.4](/design-docs/adr/1.4-query-glob-dialect.md), where a glob names files.
- **A `list_dir` exclude read as a glob** — a second dialect inside one parameter; refusing `/` instead removes
  `pkg/deep`, which works.
- **An `end_line` of 0 for the end of the file** — a magic value, where the `NonZero` rule already makes a zero a wrong
  call and omission says the same.
- **No cache by default** — every session parses the whole tree: 615 s on the data volume against 158 s warm.
- **No content index by default** — a literal `grep` of the checkout reads every candidate, 3.4-4.6 s against 4 ms.
- **A `memory` index by default** — the same answers for 235 MiB more footprint on the checkout.

## Revisit if

A consumer needs a transport other than stdio; held while the agents served launch MCP servers as child processes.

Agents index trees where reading every text file for the index costs more than their greps save. Medium confidence:
measured on one checkout and one data volume.

## History

- 2026-11-03 — Globs and names: a directory passed as a glob, or a glob as a `list_dir` exclude, selected or excluded
  nothing and said nothing (#1040)
- 2026-11-03 — Path arguments: a missed path answered a note of three causes or selected nothing, and a leading `./`
  missed (#684, #1040)
- 2026-11-03 — Hints: `tools/list` marked no tool read-only, so a client ran no call in parallel and repeated none
  (#1036)
- 2026-11-03 — Parameters: some optional parameters refused null, and the two impact tools took `end_line` 0 in two
  ways (#1036)
- 2026-11-03 — Configuration: a server given no environment took the library's defaults, so every session parsed the
  whole tree again and every `grep` read every candidate (#1034)
- 2026-11-03 — Parameters: `find_references` refused `access` `type`, which the engine and the wire take (#1120)
- 2026-10-23 — Parameters: `path_prefix` selects by file only, so no argument reached one of several definitions that
  share a name and a file, such as C++ overloads (#401)
- 2026-10-19 — Configuration: `KARTTA_CACHE_SWEEP` had no effect beyond a warning, and nothing released depended on
  it (#128)
- 2026-10-19 — Parameters: a query took the top-ranked symbol of a name, so copies that share a qualified name could
  be reached by no name (#106)
- 2026-10-18 — The tools: `find_references` could not select a field, and a separate tool for reads and writes would
  cost every session's description text (#82)
- 2026-10-18 — Configuration: a shared cache never removed an entry, so a build node that shares one for weeks filled
  its disk (#81)
- 2026-10-18 — The tools: the server answered the snapshot `index_repo` took, so its answers went stale after the
  agent's first edit (#80)
- 2026-10-18 — The tools: no tool answered what a symbol calls, what a change reaches, which definitions nothing
  reaches, or how well the graph's calls bind (#77)
