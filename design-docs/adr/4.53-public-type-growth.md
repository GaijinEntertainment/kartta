# Leave each public type open to growth unless its set is closed

- **Date:** 2026-11-02
- **Governs:** `crates/kartta-lang/src/extraction.rs`, `crates/kartta-lang/src/language.rs`,
  `crates/kartta-lang/src/symbol.rs`, `crates/kartta-graph/src/resolve.rs`, `crates/kartta-graph/src/scope.rs`,
  `crates/kartta-graph/src/graph.rs`, `crates/`
- **Pinned by:** `crates/kartta-lang/src/extraction.rs` (the `compile_fail` doctests of `OpenRecords`),
  `crates/kartta-lang/tests/records.rs`, `crates/kartta-ffi/tests/reference.rs`

Every artifact versions in lockstep ([ADR 4.46](/design-docs/adr/4.46-release-scope.md)), so a change that breaks one
public type moves all of them to 2.0. A public enum or struct is therefore `#[non_exhaustive]` unless its set is closed
by definition, and an extraction record gets a constructor; a language pays a constructor call and a line per field for
each record it builds, and a `match` in another crate gives up the compiler's check of a new variant.

## Decision

- **Open by default.** In every crate but `kartta-node`, which does not publish, each public enum, and each public
  struct whose fields are all public, is `#[non_exhaustive]`. A struct with a private field needs no attribute: no
  struct expression outside its crate builds it.
- **Closed sets.** A type stays exhaustive where a new member would contradict what it is, and its doc says so:
  `Access` (a use reads, assigns, does both or neither), `CallableRole` (a body or none), `kartta_walk::EntryKind`
  (`Other` holds the rest), `LineKind` (a match or context), `Cut` (a line's two sides),
  `FoldedDeclaration`, and the newtypes `SymbolId`, `BuiltApart` and `SameMethod`.
- **Maps of the answers.** An enum the wire or the MCP server maps stays exhaustive where its set is closed, so the
  compiler checks each map, or it carries `label()` in its own crate, where the match sees every variant, as
  `SymbolKind`, `Miss`, `Nearness`, `UnmatchedKind`, `BuildError` and `ListError` do. No wildcard arm of a map answers
  an existing label for a variant it cannot name: a surface with a spelling of its own answers the label for a label it
  does not know. An arm stays where its word means any other failure, as `build_failed` does.
- **Records.** An open record a language builds takes `new`, whose parameters are the facts every record of the kind
  states, four at most. They freeze at 1.0: a new field takes a default in `new`, and a language sets the fields that
  apply. `RawExtraction` and `Extraction` have no fact every value states, so they start from `Default`.
- **A variant the graph does not know.** A language builds the enums of `Conventions` and `Receiver`, and the graph
  reads them, as the Rust and PHP walkers read `Receiver`. A language that states a new variant needs a graph of that
  release. An older graph cannot name the variant: its wildcard arm reads it as the enum's default, a comparison as none
  of the others, and an unknown `Receiver` as an empty `Path`.
- **Lists.** A public list of variants is a slice, since an array's length is part of its type.

## Why

- `CallRef` gained three fields and `UseRef` two between 2026-10-16 and 2026-11-02; the other records kept theirs, and
  they take the attribute all the same, because a field they gain would break the same language crates.
- Outside its crate a `#[non_exhaustive]` struct takes no struct expression, functional update included, and an enum
  must be matched with a wildcard (Rust Reference, `attributes.type-system.non_exhaustive.construction` and `.match`).
- The lint that would check a wildcard against the named variants, `non_exhaustive_omitted_patterns`, is unstable
  (`rustc_feature/src/unstable.rs:683`), and the toolchain is a pinned stable.

## Consequences

- A variant added to `ValueUses`, `Twins`, `MemberCalls`, `InheritedMembers`, `IncludedRuntimeMembers` or `Receiver`
  compiles with no arm in `kartta-graph`. Accepted: nothing the variant is for happens until an arm reads it, so its
  own test fails.
- `clippy::match_same_arms` folds the default's named arm into the wildcard, so those matches do not name it. Accepted.
- Building a record takes a line per field beyond `new`. Each `new` inlines, and extraction runs the same instructions
  within 0.01% on dagor's C++ and on a Go monorepo (2026-11-02). Accepted.

## Rejected

- **A constructor of every field** — `CallRef` has seven, past the limit of four, and a list of every field breaks on
  the first one added.
- **`with_*` methods on each record** — they add API for fields a language can already assign, as it does on `Symbol`.
- **`#[non_exhaustive]` on `Access` and `LineKind`** — the graph's four maps of `Access`, its stored form and the wire
  would each take a wildcard for a set with no fifth member.
- **`Receiver` exhaustive** — it has kept its four forms, but nothing closes the set, and a fifth would be a major
  release of every artifact.
- **`ListError` exhaustive, so the wire's map needs no label** — `Pruned` came as a refinement of `NotFound`, and
  nothing closes that set.

## Revisit if

Rust stabilises `non_exhaustive_omitted_patterns`, which restores the graph's check of each variant. High confidence in
the rule; medium that `Access` stays closed, since a use that neither reads nor assigns and is no type has no variant.
