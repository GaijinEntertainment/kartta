# Bind a macro invocation only to a macro where a language writes it apart

- **Status:** accepted
- **Date:** 2026-10-24
- **Updated:** 2026-10-24
- **Initiative:** `03-code-graph`
- **Governs:** `kartta_lang::CallRef::invokes_a_macro`, `kartta_lang::MacroInvocations`,
  `crates/kartta-graph/src/resolve.rs` (`is_of_the_call_s_form`, `in_the_caller_s_package`),
  `crates/kartta-graph/src/stored.rs` (`StoredCall`), `crates/kartta-lang-rust/src/walk/calls.rs`,
  `crates/kartta-lang-rust/src/lib.rs` (`CONVENTIONS`)
- **Pinned by:** `crates/kartta-languages/tests/engine.rs`
  (`a_rust_call_binds_no_macro_and_a_macro_invocation_no_function_of_its_name`,
  `a_rust_macro_invocation_binds_by_its_name_alone_only_a_macro_of_the_caller_s_package`,
  `a_rust_macro_invocation_through_a_use_binds_the_proc_macro_function_it_names`),
  `crates/kartta-lang-rust/tests/extract.rs` (`a_macro_invocation_is_marked_apart_from_a_call_of_its_name`)

Rust writes `name!()` apart from `name()`, and the two never name each other's target. A call records which form it
was written in; where the language's conventions write the two apart, every tier admits only a target of that form,
and by name alone a macro invocation binds only a macro of the caller's Cargo package, which lets the crates of one
package share their macros by name.

## Decision

- A call records `invokes_a_macro`. The Rust walk sets it on every `name!(...)` and `path::name!(...)` it records as
  a call, those in a macro's arguments included
  ([ADR 3.54](/design-docs/adr/3.54-rust-macro-argument-calls.md) says which it reads); other
  languages leave it false, and their encoded calls keep their bytes.
- Where a language's `Conventions` set `MacroInvocations::Apart`, as Rust's do, every tier admits a macro for a macro
  invocation and no macro for any other call. `MacroInvocations::AsCalls`, the default, admits either, as a dshl call
  of a macro needs.
- In Rust a function marked `#[proc_macro]` is a macro; a derive or attribute macro stays a function.
- The tiers that bind by name alone, the name's one callable and the nearest directories
  ([ADR 3.172](/design-docs/adr/3.172-bare-call-binding.md), tier 7),
  take for a macro invocation only the macros of the files that name the caller's file's package, or no package where
  it names none; a Rust file names its Cargo package. The scope and import tiers above them, ADR 3.45's module file
  among them, are not narrowed.
- The stored call keeps the mark in a spare bit of its caller index.

## Why

- A namesake of the other form is never the target: of 30 sampled pairs the rule removes from a cargo registry of
  18,568 Rust files, 29 were wrong, `unreachable!()` binding parking_lot's `fn unreachable` among them (2026-10-24).
- A macro is in scope inside its crate by text order and elsewhere only through a path or a `use`: admitting macros
  alone, without the package bound, gave 6,600 pairs to a namesake in another package on that registry, the standard
  `debug_assert_eq!` bound to embedded-io's macro (2026-10-24).
- With the package bound, 29 of 30 sampled pairs the rule adds there are right, syn's `Token!` and regex-automata's
  `trace!` among them (2026-10-24).

## Consequences

- A `CallRef` in memory grows from 56 to 64 bytes while its file is extracted; the encoded call and the stored call
  keep their size. A macro invocation that reaches the name tiers reads the package of each of its candidates.
- A package's tests, examples and binaries are crates of their own, yet can bind each other's macros by name, as a
  test file binds a macro another test file defines. Accepted.
- Rust files under no Cargo manifest read as one package, so a macro invocation there can bind another crate's macro by
  name; the graph knows no crate boundary between them, and binding none would drop each crate's own macros.
  Accepted.
- A macro another package brings by `#[macro_use] extern crate` binds no invocation by name. Accepted.
- A call no longer counts a macro of its name among its candidates, so the one function of the name can bind where the
  macro left it ambiguous, `x.rotate_left()` binding num-traits' method. Accepted.

## Rejected

- **No name tier for a macro invocation** — drops 2,538 pairs bound at the nearest directories of the caller's own
  package on the registry, winnow's `assert_parse!` and rustix's `syscall!` among them (2026-10-24).
- **The crate the caller's include roots reach** — a crate that declares a module inside a macro invocation,
  `cfg_net! { mod udp; }`, reads as several, and binds 708 fewer pairs on the registry, mio's `syscall!` and tokio's
  `pin!` among them (2026-10-24).
- **The guards that left a name both a function and a macro export unbound** — the call's form tells them apart.
- **A macro mark in the callee's text, `name!`** — the definition keeps its bare name, so every lookup by name would
  need both spellings.

## Revisit if

The crates inside one package define macros of one name often enough that a package-wide pick binds the wrong one.
Medium confidence, held on the registry sample above alone.
