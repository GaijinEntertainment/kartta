# Record each read and write of a field or a value, and bind it when a query asks

- **Status:** accepted
- **Date:** 2026-10-18
- **Revised:** 2026-10-19
- **Initiative:** `03-code-graph`

The graph recorded calls and, for Go and DSHL, the uses of a type or of a package-qualified value; it recorded no field
access, no read of a package's own value, and no write of anything. `find_references` could not select a field at all,
so "who reads or writes `Config.Timeout`?" answered no symbol, or a symbol of the same name: `MaxRetries` a method,
`Timeout` a type. A quarter to a half of every graph's definitions are fields, variables and constants. An agent then
greps a short member name, which matches thousands of lines across unrelated types, and that is where grep is weakest.

**A use says how it touches its target and what its name is written on.** `UseRef` carries an `Access` — a read, a
write (the left side of `=`, a key of a literal that builds the owner), or an update that reads and writes (`+=`, `++`)
— and a `Receiver`: a bare name, a name qualified by a module, a member of the enclosing member's own receiver (`this`,
`self`, implicit), or a member of a value whose type a path spells as the language's receivers convention says (ADR
3.29), empty where the language cannot name the type. A use as a type reads its target. The codec moves to layout 4 and
`kartta_lang::FINGERPRINT` with it, so a cache never serves an extraction of the old contract. An encoded use writes a
name or a path an earlier use of its file spelled as the index of that text: one value's path and one field's name
repeat across a file, and the build holds every file's encoded extraction until it resolves the file (ADR 1.18).

**The graph keeps a use in the 16 bytes it took.** The receiver's form and the access ride in the top four bits of
`site_of`, and the qualifier or the path, interned, in the slot the qualifier had; a use inside a definition past the
2^28th of its file is not kept. `Graph::stats` counts the reads, the writes and the updates apart.

**Go records every data site its walk can attribute.** A selector on a value that is not a call's callee is a member
use with the operand's type path, so a method taken as a value (`RunE: c.run`) is a use of the method. A key of a struct
literal writes its field, the literal's type spelled where written and taken from the enclosing slice or map literal
where elided; an anonymous struct's keys are kept as nothing, since no symbol holds its fields. An identifier in a body
that no local, parameter, type parameter or declaration binds, that is not predeclared, a callee or an import's name, is
a bare use of a package-level value or function: the walk sees one file, so it keeps the name and the graph binds it
only where some file of the package declares it. Assignments, `range` and `select` receives that assign with `=`,
`++`, `--` and `op=` mark the outermost expression on their left; `a.b` in `a.b.c = v` is read.

**A member use binds when a query asks, in two tiers.** Through the type its path reaches, a field or a method of that
type or of a type it embeds, at 85; a path into code outside the graph, an undeclared name or a type without the member
binds nothing and stops. A path the graph cannot follow, or none, binds the one field of the name its own file declares
outside other bodies, at 80. A bare use keeps the cascade it had (ADR 3.7); an own-receiver use binds nothing until a
language records one with its tier. Fields become referents of `Graph::references`, which takes a `SiteQuery`: its
floor, its limit, and an optional access that keeps the readers (reads and updates), the writers (writes and updates)
or the updates. A site carries its access, a read and a write on one line are two sites, and the answer counts every
site by kind past the floor whatever access it keeps, and in `ambiguous` the member uses of the name that bound nothing
because the path could not be followed and no field of the name was unique in the file: any of the members of the
name, the selected one included, may be meant. That count is a counter on the resolution the query already runs.

**`find_references` answers who reads and who sets.** ADR 4.1 records the tool's surface. One record per enclosing
symbol, site kind and confidence band, its lines joined in `at=`, because a field one generated table writes thousands
of times otherwise fills the 500-site cap with one function. Revised 2026-10-19: the records come grouped by file, the
files with the most sites first, 100 sites listed and 50 more files counted (ADR 4.1).

**Revised 2026-10-18: TypeScript, JavaScript and Python record data sites, each with its own tiers.** A script language
spells no type for most values, so three tiers join the graph's two, each behind a convention a language sets. A member
of `this` or `self` binds the member of the class around the use at 85, else one a base declares at 80, where every base
searched before it was found without a guess. A non-empty path, where receivers name owners, binds the member of that
owner its file or one included file declares at 85, or, where a qualified name starts with its module, the definition
outside every owner of the one included module whose name the path ends, `mod.LIMIT` after `import mod`, at 85.
`ValueUses::Imported` binds a bare use the file does not declare through its includes: an included file that exports
the name at 70, a re-export chain at 65, and an unexported declaration of one included file only where neither offers
the name, since Python imports a name whatever its underscore says. `UntypedMembers::Unbound` turns the file's one
field off for a family; `ambiguous` then counts those uses.

**TypeScript and JavaScript** record, inside a definition, each member taken without a call and each use of a
module-level variable or constant the file imports or declares, before its declaration too, as a body runs once the
module has run. A write is the left of `=`, a name a destructuring pattern there holds, or a key, plain or quoted, of
an object literal whose type is written beside it as an annotation, `as` or `satisfies`. A member names its owner
through `this`, the one type its value's declaration spells, `p: Props`, `const cfg: Config` or `new Pool()`, or a
class or an import by name. The file's one field of the name is off: it was the member the value held in 32 of 50
sampled sites of the monorepo. By hand, 50 sites a tier: `this` 50 of 50, a typed or named owner 50 of 50, typed
literal keys 50 of 50, module values 50 of 50, imported values 50 of 50, re-exports 16 of 16, the whole pool. The
monorepo's 4,196 TypeScript and JavaScript files gain 66,135 uses, 62,938 reads, 3,059 writes and 138 updates, and the
game-engine tree's 263 files 95,970. Left out: a member of a value whose declaration spells no type, a field
initializer that is not a function, which holds no scope for its calls either, a computed member `obj["k"]`, and a read
before a later `let` of the name in its block.

**Python** declares the fields ADR 3.12 revises and records, inside a definition, each attribute taken without a call
and each use of a name the module binds. Python binds a name for the whole scope that binds it, so a use waits in the
scope that holds it until that scope closes, as a call does, and a `global` declaration gives the name to the module.
An attribute on a method's first parameter is an own-receiver use; on a name the module binds to a class, a function
or an import, a member of that owner; on anything else, a module value included, the one field of the name in its file,
which bound right in 46 of 50 sampled sites and stays on. A bare name the module binds, by an assignment, an import, a
`def` or a `class`, is a use of it. By hand on the game-engine tree, 50 sites a tier: `self` 50 of 50, a base 50 of 50,
a named owner 50 of 50, module values 50 of 50, imported values 50 of 50, module members 50 of 50 from a pool of 286;
the tiers were sampled before the last review fixes, which only move a use away from a binding. The tree's 1,215 Python
files gain 65,410 uses, 59,305 reads, 5,806 writes and 299 updates. Left out: a class body at module level, which no
definition holds; a module imported under an alias, `import a.b as m`, or named by a dotted path, `a.b.X`; and a
parameter default, looked up in its function's scope as ADR 3.12 accepts for calls.

**Reaching a function counts for dead code.** A function imported and passed as a value, a method taken through `this`
or `self`, and a Python function the module defines taken as a value now reach their definitions, which revises ADR
3.23's note that no extraction records a function passed as a value for these cases, so `dead_code` reports fewer:
4,270 to 3,990 TypeScript and JavaScript definitions on the monorepo, 490 to 469 on the game-engine tree, and 1,000 to
780 Python ones there. A Python class taken as a value is a use too, but `dead_code` judges no Python class.

**Revised 2026-10-19: a function or class a TypeScript or JavaScript module declares is used where it is taken as a
value.** A name the module binds at its top level by a `function`, `function*` or `class` declaration and spells
without a call or a `new`, `setTimeout(tick)`, `{ queryFn }` or `Component={Panel}`, is a bare use of it, as an imported
name and a module variable already were; a body that binds the name again hides it, and the declaration's own name is
no use. A function or class declared in a block outside every body stays out: binding a block's functions as they are
declared recorded not one more use on either tree, and covering them whole means hoisting each block's declarations. On
the monorepo snapshot's 2,095 TypeScript and JavaScript files the uses grow from 33,044 to 33,239 and on the game-engine
tree's 263 from 95,974 to 96,224, and `dead_code` reports 2,005 to 1,863 and 469 to 454 definitions, adding none. By
hand, each of the 15 definitions that left the game-engine tree's list and 30 sampled of the 142 that left the
monorepo's is taken as a value in its file: a handler registered, a callback passed, a React Query option, a component
passed as a property, 45 of 45. The reference reports none of the 15 dead.

**Revised 2026-10-18: C++ records its data sites.** Only a function's initializer list and body yield uses, since a
definition's head holds annotation macros the grammar reads as names (`PX_FORCE_INLINE void f()` gave `void` 10,656
times). `x.f` and `x->f` off a call's callee are member uses on a path that is the class's bare name where `x` is a
local or a parameter declared as a value of it or a reference to it for `.`, a pointer to it for `->`, else empty;
`this->f`, a constructor's initializer list and its writes are on the own receiver, and a designated initializer writes
the field of the type its declaration or compound literal spells. A bare name no local, parameter, capture or enclosing
template parameter declares before it stays a bare use: C++ looks it up in the class, then in the namespaces. The walk
keeps a scope stack in its one pre-order pass, following every declarator the crate's data symbols follow and a
reference declarator's unnamed child, range-for, structured bindings and init-captures. Enumerators and macros are
kept: the walk cannot tell them from a value another file declares, and an all-caps test drops the file's own
`static const`s. C++ binds through tiers of its own in place of the script ones, each behind the convention that
states the C++ rule it follows: the own receiver and a bare name in a member take the class-scope lookup, as a bare
name in a member reads the class first (`OwnMembers::First`); a path takes the class the file includes or reaches, as
includes are transitive; and past them `ValueUses::Included` and `UntypedMembers::IncludedField` follow the includes:

- a member of the own receiver, or a bare name in a member: the own class's field at 85, else the field of the one
  base the lookup of a bare call certainly finds (`Shape::Inherited`) at 85; a base it only admits beside free
  definitions, or several bases, counts the use as ambiguous;
- a member on a value whose path names a class: that class's field at 85, else the field of the one base of it that
  declares the name at 85; a name the graph holds no type of binds nothing, and a type the graph holds that neither
  declares, an alias most often, leaves the use to the tiers that read no type;
- then a member: the one field of the name in the file at 80, in its direct includes at 70, then, for a name at most
  32 fields share, in the files those reach at 70; a bare name past the class: the one namespace-scope variable or
  constant of the name in the file at 80, the direct includes at 70, the files those reach at 70 for a name at most 32
  values share, a declaration and its definition counting once.

Where several classes share the bare name a path or the own class names, the one the file declares or includes binds,
then one its includes reach; a class of the name the file reaches neither way binds nothing, and the use counts as
ambiguous where it names a field. `find_references` on a C++ field notes that a member on a value whose type the
graph cannot name binds only where one field of the name is in the file or its includes, and that `ambiguous=` counts
the rest.

**Revised 2026-10-19: a C++ function named without a call is a use of it.** The walk already kept `register(f)`,
`&f` and `cb = f` as bare uses of `f`, and the namespace-value tiers bound only a variable or a constant, so a callback
reached its definition nowhere. A free function now binds in those tiers beside the values, at 80 in the file and 70
through the includes, a declaration and its definition counting once; a type or a macro of the name still binds no
use. On the game-engine tree 9,272 definitions `dead_code` judged dead are reached, 9,237 functions and 35 methods
whose free namesake or counterpart a use now reaches, and none becomes dead: 128,721 dead C++ definitions fall to
119,449. By hand against the source, seeds 11 and 41: the file tier 49 of 50 right, the miss a cast to a type that a
vendored copy's misparsed header holds as a function; the include tier 27 of 30, the misses two members the class

**Revised 2026-10-19: a header's `extern` value and its definition are one value.** A namespace-scope value takes its
qualified name as the key a function takes its signature as (ADR 3.3): `extern` without an initializer declares it,
anything else defines it, and a file-local value takes none. A declaration links to the definition whose file reaches
it, so a use bound to the header's declaration counts at the definition, as a call does. On the game-engine tree 1,181
values are declared in a header and in a source; 269 of them gather 1,178 sites at their definition, as
`targetSignatureSettings` from 340 to 463 and `g_driver_state` from 184 to 243, and the rest have uses on one side
only, or a definition that does not include the header.

**Revised 2026-10-19: a qualified name read without a call is a use.** `Config::kLimit`, `&Widget::draw` and
`ns::Box<int>::empty` use their last name on the path of the scope's last segment, the class's bare name as a declared
value's path is, and `::limit` is bare; a callee stays a call and a type no use. The class tier binds a method of the
owner beside its field, as a method taken as a value, and a scope that names no type the graph holds, `std::` and the
namespaces most often, binds nothing. The game-engine tree gains 249,843 uses, 4 MB at 16 bytes, and 1,361 more
definitions are reached, 1,324 methods and 37 functions, none becoming dead; by hand, seed 11, 40 of 40 reached

**Revised 2026-10-19: an initializer outside every body names what the file reaches.** `{by_file_ctrl, ...}` and
`Handler h = on_event;` at namespace scope, or a member's default, record each name they read as a use at file scope,
which binds no edge and keeps only the name, as Puppet's top-level code does: `dead_code` counts every definition of
that name the file sees as reached (ADR 3.23). A lambda outside a body declares locals the walk does not follow, so it
yields nothing. On the game-engine tree 10,035 more definitions are reached, 9,665 functions and 370 methods, none
becoming dead; by hand, seed 41, 30 of 30 are named in their own file outside a call, an OpenSSL or libcurl method

**Revised 2026-10-19: a daslang function taken by its address is a use of it.** `@@f` and `@@mod::f`, typed or not,
are the one form daslang passes a function as a value in; they record a bare use of `f` and one qualified by `mod`,

**Revised 2026-10-19: a Quirrel name read where no call takes it is a use of it.** `subscribe("evt", onEvent)`,

**Revised 2026-10-19: a Lua name read where no call takes it is a use of it.** An argument, `table.sort(t, compare)`,
a value an assignment, a `return` or a loop takes, a field's value, `{ on_click = handler }`, an operand and a

The graph holds 3,517,268 C++ uses: 3,005,875 reads, 468,841 writes, 42,552 updates. dhat, tree-sitter routed through
it, places the warm heap peak in the last resolution batch, 777 MB against 694 MB, and 734 MB against 658 MB after the
build. Of the 82 MB at the peak the stored uses take 52 (56 MB once all are stored, 16 bytes each), the index from a
used name to its files 22 for 265,177 names, the batch's decoded uses and their strings 8. That is the data's own
cost. A 12-byte record without the path slot saves at most 14 MB and drops the 675,116 uses bound through a declared
class's path, a fifth of the C++ uses: not taken.

With the large-allocation cache off, the footprint after the build grew 64–94 MB in the rounds above, and up to 139 MB
in other series of the day, where dhat's heap grows 76 MB. The allocator's own count (`heap`) and its regions
(`vmmap`) place what dhat does not see. The allocator holds 96 MB more than on `main`, 20 MB past dhat's count, since
a block takes its whole size class: 15 MB of it is the stored uses, which `collect` grows to a power of two and macOS
shrinks in place, keeping the larger class. The names and paths only uses spell add 2 MB of text and 106,280 strings
to the C++ graph's string arena, whose 204 MB capacity dhat counts on both sides. The rest is pages of the
small-allocation regions that hold no live block, and those differ by 30–50 MB between runs of one binary. Four ways
to give it back were built and measured, warm and alternating: storing each file's uses at their exact size, under
Considered Options; one arena a graph for every file's uses, a million at a time, which kept the footprint within
10 MB of the revision's either way; resolving 1,024 or 256 files at once in place of 4,096, which raised it 19–31 MB;
and decoding the C++ uses without their name and path strings, which moved it no more than the noise. Decoding the
uses and storing none left the footprint between 8 MB under and 26 MB over `main`'s, so a decode that borrows its
texts from the encoding or interns them has little to give back. None is taken: what grows is the uses, their index
and the allocator's classes around them.

## Considered Options

- **Fields by name only, no type paths** — the by-name tiers bound 12 of 24 sampled sites right where the path was cut,
  against all of those bound through the path.
- **The package and import tiers by name** (5,331 sites on the monorepo in the research prototype) — 12 of 24 right,
  below the 90% a tier needs: test tables and anonymous structs bind namesakes.
- **The one field of the name in the family** — 2 of 7 right in C++: the field is the only one because the real struct
  was not extracted.
- **Access and form in fields of their own** — 4 bytes a use more, 16 MB on the Go monorepo, for no answer.
- **Each use's name and path spelled in full in the encoding** — the cost the paragraph above measures.
- **Each file's uses stored at their exact size**, counted before they are stored — 180 MB less allocated over the
  warm Go monorepo build and the same heap, but 10–55 MB more resident after the build on macOS in four rounds. On
  the C++ tree it frees the 15 MB of power-of-two capacity the allocator holds, yet the footprint after the build, with
  the large-allocation cache off, came out 20–50 MB lower in two series of three alternations and about 30 MB higher
  in two of eight: the freed capacity stays among live blocks.
- **A decoded use with boxed strings** — 8 to 16 of its 72 bytes, 4 to 8 MB of the batch at the peak, for a `UseRef`
  that holds its texts unlike every other extracted site.
- **A prefixed qualifier string** (`@r` + path), the prototype's shortcut — a string per distinct receiver and access.
- **Resolve field accesses at the build and store edges** — what ADR 3.7 rejected for calls: a transient peak 1.3–1.7
  times larger, and re-resolution across files on every edit.
- **Writes only** (15–17% of accesses) — answers "who sets" but not "where is it used".
- **A new tool for field uses** — `find_references` already promises the question, and a tool description costs every
  session.
- **Extraction when a query asks, through the trigram index** — no build memory, but a common member name reaches
  thousands of files a query, and the content index is optional.
- **Argument binding (L2) and stored def-use chains (L3)** — the first duplicates `find_callers` and one read per call,
  about 32 MB on the C++ tree with half the arguments in calls that bind nothing; the second takes two to four times the
  call storage, and a three-hop chain survives whole in about an eighth of cases.
- **One record per site** — up to 11 times the tokens where one function touches the field many times, and equal where
  each touches it once.
- **A C++ base the lookup only admits beside free definitions** (28,812 uses in the research prototype) — 6 of 30
  right: generated parameter structs share a name across namespaces and two vendored copies.
- **C++ names filtered at extraction by spelling**, enumerator-like or all-caps — the walk sees one file, and 3,967 of
  10,428 same-file constants it binds are all-caps `static const`s.
- **Leaving the C++ name index out** — 22 MB. `references` scanning every file's uses answers the same: `Point3::x`
  in 55–59 ms against 54–58 ms through the index, `PhysicsBase::currentState` 11–13 ms against 8 ms,
  `DagorDateTime::year` 3.6–3.9 ms against 0.5–0.7 ms, about 3 ms a name. Scanning only the files that include the
  field's file, directly or through others, takes 46 ms for `Point3::x` and counts only their ambiguous uses, 12,939
  of 27,120. A query stays in tens of milliseconds either way, but `find_unused` resolves the uses of the name of every
  function, method and macro it weighs, as the impact walks do of every symbol they reach, and either scan pays its
  milliseconds once a name there: not taken.

Open: a qualified field name that several copies share, `Config.Timeout` across packages or a nested worktree's copy,
selects no symbol, and the agent pins it with the qualified name `find_symbols` gives; listing the candidates with their
counts needs its own measurement of the answer's size. A value of an anonymous struct type records the empty path, so
its member uses count as ambiguous and can take the file's one field of the name.

Open for C++: a value a namespace qualifies, `ns::value`, binds nothing, and an initializer outside a body binds no
edge; a class matched by its bare name binds a vendored twin's field.

Revisit when `find_unused` and `impact_of_change` judge data, or when a value's anonymous type gets a path of its own.
