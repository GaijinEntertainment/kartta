# Record each read and write of a field or a value, and bind it when a query asks

- **Status:** accepted
- **Date:** 2026-10-18
- **Updated:** 2026-10-23
- **Initiative:** `03-code-graph`
- **Governs:** `kartta_lang::{UseRef, Receiver, Access, ValueUses, UntypedMembers, OwnMembers, DataUses}`,
  `crates/kartta-graph/src/{resolve,members,typed,calls}.rs`, `Graph::references`, `SiteQuery`
- **Pinned by:** `crates/kartta-graph/tests/graph/typed.rs`, `crates/kartta-graph/tests/graph/members.rs`

"Who reads or writes `Config.Timeout`?" needs the field accesses beside the calls, and an agent grepping a short member
name reads thousands of unrelated lines. Each file records its uses of names outside a call as written,
with how each touches its target and what it is written on, and a query binds the uses of the name it asks about, so
each query pays the binding and the build pays only the uses' storage.

## Decision

**What a use records.** A `UseRef` keeps the innermost symbol around the use, the name as written, its `Receiver`, its
`Access` and its line. The access is a read (a use as a type included), a write (the left side of `=`, a key of a
literal that builds the owner) or an update that reads and writes (`+=`, `++`). The receiver is bare; a module
qualifier; the enclosing member's own receiver (`this`, `self`, or none written where the language reads a bare name as
a member); or a path, the type a value's declarations spell as the language's receivers convention says (ADR 3.29),
empty where the language cannot name it. A use at file scope binds no edge, and the graph keeps only its name
([ADR 3.112](./3.112-keep-the-names-a-file-s-top-level-calls-and-uses.md)). Which sites each language records is
its own rule:

- Go: [3.60](./3.60-record-every-go-data-site-its-walk-can-place.md), and its anonymous structs
  [3.61](./3.61-name-a-go-anonymous-struct-by-the-names-that-lead-to-it.md);
- TypeScript and JavaScript:
  [3.62](./3.62-record-typescript-and-javascript-data-sites-through-what-a-value-declares.md);
- Python: [3.63](./3.63-record-python-data-sites-in-the-scope-that-binds-them.md);
- C++: [3.64](./3.64-record-c-plus-plus-data-sites-and-bind-them-as-class-scope-lookup-does.md), and its namesake
  classes [3.65](./3.65-tell-c-plus-plus-namesake-classes-apart-by-the-scopes-a-use-writes.md);
- daslang, Quirrel, Lua and Rust: [3.66](./3.66-record-a-name-a-script-or-rust-reads-without-a-call-as-a-use.md);
- PHP, Ruby and Bash, and why Puppet and BLK record none:
  [3.67](./3.67-record-a-function-a-string-or-a-symbol-names-as-a-use.md).

DSHL records the uses ADR 3.18 states. A use is kept in 16 bytes, as
[3.68](./3.68-keep-a-use-in-16-bytes-and-spell-its-text-once-a-file.md) states, and `Graph::stats` counts the reads,
the writes and the updates apart.

**How a query binds it.** Uses are bound when a query asks, as calls are (ADR 3.7), and nothing is stored. Past the
class-scope lookup, a bare or qualified use binds no field, enum variant or local symbol.

- **Bare:** the class-scope lookup first where the language sets `OwnMembers::First` (ADR 3.64), then by `ValueUses`:
  `Declared`, the definition outside every owner and body its own file declares at 80, a dot-imported package's at 95,
  its package directory's at 75 where packages are directories; `Imported`, its own file's at 80, then the one included
  file that exports the name at 70 (two bind none), a re-export chain from them at 65, then the one included file that
  declares it unexported at 70; `Included` is C++'s (ADR 3.64).
- **Qualifier:** only through the file's import of that module, an exported package-level definition at 95.
- **Own receiver:** under `OwnMembers::First` the class-scope lookup; otherwise the member of the class around the use
  at 85, else one a base declares at 80 where every base searched before it was found without a guess. No class around
  the use, or an unseen base before the find, counts as ambiguous.
- **A path, where receivers are type paths (Go):** a field or a method of the type the path reaches, or of a type it
  embeds, at 85. A path into code outside the graph, an undeclared name, or a type without the member binds nothing and
  stops. A path the graph cannot follow goes to the untyped tier.
- **A non-empty path, where receivers name owners:** the member of that owner its file or one included file declares at
  85 (two included files count as ambiguous); else the definition outside every owner of the one included module whose
  name the path ends, at 85; else a type of that name the file or one include declares at 85, then its bases at 80 under
  the same no-guess rule. Otherwise it binds nothing, and no untyped tier is tried; C++ reads includes further
  (ADR 3.64).
- **The empty path, the untyped tier:** by `UntypedMembers`. `FileField`, the one field of the name its file declares
  outside every body but the use's own, at 80, none or several counting as ambiguous; `Unbound`, nothing, counted as
  ambiguous; `IncludedField` is C++'s (ADR 3.64).

**What a query answers.** Fields, variables and constants are referents of `Graph::references`, which takes a
`SiteQuery`: a confidence floor, a limit, and an optional access that keeps the readers (reads and updates), the
writers (writes and updates) or the updates, and drops calls. A site carries its access, so a read and a write on one
line are two sites. The answer counts every site by kind past the floor whatever the access keeps. Its `ambiguous`
counts, for a member, the uses of its name that the tiers left ambiguous, and, for any root, the calls of the name that
`Walk::ambiguous` counts, so `find_references` and `find_callers` give one number for them; both counts ride on the
resolution the query already runs. [ADR 4.11](./4.11-group-a-symbol-s-references-by-file-the-busiest-first.md) states
how `find_references` renders the sites.

**Who else reads them.** `find_unused` judges a language's fields, variables and constants by their uses only where it
sets `DataUses::Every`, Go alone
([ADR 3.110](./3.110-judge-a-language-s-data-only-where-it-records-every-read-and-write.md)), and the impact walks go
from a field, a variable or a constant to its users in every language
([ADR 3.132](./3.132-walk-from-a-field-a-variable-or-a-constant-to-its-users.md)). Both bind the uses when a query
asks; the build does no work for them.

## Why

- A quarter to a half of every graph's definitions are fields, variables and constants, and before this no query could
  select one: `find_references` answered no symbol, or a namesake type or method.
- Binding when asked keeps a use valid however other files change, as ADR 3.7 argues for calls.
- The type path binds what the source reads: 64 of 64 sampled sites on the Go monorepo, where the file's one field bound
  37 of 38 right and names alone bound half (2026-10-18).

## Consequences

- The uses and their name index are the cost: the heap after a warm Go monorepo build holds 364 MB against 317 MB, and
  after the C++ game-engine tree's 734 MB against 658 MB (2026-10-18). Accepted.
- `references` of a busy field takes tens of milliseconds, `Point3::x` with 4,275 sites 54-77 ms on the C++ tree.
  Accepted.
- An untyped member under `FileField` can bind a namesake field of its file, as a value of an anonymous struct did.
  Accepted.
- `find_unused` leaves the data of every language but Go unjudged, since none records every read and write. Accepted.
- An owner-qualified name that several packages' types end with selects no symbol; ADR 3.35 answers with the
  candidates.

## Rejected

- **Fields by name only, no type paths** — bound 12 of 24 sampled sites right where the path was cut.
- **The one field of the name in the family** — 2 of 7 right in C++: the field is the only one because the real struct
  was not extracted.
- **Resolve uses at the build and store edges** — what ADR 3.7 rejected for calls: a transient peak 1.3-1.7 times
  larger, and re-resolution across files on every edit.
- **Writes only** — answers "who sets" but not "where is it used".
- **A new tool for field uses** — `find_references` already promises the question, and a tool description costs every
  session.
- **Extraction when a query asks, through the trigram index** — a common member name reaches thousands of files a
  query, and the content index is optional.
- **Argument binding and stored def-use chains** — the first duplicates `find_callers`; the second takes two to four
  times the call storage, and a three-hop chain survives whole in about an eighth of cases.
- **One record per site in `find_references`** — up to 11 times the tokens where one function touches the field many
  times.

## Revisit if

Binding a name's uses when asked grows past the answer's budget, as `find_unused` and the impact walks bind every name
they weigh. The busiest field measured binds in tens of milliseconds; held with high confidence on the measured trees.
