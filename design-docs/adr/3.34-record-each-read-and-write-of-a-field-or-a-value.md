# Record each read and write of a field or a value, and bind it when a query asks

- **Status:** accepted
- **Date:** 2026-10-18
- **Revised:** 2026-10-18
- **Initiative:** `03-code-graph`

The graph recorded calls and, for Go and DSHL, the uses of a type or of a package-qualified value; it recorded no field
access, no read of a package's own value, and no write of anything. `find_references` could not select a field at all,
so "who reads or writes `Config.Timeout`?" answered no symbol, or a symbol of the same name: `MaxRetries` a method,
`Timeout` a type. A quarter to a half of every graph's definitions are fields, variables and constants. An agent then
greps a short member name, which matches thousands of lines across unrelated types, and that is where grep is weakest.

**A use says how it touches its target and what its name is written on.** `RefSite` carries an `Access` — a read, a
write (the left side of `=`, a key of a literal that builds the owner), or an update that reads and writes (`+=`, `++`)
— and a `Receiver`: a bare name, a name qualified by a module, a member of the enclosing member's own receiver (`this`,
`self`, implicit), or a member of a value whose type a path spells as the language's receivers convention says (ADR
3.29), empty where the language cannot name the type. A use as a type reads its target. The codec moves to layout 4 and
`kartta_lang::FINGERPRINT` with it, so a cache never serves an extraction of the old contract. An encoded use writes a
name or a path an earlier use of its file spelled as the index of that text: one value's path and one field's name
repeat across a file, and the build holds every file's encoded extraction until it resolves the file (ADR 1.18).

**The graph keeps a use in the 16 bytes it took.** The receiver's form and the access ride in the top four bits of
`site_of`, and the qualifier or the path, interned, in the slot the qualifier had; a use inside a definition past the
2^28th of its file is not kept. `Graph::stats` counts the reads, the writes and the updates apart.

**Go records every data site its walk can attribute.** A selector on a value that is not a call's callee is a member
use with the operand's type path, so a method taken as a value (`RunE: c.run`) is a use of the method. A key of a struct
literal writes its field, the literal's type spelled where written and taken from the enclosing slice or map literal
where elided; an anonymous struct's keys are kept as nothing, since no symbol holds its fields. An identifier in a body
that no local, parameter, type parameter or declaration binds, that is not predeclared, a callee or an import's name, is
a bare use of a package-level value or function: the walk sees one file, so it keeps the name and the graph binds it
only where some file of the package declares it. Assignments, `range` and `select` receives that assign with `=`,
`++`, `--` and `op=` mark the outermost expression on their left; `a.b` in `a.b.c = v` is read.

**A member use binds when a query asks, in two tiers.** Through the type its path reaches, a field or a method of that
type or of a type it embeds, at 85; a path into code outside the graph, an undeclared name or a type without the member
binds nothing and stops. A path the graph cannot follow, or none, binds the one field of the name its own file declares
outside other bodies, at 80. A bare use keeps the cascade it had (ADR 3.7); an own-receiver use binds nothing until a
language records one with its tier. Fields become referents of `Graph::references`, which takes a `SiteQuery`: its
floor, its limit, and an optional access that keeps the readers (reads and updates), the writers (writes and updates)
or the updates. A site carries its access, a read and a write on one line are two sites, and the answer counts every
site by kind past the floor whatever access it keeps, and in `ambiguous` the member uses of the name that bound nothing
because the path could not be followed and no field of the name was unique in the file: any of the members of the
name, the selected one included, may be meant. That count is a counter on the resolution the query already runs.

**`find_references` answers who reads and who sets.** ADR 4.1 records the tool's surface. One record per enclosing
symbol, site kind and confidence band, its lines joined in `at=`, because a field one generated table writes thousands
of times otherwise fills the 500-site cap with one function.

**Revised 2026-10-18: TypeScript, JavaScript and Python record data sites, each with its own tiers.** A script language
spells no type for most values, so three tiers join the graph's two, each behind a convention a language sets. A member
of `this` or `self` binds the member of the class around the use at 85, else one a base declares at 80, where every base
searched before it was found without a guess. A non-empty path, where receivers name owners, binds the member of that
owner its file or one included file declares at 85, or, where a qualified name starts with its module, the definition
outside every owner of the one included module whose name the path ends, `mod.LIMIT` after `import mod`, at 85.
`ValueUses::Imported` binds a bare use the file does not declare through its includes: an included file that exports
the name at 70, a re-export chain at 65, and an unexported declaration of one included file only where neither offers
the name, since Python imports a name whatever its underscore says. `UntypedMembers::Unbound` turns the file's one
field off for a family; `ambiguous` then counts those uses.

**TypeScript and JavaScript** record, inside a definition, each member taken without a call and each use of a
module-level variable or constant the file imports or declares, before its declaration too, as a body runs once the
module has run. A write is the left of `=`, a name a destructuring pattern there holds, or a key, plain or quoted, of
an object literal whose type is written beside it as an annotation, `as` or `satisfies`. A member names its owner
through `this`, the one type its value's declaration spells, `p: Props`, `const cfg: Config` or `new Pool()`, or a
class or an import by name. The file's one field of the name is off: it was the member the value held in 32 of 50
sampled sites of the monorepo. By hand, 50 sites a tier: `this` 50 of 50, a typed or named owner 50 of 50, typed
literal keys 50 of 50, module values 50 of 50, imported values 50 of 50, re-exports 16 of 16, the whole pool. The
monorepo's 4,196 TypeScript and JavaScript files gain 66,135 uses, 62,938 reads, 3,059 writes and 138 updates, and the
game-engine tree's 263 files 95,970. Left out: a member of a value whose declaration spells no type, a module-level
function or class the file declares taken as a value, a field initializer that is not a function, which holds no scope
for its calls either, a computed member `obj["k"]`, and a read before a later `let` of the name in its block.

**Python** declares the fields ADR 3.12 revises and records, inside a definition, each attribute taken without a call
and each use of a name the module binds. Python binds a name for the whole scope that binds it, so a use waits in the
scope that holds it until that scope closes, as a call does, and a `global` declaration gives the name to the module.
An attribute on a method's first parameter is an own-receiver use; on a name the module binds to a class, a function
or an import, a member of that owner; on anything else, a module value included, the one field of the name in its file,
which bound right in 46 of 50 sampled sites and stays on. A bare name the module binds, by an assignment, an import, a
`def` or a `class`, is a use of it. By hand on the game-engine tree, 50 sites a tier: `self` 50 of 50, a base 50 of 50,
a named owner 50 of 50, module values 50 of 50, imported values 50 of 50, module members 50 of 50 from a pool of 286;
the tiers were sampled before the last review fixes, which only move a use away from a binding. The tree's 1,215 Python
files gain 65,410 uses, 59,305 reads, 5,806 writes and 299 updates. Left out: a class body at module level, which no
definition holds; a module imported under an alias, `import a.b as m`, or named by a dotted path, `a.b.X`; and a
parameter default, looked up in its function's scope as ADR 3.12 accepts for calls.

**Reaching a function counts for dead code.** A function imported and passed as a value, a method taken through `this`
or `self`, and a Python function the module defines taken as a value now reach their definitions, which revises ADR
3.23's note that no extraction records a function passed as a value for these cases, so `dead_code` reports fewer:
4,270 to 3,990 TypeScript and JavaScript definitions on the monorepo, 490 to 469 on the game-engine tree, and 1,000 to
780 Python ones there. A Python class taken as a value is a use too, but `dead_code` judges no Python class. A
module-level function a TypeScript or JavaScript file declares and takes as a value stays the cross-language follow-up
on functions passed as values.

The C++ graph is the same on both sides, no use recorded; the tree's Go files gain 29,973 uses beside their 4,108
calls, its heap under dhat is the same byte for byte with and without the text table below, and the C++ rows move
within the noise of the machine.

The Go graph holds 4,031,079 uses where `main` held 1,700,043: 3,249,618 reads, 770,738 writes and 10,723 updates.
Stored, the 2.33M new uses take 37 MB at 16 bytes, and the index from a used name to the files that use it 9 MB more;
a layout with the access and the form in fields of their own takes 20 bytes, 16 MB more for the graph's 4.03M uses.
dhat, with tree-sitter routed through it, places the warm build's heap peak inside resolution, with the graph half
grown and a batch of 4,096 files decoded (ADR 3.6): 463 MB against `main`'s 401 MB. Of the 61 MB, the uses stored so
far take 23 and their name index 9; the batch's decoded uses take 21 more, at 72 bytes a use against 56 for a use
without access and receiver, and their name and path strings 6; the encoded extractions not yet resolved take 4. After
the build the heap holds 364 MB against 317 MB, the stored uses and their index. The warm resident set grows 97–121
MB, but with `MallocLargeCache=0` the footprint after the build grows 30–38 MB, the heap's growth: the rest is memory
the build freed and macOS keeps for reuse, which a bigger decoded batch leaves more of. That cost is the trade for
answering a field: an agent's grep for a member name reads thousands of unrelated lines, and not one data question had
an answer before.

Spelling each use's name and path in full cost more: the encoded extractions took 271 MB over the warm build where
`main`'s take 215 MB and the text table's 218 MB, the cache of both trees 489 MB where `main`'s and the table's take
454 MB, and the warm build peaked at 640–649 MB of footprint and kept 788–827 MB resident.

`references` on the Go monorepo, three rounds each: the field `config.SDKConfiguration.Timeout`, 152 sites, 1.6–2.3 ms

of 10 sites in 0.2 ms; `Name` and `ID`, which select fields of a generated table with 2,975 and 2,966 sites, 25–30 ms,
where `main` answered types with 411 and 791 sites in 4–10 ms.

The two renderings of `find_references` at the 500-site cap: `types.Library.Name`, written 2,961 times by one function,
takes 152,307 bytes as one record a site and 13,192 bytes as 37 records; `config.SDKConfiguration.Timeout`, read once
in each of 152 functions, takes 41,004 bytes either way.

Precision, by hand against the source, sites drawn from the pools of all the sites of 20,400 random fields and package
values, seeds 11 and 29, each counted once: through the type path, 64 of 64 right; the one field of the file, 37 of 38
right, the wrong one a value of an anonymous struct whose field shares a name with a field of the file (`msg.Values`
bound to `DataRow.Values`); bare reads of package-level values, 30 of 30 right. Of the member sites in the pool, 45,707
bound through the path and 169 by the file. Before the file tier excluded fields of a type another body declares, all

## Considered Options

- **Fields by name only, no type paths** — the by-name tiers bound 12 of 24 sampled sites right where the path was cut,
  against all of those bound through the path.
- **The package and import tiers by name** (5,331 sites on the monorepo in the research prototype) — 12 of 24 right,
  below the 90% a tier needs: test tables and anonymous structs bind namesakes.
- **The one field of the name in the family** — 2 of 7 right in C++: the field is the only one because the real struct
  was not extracted.
- **Access and form in fields of their own** — 4 bytes a use more, 16 MB on the Go monorepo, for no answer.
- **Each use's name and path spelled in full in the encoding** — the cost the paragraph above measures.
- **Each file's uses stored at their exact size**, counted before they are stored — 180 MB less allocated over the
  warm Go monorepo build and the same heap, but 10–55 MB more resident after the build on macOS in four rounds.
- **A decoded use with boxed strings** — 8 to 16 of its 72 bytes, 4 to 8 MB of the batch at the peak, for a `RefSite`
  that holds its texts unlike every other extracted site.
- **A prefixed qualifier string** (`@r` + path), the prototype's shortcut — a string per distinct receiver and access.
- **Resolve field accesses at the build and store edges** — what ADR 3.7 rejected for calls: a transient peak 1.3–1.7
  times larger, and re-resolution across files on every edit.
- **Writes only** (15–17% of accesses) — answers "who sets" but not "where is it used".
- **A new tool for field uses** — `find_references` already promises the question, and a tool description costs every
  session.
- **Extraction when a query asks, through the trigram index** — no build memory, but a common member name reaches
  thousands of files a query, and the content index is optional.
- **Argument binding (L2) and stored def-use chains (L3)** — the first duplicates `find_callers` and one read per call,
  about 32 MB on the C++ tree with half the arguments in calls that bind nothing; the second takes two to four times the
  call storage, and a three-hop chain survives whole in about an eighth of cases.
- **One record per site** — up to 11 times the tokens where one function touches the field many times, and equal where
  each touches it once.

Open: a qualified field name that several copies share, `Config.Timeout` across packages or a nested worktree's copy,
selects no symbol, and the agent pins it with the qualified name `find_symbols` gives; listing the candidates with their
counts needs its own measurement of the answer's size. A value of an anonymous struct type records the empty path, so
its member uses count as ambiguous and can take the file's one field of the name.

Revisit when C++ records data sites, with its own tiers and its peak located;
when `find_unused` and `impact_of_change` judge data; or when a value's anonymous type gets a path of its own.
