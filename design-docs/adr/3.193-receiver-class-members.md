# Bind a call on a known class to the member the class or its nearest parent holds

- **Date:** 2026-10-31
- **Governs:** `crates/kartta-graph/src/scope.rs` (`member_of_the_receiver_s_owner`,
  `member_above_the_receiver_s_class`, `receiver_class`, `nearest_holder`, `parents_of`, `parent_name`,
  `past_the_imports`, `held_by`), `crates/kartta-lang-daslang/src/lib.rs`, `crates/kartta-lang-php/src/lib.rs`,
  `crates/kartta-lang-python/src/lib.rs` and `crates/kartta-lang-quirrel/src/lib.rs` (`CONVENTIONS`),
  `kartta_lang::Conventions::receiver_members`, `kartta_lang::ReceiverMembers`
- **Pinned by:** `crates/kartta-languages/tests/daslang_inherited_members.rs`,
  `crates/kartta-languages/tests/php_inherited_members.rs`,
  `crates/kartta-languages/tests/php_receiver_classes.rs`,
  `crates/kartta-languages/tests/python_inherited_members.rs`,
  `crates/kartta-languages/tests/quirrel_inherited_members.rs`

A call on a class the graph holds names where the language's lookup starts, and the class's own members are only the
first place that lookup reads: `Kernel::__construct()` finds nothing in `Kernel` when the class above it holds the
constructor, and the name tiers then bind the caller's own. A language opts in, and such a call binds the member of the
nearest type above the class, at 85, by a walk every language shares over the parents its extraction records, at the
price of a member a class outside the tree holds.

## Decision

- **The class.** A call's class is the class around the caller for a receiver in `Conventions::own_type_receivers`,
  else the type of the receiver's name nearest the call. Where a bare receiver names a class, a type the caller's file
  holds or includes itself stands first, then one of the caller's scope, since PHP reads the name through the file's
  imports, else under its namespace. A class that holds a member of the name itself leaves the call
  to the tiers it took before: a class's own member reaches 85 only through a receiver that spells it
  ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md), tier 5), and 80 through the caller's own owner
  ([ADR 3.41](/design-docs/adr/3.41-own-owner-receivers.md)).
- **The walk.** Where `Conventions::receiver_members` is `ReceiverMembers::Inherited`, as daslang's, PHP's, Python's and
  Quirrel's are, a class that holds no member of the name binds the one the nearest type above it holds, at 85, ahead of
  a namesake's member and of every name tier. The types are read level by level from the `parents` of each type, a
  level's traits first, and a type holds a member only when the member sits in that type's own body, under an owner its
  qualified name ends with.
- **Quirrel's `this`.** `this` is Quirrel's own receiver, so its walk starts at the class around the caller, and a
  function value with no binding, whose calls belong to the member around it
  ([ADR 3.143](/design-docs/adr/3.143-quirrel-function-names.md)), reads as that member's class, even where the language
  leaves its `this` to whoever calls it. A function in no class has no class to start from, and `this` in a table's
  member keeps [ADR 3.166](/design-docs/adr/3.166-quirrel-member-call-ties.md).
- **Bodies first.** The walk reads the types that hold bodies. Only where none holds the member does it walk the
  interfaces as well, so a member declared and implemented nowhere above the class but in an interface binds that
  declaration.
- **Parents are language facts.** What a type names as parents is the extraction's, and the walk reads each by its last
  name, among the types the name locates from the child's file; the walk itself branches on no language.
- **Imported names.** Where `Conventions::value_uses` is `ValueUses::Imported`, a type past what the file imports is no
  parent and no receiver's class, and a parent whose first name the file binds outside the repository stands for no
  type, as `db.Base` under `import django.db as db`.
- **C3.** For Python this walk approximates the language's C3 method resolution order: the two differ where a first
  base's ancestor outranks a second base.
- **Bare calls.** A bare daslang call in a method records no receiver and reads the same parents through
  [ADR 3.197](/design-docs/adr/3.197-daslang-bare-method-calls.md).
- **Languages apart.** C++ keeps `member_of_a_base`, which also leaves two bases neither derives from ambiguous, and Go
  keeps its type paths ([ADR 3.29](/design-docs/adr/3.29-go-receiver-types.md)), which return before this tier.

## Why

- PHP's own lookup reads one method table of the object's class (`zend_std_get_method`,
  `zend_std_get_static_method` in php-src 8.5.12 `Zend/zend_object_handlers.c`). The table holds a class's own method,
  then its traits', since `zend_do_link_class` binds traits before `zend_do_inheritance` and `zend_add_trait_method`
  keeps a member of the class itself, then its parent's; the language specification states the same order
  (php-langspec `spec/16-traits.md`, Traits).
- The walk binds what that table holds: of 30 pairs drawn from each side on Laravel and Symfony and read to the parent's
  declaration, 30 of the 4,750 added and 30 of the 6,947 promoted are right, and 29 of the 1,733 removed were false
  (2026-10-31, #796).
- An interface hands a class no body, so a type above the class with a body answers first, and an interface of a
  parent's name stands in no class's place: `$this->instance()` under `Application extends Container` binds the class,
  not the contract of that name. The walk with interfaces beside the bodies differs on 97 Laravel pairs, and each of 14
  read is right under this rule (2026-10-31).
- A Quirrel class copies its base's members and applies its own body over them, replacing a method of the same name
  (`squirrel/sqclass.cpp`, `SQClass::SQClass`, `SQClass::NewSlot`, at quirrel 19f17df9;
  `doc/content/pages/language/classes.md`, Inheritance and base), so the nearest holder is the member a lookup finds.
  Every one of the 1,090 pairs the walk added or moved on the game-engine tree stands on a class chain with no holder
  between the caller's class and the target, read from the extraction over the whole pool (2026-11-01, #857).
- Quirrel's `this` is each function's own first parameter (`squirrel/compiler/codegen.cpp:1599`): the receiver of a
  member call, else the caller's own `this` (`codegen.cpp:1868`, `:1895`), and `bindenv` fixes it. The bytes settle it
  for a member and for a value bound to a slot or written with `.bindenv(this)`, and leave the rest to whoever calls the
  value. Of the 1,032 `this.f()` in function values under an owner on that tree, 588 are settled, 368 sit beside a
  `this` argument, as `performDelayed(this, f)`, and 76 are bare; the 8 pairs the walk takes from the bare ones read
  right, since the helpers that take such a value bind it to the handler (2026-11-01, #857).
- Python's lookup takes the first class of `tp_mro` whose `__dict__` holds the name (`find_name_in_mro`,
  `Objects/typeobject.c:6193` in cpython v3.15.2), and `tp_mro` is the C3 merge of the bases' orders (`pmerge`,
  `:3401`). Of the 17,035 pairs the walk adds or promotes on three venvs' site-packages, judged by each venv's
  interpreter against the class's `__mro__`, 98.0% are right (2026-11-01, #856).
- A daslang class starts as a copy of its one parent's fields, a `def` among them (`ast_structureName`, daslang
  `src/parser/parser_impl.cpp:300`), `def override` replaces the field's value in place (`:461`), and a call reads the
  class's own field (`Structure::findMethodFunction`, `src/ast/ast.cpp:518`), so the nearest class that writes the `def`
  answers. On dagor the walk adds and removes no pair and takes 5 from 80 to 85, all 5 right (2026-11-01, #858).

## Consequences

- The cost is a walk per call on a class that holds no member of the name, with no stored structure: 122.68 G to 122.71
  G instructions and 104.5 MB to 104.7 MB peak on a cold Symfony build (2026-10-31). Accepted. On Python a parent's
  lookup also builds the file's include closure: resolving every call of a 9,556-file site-packages takes 0.56 s where
  it took 0.19 s, and peak footprint goes from 264 MB to 292 MB, for 10,956 more pairs at 85 (2026-11-01).
  Accepted.
- Every class of an included file ranks as imported, since the graph holds the file a `use` names and not the class:
  one a `use function` or a `use const` maps to, or a second class beside the one a `use` imports. No class of Laravel
  or Symfony stands in a file a function or constant `use` maps to. Accepted.
- A class outside the tree above a class of the tree hides its members, so the name tiers bind them:
  `PHPUnit::assertEmpty()` on `Illuminate\Testing\Assert`, which extends PHPUnit's, binds
  `FilesystemAdapter::assertEmpty` at 60. Accepted.
- A trait a trait uses stands one level above the class, beside the class's parent's parents, where PHP's table holds it
  ahead of the parent. No pair of Laravel or Symfony turns on it (2026-10-31). Accepted.
- `insteadof` and `as` in a `use` block are not read: the first trait that holds a name answers, and an alias binds
  nothing. Three Symfony classes write `insteadof`. Accepted.
- An abstract member of a trait answers ahead of a parent's body, where `zend_do_link_class` binds such a member after
  inheritance so that the body stays: `HasOne::getResults` binds `ComparesRelatedModels::getParentKey`, not
  `HasOneOrMany`'s. 2 Laravel pairs. Accepted.
- A Quirrel function value that its caller hands another `this` still reads as the member's class. No sampled pair of
  the game-engine tree turns on it. Accepted.
- A Quirrel class with no name, `register(class (Base) {})`, is no type the graph holds
  ([ADR 3.143](/design-docs/adr/3.143-quirrel-function-names.md)), so no walk starts there: 1,415 `this.f()` of the
  game-engine tree stay with the name tiers. Accepted.
- A Quirrel table's delegate is no parent, though a lookup falls through to it (`squirrel/sqvm.cpp:2472`): the
  extraction records none, and the game-engine tree writes 4 `setdelegate` or `delegate` calls. Accepted.
- Python's C3 order answers a first base's ancestor ahead of a second base where the walk takes the nearer level:
  `GenericClass(DefineGenericBaseClass, ClassMixin)` binds `ClassMixin.py__name__`, not `HelperValueMixin`'s. 8 pairs of
  the six Python trees. Accepted.
- A Python base's last name ties across the namesakes the imports reach, so `class Linear(nn.Linear, TinyLoraLayer)`
  reaches peft's other `Linear`. `self.m()` in a nested class stays with the tiers, since `class_of` reads no chain, and
  `class Child(B)` under `from base import Base as B` has no parent, which is 187 of the 38,149 bases written as a
  bare name on the three venvs. Accepted.

## Rejected

- **Replace `member_of_a_base` with the shared walk** — moved +1,893 -1,151 on the C++ game-engine tree, and 513 of the
  removed pairs are `HashMapBase` and `HashSetBase` members a PhysX `HashMap` does reach (2026-10-31).
- **Interfaces in the one walk** — an interface of a parent's name hides the class, and a level's interface answers
  ahead of a body farther up, as `Enumerable::unless` ahead of `Conditionable::unless` (2026-10-31).
- **Drop the other concrete classes' members from a call the walk does not bind** — about 17 of 30 removed pairs were
  right on PHP: facades forward through `__callStatic`, and a trait's `$this->m()` reaches a member of the class that
  uses it (2026-10-31).
- **Read Quirrel's `this` as the member's class only where the bytes settle it** — turns away 74 of the 1,090 pairs, of
  function values beside a `this` argument or bare, to keep out a mistake no pair read shows (2026-11-01).
- **C3 for Python's walk** — built: 16,690 of the 17,033 judged pairs right against 16,697, because a tie among a base's
  namesakes puts the wrong one's ancestors ahead of the second base: of the 24 pairs of the six trees where the orders
  differ, 14 are right under the level walk, 8 under C3 and 2 under neither (2026-11-01).

## Revisit if

The extraction records the names `insteadof`, `as` and an alias's base give; a Python base resolves through its import
to one type, which takes away C3's loss; or a language joins whose lookup a level-by-level walk misreads past these.
High confidence for PHP's single inheritance plus traits and for Quirrel's single base, medium for Python.
