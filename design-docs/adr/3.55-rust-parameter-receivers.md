A method call on a parameter, `ranking.offer()` in `fn offer(ranking: &mut Ranking)`, on a field of `self`,
`self.index.refresh_paths()` beside `struct Engine { index: Index }`, on a local, `w.drain()` after
`let w = Watcher::new()?;`, or on a chain, `o.expect("a watcher").drain()` on an `Option<Watcher>`, names a value whose
type a declaration, an initializer or a method's return type spells. The walk records that type as the receiver, which
the owner tier binds, but only where the file shows the type may be one of the tree, since that tier binds by name and
crates declare namesakes of the standard library's types. A return type the walk cannot reach from its file, the
receiver spells as a path of calls the graph reads.

## Decision

- **The declared type.** The walk keeps the type each parameter of a `fn` is declared as, for a name or `mut name`
  pattern. A method call on the name records the type's last segment, which the receiver-owner tier of
  [ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md) binds at 85.
- **A field of `self`.** A method call on a named field of `self`, `self.index.m()`, records the type the field is
  declared as, where the impl around the call names its type by a bare name and the struct or union of that name is
  declared beside the impl, in the same module or block. Any other named field, one whose struct is declared elsewhere
  or whose type gives none, records its name after a `.`, `.index`, as a value does
  ([ADR 3.56](/design-docs/adr/3.56-rust-call-receivers.md)), so the caller's own owner tier does not take it. A tuple
  field, `self.0.m()`, and a longer chain, `self.a.b.m()`, keep the empty receiver.
- **A local.** A `let` of a name or `mut name` holds the type it declares, `let x: T`, by the shapes below, or else the
  type its initializer constructs: `T::f()` or `T::f::<U>()` with `T` capitalised, `Self` included, as written or
  through `?`, `.unwrap()` or `.expect(..)`, with `.map_err(..)`, `.as_ref()` or `.as_mut()` before them, which alone
  leave a `Result` or an `Option` and name no type, or else what a method call returns, as a chain reads it. A function
  whose name ends in `builder`, and a call through `Box`, `Rc` or `Arc`, name none. A later `let` of the name replaces
  the type, and a call in a nested block or a closure sees it.
- **A chain.** A method call on another call names, under the same unwraps: the type `T::f()` constructs, read as a
  local's; what a name or a named field of `self` declared `Option<T>` or `Result<T, E>` holds, once the chain unwraps
  it; or what a method call returns. A chain inside a macro's arguments keeps the empty receiver, as does any other.
- **What a method returns.** Each function records as its value type the type its return type names, by the shapes
  below, through `Pin<P>`, after a `?` where an `Option` or a `Result` holds it. An `async` function, and a type the
  file does not show as one the tree may hold, under the rule of a local, record none. A method call on `x.m()` or on a
  local it initializes spells the receiver `T::m()`, up to eight calls long, from the type `x` names; `?` marks a call
  the chain unwraps. The graph finds each method as the owner tier does and takes the value type it gives, where the
  `?`s of the path and of the value type agree. A path that reaches no type leaves the value's name after a `.`, or
  the empty receiver for a chain.
- **Shapes that name a type.** The shapes that name a type: `T`, `&T`, `&mut T` and a path; the base of `T<..>`,
  lifetimes alone included; the pointee of `Box`, `Rc` and `Arc`; the type of the `impl` or trait around the call for
  `Self`; and the trait of an `impl Trait` or `dyn Trait` of one bound. A type parameter of the function, of the `impl`
  or trait around it, or of the struct that declares the field, a path through one or through `Self`, `T::Item`, a
  tuple, and any pattern other than a name give no type.
- **The innermost binding.** The innermost binding decides: a `let`, a closure's parameter or a pattern that binds the
  name again hides the type, and a name a closure in a macro's arguments binds is no parameter.
- **A type the tree may hold.** A type is kept only where the file shows it may be the tree's. A name a `use` brings is
  shown where the `use`'s first segment is no toolchain crate, `std`, `core`, `alloc`, `test` or `proc_macro`. The
  innermost `use` in a block around where the type is written decides first, so a `use` inside a function body reaches
  the `let`s of that body and no signature of the function; inside an inline module that module's `use`s decide before
  the file's. A path is shown where its first segment is `crate`, `self`, `super` or a module the file declares, or is
  no toolchain crate, by itself or through the file's `use` of it. A name no `use` brings is shown where the file
  declares a type of the name, or, for a parameter or a field and never for a local, where the file has a top-level
  glob and the name is none of the prelude's `Box`, `Option`, `Result`, `String` and `Vec`. Any other type leaves the
  receiver the value's name after a `.` ([ADR 3.56](/design-docs/adr/3.56-rust-call-receivers.md)).

## Why

- `ranking.offer()` recorded `.ranking`, which names no owner, so `find_callers` of `Ranking::offer` listed 6 callers
  and counted the call of kartta-fs's `offer` ambiguous, while the same call written `Ranking::offer(ranking)` bound
  (this repository, 2026-10-23, #253).
- `self.index.refresh_paths()` recorded the empty receiver, which the caller's own owner tier binds, so the call bound
  `Engine::refresh_paths` instead of `Index::refresh_paths`; on wasmtime the field rule adds 2,335 pairs and removes
  788, 29 of 30 sampled added and 30 of 30 sampled removed right (2026-10-25, #248).
- The owner tier binds by name, and a registry's crates declare namesakes of the standard library's types: a parameter
  of `std::fs::File` bound tokio's `File`, a `Vec` allocator-api2's (cargo registry of 488 crates, 2026-10-23, #253).
- 446 of the 464 pairs the rule added or raised on this repository are right, 96% (2026-10-23, #253).
- `w.drain()` after `let w = Watcher::new()?;` recorded `.w`, which names no owner, so it bound nothing or a namesake.
  On six Rust trees the local rule adds 3,626 pairs and removes 237; its weakest shape, `T::new()?`, stands at 87% of 30
  sampled right, and 97% of 30 sampled removed were right to go (2026-10-30, #484).
- A method's return type lies in another file as often as not, so `gcstore.gc_object_data(self)?.write_i32(..)` needs
  the graph, and a chain's empty receiver bound the caller's own method of the name. On six Rust trees the chain and
  method rules add 5,191 pairs, remove 406 and raise 3,126: 29 of 30 sampled added, 30 of 30 removed and 29 of 30
  raised are right (2026-10-31, #485).

## Consequences

- A call on a local of a type only a glob brings keeps the value's name, and so does a call on a field whose struct
  another file declares. A free function's return type goes unread, so `make()?.m()` and `let x = make();` name no type.
- An associated function's return type goes unread, so one that returns another type, `Factory::make() -> Product`,
  names `Factory` and can bind a namesake method of `Factory`: accepted, `T::f()` stands at 97% of 30 sampled right
  (2026-10-30, #484).
- A `use` alias keeps its spelling, so `use x::Builder as RuntimeBuilder;` then `RuntimeBuilder::new().enable_io()`
  names no owner and loses the empty receiver's binding: 2 of 30 sampled removed for `T::f()` chains. Accepted.
- Of a namesake the owner tier takes the first in path order wherever no `use` decides (#650), so the wrong pairs of the
  local rule are namesakes: 4 of 30 for `T::new()?`.
- The walk holds each name of a region with its type path, a `HashMap` entry of 40 bytes against 16, and walks up to the
  function once per `let` that names a type, for its type parameters: Rust extraction of wasmtime retired 42.86 G
  instructions against 42.02 G, 2% (2026-10-30, #484).
- Reading chains, returns and the locals they initialize raises Rust extraction of wasmtime to 46.07 G instructions
  against 43.26 G, 6.5%, for the pairs above (2026-10-31, #485).
- A field of a standard library type, `child: std::process::Child`, keeps `.child`, which the tiers that read no
  receiver still bind to a namesake: the caller's file, the caller's own owner's method there included, and the name's
  one callable.
- Finding a field's declaration walks up from the call to its impl and scans the items beside it, once per such call:
  Rust extraction of wasmtime took 2.30 s against 2.22 s, medians of 8 rounds on 3 threads (2026-10-25, #248).

## Rejected

- **A type parameter's bound** — binds serde's `Serializer`, `Deserializer` and `Visitor` to whichever of ciborium,
  postcard or serde_json is nearest: 19 of 30 sampled pairs right in the registry (2026-10-23).
- **A closure's typed parameter** — about 18 of 30 sampled right.
- **A guess tier for an owner of several files** — binding a receiver whose owner's members lie in several files at 15
  demotes 4,572 pairs on five Rust trees, of which 22 of 30 sampled bind the right method (2026-10-30, #484).
- **A type surviving a shadowing `let`** — the pairs it adds are right mostly by chance.
- **No type through any glob for a parameter or a field** — the pairs it removes are mostly right.
- **A glob's type for a local** — the owner tier cannot tell which namesake a glob brings: `use wasmtime::*;` then
  `Instance::new(..)?` bound the component model's `Instance::get_typed_func`. The glob gives 1,688 pairs on six Rust
  trees, 67% of 30 sampled right (2026-10-30, #484).
- **The type a `builder` function is called on** — it constructs another type: rust-analyzer's `TextEdit::builder()`
  bound `TextEdit::insert` for the builder's own (2026-10-30, #484).
- **`Box`, `Rc` or `Arc` as what its function constructs** — `Arc::make_mut(..)` holds what the `Arc` points to, so
  naming `Arc` lost the call's binding (2026-10-30, #484).
- **Every return type a method spells, whether or not the file shows it as the tree's** — `-> impl Iterator` bound
  rust-analyzer's `minicore` fixture for the standard library's trait: 41 of 1,716 added pairs (2026-10-31, #485).

## Revisit if

The owner tier tells a standard library type from a namesake that a crate the caller is built with declares, so that
the namesake no longer takes the call. Not planned.
