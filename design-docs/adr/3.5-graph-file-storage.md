# Keep the graph a file at a time

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-graph/src/graph.rs` (`Graph::insert`, `Graph::remove`, `Graph::outline`,
  `Graph::definitions`, `find_test_modules`), `crates/kartta-graph/src/strings.rs`, `kartta_lang::Extraction`
  (`test_includes`)
- **Pinned by:** `crates/kartta-graph/tests/graph/contract.rs` (`a_file_inserted_again_replaces_what_it_defined`,
  `a_removed_file_is_forgotten_and_its_slot_serves_the_next_file`,
  `an_outline_tells_a_file_with_no_definitions_from_one_the_graph_does_not_hold`,
  `vendored_code_ranks_after_the_repository_s_own_code_and_before_test_code`,
  `every_definition_of_a_file_only_test_modules_include_is_test_code`,
  `a_file_a_plain_include_reaches_is_test_code_only_once_that_includer_is_removed`,
  `a_module_only_test_modules_include_is_test_code_too`, `a_test_include_the_file_does_not_include_marks_nothing`),
  `crates/kartta-languages/tests/test_code.rs` (the `a_cpp_*` tests)

kartta's index refreshes in place ([ADR 1.15](/design-docs/adr/1.15-whole-tree-refresh.md),
[ADR 1.16](/design-docs/adr/1.16-scoped-refresh.md), [ADR 1.17](/design-docs/adr/1.17-change-notifications.md)), and
the code graph must follow it without being built again. The graph keeps each file in a slot of its own and addresses
a definition by its file's slot, so one file going in or out renumbers no other file's definitions, at the price of
slots and per-name lists where a dense graph would hold compact rows.

## Decision

- **A graph holds one language family's files, each in a slot.** `Graph::insert` takes one file's `Extraction` and
  replaces whatever the graph held for that path; files arrive in any order, and the graph keeps them in path order as
  [ADR 3.36](/design-docs/adr/3.36-graph-file-order.md) states. `Graph::remove` forgets the file and empties its slot,
  and the next insert of a new path takes it. A definition is addressed by its file's slot and its place in the file,
  so one file going in or out renumbers no other file's definitions: the name index loses the removed file's entries
  and gains the new file's, and no other entry changes. Only path ranks are relabelled, a block of files at a time, as
  [ADR 3.36](/design-docs/adr/3.36-graph-file-order.md) states. Calls and references stay as written in the file's slot
  and resolve when a query asks ([ADR 3.7](/design-docs/adr/3.7-call-resolution.md)).
- **Names are interned once per graph.** Every name, qualified name, owner and signature is stored once in one byte
  arena and named by a 4-byte handle, which a definition stores in place of its strings. A string is never removed, so
  a graph refreshed many times keeps the names of files it no longer holds.
- **Answers borrow from the graph and say what they cut.** `Graph::outline` answers what a file defines, ordered by the
  line each starts on, one that encloses others before them, and tells a file with no definitions, an empty outline,
  from one the graph does not hold, `None`. `Graph::definitions` answers where a bare or qualified name is defined:
  nearest to the asking file first, then outside test code, then outside vendored code, then by path and line, cut to a
  limit, with `total` counting every definition the name selects.
- **A file's test flag also follows from the files that include it.** An extraction names in `test_includes` the files
  it pulls in as test-only modules, since the included file is extracted on its own and cannot see the gate, as the
  file of a Rust `#[cfg(test)] mod tests;` cannot ([ADR 3.11](/design-docs/adr/3.11-rust-item-names.md)). A test include
  counts only where the file's includes hold the same target.
  - A file is test code, with every definition in it, when every file that includes it lists it as a test include or
    is such a test module itself, so the modules a test module declares are test code too. One production file that
    includes it keeps it production code.
  - Where includes paste text, a test file lists as test includes what it includes that no path marks, and the file
    must also include a test file itself, a file its own path marks: a helper pastes the test code it builds on. The
    source of the same stem beside such a header, which no file includes, does not count against it and is test code
    with it, as breakpad's `synth_elf.cc` is with `synth_elf.h`.
  - Every answer and query that reads the flag reads it so: the ranking of definitions, dead code's `test` exclusion
    ([ADR 3.23](/design-docs/adr/3.23-dead-code-judgment.md)), the hotspots of an analysis
    ([ADR 3.22](/design-docs/adr/3.22-change-impact-analysis.md)) and the names a directory package offers a call
    ([ADR 3.7](/design-docs/adr/3.7-call-resolution.md)).
  - The graph does not store the flag, which depends on other files. It keeps the includers of each test include beside
    its includers, works out the set of test modules the first time a query asks after an insert or a removal, and
    forgets the set on the next one.

## Why

- A graph that numbers its definitions densely in path order renumbers, on an insert, every definition after it and
  rewrites every edge and index entry naming one: for a file early in path order, close to what a rebuild costs.
- A name repeats across definitions, owners and files; stored once, it costs each of them a 4-byte handle.
- Without the test-module rule, a Cargo registry of 16,978 Rust files kept 1,791 test definitions in 184 files as
  production code (2026-10-17, #66).
- Test helpers that no path marks hold the calls of a C++ tree into its test code: the rule marks 16 files of 42,308 in
  the C++ game-engine tree, all 16 read as test support, and gives back the 9 pairs breakpad's helpers lost, all right
  (2026-10-31, #432).

## Consequences

- The arena keeps the names of every file a refresh dropped until it is compacted; not measured, and compacting waits
  until a refresh can count what nothing references (accepted).
- A graph with no test include pays one emptiness check per definition read; a graph with one pays the set's
  computation on the first query after each change and one set lookup per definition read. A C++ graph has one
  wherever a test file includes a file no path marks: 0.6 ms for the 1,883 files of the C++ game-engine tree; accepted.
- A helper whose header and source lie in different directories keeps its source as production code, and a helper that
  includes no test file stays production code: it binds no test definition, so it loses no pair; accepted.

## Rejected

- **Dense ids in path order, with edges in compressed rows** — compact and fast to query, and rebuilt whole on any
  change.
- **Owned strings in each definition** — no interner to maintain, and every repeated name stored again.
- **The test flag stored per file at insert** — the flag depends on the file's includers, so an insert or a removal
  of one file would rewrite the flags of others.
- **A C++ file only test code includes, whatever it includes** — 346 files of which 23% of 30 sampled are test support:
  a library's interface that only its tests include in the tree, as `absl_check.h`, with its sources (2026-10-31).
- **A C++ file that includes a test file, whoever includes it** — 105 files, 47% of 30 sampled: a name that ends in
  `Test` is often a product's visibility or collision test, as `gpuVisibilityTest.h`. Carried on through includers, it
  marks 931 files, `prog/daNetGame/render` among them (2026-10-31).
- **Names such as `synth_*` and `*_assembler`** — they fit one library's helpers and no other (2026-10-31).

## Revisit if

A refresh's leftover strings become measurable against the arena, or the per-name lists of the name index a measurable
share of a graph's memory. Medium confidence: neither was measured on a refreshed graph.
