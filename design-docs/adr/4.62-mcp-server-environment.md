# Read the MCP server's settings from its environment, with a cache and a mapped grep index by default

- **Date:** 2026-11-03
- **Governs:** `crates/kartta-mcp/src/config.rs`, `crates/kartta-mcp/src/main.rs`
- **Pinned by:** `crates/kartta-mcp/src/config.rs` (its tests), `crates/kartta-mcp/tests/stdio.rs`
  (`a_server_told_nothing_shares_a_cache_under_the_user_s_and_narrows_grep_by_an_index`)

A client launches the server with an environment and no flags, and each session starts its own server, so each pays a
build and greps many times. The server reads its settings from the environment and, told nothing, keeps a content cache
under the user's cache directory and a mapped trigram index, at the cost of disk it writes unasked.

## Decision

- **Configuration.** The server reads the environment: `KARTTA_CACHE_DIR` the shared cache
  ([ADR 2.1](/design-docs/adr/2.1-shared-cache-store.md)), `KARTTA_CACHE_ENTRY_TTL_SECS` an entry's time to live as
  [ADR 2.3](/design-docs/adr/2.3-cache-entry-expiry.md) reads it, which also leaves `KARTTA_CACHE_SWEEP` unread,
  `KARTTA_GREP_INDEX` `memory`, `file` or `mmap` and `KARTTA_GREP_INDEX_DIR` the trigram index
  ([ADR 1.14](/design-docs/adr/1.14-content-search-narrowing.md)), `KARTTA_THREADS` the thread bound
  ([ADR 1.13](/design-docs/adr/1.13-index-threads.md)), `KARTTA_WATCH` the watch
  ([ADR 4.4](/design-docs/adr/4.4-mcp-index-follow.md)), and `KARTTA_MAX_ROOTS` how many roots it holds
  ([ADR 4.21](/design-docs/adr/4.21-mcp-engine-slot.md)). Unset, `KARTTA_CACHE_DIR` is `kartta` under the user's cache
  directory, `~/Library/Caches` on macOS, `%LOCALAPPDATA%` on Windows and an absolute `$XDG_CACHE_HOME`, else
  `~/.cache`, elsewhere, and `KARTTA_GREP_INDEX` is `mmap` in the temporary directory; an empty value turns either off.
  A server with no user cache directory warns and builds without a cache. A value that does not read warns on stderr and
  keeps the default. The walk prunes the engine's default `PrunedNames`
  ([ADR 1.19](/design-docs/adr/1.19-pruned-names.md)).

## Why

- A session starts its own server, so every session pays a build, and an agent greps many times in one. On a
  171,628-file C++ checkout a warm cache cut the build from 27-31 s to 5.8 s, and the mapped index answered a literal
  `grep` of the whole tree in 4 ms against 3.4 s, adding no footprint and no measurable build time (macOS, 4 threads,
  2026-11-03, #1034).

## Consequences

- A server writes to the user's cache directory unasked: 590 MiB for the checkout and 8.1 GiB for a 4.1M-file data
  volume, whose payloads [ADR 2.3](/design-docs/adr/2.3-cache-entry-expiry.md)'s expiry holds within about twice what
  its unexpired entries take, an entry staying until its pack is rewritten. Accepted.
- The index reads every text file each build: on the data volume a warm build took 276 s against 158 s, and the scratch
  file held 3.7 GiB. Accepted: a literal `grep` there took 3.2 s against 158 s without it.
- Where the temporary directory is a memory filesystem, the mapped index occupies memory. Accepted.
- A pattern with no three-byte literal still reads every candidate: 3.2-5.5 s on the checkout. Accepted.

## Rejected

- **No cache by default** — every session parses the whole tree: 615 s on the data volume against 158 s warm.
- **No content index by default** — a literal `grep` of the checkout reads every candidate, 3.4-4.6 s against 4 ms.
- **A `memory` index by default** — the same answers for 235 MiB more footprint on the checkout.

## Revisit if

Agents index trees where reading every text file for the index costs more than their greps save. Medium confidence:
measured on one checkout and one data volume.
