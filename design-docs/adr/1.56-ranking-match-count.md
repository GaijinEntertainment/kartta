# Count a ranking's matches as it scores them

- **Status:** accepted
- **Date:** 2026-10-20
- **Updated:** 2026-10-20
- **Initiative:** `01-kartta-fs-port`
- **Governs:** `crates/kartta-fs/src/fuzzy.rs` (`FuzzyMatches::matched`), `crates/kartta-fuzz/src/ranking.rs`
  (`Ranking::matched`, `Ranking::merge`)
- **Pinned by:** `crates/kartta-fs/tests/index.rs` (`fuzzy_honours_a_limit_and_scores_descend`,
  `an_empty_query_counts_nothing_with_or_without_a_limit`,
  `a_fuzzy_exclusion_removes_a_file_and_a_directory_with_everything_beneath_it`),
  `crates/kartta-fs/src/fuzzy.rs::chunks_ranked_apart_answer_and_count_as_one_chunk_does`

A ranked answer explains its cut by its order (ADR 1.5) and still leaves a caller unable to tell ten matches from the
best ten of thousands. `Index::fuzzy` counts every path that matched, those past the cap included, from the scoring it
already does. An empty query is not counted, because counting it would cost the pass its cap avoids.

## Decision

- `Index::fuzzy` answers a `FuzzyMatches`: the best matches, and `matched`, how many paths matched every term of the
  query, those the limit left out included.
- Only what the ranking scores counts: never a directory, a path the filter does not select, or one the exclusion
  removes (ADR 1.55).
- The count is a tally of the scoring: a query with terms scores every path the filter and the exclusion leave before
  the heap keeps or turns it away. `kartta_fuzz::Ranking::matched` counts per run of the parallel ranking, and
  `Index::fuzzy` sums the runs' counts in the reduction that merges their rankings.
- `matched` is `None` for an empty query, one with no term. An empty query matches every candidate the filter and the
  exclusion leave, in index order, and each run stops at the limit without reading the rest.
- `matched` is a count beside the ranking, never folded into a `truncated`; the ranked answer carries no flag.

## Why

1. A caller that sees ten paths as ten of however many matched knows whether to narrow the query.
2. The count costs no pass of its own, because a query with terms already scores each candidate the cap could turn
   away.
3. Under a limit an empty query stops reading at the limit, so a count would be the pass the limit spares, and a
   partial number would read as a whole one. Without a limit its answer already holds every match.

## Consequences

A ranking holds one counter per run. Accepted.

## Rejected

- **Count an empty query's matches** — its runs stop at the limit unread, so the count would be partial or cost the
  pass the limit avoids.
- **Widen `truncated` into the number** — a ranked answer carries no flag (ADR 1.5), and a count is its own named
  thing.

## Revisit if

The ranking stops scoring every candidate the filter and the exclusion leave, as a pruned or early-exit ranking would;
the count would then cost a pass. High confidence while the ranking scores each candidate.
