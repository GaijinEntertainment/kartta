# Fold a C++ declaration into the one definition its file reaches

  `a_declaration_whose_file_includes_two_definitions_links_to_neither`)

A C++ callable is declared in one place and defined in another, often in another file, and a call binds whichever the
caller sees. The walk keeps a declaration only where its own file holds no definition of it, and the graph links a
declaration to the one definition the translation units that declare it hold, so a call of either reaches the same
body; a declaration with several candidate definitions links to none of them.

## Decision

1. A declaration without a body is queued during the walk and flushed after it. It is emitted only where the file has
   recorded no callable of its identity, its callable key, by then: no definition, and no earlier declaration of the
   key. A declaration without a key is always emitted. An in-class declaration whose out-of-line definition the same
   file holds is recorded as a folded declaration of that definition.
2. A queued declaration takes its namespace when it is queued, since the namespace scopes have closed by the flush.
   Its id comes after every definition's, and it opens no scope that a call is attributed to, so the ids of the
   callers stay in source order.
3. A file-scope constant of a `.c` file that its signature does not mark `static` is exported, with a definition keyed
   by its qualified name, as C links it outside its file.
4. The graph links a declaration to a definition of its key whose file reaches the declaration's file through its
   includes, or, where a language's includes are transitive as C++'s are, one the declaration's own file reaches, as
   an inline implementation header that a class header includes at its end. Only the one definition that qualifies
   links: where two qualify, a platform's conditional alternatives, the declaration links to none, and a copy in
   another checkout, which no file of the class reaches, stays apart.

## Why

- A header keeps its declarations, which a call sees through an include, while a source that declares and defines a
  function keeps one symbol for it.
- An `#include` pastes text in place, so a definition the declaration's own file reaches is in every translation unit
  that declares it. Linked only from the definition's side, the members an inline header defines linked nothing: a
  call bound the empty declaration, the definition had no callers, and a bare call in its body met no class. Linked
  both ways, 554 caller and callee pairs arrived on the C++ game-engine tree, 28 of 30 sampled right (2026-10-23).
- C gives a file-scope `const` external linkage where C++ gives it internal linkage, and the walk reads every file as
  C++.

## Consequences

- A query builds the closure of the declaration's file where a definition of the key misses the first test; nothing
  is stored.
- A declaration whose header reaches several platforms' bodies links none, so a call of it binds the declaration.
  Accepted.
- A call inside such a member on a field still binds nothing (#482).

## Rejected

- **Link a definition that only the declaration's file includes directly** — binds 207 pairs this rule does not, each
  an arbitrary one of a declaration's platform alternatives its header happens to include directly,
  `dag_vecMath_neon.h` for `dag_vecMath.h`.
- **Link a definition whose includer reaches the declaration, through the includers index of ADR 3.19** — binds 360
  pairs more, 7 of 20 sampled a platform's alternative again.

## Revisit if

A language whose includes are transitive gains a construct that pastes one definition per build, so that several
definitions a header reaches are not alternatives. Medium confidence that C++'s are alternatives most often.
