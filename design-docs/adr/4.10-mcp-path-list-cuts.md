# Close a cut path list with a line no path can read as

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-mcp/src/llmxml.rs` (`line`, `List`), `crates/kartta-mcp/src/render/files.rs` (`paths`,
  `globbed`, `default_cut`, `failures_block`), the `find_files` and `glob_files` tools
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs` (`find_files_counts_every_match_when_its_cap_cuts_the_list`,
  `glob_files_lists_in_path_order_and_says_when_the_cap_cut_it`,
  `find_files_and_glob_files_say_when_their_default_cap_cut_the_list`, `an_empty_glob_answer_tells_one_glob_from_two`,
  `a_path_that_opens_with_a_parenthesis_is_quoted_so_it_cannot_read_as_the_closing_line`,
  `grep_quotes_an_unreadable_path_that_opens_with_a_parenthesis_and_not_the_count_after_it`)

`find_files` and `glob_files` answer plain paths, one a line, as the prompts in use read them, so what a cap or the
excludes left out has to be a line too. Each cut list ends with a line in parentheses that counts what it can count
without more work, and a path that could read as such a line, or split across two, is quoted.

## Decision

- **A record.** A path holding a control character, or opening with a quote or a parenthesis, is written quoted and
  escaped as an attribute value is (`\n`, `\t`, `\"`, `\\`); any other path is written as it is. The closing lines
  follow the list unquoted. `grep`'s `<failures>` list shares the writer: a `path: error` record whose path opens with
  `(` is quoted whole, and its `(+N more)` line is not. `list_dir` and `grep`'s `<file>` carry a path as an attribute
  value, escaped already.
- **The default cap.** A list the default `max_results` cut ([ADR 4.23](/design-docs/adr/4.23-mcp-default-limits.md))
  ends, after every other line, with `(the default max_results of 200 cut this list - a higher max_results, or 0, lists
  the rest)`; a cap the call names adds no such line.
- **`find_files`.** A list `max_results` cut ends with `(N of M matching paths, best first)`, M the ranking's own tally
  of every path it scored, which the includes and excludes narrow
  ([ADR 1.56](/design-docs/adr/1.56-ranking-match-count.md)). A list the cap did not cut has no closing line. It says
  nothing of what its excludes removed: its order explains the cap. A pattern with no term is a tool error pointing at
  `glob_files`.
- **`glob_files`.** A list `max_results` cut ends with `(truncated: the first N matching paths in path order; more
  match)`, and `(excludes removed: N)` counts the matches the excludes removed before the list ended.
- **An empty `glob_files` answer** echoes each glob quoted and escaped as an attribute value is, a comma and a space
  between them, as `find_files` quotes its one pattern: `no files match "x, y"` is one glob, `no files match "x", "y"`
  two.
- **Excludes.** Both tools hand their excludes to the index, which drops a matched directory with everything beneath
  it, as `grep`'s and `list_dir`'s excludes do ([ADR 1.55](/design-docs/adr/1.55-path-query-exclusion.md)), and caps
  after them.
- **Descriptions.** The `find_files` and `grep` descriptions and the crate README say how a path is quoted.

## Why

- A path list in path order looks the same whether or not more follow, and an agent reads 20 paths as all there are;
  with M it reads them as 20 of 43,729 and narrows the pattern rather than raising the cap.
- The ranking scores every match anyway, and a counter beside its heap counts them: the count keeps nothing more.
- An agent that named no cap reads the paths it got as every match unless the answer says the server cut them; the
  maintainer took the default on the condition "that limit must have explicit marker" (2026-11-25, #1039).
- A line break inside a path splits its record, and a path such as `(x).txt` reads as a closing line, or a closing line
  as a path (#74).
- Matched against the returned paths alone, `**/vendor` removed nothing beneath `vendor/`, and capping after the drop
  ranked or globbed the whole tree.
- A glob may hold any character a file name holds, a line break and a quote included, so no separator written as it is
  can part two globs. Quoted, every `"`, `\` and line break a glob holds is escaped, so the text between two globs, a
  quote, a comma, a space and a quote, occurs in no quoted glob. Joined by a comma and a space alone, the one glob
  `x, y` and the two globs `x` and `y` read alike (#1176).

## Consequences

- A capped `glob_files` says that more match, not how many. Accepted: the count is a walk of the whole tree.

## Rejected

- **Counting the matches past `glob_files`' cap** — the whole-tree walk the cap exists to avoid.
- **Counting `find_files`' matches by keeping and sorting every one** — a cost per call on a tree of millions of paths;
  the ranking's tally gives the same count for nothing.
- **Matching the excludes against the returned paths** — a directory exclude removes nothing beneath it, and the cap
  then applies after a pass over everything.
- **One glob a line, as `grep` echoes its patterns** — `grep` refuses a pattern that holds a line break, while a glob
  may hold one, so a line break parts no two globs.

## Revisit if

A consumer reads these answers as data rather than as text, so a structured list would serve it better than closing
lines. Low likelihood: the prompts in use read plain paths.
