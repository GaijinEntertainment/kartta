# Prune editor and OS clutter by name during the walk

- **Status:** accepted
- **Date:** 2026-10-17
- **Revised:** 2026-10-18
- **Initiative:** `01-kartta-fs-port`

Editors keep their state inside the tree they edit — `.idea` for JetBrains IDEs, `.vscode` for VS Code, `.fleet` for
Fleet — and macOS leaves a `.DS_Store` in every folder Finder opens. Few repositories carry a rule for them, because
each developer's global excludes do, and those are machine-local sources the reproducible level of ADR 1.3 leaves out.
So a build indexed them, and an agent asking which files a tree holds was answered with workspace layouts and Finder
records as well.

**`BuildOptions::pruned_names` holds the names a build neither indexes nor descends.** It is a `PrunedNames`, composed
the way ADR 1.7 composes the binary extension set: `PrunedNames::builtin` — `.DS_Store`, `.fleet`, `.idea` and
`.vscode` — is the default, a caller's own names join it by `union` and leave it by `difference`, and
`PrunedNames::none` prunes nothing beyond `.git`. A name no entry in a tree carries is no error, and a name that cannot
be an entry's — empty, `.` or `..`, or holding a path separator or a NUL — is refused by name.

**Revised 2026-10-18: a caller extends the built-in set or states its own.** `PrunedNames::difference`,
`PrunedNames::none` and `PrunedNames::names` are gone, as ADR 1.7's revision removed their counterparts: the C ABI wire
offers extend and replace, and no consumer took a name out or read the names back. An empty `PrunedNames::new` set
prunes nothing beyond `.git`, as `none` did.

**A name prunes an entry of any kind, at any depth, and only by the entry's own name, compared exactly.** Editor state
is a directory and Finder's record a file, and a kind check would buy nothing for a cost on every entry the name
matches. The tools that write these names spell them one way, so a case-folding compare would add a fold per entry to
match spellings no tool writes. The root a build is given is never pruned, whatever its name: a caller who indexes
`.vscode` itself asked for it.

**Pruning comes before the ignore rules, and outside them.** The walk drops a pruned entry by the name it decoded from
the listing, before it checks that the name decoded without loss or matches it against a `.gitignore`, so a pruned
directory costs a name check and its listing is never read.
No negation brings a pruned name back, and `IgnoreSources::None` keeps it out too: `IgnoreSources` stays the ladder of
git's own sources that ADR 1.3 draws reproducibility on, and pruning is the caller's statement of what the index is
for. While ignore rules apply, a pruned `.gitignore` still applies its rules, as an ignored one does (ADR 1.12), and no
visitor is handed it, since the index does not hold it. `BuildOptions` compares and hashes the set by its members, so
a cache keyed on a build's configuration covers it.

**`.git` stays outside the set, pruned whatever the set holds.** It is not clutter. A `.git` below the root marks a
nested repository, where the inherited rules reset; a refresh widens a changed `.git` to the directory that holds it
and skips every path inside one (ADR 1.16); and what it holds is the object store, often larger than the tree. A set
that let a caller take it out would have to answer what the index means by a repository's bookkeeping, for a caller
nobody has met. A set may hold `.git`, and prunes exactly as one that does not.

**A refresh prunes what the build pruned.** The index keeps its set, and `Index::refresh` walks with it. A path given
to `Index::refresh_paths` through a pruned name names nothing the index holds, so it is skipped, as a path inside
`.git` is, rather than widened to the pruned directory, which would index it. A pruned `.gitignore` is the exception,
because its rules apply: it widens to the directory it governs, as an unpruned one does. The Linux watcher of
ADR 1.17 watches no directory named `.git` or in the set: a directory made after the start under such a name would take a watch from a
limit every process of the user shares, for events a refresh skips. `FSEvents` and `ReadDirectoryChangesW` cover the
whole tree with one watch, so they report pruned paths, and a refresh skips them at no pass over the index.

**A listing says when a pruned name is why it found nothing, and counts nothing it pruned.** A listing asked for a
path through a pruned name, `.git` included, fails as `ListError::Pruned` and names the name, so an agent can tell an
entry the build pruned from one that is absent or ignored, which both answer `NotFound`. The check runs only on the
failure, at a comparison per name of the path. A listing that holds a directory does not count the pruned entries in
it: the index keeps no trace of a pruned entry, so a count would cost memory per pruned entry, and a count of what lies
beneath a pruned directory would cost reading what pruning exists to skip (ADR 1.8 counts only what is free). Nor does
a build report how many entries each name pruned. ADR 1.7 counts what each binary extension settled because a
misspelled extension changes no answer anyone sees; a misspelled name leaves the entries it was meant to prune in the
index, where every listing shows them.

## What it costs

Measured on macOS against `main` on a shared machine, before ADR 1.18 landed, interleaved and alternating which side
ran first; each range spans every round, `main` first. The heap is a counting allocator's, at its peak during the
build and what the index holds after it; the footprint is the process's peak. The engine builds every language with no
cache.

| tree | entries | pruned | index build | heap, peak / held | footprint |
| --- | --- | --- | --- | --- | --- |
| game-engine checkout | 182,714 | 0 | 0.147–0.210s / 0.148–0.199s | 22.7 / 5.0 MB on both | 37–38 / 37–39 MB |
| Go monorepo | 70,011 | 12 | 0.154–0.203s / 0.150–0.192s | 9.3 / 1.8 MB on both | 17–18 / 17 MB |
| data volume | 8.0–8.4M | 461 | 58.2–80.0s / 50.2–72.6s | 1,168–1,219 / 286–297 MB on both | 975–1,006 / 954–1,006 MB |

| tree | engine build | footprint | files graphed |
| --- | --- | --- | --- |
| game-engine checkout | 14.8–16.5s / 14.6–16.5s | 1,211–1,304 / 1,226–1,732 MB | 146,752 on both |
| Go monorepo | 3.7–7.2s / 3.7–6.3s | 705–774 / 690–804 MB | 44,443 on both |
| data volume | 482–607s / 487–492s | 16,300–17,298 / 16,238–16,587 MB | 2.71–2.89M, as the tree moved |

The index builds ran 10 rounds a side on the checkouts and 5 on the data volume, the heap 3 and 2, the engine 4 and 2.
The monorepo's 12 entries are two `.idea` directories and the scope lists in them. The data volume's 461 are 102
`.vscode` and 28 `.idea` directories with what they hold, and 37 `.DS_Store` files. The data volume's slowest engine
build, on `main`, ran while some 270k entries were deleted under it and failed to read 10,931 files; its other round
took 482s against the branch's 487–492s on the same tree.

Every difference sits inside the noise. Pruning saves in proportion to what it prunes, and these trees hold little of
it: 0.017% of the monorepo's entries and 0.006% of the data volume's, none of them a source any language claims, so
each engine graphed the same files on both sides. The data volume also moved by up to 400k entries between rounds as
other work wrote to it. What the prune changes on these trees is the answer, not its cost: the monorepo's file set
loses the 8 files of its two `.idea` scope lists. The check costs nothing measurable either — a comparison with `.git`
and a binary search over the set's names, four by default, for each entry.

## Considered Options

- **Glob patterns, as `ListOptions::exclude` takes** — a glob set matched against every path the walk finds, where a
  name is a binary search over a handful of names; and clutter is named by its name, wherever it lies. A pattern over
  paths remains the query's to apply, through `Filter`.
- **The names as a synthetic `.gitignore` layer** — `IgnoreSources::None` would index them again, git's rules and the
  caller's would share one ladder, and every entry would pay a `wildmatch` per name.
- **A flag that turns a fixed list on or off** — serves neither a caller with clutter of its own nor one that wants a
  single name back, the argument ADR 1.7 settled for binary extensions.
- **Leave it to the consumer to filter answers** — the walk would still descend and read every pruned directory, and
  every query would filter every answer.
- **A wider default** — `Thumbs.db`, `desktop.ini`, `.vs`, `__MACOSX` and `.history` were counted on the same trees.
  Neither checkout holds any of them, and the data volume holds two `.history` directories, 78 entries in all. A
  default that grew past the editors and the OS in common use would prune names some tree uses for content.
- **`.git` in the set, removable** — see above: it bounds the ignore rules and the refresh, and holds the object store.

Revisit if a consumer needs to see what a pruned directory holds without listing it by name, if a name outside the
default turns out common on the trees this engine serves, or if a caller needs a path-shaped prune at walk time.
