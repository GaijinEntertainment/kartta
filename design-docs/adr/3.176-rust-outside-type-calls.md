# Bind no Rust call through a type outside the graph

- **Date:** 2026-10-24
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`resolve_by_name`, `through_the_receiver_s_owner`,
  `names_a_type_outside_the_graph`), `kartta_lang::MemberCalls::ModulePaths`
- **Pinned by:** `crates/kartta-languages/tests/engine.rs`
  (`a_rust_call_through_a_type_the_tree_does_not_declare_binds_no_member_of_another_type`)

`Vec::new()` calls the standard library, and Rust's prelude and its `use`s of outside crates leave no trace the graph
reads, so a `new` of the caller's own file is a namesake. A call through a type the graph holds no definition of binds
nothing.

## Decision

- **Type paths.** Where `Conventions::member_calls` is `MemberCalls::ModulePaths`, as Rust's is, a receiver whose last
  segment starts with an ASCII capital and holds only letters, digits and `_` is a type path: `Vec`,
  `tempfile::NamedTempFile`, and the type a method call on a parameter records
  ([ADR 3.55](/design-docs/adr/3.55-rust-parameter-receivers.md)).
- **Types outside the graph.** A call through a type path of whose last segment the graph holds neither a type nor a
  value that the caller's package can reach by [ADR 3.179](/design-docs/adr/3.179-rust-crate-reach.md), once the
  receiver's owner tier ([ADR 3.171](/design-docs/adr/3.171-receiver-call-binding.md), tier 5) binds nothing, binds
  nothing at any tier below it: no definition of the caller's file or its includes, no re-export, no member of the
  caller's own owner, and neither the one callable of the name nor the one nearest the caller. The miss counts as not
  admitted. A `use … as` of a type the tree holds names that type
  ([ADR 3.56](/design-docs/adr/3.56-rust-call-receivers.md)), so only a rename of a type outside the tree comes here.
- **Types and values the graph holds.** A type the graph holds and the caller's package can reach keeps every tier, so a
  trait's default method or a type alias's target still binds by name. A value keeps them too: `BANNER.marks()` on a
  `static` is a call on a value written capitalised. A value a macro writes counts under a method call alone
  ([ADR 3.191](/design-docs/adr/3.191-rust-macro-items.md)).

## Why

- A type the graph does not hold has no member in the graph: of 135 sampled pairs the rule unbinds on this
  repository, tree-sitter, the cargo registry and the Rust crates of the Go monorepo snapshot, 130 were wrong, 36 of
  40 on the registry (2026-10-24, #219).
- A Rust `mod` file is no scope a type's name is looked up in, so a namesake one declares is no likelier the callee.

## Consequences

- A call on a constant a macro of another file declares loses its one-callable edge; one of the file's own macros
  declares a value the graph holds ([ADR 3.191](/design-docs/adr/3.191-rust-macro-items.md)), as plotters' `BLACK`
  is. Open with #610.

## Rejected

- **Every type path whose owner has no member of the name** — unbinds trait default methods and calls through type
  aliases: about half of 40 sampled of the 3,316 further pairs it unbinds on the cargo registry were right
  (2026-10-24).
- **Bind through the file's includes and re-exports, as a PHP class outside the graph does
  ([ADR 3.167](/design-docs/adr/3.167-php-outside-class-calls.md))** — a submodule's namesake then binds, `Box::new()`
  reaching `Emitter::new`: 4 of 4 sampled on this repository.
- **Read a receiver without a lower-case letter as a constant** — keeps type parameters such as `FromA::default()` and
  statics outside the graph: about a quarter of the 29 pairs it keeps on the registry are right.
- **Types alone, without the value check** — unbinds calls on statics the graph holds: 26 of 30 sampled of the 470
  further pairs on the registry were right.

## Revisit if

The Rust walk records the type a `use` brings in and the prelude's names, so a receiver's type can be told from the file
itself. Not planned.

## History

- 2026-10-31 — Types outside the graph: a rename of a type the tree holds read as a type outside it, so
  `ClapError::unknown_argument()` bound nothing (#515)
- 2026-10-24 — Types and values the graph holds: a value a macro writes made `Box::new()` keep every tier, as
  rust-analyzer's `sym::Box` did (#324)
- 2026-10-24 — Types outside the graph: a Rust call bound a definition in a crate the caller's crate does not depend
  on, `Config::default()` in kartta-fs binding kartta-mcp's `Config::default` (#228)
