# Qualify a Ruby member by its whole namespace chain

- **Date:** 2026-10-16
- **Governs:** `crates/kartta-lang-ruby/src/owner.rs`, `crates/kartta-lang-ruby/src/macros.rs`,
  `crates/kartta-lang-ruby/src/bindings.rs`, `crates/kartta-lang-ruby/src/walk.rs` (definitions, receivers),
  `crates/kartta-lang-ruby/src/lib.rs` (the crate docs)
- **Pinned by:** `crates/kartta-lang-ruby/tests/ruby.rs` (`every_definition_is_qualified_by_its_namespace_chain`,
  `two_types_of_one_name_keep_their_members_apart`, `a_type_inside_a_method_has_no_owner`,
  `visibility_modifiers_decide_what_is_exported`,
  `private_class_method_hides_a_class_method_and_a_bare_private_does_not`,
  `an_alias_keeps_the_body_its_original_named_at_the_alias`,
  `a_self_receiver_names_the_type_chain_and_a_receiver_on_a_class_ends_in_the_class_method_separator`,
  `a_bare_new_in_a_class_method_names_an_instance_of_the_owner_and_elsewhere_is_as_written`,
  `a_literal_receiver_names_the_class_of_the_value_it_makes`),
  `crates/kartta-languages/tests/ruby_singleton_methods.rs`
- **Implementation:** pending — `private_class_method def self.x` leaves `x` exported, since the modifier reads only
  symbol arguments and a `def self.x` is exported (#501)

Ruby reopens a type in any file, two libraries often hold types of one name in different namespaces, and much of a
type's structure comes from method calls in its body. The extraction reads one file and runs no code: it qualifies a
member by the whole namespace chain of its type and reads the class-body macros with no receiver as structure, at the
cost of what only running the code would show.

## Decision

- **A member is qualified by the whole chain of its type.** The owner of a member is the `::`-joined chain from the
  outermost enclosing type, `Geo::Shape`, and the member's name extends it: `Geo::Shape#area` for an instance method,
  `Geo::Shape.build` for a class method, `Geo::Shape::MAX` for a constant or a nested type. A `class << self` block is
  transparent, and its `def` is a class method. A method ends the chain, so a type that a method holds belongs to no
  outer type. `def self.x` belongs to the enclosing type, `def Foo.x` to the nearest enclosing type named `Foo`, else to
  `Foo` as written, and `def obj.x` to no type. A constant bound to `Struct.new` or `Data.define` is a class, and a
  qualified constant assignment, `Foo::BAR = 5`, defines nothing.
- **A call records its receiver as the source spells it.** A plain name is the receiver as written, `self` is the chain
  of the caller's own type, a literal is the class of Ruby's runtime its value is of, `String` for `"a"` and `Array`
  for `%w[a]`, and any other expression is the empty receiver. What a call on a constant or a literal binds is
  [ADR 3.190](/design-docs/adr/3.190-ruby-constant-receivers.md). A bare `new` that no
  binding makes a local is, in a class method, an instance of the owner, `Geo::Shape`, and elsewhere the name as
  written. How a call outside every method names its type is
  [ADR 3.158](/design-docs/adr/3.158-ruby-type-body-calls.md).
- **A receiver that is a class ends in `.`, the separator of a class method's name.** `self` in a class method or a
  type's body is `Geo::Shape.`; a constant or a constant path keeps its path as written, `Shape.`, and one written from
  the root keeps its leading `::`; `self.class` in an instance method is `.` alone, a class the walk does not name. A
  use's constant path ends in `.` too, `Cache.`. Of an owner's methods of one name, a
  receiver on a class reaches the class method first, `Geo::Shape.build`, and any other receiver the instance method
  first, `Geo::Shape#build`; an owner that declares one kind offers it to both. A bare call takes the kind of the method
  around it.
- **A class-body macro is structure only with no receiver.** `include`, `extend` and `prepend` add their constant
  arguments to the parents of the enclosing type, the accessor macros define accessors, and the visibility modifiers
  decide which methods, accessors and aliases are exported, each form as the
  [crate docs](/crates/kartta-lang-ruby/src/lib.rs) list it; in a method body they add nothing. A `class << self` body
  keeps a visibility of its own, which covers its class methods, and `private_class_method :x` and
  `public_class_method :x` change a class method from the class body. A bare `private` in a class body leaves a
  `def self.x` exported, as Ruby does. `module_function` is not tracked. A macro stays a recorded call beside the
  structure it adds. The same words with a receiver, `Other.include Comparable`, are calls of methods of their own, and
  add no structure.
- **An alias is one callable with the body its original names at the alias.** `alias` and `alias_method` define the new
  name, a class method inside `class << self`. When the file declares the original before the alias, in the same type,
  kind and enclosing method, the two symbols are one callable: the original's body defines it, and the alias declares
  it. A later redefinition of the original leaves the alias on the earlier body, as Ruby does. A later declaration of
  the alias's own name replaces the alias, so that alias joins nothing.
- **Bare names and requires.** How a bare name is told from a local's read is
  [ADR 3.183](/design-docs/adr/3.183-ruby-bare-calls.md), and how a require resolves is
  [ADR 3.157](/design-docs/adr/3.157-ruby-require-resolution.md).

## Why

- Two types of one name keep their members apart, and a call on `self` names the chain of the caller's own type, so
  it binds the member of that type and no namesake's.
- The macros are the class body's structure, and read without a receiver they mean what Ruby's own `Module` methods
  do: on Homebrew, the visibility of a `class << self` body and `private_class_method` hide 161 class methods
  (2026-10-16, #36).
- A class's own method and an instance method of one name are two methods, and a receiver on the class reaches the
  first, as Ruby dispatches: on Homebrew's library, 125 distinct call sites change the method they bind, 101 of the
  125 to the right one and 1 away from it (2026-10-23, #193).
- A bare `new` in a class method is `self.new`, an instance of the owner, so its call reaches the owner's instance
  method: on Homebrew's library, all 34 pairs it changes are right (2026-10-24, #210).

## Consequences

- A type or a method that code defines at run time, `Class.new`, `define_method` or `class_eval`, is not seen.
  Accepted.
- A variable that holds a class, `@command_manager_class.instance`, reaches the instance method first. Accepted.

## Rejected

- **An owner by its last name, `Worker`** — one string less per member, but `A::Worker#run` and `B::Worker#run` become
  one name, and a call binds to either.
- **The kind of `self` read from the caller alone** — needs no mark on `self`, but a constant naming the caller's own
  class in an instance method, `Formula.build` inside `Formula#install`, reads as `self` and reaches the instance
  method.
- **A bare `new` in a type's body as an instance too** — the body's blocks most often run with another `self`, through
  `class_eval` or `define_method`, and on Homebrew each of the 6 pairs it changes is wrong.

## Revisit if

The extraction runs code, or reads what a type gains at run time through `define_method` or `class_eval`. Not planned.

## History

- 2026-10-25 — A call records its receiver as the source spells it, and a receiver that is a class ends in `.`: a
  constant recorded `.` alone and a literal the empty receiver, so `Hash.new(0)` and `"a".freeze` bound any project
  method of their name (#465)
- 2026-10-24 — A call records its receiver as the source spells it: a bare `new` in a class method was a value name,
  so once #184 narrowed the receiver rule the caller's-owner tier no longer bound `new.getopts` to the owner's
  instance method (#210)
- 2026-10-23 — A receiver that is a class ends in `.`: a class that declares both `def build` and `def self.build`
  bound a call on either receiver to whichever the file declares first (#193)
