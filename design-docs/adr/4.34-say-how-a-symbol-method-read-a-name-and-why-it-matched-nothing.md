# Say how a symbol method read a name, and why it matched nothing

- **Status:** accepted
- **Date:** 2026-10-20
- **Updated:** 2026-10-23
- **Initiative:** `04-consumer-surfaces`
- **Governs:** `crates/kartta-ffi/src/query.rs` (`ask_named`, `call_path`), `crates/kartta-ffi/src/built.rs`
  (`Matches`), `crates/kartta/src/reading.rs` (`ask_reading`, `unmatched`, `selects_as_callers`),
  `bindings/go/wire/graph.go` (`Matches`, `Unmatched`, `GraphDefinition`)
- **Pinned by:** `crates/kartta-ffi/tests/golden/definitions.json`, `call_path.json`, `references-unmatched.json`,
  `call_path-unmatched.json`, `callers-one_edit.json`, `definitions-one_edit.json`

When a symbol method of ADR 4.2 selects no symbol by a name, an empty `matches` alone cannot tell a name spelled with
another language's separator from one the path prefix keeps from every definition, one several definitions end with,
or one a typo away from a definition, and a consumer would guess its next call. The answer reads the other separator
and names the case and the definitions it found, from lookups the engine makes per graph, never a search; a miss costs
those lookups and a name that matches costs nothing more.

## Decision

- **The other separator.** `callers`, `callees`, `references`, `implementations`, `definitions` and `sources` read a
  qualified name that selects no definition of the kinds the method takes, in the graphs it asks and under its path
  prefix, with each `.` as `::`, or else each `::` as `.`, the first reading that selects one. The answer carries the
  reading as `read_as` beside `matches`; `call_path` reads each end on its own, into `from_read_as` and `to_read_as`. A
  name that selects as written is never read another way and carries no key. A reading the method then answers nothing
  for still names what was read, over an empty `matches`.
- **Why nothing matched.** Where `matches` is empty, `callers`, `callees`, `references` and `implementations` carry
  `unmatched`, and `call_path` `from_unmatched` and `to_unmatched` for an end that selects nothing in any graph asked,
  tested by selection before any lookup. Each holds `kind`, `total` and `listed`, over the definitions of the kinds the
  method selects of the name, as read:
  - `several`: more than one is under the path prefix and on the line, each looking everywhere where left out;
  - else `outside_prefix`: some are outside the prefix or off the line, and at most one under and on them;
  - else `one_edit`: the name names no definition of any kind, and names one edit from it do, as
    `Graph::definitions_one_edit_from` looks them up
    ([ADR 3.131](./3.131-answer-a-missed-name-with-the-definitions-one-edit-from-it.md)).

  `total` counts them across the graphs asked, and `listed` holds the first five, each a `graph` and its `definition`,
  graph by graph, in the order `definitions` ranks them, or for `one_edit` outside test code first, then outside
  vendored code, then by path and line. `definitions` and `sources` take no path prefix and select every definition a
  name selects, so they carry `unmatched` of kind `one_edit` alone. The key is absent for a name that matched and for
  one no case holds.
- **One reading, two surfaces.** The keys sit beside `matches`, not in each part, since one reading is chosen across the
  graphs asked. The reading and the case are the engine's own, `kartta::ask_reading`, `kartta::unmatched` and
  `kartta::selects_as_callers`, which the MCP tools call too
  ([ADR 3.48](./3.48-read-a-qualified-name-with-the-other-owner-separator-when-it-selects-nothing.md),
  [ADR 4.18](./4.18-answer-a-name-that-selects-nothing-with-what-it-does-match.md)), so both surfaces read a name and
  tell a miss apart one way.
- **No alternatives.** The wire lists no close alternatives for a name no case holds; a consumer that wants them asks
  `search`.
- **The bindings.** Go's `wire.Matches` and TypeScript's `Matches` carry every key, as the type every graph query
  answers, so a typed call keeps its signature; `kind` is a string whose docs list the three values.

## Why

- A consumer that asked for `Index.refresh_paths` in Rust got no match and no hint, where the MCP tools read the same
  name as `Index::refresh_paths`.
- The definitions, not a count, show a consumer the longer name or the prefix that picks one, and listing five costs
  nothing past the lookup that counts them.
- A name taken from a diff or a log with one typo had no route to the symbol meant; the one-edit lookup lists the meant
  definition first far more often than a search of the same typo does.
- The engine holds no list of alternatives when a miss answers: a search of each graph costs thousands of times the
  miss, and `search` already answers it, ranked and counted.

## Consequences

- A miss pays lookups a match does not: a `several` or `outside_prefix` miss looks the name up once per graph and ranks
  every definition of it to list five, at most about half a millisecond for the commonest names, and a `one_edit` miss
  looks up about 128 names per character in each graph, so its cost grows with the square of the name's length, up to
  hundreds of milliseconds for the 256 characters a lookup takes (ADR 3.131; C++ game-engine tree, 2026-10-21):
  accepted, since a miss that pays milliseconds is still a miss.

## Rejected

- **The reading in each part** — a reading the method answers nothing for would leave no part to carry it, and the
  same string would repeat in every graph's part.
- **A type of its own for the `call_path` answer in the bindings** — Go's `CallPath` answers a
  `wire.Matches[wire.CallPath]`, and a new type would break every caller that names it.
- **Counts alone** — the definitions are what shows the consumer its next call.
- **A key per case, `several` and `outside_prefix`** — a consumer checks two keys where one names its case, and
  `call_path` would carry four.
- **Close alternatives, or the search's best hits, where no case holds** — thousands of times the miss, and the search
  found the meant name for fewer typos than the one-edit lookup lists.
- **A lookup that ranks only the definitions it lists** — a public `kartta-graph` surface to save at most half a
  millisecond on a miss of the commonest names.
- **`one_edit` only on request** — a consumer would have to know a name might be one edit off before it asks, the case
  a miss is there to tell it.
- **An end tested by a walk over its callers** — a `call_path` miss took up to 0.97 ms where selection alone takes
  microseconds (C++ game-engine tree, 2026-10-21).

## Revisit if

A consumer needs alternatives for a name no case holds often enough that a search on every such miss pays. Medium
confidence: how often consumers miss with no case is not measured.
