Agents working in parallel share one server, each in a worktree of its own. The server holds the index of each root it
builds, up to `KARTTA_MAX_ROOTS`, and every call but an `index_stats` listing names the root it asks about, so each
agent's answers come from its own checkout. The trade is each held root's engine in memory, and a call that names its
root every time.

## Decision

- **The root of a call.** Every tool takes `root`, the absolute path `index_root` was given, and it is required on every
  tool but `index_stats`. A call answers from that root's index; one that names a root the server holds no index of is a
  tool error that says the server has not indexed it, names each root it holds, marked building or failed where it is,
  and sends the agent to `index_root` with that root. A root inside a held root names the held root and its two fixes.
  Roots match by their path's components, as `Path` compares them, without reading the filesystem. A query's answer does
  not repeat the root, which the call named; the `<index>` envelope names it, as it always has.
- **No root.** `index_stats` alone may leave `root` out. With a root it answers that root's envelope, and a root it
  holds no index of is the miss above; without one it answers one `<roots total="N">` element around one envelope per
  root held, in the order the server was first asked to build them, a root whose index cannot answer listed as
  `status="broken"` with why, and the element holds a hint to call `index_root` when the server holds none. There is no
  default root.
- **The bound.** `KARTTA_MAX_ROOTS`, 4 by default, bounds the roots held, failed ones included. An `index_root` of a new
  root past it drops a failed root, else the root a call named least recently, and never a root that is building; when
  every held root is building, the call is a tool error that lists them, and nothing is dropped. With 1, an
  `index_root` of another root replaces the one held unless it is building. The root given at launch is dropped like
  any other. The `index_root` that drops a root ends its answer, an index, a building envelope or an error alike, with
  a line that names the dropped root, why the bound chose it, and the `index_root` that builds it again.
- **One build at a time.** A build starts once the build under way has ended, and once the engine it replaces or drops
  is gone: the build that held it ended and every query holding it answered. The process never holds more engines than
  the bound.
- **At launch.** A root given as the argument, or as `KARTTA_ROOT` when there is none, starts the build before any call.
  A relative launch root is read against the working directory once, and calls name the absolute path it comes to.
  Until the build ends, `index_stats` answers `status="building"` with the seconds so far, and every other query of the
  root answers a tool error saying so. A launch build that ends without an index writes why on stderr.
- **The root of `index_root`.** One that is not an absolute path, or names no directory the server can read, is a tool
  error before any root changes.
- **A repeat.** An `index_root` of the request being built, the same root, languages and `index_ignored`, waits for it.
  A repeat of the request a held index was built from answers that index: at once while it follows its tree, after a
  whole refresh while its watch is off, and rebuilt only when a refresh that panicked broke it. Another request for a
  held root cancels its build under way, or a refresh of its engine, and replaces its index.
- **The wait.** An `index_root` waits for its build 30 s at most. When the root still builds that call's request, the
  call then answers the `status="building"` envelope `index_stats` gives and the build runs on, and the server's
  instructions and the tool's description send the agent to `index_stats` until it answers the index. A build a later
  `index_root` replaced answers a tool error saying so once the cancelled build ends, and a repeat answered from the
  held index once its refresh ends, whatever either takes.
- **No index.** `index_stats` of a root answers an `<index>` envelope in every state the root can hold:
  `status="building"` during a build, `status="failed"` with the root and the error after one that failed.
- **Cancel.** A request the client cancels with `notifications/cancelled` cancels its `grep`'s token
  ([ADR 1.70](/design-docs/adr/1.70-content-search-batches.md)), which each file checks before it is opened,
  so a cancelled search ends with the files already being read. The answer of a cancelled request is never sent.

## Why

- An `index_root` of one worktree replaced the index every other agent on the server read, so each agent was told to
  read the main checkout's answers in place of its own (#170).
- A mandatory `root` lets a call on a root the server holds no index of say so and send the agent to index that
  root, where a call that names no root would answer from another (#170).
- Two builds of a 171,628-file C++ checkout at once, at 3 threads each, peaked at 1,952-2,013 MiB against 1,512-1,662
  MiB one after the other, ran on twice the threads `KARTTA_THREADS` names, and readied the first root at 41-45 s
  against 34-40 s (macOS, 2026-11-25).
- A build of that checkout takes 52-57 s at 2 threads (#1033, 2026-11-24), and the MCP TypeScript SDK waits 60 s for a
  request by default (`DEFAULT_REQUEST_TIMEOUT_MSEC` in `shared/protocol.js`), resetting that timer on progress only
  when the caller asks. Claude Code sets no per-request timer on a stdio server, and its tool timeout defaults to about
  28 hours (Claude Code's MCP documentation, "Time limits on MCP tool calls").
- A mistyped root replaced the held index with a failure, so every later query answered that failure (#1033).
- An `index_root` that dropped a root answered the new root's envelope alone, so the agent learned of the drop only
  from the error of its next call on the dropped root (#1307).
- A launch root the bound never drops holds one of its places for the life of the process, whether or not a call
  names it again, so every other root shares one place fewer, and a bound of 1 would refuse every other root. Once
  the drop names the root, a session that comes back to it builds it again with one call.
- A followed index already holds what a rebuild of the same request would build. On the Go monorepo snapshot at 4
  threads a repeat rebuilt in 6.2 to 6.7 s, every other tool answering an error meanwhile, where the held index answers
  in 8 ms, and in under 0.2 s after a whole refresh (2026-11-03).
- A search nobody waits for holds the index's threads: a grep of the macOS data volume takes about 12 s, which a
  cancelled request spent in full before the cancel reached the search (2026-10-19).

## Consequences

- Each held root costs its own engine: 405-634 MiB of footprint for a 171,628-file C++ checkout, whose four roots peaked
  at 2,838 MiB against 1,174 MiB for main's one (macOS, 3 threads, 2026-11-25). On macOS a dropped root's memory stays
  with the allocator, which the next build reuses, so the footprint does not fall (2026-10-21, #170). Accepted.
- Every call but an `index_stats` listing names its root: about 130 bytes of `tools/list` per tool, which with the
  descriptions that say so took the result to 69,998 bytes of the 71,680 its budget allows (2026-11-25). Accepted.
- Two spellings of one directory, through a symlink or a firmlink, are two roots, each built apart. Accepted.
- A session that comes back to its launch root after the bound dropped it waits for a whole build of it again: 52-57 s
  at 2 threads for the 171,628-file C++ checkout (#1033). Accepted.
- A build queued behind another counts its seconds from the call, and a call meanwhile answers that it is building.
  Accepted.
- A query that arrives during its root's rebuild answers an error until the build ends. Accepted.
- A client whose request timeout is under 30 s still times out on a long build, and an agent on a build past 30 s
  polls `index_stats` until it is ready. Accepted.

## Rejected

- **An optional `root` that falls back to the latest `index_root`** — an agent that names no root reads another agent's
  checkout without a word of it, where a required root lets the server say it has not indexed the root.
- **A default root that the bound never drops** — with every root named, no root is the default.
- **A launch root that the bound never drops** — it holds a place whether or not a call names it again, and it leaves a
  bound of 1 no place for any other root.
- **Naming the root in every answer** — the call named it, and a server with one root answers as it did.
- **Builds side by side** — two builds of the C++ checkout peaked 350-440 MiB higher, on twice the threads the
  configuration names.
- **Dropping a building root past the bound** — it cancels another agent's build that its `index_root` still waits for.
- **Keep the replaced engine serving while a rebuild of its root runs** — doubles that rebuild's peak memory, to serve
  answers about a tree the caller asked to replace.
- **Resolve a relative `index_root` root against the server's directory** — indexes a tree the agent cannot see and did
  not name.
- **Progress notifications while `index_root` builds** — the TypeScript SDK resets its timer on progress only when the
  caller asks, and Claude Code's per-server timeout ignores progress.
- **A `force` parameter on `index_root`** — schema text every session pays for, where `refresh` already brings an index
  up to its tree.
- **A tool that drops a root** — the bound drops the least recently asked, and an agent cannot tell which roots other
  agents still read.

## Revisit if

Agents on one server work in more checkouts at once than the bound holds, so they rebuild one another's roots; held
while one session's agents share a server and each works one worktree.
