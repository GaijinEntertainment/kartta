# Bound each MCP tool's answer by a default limit

- **Date:** 2026-10-18
- **Governs:** `crates/kartta-mcp/src/server.rs` (the limit constants), `crates/kartta-mcp/src/params.rs`,
  `crates/kartta-mcp/src/render/calls.rs` (`DIRECT_RECORD_BYTES`)
- **Pinned by:** `crates/kartta-mcp/tests/stdio.rs`, `crates/kartta-mcp/tests/graph.rs`,
  `crates/kartta-mcp/tests/outline.rs`

Each answer of [ADR 4.1](/design-docs/adr/4.1-mcp-server-tools.md)'s server lands whole in an agent's context. The
tools below stop at a default limit, the prompts' own for the tools they name, and the answer counts what the limit cut
([ADR 4.24](/design-docs/adr/4.24-mcp-omission-counts.md)), so a cut answer costs the agent a second call where it
needs more.

## Decision

- **`find_files` and `glob_files`.** With no `max_results` the server cuts a list at 200 paths, and 0 lists every match;
  a cut list ends with a line saying so, and one the server's default cut with a line naming `max_results`
  ([ADR 4.10](/design-docs/adr/4.10-mcp-path-list-cuts.md)).
- **`grep`.** A search lists 100 matching lines, cuts a line to 1 KiB around its match with the bytes it lost, and
  skips files over 4 MiB; an unscoped search excludes `**/vendor`, `**/node_modules`, `**/dist` and `**/__pycache__`.
- **`grep` context.** The answer's lines, matches and context together, fill at most 40,000 bytes. Past that every
  match keeps the most context lines a side that fit, the same number for each, so the answer is the one that number
  asks for; no match line is dropped. The bound lives in the server, and `kartta-fs` answers the context it is asked:
  the server asks it for no more than a third of the budget a side, since a context line renders in 3 bytes at least.
- **`list_dir`.** A listing shows one level and 1000 entries, and does not enter `vendor`, `node_modules`, `dist`,
  `build` or `__pycache__`.
- **`find_symbols`.** A search answers 20 hits, fuzzy ones only for a query no keyword matches
  ([ADR 4.74](/design-docs/adr/4.74-mcp-fuzzy-hits.md)).
- **`read_definitions`.** A read answers 3 definitions of each of at most 10 names, a body at most 500 lines, each line
  cut at 1,024 bytes; a definition ranks `same-directory`, `vendored` or `other` by directory, not by the imports of the
  asking file.
- **`find_callers` and `find_callees`.** `find_callers` walks 3 hops and `find_callees` 1 hop, and `find_callees` puts
  `at=` only on a direct callee, since the walk records the line of each call but not which callee further out made it;
  both stop at 500 symbols. `find_callers` lists the nearest 100 callers its `role` keeps, and its `limit` raises that;
  `total=` counts the whole walk. It and `find_references` list the first 50 file-scope users of a
  symbol in path order.
- **`file_outline`.** An outline lists the first 100 definitions in source order, and its `limit` raises that.
- **`find_call_path` and `find_implementations`.** `find_call_path` walks 8 calls and 20,000 symbols, and
  `find_implementations` answers 500 implementors.
- **`find_importers`.** The walk reaches 3 includes away, which its `hops` sets from 1 through `u32::MAX`, and the
  answer lists the nearest 200 importers, which its `limit` raises; `total=` counts the whole walk.
- **`find_references`.** An answer counts every site, lists 100 and names 50 more files
  ([ADR 4.11](/design-docs/adr/4.11-mcp-reference-listing.md)).
- **`impact_of_edit` and `impact_of_change`.** Both run [ADR 3.22](/design-docs/adr/3.22-change-impact-analysis.md)'s
  walk at 3 hops and 500 symbols. `impact_of_edit` lists the 10 symbols of widest reach in source order, the first
  among equal reaches, and the first 10 files of each include list in path order, which its `limit` raises, and 50
  direct callers and callees of each symbol; `impact_of_change` lists 20
  changed symbols and 20 hotspots, and 10 direct callers of each, or their directories past 30 callers. A change
  arrives as regions or a diff ([ADR 4.20](/design-docs/adr/4.20-change-diff-input.md)).
- **`impact_of_edit` direct lists.** The records of an answer's caller, user and callee lists fill at most 40,000
  bytes. Past that every list keeps the most records that fit, the same number for each, and no symbol is dropped. The
  bound lives in the server: the engine lists the 50 it is asked for, and the server lists fewer of them.
- **`find_unused`.** The tool judges every kind by [ADR 3.23](/design-docs/adr/3.23-dead-code-judgment.md), under an
  optional `path_prefix`, and lists 50 in path order across the graphs; an answer that judged every definition and
  found each reached says so.
- **`index_root` and `index_stats`.** They count each graph's `calls`, `uses` and `includes`, not resolved edges, which
  [ADR 3.7](/design-docs/adr/3.7-call-resolution.md) does not build. With `coverage`, `index_stats` resolves every
  call ([ADR 3.24](/design-docs/adr/3.24-graph-stats-and-coverage.md)) each time it is asked, and adds a
  `<coverage/>` record for each language that holds a file.

## Why

- The tools the prompts name keep the prompts' defaults, so an answer has the size those prompts were written for
  (#74).
- The walk records the line of each call but not which callee further out made it, so a callee past the first hop
  answers no line.
- `find_files` and `glob_files` answer anyone's agent ([ADR 4.46](/design-docs/adr/4.46-release-scope.md)), not only
  the prompts that set their own `max_results`: listed whole, dagor's 171,628 paths answered 13 MB. A glob or a pattern
  can select any paths, so the widest cut list holds the longest: the 200 longest answer 29,726 bytes on dagor and
  23,019 on the Go monorepo snapshot (2026-11-25).
- An answer the default limit cut says so with an explicit marker, so an agent that named no cap does not read the
  paths as every match (#1039).
- Claude Code moves a tool result past 50,000 characters to a file, out of the context. Unbounded, `file_outline` of a
  3,855-symbol header answered 933 KB, `impact_of_edit` of it 2.07 MB, `find_callers` of hot names 77 to 128 KB, and
  `find_importers` of a hub header on dagor 1.70 MB for 21,473 importers (#1038).
- A caller's count comes from the walk the engine runs whatever it lists, so the cap costs `find_callers` no
  fact an agent reads most; the nearest callers are the ones an edit breaks first.
- An outline record runs 90 to 320 bytes with its signature. On the widest files of dagor, the Go monorepo snapshot and
  this repository, 100 records answer at most 31 KB (2026-11-06).
- An `impact_of_edit` symbol carries up to 50 callers and 50 callees at about 250 bytes a record. Over 62 whole files
  of dagor, the Go monorepo snapshot and this repository, 32 answered past 50,000 characters at the defaults, up to
  143 KB; with the records held to 40,000 bytes the largest answered 46.9 KB with every symbol listed (2026-11-07).
  The widest symbols are the ones an edit's risk turns on, so the lists give way before they do.
- At 200 importers, the widest `find_importers` answers of dagor and the Go monorepo snapshot reach 29,838 bytes
  (2026-11-06).
- `find_importers`' walk visits each file once and ends where a depth adds none, so the include graph bounds its cost,
  not `hops`: with no bound, the widest walk on dagor reached 33,823 files in 3 ms (2026-11-06).
- Over the 787 greps of the parity plans on dagor, the Go monorepo snapshot and this repository, `context_lines`
  100000 answered up to 2.27 MB and 374 of them passed 50,000 characters; with the lines held to 40,000 bytes the
  largest answered 43.6 KB at every `context_lines` measured (2026-11-06). The match lines alone answer up to 28 KB,
  so a budget on the context alone lets an answer past it.

## Consequences

- An agent that needs a callee past the first hop, or more than a limit lists, makes a second call. Accepted.
- `impact_of_edit` of a wide file lists fewer callers and callees of each symbol: 12 to 48 a list on the 39 measured
  answers the budget cut, against 50. No parameter raises the lists, and a cut list names the `find_callers`,
  `find_callees` or `find_references` call that lists the rest
  ([ADR 4.24](/design-docs/adr/4.24-mcp-omission-counts.md)). The symbols, their signatures, the include lists and the
  cut lines stay outside the budget: they took up to 7.3 KB of the 62, and a file where they pass 10 KB still answers
  past 50,000 characters. Accepted.
- A `grep` whose matches are many or long shows less context for each, and one whose match lines alone pass 40,000
  bytes shows none; a whole file is a read of the file, not a `grep`. The budget renders each context line once more
  to count its bytes. Accepted.
- The first 50 file-scope users are listed in path order, not by confidence; `file_scope=` counts every one and
  `file_scope_shown=` the listed. `find_references` lists those past 50 under a narrower `sites_under`, and no
  `find_callers` parameter lists them, which each cut list says. Accepted.
- `find_implementations` lists 500 implementors and no parameter lists the rest: dagor holds 5 C++ parents past 500
  (#1234).
- `find_importers` of a hub lists only part of its direct importers at 200: a header of dagor has 900. `total=` and
  `shown=` say how many are left, and `limit` lists them. Accepted.

## Rejected

- **`find_callees` 3 hops deep by default, as `find_callers`** — a callee past the first hop carries no line of its
  call, and the question asked is what a body calls.
- **`file_outline` at 150 or 200 definitions** — the widest header measured answered 46 KB at 150 and 64 KB at 200,
  so 150 leaves 8% of the budget to a file with longer signatures and 200 passes it.
- **`impact_of_edit` at 20 or 50 symbols** — 10 and 13 of the 15 probes passed 50,000 bytes, against 4 at 10.
- **`impact_of_edit` at 3 or 5 symbols** — at 5, 11 of the 62 whole files passed 50,000 characters; at 3 all fit, but
  the answers listed 185 of the 592 symbols the budget lists.
- **A per-symbol cap of 10 to 20 records in the server, alone or with 5 symbols** — 15 and 20 left 2 and 3 of the 62
  past the bound; 10, and 20 at 5 symbols, fit all but listed 4,990 and 4,699 records against the budget's 10,488,
  because a cap cuts the lists of an answer that already fits.
- **`find_callers` grouped by file, as `find_references` lists sites** — a new shape, and the hop order an agent
  follows outward is lost.
- **A lower walk cap for `find_callers`** — it shrinks the count, the fact most calls read.
- **No default limit for `find_files` and `glob_files`, as the prompts set their own** — an agent outside those
  prompts gets every match, 13 MB on dagor.
- **`find_files` and `glob_files` at 300 or 500 paths** — the longest paths of dagor answer 43,982 bytes at 300 and
  72,077 at 500, so 300 leaves 12% of the budget to longer paths and 500 passes it.
- **`read_definitions` ranked by the imports of the asking file** — an agent the nearest definitions miss reads
  another by the candidates' `path_prefix` and `line`, so the ranking by directory costs it one more call (#1039).
- **`find_importers` at 300 or 500 importers** — the widest answers measured reached 43,541 bytes at 300 and 72,702
  at 500, so 300 leaves 13% of the budget to longer paths and 500 passes it.
- **A `find_importers` `hops` bound below `u32::MAX`** — no depth costs more than the include graph, so a lower bound
  turns away a depth an agent can need and saves no time.
- **A ceiling on `context_lines`** — at 3 lines a side dagor still answered 52 KB, and it cuts the context of a grep
  of one match that the budget carries whole; a refusal past it turns away a value an agent may need.
- **A budget on the context lines alone** — at 40,000 bytes the match lines took answers to 64 KB, 6 of the 787 past
  50,000 characters.
- **Coverage on every `index_stats`, or cached per build** — every first call would pay 0.1 to 0.4 s on the measured
  trees and a resolution's memory for counts most calls do not read, and a cache saves only a repeat.

## Revisit if

The prompts in use change the defaults they pass, or agents raise a tool's limit on most of its calls. Medium
confidence; how often agents raise a limit is not measured.

  to 2.27 MB (#1038)

  a fixed 3 includes with no way to follow the importers it stopped at (#1038)

- 2026-10-18 — The limits of `find_callees`, `impact_of_change`, `find_unused` and `index_stats` `coverage`: no tool

  bind (#77)
