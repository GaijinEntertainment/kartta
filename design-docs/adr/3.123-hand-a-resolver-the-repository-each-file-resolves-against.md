# Hand a resolver the repository each file resolves against

- **Status:** accepted
- **Date:** 2026-10-22
- **Updated:** 2026-10-22
- **Initiative:** `03-code-graph`
- **Governs:** `kartta_lang::Language::resolver`, `kartta_lang::Resolver::resolve`, each
  `crates/kartta-lang-*/src/resolve.rs`

A followed engine keeps a family's resolver from one refresh to the next
([ADR 3.82](./3.82-build-a-followed-family-s-resolver-again-only-when-a-refresh-reaches-what-it-read.md)), and a
refresh's repository lives only as long as the refresh. A resolver therefore borrows no repository: it owns what it
read, and each `resolve` is handed the repository the file resolves against, at the price of a view built inside
`resolve` by a resolver whose helpers ask the repository.

## Decision

- `Language::resolver` reads the configuration through the repository it is handed and returns a resolver that borrows
  neither the language nor the repository. The resolver keeps what it read as owned data.
- `Resolver::resolve` takes the raw extraction, the file's path and the repository that file resolves against.
- A resolver whose helpers ask the repository builds them as a view inside `resolve`.

## Why

- A resolver that borrowed the repository it was built over could not outlive that repository, so no engine could keep
  one from one refresh to the next.
- The change costs a build nothing measurable: the answers were identical on dagor and on the Go monorepo snapshot, and
  a build's time and peak footprint stayed within run-to-run spread at 8 threads (2026-10-22).

## Consequences

- A resolver whose helpers ask the repository builds that view once per file; within run-to-run spread on the measured
  trees; accepted.

## Rejected

- **A configuration a language reads, kept apart from a resolver it builds over each build's or refresh's repository**
  — keeps a followed family's configuration as well, but every language crate implements a second trait and the
  engine builds a resolver per refresh, where an owned resolver handed the repository is both.
- **A resolver that borrows the repository it was built over** — no engine could keep it past the refresh whose
  repository it borrows.

## Revisit if

The view a resolver builds inside `resolve` shows in a build's profile. High confidence it does not: the measured
builds moved within their spread.
