# Bind no call to a namespace where a language's calls name none

- **Date:** 2026-10-20
- **Governs:** `crates/kartta-graph/src/resolve.rs` (`is_unbound_namespace`, `resolve_call`),
  `crates/kartta-graph/src/scope.rs` (`admits`), `crates/kartta-lang-rust/src/lib.rs`, `kartta_lang::NamespaceCalls`
- **Pinned by:** `crates/kartta-graph/tests/graph/calls.rs`
  (`a_call_binds_no_namespace_where_the_language_binds_none_and_the_namespace_still_counts`,
  `a_dot_import_binds_no_namespace_where_the_language_binds_none`),
  `crates/kartta-languages/tests/engine.rs::a_rust_call_named_like_a_module_binds_no_call_to_the_module`

Every kind but a field and a variant is a call target, so a call could bind a namespace of its name. No Rust call names
a module, so where a language says its calls name no namespace, no call binds one, and the namespace still counts among
the definitions of its name.

## Decision

- **No call binds a namespace.** Where `Conventions::namespace_calls` is `NamespaceCalls::Unbound`, as Rust's is, no
  call binds a namespace: no call's shape admits one, so a tier that would take it takes another definition it reaches,
  or the call binds nothing and counts as not admitted.
- **The namespace still counts.** The namespace still counts among the definitions of its name at the one callable of
  the name and the proximity steps, as a definition the call's shape rules out does, so a function named like a module
  elsewhere is not the one callable of its name.
- **The default.** `NamespaceCalls::Bound`, the default, keeps a namespace callable; every language but Rust keeps
  it.

## Why

No Rust call names a module, and each binding to one was wrong: `tree.walk()` bound `mod walk;`, `write!` bound
`pub mod write;`, and every sampled module edge in a cargo registry of 486 crates was a call of something else
(2026-10-20, #216).

## Consequences

A call that a module kept from a guess stays unbound: in this repository 152 calls that bound a module bind nothing, 145
of them counted as ambiguous (2026-10-20).

## Rejected

- **The namespace out of the candidates too** — adds 1,870 edges in the registry at about 81% right and 108 in the Go
  monorepo at about 54%, since the module was what kept those calls from a guess: `node.walk()` took a test module's
  `walk` helper (2026-10-20).
- **The cascade ends at a namespace** — drops the same edges and loses the 600 new registry edges, about 94% right, that
  a tier finds past the module.

## Revisit if

A language that sets `Unbound` gains a construct through which a call names a namespace. High confidence for Rust.
