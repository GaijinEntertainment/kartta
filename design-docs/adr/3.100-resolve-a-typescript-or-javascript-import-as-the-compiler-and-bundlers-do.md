# Resolve a TypeScript or JavaScript import as the compiler and bundlers do

A TypeScript or JavaScript specifier names a file through rules the compiler and the bundlers take from the
repository's `tsconfig.json`, `jsconfig.json` and `package.json` files. The `jsts` family's resolver
([ADR 3.4](./3.4-extract-typescript-and-javascript-as-one-family.md)) reads those files and resolves as they do, and
leaves out the configuration that only a bundler or a web server states, save the alias Vue CLI sets unasked.

## Decision

1. The family builds one resolver
   ([ADR 3.122](./3.122-resolve-a-language-family-through-the-resolver-its-first-language-builds.md)). It reads every
   `tsconfig.json`, `jsconfig.json` and `package.json` outside `node_modules` and `vendor` directories when it is
   built, and a `tsconfig*.json` or `jsconfig*.json` only when one of those extends or references it. A file of
   another name that a config extends is not read. It keeps only what it derived, which a refresh compares
   ([ADR 3.82](./3.82-build-a-followed-family-s-resolver-again-only-when-a-refresh-reaches-what-it-read.md)).
2. A specifier that starts with `./` or `../` probes the path as written, with each script extension (`.tsx`, `.ts`,
   `.mts`, `.cts`, `.d.ts`, `.jsx`, `.js`, `.mjs`, `.cjs`), and as a directory with an `index` file of each. On a miss,
   a path ending in `.js`, `.mjs`, `.cjs` or `.jsx` probes again without it, which finds the TypeScript source an ESM
   `./m.js` stands for. Every probe below takes the same steps.
3. A `#` specifier takes the `imports` of the nearest `package.json` above the importing file, which stops the lookup
   whether it declares any or not.
4. Any other specifier first takes the `paths` of the nearest config above the importing file, a `tsconfig.json` or
   else a `jsconfig.json`, which governs alone, one that yields no `paths` included. A root-relative specifier takes
   `paths` alone: `"/*": ["./*"]` in `public/jsconfig.json` reads `/scripts/m.js` as `public/scripts/m.js`. Another
   specifier that no `paths` pattern resolves takes the config's explicit `baseUrl`, unless `paths` declares `*`:
   `helpers/fetch` under `"baseUrl": "src"` names `src/helpers/fetch.ts`. One `extends` hop applies, the child
   replacing `paths` and `baseUrl` whole, and a path the base supplies stays relative to the base. A config that
   declares neither `paths` nor `baseUrl` but references configs in its own directory takes theirs, as the current
   Vite scaffold splits them; a reference into a subdirectory is that subproject's. A `package.json` that lists
   `@vue/cli-service` in its `dependencies` or `devDependencies` governs as a config whose one alias reads `@/` as its
   own `src/`, the alias Vue CLI's webpack config sets, below a config of its directory. In `paths`, `exports` and
   `imports` an exact key comes before a pattern, and the pattern with the longer prefix before its `*` first.
5. Where those `paths` resolve nothing, or there are none, a specifier that names a package of the repository takes its
   `exports`, where an object whose keys are conditions is the target of `.`, the conditions tried in the order
   `source`, `import`, `module`, `default`, `require`, `node`, `types`. Failing `exports`, the bare name takes the
   package's `module`, then its `main`, then its directory, and a subpath takes the file under the package's directory.
   A bare import of a package whose `exports` omits `.` therefore falls through to `main`, where Node rejects it.
6. Of the packages whose names prefix the specifier, the longest name wins, then the package nearest the importing
   file; two equally near resolve to neither.
7. A specifier with a `?query`, as Vite writes them, resolves without the query only after it misses as written.
8. A resolved import, a `require` or a dynamic `import()` of a string, a type-only one included, is an include of its
   file; one that names no file of the repository is kept as an import as written.
9. Each name that an `import` of a bare specifier binds, or a declarator that takes a `require` of one, where the
   specifier resolves to no file, is an import binding outside the repository, which the cascade answers as a call
   into an external import, whether through the name
   ([ADR 3.171](./3.171-bind-a-call-through-the-import-type-qualified-name-or-owner-it-is-written-on.md), tier 2) or
   of it ([ADR 3.172](./3.172-bind-a-bare-call-through-the-scope-that-offers-its-name-then-the-nearest-callable.md),
   tier 6), unless the caller's file defines the name: `<Dialog.Footer>` with `Dialog` from `@chakra-ui/react`,
   `useState()` with `useState` from `react`, and `fs.readFileSync()` or `readFileSync()` with `const fs =
   require("fs")` or `const { readFileSync } = require("fs")`, bind nothing in the repository. The declarator binds
   each name of its pattern, a property key and a default value none, and `require("chalk").default` binds no name.
   A specifier that starts with `.`, `/` or `#` names a file of the repository even where none resolves, so its names
   get no such binding.
10. A re-export names the file its specifier resolves to by the same rules, or none, and resolves together with the
    import of its statement.

## Why

- The compiler and the bundlers already define where a specifier leads, and the repository's own configuration is what
  they read. Vendored configs belong to third-party packages, and a checkout can hold thousands.
- The compiler resolves a non-relative specifier against an explicit `baseUrl` before it looks for a package, and a
  project that sets one imports its own files that way: on dagor, 43 TypeScript call pairs bind or rise to the include
  tier through it (2026-10-24).
- The TypeScript language service looks for a `jsconfig.json` after a `tsconfig.json` in each directory, and applies
  `paths`, not `baseUrl`, to a root-relative specifier. SillyTavern's `public/jsconfig.json` roots all 27 such import
  lines at the `public/` its server serves: 26 call pairs rise to the include tier and 12 bind, each right (2026-10-24).
- Vue CLI aliases `@` to `src` in every project it builds, and a project with no `tsconfig.json` imports its own files
  through it: 4 imports on the Go monorepo snapshot, each naming a file of the repository (2026-10-24).
- A repository finds files by their exact name, and a `tsconfig*.json` variant takes part only as the target of a
  config that names it.
- An include edge is worth more than strictness: `main` is the module most bundler setups load. A monorepo of
  independent frontends can declare one package name twice, and a missing edge is better than one no bundler would
  make.
- A name imported from a package holds that package's code, so a member call through it bound a repository definition
  that only shares the member's name: 146 such caller and callee pairs on three trees, none right (2026-10-23). A bare
  call of the name bound the same way: 660 such pairs on dagor and the Go monorepo snapshot, none right (2026-10-24).
  A `require` of a package holds that package's code as an import does; on dagor, daScript, sso and the snapshot the
  one pair it lets bind no more is wrong, `utf8.encode()` with `utf8` from `require('utf8')` bound to a vendored
  bundle's `encode` (2026-10-24).
- The caller's file defines an imported name only where a definition nested in the caller shadows the import, or
  where a test hook such as `beforeEach` is named for itself, so its definition is the one meant.
- A re-export resolved with its statement costs no second resolution, and the resolver knows the extensions and
  aliases a graph-side match would guess at.

## Consequences

- Each re-export that names a file costs a copy of its path: 118,642 of 166,762 on a monorepo checkout of 374,827
  files (2026-10-16). Accepted.
- A root-relative specifier that no config's `paths` roots stays an import as written and goes on to the name tiers,
  though the server's code, `express.static('public')`, may root it. Accepted.
- A `jsconfig.json` include lets a member call on a call's result, or on a local one initializes, bind the included
  file's member of its name: 7 of the 20 pairs it adds on SillyTavern, `$('#x').hide()` among them (2026-10-24, #592).
- A specifier under a `baseUrl` that names no file of the repository probes the `baseUrl` once more before the
  packages. Accepted.
- An include the `baseUrl` resolves lets a bare call of a name a local declares, `const { setError } =
  useContext(AppContext)`, bind the included file's namesake: 13 pairs on dagor, none right, and 3 functions that a
  React context hands out read as unused (2026-10-24, #543).
- A bare specifier that names a file of the repository only through configuration this resolver does not read, a
  bundler's own alias, is taken for a package, so no call of a name it imports binds: no right pair lost on dagor or
  the Go monorepo snapshot (2026-10-24).

## Rejected

- **The graph matching re-exports to includes** — by stem, path segment or an appended `.ts`, it could not see an ESM
  `.js` specifier, an alias, an `index.tsx` barrel or a package, and the graph would keep a language's extension rules
  against ADR 3.1.
- **Resolving each re-export on its own** — one more resolution per re-exported name, where a statement re-exporting
  many names resolves the same specifier once.
- **A `baseUrl` probe kept apart from `paths`** — answers as the `*` pattern does, with one more field on every
  config.
- **Leaving a Vue CLI project's `@/` a package import** — its member calls bind outside the repository, and with
  #422 its bare calls do too.
- **Reading every `tsconfig*.json` up front** — reads variants that take part only through a config that names them.
- **Node's strict `exports`** — drops the include edge of a package whose `main` is what its bundler loads.
- **An external binding for every specifier that resolves to no file** — dropped 5 more pairs on SillyTavern, 3 of them
  right, `MacrosParser.registerMacro` through `'/scripts/macros.js'`, a path a web server roots at `public/`
  (2026-10-23).
- **Rooting a root-relative specifier at the nearest `index.html`, a `public/` beside the `package.json`, or the
  nearest ancestor holding the file** — each binds SillyTavern's pairs as its `jsconfig.json` does and no tree measured
  gains more, while each guesses at a server; a `public/` misreads Vite's `/src/main.tsx` (2026-10-24).
- **Ending a bare call at the import before the caller's file** — drops the 22 pairs from a `describe` to its
  `beforeEach` or `afterEach` hook where `vitest` exports the hook's name, pairs a global hook keeps.
